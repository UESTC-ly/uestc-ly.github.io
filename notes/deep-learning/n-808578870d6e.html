视频处理是把图像算法放进时间轴。OpenCV 用 VideoCapture 统一文件、摄像头和网络流，用 VideoWriter 写回处理帧；光流、背景建模和跟踪器依赖连续帧变化。以 OpenCV 5 为主兼 4.12。资料 Video I/O https://docs.opencv.org/5.0/main_modules/videoio.html，Video Analysis https://docs.opencv.org/5.0/main_modules/video_track.html，Tracking contrib https://docs.opencv.org/5.0/extra_modules/tracking.html。

1. VideoCapture、后端与时间基

cv.VideoCapture(source, apiPreference=cv.CAP_ANY) 可打开视频、摄像头、RTSP/HTTP 流或图像序列。CAP_ANY 会自动选后端，但行为不一定一致。常见后端包括 V4L2、GStreamer、FFmpeg、MSMF/DSHOW、AVFoundation。后端决定解码、seek、硬件属性和时间戳可靠性。

常用属性：CAP_PROP_FRAME_WIDTH/HEIGHT 是尺寸，CAP_PROP_FPS 是声明帧率或设备报告值，CAP_PROP_FRAME_COUNT 对直播流常不可靠，CAP_PROP_POS_FRAMES 是帧号，CAP_PROP_POS_MSEC 是毫秒位置，CAP_PROP_FOURCC/BITRATE/BACKEND 可诊断编码和后端，CAP_PROP_EXPOSURE/GAIN/FOCUS/AUTO_EXPOSURE 依赖设备和驱动。set() 返回真不保证硬件实际执行。

时间基要分清三层：容器时间戳、声明 FPS、程序墙钟时间。离线文件可逐帧处理；实时摄像头要用 time.monotonic() 量耗时。30 FPS 每帧预算约 33 ms，超预算就会掉帧或累积延迟。网络流应处理“最新帧”，而不是缓冲区里的每一帧。

2. VideoWriter、编码器与尺寸

VideoWriter(filename, fourcc, fps, frameSize, isColor) 写视频时，fourcc、容器、fps、帧尺寸和颜色标志必须匹配。常见失败是写入帧尺寸与初始化尺寸不同，或灰度帧按彩色视频写。.avi + MJPG 兼容性强但文件大；.mp4 + mp4v 或 H.264 更适合交付，但编码器取决于构建和系统后端。写入前必须检查 writer.isOpened()；失败时换 fourcc/容器，或用 cv.getBuildInformation() 查看 FFmpeg/GStreamer。

完整 Python 示例：读取、逐帧处理、叠加时间信息、写出。

import time

import cv2 as cv


def main():
    source, out_path, show = "input.mp4", "out.avi", False
    src = int(source) if source.isdigit() else source
    cap = cv.VideoCapture(src, cv.CAP_ANY)
    if not cap.isOpened():
        raise RuntimeError(f"cannot open {source}")

    w = int(cap.get(cv.CAP_PROP_FRAME_WIDTH)) or 640
    h = int(cap.get(cv.CAP_PROP_FRAME_HEIGHT)) or 480
    fps = cap.get(cv.CAP_PROP_FPS) or 30.0
    writer = cv.VideoWriter(
        out_path, cv.VideoWriter_fourcc(*"MJPG"), fps, (w, h), True
    )
    if not writer.isOpened():
        raise RuntimeError("cannot open writer")

    i, last = 0, time.monotonic()
    while True:
        ok, frame = cap.read()
        if not ok or frame is None:
            break
        now = time.monotonic()
        pos_ms = cap.get(cv.CAP_PROP_POS_MSEC)
        gray = cv.cvtColor(frame, cv.COLOR_BGR2GRAY)
        edges = cv.Canny(gray, 80, 160)
        frame[edges > 0] = (0, 255, 255)
        cv.putText(frame, f"f={i} pos={pos_ms:.0f}ms loop={(now-last)*1000:.1f}ms",
                   (20, 35), cv.FONT_HERSHEY_SIMPLEX, 0.7, (0, 255, 0), 2)
        last = now
        writer.write(frame)
        if show:
            cv.imshow("video", frame)
            if cv.waitKey(1) in (27, ord("q")):
                break
        i += 1

    cap.release()
    writer.release()
    if show:
        cv.destroyAllWindows()
    print(f"{i} frames -> {out_path}")


if __name__ == "__main__":
    main()

3. 实时循环与无头环境

基本循环是：打开来源、读取、检查空帧、处理、显示或写出、退出、释放。cv.waitKey() 还驱动 HighGUI 窗口事件；服务器、Docker、CI 里不要依赖 imshow()，应使用 headless 包、写文件或 Web 输出。实时程序要测采集、预处理、算法、绘制、写出各阶段耗时，并明确是离线保留全部帧，还是实时只处理最新帧。

4. 帧差、MOG2 与 KNN 背景建模

帧差把相邻灰度帧相减后阈值化，适合固定摄像头下的明显运动；缺点是目标停下会消失，光照闪烁或摄像头抖动会误报。背景建模维护长期背景并输出前景掩膜。OpenCV 提供 createBackgroundSubtractorMOG2() 和 createBackgroundSubtractorKNN()：MOG2 基于混合高斯并支持阴影检测，KNN 使用历史样本近邻，对动态背景有时更稳。history 越大越稳定但适应慢；阈值越小越敏感；learningRate=0 可冻结背景；开启阴影时，阴影常是 127，真实前景通常是 255。

import cv2 as cv

cap = cv.VideoCapture("street.mp4")
bg = cv.createBackgroundSubtractorMOG2(history=500, varThreshold=16,
                                       detectShadows=True)
kernel = cv.getStructuringElement(cv.MORPH_ELLIPSE, (5, 5))
while True:
    ok, frame = cap.read()
    if not ok:
        break
    mask = bg.apply(frame)
    _, fg = cv.threshold(mask, 200, 255, cv.THRESH_BINARY)
    fg = cv.morphologyEx(fg, cv.MORPH_OPEN, kernel)
    fg = cv.morphologyEx(fg, cv.MORPH_CLOSE, kernel, iterations=2)
    contours, _ = cv.findContours(fg, cv.RETR_EXTERNAL, cv.CHAIN_APPROX_SIMPLE)
    for c in contours:
        if cv.contourArea(c) >= 800:
            x, y, w, h = cv.boundingRect(c)
            cv.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

C++ 对照：cv::Ptr<cv::BackgroundSubtractor> bg = cv::createBackgroundSubtractorMOG2(); bg->apply(frame, mask);。KNN 只需替换为 cv::createBackgroundSubtractorKNN()。

5. 光流方程、假设与金字塔

光流描述亮度模式在两帧之间的位移。经典亮度恒定假设是 I(x,y,t)=I(x+u,y+v,t+1)，小位移泰勒展开得到 Ix*u + Iy*v + It = 0。一个像素只有一个方程却有 u,v 两个未知量，这就是孔径问题。Lucas-Kanade 在局部窗口内假设邻域共享同一运动，用多个像素方程最小二乘求解，所以角点和纹理区域好跟踪，纯色区、直边、反光和模糊区域不稳定。

光流依赖三个假设：亮度近似恒定、帧间位移较小、局部运动一致。自动曝光、强光照变化、运动模糊、遮挡边界、非刚体变形都会破坏它。图像金字塔先在低分辨率估计大运动，再逐层回到高分辨率细化，是 OpenCV LK 和 Farneback 参数里 maxLevel/levels 的核心原因。遮挡会让点在下一帧没有真实对应；漂移是小误差持续累积。工程上要看 status、误差、前后向一致性、点数下限，并周期性重检测。

6. 稀疏 Lucas-Kanade

稀疏 LK 只跟踪选定点，速度快，适合角点轨迹、相机运动估计和跟踪辅助。流程：第一帧用 goodFeaturesToTrack() 找角点；后续用 calcOpticalFlowPyrLK() 估计新位置；只保留 status==1 的点；点数过少则重新检测。

import cv2 as cv
import numpy as np

cap = cv.VideoCapture("vtest.avi")
ok, old = cap.read()
if not ok:
    raise RuntimeError("cannot read first frame")
old_gray = cv.cvtColor(old, cv.COLOR_BGR2GRAY)
p0 = cv.goodFeaturesToTrack(old_gray, 200, 0.01, 8, blockSize=7)
if p0 is None or len(p0) == 0:
    raise RuntimeError("no corners detected in first frame")
canvas = np.zeros_like(old)
lk = dict(winSize=(21, 21), maxLevel=3,
          criteria=(cv.TERM_CRITERIA_EPS | cv.TERM_CRITERIA_COUNT, 30, 0.01))

while True:
    ok, frame = cap.read()
    if not ok:
        break
    gray = cv.cvtColor(frame, cv.COLOR_BGR2GRAY)
    p1, status, err = cv.calcOpticalFlowPyrLK(old_gray, gray, p0, None, **lk)
    if p1 is None or status is None:
        break
    good_new = p1[status.ravel() == 1]
    good_old = p0[status.ravel() == 1]
    for new, old_pt in zip(good_new, good_old):
        a, b = new.ravel().astype(int)
        c, d = old_pt.ravel().astype(int)
        cv.line(canvas, (a, b), (c, d), (0, 255, 0), 2)
        cv.circle(frame, (a, b), 3, (0, 0, 255), -1)
    vis = cv.add(frame, canvas)
    old_gray = gray
    p0 = good_new.reshape(-1, 1, 2)
    if len(p0) < 40:
        new_p0 = cv.goodFeaturesToTrack(gray, 200, 0.01, 8, blockSize=7)
        if new_p0 is None or len(new_p0) == 0:
            break
        p0 = new_p0
        canvas[:] = 0

C++ 对照：cv::calcOpticalFlowPyrLK(prevGray, gray, prevPts, nextPts, status, err, cv::Size(21,21), 3, criteria);。OpenCV 还提供 cv::SparsePyrLKOpticalFlow 和 CUDA 版本，是否可用取决于构建选项。

7. 稠密 Farneback 与相关新 API

稠密光流为每个像素估计运动向量，适合运动分割、可视化、稳定和行为分析。calcOpticalFlowFarneback() 是稳定的函数式 API，输入为同尺寸 8 位单通道图像，输出 CV_32FC2。pyr_scale 控制金字塔缩放，levels 影响大位移能力，winsize 越大越平滑，iterations 控制每层迭代，poly_n/poly_sigma 控制局部多项式展开。

ok, prev = cap.read()
prev_gray = cv.cvtColor(prev, cv.COLOR_BGR2GRAY)
while True:
    ok, frame = cap.read()
    if not ok:
        break
    gray = cv.cvtColor(frame, cv.COLOR_BGR2GRAY)
    flow = cv.calcOpticalFlowFarneback(
        prev_gray, gray, None, 0.5, 3, 15, 3, 5, 1.2, 0)
    mag, ang = cv.cartToPolar(flow[..., 0], flow[..., 1], angleInDegrees=True)
    prev_gray = gray

OpenCV 5/4.x 还包含 cv::FarnebackOpticalFlow::create()、cv::DISOpticalFlow、cv::VariationalRefinement、CUDA optflow 等接口。Python 是否暴露这些类取决于主模块、contrib 模块和构建配置；教学和跨平台脚本优先使用稳定函数式接口。

8. 目标跟踪器与 contrib 边界

跟踪器输入初始框，后续估计目标位置；检测器逐帧重新找目标。跟踪器快但会漂移，检测器稳但慢。OpenCV tracking 涉及 opencv_contrib 和 legacy 命名空间。OpenCV 5 文档中可见 cv::legacy::TrackerKCF::create()、cv::legacy::TrackerCSRT::create()；Python 里可能是 cv.legacy.TrackerKCF_create()、cv.legacy.TrackerKCF.create()。安装 opencv-python 通常没有这些接口，需 opencv-contrib-python 或源码构建 contrib。

兼容创建与单目标跟踪：

def create_tracker(name="CSRT"):
    name = name.upper()
    attr = f"Tracker{name}_create"
    if hasattr(cv, attr):
        return getattr(cv, attr)()
    if hasattr(cv, "legacy"):
        if hasattr(cv.legacy, attr):
            return getattr(cv.legacy, attr)()
        cls = getattr(cv.legacy, f"Tracker{name}", None)
        if cls is not None and hasattr(cls, "create"):
            return cls.create()
    raise RuntimeError("install opencv-contrib-python or build tracking module")


cap = cv.VideoCapture("person.mp4")
ok, frame = cap.read()
bbox = cv.selectROI("select", frame, False, True)
tracker = create_tracker("CSRT")
tracker.init(frame, bbox)
while True:
    ok, frame = cap.read()
    if not ok:
        break
    ok, box = tracker.update(frame)
    if ok:
        x, y, w, h = map(int, box)
        cv.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

C++ 对照：

cv::Ptr<cv::legacy::TrackerCSRT> tracker = cv::legacy::TrackerCSRT::create();
tracker->init(frame, box);
bool ok = tracker->update(frame, box);

CSRT 通常较准但慢，KCF 较快但对遮挡和尺度变化敏感，MOSSE 很快但精度有限。具体可用列表以当前 OpenCV 官方文档和 cv2 实际属性为准。

9. 检测 + 跟踪、运动估计与稳定

只检测适合安全告警、计数等逐帧确认任务，代价是算力高；只跟踪适合短时连续跟随，风险是遮挡、出画、同类目标交叉、快速运动和外观变化。常用组合是“低频检测 + 高频跟踪”：第 0 帧或每隔 N 帧检测，中间帧跟踪；当 tracker 失败、框面积异常、运动突变、LK 点数过少、检测框与跟踪框 IoU 过低时重检测。多目标还需要 IoU、中心距离、外观特征或卡尔曼滤波做关联。

视频稳定也是运动估计问题：在上一帧找角点，用 LK 跟踪到当前帧，用 estimateAffinePartial2D() 或 findHomography() 估计相机主运动，累积轨迹并滑动平均，再用 warpAffine() 或 warpPerspective() 重绘。仿射适合轻微平移、旋转、缩放；单应适合平面或纯旋转。前景大物体应由 RANSAC 当作离群点排除，否则稳定会跟着前景跑。

10. 多线程采集、缓冲与延迟

摄像头和 RTSP 常见问题是处理慢导致缓冲堆积，画面看似流畅但延迟几秒。实时系统可用采集线程不断 read()，只保存最新帧，处理线程拿最新帧并允许丢帧；离线分析则应保留全部帧。最小结构如下：

import threading, time

latest, ts, lock, running = None, 0.0, threading.Lock(), True

def grab_loop():
    global latest, ts, running
    while running:
        ok, frame = cap.read()
        if not ok:
            running = False
            break
        with lock:
            latest, ts = frame, time.monotonic()

threading.Thread(target=grab_loop, daemon=True).start()
# 处理线程中：with lock: frame = latest.copy(); frame_ts = ts

性能清单：测各阶段耗时；降低分辨率、裁剪 ROI、灰度化；检测器隔帧运行；减少拷贝；显示和写视频也要计时；比较 V4L2/GStreamer/FFmpeg、MSMF/DSHOW、AVFoundation；硬件解码、CUDA、OpenCL 要算上传下载成本；明确低延迟还是全帧完整。

11. 常见故障

  • cap.isOpened() 为假：路径或权限错误、URL 不通、后端不可用、文件编码不支持。
  • CAP_PROP_FPS 为 0：摄像头或直播流没有可靠声明，用墙钟估计。
  • VideoWriter 输出空文件：fourcc/容器不匹配、尺寸不一致、编码器缺失、没有 release()。
  • 颜色不对：OpenCV 默认 BGR，某些管线可能返回 RGB/YUV，检查后端和 CAP_PROP_CONVERT_RGB。
  • 背景减除全屏误报：自动曝光、灯光变化、摄像头抖动、学习率过大。
  • LK 点越来越少：纹理不足、位移过大、模糊或遮挡，需调金字塔或重检测。
  • 稠密光流噪声大：亮度假设被破坏，先归一化、降噪或调大窗口。
  • tracker 接口不存在：缺少 opencv-contrib-python，或版本中接口移到 cv.legacy。
  • 无头环境 GUI 报错：使用 headless 包并移除 imshow()/selectROI() 等交互。

12. 练习

  1. 打开同一视频，打印 FPS、FRAME_COUNT、POS_MSEC，比较声明时间和墙钟时间。
  2. 分别尝试 MJPG、XVID、mp4v 写出视频，记录你的系统可用组合。
  3. 用帧差、MOG2、KNN 做固定摄像头运动检测，比较光照变化和目标停止时的结果。
  4. 用 LK 跟踪角点，并加入点数少于阈值时自动重检测。
  5. 用 Farneback 生成运动幅值统计，调 winsize、levels 并记录耗时。
  6. 安装 contrib 包后测试 CSRT/KCF，并写兼容 cv.legacy 的创建函数。
  7. 设计“每 10 帧检测一次，其余帧跟踪”的流程，并用 LK + 仿射估计做简单视频稳定。

小结

视频算法的关键是时间、缓冲和可靠性。VideoCapture/VideoWriter 不消除后端差异；背景建模适合固定机位；光流依赖亮度恒定、小位移和局部一致；跟踪器会漂移，检测器更稳但更慢。实际系统要组合检测、跟踪、光流、运动估计和缓冲策略，在准确性、吞吐和延迟之间取舍。
