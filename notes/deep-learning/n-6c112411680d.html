学习目标

  • 用结构化答案覆盖视觉任务、模型、训练、指标、部署和工业落地。
  • 面试回答做到先定义问题，再讲原理、取舍、工程风险和验证方法。
  • 能把单点知识与前文笔记串联：见 07_视觉任务与典型模型.md、08_训练_损失_数据与诊断.md、09_评价指标与误差分析.md、10_推理部署与工业视觉.md。

答题框架

回答技术题可按这个顺序组织：

  1. 定义：先说输入、输出、目标和约束。
  2. 原理：讲核心机制，不背名词。
  3. 取舍：说明优缺点和适用场景。
  4. 工程：补充数据、训练、指标、部署风险。
  5. 验证：说如何用实验、可视化、切片指标证明。

1. CNN 和 Transformer/ViT 在视觉任务中的区别是什么？

答案框架：

  • CNN 有局部感受野、权重共享和平移等变先验，适合低层纹理、边缘、小数据和高效部署。
  • Transformer/Self-Attention 直接建模 token 间全局关系，适合长距离依赖和大规模预训练迁移。
  • ViT 把图像切 patch 后作为 token 输入，弱化卷积先验，通常更依赖数据量、预训练、增强和正则化。
  • 混合结构用 CNN 提供局部特征和降采样，用 attention 建模全局上下文。
  • 工程选择看数据量、任务、小目标比例、延迟预算和硬件。

延伸阅读：07_视觉任务与典型模型.md

2. U-Net 的 skip connection 为什么重要？

答案框架：

  • U-Net 是 encoder-decoder 结构，encoder 下采样提取语义，decoder 上采样恢复分辨率。
  • 下采样会丢失边界和精细定位信息。
  • skip connection 把 encoder 中同尺度的低层空间细节传给 decoder。
  • 高层语义决定类别，低层细节帮助恢复边界。
  • 对医学图像、小目标分割、边界敏感任务尤其重要。

常见追问：skip 是拼接还是相加？两者都可用，拼接保留信息更多但通道和计算增加，相加更轻量但要求特征对齐更强。

3. Mask R-CNN 相比 Faster R-CNN 多了什么？

答案框架：

  • Faster R-CNN 做目标检测，输出类别和边框。
  • Mask R-CNN 在检测基础上增加 mask head，为每个 RoI 预测实例 mask。
  • 使用 RoIAlign 替代粗糙量化的 RoIPool，提升像素级对齐。
  • loss 通常包括分类、框回归和 mask 分支损失。
  • 评估要看 box AP 和 mask AP，不能只看检测框。

适用场景：需要知道每个实例精确轮廓，如缺陷区域、医学病灶、物体抓取。

4. 目标检测里 mAP@0.5 和 mAP@0.5:0.95 有什么区别？

答案框架：

  • AP 是某一类别 PR 曲线下的面积，mAP 是各类别 AP 平均。
  • mAP@0.5 使用 IoU 0.5 判断 TP，定位要求相对宽松。
  • mAP@0.5:0.95 在多个 IoU 阈值上平均，更严格，更能反映定位质量。
  • 若 @0.5 高但 @0.5:0.95 低，说明模型能找到目标但框不够准。
  • 分析时要结合小中大目标 AP、可视化和 NMS 参数。

延伸阅读：09_评价指标与误差分析.md

5. Precision、Recall、F1 如何理解？阈值怎么选？

答案框架：

  • Precision 关注预测为正的样本有多少是真的，误报成本高时重要。
  • Recall 关注真实正样本有多少被找回，漏报成本高时重要。
  • F1 是 precision 和 recall 的调和平均。
  • 阈值升高通常 precision 上升、recall 下降；阈值降低通常 recall 上升、precision 下降。
  • 阈值应由业务成本、人工复核能力、安全要求和 PR 曲线决定，不应固定迷信 0.5。

工程补充：不同类别可设置不同阈值，上线后要监控置信度分布漂移。

6. CE、BCE、Focal、Dice、IoU Loss 分别适合什么？

答案框架：

  • CE：单标签多分类，概念上对应 softmax；常用实现直接接收 logits。
  • BCE：二分类或多标签分类，概念上对应各类别独立 sigmoid；BCEWithLogitsLoss 直接接收 logits。
  • Focal：类别或前景背景不平衡，降低易样本权重，检测中常见。
  • Dice：分割中前景很小或类别不平衡，关注区域重叠。
  • IoU/GIoU/DIoU/CIoU：检测框回归，直接优化框重叠和几何关系。
  • 实际项目常组合使用，如 BCE + Dice、分类 loss + box loss + mask loss。

延伸阅读：08_训练_损失_数据与诊断.md

7. 训练中如何判断过拟合和欠拟合？

答案框架：

  • 过拟合：训练 loss 下降、训练指标高，但验证 loss 上升或验证指标下降。
  • 欠拟合：训练集也学不好，训练 loss 高或指标低。
  • 过拟合优先查划分泄漏、验证集代表性、数据量、增强、正则化、模型容量。
  • 欠拟合优先查标签、预处理、loss、学习率、增强过强、模型容量不足。
  • 单 batch 过拟合是强诊断手段：如果单 batch 都拟合不了，多半是代码、标签或 loss 问题。

8. 如何避免数据泄漏？

答案框架：

  • 不只按图片随机划分，要按实体、视频、设备、时间或场景隔离。
  • 同一视频相邻帧、同一工件、同一病人、同一相机点位不能跨 train/test。
  • 增强应在划分后进行，不能先增强再随机划分。
  • 测试集不能参与阈值选择、模型选择、早停和调参。
  • 检查文件名、背景、水印、采集设备是否暗含标签。

工程补充：固定测试集版本，每次报告写清样本量、划分规则和类别分布。

9. SGD、Adam/AdamW、warmup、cosine 学习率如何选择？

答案框架：

  • SGD with momentum 泛化稳定，是 CNN 训练常见基线。
  • Adam/AdamW 收敛快，对 Transformer、ViT 和微调常用。
  • AdamW 解耦 weight decay，现代深度学习中常比 Adam + L2 更稳。
  • warmup 在训练初期逐步增大学习率，减少大 batch、预训练模型或 Transformer 的初始震荡。
  • cosine decay 平滑降低学习率，常与 warmup 组合。
  • 最终要看 loss 曲线、验证指标和不同 seed 的稳定性。

10. 数据增强应该怎么设计？

答案框架：

  • 增强应模拟真实分布变化，如光照、模糊、噪声、裁剪、尺度、遮挡。
  • 检测、分割、关键点增强必须同步变换标签。
  • OCR、医学、工业任务不能随意翻转或旋转，需确认语义是否改变。
  • 小目标任务要防止 crop/resize 直接删掉目标。
  • mixup、cutmix、mosaic 可提升鲁棒性，但可能影响定位、边界或置信度校准。
  • 判断增强是否有效，要看真实验证集和切片指标，不是只看训练 loss。

11. 模型导出到 ONNX/TensorRT 时常见问题有哪些？

答案框架：

  • ONNX 是交换格式，TensorRT 是 NVIDIA GPU 推理优化引擎。
  • 常见问题包括动态 shape、非支持算子、NMS/RoIAlign/grid_sample 插件、预处理不一致。
  • FP16/INT8 可能改变输出分布，阈值需要重新验证。
  • 要用固定样例对齐 PyTorch、ONNX Runtime、TensorRT 输出。
  • 验证应包括精度、延迟、吞吐、显存和异常输入。

延伸阅读：10_推理部署与工业视觉.md

12. FP32、FP16、INT8、PTQ、QAT 如何取舍？

答案框架：

  • FP32 稳定但慢、显存大，适合训练和基准。
  • FP16 通常在 GPU 上加速明显，精度损失较小，是常见首选部署优化。
  • INT8 更快更省内存，但对量化校准和分布变化敏感。
  • PTQ 成本低，用校准集做训练后量化，适合快速尝试。
  • QAT 在训练中模拟量化误差，精度更稳但流程更复杂。
  • 量化后必须看真实测试集、切片指标、小目标、边界和置信度阈值。

13. 工业视觉项目如何排查线上效果变差？

答案框架：

  • 先确认输入链路：图像是否为空、分辨率、颜色空间、相机曝光、光源。
  • 再查预处理：resize、padding、归一化、RGB/BGR 是否和训练一致。
  • 查模型版本、类别表、后处理阈值、NMS、坐标缩放。
  • 对比 FP32 与部署引擎输出，排除导出和量化问题。
  • 做切片分析：新产品、光照、设备、班次、材料、污染、磨损。
  • 保存失败样本，判断该补数据、调阈值、修后处理还是回滚模型。

14. PatchCore、PaDiM、EfficientAD 这类异常检测方法的核心思想是什么？

答案框架：

  • 适合缺陷少、异常类型未知或异常标注成本高的工业场景。
  • PatchCore 用预训练特征建立正常 patch 特征库，测试时用最近邻距离找异常。
  • PaDiM 对每个空间位置的正常特征建高斯分布，用 Mahalanobis distance 衡量偏离。
  • EfficientAD 用高效 teacher-student 或 autoencoder 结构产生异常响应。
  • 局限是对位置、光照、产品姿态和正常样本覆盖敏感，阈值需要按产线校准。

15. 如果检测模型误报很多，你会怎么处理？

答案框架：

  • 先确认标注是否漏标；漏标会把正确预测算成 FP。
  • 看误报类型：背景纹理、相似类别、重复框、低质量图、阈值过低。
  • 调整置信度阈值和 NMS，观察 PR 曲线。
  • 补充 hard negative，特别是高频误报背景。
  • 检查类别定义是否重叠，必要时合并或重标。
  • 再考虑 Focal Loss、采样策略、模型容量和输入分辨率。

16. 如果检测模型漏检小目标，你会怎么处理？

答案框架：

  • 先按目标尺寸切片确认小目标 AP/AR 是否低。
  • 检查标注一致性和小目标是否被 resize/crop 增强破坏。
  • 提高输入分辨率，调整 feature stride、FPN 层级或 anchor/assigner。
  • 增加小目标样本和场景增强。
  • 降低阈值可能提高召回，但要评估误报。
  • 若部署受限，要权衡分辨率、速度和显存。

17. 语义分割和实例分割有什么区别？

答案框架：

  • 语义分割给每个像素分配类别，不区分同类不同对象。
  • 实例分割既要像素级 mask，也要区分每个实例身份。
  • 语义分割常用 mIoU、Dice，实例分割常用 mask AP。
  • 若只关心道路、天空、背景区域，用语义分割；若要数每个零件或缺陷实例，用实例分割。
  • 实例分割通常更复杂，对标注和推理成本要求更高。

18. 如何做一次完整的视觉模型实验报告？

答案框架：

  • 写清数据集版本、划分方式、样本量、类别分布。
  • 写清模型、输入尺寸、预训练、训练参数、增强、loss。
  • 给主指标、分类别指标、切片指标和阈值。
  • 放成功案例与失败案例，解释主要错误来源。
  • 给部署指标：延迟、吞吐、显存、模型大小。
  • 给结论：是否达到业务目标，下一步优先改数据、模型、阈值还是部署。

19. CNN 为什么适合处理图像？

答案框架：

  • 局部连接利用了图像局部像素强相关的结构，先学习边缘、纹理等局部模式。
  • 权重共享使同一卷积核能在不同位置检测相同模式，参数量远少于同尺寸全连接层。
  • 卷积具有平移等变性：输入平移会使特征响应相应平移；池化、下采样和数据增强再提供一定平移鲁棒性。
  • 多层堆叠形成“像素 → 边缘/纹理 → 部件 → 目标”的层次化表示。
  • 代价是局部归纳偏置限制直接全局建模，因此常用大感受野、注意力或混合结构补充。

20. 卷积核、stride、padding、channel 分别是什么？

答案框架：

  • kernel size 决定一次聚合的局部范围；多个 3×3 可用更少参数和更多非线性获得较大感受野。
  • stride 是滑动步长，增大 stride 会下采样，减少空间尺寸和计算，但可能损失小目标细节。
  • padding 是边界填充，用于控制输出尺寸和保留边缘位置；填充值和边界模式也会影响结果。
  • 输入 channel 是输入特征种类，输出 channel 等于卷积核组数，代表网络学习的不同特征响应。
  • 必须会用输出尺寸公式，并区分张量布局 NCHW 与 NHWC。

21. 什么是感受野？为什么需要大感受野？

答案框架：

  • 某层一个位置在原图上能够影响到的区域叫感受野。
  • 浅层小感受野适合边缘和纹理；识别完整目标、处理遮挡或利用上下文需要更大感受野。
  • 堆叠卷积、stride/pooling、空洞卷积、金字塔和 attention 都能扩大或补充上下文。
  • 理论感受野不等于有效感受野；信息经过过多下采样也可能丢失精确定位。
  • 检测和分割要同时兼顾大上下文与高分辨率细节，因此需要 FPN、skip connection 等结构。

22. ResNet 为什么有效？残差连接解决什么问题？

答案框架：

  • 普通网络加深后可能出现训练误差反而上升的退化问题，并伴随优化与梯度传播困难。
  • ResNet 把目标映射写成 \(H(x)=F(x)+x\)，让分支学习残差 \(F(x)\)。
  • shortcut 给前向信息和反向梯度提供直接路径；若额外层暂时无益，让 \(F(x)\) 接近 0 比重新拟合恒等映射更容易。
  • 输入输出 shape 不同需要 projection shortcut；BN/激活位置又区分 post-activation 与 pre-activation。
  • 残差不能保证任意深度都更好，它改善的是可优化性，仍受数据、计算、正则化和结构设计约束。

23. 图像分类和目标检测有什么区别？

答案框架：

  • 分类输入整图，输出图像级类别；检测还要输出每个实例的位置、类别和置信度。
  • 分类常用图像级标签和 CE/BCE；检测需要框标注、正负样本分配、分类与框回归等多项损失。
  • 检测必须处理多尺度、多个实例、密集候选、坐标解码和 NMS/集合去重。
  • 分类常看 Accuracy/F1；检测看 AP/mAP、Recall、定位质量和不同尺寸目标表现。
  • 如果业务只需要判断“有没有缺陷”，不必为了展示定位而承担检测标注与部署成本。

24. YOLO 的 Backbone、Neck、Head 分别负责什么？

答案框架：

  • Backbone 从图像提取多层特征，浅层空间细节多，深层语义强。
  • Neck 用 FPN/PAN 等结构融合不同尺度，让高分辨率层获得语义、低分辨率层补充定位信息。
  • Head 在各尺度上输出类别、框和目标质量/置信度；解耦头把分类与回归分支分开优化。
  • 推理阶段还需要坐标解码、阈值过滤和 NMS；所以 YOLO 不是只有一个 Backbone。
  • 选型要联动输入分辨率、小目标比例、算子支持、端到端时延和内存，而不是只比较模型代号。

25. IoU、NMS、Precision、Recall、mAP 如何串起来？

答案框架：

  • IoU 衡量预测框和真实框的重叠；评估时用于决定定位是否达标，训练时也可构造框损失。
  • NMS 是推理后处理：按分数保留代表框并抑制高度重叠的重复候选。
  • 在指定置信度与 IoU 匹配规则下统计 TP/FP/FN，得到 Precision 和 Recall。
  • 扫描置信度阈值得到 PR 曲线，单类曲线面积是 AP，多类别再平均得到 mAP。
  • 业务工作阈值与评测阈值不是一回事；必须报告匹配协议、NMS、类别/尺寸切片和实际漏检成本。

26. 训练效果不好时如何系统排查？

答案框架：

  1. 数据：覆盖度、重复、长尾、域差异和脏图。
  2. 标注：漏标、错标、边界/框规范和类别定义一致性。
  3. 划分：同对象、相邻帧、设备或时间泄漏，测试集是否参与调参。
  4. 输入：RGB/BGR、resize、padding、归一化和标签变换是否对齐。
  5. 训练：单 batch 能否过拟合，学习率、梯度、batch、冻结层与增强是否合理。
  6. 损失与匹配：各分量量级、正负样本分配和实现是否正确。
  7. 后处理与指标：坐标还原、阈值、NMS、mask resize 和评测协议。
  8. 部署：框架输出对齐、精度模式、量化、动态 shape 与算子回退。

只有前面链路有证据正常后，才把换模型作为主要变量。

27. 为什么视觉系统不能只看模型精度？

答案框架：

  • 离线平均指标不直接等于业务价值：不同类别的漏检/误检成本不同，平均值还会掩盖长尾场景。
  • 实时系统还受端到端 P95/P99 latency、throughput、峰值内存、功耗、冷启动和稳定性约束。
  • 成像质量、预处理、后处理、时序过滤、规则、通信和执行机构都会改变最终结果。
  • FLOPs 和参数量只是代理指标，实际延迟取决于算子、硬件利用率、内存带宽、数据搬运和 batch。
  • 验收应在目标硬件和真实分布上联合评价精度、漏检率、延迟、吞吐、资源、鲁棒性和成本。

面试回答注意事项

  • 不要只背模型名，要说明为什么适合任务。
  • 指标必须结合阈值、数据分布和业务成本。
  • 遇到线上问题先查数据链路和预处理，不要直接换模型。
  • 对工业视觉，成像、光源、标注和闭环通常比追新模型更重要。
  • 任何优化都要用固定测试集和切片评估验证。
