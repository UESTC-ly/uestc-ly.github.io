1. 概念：OpenCV 5 与 4.x 的版本定位

OpenCV 是面向计算机视觉和机器学习的开源库，常用接口包括 C++、Python、Java 和 JavaScript。本讲义以 OpenCV 5.0 为主线，同时兼顾仍被大量项目使用的 4.x，尤其是 4.12。学习第 1 章时，不要急着写复杂算法，先把三个事实记牢：第一，OpenCV 处理的图像本质上是数值矩阵；第二，Python 接口里这块矩阵通常表现为 numpy.ndarray；第三，C++ 接口里同一块数据通常表现为 cv::Mat。

OpenCV 5.0 是基于 4.x 演进出的主版本。官方文档明确列出若干重要变化：C++17 成为最低 C++ 标准要求；Python 2 已被移除，Python 3.6+ 是要求；旧 C API 被移除；核心模块增加了 CV_16BF、CV_32U、CV_64U、CV_64S、CV_Bool 等数据类型，并改进了 0 维和 1 维数组支持；原来的 calib3d 被拆分到 geometry、calib、stereo、ptcloud 等模块。对初学图像读写、矩阵、通道和 ROI 来说，4.x 与 5.0 的多数 API 仍保持连续，但工程配置、模块边界和少数默认行为需要留意。

截至本章写作时，OpenCV 官方 GitHub releases 中可以看到 5.0.0、4.12.0 以及后续 4.x release 同时存在。也就是说，OpenCV 5 是主版本演进方向，4.x 仍是很多生产环境、课程环境和第三方包的基础。Python 端尤其要注意：你通过 pip install opencv-python 安装到的具体版本由 PyPI wheel 发布节奏决定，未必就是你阅读的文档主版本。写代码时应先打印 cv.__version__，再按当前环境验证 API。

4.12 与 5.0 的学习差异可以这样处理：核心概念用 5.0 讲，API 先学稳定入口，例如 cv.imread、cv.imwrite、cv.imshow、cv.cvtColor、cv.split、cv.merge、Mat::clone、Mat::copyTo；遇到模块拆分、C++ 标准、数据类型、默认 flag 等问题时，再按实际版本查文档。特别是 OpenCV 5 的 imread 文档中，默认读取 flag 写为 IMREAD_COLOR_BGR，用于明确默认彩色输出是 BGR 顺序；很多 OpenCV 4.x 教材仍写 IMREAD_COLOR。二者在常规彩色读取场景下都表示读成三通道 BGR，但 5.0 文档命名更清楚。

学习时还要区分“库版本”和“绑定版本”。C++ 程序链接的是本机安装或项目构建出的 OpenCV 库，头文件、动态库和运行期库必须互相匹配；Python 程序导入的是当前解释器环境里的 cv2 扩展模块，它内部已经打包或链接了相应 OpenCV 构建。很多“我明明装了 OpenCV 但导入失败”的问题，本质上是 IDE 选择了另一个 Python 解释器，或者系统里同时存在多个 OpenCV 动态库。排查顺序应从当前进程出发：Python 先看 sys.executable、cv.__version__ 和 cv.getBuildInformation()；C++ 先看编译命令、链接库路径和程序运行时加载到的库版本。不要只凭系统包管理器显示“已安装”就断定运行环境正确。

本章不会深入所有模块，但需要知道模块边界如何影响 include 和链接。C++ 中只使用矩阵和基础类型时，包含 <opencv2/core.hpp> 即可；读写图片需要 <opencv2/imgcodecs.hpp>；窗口显示需要 <opencv2/highgui.hpp>；颜色转换、绘图、阈值和滤波多在 <opencv2/imgproc.hpp>。Python 中这些模块都挂在 cv2 命名空间下，看起来更统一，但底层仍对应不同模块。理解模块边界有两个好处：一是 C++ 编译时可以写出更清晰的依赖；二是报错时能迅速判断问题来自文件编解码、GUI 后端、核心矩阵还是图像处理算法。

2. 原理：图像就是矩阵，矩阵元素就是像素

数字图像可以看成二维网格。灰度图每个位置通常只有一个强度值；彩色图每个位置有多个通道，例如 B、G、R 三个值。OpenCV 延续矩阵习惯：先行后列，行对应 y 坐标，列对应 x 坐标。因此，访问像素时写 img[y, x]，而不是 img[x, y]。这是很多新手的第一个错误来源。

在 Python 中，cv.imread("a.jpg") 返回的通常是 numpy.ndarray。如果读取失败，返回 None，不能直接访问 .shape。彩色图常见形状是 (height, width, channels)，例如 (480, 640, 3)；灰度图常见形状是 (height, width)。img.shape[0] 是高或行数，img.shape[1] 是宽或列数，img.shape[2] 才是通道数。img.dtype 说明每个通道的数值类型，最常见是 uint8，取值范围是 0 到 255。

在 C++ 中，cv::Mat 是 OpenCV 最重要的矩阵容器。一个 Mat 对象包含头部和数据区：头部记录尺寸、类型、步长、引用计数等元信息；数据区保存真实像素。Mat 的赋值和拷贝构造默认只复制头部，底层数据共享；需要深拷贝时使用 clone() 或 copyTo()。这种设计让 ROI、临时矩阵和函数返回值很高效，但也意味着“改一个视图会影响原图”。

把图像看成矩阵，并不意味着可以忽略图像语义。矩阵只负责存数，数值代表什么取决于类型、通道顺序和颜色空间。同样是三通道 uint8，它可以表示 BGR，也可以表示 RGB、HSV、Lab，甚至是某个模型的三张特征图。OpenCV 函数通常不会把“这张图到底是什么颜色空间”写入矩阵元数据，它只按你传入的 flag 和函数约定解释数据。因此，代码中应通过变量名和转换步骤保留语义，例如 bgr、rgb、gray、hsv，而不是所有变量都叫 img2、dst。矩阵层面的尺寸正确，并不能证明颜色语义正确。

图像矩阵还有一个重要特点：通道通常交错存储。常见 CV_8UC3 图像在内存中不是先放完整蓝色平面、再放绿色平面、再放红色平面，而是按像素交错为 B,G,R,B,G,R,...。这让单个像素访问很自然，也符合许多图像编解码和显示后端的习惯。相对地，某些深度学习框架偏好 C,H,W 的平面格式。把 OpenCV 图像送入模型时，常见预处理包括 BGR 转 RGB、H,W,C 转 C,H,W、uint8 转浮点、归一化和增加 batch 维度。不要把这些步骤混在一起省略说明，否则后续排错会非常困难。

shape、rows、cols、channels

Python：

  • img.shape：数组形状。彩色图通常是 (rows, cols, 3)，灰度图通常是 (rows, cols)。
  • img.ndim：维度数。灰度图常为 2，彩色图常为 3。
  • img.shape[:2]：高和宽。
  • img.shape[2] if img.ndim == 3 else 1：通道数。

C++：

  • img.rows：行数，即高度。
  • img.cols：列数，即宽度。
  • img.channels()：通道数。
  • img.size()：二维尺寸，常以 cv::Size(width, height) 表示，注意它的参数顺序是宽在前、高在后。

dtype、depth、type

Python 的 dtype 对应 NumPy 数据类型，例如 np.uint8、np.float32。OpenCV C++ 中常用 depth() 表示单通道元素深度，例如 CV_8U、CV_32F；type() 同时编码深度和通道数，例如 CV_8UC3 表示 8 位无符号、3 通道。把这两个概念分清很重要：CV_8U 不是一张完整彩色图的类型，只是单个通道的深度；CV_8UC3 才说明它有 3 个通道。

步长与连续性

矩阵每一行在内存中占多少字节，称为步长。Python 中是 img.strides，C++ 中是 img.step。如果一张图是连续存储的，逐行数据在内存里没有额外间隔，Python 中 img.flags["C_CONTIGUOUS"] 多半为真，C++ 中 img.isContinuous() 为真。整图通常连续，但 ROI、切片、转置后的视图常常不是连续的。

连续性影响性能和接口兼容性。例如你把 ROI 传给只接受连续缓冲区的第三方库时，最好先执行 np.ascontiguousarray(roi)；C++ 中可以在必要时用 roi.clone() 得到独立连续矩阵。不要把 shape 正确误认为内存布局也一定正确。

ROI 浅拷贝与深拷贝

ROI 是 region of interest，即感兴趣区域。Python 中 roi = img[y1:y2, x1:x2] 是 NumPy 视图，通常共享底层数据；C++ 中 cv::Mat roi = img(rect) 也只是新建一个头部，指向原图的一部分。修改 ROI，会修改原图对应区域。要得到独立副本，Python 用 roi.copy()，C++ 用 roi.clone() 或 roi.copyTo(dst)。

这个规则也适用于通道切片。例如 blue = img[:, :, 0] 通常是视图，直接赋值会改原图蓝色通道。通道拆分 cv.split(img) 在 Python 中会返回独立的单通道数组；C++ 中 cv::split 输出单通道 Mat。如果只是简单置零某个通道，直接切片往往更快，但要清楚它是在原图上改。

浅拷贝不是缺陷，而是 OpenCV 高性能设计的一部分。许多算法会在流水线中不断生成中间区域，如果每一步都复制完整像素，内存和时间成本会迅速上升。问题出在程序员没有标明“这个变量是视图还是副本”。一个实用习惯是：变量名中使用 roi、view 表示共享数据，用 copy、clone 表示独立数据；函数参数中如果会原地修改图像，应在函数名或注释中明确。例如 draw_boxes_inplace(image, boxes) 比 draw_boxes(image, boxes) 更容易让调用者意识到原图会被改变。C++ 中也可以用 const cv::Mat& 表示只读输入，用单独的输出参数承载结果。

深拷贝也不是越多越安全。对大图或视频帧循环来说，反复 copy()、clone() 会显著拖慢程序。判断是否需要深拷贝，可以问三个问题：后续是否要保留原图不变；这块数据是否要脱离原图生命周期长期保存；接收方是否要求连续独立缓冲区。只要有一个答案为是，就考虑深拷贝。否则，保留浅视图通常更合适。这个判断能力比机械记忆 API 更重要。

3. API：安装、版本检查与核心模块

Python 安装

官方 Python pip 教程建议在虚拟环境中安装，并且四个 wheel 变体只能选一个：

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install opencv-python

服务器、Docker、CI 或没有桌面 GUI 的环境，应优先选择 headless 版本：

python -m pip install opencv-python-headless

如果需要 xfeatures2d 等 contrib 扩展模块，再选择：

python -m pip install opencv-contrib-python

不要在同一个环境里同时安装 opencv-python、opencv-python-headless、opencv-contrib-python、opencv-contrib-python-headless。它们都提供 cv2 包，混装会让导入路径和动态库来源变得不可预测。检查方式如下：

import cv2 as cv

print("OpenCV version:", cv.__version__)
print("Build contains GUI info:")
print(cv.getBuildInformation().split("GUI:")[1].splitlines()[0].strip())

C++ 安装与版本检查

C++ 端安装方式因系统而异：可以使用系统包管理器、OpenCV 官方预编译包，或从源码编译。OpenCV 5 要求 C++17，所以 CMake 工程至少应设置：

cmake_minimum_required(VERSION 3.16)
project(opencv_ch01 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(OpenCV REQUIRED)
add_executable(version_check main.cpp)
target_link_libraries(version_check PRIVATE ${OpenCV_LIBS})

main.cpp：

#include <opencv2/core.hpp>
#include <iostream>

int main() {
    std::cout << "OpenCV version: " << CV_VERSION << '\n';
    std::cout << cv::getBuildInformation() << '\n';
    return 0;
}

OpenCV 的基础模块可以先按任务理解：

  • core：矩阵、数组运算、基础数据结构、通道拆分合并、掩膜和数学函数。
  • imgcodecs：图像文件读写，例如 imread、imwrite。
  • highgui：简单窗口显示和键盘事件，例如 imshow、waitKey。
  • imgproc：图像处理，例如颜色空间转换、滤波、几何变换、阈值、形态学。
  • videoio：摄像头和视频文件输入输出。
  • dnn：深度神经网络推理。

第 1 章主要使用 core、imgcodecs、highgui 和少量 imgproc。

图像读写与显示 API 的工作边界

imread 负责从文件解码成矩阵。官方文档说明，文件类型主要由内容而不是扩展名判断；读取失败时返回空矩阵；彩色图像解码后的通道按 BGR 顺序存储。这意味着 .jpg 后缀并不能保证文件真的是 JPEG，路径存在也不保证解码成功。实际工程中，读图之后必须检查结果，同时把错误信息写得足够具体，包括路径、当前工作目录、期望格式和 OpenCV 版本。

imwrite 负责把矩阵编码到文件。格式由输出文件扩展名决定，返回值是布尔值。很多初学者忽略这个返回值，以为没有异常就是保存成功；但路径不可写、扩展名不支持、图像类型不合适时都可能失败。稳妥写法是检查输出目录是否存在，调用后判断返回值，必要时打印 cv.haveImageWriter(".png") 这样的能力检查。

imshow 是开发调试工具，不是通用输出接口。它依赖 HighGUI 后端和系统图形环境；显示窗口还需要 waitKey 或 pollKey 处理事件。服务器程序、批处理脚本、在线评测和 CI 中，保存图片或导出数组通常比弹窗更可靠。如果你写的课程代码要在不同机器上运行，应提供 --show 开关，而不是默认弹窗。

掩膜的含义

掩膜是一张与原图宽高一致的单通道图，用来说明哪些位置参与计算。OpenCV 中许多 mask 参数约定非零即有效，常用 255 表示有效、0 表示无效。掩膜本身不是透明度图，也不是颜色图。它只控制某些操作应用到哪里。比如 cv.bitwise_and(src, src, mask=mask) 会保留掩膜非零处的像素，把其他位置置为零；而 copyTo 的 mask 版本会只复制掩膜非零处的数据。理解这个约定后，阈值分割、目标提取、局部增强和背景替换都会变得更清晰。

掩膜的尺寸、类型和通道数必须谨慎检查。尺寸不匹配通常会触发 OpenCV 断言；三通道 mask 不是大多数 API 期望的 mask；布尔数组在 Python 里有时需要显式转换为 uint8。常见写法是先得到布尔条件，再转为 0/255：mask = (gray > 128).astype(np.uint8) * 255。这样打印和保存时也更直观。

4. Python 示例：读写、矩阵属性、像素、通道与掩膜

下面的示例是一个可运行脚本。它包含输入检查；如果没有 GUI，就只保存结果，不强行调用 imshow。

from pathlib import Path
import argparse
import os

import cv2 as cv
import numpy as np


def has_display() -> bool:
    if os.name == "nt":
        return True
    return bool(os.environ.get("DISPLAY") or os.environ.get("WAYLAND_DISPLAY"))


def describe_image(name: str, img: np.ndarray) -> None:
    if img is None:
        raise ValueError(f"{name} is None")
    if img.ndim not in (2, 3):
        raise ValueError(f"{name} must be a 2D grayscale or 3D color image")

    rows, cols = img.shape[:2]
    channels = img.shape[2] if img.ndim == 3 else 1
    print(f"{name}: rows={rows}, cols={cols}, channels={channels}")
    print(f"{name}: shape={img.shape}, dtype={img.dtype}, strides={img.strides}")
    print(f"{name}: contiguous={img.flags['C_CONTIGUOUS']}")


def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("input", help="path to an input image")
    parser.add_argument("--out", default="ch01_output.png", help="output image path")
    parser.add_argument("--show", action="store_true", help="show window when GUI is available")
    args = parser.parse_args()

    input_path = Path(args.input)
    if not input_path.is_file():
        raise FileNotFoundError(f"input image not found: {input_path}")

    img = cv.imread(str(input_path), cv.IMREAD_COLOR)
    if img is None:
        raise ValueError(f"OpenCV cannot decode image: {input_path}")

    describe_image("img", img)

    rows, cols = img.shape[:2]
    y, x = rows // 2, cols // 2
    b, g, r = img[y, x]
    print(f"center pixel at (x={x}, y={y}): B={b}, G={g}, R={r}")

    result = img.copy()

    # ROI 是浅视图；这里有意在 result 上修改，不影响原始 img。
    y1, y2 = rows // 4, rows * 3 // 4
    x1, x2 = cols // 4, cols * 3 // 4
    roi = result[y1:y2, x1:x2]
    if roi.size == 0:
        raise ValueError("computed ROI is empty")

    roi[:, :, 1] = np.clip(roi[:, :, 1].astype(np.int16) + 60, 0, 255).astype(np.uint8)

    blue, green, red = cv.split(result)
    merged = cv.merge([blue, green, red])
    if merged.shape != result.shape:
        raise RuntimeError("split/merge changed image shape unexpectedly")

    mask = np.zeros((rows, cols), dtype=np.uint8)
    cv.circle(mask, (cols // 2, rows // 2), min(rows, cols) // 4, 255, thickness=-1)
    foreground = cv.bitwise_and(merged, merged, mask=mask)

    ok = cv.imwrite(args.out, foreground)
    if not ok:
        raise OSError(f"failed to write output image: {args.out}")
    print(f"wrote: {args.out}")

    if args.show:
        if has_display():
            cv.imshow("foreground", foreground)
            cv.waitKey(0)
            cv.destroyAllWindows()
        else:
            print("GUI display is not available; skipped imshow")

    return 0


if __name__ == "__main__":
    raise SystemExit(main())

这段代码体现了几个基础习惯。读图后第一时间检查 img is None；读取彩色图后，像素顺序按 BGR 解包；访问中心像素时用 [y, x]；对 ROI 修改前先用 result = img.copy() 隔离原图；写文件检查 cv.imwrite 的布尔返回值；无 GUI 环境不调用 imshow。

示例中对绿色通道增强时，先把 uint8 转成 int16，再 clip 回 0 到 255，最后转回 uint8。这样写是为了避免 NumPy 的无符号整数溢出。若直接让 uint8 加 60，超过 255 的值会按 256 取模，视觉结果会突然变暗。OpenCV 自带的 cv.add 使用饱和语义，更接近图像处理直觉；NumPy 的行为更接近底层数组运算。两者没有谁绝对正确，关键是你要知道自己选择的是哪一种数学规则。

示例还刻意把原图复制到 result 后再修改 ROI。这样做便于教学，因为 img 保持原始输入，result 是处理输出。在真实项目里，如果任务就是原地标注或原地预处理，可以不复制；但函数名、文档或调用约定要讲清楚。大量 bug 都来自调用者以为函数返回新图，实际函数悄悄改了传入图。

如果要把 OpenCV 的 BGR 图像交给 Matplotlib、Pillow 或许多深度学习可视化工具，通常需要转换为 RGB：

rgb = cv.cvtColor(img, cv.COLOR_BGR2RGB)

反过来，从 RGB 库得到的三通道数组交给 OpenCV 保存或处理前，应确认是否需要转回 BGR：

bgr = cv.cvtColor(rgb, cv.COLOR_RGB2BGR)
cv.imwrite("from_rgb_source.png", bgr)

掩膜在 OpenCV 中通常是一张单通道 uint8 图，与被处理图像宽高相同。非零位置表示参与处理，零位置表示不参与。很多 API 的 mask 参数都遵循这个约定。掩膜不是三通道彩色图，也不是布尔数组；虽然 Python 有时会接受可转换数据，但初学阶段建议显式构造 np.uint8 的 0/255 掩膜。

从 Python 过渡到 C++ 时，最容易不适应的是类型显式化。Python 中 img[y, x] 可以直接返回一个小数组；C++ 中必须告诉编译器这个像素是什么类型。类型显式化让 C++ 更快，也让错误更早暴露。初学阶段可以把常见类型背下来：灰度 8 位图用 uchar；BGR 8 位图用 cv::Vec3b；灰度 32 位浮点图用 float；BGR 32 位浮点图用 cv::Vec3f。若算法前面做了 convertTo(CV_32F)，后面的 at 类型也必须同步改变。

5. 关键 C++ 对照：cv::Mat、ROI、clone/copyTo

下面的 C++ 示例与 Python 脚本做同类事情：读取图像、检查属性、访问像素、修改 ROI、拆分合并通道、使用掩膜、保存结果。

#include <opencv2/core.hpp>
#include <opencv2/imgcodecs.hpp>
#include <opencv2/imgproc.hpp>
#include <opencv2/highgui.hpp>

#include <algorithm>
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

static void describeImage(const std::string& name, const cv::Mat& img) {
    if (img.empty()) {
        throw std::invalid_argument(name + " is empty");
    }

    std::cout << name << ": rows=" << img.rows
              << ", cols=" << img.cols
              << ", channels=" << img.channels() << '\n';
    std::cout << name << ": depth=" << img.depth()
              << ", type=" << img.type()
              << ", step=" << img.step
              << ", continuous=" << std::boolalpha << img.isContinuous() << '\n';
}

int main(int argc, char** argv) {
    if (argc < 2) {
        std::cerr << "Usage: " << argv[0] << " <input-image> [output-image]\n";
        return 2;
    }

    const std::string input = argv[1];
    const std::string output = argc >= 3 ? argv[2] : "ch01_output_cpp.png";

    cv::Mat img = cv::imread(input, cv::IMREAD_COLOR);
    if (img.empty()) {
        std::cerr << "OpenCV cannot decode image: " << input << '\n';
        return 1;
    }

    describeImage("img", img);

    const int y = img.rows / 2;
    const int x = img.cols / 2;
    const cv::Vec3b bgr = img.at<cv::Vec3b>(y, x);
    std::cout << "center pixel at (x=" << x << ", y=" << y << "): B="
              << static_cast<int>(bgr[0]) << ", G=" << static_cast<int>(bgr[1])
              << ", R=" << static_cast<int>(bgr[2]) << '\n';

    cv::Mat result = img.clone();

    const int x1 = img.cols / 4;
    const int y1 = img.rows / 4;
    const int w = img.cols / 2;
    const int h = img.rows / 2;
    cv::Rect rect(x1, y1, w, h);
    cv::Mat roi = result(rect);  // 浅拷贝头部，数据仍属于 result。

    for (int row = 0; row < roi.rows; ++row) {
        for (int col = 0; col < roi.cols; ++col) {
            cv::Vec3b& px = roi.at<cv::Vec3b>(row, col);
            px[1] = cv::saturate_cast<uchar>(px[1] + 60);
        }
    }

    std::vector<cv::Mat> channels;
    cv::split(result, channels);
    if (channels.size() != 3) {
        std::cerr << "expected 3 channels\n";
        return 1;
    }

    cv::Mat merged;
    cv::merge(channels, merged);

    cv::Mat mask = cv::Mat::zeros(img.rows, img.cols, CV_8UC1);
    cv::circle(mask, cv::Point(img.cols / 2, img.rows / 2),
               std::min(img.rows, img.cols) / 4, cv::Scalar(255), cv::FILLED);

    cv::Mat foreground;
    cv::bitwise_and(merged, merged, foreground, mask);

    if (!cv::imwrite(output, foreground)) {
        std::cerr << "failed to write output image: " << output << '\n';
        return 1;
    }

    std::cout << "wrote: " << output << '\n';
    return 0;
}

编译示例：

c++ -std=c++17 ch01.cpp -o ch01 $(pkg-config --cflags --libs opencv4)
./ch01 input.jpg output.png

有些系统上即使安装的是 OpenCV 5，pkg-config 名称也可能仍由发行版决定；更稳妥的工程方式是使用 CMake 的 find_package(OpenCV REQUIRED)。如果 pkg-config --libs opencv4 找不到，并不必然说明 OpenCV 不存在，只说明当前系统没有提供这个 pkg-config 文件。

C++ 像素访问需要类型匹配。img.at<cv::Vec3b>(y, x) 适用于 CV_8UC3 彩色图；灰度 CV_8UC1 应使用 img.at<uchar>(y, x)；浮点图要用 float 或 cv::Vec3f。类型写错可能触发断言，也可能在 release 构建下变成难查的数据错误。因此生产代码中应先检查 img.type() 或至少检查 img.channels() 和 img.depth()。

6. 常见坑

第一，读图失败后继续处理。Python 的 cv.imread 失败返回 None，C++ 的 cv::imread 失败返回空 Mat。不要等到 .shape、at 或 cvtColor 报错时才发现路径错了。路径含中文或特殊字符时，也要用当前 OpenCV 构建实际测试；不同平台和编码环境可能表现不同。

第二，把 BGR 当 RGB。OpenCV 的彩色读取默认通道顺序是 BGR，不是 RGB。保存时 cv.imwrite 也按 BGR 解释三通道矩阵。典型症状是红蓝反了：人的脸发蓝，蓝色物体发红。和 Matplotlib、Pillow、网页 Canvas、深度学习数据集交互时要显式转换。

第三，把坐标顺序写反。OpenCV 矩阵索引是 [row, col]，也就是 [y, x]；但很多几何 API 使用 Point(x, y) 或 (x, y)。一句话记忆：访问数组先 y 后 x，表达空间点先 x 后 y。

第四，误解 ROI 拷贝。roi = img[y1:y2, x1:x2] 和 cv::Mat roi = img(rect) 都是浅视图。你在 ROI 上画框、置零、调亮，原图对应区域会变。想保留原图就深拷贝：Python 用 .copy()，C++ 用 .clone()。

第五，混淆 dtype、depth 和通道。uint8 只说明每个通道是 8 位无符号；它不说明是灰度还是 BGR。C++ 的 CV_8U 是深度，CV_8UC3 才是三通道类型。Python 里也不要只看 dtype，还要看 ndim 和 shape。

第六，在无 GUI 环境调用 imshow。imshow 属于 HighGUI，需要图形后端和事件循环。官方文档要求 imshow 后配合 waitKey 或 pollKey 处理 GUI 事件，否则窗口可能不显示或无响应。服务器、Docker、远程 CI 中常用 opencv-python-headless，它没有 GUI 能力；这类环境应使用 imwrite、日志、Notebook 显示或专门的可视化工具。

第七，忽略非连续数组。ROI、步长切片、通道视图可能不是连续内存。OpenCV 自己的大多数 Python 函数能处理 strided ndarray，但第三方 C 扩展、深度学习框架或自写绑定可能要求连续数组。传出前用 np.ascontiguousarray 是简单保险的做法。

第八，用 NumPy 加法替代 OpenCV 饱和加法。np.uint8([250]) + np.uint8([10]) 会按 256 取模得到 4；cv.add 会饱和到 255。图像增强、融合和亮度调整时要明确选择语义。想要 OpenCV 风格的饱和运算，用 cv.add、cv.subtract 或 cv.convertScaleAbs。

第九，保存浮点图却期待自动归一化。imshow 对不同深度会有显示缩放规则，但 imwrite 对格式和类型有要求。常规保存建议先转换到 uint8 并确认范围。浮点处理链中，显示、保存和后续算法输入要分别考虑。

第十，在同一 Python 环境混装多个 OpenCV wheel。opencv-python 和 opencv-python-headless 都提供 cv2，混装后版本、动态库、GUI 支持可能互相覆盖。出问题时先 python -m pip list | grep opencv，卸载多余包，再只安装一个变体。

7. 排错流程：从环境到数据逐层收窄

OpenCV 初学阶段的错误看起来很多，其实可以按固定顺序排查。第一层是环境：程序到底使用了哪个解释器、哪个 OpenCV 版本、是否有 GUI 后端、是否能找到图像编解码器。Python 中先打印 cv.__version__ 和 cv.getBuildInformation()，再确认 python -m pip show opencv-python 显示的是同一个环境。C++ 中先确认头文件来自哪里、链接库来自哪里、运行时加载的动态库又来自哪里。编译能通过不代表运行时库一定匹配，尤其是在系统包、源码编译和 Conda/Homebrew 并存的机器上。

第二层是输入：路径是否存在、当前工作目录是否符合预期、文件是否真是图片、权限是否允许读取。imread 不按扩展名盲信文件类型，它会根据文件内容和可用 codec 解码；这对可靠性是好事，但也要求你检查返回值。课程作业中经常出现相对路径错误，脚本从 IDE 运行和从终端运行时工作目录不同，导致同一行代码一会儿成功一会儿失败。稳妥办法是把输入路径打印出来，必要时转成绝对路径，并在读图前检查 Path(...).is_file()。

第三层是矩阵属性：拿到图像后立即打印尺寸、通道、类型和连续性。算法要求灰度图却传入三通道图，要求 uint8 却传入 float32，要求同尺寸 mask 却传入另一张图的 mask，都会产生断言或静默错误。不要只看图像“能显示”，显示成功只能说明它可以被某个显示路径解释，不说明它满足算法输入契约。严谨的处理函数应在入口检查关键条件，发现不满足时给出明确错误，而不是让底层 OpenCV 抛出难读的断言信息。

第四层是颜色和坐标语义。颜色错误通常表现为红蓝反转、阈值范围不对、HSV 提取结果为空；坐标错误通常表现为 ROI 位置偏移、画框错位、访问越界。排查时先选一个已知像素，例如图像中心或手工创建的小矩阵，打印它在每一步转换后的值。对坐标，先画一个小圆或矩形验证 (x, y) 是否落在预期位置，再写复杂逻辑。小图、小矩阵、已知值是调试图像程序最有效的工具。

第五层是拷贝关系和生命周期。若修改 ROI 后原图也变了，这不是 OpenCV 随机出错，而是浅视图共享数据。若函数返回的矩阵在后续阶段异常，检查它是否引用了已经释放或复用的数据。Python 里 NumPy 的视图生命周期通常由引用管理，问题较少；C++ 中如果把外部缓冲区包装成 Mat，就必须保证外部缓冲区活得足够久。普通 imread 得到的 Mat 由 OpenCV 管理，不需要手动释放。

第六层是显示与保存。显示偏暗、偏亮或全黑时，先看图像类型和值域。浮点图显示和保存都需要明确缩放；二值 mask 保存前最好确认值是 0 和 255，而不是 0 和 1。保存失败时检查输出目录、扩展名和返回值。无 GUI 环境中，不要把 imshow 失败误判为图像处理失败；先用 imwrite 保存中间结果，再在本地查看。

按这个顺序排查，可以把多数问题从“OpenCV 不知道哪里坏了”变成一组可验证的事实：环境是否正确，输入是否有效，矩阵是否符合契约，颜色坐标是否一致，内存共享是否符合预期，输出路径是否可用。后续章节的算法会更复杂，但这个排错框架仍然适用。

8. 练习

  1. 写一个 Python 脚本，接收图像路径，打印 shape、dtype、strides、是否连续、中心像素 BGR 值；如果读图失败，输出清晰错误信息并以非零状态退出。

  2. 读取一张彩色图，把左上角四分之一区域的红色通道增强 50，同时保存原图和修改图。验证原图是否被修改：先用 ROI 浅拷贝做一遍，再用 .copy() 做一遍，比较差异。

  3. 用 cv.cvtColor 把 BGR 转为 RGB，再用 Matplotlib 显示；同时故意不转换显示一次，观察红蓝反转。

  4. 创建一个与原图同宽高的圆形 uint8 掩膜，只保留圆内区域，圆外变黑。要求检查掩膜维度必须是二维，类型必须是 uint8。

  5. 用 C++ 重写练习 1，要求检查 img.empty()、img.channels()、img.depth()，并分别打印 rows、cols、step、isContinuous()。

  6. 在 Python 中构造 np.uint8([250]) 和 np.uint8([10])，分别用 NumPy 加法和 cv.add 相加，解释为什么结果不同。

  7. 对一张 ROI 执行 np.ascontiguousarray，打印转换前后的 strides 和连续性。说明什么时候需要这一步。

  8. 在无 GUI 环境中运行带 --show 的示例脚本，确认它不会崩溃，而是保存输出并提示跳过显示。

9. 本章小结

本章的核心不是记住多少函数，而是建立正确的数据模型。OpenCV 的图像是矩阵；矩阵有尺寸、通道、类型、步长和连续性；Python 的 ndarray 与 C++ 的 cv::Mat 都可能共享底层数据；ROI 默认是浅视图；彩色图默认按 BGR 解释；坐标访问要区分数组索引和空间点。只要这些基础稳定，后续学习滤波、阈值、边缘、特征、几何变换和深度学习推理时，调试成本会低很多。

建议把本章示例当作以后所有图像实验的启动模板：先确认版本和输入，再打印矩阵属性，随后才进入算法步骤；每产生一个关键中间结果，都能说明它的尺寸、类型、颜色空间和是否会修改原数据。这个习惯看似啰嗦，却能把大部分低级错误挡在算法之前。

后续章节默认读者已经掌握这些检查方法，并能独立判断错误发生在环境、输入、矩阵属性还是算法逻辑。
