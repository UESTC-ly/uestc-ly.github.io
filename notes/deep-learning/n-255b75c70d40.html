学习目标

  • 掌握视觉模型从数据到训练、验证、调参、上线前检查的完整流程。
  • 理解 CE、BCE、Focal、Dice、IoU 族损失和多任务 loss 的适用场景。
  • 能诊断过拟合、欠拟合、数据泄漏、类别不平衡、标注噪声和迁移失败。
  • 与任务选择、指标和部署联动：见 07_视觉任务与典型模型.md、09_评价指标与误差分析.md、10_推理部署与工业视觉.md。

标准训练流程

  1. 明确任务和输出：分类、检测、分割、OCR 等任务的标签格式不同，不能混用指标和损失。
  2. 收集和清洗数据：统一采集条件、分辨率、标注规范、类别定义。
  3. 划分数据集：训练、验证、测试必须按业务实体、时间、产线、场景或设备隔离，避免泄漏。
  4. 建立 baseline：先用成熟模型和简单增强跑通端到端流程。
  5. 训练与验证：记录 loss、指标、学习率、样本可视化、预测可视化。
  6. 误差分析：按类别、尺寸、场景、设备、光照、遮挡、时间切片分析。
  7. 迭代数据和模型：优先修复数据问题，再调模型容量和损失。
  8. 导出和部署前验证：检查精度、速度、显存、稳定性和量化影响。

数据划分与泄漏

数据泄漏是视觉项目常见的高分陷阱。随机按图片划分并不总是安全。

高风险情况：

  • 同一视频相邻帧同时出现在训练集和测试集。
  • 同一产品、同一病人、同一工件、同一相机点位被拆到不同集合。
  • 增强后的图片被保存后再统一随机划分。
  • 测试集参与阈值选择、早停、模型选择。
  • 文件名、水印、背景、拍摄设备暗含类别信息。

推荐划分原则：

  • 按实体划分：同一对象不能跨集合。
  • 按时间划分：模拟未来数据，适合线上业务。
  • 按场景划分：专门验证跨域能力。
  • 固定测试集：只用于最终汇报，不用于日常调参。

损失函数

CE 与 BCE

Cross Entropy 适合单标签多分类：每个样本只有一个正确类别，概念上对应 softmax 概率。

BCE 适合二分类或多标签分类：每个类别独立判断，概念上对应 sigmoid 概率。多标签任务不能用 softmax CE，因为多个类别可同时为真。

实现时不要重复做概率变换：例如 PyTorch 的 CrossEntropyLoss 接收 raw logits 并在内部完成 log-softmax，BCEWithLogitsLoss 也接收 raw logits 并在内部组合 sigmoid 与 BCE，以获得更好的数值稳定性。softmax/sigmoid 概率主要用于解释、阈值判断和推理后处理。

Focal Loss

Focal Loss 在 CE/BCE 基础上降低易分类样本权重，强调难样本。它常用于检测中的前景/背景不平衡，也可用于长尾分类。

直觉：

  • 易样本已经预测很准，对梯度贡献应变小。
  • 难样本、少数类、低置信正样本应获得更多学习信号。

使用注意：

  • gamma 太大可能让训练不稳定。
  • alpha 只调类别或正负样本权重，不应代替数据修复。

Dice Loss

Dice 衡量预测区域与真实区域的重叠，常用于医学图像和小目标分割。它对类别不平衡更友好，因为关注区域交并关系，而不是逐像素平均。

Dice Loss 适合：

  • 前景像素远少于背景。
  • 更关注区域完整性而非单个像素分类。

风险：

  • 小目标上对少量像素错误很敏感。
  • 单独使用可能导致概率校准较差，常与 BCE/CE 组合。

IoU 族损失

检测框回归常用 IoU、GIoU、DIoU、CIoU 等损失。

  • IoU Loss：直接优化框重叠，但无重叠时梯度不足。
  • GIoU：引入最小外接框，缓解无重叠问题。
  • DIoU：加入中心点距离。
  • CIoU：进一步考虑宽高比。

分割也可使用 soft IoU/Jaccard loss，强调预测 mask 与真实 mask 的交并比。

多任务 Loss

检测、实例分割、关键点、OCR 常见多任务训练。例如 Mask R-CNN 同时有分类、框回归、mask loss。

多任务 loss 的关键不是简单相加，而是权重平衡：

  • 不同 loss 数值尺度不同，直接相加可能让某个任务支配训练。
  • 某个 head 收敛慢不一定代表整体模型坏，需分别看分支指标。
  • 可用固定权重、动态权重、不确定性权重、梯度归一化等方法。

工程上先用论文或框架默认权重建立 baseline，再根据分支指标和可视化调整。

优化器与学习率

SGD with momentum 泛化稳定，常用于 CNN 分类和检测。Adam/AdamW 收敛快，对 Transformer 和大规模预训练迁移常用。AdamW 将权重衰减与梯度更新解耦，通常比 Adam + L2 更符合现代训练习惯。

学习率策略：

  • warmup：训练初期从小学习率逐步升高，避免大 batch、预训练模型或 Transformer 初始震荡。
  • step decay：到指定 epoch 降低学习率，简单可控。
  • cosine decay：平滑下降，常与 warmup 组合。
  • one-cycle：先升后降，适合快速训练实验。

学习率排查：

  • loss 发散或 NaN：学习率过大、混合精度溢出、标签异常。
  • loss 很慢：学习率过小、冻结层过多、数据增强过强。
  • 验证指标震荡：batch 太小、验证集太小、学习率偏大、标注噪声。

预训练与迁移学习

预训练模型提供通用边缘、纹理、形状和语义特征，通常能减少数据需求。

常见策略：

  • 冻结 backbone，只训练 head：快，适合数据很少或先跑通流程。
  • 解冻高层：适合目标域与预训练域相近。
  • 全量微调：适合数据足够或域差异明显。
  • 分层学习率：backbone 小学习率，head 大学习率。

迁移失败原因：

  • 输入分辨率、通道、归一化与预训练不一致。
  • 目标域差异太大，如自然图像迁移到红外、X 光、工业缺陷。
  • 标注定义与预训练语义冲突。
  • 训练集过小却全量微调导致过拟合。

数据增强

增强的目标是扩大真实分布，而不是制造不可能样本。

常用增强：

  • 几何：resize、crop、flip、rotate、affine、perspective。
  • 颜色：brightness、contrast、saturation、hue、white balance。
  • 退化：blur、noise、JPEG compression、motion blur。
  • 遮挡：cutout、random erasing。
  • 混合：mixup、cutmix、mosaic。

任务约束：

  • OCR 不宜随意水平翻转文字。
  • 医学和工业方向要确认旋转、镜像是否改变语义。
  • 检测/分割增强必须同步变换 box/mask/keypoints。
  • 小目标任务中过强 resize/crop 会直接删除目标。

过拟合、欠拟合与诊断

过拟合表现：训练 loss 下降，训练指标高，验证指标不升反降。处理优先级：

  1. 检查数据划分是否泄漏或验证集是否过小。
  2. 增加真实数据和难例，修正噪声标注。
  3. 加强合理增强。
  4. 使用 weight decay、dropout、label smoothing、early stopping。
  5. 减小模型容量或冻结更多层。

欠拟合表现：训练集也学不好。处理优先级：

  1. 检查标签、预处理、类别映射、loss 是否写错。
  2. 降低增强强度。
  3. 提高学习率或调整 scheduler。
  4. 增大模型容量、训练更久、解冻 backbone。
  5. 检查任务是否本身不可由输入信息决定。

训练日志应看什么

  • train loss 与 val loss 是否同步下降。
  • 分类看 accuracy、F1、混淆矩阵；检测看 mAP、召回、不同尺寸 AP；分割看 mIoU、Dice。
  • 每个类别的指标，而不是只看平均值。
  • 正负样本比例和 hard negative。
  • 可视化一批训练样本、增强样本、预测样本。
  • 保存失败案例，按错误类型归档。

常见故障排查顺序

  1. 数据能否正确读取：图像、标签、类别名、坐标系、mask 编码。
  2. 可视化标注是否对齐：box/mask/keypoint 是否和图像匹配。
  3. 单 batch 能否过拟合：不能过拟合通常是代码、loss 或标签问题。
  4. loss 数值是否正常：NaN、恒定、极端大/小都要排查。
  5. 训练与验证预处理是否一致。
  6. 指标实现是否和任务匹配。
  7. 检查 checkpoint 加载、冻结层、学习率、混合精度。
  8. 再考虑模型结构和复杂调参。
