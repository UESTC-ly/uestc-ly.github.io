# 二分查找：区间写法与循环条件辨析

> 本笔记整理自本次会话中反复出现的两个疑问：
>
> - 为什么有的题写 `while (left < right)`，有的题写 `while (left <= right)`？
> - 「第一个 `>= target`」和「第一个 `> target`」两个模板差在哪？
>

## 一、核心原则：三要素必须配套

二分查找出错，绝大多数不是“不会二分”，而是把两套模板混用了。

```text
区间定义  →  循环条件  →  边界更新
三者必须来自同一套模板
```

| 区间定义 | 循环条件 | 右边界初值 | 收缩写法 | 典型返回 |
|---|---|---|---|---|
| 左闭右开 `[left, right)` | `left < right` | `nums.size()` | `right = mid` | `left` |
| 左闭右闭 `[left, right]`，检查未分类元素 | `left <= right` | `n - 1` | `right = mid - 1` | 命中下标、`-1` 或分界 `left` |
| 左闭右闭 `[left, right]`，始终保留答案 | `left < right` | `n - 1` | `right = mid` | 唯一候选 `left` |

---

## 二、为什么循环条件不同

### 1. `[left, right)` 用 `left < right`

右边界取不到，所以当 `left == right` 时区间已经为空，没有元素可查，应当结束。

```text
nums = [1,3,5,6]
left = 0, right = 4 表示 [0,4)，即下标 0,1,2,3
收缩到 left = 1, right = 1，即 [1,1) → 空区间 → 结束
```

### 2. `[left, right]` 中逐个排除 mid 的模板用 `left <= right`

右边界取得到，所以当 `left == right` 时区间里**还剩一个元素**，必须检查。

反例说明为什么不能写成 `<`：

```text
nums = [1], target = 1
left = 0, right = 0
若写 while (left < right)：0 < 0 不成立，循环一次都不进
nums[0] 根本没被检查过，直接漏答案
```

### 3. 判断依据的实质

> 循环条件不是题目规定的，而取决于：**当区间只剩一个位置时，还需不需要进入循环去检查它。**

- 需要检查（要拿它和 `target` 比较）→ `left <= right`
- 不需要检查（它已经必然是答案）→ `left < right`

## 三、两类题型的默认选择

### 1. 找边界 → 左闭右开 `[left, right)`

适用：搜索插入位置、找左右边界、`lower_bound`、`upper_bound`。

```cpp
int left = 0;
int right = nums.size();

while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid;   // mid 可能就是答案，不能丢
    }
}
return left;
```

特点：`right` 可取 `nums.size()`；收缩用 `right = mid`；最终 `left == right` 就是答案位置。

### 2. 找具体值 → 左闭右闭 `[left, right]`

适用：普通二分查找、33. 搜索旋转排序数组。

```cpp
int left = 0;
int right = nums.size() - 1;

while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;   // mid 已检查过，可以排除
}
return -1;
```

特点：`right` 是有效下标；收缩用 `mid ± 1`；找不到返回 `-1`。

### 3. 收缩候选区间 → 闭区间 + `left < right`

153. 寻找旋转排序数组中的最小值属于第三种：区间是闭的，但循环内不做“等于目标”的判断，只是不断收缩“答案可能存在的范围”。

```cpp
int left = 0;
int right = nums.size() - 1;

while (left < right) {          // 剩一个元素时它必然是答案
    int mid = left + (right - left) / 2;
    if (nums[mid] > nums[right]) left = mid + 1;
    else right = mid;           // mid 可能就是最小值
}
return nums[left];
```

## 四、混用模板的典型后果：死循环

33 题里出现过这样的写法：循环条件用了闭区间的 `left <= right`，但收缩时写成了边界查找模板的 `right = mid` / `left = mid`。

```cpp
while (left <= right) {
    int mid = left + (right - left) / 2;
    ...
    right = mid;   // 与 while (left <= right) 不配套
    left = mid;    // 同样危险
}
```

后果：

```text
nums = [1]，left = right = 0，mid = 0
right = mid = 0  →  区间完全没变  →  死循环

left = 4, right = 5 时 mid = 4
left = mid = 4   →  left 没动  →  可能卡住
```

结论：

```text
闭区间 [left, right] + while (left <= right)  →  必须 mid ± 1
左闭右开边界模板 / 闭区间保留答案模板 + while (left < right) → 可以 right = mid
```

（当 `left < right` 且循环体保证每轮至少缩小一格时，`right = mid` 才是安全的。）

## 五、边界模板对比：第一个 `>=` 与第一个 `>`

两个模板结构完全一样，**唯一差别是判断条件的等号位置**。

### 1. 第一个 `>= target`（`lower_bound`）

```cpp
int lowerBound(const vector<int>& nums, int target) {
    int left = 0;
    int right = nums.size();

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid + 1;      // 太小，mid 一定不是答案
        } else {
            right = mid;         // nums[mid] >= target，mid 可能是答案
        }
    }
    return left;
}
```

### 2. 第一个 `> target`（`upper_bound`）

```cpp
int upperBound(const vector<int>& nums, int target) {
    int left = 0;
    int right = nums.size();

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) {
            left = mid + 1;      // 等于 target 也不算答案，必须跳过
        } else {
            right = mid;         // nums[mid] > target，mid 可能是答案
        }
    }
    return left;
}
```

### 3. 差别只有一句

```text
第一个 >= target ：if (nums[mid] <  target) left = mid + 1;
第一个 >  target ：if (nums[mid] <= target) left = mid + 1;
```

原因：

- 找第一个 `>=` 时，`nums[mid] == target` 可能就是答案，必须保留 → 走 `right = mid`；
- 找第一个 `>` 时，`nums[mid] == target` 一定不是答案，必须跳过 → 走 `left = mid + 1`。

### 4. 同一个例子看清区别

```text
nums = [1,3,3,3,5,7], target = 3

第一个 >= 3  →  下标 1（等于 3 的位置要保留）
第一个 >  3  →  下标 4（等于 3 的位置全部跳过，指向 5）
```

### 5. 一句话记忆

```text
找第一个 >= target：跳过所有 <  target 的数
找第一个 >  target：跳过所有 <= target 的数
```

## 六、四道题的区间选择速查

| 题目 | 本质 | 区间 | 循环条件 |
|---|---|---|---|
| 35. 搜索插入位置 | 第一个 `>= target` | `[left, right)` | `left < right` |
| 34. 查找第一个和最后一个位置 | 左边界 + 右边界 | `[left, right)` ×2 | `left < right` |

| 33. 搜索旋转排序数组 | 局部有序中找具体值 | `[left, right]` | `left <= right` |
| 153. 寻找旋转数组最小值 | 收缩最小值候选区间 | `[left, right]` | `left < right` |

## 七、方法归纳

> 先问自己三个问题，再动手写：
>
> 1. 我在找**具体值**，还是找**边界 / 候选区间**？
> 2. 我的 `right` 初值是 `size()` 还是 `size() - 1`？（决定区间开闭）
> 3. `left == right` 时，那个元素还需不需要检查？（决定 `<` 还是 `<=`）
>
> 这些问题帮助选择一套自洽的模板，但题型不唯一决定区间写法：35、34 也能用闭区间排除 mid，结束时返回分界 left。具体代码与相等时继续查找的解释见 [35、34 的闭区间补充](./二分查找专题（35、34、74）.md#补充闭区间写法与相等为何不直接返回)。

补充一个容易忽略的区间类型：

```text
当二分对象是“分割位置”时，长度为 m 的数组有 m+1 个合法分割位置：
0, 1, 2, ..., m
```

因此 LeetCode 4 的初始范围是：

```cpp
int left = 0;
int right = m;
```

这里的 `[0, m]` 表示“左边可以选取 0 到 m 个元素”，并不是数组元素的下标范围。

统一判断原则：

1. 先说明 `left`、`right` 表示元素下标还是分割位置；
2. 再确定循环条件；
3. 最后根据 `mid` 是否仍可能成为答案，决定保留还是排除 `mid`。
