# 第 10 章 传统机器学习与实用视觉模块

本章把 OpenCV 中“模型不一定是深度网络”的部分串起来：`cv.ml` 负责把特征矩阵训练成分类或回归模型；`objdetect`、`imgproc`、`photo` 中有一批可直接落地的检测、分割和修复工具。它们的共同特点是可解释、数据需求少、部署轻，但强依赖特征设计、光照和成像条件。学习目标不是背 API，而是知道样本如何组织、特征如何影响决策边界、验证如何避免数据泄漏，以及什么时候该从传统方法切到 DNN 或混合方案

官方第一方资料入口：OpenCV 4.12 `Machine Learning` 模块、`cv::ml::TrainData`、`StatModel`、`KNearest`、`SVM`、`DTrees`、`RTrees`，`HOGDescriptor`、`CascadeClassifier`、`QRCodeDetector`、`barcode::BarcodeDetector`，以及 `grabCut`、`matchTemplate`、`fastNlMeansDenoising`、`inpaint`、`seamlessClone` 等函数文档。OpenCV 5 主线保留这些能力；条码检测在 5.0 教程中标注兼容 OpenCV >= 4.8，Caffe 超分模型不再用于条码解码增强，改用单文件 ONNX。

## 10.1 cv.ml 的数据组织

`cv.ml` 把每个样本看成一个定长向量。若使用 `ROW_SAMPLE`，矩阵每一行是一个样本，每一列是一个特征；若使用 `COL_SAMPLE`，每一列是一个样本。Python 中准备 `np.float32` 的二维数组 `X` 和标签 `y`。分类标签常用整数，回归目标可用浮点。`StatModel::train(samples, layout, responses)` 是最短入口；需要训练/测试划分或样本权重时，用 `TrainData.create` 更清楚。

图像不能直接丢给多数传统模型。先把图像变成特征：灰度直方图、颜色统计、轮廓几何量、HOG、LBP、自定义测量值，或前几章得到的区域属性。特征必须定长，尺度也必须可比；若直接混在一起，KNN 的距离和 SVM 的间隔会被大数值特征支配。

最小训练流程如下：

```python
import cv2 as cv
import numpy as np

X = np.asarray(features, dtype=np.float32)      # shape: [n_samples, n_features]
y = np.asarray(labels, dtype=np.int32).reshape(-1, 1)

rng = np.random.default_rng(7)
idx = rng.permutation(len(X))
cut = int(len(X) * 0.8)
train_idx, test_idx = idx[:cut], idx[cut:]

mean = X[train_idx].mean(axis=0, keepdims=True)
std = X[train_idx].std(axis=0, keepdims=True)
std[std < 1e-6] = 1.0

X_train = ((X[train_idx] - mean) / std).astype(np.float32)
y_train = y[train_idx]
X_test = ((X[test_idx] - mean) / std).astype(np.float32)
y_test = y[test_idx]

train = cv.ml.TrainData_create(X_train, cv.ml.ROW_SAMPLE, y_train)
```

标准化参数只能从训练集估计，模型也只用训练索引对应的样本训练；`X_test/y_test` 保持独立，只用于最终评估。若先用全量数据计算均值和方差，或在已经手动切分后又调用 `setTrainTestSplitRatio()` 二次随机切分，测试集信息和样本边界都会被污染，指标会偏乐观。类似泄漏还包括：同一个视频相邻帧被随机拆到训练和测试、同一个工件的多张增强图跨集合、根据测试集表现反复调阈值。真实工程中应按场景、设备、批次、视频或对象分组切分。

C++ 对照：

```cpp
#include <opencv2/ml.hpp>
using namespace cv;
using namespace cv::ml;

Mat trainSamples;  // CV_32F, standardized with train-set mean/std
Mat trainLabels;   // CV_32S or CV_32F, one response per train sample
Mat testSamples;   // standardized with the same train-set mean/std
Mat testLabels;    // held out for evaluation only
Ptr<TrainData> data = TrainData::create(trainSamples, ROW_SAMPLE, trainLabels);
```

## 10.2 训练、验证与指标

`StatModel` 是多数模型的共同基类，提供 `train`、`predict`、`calcError`、`save` 等接口。`calcError(data, true, resp)` 在有测试划分时计算测试子集错误；官方文档说明分类任务返回误分类百分比，回归任务返回 RMS。这个数只能回答“错了多少”，不能回答错在哪类、漏检是否比误检更严重。

分类任务至少要看混淆矩阵、准确率、精确率、召回率和 F1。缺陷检测、安防报警、二维码识别失败重试等场景通常更关心召回率；自动分拣、闸机放行等场景误报代价也很高。若输出分数可排序，还应画阈值曲线。OpenCV ML 模型本身不替你做完整评估，工程中常用 NumPy 或自写统计。

```python
_, pred = svm.predict(X_test.astype(np.float32))
pred = pred.astype(np.int32).ravel()
truth = y_test.ravel()

classes = np.unique(np.r_[truth, pred])
cm = np.zeros((len(classes), len(classes)), np.int32)
pos = {c: i for i, c in enumerate(classes)}
for t, p in zip(truth, pred):
    cm[pos[t], pos[p]] += 1
print(cm)
print("accuracy:", np.trace(cm) / cm.sum())
```

小数据集不要只做一次随机切分。可用 k 折交叉验证估计波动，但要按组切分。模型选择阶段使用验证集或交叉验证；最终只在从未参与调参的测试集上报告一次。

## 10.3 KNN：距离就是模型

KNN 没有显式训练决策边界，训练阶段主要保存样本；预测时计算输入样本与训练样本的距离，找最近的 `k` 个邻居，分类用投票，回归用均值。它适合样本少、特征维度低、类别边界弯曲但局部相似性强的任务，例如简单形状分类、颜色块分类、少量模板特征的原型验证。

KNN 的弱点也来自距离：特征未标准化会失真；高维空间距离区分度下降；训练样本越多预测越慢；异常点会影响局部投票。`k` 太小容易过拟合，`k` 太大又会抹平局部结构。

```python
knn = cv.ml.KNearest_create()
knn.setDefaultK(5)
knn.setIsClassifier(True)
knn.train(X_train.astype(np.float32), cv.ml.ROW_SAMPLE, y_train.astype(np.int32))

ret, results, neighbors, dist = knn.findNearest(X_test.astype(np.float32), 5)
```

C++ 中核心调用是 `KNearest::create()`、`train(samples, ROW_SAMPLE, labels)`、`findNearest(samples, k, results, neighborResponses, dist)`。若只需要最近邻原型，可把 `neighborResponses` 和 `dist` 打印出来，观察错误样本到底靠近了哪些训练样本。

## 10.4 SVM：间隔、核函数与 HOG

SVM 是判别式分类器，线性 SVM 学到一个超平面，把两类样本分开，并尽量让离边界最近的样本到边界的间隔最大。非线性 SVM 通过核函数在隐式高维空间中形成弯曲决策边界。OpenCV 提供 `SVM::C_SVC` 等类型，以及 `LINEAR`、`RBF`、`POLY` 等核。

参数含义要从边界形状理解。`C` 控制对训练错误的惩罚：大 `C` 更努力贴合训练集，可能过拟合；小 `C` 更宽容，边界更平滑。RBF 的 `gamma` 控制单个样本影响范围：过大时边界会绕着样本弯曲，过小时边界过于平滑。OpenCV 的 `trainAuto` 可做参数网格搜索，但仍要确保交叉验证没有泄漏。

```python
svm = cv.ml.SVM_create()
svm.setType(cv.ml.SVM_C_SVC)
svm.setKernel(cv.ml.SVM_RBF)
svm.setC(2.0)
svm.setGamma(0.5)
svm.train(X_train.astype(np.float32), cv.ml.ROW_SAMPLE, y_train.astype(np.int32))
_, pred = svm.predict(X_test.astype(np.float32))
svm.save("shape_svm.yml")
svm2 = cv.ml.SVM_load("shape_svm.yml")
```

C++ 对照：

```cpp
Ptr<SVM> svm = SVM::create();
svm->setType(SVM::C_SVC);
svm->setKernel(SVM::RBF);
svm->setC(2.0);
svm->setGamma(0.5);
svm->train(trainSamples, ROW_SAMPLE, trainLabels);
svm->save("shape_svm.yml");
Ptr<SVM> loaded = SVM::load("shape_svm.yml");
```

HOG+SVM 是传统行人检测和刚性目标检测的经典组合。HOG 把窗口划分成 cell 和 block，统计局部梯度方向直方图，并做块归一化，使轮廓和边缘结构比原始像素更稳定。训练时对正负样本窗口提取同样长度的 HOG 向量，再训练线性 SVM；检测时用滑动窗口和图像金字塔扫描。OpenCV `HOGDescriptor` 默认窗口常见为 `64x128`，并提供 `setSVMDetector` 和内置行人检测器系数。

```python
hog = cv.HOGDescriptor()
hog.setSVMDetector(cv.HOGDescriptor_getDefaultPeopleDetector())
rects, weights = hog.detectMultiScale(img, winStride=(8, 8), padding=(8, 8), scale=1.05)
```

HOG+SVM 的优点是轻量、可解释、无需大量数据；局限是姿态、遮挡、视角和背景变化稍大就会下降，密集目标时滑窗也慢。今天它更适合作为教学、边缘设备上的固定场景检测，或作为深度模型前的候选区域生成器。

## 10.5 决策树与随机森林

决策树把特征空间不断切分成矩形区域，每个内部节点问一个问题，例如“面积是否小于阈值”“圆度是否大于 0.8”，叶子节点输出类别或数值。它的优点是可解释、能处理非线性和特征交互，对特征尺度不如 KNN/SVM 敏感；缺点是单棵树容易过拟合，边界呈阶梯状，对训练集扰动敏感。

`cv.ml.DTrees` 可设置树深、最小样本数、回归精度、是否使用代理分裂和交叉验证折数。随机森林 `RTrees` 训练多棵树，每棵树看样本和特征的随机子集，再用投票或平均输出。它通常比单棵树更稳，还可输出 OOB 误差和变量重要性。代价是模型更大、推理解释变成整体统计而不是一条路径。

```python
tree = cv.ml.DTrees_create()
tree.setMaxDepth(8)
tree.setMinSampleCount(5)
tree.train(X_train.astype(np.float32), cv.ml.ROW_SAMPLE, y_train.astype(np.int32))

rf = cv.ml.RTrees_create()
rf.setMaxDepth(12)
rf.setMinSampleCount(3)
rf.setActiveVarCount(0)  # 0 表示让实现选择默认策略
rf.setCalculateVarImportance(True)
rf.train(X_train.astype(np.float32), cv.ml.ROW_SAMPLE, y_train.astype(np.int32))
print("OOB:", rf.getOOBError())
```

C++ 名称为 `DTrees::create()`、`RTrees::create()`、`setMaxDepth`、`setActiveVarCount`、`getVarImportance`、`getOOBError`。树模型特别适合混合人工特征：尺寸、比例、颜色均值、边缘密度、纹理统计、连通域属性等。

## 10.6 CascadeClassifier：级联检测器及其边界

`CascadeClassifier` 是 Haar/LBP 等弱分类器级联的传统检测器，最常见示例是人脸检测。它用多尺度窗口扫描图像，早期级联快速拒绝大量背景窗口，后级联处理更像目标的候选。使用时加载 XML 模型，调用 `detectMultiScale`。

```python
face = cv.CascadeClassifier("haarcascade_frontalface_default.xml")
gray = cv.cvtColor(img, cv.COLOR_BGR2GRAY)
boxes = face.detectMultiScale(gray, scaleFactor=1.1, minNeighbors=5, minSize=(40, 40))
```

它的优势是 CPU 上很快、部署简单；局限是模型强依赖训练分布，对侧脸、遮挡、强光、低清、非正脸和复杂背景不稳，误检也常见。现代人脸和目标检测通常优先用 DNN；Cascade 更适合教学、老系统维护或固定角度、固定尺度、低算力场景。

## 10.7 GrabCut 与模板匹配

GrabCut 是交互式前景分割。用户给一个大致矩形或掩膜，算法用颜色模型估计前景/背景，并通过图割优化边界。它不理解“物体语义”，只利用颜色和边界一致性；当前景和背景颜色相近、边界毛发状、透明或强阴影时容易失败。

```python
mask = np.zeros(img.shape[:2], np.uint8)
bgd = np.zeros((1, 65), np.float64)
fgd = np.zeros((1, 65), np.float64)
rect = (30, 40, img.shape[1] - 60, img.shape[0] - 80)
cv.grabCut(img, mask, rect, bgd, fgd, 5, cv.GC_INIT_WITH_RECT)
keep = np.where((mask == cv.GC_FGD) | (mask == cv.GC_PR_FGD), 255, 0).astype("uint8")
fg = cv.bitwise_and(img, img, mask=keep)
```

模板匹配 `matchTemplate` 把模板滑过图像，计算每个位置的相似度。`TM_SQDIFF` 越小越好，`TM_CCORR` 和 `TM_CCOEFF` 越大越好，归一化版本更能抵抗亮度变化。它适合尺寸、旋转、外观稳定的图标、印刷标记、UI 元件定位；不适合尺度变化大、透视变化大、纹理重复或遮挡严重的目标。多尺度模板匹配可以缓解尺度问题，但计算量和误检都会增加。

```python
res = cv.matchTemplate(gray, templ, cv.TM_CCOEFF_NORMED)
_, max_val, _, max_loc = cv.minMaxLoc(res)
if max_val > 0.82:
    x, y = max_loc
    h, w = templ.shape[:2]
    cv.rectangle(img, (x, y), (x + w, y + h), (0, 255, 0), 2)
```

## 10.8 QRCodeDetector、BarcodeDetector 与 objdetect

`QRCodeDetector` 可检测并解码二维码，常用 `detectAndDecode`，多码场景用 `detectAndDecodeMulti`。OpenCV 5 文档中它继承图形码检测器相关接口，并提供弯曲二维码解码等能力。二维码检测依赖清晰的定位图形、足够像素、合理透视和对比度；运动模糊、过曝、低分辨率、反光和严重弯曲都会导致检测或解码失败。

```python
det = cv.QRCodeDetector()
text, points, straight = det.detectAndDecode(img)
if points is not None and text:
    pts = points.astype(np.int32).reshape(-1, 2)
    cv.polylines(img, [pts], True, (0, 255, 0), 2)
    print(text)
```

条码能力位于 `cv.barcode` 命名空间，Python 中常见入口是 `cv.barcode.BarcodeDetector`。官方 OpenCV 5 条码教程说明当前支持 EAN-8、EAN-13、UPC-A、UPC-E 等标准，并可选用 ONNX 超分模型改善小条码解码。构建时需要启用对应模块；某些发行包可能没有 `cv.barcode`。

```python
if hasattr(cv, "barcode"):
    bardet = cv.barcode.BarcodeDetector()
    ok, info, typ, corners = bardet.detectAndDecodeWithType(img)
    if ok:
        for s, t in zip(info, typ):
            print(t, s)
```

这些检测器适合“码本身就是目标”的任务。若要先在复杂场景中找包装、票据或屏幕，再读其中的码，通常需要几何校正、曝光控制、超分或 DNN 检测器提供 ROI。

## 10.9 photo 模块：去噪、修复与无缝克隆

`photo` 模块处理成像质量和局部编辑。`fastNlMeansDenoising` 和 `fastNlMeansDenoisingColored` 用非局部均值思想去噪：相似小块相互平均，能保留部分纹理，但参数过强会把细节抹平。它适合静态图像的轻中度噪声；实时视频要注意性能。

`inpaint` 根据掩膜修补区域，常用 `INPAINT_TELEA` 或 `INPAINT_NS`。掩膜中非零像素表示要修复的区域。它适合去小划痕、文字、水印或传感器坏点；大面积结构缺失、复杂语义内容不能指望传统修复自然生成。

`seamlessClone` 使用泊松融合把源图贴到目标图，减少边界色差。它需要源图、目标图、掩膜和中心点，常见模式是 `NORMAL_CLONE`、`MIXED_CLONE`。它解决的是融合边界，不解决透视、尺度、光照方向和语义合理性。

```python
den = cv.fastNlMeansDenoisingColored(img, None, 10, 10, 7, 21)

mask = cv.imread("mask.png", cv.IMREAD_GRAYSCALE)
fixed = cv.inpaint(img, mask, 3, cv.INPAINT_TELEA)

center = (dst.shape[1] // 2, dst.shape[0] // 2)
blend = cv.seamlessClone(src, dst, src_mask, center, cv.NORMAL_CLONE)
```

C++ 对照函数名保持一致：`cv::fastNlMeansDenoisingColored`、`cv::inpaint`、`cv::seamlessClone`，头文件通常包含 `opencv2/photo.hpp`。

## 10.10 传统方法、DNN 与混合方案选型

| 场景 | 优先方案 | 原因 | 风险 |
| --- | --- | --- | --- |
| 固定相机、固定光照、规则工件 | 传统特征 + KNN/SVM/树 | 数据少、可解释、部署轻 | 换光源或换批次可能失效 |
| 人脸、车辆、通用目标检测 | DNN | 姿态、尺度、背景变化大 | 需要模型、算力和标注 |
| 二维码、条码读取 | 专用 detector + 几何/曝光预处理 | 码制有明确结构 | 低清、反光、弯曲会失败 |
| UI 图标、印刷定位点 | 模板匹配 | 外观固定、实现简单 | 缩放旋转变化敏感 |
| 前景抠图且有人工提示 | GrabCut | 少量交互即可工作 | 不理解语义，颜色相近时差 |
| 缺陷检测小样本 | 传统特征 + 树/一类方法，必要时 DNN 复核 | 标注少、误报可解释 | 新缺陷类型覆盖不足 |
| 高召回流水线 | 混合方案 | 传统方法快速生成候选，DNN 精判 | 阈值和接口要严格验证 |

选择传统方法时，先问目标是否稳定、成像是否可控、特征是否能解释类别差异。选择 DNN 时，先问是否有足够覆盖的数据、部署算力和维护预算。混合方案常见于工业视觉：传统阈值/形态学找 ROI，HOG/SVM 或树模型筛选，再用 DNN 精判；或 DNN 检出对象后，用二维码、模板匹配、几何测量完成结构化读数。

## 10.11 模型保存、加载与版本边界

OpenCV ML 模型继承 `Algorithm` 保存机制，用 XML/YAML 文件。Python 中有 `model.save(path)` 和对应类的 `load`，例如 `cv.ml.SVM_load`、`cv.ml.RTrees_load`；C++ 中为 `SVM::load(path)`、`RTrees::load(path)`。保存模型不等于保存完整实验。还必须保存特征提取代码版本、标准化均值方差、标签映射、训练数据版本、OpenCV 版本和构建信息。

部署时先检查版本和构建：

```python
print(cv.__version__)
print(cv.getBuildInformation())
```

OpenCV 4.12 的 `ml`、`objdetect`、`photo` 是稳定常用模块；OpenCV 5 主线文档继续整理模块页面。Python 包是否包含 contrib、barcode、CUDA、OpenCL 或特定解码能力，取决于安装包和编译选项。代码中不要假设 `cv.barcode` 一定存在，应使用 `hasattr` 或启动自检。

## 10.12 常见错误

1. 把原始图像 reshape 成一行就训练，未设计稳定特征，模型学到背景和尺寸。
2. 标准化使用了全量数据，或增强样本跨训练/测试集合，导致数据泄漏。
3. KNN 未标准化特征，距离被面积、周长等大数值特征支配。
4. SVM RBF 直接套默认参数，不看 `C`、`gamma` 对边界的影响。
5. 只报告准确率，不看类别不平衡下的召回和误报。
6. 模板匹配用错方向：`TM_SQDIFF` 应取最小值，相关类方法取最大值。
7. Cascade 在侧脸、遮挡、低清场景误检漏检，却误以为是现代检测器。
8. GrabCut 矩形框太紧，把真实前景边界排除在初始化之外。
9. `QRCodeDetector` 返回点但文本为空时，误判为成功；检测成功不等于解码成功。
10. 只保存 `.yml` 模型，没有保存特征定义、标准化参数和标签映射，导致部署不可复现。

## 10.13 练习

1. 用轮廓面积、长宽比、圆度、Hu 矩和颜色均值构造特征，训练 KNN、SVM、RTrees 三种分类器，比较混淆矩阵。
2. 人为制造一次数据泄漏：先全量标准化再切分；再改成只用训练集标准化，对比测试指标差异。
3. 用 `HOGDescriptor` 提取固定窗口特征，训练一个二分类线性 SVM，并观察负样本不足时的误检。
4. 选一张含二维码的图片，测试缩放、模糊、透视变换对 `QRCodeDetector` 的影响，记录检测失败和解码失败的区别。
5. 对同一目标分别使用模板匹配和 DNN 检测，写出两者在尺度变化、旋转、遮挡、推理速度上的差异。
6. 用 `inpaint` 修复小划痕，再扩大掩膜到大面积缺失，观察传统修复的边界。

本章的核心结论是：传统视觉是可解释特征、轻量模型和专用算法的组合。只要成像条件可控、特征与目标差异匹配，它比 DNN 更简单可靠；当变化来自姿态、语义和复杂背景时，应及时转向 DNN 或把传统方法放在候选生成、几何校正和后处理位置。
