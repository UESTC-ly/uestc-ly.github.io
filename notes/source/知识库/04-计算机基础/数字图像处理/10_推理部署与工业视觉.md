# 10 推理部署与工业视觉

## 学习目标

- 理解 FP32、FP16、INT8、PTQ、QAT、剪枝、蒸馏、ONNX、TensorRT 的工程含义。
- 能用 latency、throughput、memory、精度变化共同评估部署方案。
- 掌握工业视觉流水线、异常检测思路和线上故障排查顺序。
- 与模型、训练、指标联动：见 [07_视觉任务与典型模型.md](./07_视觉任务与典型模型.md)、[08_训练_损失_数据与诊断.md](./08_训练_损失_数据与诊断.md)、[09_评价指标与误差分析.md](./09_评价指标与误差分析.md)。

## 部署目标

视觉部署不是只把模型导出。实际目标是在指定硬件、输入分布、延迟预算和业务阈值下，稳定地产生可解释、可监控、可回滚的结果。

上线前要同时确认：

- 精度：离线测试集、场景切片、线上抽样。
- 延迟：平均、P95、P99，包含预处理和后处理。
- 吞吐：单位时间处理帧数或图片数。
- 内存：显存、内存峰值、batch 变化。
- 稳定性：长时间运行、异常输入、空图、坏图、超大图。
- 可运维：日志、版本、监控、回滚、告警。

## 数值精度：FP32、FP16、INT8

FP32 是训练和基准推理常用精度，数值范围和稳定性好，但速度和显存成本高。

FP16 使用半精度浮点，通常在 GPU 上显著提升吞吐并降低显存。多数 CNN/Transformer 推理可用 FP16，但要注意 softmax、归一化、后处理和极小数值。

INT8 使用 8 位整数表示权重和激活，通常能降低模型存储和内存带宽，并可能显著加速，但真实收益取决于硬件、算子覆盖、运行时、shape 与数据搬运；不支持的算子回退后甚至可能抵消收益。它需要量化尺度，对分布变化、异常值和逐层敏感性更敏感，可能造成小目标、边界、低置信类别精度下降。

经验顺序：

1. 先建立 FP32 离线基线。
2. 尝试 FP16，验证精度和速度。
3. 再做 INT8，重点看切片精度和失败案例。

## PTQ 与 QAT

PTQ 是训练后量化，不重新训练或只用少量校准数据估计量化参数。优点是成本低、流程快；缺点是精度下降不可控，尤其对检测、分割、小目标和分布偏移敏感。

QAT 是量化感知训练，在训练中模拟量化误差，让模型适应 INT8。优点是精度更稳；缺点是训练流程复杂，需要训练数据和更多调参。

PTQ 校准数据要求：

- 覆盖真实输入分布。
- 包含不同光照、尺寸、类别、相机和典型难例。
- 不要只用训练集头部类别或干净样本。

量化验证不能只看总 mAP，要看小目标、低对比、边界、置信度分布和阈值是否需要重调。

## 剪枝与蒸馏

剪枝通过删除不重要的通道、卷积核、层或注意力头降低计算。非结构化剪枝理论压缩率高，但普通硬件上不一定加速；结构化剪枝更容易获得真实部署收益。

蒸馏用大模型 teacher 指导小模型 student。常见蒸馏信号：

- logits 蒸馏：学习类别软分布。
- feature 蒸馏：学习中间特征。
- relation 蒸馏：学习样本或空间关系。
- task head 蒸馏：检测框、mask、heatmap、OCR 序列。

蒸馏适合在不改变部署硬件的情况下提升轻量模型精度。要用同一测试集验证 student 是否真的优于直接训练的小模型。

## ONNX 与 TensorRT

ONNX 是模型交换格式，常用于从 PyTorch、TensorFlow 等框架导出到推理引擎。它描述计算图和算子，但不等于自动高性能。

TensorRT 是 NVIDIA GPU 上的高性能推理优化器，可做 layer fusion、kernel selection、precision calibration、dynamic shape optimization 等。

导出常见问题：

- 动态 shape 没配置，线上不同分辨率失败。
- 非标准算子不被 ONNX/TensorRT 支持。
- NMS、RoIAlign、grid_sample、deformable attention 等算子需要插件或替代实现。
- 训练预处理与部署预处理不一致。
- FP16/INT8 后置信度分布变化，原阈值失效。

建议保存端到端对齐用例：同一张图在 PyTorch、ONNX Runtime、TensorRT 上输出差异应在可接受范围内。

## Latency、Throughput 与 Memory

Latency 是单个请求从输入到输出的耗时。工业检测常看单帧端到端延迟，包括采图、解码、预处理、模型、后处理、通信和落库。

Throughput 是单位时间处理量，常通过 batch、流水线并行和异步队列提升。高吞吐不代表低延迟，大 batch 可能提升 FPS 但增加单张等待时间。

Memory 包括模型权重、激活、输入输出 buffer、后处理临时张量、队列缓存。显存不足会导致降 batch、OOM、频繁拷贝或吞吐抖动。

优化顺序：

1. 先测端到端耗时，分解预处理、推理、后处理。
2. 找最大瓶颈，不要凭感觉优化。
3. 减少 CPU/GPU 数据拷贝。
4. 固定输入尺寸或使用合理 dynamic shape profile。
5. 尝试 FP16、TensorRT、batch、异步流水线。
6. 必要时再做模型压缩、剪枝、蒸馏、INT8。

## 工业视觉流水线

典型工业视觉系统：

1. 触发采图：PLC、光电传感器、相机硬触发。
2. 图像获取：曝光、增益、白平衡、光源控制。
3. 预处理：裁剪 ROI、畸变校正、归一化、增强对齐。
4. 推理：分类、检测、分割、OCR 或异常检测。
5. 后处理：阈值、NMS、连通域、几何规则、尺寸测量。
6. 业务判定：OK/NG、缺陷等级、报警策略。
7. 通信执行：PLC、MES、机械臂、剔除机构。
8. 记录追溯：原图、结果图、模型版本、设备号、时间戳。
9. 监控迭代：抽检、漂移检测、失败样本回流。

工业项目要重视光源、镜头、相机安装和工艺节拍。很多问题不是模型结构能解决的，而是成像质量和数据闭环问题。

## 异常检测

工业异常检测常用于缺陷少、异常类型未知或标注成本高的场景。核心思路是只学习正常样本分布，推理时找偏离正常模式的区域。

PatchCore 思想：

- 用预训练 CNN 提取 patch 特征。
- 建立正常样本特征库，并用 coreset 降低存储。
- 测试时计算 patch 到正常特征库的最近邻距离。
- 距离大表示异常，可生成 anomaly map。

PaDiM 思想：

- 对每个空间位置建模正常特征的多元高斯分布。
- 测试时用 Mahalanobis distance 衡量偏离程度。
- 优点是位置相关，适合固定视角工业图像。

EfficientAD 思想：

- 使用 teacher-student 或 autoencoder 异常响应。
- 通过高效网络获得较快推理。
- 同时关注局部结构异常和全局重构差异。

异常检测局限：

- 对位置、光照、背景、产品姿态变化敏感。
- 正常样本覆盖不足会导致误报。
- 与监督检测相比，异常类别语义解释弱。
- 阈值通常需要按产线和产品型号单独校准。

## 上线故障排查顺序

1. 输入是否正确：图像是否为空、通道顺序、分辨率、颜色空间、压缩格式。
2. 预处理是否一致：resize、padding、归一化、mean/std、BGR/RGB。
3. 模型版本是否一致：checkpoint、导出文件、类别表、配置。
4. 输出解析是否正确：维度、坐标缩放、mask resize、OCR 字典。
5. 后处理是否一致：阈值、NMS、连通域、业务规则。
6. 数值精度是否影响：FP32、FP16、INT8 输出差异。
7. 性能瓶颈在哪里：采图、CPU 预处理、GPU 推理、后处理、通信。
8. 数据分布是否漂移：新产品、光照、相机位置、污染、磨损。
9. 监控和日志是否足够复现：保存原图、结果、版本、耗时和异常栈。
10. 回滚或降级策略是否可用：旧模型、人工复核、规则兜底。

## 部署验收清单

上线前应产出：

- 模型文件和版本号。
- 类别表、输入尺寸、预处理参数、后处理参数。
- 离线测试报告和切片评估。
- 与训练框架输出对齐的导出验证。
- 压测报告：平均、P95、P99、吞吐、内存。
- 异常输入测试。
- 回滚方案和监控字段。
