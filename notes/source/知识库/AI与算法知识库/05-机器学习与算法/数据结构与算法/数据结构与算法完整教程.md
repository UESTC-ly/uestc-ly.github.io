## 第 1 章：数据结构与算法基础

欢迎来到我们教程的第 1 章！在深入具体的数据结构（如数组、链表、树等）之前，我们需要先打好基础，理解一些核心概念。

### 1. 什么是数据结构？为什么它如此重要？

**数据结构 (Data Structure)** 是计算机中存储、组织数据的方式。它不仅包括数据元素本身，还包括数据元素之间的关系，以及对这些数据可以进行的操作。

* **为什么重要？**
  * 不同的场景需要不同的数据组织方式。例如，如果您需要快速查找数据，哈希表是首选；如果需要保证数据的绝对顺序，数组或链表可能更合适。
  * 优秀的数据结构选择能够极大提升程序的运行效率（减少执行时间）和资源利用率（降低内存消耗）。
  * 著名公式：“**程序 = 数据结构 + 算法**”（尼克劳斯·维尔特）。数据结构是算法发挥作用的舞台。

---

### 2. 算法复杂度分析 (时间复杂度与空间复杂度)

在我们编写代码时，如何衡量这段代码的“好坏”呢？主要通过两个指标：执行所需的时间和占用的内存空间。我们通常使用 **大 O 表示法 (Big O Notation)** 来描述随着输入数据规模 ($n$) 的增加，算法性能的变化趋势。

#### 2.1 时间复杂度 (Time Complexity)

时间复杂度衡量的是算法执行时间随输入规模增长的趋势，而不是精确的执行秒数。

常见的几个时间复杂度（从优到劣）：

* **O(1) - 常数时间**：无论数据规模多大，执行时间都固定。例如：通过索引访问数组元素 `arr[5]`。
* **O(log n) - 对数时间**：每次操作能排除掉一半的可能性。例如：二分查找 (Binary Search)。
* **O(n) - 线性时间**：执行时间与数据规模成正比。例如：使用一个 `for` 循环遍历数组。
* **O(n log n) - 线性对数时间**：常见于高效的排序算法，如快速排序、归并排序。
* **O(n^2) - 平方时间**：嵌套两层循环。例如：冒泡排序。
* **O(2^n) - 指数时间** / **O(n!) - 阶乘时间**：通常是暴力穷举，在 $n$ 较大时极其缓慢，应尽量避免。

##### 代码示例：展示不同的时间复杂度

```cpp
#include <iostream>
#include <vector>

using namespace std;

// O(1) 操作：直接访问，与数组大小无关
int getElementStart(const vector<int>& v) {
    if (v.empty()) return -1;
    return v[0];
}

// O(n) 操作：我们需要遍历整个数组
int sumArray(const vector<int>& v) {
    int sum = 0;
    for (int num : v) {
        sum += num;
    }
    return sum;
}

// O(n^2) 操作：双重循环嵌套
void printPairs(const vector<int>& v) {
    for (int i = 0; i < v.size(); i++) {
        for (int j = 0; j < v.size(); j++) {
            cout << "(" << v[i] << ", " << v[j] << ") ";
        }
        cout << endl;
    }
}
```

#### 2.2 空间复杂度 (Space Complexity)

空间复杂度衡量的是算法运行过程中**额外**占用的内存空间随输入规模 $n$ 的增长趋势。（不包含输入数据本身占用的基本空间）。

* **O(1)**：如果算法只需要几个普通变量存放中间结果，例如只占用几个 `int` 类型的指针，那么空间复杂度就是 O(1)。
* **O(n)**：如果为了完成算法，需要额外创建一个大小为 $n$ 的数组或链表，那么空间复杂度就是 O(n)。

---

### 3. 内存基础：连续空间与分散空间

要真正理解数据结构的底层性能差异，必须要了解内存。在操作系统分配内存时，主要有两种物理存储方式：

1. **连续内存空间 (Contiguous Memory)**
   * **特点**：在内存中申请一整块连续的区域。
   * **代表结构**：数组 (Array)。
   * **优势**：支持随机访问（通过索引一步到位找到元素，O(1) 时间），且因为 CPU 缓存机制（局部性原理），连续内存的读取速度极快。
   * **劣势**：插入和删除元素较慢（需要移动后续所有元素），且分配大块连续内存时可能会遇到内存碎片问题。

2. **分散/非连续内存空间 (Non-contiguous Memory)**
   * **特点**：数据分散存储在内存的各个角落，每个数据块除了存储数据本身，还要存储指向下一个（或上一个）数据块位置的指针（地址）。
   * **代表结构**：链表 (Linked List)。
   * **优势**：可以在不用移动其他元素的情况下，极其快速地插入和删除数据（只需改变指针指向），对内存利用率高。
   * **劣势**：无法随机访问，必须从头顺藤摸瓜遍历（O(n) 时间）。因为物理不连续，CPU 缓存命中率较低。

理解了「连续」与「分散」这两个核心概念后，您就已经掌握了这门课程的“内功心法”。接下来在第 2 章中，我们将详细讨论基于这两种内存方式设计的两大基础结构：**数组与链表**。

## 第 2 章：数组与链表 (Array & Linked List)

在第 1 章中，我们了解到内存分配主要有**连续空间**和**分散空间**两种方式。这就是数组和链表的底层根源。无论多么复杂的数据结构（如树、图、哈希表），其底层基石归根结底都是数组或链表（或二者的结合）。

---

### 2.1 数组 (Array)

数组是将相同类型的元素存储在**连续的内存空间**中的数据结构。

#### 优缺点分析

*   **优点（随机访问极快）**：因为内存是连续的，只要知道数组起始地址和元素类型的大小，就能直接计算出任何一个索引元素的内存地址。例如获取 `arr[5]`，地址等于 `起始地址 + 5 * 数据大小`。时间复杂度是真正的 **O(1)**。
*   **缺点（增删极慢，大小固定）**：
    *   **插入与删除慢**：如果要在数组中间插入（或删除）一个元素，该位置之后的所有元素都必须向后（或向前）移动一位，时间复杂度为 **O(n)**。
    *   **大小固定**：原生数组一旦创建，大小无法改变。如果装满了，需要申请一块更大的新连续内存，将原数据全拷过去（这就衍生出了动态数组的概念）。

#### 动态数组 (如 C++ 的 `std::vector`)

在 C++ 中，原生数组使用较繁琐。标准库为我们提供了强大的动态数组 `std::vector`，它底层依然是数组，但它会在容量不足时自动进行扩容（通常是变为原来容量的 1.5 倍或 2 倍）。

##### 代码示例：C++ 中 `std::vector` 的基础操作
```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    // 声明一个动态数组
    vector<int> nums = {10, 20, 30};

    // 1. O(1) 随机访问
    cout << "索引 1 的元素是: " << nums[1] << endl; // 输出 20

    // 2. O(1) 尾部追加元素
    nums.push_back(40); // 数组变为 {10, 20, 30, 40}

    // 3. O(1) 尾部删除元素
    nums.pop_back(); // 数组变为 {10, 20, 30}

    // 4. O(n) 中间插入元素：很耗时，需移动后续元素
    nums.insert(nums.begin() + 1, 15); // 变成 {10, 15, 20, 30}

    // 5. O(n) 遍历数组
    cout << "当前数组: ";
    for (int n : nums) {
        cout << n << " ";
    }
    cout << endl;

    return 0;
}
```

### 2.2 链表 (Linked List)

链表的数据节点存在于**分散的内存空间**中。通过节点中的“指针”（指向下一个节点的内存地址）将所有分散的节点串联起来。

#### 单向链表 (Singly Linked List)
单向链表的每个节点包含两部分：
1.  **数据域 (Data/Val)**：存储实际的数据。
2.  **指针域 (Next)**：存储下一个节点的地址。

##### 单向链表节点及其基本操作的代码实现

```cpp
#include <iostream>

using namespace std;

// 链表节点结构体
struct ListNode {
    int val;           // 数据域
    ListNode* next;    // 指针域

    // 构造函数
    ListNode(int x) : val(x), next(nullptr) {}
};

int main() {
    // 1. 创建节点
    ListNode* node1 = new ListNode(10);
    ListNode* node2 = new ListNode(20);
    ListNode* node3 = new ListNode(30);

    // 2. 将节点链接起来：node1 -> node2 -> node3
    node1->next = node2;
    node2->next = node3;

    // 3. O(n) 遍历链表 (因为无法随机访问，必须从头开始找)
    ListNode* current = node1;
    cout << "链表元素: ";
    while (current != nullptr) {
        cout << current->val << " -> ";
        current = current->next;
    }
    cout << "nullptr" << endl;

    // 4. O(1) 插入新节点：在 node1 和 node2 之间插入 nodeNew
    /* 
       不需要移动其他元素，只需断开并重连两根指针。
       但前提是你已经拿到了这个插入位置的指针。
    */
    ListNode* nodeNew = new ListNode(15);
    nodeNew->next = node1->next; // 先把新节点接向 20
    node1->next = nodeNew;       // 再把 10 接向新节点

    return 0;
}
```

#### 2.3 双向链表与循环链表

*   **双向链表 (Doubly Linked List)**：除了 `next` 指向后一个节点外，还多出了一个 `prev` 指针指向前一个节点。这使得“向前遍历”成为了可能，并且在已知待删除节点本身时，能真正实现 O(1) 时间内删除自己（因为能轻易找到前继节点修改其 next 指针）。
*   **循环链表 (Circular Linked List)**：链表的尾节点不再指向 null，而是指向头节点，形成一个闭环。常用于解决“约瑟夫环”等周期性问题。

---

### 2.4 数组与链表的终极对比

| 特性 | 数组 (Array) | 链表 (Linked List) |
| :--- | :--- | :--- |
| **内存分配** | 连续物理内存 | 分散物理内存 |
| **空间效率** | 优秀（无需存储前驱后继指针） | 较差（每个节点都要浪费空间存指针） |
| **随机访问 (查/改)** | **O(1)** （索引极快） | **O(n)** （必须从头开始遍历寻找） |
| **头部/中间的插入/删除** | **O(n)** （需要大量搬移数据） | **O(1)** （仅涉及相邻节点指针转向，前提是已定位到该位置） |
| **尾部插入** | O(1)（动态数组扩容时会有 O(n) 的小概率开销） | O(1) （若维护了尾指针） |
| **CPU 缓存亲和度** | 极佳（空间连续，CPU可预读） | 较差（空间跳跃，易引发 Cache Miss） |

#### 适用场景总结：
*   如果你的应用**“读多写少”**，经常需要根据索引快速获取元素，且数据条目的大致数量是已知的，**坚决使用数组 (`std::vector`)**。
*   如果你的应用**“写多读少”**，频繁在集合的**头部或中间**进行增删操作，并且极少需要使用索引查询特定的元素位置，那么可以考虑使用**链表**。

> **小提示：** 在实际工程（例如 C++ 开发中），由于连续内存带来的极致 CPU 缓存命中率优势，绝大多数场景下 `std::vector` 的综合性能都远超链表 `std::list`，哪怕存在偶尔的中间插入。因此，只有在非常明确确实有海量增删操作且需要频繁避免数据搬移时，才去选择链表解决问题。

## 第 3 章：栈与队列 (Stack & Queue)

在掌握了数组和链表（通常被称为“线性表”）之后，我们来看两种基于线性表构建的、带有**特殊操作限制**的数据结构：栈与队列。

### 3.1 栈 (Stack)：后进先出 (LIFO)

栈是一种只能在一端（称为**栈顶 Top**）进行插入和删除操作的线性表。
*   **特性**：**后进先出** (Last In, First Out - **LIFO**)。最后压入栈的元素，最先被弹出来。
*   就像一摞洗干净的盘子，你只能把新盘子放在最顶上，也只能从最顶上拿盘子。

#### C++ `std::stack` 基本操作

在 C++ 中，`#include <stack>` 提供了标准栈实现。

```cpp
#include <iostream>
#include <stack>

using namespace std;

int main() {
    stack<int> s;

    // 1. 压栈 (Push) - O(1)
    s.push(10);
    s.push(20);
    s.push(30);

    // 2. 查看栈顶元素 (Top) - O(1)
    cout << "栈顶元素: " << s.top() << endl; // 输出 30

    // 3. 出栈 (Pop) - O(1) (注意：pop() 不返回弹出的值)
    s.pop(); 
    cout << "弹出一次后，新的栈顶: " << s.top() << endl; // 输出 20

    // 4. 判断是否为空 (Empty)
    if (!s.empty()) {
        cout << "栈的大小: " << s.size() << endl; // 输出 2
    }

    return 0;
}
```

#### 栈的经典应用场景
1.  **函数调用栈**：每次调用函数时，局部变量、返回地址等信息都会被压入系统调用栈；函数执行完毕后出栈。这就是递归能够工作的基础。
2.  **括号匹配**：阅读一段代码，遇到左括号 `(` 则压栈，遇到右括号 `)` 则判断栈顶是否是匹配的左括号并弹出。
3.  **浏览器的前进/后退**：使用两个栈可以实现页面的前进和后退功能。

---

### 3.2 队列 (Queue)：先进先出 (FIFO)

队列是一种允许在**一端（队尾 Rear）**进行插入，在**另一端（队头 Front）**进行删除的线性表。
*   **特性**：**先进先出** (First In, First Out - **FIFO**)。最先排队的元素，最先被处理。
*   如同超市结账排队，先来的人先结账离开。

#### C++ `std::queue` 基本操作

```cpp
#include <iostream>
#include <queue>

using namespace std;

int main() {
    queue<string> q;

    // 1. 入队 (Push) - O(1)
    q.push("Alice");
    q.push("Bob");
    q.push("Charlie");

    // 2. 查看队头元素 (Front) 和 队尾元素 (Back) - O(1)
    cout << "队头: " << q.front() << endl; // 输出 Alice
    cout << "队尾: " << q.back() << endl;  // 输出 Charlie

    // 3. 出队 (Pop) - O(1)
    q.pop();
    cout << "出队一次后，新的队头: " << q.front() << endl; // 输出 Bob

    return 0;
}
```

#### 队列的拓展

1.  **循环队列 (Circular Queue)**：通常用固定大小的数组实现，通过将数组头尾逻辑上相连，避免了普通数组队列在出队后造成的空间浪费。
2.  **双端队列 (Deque, Double-Ended Queue)**：允许在队头和队尾都可以进行插入和删除操作。在 C++ 中是 `std::deque`。
3.  **优先队列 (Priority Queue)**：虽然叫队列，但它的出队顺序与入队无关，而是按照元素的**优先级**来出队。底层的实现通常是 **堆 (Heap)**，我们将在第 5 章详细讲解。

#### 队列的应用场景
*   **操作系统任务调度**：CPU 处理多线程或突发任务时，会将任务放入队列中排队。
*   **广度优先搜索 (BFS)**：在图或树结构中，使用队列来按层级逐步向外扩散搜索（详见第 7 章）。

## 第 4 章：树与二叉树 (Tree & Binary Tree)

前面介绍的数组、链表、栈和队列都是**线性结构**（一对一关系）。而**树 (Tree)** 是一种非常重要的**非线性结构**，用于表示具有层次关系（一对多）的数据。

### 4.1 树的基本概念

*   **节点 (Node)**：树的基本单元，包含数据和指向子树的指针。
*   **根节点 (Root)**：树的最顶端节点，没有父节点。
*   **叶子节点 (Leaf)**：没有子节点的节点。
*   **深度 (Depth)**：从根节点到某节点的最长路径长度（根的深度通常记为 0 或 1）。
*   **高度 (Height)**：从某节点到其最远叶子节点的最长路径长度。

---

### 4.2 二叉树 (Binary Tree)

**二叉树**是树的一种特殊形式，它的每个节点**最多只有两个子节点**，分别称为**左子节点 (Left Child)**和**右子节点 (Right Child)**。

#### C++ 二叉树节点定义

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
```

#### 满二叉树与完全二叉树
*   **满二叉树 (Full Binary Tree)**：所有的非叶子节点都有左右两个子节点，且所有叶子节点全在最底层。
*   **完全二叉树 (Complete Binary Tree)**：除了可能最后一层没有填满外，其余所有层都是满的，并且最后一层的节点尽量靠左排列。堆 (Heap) 就是一种典型的完全二叉树。

---

### 4.3 二叉树的遍历 (Tree Traversal)

遍历是指按照一定顺序访问树中的所有节点，每个节点被访问且仅被访问一次。可以分为两大类：**深度优先搜索 (DFS)** 和 **广度优先搜索 (BFS)**。

#### 1. 深度优先遍历 (DFS)
通常使用**递归**或**栈**来实现。包含以下三种：
*   **前序遍历 (Pre-order)**：根 -> 左子树 -> 右子树
*   **中序遍历 (In-order)**：左子树 -> 根 -> 右子树
*   **后序遍历 (Post-order)**：左子树 -> 右子树 -> 根

**代码示例：中序遍历 (递归版本)**
```cpp
#include <iostream>

void inorderTraversal(TreeNode* root) {
    if (root == nullptr) {
        return;
    }
    inorderTraversal(root->left);   // 1. 遍历左子树
    std::cout << root->val << " ";  // 2. 访问根节点
    inorderTraversal(root->right);  // 3. 遍历右子树
}
```

#### 2. 广度优先遍历 (层序遍历, Level-order)
从上到下、从左到右，一层一层地访问。这种遍历方式必须借助**队列 (Queue)** 来实现。

```cpp
#include <iostream>
#include <queue>

void levelOrderTraversal(TreeNode* root) {
    if (root == nullptr) return;
    
    std::queue<TreeNode*> q;
    q.push(root);
    
    while (!q.empty()) {
        TreeNode* current = q.front();
        q.pop();
        
        std::cout << current->val << " ";
        
        if (current->left != nullptr) q.push(current->left);
        if (current->right != nullptr) q.push(current->right);
    }
}
```

---

### 4.4 二叉搜索树 (Binary Search Tree, BST)

**二叉搜索树**是一种特殊的二叉树，它具有如下神奇的性质：
*   **左子树**上所有节点的值均 **小于** 它的根节点的值。
*   **右子树**上所有节点的值均 **大于** 它的根节点的值。
*   对其进行 **中序遍历**，可以得到一个**递增**的有序序列。

**时间复杂度：**
*   在理想情况下（树比较平衡），查找、插入、删除的时间复杂度均为 **O(log n)**，这使得它成为了高效查找的利器。
*   但在极端情况下（如持续插入递增的数字 1, 2, 3...），BST 会退化成一条普通的链表，时间复杂度退化为 **O(n)**。

为了解决退化问题，计算机科学家发明了**自平衡二叉搜索树**。
*   **AVL 树**：严格平衡，左右子树高度差不超过 1。查询最快，但插入删除需要频繁旋转。
*   **红黑树 (Red-Black Tree)**：非严格平衡（最长路径不超过最短路径的 2 倍），通过变色和旋转维护平衡。C++ 的 `std::map` 和 `std::set` 底层正是由红黑树实现的。


---

## 第 5 章：堆与优先队列 (Heap & Priority Queue)

在第 3 章我们提到，优先队列的出队顺序取决于元素的**优先级**，而不是先进先出。为了高效实现优先队列，底层通常会使用一种叫做**堆 (Heap)** 的数据结构。

### 5.1 什么是二叉堆？

**二叉堆 (Binary Heap)** 本质上是一棵**完全二叉树**（除了最后一层外全是满的，且最后一层靠左排列）。基于此特性，堆非常适合用**数组（连续内存）**来存储，而不需要使用指针。

如果数组的下标从 `0` 开始，对于任意位置 `i` 的节点：
*   左子节点下标：`2 * i + 1`
*   右子节点下标：`2 * i + 2`
*   父节点下标：`(i - 1) / 2`

**堆的性质分类：**
1.  **大顶堆 (Max Heap)**：任意节点的值都 **大于或等于** 其左右子节点的值。根节点是全堆中的**最大值**。
2.  **小顶堆 (Min Heap)**：任意节点的值都 **小于或等于** 其左右子节点的值。根节点是全堆中的**最小值**。

---

### 5.2 堆的核心操作：上浮与下沉

要使一棵完全二叉树时刻保持“堆”的性质，离不开两种核心微调操作。所有插入和删除都基于这两个操作完成，时间复杂度均为 **O(log n)**。

*   **上浮 (Sift Up) - 对应【插入】元素**：
    将新元素放到数组的最末尾（树的最后一片叶子）。如果新元素比它的父亲大（以大顶堆为例），就与父亲交换位置，继续向上比较，直到它没有父亲或者比父亲小为止。
    
*   **下沉 (Sift Down) - 对应【删除】堆顶元素**：
    删除根节点（最大值/最小值）后，将数组最末尾的元素搬到根节点的位置。然后让这个元素与其左右儿子比较，如果比儿子小（以大顶堆为例），就和**较大的那个儿子**交换位置，继续向下比较，直到叶子节点。

---

### 5.3 C++ 中的优先队列 (`std::priority_queue`)

在工程中，如果我们需要维护一个随时获取最大值或最小值的数据流，无需手动手写上浮和下沉，可直接使用 `<queue>` 库中的 `std::priority_queue`。

#### 代码示例：C++ 优先队列

```cpp
#include <iostream>
#include <queue>
#include <vector>

using namespace std;

int main() {
    // 1. 默认是大顶堆 (Max Heap)，最大的元素优先出队
    priority_queue<int> maxHeap;
    maxHeap.push(10);
    maxHeap.push(30);
    maxHeap.push(20);

    cout << "大顶堆的堆顶 (最大值): " << maxHeap.top() << endl; // 输出 30

    // 2. 自定义为小顶堆 (Min Heap)，最小的元素优先出队
    // 参数说明：<数据类型, 存储容器底层(通常用vector), 比较器>
    priority_queue<int, vector<int>, greater<int>> minHeap;
    
    minHeap.push(10);
    minHeap.push(30);
    minHeap.push(20);

    cout << "小顶堆的堆顶 (最小值): " << minHeap.top() << endl; // 输出 10
    
    // 3. 元素出队 (O(log n))
    minHeap.pop(); // 弹出 10
    cout << "新的小顶堆堆顶: " << minHeap.top() << endl; // 输出 20

    return 0;
}
```

### 5.4 堆排序 (Heap Sort) 的简短介绍
利用堆可以实现高效的原地排序（时间复杂度 **O(n log n)**，空间复杂度 **O(1)**）：
1. 将无序数组进行 `heapify` 演化为大顶堆（此时数组头为最大元素）。
2. 将数组头的最大元素与数组尾元素交换。堆的大小减一。
3. 对换到头部的元素进行一次**下沉**操作，恢复堆的性质。
4. 重复步骤 2 和 3，直到堆大小为 1，此时数组完全转化为递增排序。

## 第 6 章：哈希表 (Hash Table)

**哈希表 (Hash Table)**，又称散列表，是计算机科学中最被广泛应用的高效数据结构之一。它用极其巧妙的方式，完美融合了数组的高速随机访问优势。

### 6.1 哈希表的核心概念

哈希表的主要思想是：通过一个叫做 **哈希函数 (Hash Function)** 的东西，把我们存入的查找键 (Key) 转化为数组的索引（整数），然后直接通过这个索引，在底层的数组里 O(1) 地存放或获取它对应的值 (Value)。

*   **输入**：Key (比如用户名 `"Alice"`)
*   **哈希函数**：`Hash("Alice") = 152`
*   **存储动作**：直接将 `"Alice"` 的相关信息丢到数组下标为 `152` 的位置。

这种直接定位的过程，赋予了哈希表近乎 **O(1)** 的完美插入、删除和查询速度。

---

### 6.2 哈希冲突 (Hash Collision)

宇宙中没有完美的函数。当你要存储的数据极多，而数组容量有限时，必然会出现两个不同的 Key 经过哈希函数计算后，得出了**同一个数组索引**。这种情况称为 **哈希冲突**。

解决哈希冲突最主流的核心方案有以下两种：

#### 1. 拉链法 (Chaining) - 最常见
利用我们在前几章学过的链表。哈希表底层的数组不再直接存数据，而是存储指向一个链表头节点的指针。如果两个 Key 算出了相同的索引，就把它们依次**挂在同一个链表后面**。
*   Java 的 `HashMap`，C++ 的 `unordered_map` 底层大多以此为基础。

#### 2. 开放寻址法 (Open Addressing)
如果算出的索引已经被别人占了，那就按照某种规则（比如往后挪一步，或者跳跃着找）在这个数组里**找下一个空位置**，直到找到为止。

---

### 6.3 负载因子与扩容 (Rehashing)

随着存入哈希表的元素越来越多，发生冲突的概率会急剧上升，拉链法挂接的链表会越来越长，本来 O(1) 的查询速度会慢慢退化成 O(n)。

*   **负载因子 (Load Factor)** = `已存元素个数 / 哈希表数组总容量`

当负载因子达到一定阈值（如 0.75 时），哈希表会自动触发 **扩容 (Rehashing)**：它会申请一个通常为原来两倍大的新数组，将所有旧元素重新通过新的哈希函数计算并安排到新数组中。这个操作十分耗时，但均摊在每一次操作上的时间复杂度仍然是 O(1)。

---

### 6.4 C++ 中的哈希表使用

在 C++ STL 中，只要带有 `unordered_` 前缀的容器，底层统统是哈希表。而不带这个前缀的（如 `std::map`, `std::set`）底层是我们在第 4 章讲到的能保持数据有序的红黑树。

#### 代码示例：`std::unordered_map` 与 `std::unordered_set`

```cpp
#include <iostream>
#include <unordered_map>
#include <unordered_set>
#include <string>

using namespace std;

int main() {
    // 1. 无序映射：存放 Key-Value 键值对
    unordered_map<string, int> ageMap;
    
    // 极其快速的 O(1) 插入
    ageMap["Alice"] = 25;
    ageMap["Bob"] = 30;
    
    // O(1) 查找
    if (ageMap.find("Alice") != ageMap.end()) {
        cout << "Alice 的年龄是: " << ageMap["Alice"] << endl;
    }

    // 2. 无序集合：只存放 Key（保证唯一性，常用于去重）
    unordered_set<int> uniqueNumbers;
    uniqueNumbers.insert(10);
    uniqueNumbers.insert(20);
    uniqueNumbers.insert(10); // 重复插入将被忽略

    cout << "集合的大小是: " << uniqueNumbers.size() << endl; // 输出 2

    return 0;
}
```

#### 何时使用哈希表？
每当问题中出现：“查找某个元素是否存在”、“统计频次”、“找两个数之和等需要缓存历史数据以便后续瞬间查阅”的场景，首选**哈希表**一定毋庸置疑！

## 第 7 章：图论基础 (Graph)

相比于树，**图 (Graph)** 是一种更为宽泛和复杂的非线性数据结构。实际上，链表是一棵特殊的树，而树也是一种特殊的图。这种数据结构常被用于表示互联网、社交网络路线、以及地图导航。

### 7.1 图的核心概念

一个图 $G$ 定义为顶点集合 $V$ 和边集合 $E$ 的组合：$G = (V, E)$。
*   **顶点 (Vertex/Node)**：例如在社交网络中，每个用户就是一个顶点。
*   **边 (Edge)**：连接两个顶点的线。例如两个用户是好友。
*   **有向图 (Directed Graph)**：边有方向，比如你在微博关注了某人，某人没关注你。
*   **无向图 (Undirected Graph)**：边没有方向，比如微信好友，必然是双向的。
*   **权重 (Weight)**：如果边带有一个数值，叫做权重（比如地图上两个城市之间的实际物理距离）。

---

### 7.2 图的表示方式

要把无尽纵横的“图”塞入存在内存里的“线性数组”中，主要有两种方法：

#### 1. 邻接矩阵 (Adjacency Matrix)
使用一个二维数组 `matrix[i][j]`。
如果顶点 `i` 和顶点 `j` 之间有边，那么矩阵对应的值为 1（或权重），否则为 0。
*   **特点**：极其耗费空间（时间空间皆为 $O(V^2)$），只适合点少边多（稠密图）。但查询某两个点是否有连接只需要 O(1)。

#### 2. 邻接表 (Adjacency List)
给图中的每一个顶点创建一个“链表”（或动态数组 `vector`）。这个链表里只存放和该点直接相连的其余顶点的编号。
*   **特点**：极高地节省了空间，适合大型网络环境下的稀疏图。

**C++ 中以邻接表表示图的常见写法:**
```cpp
#include <iostream>
#include <vector>

using namespace std;

int main() {
    int n = 5; // 假设有 0 到 4 五个顶点
    
    // 外层 vector 代表 5 个顶点，内层 vector 存储与其相邻的顶点集合
    vector<vector<int>> graph(n);
    
    // 添加无向边: 0 - 1, 0 - 4, 1 - 2, 1 - 3, 1 - 4
    graph[0].push_back(1); graph[1].push_back(0);
    graph[0].push_back(4); graph[4].push_back(0);
    graph[1].push_back(2); graph[2].push_back(1);
    graph[1].push_back(3); graph[3].push_back(1);
    graph[1].push_back(4); graph[4].push_back(1);

    return 0;
}
```

---

### 7.3 图的遍历 (DFS 与 BFS)

与树一样，图的遍历也是最为基础的核心操作，用以探索整个图。

#### 深度优先搜索 (Depth First Search, DFS)
*   **思想**：一条路走到黑。从某点出发，选一条没走过的边大胆走到底，无路可走就退后一步换一条路。
*   **实现机制**：递归或 **栈 (Stack)**。
*   **关键点**：由于图里可能存在“环”（走着走着又走回了原点），必须用一个 `visited` 数组记录走过的点，去过的地方绝不去第二次！

#### 广度优先搜索 (Breadth First Search, BFS)
*   **思想**：像水波纹一样层层扩散。先拜访离自己最近的朋友，再慢慢拜访朋友的朋友。
*   **实现机制**：**队列 (Queue)**。
*   **重大作用**：BFS 是图论中寻找 **“无权图最短路径”** 最天然、最优越的算法。

#### 最短路径与最小生成树初步
在面临更为复杂的加权图时：
*   求解最经典的**最短路径问题**（从 A 市去 B 市，怎么走最省油/距离最短）：Dijkstra 算法、Bellman-Ford 算法等。
*   求解**最小生成树问题**（铺设网线连接所有城市，怎么施工花费最低）：Kruskal 算法、Prim 算法。


---

## 第 8 章：排序算法汇总 (Sorting Algorithms)

“排序”是计算机处理海量数据最古老、最根本的需求。我们将几百种排序算法提炼出最核心的代表，在数据结构的最后一章对它们进行全方位比较。

### 8.1 基础排序 (时间复杂度通常 $O(n^2)$)

由于存在双重循环，这类排序很难应用在数据量庞大的生产环境中，但它们能提供良好的算法思维启蒙。

1.  **冒泡排序 (Bubble Sort)**：每轮相邻两个元素做比较，把大的元素像泡泡一样“顶”到数组末尾。
2.  **选择排序 (Selection Sort)**：每一轮遍历出数组中最小的元素，毫无顾忌地把它直接放到数组对应的前排位置。
3.  **插入排序 (Insertion Sort)**：像打扑克牌一样，每次摸到一张新牌，就从右向左对比，将它插入到已有序的左边的位置里。（如果原数组基本有序，插入排序效率会奇高，无限逼近 O(n)）。

---

### 8.2 高效排序 (时间复杂度通常 $O(n \log n)$)

这两种排序彻底改变了性能瓶颈，其核心都运用了**分治法 (Divide & Conquer)**，也就是把大问题拆成毫无相关的小问题解决。

#### 1. 归并排序 (Merge Sort)
*   **极度稳定**：它是最平稳的排序。它先把大数组从中间“一刀切”持续切成长度为 1 的单个元素，然后将这两个有序的部分，像拉拉链一样，利用额外申请的内存合并成大的有序部分。
*   时间复杂度稳定在 $O(n \log n)$，但空间因为需要额外开辟数组，为 $O(n)$。

#### 2. 快速排序 (Quick Sort)
*   **工业界真神**：你使用的各类语言 `sort()` 函数，底层最核心的框架大概率是快速排序（辅以其他排序）。
*   **原理**：随便挑选一个基准点 (Pivot)。把比它小的统统移到它左侧，比它大的统统移到它右侧。然后对左右子数组进行相同的操作，直到排序完成。
*   时间平均 $O(n \log n)$，且是在原数组内直接交换，空间复杂度 $O(\log n)$（递归栈），但若运气极差（比如已排好序的数组选错基准），可能退化成 $O(n^2)$。

#### 代码示例：C++ 标准库神级函数 `std::sort`
在绝大多数情况下，不要去手写以上算法，直接调用强大的 STL。
```cpp
#include <iostream>
#include <vector>
#include <algorithm> // sort 头文件

using namespace std;

int main() {
    vector<int> nums = {4, 2, 8, 5, 1, 7};
    
    // 默认是升序排序 (从小到大)
    sort(nums.begin(), nums.end());
    
    // 若要降序排序，可传入第三个参数（利用 lambda 或者 std::greater）
    sort(nums.begin(), nums.end(), greater<int>());
    
    return 0;
}
```

---

### 8.3 排序算法大乱斗全面对比表

| 排序算法 | 平均时间复杂度 | 最差时间复杂度 | 空间复杂度 | 稳定性 | 特点与应用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **冒泡排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 教学意义大于实际意义 |
| **插入排序** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 处理非常小规模或**基本有序**的数据极其高效 |
| **归并排序** | $O(n \log n)$ | $O(n \log n)$ | **$O(n)$** | 稳定 | 适合外部大数据排序（在磁盘中排序并合并） |
| **快速排序** | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | **不稳定** | **大多数通用内存排序的首选之星** |
| **堆排序** | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | **不稳定** | 适合找“前 K 大”或“前 K 小”元素 (Top-K 问题) |

> *稳定性*：指若两个元素值相等，经过排序后，他们原来的前后相对位置是否被保持。这对基于多个属性进行排序时具有重大意义。
