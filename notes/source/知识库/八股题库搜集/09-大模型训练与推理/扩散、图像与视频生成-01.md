## 2）如何保证 AI coding 生成代码的质量？

**回答：**

质量不能靠一句“请生成高质量代码”保证，而要把自然语言要求转换成可执行的质量门禁。

首先明确契约：函数签名、数据不变量、错误语义、性能上限、兼容版本和安全要求；对 Agent 工具尤其要定义参数 schema、权限、幂等性和副作用。然后让模型先写测试或验收样例，再实现代码，降低“实现了错误需求”的风险。

验证链路至少包括：

- 编译、类型检查、lint、格式检查和依赖漏洞扫描；
- 单元测试覆盖正常、边界、异常、空值、超时和重复调用；
- 集成测试验证数据库、消息队列、外部 API 和工具调用；
- 性能、并发、资源泄漏和故障注入测试；
- 对模型/Agent 代码增加轨迹回放、结构化输出校验、工具参数校验和离线评测集。

审查时重点看 AI 容易犯的错误：凭空引入不存在的 API，忽略旧接口兼容性，把异常吞掉，重试造成重复副作用，使用不安全的反序列化，或在并发场景下共享可变状态。高风险模块采用小 diff、双人评审和灰度发布；低风险重复代码可以提高自动化比例。

最终质量标准是“可证明地满足约束”，而不是代码看起来像人写的。模型可以生成候选实现，但测试、静态分析、代码评审和线上可观测性共同承担质量责任。

## 3D 先验如何提升数字人生成的可控性？

3D 先验的价值在于把难以直接从像素中稳定学习的结构变量显式化。

常见方式包括：

- **用 3DMM/FLAME 控制脸部**：将头部姿态、表情、眼球、下颌、嘴型转为可渲染条件。
- **用 SMPL/SMPL-X 控制身体**：把人体姿态、体型、手势和面部表情变成统一参数。
- **用深度/法线/分割控制生成**：给扩散模型提供空间约束，减少肢体错位、脸部变形和服装漂移。
- **用 UV/纹理空间保持身份**：把人脸或身体纹理绑定到稳定拓扑，跨帧复用。
- **用可微渲染做反向优化**：通过图像损失反推相机、姿态、形状、表情、光照和材质参数。

例如人像视频生成可以先估计每帧 FLAME 参数，再渲染法线图、深度图和语义图，最后用视频扩散模型生成高保真帧。这样模型不需要凭空“猜”头部旋转和嘴型结构。

## 3D 数字人与生成式模型如何结合？

AIGC 时代的 3D 数字人越来越多采用“3D 结构控制 + 生成式外观增强”的混合路线。

常见结合方式：

1. **3D 条件控制扩散模型**

   先从 3DMM/SMPL/SMPL-X 渲染 depth、normal、pose、segmentation、DensePose、UV，再作为 ControlNet/Adapter/视频扩散模型条件。

2. **生成模型补全 3D 资产**

   使用图像/文本到 3D、纹理生成、材质生成、法线生成，为 Mesh Avatar 生成外观。

3. **神经渲染增强真实感**

   用 NeRF/3DGS/neural texture 表示传统 Mesh 难以表达的头发、皮肤细节、衣物褶皱和视角相关反射。

4. **3D 约束视频生成**

   通过相机轨迹、骨架动作、表情曲线和口型参数约束视频生成，减少时序漂移。

5. **从视频反向构建 Avatar**

   从一段真人视频估计人脸/人体参数、纹理、动态细节，再训练可驱动 Avatar。

一句话总结：

3D 提供结构和控制，生成模型提供真实感和多样性；二者结合是当前数字人落地的主流方向。

## AnyTalker 与 MultiTalk 在多人对话生成上有什么区别？

MultiTalk 和 AnyTalker 都面向多人说话视频生成，但侧重点不同。

**MultiTalk** 更强调多路音频与人物的绑定问题。它提出 Multi-Person Conversational Video Generation，并使用 L-RoPE 将人物标签信息注入 rotary position embedding，使音频 token 和对应人物区域更容易在 attention 中匹配。

**AnyTalker** 更强调多人规模化和互动自然性。它希望用更灵活的多流结构扩展多身份，并通过 interactivity refinement 让人物之间不仅各说各话，还能有倾听、回应、视线和互动动作。

对比：

| 维度 | MultiTalk | AnyTalker |
| --- | --- | --- |
| 核心问题 | 多路音频和人物绑定 | 多人扩展与互动自然性 |
| 关键技术 | L-RoPE、部分参数训练、多任务训练 | 多流结构、交互细化、多人 checkpoint |
| 典型能力 | 单人/多人说话、唱歌、prompt 控制 | 多人对话、互动动作、身份扩展 |
| 面试关键词 | audio-person binding | interactivity refinement |

多人数字人的关键不是“把多个单人模型拼起来”，而是要同时解决说话人绑定、轮次交替、倾听表情、人物间视线和群体构图。

## autoregressive policy / diffusion policy

**回答：**

自回归策略把联合动作分布分解为条件序列分布，逐个生成动作维度、时间步或编码 token；具体分解顺序由动作表示决定。它不必只处理离散动作，也不必与 chunking 互斥。

```math
p(z_{1:M}\mid c)=\prod_{i=1}^{M}p(z_i\mid z_{\lt i},c)
```

条件 c 包含观测和任务。离散 token 方案常用交叉熵训练；量化粒度、序列长度和解码方法影响精度与延迟，teacher forcing 与实际生成的条件差异也值得关注。

Diffusion Policy 则学习条件动作序列分布，训练时对真实动作加噪并学习去噪，推理从噪声开始多步生成动作块。以噪声预测形式为例：

```math
\mathcal L=\mathbb E_{A,c,t,\epsilon}\left[\left\|\epsilon-\epsilon_\theta(\sqrt{\bar\alpha_t}A+\sqrt{1-\bar\alpha_t}\epsilon,t,c)\right\|_2^2\right]
```

| 维度 | 自回归策略 | 扩散策略 |
| --- | --- | --- |
| 生成方式 | 按所选序列顺序逐项生成 | 多次迭代更新一段动作 |
| 常见优势 | 适合 token 接口和序列条件建模 | 连续、多峰动作序列建模较自然 |
| 主要代价 | 序列长度与串行解码开销 | 去噪次数及每步网络计算 |
| 实际评估 | 编码误差、闭环效果、时延 | 采样步数、闭环效果、时延 |

“扩散一定更慢”或“自回归一定更准”都需要给出具体模型和预算。流匹配也可生成连续动作，但学习的是相应速度场，不能把其目标函数直接写成所有扩散模型都使用的噪声预测损失。

**流匹配与扩散的区别应讲到训练目标。** 用一个简化的条件流匹配例子说明：令 $`A_0`$ 是噪声动作块，$`A_1`$ 是数据动作块，构造直线路径 $`A_\tau=(1-\tau)A_0+\tau A_1`$。其对应速度目标是 $`A_1-A_0`$：

```math
\mathcal L_{\mathrm{FM}}=\mathbb E\left[\left\|v_\theta(A_\tau,\tau,c)-(A_1-A_0)\right\|_2^2\right].
```

推理时沿学习到的速度场积分，逐步把噪声变为动作。这个式子用于解释一类直线路径流匹配，不是对所有 VLA 或某个具体模型完整训练配方的复述。路径、时间采样、条件注入、损失权重和数值求解器都可能变化。

三类策略的比较应固定机器人任务、数据、动作语义和推理预算，再看成功率与延迟。动作分布可以多峰，闭环系统却需要在实际执行时选择一条一致的行为；每次重规划切换模式，也可能产生不连续动作。生成模型的表达能力与控制系统的时间一致性要一起考虑。

## Causal Video Generation 为什么适合流式生成？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

Causal Video Generation 要求第 $i$ 个生成单元只依赖已生成历史和当前可用条件，不读取未来视频内容。生成单元可以是一帧、一组 latent token，也可以是一个 chunk：

```math
p(X_{1:K} \mid c) = \prod_{i=1}^{K} p(X_i \mid X_{<i}, c)
```

其中， $X_i$ 表示第 $i$ 个生成单元， $c$ 可以包含文本或预先给定的全局计划。这个分解允许系统完成一段就向外输出一段，也能把历史特征放入 cache 或压缩状态中复用，无须等待完整视频生成完毕。

**流式能力需要整条链路成立**

- **生成主干**：注意力掩码或递推结构不能访问未来视频 token。
- **视频编解码器**：若编码或解码当前片段时仍需要未来帧，就无法低延迟地输出。Causal VAE 可以消除这一层对未来帧的依赖。
- **推理系统**：采样步数、缓存更新和后处理延迟必须满足在线输出要求。模型具备 causal 结构，不代表端到端延迟一定足够低。

这里尤其要分清 **causal VAE** 和 **causal generation**。前者只约束编解码的时间感受野；生成主干若仍对整段 latent 做双向去噪，系统就不具备严格的增量生成能力。反过来，主干可以按 chunk 递推，但非 causal 解码器仍会增加输出等待时间。

代价也很明确。causal 依赖缺少未来视觉上下文，长程规划更依赖预先给定的脚本、关键帧或状态计划；递推时还可能出现误差反馈和后段重复。验证时可分别检查主干 attention mask、缓存前后一致性，以及只扰动未来输入时 causal VAE 的早期 latent 是否保持不变。

> **面试速答**：Causal Video Generation 让当前帧或 chunk 只依赖历史，因此可以增量生成并复用缓存。端到端流式输出还要求生成主干、视频编解码器和推理链路都不等待未来内容；只有 causal VAE，不能证明整个生成模型是 causal 的。

参考资料：[Phenaki](https://arxiv.org/abs/2210.02399)、[StreamingT2V](https://arxiv.org/abs/2403.14773)、[CogVideoX](https://arxiv.org/abs/2408.06072)

## DDIM 为什么可以做确定性采样？

DDPM 采样通常包含随机噪声项：

$$
x_{t-1}=\mu_{\theta}(x_t,t)+\sigma_t z,\quad z\sim\mathcal{N}(0,I)
$$

DDIM 构造了一个非马尔可夫反向过程，使得边缘分布 $q(x_t|x_0)$ 与 DDPM 保持一致，但采样路径可以由参数 $\eta$ 控制随机性。

常见形式：

$$
x_{t-1}
=
\sqrt{\bar{\alpha}_{t-1}}\hat{x}_0
+
\sqrt{1-\bar{\alpha}_{t-1}-\sigma_t^2}\epsilon_{\theta}(x_t,t)
+
\sigma_t z
$$

其中：

$$
\hat{x}_0=\frac{x_t-\sqrt{1-\bar{\alpha}_t}\epsilon_{\theta}(x_t,t)}{\sqrt{\bar{\alpha}_t}}
$$

当 $\eta=0$ 时：

$$
\sigma_t=0
$$

于是：

$$
x_{t-1}
=
\sqrt{\bar{\alpha}_{t-1}}\hat{x}_0
+
\sqrt{1-\bar{\alpha}_{t-1}}\epsilon_{\theta}(x_t,t)
$$

不再注入随机噪声，因此给定初始噪声 $x_T$ 和条件，采样轨迹是确定的。

**意义：**

- DDIM 可以少步采样。
- 确定性路径便于图像反演和编辑。
- 随机性由 $\eta$ 控制，$\eta=0$ 是确定性，$\eta>0$ 更接近随机采样。

## DDPM 的 $q(x_t|x_0)$ 一步采样公式如何推导？

DDPM 前向过程：

$$
q(x_t|x_{t-1})=\mathcal{N}(x_t;\sqrt{\alpha_t}x_{t-1},(1-\alpha_t)I)
$$

其中：

$$
\alpha_t=1-\beta_t
$$

可重参数化为：

$$
x_t=\sqrt{\alpha_t}x_{t-1}+\sqrt{1-\alpha_t}\epsilon_t
$$

对 $x_{t-1}$ 继续展开：

$$
x_{t-1}=\sqrt{\alpha_{t-1}}x_{t-2}+\sqrt{1-\alpha_{t-1}}\epsilon_{t-1}
$$

代入得到：

$$
x_t=\sqrt{\alpha_t\alpha_{t-1}}x_{t-2}+\text{Gaussian noise}
$$

由于独立高斯噪声的线性组合仍是高斯噪声，递推可得：

$$
x_t=\sqrt{\bar{\alpha}_t}x_0+\sqrt{1-\bar{\alpha}_t}\epsilon
$$

$$
\bar{\alpha}_t=\prod_{s=1}^{t}\alpha_s,\quad \epsilon\sim\mathcal{N}(0,I)
$$

因此：

$$
q(x_t|x_0)=\mathcal{N}(x_t;\sqrt{\bar{\alpha}_t}x_0,(1-\bar{\alpha}_t)I)
$$

**意义：**

训练时不需要一步步加噪到 $t$，可以随机采样 $t$ 后直接生成 $x_t$，极大提高训练效率。

## Diffusion、Flow Matching 与 Rectified Flow 是什么关系？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三者不能简单理解为互斥的模型类别。Diffusion 先规定数据逐渐变成噪声的随机过程，再学习其反向去噪量或 score；对应的 probability flow ODE 又能把同一组边缘分布写成确定性流。Flow Matching 则直接回归一条给定概率路径上的速度场，而这条路径既可以是扩散路径，也可以是其他路径。Rectified Flow 是强调直线插值与路径拉直的一类流模型构造，范围比 Flow Matching 更窄。

具体边界见表2-3。

<p align="center">表2-3 Diffusion、Flow Matching 与 Rectified Flow 的建模关系</p>

| 方法 | 训练时主要学习什么 | 路径如何得到 | 推理时如何生成 | 需要避免的误解 |
| --- | --- | --- | --- | --- |
| Diffusion / score-based model | 噪声、干净样本、velocity 或 score | 先定义前向加噪过程 | 求解反向 SDE、概率流 ODE 或其离散化更新 | 不等于只能随机采样，也不只支持 $\epsilon$ prediction |
| Flow Matching | 给定概率路径上的速度场 | 可使用扩散路径、OT 路径等 | 用 ODE 求解器积分速度场 | 不是 Diffusion 的简单反义词 |
| Rectified Flow | 尽量沿端点直线输运的速度场 | 给定噪声—数据耦合，使用直线插值；可进一步 reflow | 通常求解 ODE | 是流模型的一类构造，不等于所有 Flow Matching |

## Flow Matching 的速度场目标如何理解？

Flow Matching 希望学习一个速度场：

$$
v_{\theta}(x,t)
$$

使样本从简单分布 $p_0$ 流动到数据分布 $p_1$。

设 $x_0\sim p_0$ 是噪声，$x_1\sim p_1$ 是数据。若使用线性路径：

$$
x_t=(1-t)x_0+tx_1
$$

则路径对时间求导：

$$
\frac{dx_t}{dt}=x_1-x_0
$$

因此目标速度可以写为：

$$
u_t=x_1-x_0
$$

训练目标：

$$
L_{\text{FM}}=
\mathbb{E}_{t,x_t}
\left[
\|v_{\theta}(x_t,t)-u_t(x_t)\|_2^2
\right]
$$

采样时从噪声出发，求解 ODE：

$$
\frac{dx}{dt}=v_{\theta}(x,t)
$$

从 $t=0$ 积分到 $t=1$ 得到数据样本。

**与扩散模型对比：**

- 扩散模型常学习 score 或噪声。
- Flow Matching 学习速度场。
- Rectified Flow 希望路径更直，让少步采样更高效。

## I2VGen-XL 的 cascaded diffusion 为什么适合 I2V？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

I2V 同时要求语义和输入图像一致，还要保证视频清晰、细节连续。I2VGen-XL 没有把这些目标全部压给一个高分辨率去噪器，而是采用基础生成与细化两阶段级联，流程如图3-3所示。

  <img src="./imgs/ch03/fig-3-03-i2vgen-xl-cascaded-generation.png" alt="I2VGen-XL 先由 Base Stage 根据输入图像和层级特征生成基础视频，再由 Refinement Stage 结合简短文本提升细节与分辨率" width="780">
  <p>图3-3 I2VGen-XL 的两阶段级联生成流程</p>

**两个阶段承担不同目标**

- **基础阶段先确定内容与整体视频结构**：两个层级图像编码器提供互补的图像条件，使生成结果保持输入内容并维持语义连贯。这里不能简单概括成“专门负责运动”，运动只是基础视频结构的一部分。
- **细化阶段提升质量**：在基础视频上补充细节，并结合额外的简短文本提高分辨率和视觉质量。它主要做条件增强的视频细化，不负责重新决定主体身份或完整运动轨迹。

**级联错误要从前级开始排查**

级联的价值是把语义一致性与高分辨率细节的优化压力分开，但代价是误差会跨阶段传播。基础阶段若已经出现身份错误、运动断裂或构图漂移，细化阶段通常只会把错误变清晰。因此排障时应先检查基础视频，再判断细化模型是否引入纹理闪烁或条件偏移。

> **面试速答**：I2VGen-XL 用基础阶段保证语义连贯和输入内容保持，再由细化阶段补细节、升分辨率。它降低了单阶段同时处理语义与画质的难度，但基础阶段的结构性错误也会传给后级。

参考资料：[I2VGen-XL 原论文](https://arxiv.org/abs/2311.04145)

## ID 保持生成的核心目标是什么？

ID 保持生成的目标是：给定一个或多个参考人物图像，在新文本、新姿态、新场景或新风格条件下生成同一身份的人物图像/视频。

可写成：

$$
I_{\text{out}} = G(c_{\text{text}}, c_{\text{id}}, c_{\text{layout}}, c_{\text{style}})
$$

其中 $c_{\text{id}}$ 是身份条件，通常来自人脸识别模型、CLIP 图像编码器、ReferenceNet、多图聚合 embedding 或专门的 ID adapter。

**关键矛盾：**

- ID 条件太弱：不像本人。
- ID 条件太强：copy-paste、表情僵硬、文本不听话。
- 文本条件太强：身份漂移。
- 结构条件太强：姿态准确但细节丢失。

## JS 散度、互信息、最大熵原理在生成模型中有什么意义？

JS 散度是 KL 的对称平滑版本：

$$
D_{JS}(P\|Q)=\frac{1}{2}D_{KL}(P\|M)+\frac{1}{2}D_{KL}(Q\|M)
$$

其中：

$$
M=\frac{1}{2}(P+Q)
$$

GAN 原始目标与 JS 散度有关，但当真实分布和生成分布支撑集几乎不重叠时，训练可能不稳定。

互信息衡量两个随机变量共享的信息：

$$
I(X;Y)=D_{KL}(P(X,Y)\|P(X)P(Y))
$$

也可写为：

$$
I(X;Y)=H(X)-H(X|Y)
$$

**AI 中用途：**

- 对比学习希望正样本表示共享更多信息。
- 多模态学习希望图文表示对齐。
- 表征学习希望保留任务相关信息，压缩无关噪声。

最大熵原理：在已知约束下选择熵最大的分布，避免引入额外假设。Softmax、最大熵强化学习、温度采样都与这个思想相关。

## LTX-Video 如何通过高压缩表示和整体去噪实现低延迟生成？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

LTX-Video 的低延迟来自压缩器和去噪器的协同设计。Video-VAE 将 patchify 前移到编码器，使每个 latent token 覆盖 $8\times32\times32$ 的时空像素区域，论文报告的整体表示压缩比为 $1:192$。token 数减少后，Transformer 才能以可接受成本使用 full spatiotemporal self-attention。

**整体去噪补偿高压缩损失**

高压缩会先丢失细节。LTX-Video 没有把 VAE 与 DiT 当成完全独立模块，而是让解码器同时承担 latent-to-pixel 映射和最后一步去噪：前面多步在 latent 空间生成结构与运动，最后一步直接在像素空间恢复干净结果。整体过程如图3-9所示。

  <img src="./imgs/ch03/fig-3-09-ltx-holistic-denoising.png" alt="LTX-Video 在高压缩 latent 空间完成从 t=T 到 t=2 的多步去噪，并在 t=1 由 VAE Decoder 完成解码和像素域最后一步去噪" width="780">
  <p>图3-9 LTX-Video 的 holistic denoising strategy 示意图</p>

若原始视频尺寸为 $T\times H\times W$，仅考虑时空下采样时，Transformer 处理的 token 数近似为：

```math
N_{\text{latent}} \approx \frac{T}{8}\times\frac{H}{32}\times\frac{W}{32}
```

**Token 缩减与表示压缩比不是同一个量**

这里是 token 数的时空缩减，不应与包含通道维度的 $1:192$ 表示压缩比混为一谈。压缩后的 3D Transformer block 如图3-10所示。

  <img src="./imgs/ch03/fig-3-10-ltx-3d-transformer-block.png" alt="LTX-Video 3D Transformer Block 依次执行全时空自注意力、文本交叉注意力和 FFN，并由位置编码、文本编码与时间步 AdaLN 分别提供条件" width="680">
  <p>图3-10 LTX-Video 的 3D Transformer block 架构示意图</p>

**三层协同共同决定速度与质量**

这条路线的取舍很明确：压缩降低注意力和显存成本，全时空注意力换取跨帧、跨区域交互，像素域最后一步去噪补偿高压缩细节。排障时先对真实视频做 VAE 重建；重建已糊，问题在表示层；重建正常但生成漂移，再查 DiT 和训练数据；质量正常但延迟高，再拆分 VAE、每步 Transformer 和采样步数的耗时。

**“实时”必须绑定硬件与输出规格**

论文中的快于实时结论对应特定 H100、分辨率、帧率和模型设置，不能直接推广到任意消费级设备；后续蒸馏、量化和多尺度工作流还会形成新的速度—质量档位。

> **面试速答**：LTX-Video 用高压缩 VAE 大幅缩短视频 token 序列，再用全时空注意力建模全局运动，并让 VAE 解码器完成最后一步像素去噪以补偿细节。实时性来自整条链路协同，必须连同硬件、规格和采样设置一起评价。

## Motion Module 如何提升帧间一致性？

如果逐帧生成，每一帧的噪声采样和去噪路径不同，容易出现闪烁。Motion Module 在时间维度上建模多帧关系：

$$
Z \in \mathbb{R}^{B \times C \times T \times H \times W}
$$

它可以是：

- temporal attention
- 3D convolution
- temporal transformer
- motion LoRA / adapter

其作用：

1. 学习自然运动先验。
2. 让相邻帧共享时序上下文。
3. 减少局部纹理跳变。
4. 让姿态变化更平滑。

**面试要点：**

Motion Module 不是负责“人物长什么样”，而是负责“连续帧怎么动、怎么稳定”。外观保持主要靠 ReferenceNet/ID 条件，动作跟随主要靠 Pose Encoder，时序稳定靠 Motion Module。

## ONNX Runtime Profiling 如何开启？生成的 JSON Trace 如何解读？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

### 一、开启 ONNX Runtime Profiling

ONNX Runtime 提供了内置的 Profiling 功能，通过在 `SessionOptions` 中设置即可开启：

```python
import onnxruntime as ort

options = ort.SessionOptions()
options.enable_profiling = True           # 开启 profiling
options.profile_file_prefix = "ort_profile"  # 输出文件前缀

session = ort.InferenceSession("model.onnx", options)
session.run(None, {"input": input_data})
# profiling 结果自动写入 ort_profile_TIMESTAMP.json
```

或者在命令行中使用：
```bash
python -m onnxruntime.tools.benchmark --help
```

### 二、JSON Trace 文件结构

生成的 JSON 文件符合 Chrome Trace Event 格式，包含一个事件数组。每个事件的关键字段：

| 字段 | 含义 |
|------|------|
| `name` | 算子名称（如 `Conv_0`、`Gemm_1`） |
| `cat` | 类别（`Node`=计算节点, `Kernel`=GPU Kernel） |
| `dur` | 持续时间（微秒） |
| `args` | 附加信息（provider、op_type、input shapes、thread_id） |
| `tid` | 线程 ID |
| `pid` | 进程 ID |

### 三、解读 JSON Trace 的关键步骤

**步骤 1：按 `dur` 排序找最慢算子**
```python
import json
with open("ort_profile_xxx.json") as f:
    events = json.load(f)

# 过滤出计算节点
nodes = [e for e in events if e.get("cat") == "Node"]
nodes_sorted = sorted(nodes, key=lambda x: x["dur"], reverse=True)

for n in nodes_sorted[:5]:
    print(f"{n['name']}: {n['dur']/1000:.2f} us")
```

**步骤 2：按 `args['provider']` 分组比较**
- 看哪些算子跑在 CPU EP 上（可能是 GPU 不支持的算子）
- CPU EP 上的算子在 Timeline 上通常有明显更长的 `dur`

**步骤 3：在 Chrome Trace 中可视化**
- 在浏览器中打开 `chrome://tracing`，加载 JSON 文件
- 按线程（`tid`）分组查看，分析各算子的时序

### 四、Profiling 结果中的典型问题

| 观察 | 可能的含义 |
|------|-----------|
| 某算子的 `dur` 远大于其他算子 | 该算子是瓶颈，需重点优化或替换 EP |
| 大量算子 `provider` 为 `CPUExecutionProvider` | 可能 GPU EP 不支持某些算子，发生 CPU fallback |
| 算子间有大量间隔（通过 Timeline 观察） | CPU 端调度或数据搬运开销 |
| 同一算子在 CPU 和 GPU 间来回切换 | 频繁的 H2D/D2H 可能导致性能下降 |

可以总结为：**ONNX Runtime Profiler 通过内置的 trace 机制记录每个算子的执行时间和 EP 归属。解读 JSON Trace 的思路是"排序找热点 → 分组看 EP → Timeline 看时序"。其中 "CPU fallback"（算子从 GPU EP 回退到 CPU EP）是最常见也是影响最大的性能问题。**

## ReferenceNet、Pose Encoder、ControlNet、Motion Module 各自起什么作用？

**ReferenceNet**：通常是与 U-Net 相似的结构，用参考图提取多尺度特征，在去噪网络中通过 attention 或 feature injection 注入外观信息。

**Pose Encoder**：把姿态图、骨架图、DensePose、Depth、Normal 等结构条件编码成 latent feature，用来约束人物动作。

**ControlNet**：在冻结原扩散模型的基础上，增加可训练控制分支，使模型遵循边缘、深度、姿态等空间条件。优点是兼容性好，缺点是视频时序控制需要额外设计。

**Motion Module**：建模时间维度上的相邻帧关系，常见形式包括 temporal convolution、temporal attention、3D U-Net block。

**条件注入方式：**

- concat 到 latent channel
- cross attention
- self attention feature injection
- residual adapter
- control branch
- token 拼接或 DiT 条件调制

## Score Matching、SDE、ODE 与扩散模型有什么关系？

Score 是数据对数密度对样本的梯度：

$$
\nabla_x \log p_t(x)
$$

它指向概率密度上升最快方向。Score-based model 学习不同噪声尺度下的 score，用它从噪声逐步回到数据分布。

连续时间扩散可写为 SDE：

$$
dx=f(x,t)dt+g(t)dw
$$

反向时间 SDE：

$$
dx=[f(x,t)-g(t)^2\nabla_x\log p_t(x)]dt+g(t)d\bar{w}
$$

对应还存在 Probability Flow ODE：

$$
dx=\left[f(x,t)-\frac{1}{2}g(t)^2\nabla_x\log p_t(x)\right]dt
$$

**区别：**

- SDE 采样带随机性。
- ODE 采样确定性，更适合反演、编辑、似然计算。
- DDPM 可看作离散时间扩散，SDE 是连续时间统一框架。

## SGLang 后端生成阶段执行流程

![](https://raw.githubusercontent.com/WeThinkIn/AIGC-Interview-Book/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80/imgs/SGLang_generate_frame.png)
ModelRpcServer 得到 TokenizedGenerateReqInput 之后将通过 handle_generate_request 函数将其变成 Req 的数据结构，然后顺序放入 forward_queue 中用于之后的 forward。Req 的数据结构特别在于：如果 request 中包含正则表达式 regex，那么就会给其绑定一个 FSM，这块主要是和前端有关暂不展开。
接下来就会执行 forward_step进行正式的推理。

forward_step 函数中有如下逻辑：
1. 调用 get_new_fill_batch 来将当前新的 request 动态组成 new batch。首先计算所有 request 在 RadixCache 中的共享 prefix（由此也就拿到对应的 kv cache），然后 Scheduler 重新安排所有 request 的优先级（默认是 LPM，即最长的共享 prefix 最先处理），接下来按照优先级依次放入 can_run_list 中并估计占用的显存空间，当可能会占满空间的时候就停止放入，最后将其组成一个 Batch 称为 new_batch。
2. 如果 new batch 不为空，那么进入 Fill 阶段（forward_fill_batch），即分配新的显存给所有的 Request 的 token（init_extend_batch，注意此时已经分配好了 Extend 部分的 KV Cache 空间）、forward 计算所有的 logits（ModelRunner::forward）、采样得到 next_token（sample）、检查是否推理结束（check_finished），若结束进入 handle_finished_requests 函数。最后如果这些 new batch 没有推理完就放到 running_batch中，以后再调用的时候就会走 Decode 阶段。
3. 如果 new batch 为空，那么就查看当前的 running_batch ，如果有 running_batch 就进入 Decode 阶段（forward_decode_batch），即给每条 request 即将生成的 1 个 token 分配连续空间（update_for_decode）、forward 计算所有的 logits（ModelRunner::forward）、采样得到 next_token（sample）、检查是否推理结束（check_finished），若结束进入 handle_finished_requests 函数。此处为了减少 Overhead，直接重复 Decode 阶段 10 次。
4. Logging 相关：每经过 Decode 阶段 20 次就会打印一下当前的状态。

handle_finished_requests会将推理结束的 Req 包装成 BatchTokenIDOut，之后会发送给 DetokenizerManager，然后会：
1. 更新 RadixCache（将推理结束的 request insert 到 RadixCache 中形成 common prefix，其中 key 是 token ids，value 是在 TokenToKVPool 的 indices）
2. 将这条 request 的前缀在 TokenToKVPool 的引用计数减一（为什么是前缀部分？因为在 get_new_fill_batch 的时候就给 prefix 增加了引用计数）
3. 将这条 Request 在 ReqToTokenPool 中去掉（ReqToTokenPool 只保存当前正在处理的 Request）
4. RadixCache 将一路引用计数都减一，当引用计数为0的时候就可以被 evict（为什么要减引用计算，因为在 get_new_fill_batch 的时候有增加过引用计数来确保不被 evict）
5. 将当前 batch 中去除推理结束的 Request

Generate 逻辑中最主要的是 ModelRunner::forward，首先它会将输入的各种信息包装成 InputMetadata（调用 InputMetadata.create），具体包括如下输入信息：
1. forward_mode：分成 EXTEND（Fill 阶段调用）、DECODE（Decode 阶段调用）、PREFILL（暂时没有地方调用）
2.  tp_size：TensorParllel 的 size，分布式推理使用
3. req_pool_indices：当前所有 request 占ReqToTokenPool的 index 列表
4.  seq_lens：当前所有 request 的长度列表
5. prefix_lens：当前所有 request 的共享 prefix 的长度列表
6. position_ids_offsets：一直都是 0，暂时可以忽略
7. out_cache_loc：KVCache Tensor 中分配的显存 slot 的索引列表
8. out_cache_loc_start：KVCache Tensor 中分配的显存 slot 的起始 index
9. out_cache_loc_end：KVCache Tensor 中分配的显存 slot 的结束 index
10. return_normalized_logprob：布尔值，返回是否要将输出 logits 做 normalize
然后会计算一些其他变量，例如 positions记录 token 的 position id：对于 EXTEND，因为需要推理从 prefix_len 到 seq_len 的所有 token 的 kv，所以positions 为 prefix_len 到 seq_len 的 id，input_ids 也只包含需要 extend 的部分；对于 DECODE，只需要推理一个 token，所以 positions 只包含新的一个 seq_len 的 id。 
最后用 InputMetadata 和 input_ids 等调用具体模型的 forward

## Stable-Diffusion模型中，有哪几种不同的sampling方法可以用来生成数据？

以下是一些常见的sampling方法：

（1）Gaussian sampling：是Stable Diffusion中最常用的一种sampling方法。它通过将高斯噪声添加到数据中来生成新的样本。这种方法可以帮助模型更好地理解数据的分布和特征。

（2）Langevin sampling：一种基于随机梯度下降的sampling方法。它通过将随机噪声添加到梯度中来生成新的样本。这种方法可以帮助模型更好地处理高度非线性的数据。

（3）Metropolis-Hastings sampling：一种Markov Chain Monte Carlo（MCMC）方法，它可以生成一个序列来表示数据的分布。这种方法可以帮助模型更好地理解数据的复杂性和不确定性。

（4）Hamiltonian Monte Carlo sampling：一种MCMC方法，它可以利用动态系统的特性来生成数据样本。这种方法可以帮助模型更好地理解数据中的隐含结构和特征。

（5）Diffusion Process Model：DPM是基于扩散过程的理论原理，通过对数据样本中的噪声进行建模，可以帮助消除数据中的噪声和偏差，提高模型的准确性和泛化能力。

这些方法在Stable Diffusion的参数中都可以调整，其中Sampling step更会影响图片生成的运算时间及效果，原则上会根据采样方法不同而有所差异。

## Step-Video-T2V 如何协调 30B DiT、深压缩 Video-VAE 与 Flow Matching？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

三者构成一组计算闭环：Video-VAE 先把视频压到可承受的 token 数，30B DiT 用 3D full attention 建模这些 token，Flow Matching 定义从噪声到数据的学习路径。缺少深压缩，30B 全注意力的训练和推理成本很难落地。

**深压缩让大规模全注意力可落地**

Step-Video-T2V 的 Video-VAE 采用空间 $16\times16$ 、时间 $8\times$ 压缩。忽略边界取整后，latent token 数近似为：

```math
N_{\text{latent}} \approx \frac{T}{8} \times \frac{H}{16} \times \frac{W}{16}
```

压缩将 token 数降到像素时空体积的约 $1/2048$ ，代价是细节和快速运动先经过有损瓶颈。VAE 重建若已丢失文字、手部或短时动作，DiT 很难恢复真实信息。

**Flow Matching 定义学习路径**

生成主干学习条件速度场：

```math
\frac{d x_t}{d t} = v_\theta(x_t, t, c)
```

其中 $v_\theta$ 是预测速度，$c$ 是双语文本条件。Flow Matching 规定训练目标，不自动保证少步采样；实际延迟仍由求解器步数、模型规模、token 数和并行效率共同决定。Video-DPO 位于后训练阶段，用偏好信号减少伪影、改善观感，也不能替代基础预训练。

**故障定位沿生成链路展开**

排障时可直接按链路切开：VAE 重建差先修压缩器；重建正常但文本动作缺失，看文本编码、caption 与条件注入；短视频正常、长视频漂移，再查训练长度分布和 3D attention 是否学到长程状态。

> **面试速答**：深压缩 VAE 让 30B 全时空 DiT 的 token 成本可控，Flow Matching 负责学习生成路径，Video-DPO 再做偏好后训练。四者分别作用于表示、容量、目标和对齐，不能用扩大参数量替代其中任何一层。

参考资料：[Step-Video-T2V 技术报告](https://arxiv.org/abs/2502.10248)、[官方仓库](https://github.com/stepfun-ai/Step-Video-T2V)

## Temperature、Top-p、Typical Sampling、Contrastive Decoding 如何改变生成分布？

Temperature：

$$
p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

$T<1$ 让分布更尖锐，$T>1$ 让分布更平坦。

Top-p 选择累计概率达到阈值 $p$ 的最小集合 $V_p$：

$$
V_p=\min\left\{V':\sum_{i\in V'}p_i\ge p\right\}
$$

然后在 $V_p$ 内重新归一化。

Typical Sampling 不是单纯取高概率 token，而是选择信息量接近分布熵的 token。token 信息量：

$$
I_i=-\log p_i
$$

熵：

$$
H(p)=\sum_i p_i(-\log p_i)
$$

Typical Sampling 偏向保留 $|I_i-H(p)|$ 较小的 token，避免过于普通或过于离群的选择。

Contrastive Decoding 常用强模型与弱模型的 log probability 差：

$$
s(y_t)=\log p_{\text{strong}}(y_t|x,y_{<t})-\alpha \log p_{\text{weak}}(y_t|x,y_{<t})
$$

直觉是保留强模型偏好、惩罚弱模型也容易生成的通用/退化文本。

## 三道闸数据过滤流水线如何抑制重复生成？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

InternVL2.5 设计了一条三道闸的数据过滤流水线，专门清除异常样本，尤其是重复样本：

1. **LLM 质量打分（LLM-Based Quality Scoring）。** 用于纯文本数据。用预训练 LLM 配合领域专用的提示词给每条样本打 0~10 分，低于阈值（如 7 分）的直接剔除，守住整体质量[11]。

2. **重复检测（Repetition Detection）。** 用 LLM 配合专门的提示词标记带重复模式的样本，经人工复核后，低于阈值（如 3 分）的剔除。多模态数据也走这一步，高质量的学术数据集豁免，避免误删[11]。

3. **启发式规则过滤（Heuristic Rule-Based Filtering）。** 用规则检测句长异常、重复行等显式异常，人工确认后移除，多模态数据也用类似的规则[11]。

论文报告，这套流水线明显减少了重复生成等异常行为，CoT 推理任务提升明显[11]。少量异常数据就能明显影响推理行为，所以清洗必须在训练前完成。这和 [5.4.9.2](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/4_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E4%B8%BB%E6%B5%81%E6%A8%A1%E5%9E%8B%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-4-9-2) 的数据配比、[5.4.12.2](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/4_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E4%B8%BB%E6%B5%81%E6%A8%A1%E5%9E%8B%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-4-12-2) 的校验器稳健性是同一个道理，数据和奖励信号的质量直接决定模型行为。

> **面试速答**：第一道是 LLM 质量打分，给纯文本样本打 0~10 分，低于 7 分左右的剔除；第二道是重复检测，用 LLM 标记重复样本，人工复核后剔除，学术数据集豁免；第三道是启发式规则，过滤句长异常、重复行等。论文报告重复生成明显减少，CoT 任务提升明显。

## 不同的输出结果分别在哪个环节生成？

**回答：**

解析阶段生成结构化文档、页码和段落位置；切分与索引阶段生成 chunk、元数据及检索索引；对齐阶段生成两份文档的对应关系和未匹配项；分析阶段生成候选差异、解释或问答内容；校验阶段检查字段、引用和覆盖情况；报告阶段把已校验的结果组织成用户可读内容。

这个划分能解释“为什么最终报告错了”：可能是解析丢失表格、版本选择错误、对齐失败、检索遗漏，也可能是模型推理或报告汇总出错。应保留各阶段的产物引用和版本信息，以便定位错误发生的位置，而不是只保存最终文本。

报告生成不应重新自由发挥、创造新的事实。可以基于结构化结果和证据生成表述，再验证报告中的条款编号、数字和结论能否回到对应差异项。中间结果若对用户可见，应标注尚未完成校验，不能和正式结果混淆。

## 为什么人体驱动中的脸部 ID 最容易崩？

原因包括：

- 脸部在全身图中占比小，训练损失容易被身体和背景主导。
- 人脸对微小差异敏感，眼睛、鼻子、嘴角轻微变化都会被察觉。
- 姿态和表情变化会改变局部几何，模型容易把身份和表情混淆。
- ReferenceNet 保存外观，但不一定有强身份判别能力。
- 视频生成中累积误差会让脸逐渐漂移。

常见解决方式：

- 使用 ArcFace/InsightFace ID loss。
- 加 Face Adapter 或局部人脸 ReferenceNet。
- 对脸部区域加权训练。
- 生成后做人脸局部修复。
- 多参考图提取稳定 ID embedding。
- 使用 face parsing mask 限制身份条件作用区域。

## 主流生成器各自的设计动机、优势与适用场景是什么？

### <a id="q5-2-11-1"></a>5.2.11.1 面试问题：扩散模型生成器（DDPM/LDM/SD3/FLUX）的核心机制与适用场景

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

扩散模型是目前图像和视频生成的主流方法。训练时逐步给数据加噪直到变成纯噪声，同时训练一个网络学会逐步去噪；推理时从纯噪声出发，反复去噪得到新样本。

**技术演进**

1. **DDPM（2020）**：打下基础，训练和采样都用 T=1000 步，采用固定的 $`\beta`$ 噪声调度[82]。质量好，推理慢。

2. **DDIM（2021）**：把采样改成非马尔可夫过程，50 步左右就能接近 1000 步的质量[75]。

3. **LDM / Stable Diffusion（2022）**：把扩散从像素空间搬到 VAE 的 latent 空间（64×64×4），计算量大幅下降，消费级 GPU 也能跑文生图，扩散模型由此走向大规模应用[47]。

4. **DiT（2023）**：用 Transformer 替换 U-Net，扩散模型开始表现出类似 LLM 的规模扩展规律[83]。SD3、Wan 都用 DiT 类架构[59,61]。

5. **SD3 / FLUX.1（2024）**：改用 Rectified Flow 训练目标（见 [5.2.11.3](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/2_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A0%B8%E5%BF%83%E7%BB%84%E4%BB%B6%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-2-11-3)），采样步数进一步减少[59,60]。

6. **SD3.5 / FLUX.2 / Qwen-Image（2025）**：参数规模到了 8B 到 32B（SD3.5 Large 约 8B[84]，Qwen-Image 20B[62]，FLUX.2 [dev] 32B[49]），文字渲染、长 prompt 理解和多参考图一致性明显变好。

7. **Z-Image（2025）**：阿里通义的 6B 模型，用单流 DiT（S3-DiT）把文本 token 和图像 latent 拼成一条序列统一处理，技术报告称效果可以比肩参数量大得多的开源模型，蒸馏版 Z-Image-Turbo 只需 8 次函数评估[63]。

**优势**

1. **训练稳定**：相比 GAN 很少训崩，是目前最容易训练的高质量生成方法。

2. **质量上限高**：目前主流的开源图像基座（FLUX、Qwen-Image、Z-Image）都走扩散或流匹配路线[60,62,63]。

3. **控制手段多**：CFG、ControlNet、IP-Adapter、LoRA 微调等工具最完善，见 [5.2.12.1](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/2_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A0%B8%E5%BF%83%E7%BB%84%E4%BB%B6%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-2-12-1)。

4. **生态成熟**：Hugging Face Diffusers、ComfyUI 等工具链覆盖完整工作流，社区分享的 LoRA 和 ControlNet 模型数量庞大。

**局限**

1. **推理慢**：常规采样要几十步，实时场景用不了，需要 LCM、Turbo 等蒸馏方法加速[57,85]，见 [5.2.12.3](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/2_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A0%B8%E5%BF%83%E7%BB%84%E4%BB%B6%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-2-12-3)。

2. **难与文本 token 统一**：扩散输出的是连续 latent，没法像自回归那样和文本 token 共用一个 LLM，做统一多模态模型要多一层设计。BLIP3-o 等自回归加扩散的混合方案就是为了解决这个问题[73]。

扩散模型适合高质量图像生成、视频生成、电商海报和漫画分镜等设计工作流，以及建筑设计、姿态生成等需要强结构控制的场景。代表作 FLUX.2。

> **面试速答**：扩散模型训练时逐步加噪、学习逐步去噪，推理时从纯噪声反复去噪生成样本。演进上 DDIM 减少步数，LDM 搬到潜空间降成本，DiT 换成 Transformer 便于扩展，SD3、FLUX 改用流匹配目标。它训练稳、质量高、控制工具多，短板是推理慢、难和文本 token 统一。

### <a id="q5-2-11-3"></a>5.2.11.3 面试问题：流匹配生成器（Flow Matching/Rectified Flow）的核心机制与优势

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

流匹配（Flow Matching）在 2022 年提出、2023 年发表于 ICLR[89]，2024 年起在大规模生成模型里普及。它可以看成扩散模型的另一种表述，目标相近，训练目标更直接，推理路径更短。

流匹配不再定义加噪和反向去噪过程，直接学习一个随时间变化的速度场 $`v_\theta(x_t, t)`$，描述从噪声分布 $`x_0 \sim \mathcal{N}(0, I)`$ 到数据分布 $`x_1 \sim p_{\text{data}}`$ 的连续变换。训练目标为

$$\mathcal{L}_{\text{FM}} = \mathbb{E}_{t, x_0, x_1}\left[\|v_\theta(x_t, t) - (x_1 - x_0)\|^2\right]$$

其中 $`x_t = (1-t) x_0 + t x_1`$ 是两点之间的直线插值。推理时用欧拉法或 RK4 求解 ODE $`\frac{dx}{dt} = v_\theta(x_t, t)`$，从 $`x_0`$ 积分到 $`x_1`$[89]。

Rectified Flow 是工业界最常用的形式。它让噪声和数据之间走直线，reflow 操作可以把路径进一步拉直，减少采样步数[90]。

**相比传统扩散的优势**

1. **采样步数更少**：DDPM 要 1000 步，DDIM 约 50 步，DPM-Solver 约 20 步[75,76,82]；流匹配模型直接采样一般二三十步，SD3 官方示例默认 28 步[79]。压到 1 到 4 步仍然要靠蒸馏或 reflow，FLUX.1 [schnell] 是蒸馏得到的 4 步以内版本[80]。

2. **训练目标简单**：只有一个 MSE 损失，不依赖复杂的噪声调度系数，代码更短。

3. **概念更清楚**：直接学速度场，不需要“加噪再去噪”两段叙述。

4. **工具能复用**：在特定参数化下和扩散模型等价，CFG、ControlNet 等扩散生态的工具基本能直接迁移。

**代表工作**

1. **Flow Matching（Lipman 等，ICLR 2023）**：理论奠基[89]。

2. **Rectified Flow（Liu 等，ICLR 2023）**：提出 reflow 把路径拉直[90]。

3. **SD3（Stability AI，2024）**：把 Rectified Flow 扩展到 8B 规模的文生图模型，并让训练时的时间步采样偏重轨迹中段[59]。

4. **FLUX.1（Black Forest Labs，2024）/ FLUX.2（2025）**：同样基于流匹配，FLUX.2 [dev] 为 32B[49,60]。

5. **MeanFlow（2025）**：何恺明团队提出，学习一段时间区间上的平均速度（流匹配学的是瞬时速度），不用蒸馏就能一步生成，ImageNet 256×256 一步生成的 FID 为 3.43[91]。

6. **CAFM（字节跳动 Seed，2026）**：用学习到的判别器替换流匹配固定的 MSE 损失，主要用于对已有流匹配模型做后训练。在 ImageNet 256×256 上，SiT 的无引导 FID 从 8.26 降到 3.63，加引导后从 2.06 降到 1.53，论文明确说明它不是为少步生成设计的[92]。

新发布的开源文生图、文生视频基座大多采用流匹配目标，SD3、FLUX、Wan、Z-Image 都是[59-61,63]；对延迟敏感、需要少步采样的场景，流匹配模型也更容易蒸馏到几步。

> **面试速答**：流匹配直接学习从噪声到数据的速度场，Rectified Flow 让两者之间走直线，训练只要一个 MSE 损失。相比扩散，它采样步数更少，SD3 默认 28 步，蒸馏后可到 1 到 4 步，扩散生态的工具也能复用。SD3、FLUX、Wan、Z-Image 都用流匹配目标。

## 主流生成器的分类维度与代表方案有哪些？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

生成器可以从两个角度分类，一是按建模方式（怎么生成），二是按目标模态（生成什么）。按建模方式分四类：

1. **扩散模型（Diffusion）**：从噪声出发，经过多步迭代去噪得到数据。代表作 Stable Diffusion[47]。

2. **自回归生成（Autoregressive）**：把目标模态离散成 token 序列，和文本 token 一起用 Transformer 做 next-token 预测。代表作 Emu3[58]。

3. **流匹配（Flow Matching / Rectified Flow）**：学习一个把噪声连续变换成数据的速度场，推理时沿这个场求解常微分方程（ODE）。它和扩散模型关系很近，SD3、FLUX、Wan 这些扩散架构的模型用的都是流匹配训练目标[59-61]。代表作 FLUX.2[49]。

4. **声码器与神经音频编解码器（Vocoder / Codec）**：把梅尔谱或离散声学 token 还原成波形，是语音生成链路的最后一步。代表作 HiFi-GAN[48]。

按目标模态分五类，如表 2-2 所示。

<p align="center">表 2-2 生成器按目标模态分类</p>

| 目标模态 | 主流范式 | 代表方案 |
|---|---|---|
| 图像 | 扩散/流匹配为主，自回归追赶 | FLUX.2、Qwen-Image、Z-Image、Emu3 |
| 视频 | 扩散/流匹配（DiT 架构） | Wan 2.1、HunyuanVideo、Veo 3.1、Seedance 2.5 |
| 语音（TTS） | 自回归语言模型 + codec/声码器，或非自回归扩散 | CosyVoice 3、OmniVoice |
| 3D 资产 | 多视图生成 + 重建、结构化 latent 生成 | TripoSR、InstantMesh、TRELLIS.2 |
| 统一多模态 | 统一 token 空间自回归，或自回归 + 扩散混合 | Chameleon、Emu3、Janus-Pro、Show-o、BLIP3-o |

表 2-2 中开源模型的范式取自各自的论文或技术报告[58,61-73]；FLUX.2、Veo 3.1、Seedance 2.5 的信息来自官方发布[49,50,74]，其中闭源模型没有公开结构细节，范式一列以开源模型为依据。

图像和视频生成以扩散和流匹配为主，自回归在统一多模态模型里用得最多，TTS 的主流是自回归语言模型加 codec 或声码器，声码器专门负责语音链路的最后一步。

> **面试速答**：按建模方式分扩散、自回归、流匹配、声码器四类，代表作分别是 Stable Diffusion、Emu3、FLUX.2 和 HiFi-GAN。按目标模态分图像、视频、语音、3D 和统一多模态。图像视频以扩散和流匹配为主，统一多模态多用自回归，语音末端靠声码器。

## 人体驱动常见输入条件有哪些？

人体驱动常见条件包括：

- **2D Pose / OpenPose / DWPose**：人体骨架、手部、脸部关键点。
- **DensePose**：人体表面 UV 对应关系，能提供比骨架更密集的身体区域信息。
- **Depth**：深度图，提供前后空间关系。
- **Normal**：法线图，提供局部表面朝向。
- **Segmentation / Parsing**：人体、衣服、头发、手臂等语义区域。
- **SMPL/SMPL-X**：参数化人体模型，提供 3D 姿态、体型、手势、表情。
- **Driving Video**：直接从目标视频提取动作、头动、表情和镜头运动。

**选择原则：**

- 只需要粗动作：2D Pose 足够。
- 需要身体表面贴合：DensePose 更强。
- 需要 3D 视角/体型一致：SMPL/SMPL-X 更合适。
- 需要服装/遮挡处理：Parsing、Depth、Normal 往往要一起用。

## 人体驱动生成中如何提升脸部 ID 相似度？

脸部 ID 相似度难提升，原因是脸部区域小、人类敏感度高、动作/表情变化大，而且扩散模型容易优先满足姿态和整体画面。

常见方案：

1. **人脸 ID Loss**：使用 ArcFace/InsightFace 等人脸识别模型提取生成脸和参考脸 embedding，约束余弦相似度。

$$
L_{\text{id}}=1-\cos(f_{\text{face}}(I_{\text{gen}}),f_{\text{face}}(I_{\text{ref}}))
$$

2. **Face Adapter**：单独提取人脸区域特征，并在 U-Net/DiT 中注入。

3. **面部 mask 加权**：对脸部区域增加重建损失、感知损失或 attention 权重。

4. **局部高分辨率修复**：生成后对人脸区域做 face restoration 或局部重绘。

5. **多参考图训练/推理**：用多角度、多表情图像提取更稳健 ID 表示，减少 copy-paste。

## 分段生成、重叠融合和时间感知位置偏移有什么区别？

**分段生成**：

把长视频切成多个 clip，每个 clip 独立生成。简单但边界容易跳变。

**重叠融合**：

相邻片段保留 overlap 帧，在 latent 或 pixel 空间加权融合：

$$
\hat{z}^{(i)} = w_i z_A^{(i)} + (1-w_i) z_B^{(i)}
$$

可以缓解片段边界闪烁，但如果两个片段内容差异大，融合会模糊。

**时间感知位置偏移**：

在每个时间步处理音频片段时，引入累计时间偏移，让模型知道当前 clip 在全局视频中的位置，并平滑连接前后片段。Sonic 和 HunyuanVideo-Avatar 旧笔记都提到类似思路。

**对比：**

- 重叠融合是后处理/推理融合。
- 时间偏移是让模型在条件层面感知全局时间。
- 两者可以同时使用。

## 剪映「智能成片」类功能如何编排理解与生成模型？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

智能成片属于模型即组件，由理解、决策和生成三段中的多个模型与算法编排而成。公开资料没有给出剪映的完整模型清单，下面按三段拆解这类功能的共同结构：

1. **理解。** 镜头边界检测先把素材切分为镜头（shot），视频理解模型为每个片段生成带时间戳的描述，包括人物、动作、场景和情绪，时间对齐见 [5.4.8.1](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/4_AI多模态主流模型核心技术高频考点.md#q5-4-8-1)。高光打分综合画质、人脸表情、动作幅度和音频能量，得出片段的可用度排序。

2. **决策。** 模板确定叙事结构和目标时长，再从高光片段池中选段、排序。配乐确定之后做节拍对齐，把剪辑点吸附到音乐节拍上；这一步由算法完成，对成片节奏的影响很大。

3. **生成。** 语音识别生成字幕，语言模型润色标题和文案，按情绪推荐配乐，需要旁白时再接语音合成。补充转场和空镜时可以接入视频生成模型，例如字节 2026 年 7 月发布的 Seedance 2.5，它延续 Seedance 2.0 的音视频联合生成架构，单次可生成 30 秒视频[20]；公开资料没有披露剪映内部使用的具体模型。

> **面试速答**：智能成片由多个组件编排而成，剪映的内部模型清单没有公开。理解段切分镜头、生成带时间戳的描述并给片段打高光分；决策段按模板选段，并把剪辑点对齐音乐节拍；生成段补字幕、文案、配乐和旁白，转场和空镜可以接视频生成模型。

## 可控人体生成的核心目标是什么？

可控人体生成的目标是：给定一个人物外观参考和一个控制条件，让模型生成该人物在目标动作、姿态、镜头或场景下的图像/视频，同时保持身份、服装、发型、配饰、背景和时序稳定。

典型输入输出可以写成：

$$
V_{\text{out}} = G(I_{\text{ref}}, C_{\text{motion}}, C_{\text{text}}, C_{\text{scene}})
$$

其中：

- $I_{\text{ref}}$：参考人物图像或参考视频。
- $C_{\text{motion}}$：姿态、骨架、DensePose、SMPL、驱动视频。
- $C_{\text{text}}$：文本描述，如动作、场景、风格。
- $C_{\text{scene}}$：背景、镜头、光照、环境约束。

**面试回答重点：**

可控人体生成不是单纯“生成人”，而是要在“强控制”和“高真实感”之间平衡。控制太弱，动作不跟随；控制太强，画面僵硬、身份丢失或服装纹理变形。

## 多镜头生成中的镜头切换为什么难？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

镜头切换需要同时表达“有意变化”和“状态承接”。它与 Chunk 边界不同：Chunk 往往是计算切分，目标是让边界不可察觉；shot cut 是叙事结构，画面可以明显跳变，但跳变前后的空间、动作和事件关系仍应可解释。

**切换时要传递的不是上一帧像素**

- **实体与状态**：出场角色、服饰、道具及其最新状态必须进入下一镜头条件。
- **动作承接**：切出前和切入后的动作阶段要匹配。镜头可以换，但抬手、转身或开门等动作不能无故回退。
- **空间关系**：同一场景内要维护人物朝向、视线和相对位置。轴线规则、视线匹配等可作为常见镜头语言先验，但不是不可违反的硬规则。
- **叙事关系**：地点或时间发生跳转时，应由分镜计划明确标记，避免把计划中的转场误判为场景漂移，也避免把模型错误解释成创作性跳切。

工程上可在 shot plan 中显式保存转场类型、切点、相机相对轴线的位置、出入场实体，以及切换前后的事件状态；再用首尾关键帧、动作锚点或跨镜头参考约束局部生成。约束过强会把镜头切换做成近似续写，削弱构图变化，因此身份和事件状态可以强约束，景别与局部纹理通常需要留出变化空间。

排查时先看 shot plan 是否给出了正确的前后状态，再看关键帧是否遵循计划，最后检查视频生成器是否执行了关键帧和动作条件。这样可以区分上层转场设计错误、视觉锚点错误和局部生成偏离。

> **面试速答**：镜头切换允许画面、视角甚至时间明显变化，因此不能按 Chunk 的无缝拼接来处理。系统需要传递实体、动作阶段、空间关系和事件状态，并在计划中标明哪些跳变是有意转场；约束过强又会把切镜做成续写，所以要强保身份与事件，给景别和构图留出变化空间。

参考资料：[VideoDirectorGPT](https://arxiv.org/abs/2309.15091)、[MovieDreamer](https://arxiv.org/abs/2407.16655)、[MovieBench](https://arxiv.org/abs/2411.15262)

## 如何生成负例以提升模型性能？如何构建高质量的难负例？

生成负例提升性能的方法：

- 随机负采样：随机选取非匹配样本，简单但效果有限。
- 硬负采样（Hard Negative Mining）：选择与正样本相似度较高但不匹配的样本，能显著提升模型判别能力。
- 动态负采样：训练过程中不断更新负例集合，使负例更贴近当前模型难区分样本。

构建高质量难负例的方法：

- 利用现有模型检索出与正样本最相似的错误匹配项。
- 通过领域知识筛选容易混淆的样本。
- 利用对抗生成方法制造与正样本高度相似但标签不同的样本。

## 如何设计一个可控 3D 数字人生成系统？

可以按“输入、建模、驱动、渲染、增强、评估、部署”回答。

**1. 输入层**

- 身份参考：单图、多图或短视频。
- 驱动信号：文本、音频、动作视频、骨骼序列、表情参数。
- 场景条件：相机、背景、光照、服装、风格。

**2. 建模层**

- 人脸：检测关键点，拟合 FLAME/3DMM，提取身份纹理和表情空间。
- 人体：估计 SMPL/SMPL-X 参数，得到骨架、体型和姿态。
- 外观：构建 Mesh 贴图、神经纹理、NeRF 或 3DGS 表示。

**3. 驱动层**

- 音频到口型和表情。
- 文本到动作或手势。
- 视频到姿态迁移。
- 手动控制表情、视线、头部和身体动作。

**4. 渲染层**

- 实时需求：Mesh + PBR + BlendShape/LBS。
- 高保真需求：NeRF/3DGS/neural rendering。
- 生成增强：渲染 depth/normal/segmentation，再用扩散模型提升真实感。

**5. 时序层**

- 使用运动平滑、光流一致性、表情曲线平滑、身份一致性损失。
- 对长视频做分段生成和跨段状态继承。

**6. 部署层**

- 模型压缩、缓存、流式推理、GPU/CPU 分工。
- Web/移动端使用轻量 Mesh，云端使用高保真生成。
- 增加安全审核、水印和授权校验。

## 如何评估 GAN/Diffusion 数字人的质量？

| 维度 | 关注点 | 常见指标 |
| --- | --- | --- |
| 图像真实感 | 是否清晰自然 | FID、LPIPS、CLIP-IQA、人工评测 |

| 表情自然度 | 情绪、眨眼、头动是否合理 | landmark dynamics、人工评分 |
| 姿态准确性 | 是否跟随驱动姿态 | keypoint error、PCK、MPJPE |
| 时序稳定性 | 是否闪烁、漂移 | optical flow consistency、temporal LPIPS |
| 背景融合 | 边界、遮挡是否自然 | mask boundary error、人工评测 |
| 推理性能 | 是否满足产品需求 | FPS、latency、显存、吞吐 |
| 安全合规 | 是否滥用身份或生成违规内容 | 水印、检测器、审核通过率 |

评估建议：

- 不要只看 FID。数字人更关心身份、口型、时序和用户主观感受。
- 对实时系统必须统计 P50/P90/P99 延迟。
- 对长视频必须评估跨段身份一致性和累积漂移。
- 对换脸必须评估遮挡、侧脸、强光、低清、人脸小目标等困难集。

## 如何避免条件冗余和 Copy-Paste？

条件冗余指多个条件携带重复甚至冲突的信息。例如参考图、DensePose、mask、CLIP image embedding 都可能包含人物外观，导致模型不知道该信谁。

缓解策略：

- 条件解耦：身份、姿态、表情、服装分别编码。
- 条件 dropout：训练中随机丢弃部分条件，避免模型依赖单一路径。
- 延迟注入：前期弱化 ID，后期增强细节。
- 区域限制：ID 条件只影响脸部，服装条件只影响衣服区域。
- 多参考/跨姿态训练：减少单图 copy-paste。
- Copy-Paste 指标：比较生成图更接近参考图还是目标真实图，惩罚无脑复制。

## 如果 Prompt 中给了明确的输出格式，但模型仍然经常生成非法 JSON，如何处理？

**回答：**

将问题分成语法、Schema 和业务三层。合法 JSON 不代表符合字段契约，字段契约正确也不代表内容可信。优先使用部署模型与服务端确实支持的结构化输出或约束解码，再做应用端严格验证，不能只在 Prompt 里反复强调“必须是 JSON”。

对于支持原生结构化输出的模型，可使用 provider 原生策略；否则使用 tool calling 或工具策略，并处理解析与 Schema 校验错误。LangChain 当前的结构化输出路径区分 `ProviderStrategy` 与 `ToolStrategy`，但是否支持完整 Schema、能否和其他工具同时使用，仍取决于具体模型、提供方和锁定版本。JSON mode、tool calling 与严格 Schema 约束不是等价承诺。

约束解码也可能遇到输出截断、拒绝或流式未完成，所以应在完整结果到达且结束状态合法后再解析。不要用正则截取首尾大括号，不要用 `eval`，也不要在部分 JSON 到达时就执行有副作用的操作。

下面用标准库演示一个限定为 `intent` 和 `confidence` 两个字段的严格应用契约，特意拒绝重复键、非有限数和把布尔值当数字的情况：

```python
import json
import math

def parse_result(text):
    if not isinstance(text, str) or len(text.encode('utf-8')) > 16384:
        raise ValueError('Invalid input or payload too large')

    def reject_constant(value):
        raise ValueError('Non-finite JSON number')

    def unique_object(pairs):
        result = {}
        for key, value in pairs:
            if key in result:
                raise ValueError('Duplicate key')
            result[key] = value
        return result

    try:
        data = json.loads(text, parse_constant=reject_constant,
                          object_pairs_hook=unique_object)
    except (json.JSONDecodeError, RecursionError) as exc:
        raise ValueError('Invalid JSON') from exc

    if type(data) is not dict or set(data) != {'intent', 'confidence'}:
        raise ValueError('Unexpected fields')
    if type(data['intent']) is not str:
        raise ValueError('Intent must be a string')
    if data['intent'] not in {'QUERY', 'EDIT', 'CLARIFY'}:
        raise ValueError('Unknown intent')
    score = data['confidence']
    if type(score) not in (int, float) or not 0 <= score <= 1:
        raise ValueError('Confidence out of range')
    if not math.isfinite(score):
        raise ValueError('Confidence must be finite')
    return data
```

该代码只验证数据契约，不会让模型自报的 confidence 自动变得可信；应由经过验证的评分或校准系统支撑。金额、租户、审批等另有服务端语义校验。生产端还应在网络接入层限制消息体，并限制嵌套深度和解析资源。

若失败，最多进行预算内的定向格式修复，修复后重新校验，并检查业务字段是否改变。缺少关键字段时不能编造默认金额、订单号或审批结果；应澄清或失败返回。高风险操作始终要求通过独立的授权与业务验证。

## 如果我们需要生成小说的标题、角色描述和故事梗概，当单次模型调用生成效果不佳时，如何分步生成？

可以采用**分步生成策略**，分阶段控制质量与连贯性：

分步流程设计：

- Step 1：生成小说主题或关键词
- Step 2：基于主题生成小说标题
- Step 3：根据标题设定角色
- Step 4：生成故事梗概

优点：

- 更高控制力：每步可加入人工或规则约束，确保输出质量。
- 提升上下文一致性：逐步构建世界观，避免信息混乱。
- 易于纠错与重试：某一步生成不佳时，仅重试该步。

## 扩散式人体动画和 GAN 人体动画的本质差别是什么？

| 维度 | GAN 人体动画 | 扩散式人体动画 |
| --- | --- | --- |
| 生成机制 | 直接生成或 warping + refinement | 从噪声逐步去噪生成视频 |
| 条件控制 | 姿态、关键点、光流、身份图像 | 文本、姿态、参考图、音频、深度、分割等 |
| 真实感 | 局部锐利，依赖训练域 | 综合真实感更高 |
| 多样性 | 较低，容易模式受限 | 更强 |
| 时序建模 | 光流/时序判别器/缓存 | motion module、temporal attention、3D VAE、video DiT |
| 推理速度 | 快 | 慢，需要加速 |
| 工程适配 | 实时强 | 离线高质量强 |

扩散模型的优势是能利用大规模图像/视频预训练和丰富条件控制；GAN 的优势是推理快、局部任务稳定。当前高质量人体动画通常偏扩散/DiT，实时应用仍可能保留 GAN 或轻量生成器。

## 有了强大的生成式大模型，嵌入模型还有什么用？

- 嵌入模型速度快、成本低，适合做大规模文本检索和相似度计算。
- 嵌入能把文本转成向量，方便做分类、聚类和搜索等基础任务。
- 生成模型更重，更适合复杂对话和文本生成，嵌入模型更轻量，能做很多高效的辅助工作。
- 嵌入模型可以跟生成模型配合使用，提升整体系统效果。
