## 在视频编辑中，如何评估生成视频的质量？

在视频编辑中，可从以下几方面评估生成视频的质量：

**一、视觉方面**
1. **分辨率与清晰度**：检查视频的分辨率是否符合需求，高分辨率（如4K、8K）通常意味着更清晰的画面，但也要考虑播放设备和用途。画面应无模糊、锯齿现象，细节（如文字、物体边缘）要清晰可辨。
2. **色彩准确性**：色彩应还原真实场景或符合创作意图。检查是否存在偏色、色彩饱和度过高或过低的情况。例如，人物肤色应自然，风景的色彩要协调。
3. **对比度**：合适的对比度能使画面亮部更亮，暗部更暗，增强视觉冲击力。过高的对比度可能导致亮部过曝、暗部死黑，丢失细节；过低则使画面看起来平淡。
4. **帧率稳定性**：帧率决定了视频的流畅度。正常情况下，帧率应稳定，如常见的24fps、30fps或60fps。帧率波动会导致视频卡顿或闪烁。

**二、音频方面**
1. **音量平衡**：确保视频中的各个音频元素（如对话、背景音乐、环境音效）音量平衡。对话应清晰可听，背景音乐和环境音效不能掩盖对话，也不能过于微弱。
2. **音频清晰度**：音频应无杂音、失真或爆音。人声、音乐和环境音都应清晰，特别是在有语音内容时，发音要能被准确理解。
3. **音频与视频同步**：音频和视频必须严格同步，声音和对应的画面动作要一致，否则会影响观看体验。

**三、内容方面**
1. **连贯性**：视频内容的情节、动作、场景转换要连贯。剪辑点应自然，避免出现突兀的跳跃或中断，让观众能够轻松理解视频的叙事逻辑。
2. **准确性**：如果视频传达特定信息（如新闻报道、教学视频），内容必须准确无误，包括事实、数据、演示操作等。
3. **吸引力**：视频应能吸引观众的注意力，通过有趣的情节、独特的视觉效果或引人入胜的音频等手段，使观众愿意观看下去。

## 均方误差在多模态大模型中的定义是什么？

均方误差（Mean Squared Error, MSE）在多模态大模型中是一种常用的损失函数，用于衡量模型预测值与实际值之间的差异。它的定义和计算方法如下：

**均方误差的定义**

均方误差是预测误差的平方和的平均值，用于评估模型的预测性能。

**均方误差的计算公式**

$$\text{MSE} = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

其中，$n$ 是样本数量，$y_i$ 是实际值，$\hat{y}_i$ 是预测值。

**均方误差在多模态大模型中的应用**

在多模态大模型中，均方误差常用于回归任务，如图像重建、语音识别等，通过最小化均方误差来优化模型参数，提高模型的预测精度。

均方误差对大误差较为敏感，这使得它在需要精确预测的场景中非常有用，但也需要注意对异常值的处理。

## 基于KL散度的智力度量的依据是什么，怎么在实际场景中做调整？

基于KL散度的智力度量需要结合领域特性进行修正。比如在化学发现任务中，发现单纯比较预测分布 \(P_\theta\) 与真实分布 \(P_w\) 会 **高估记忆能力而低估推理能力**。为解决这一问题，引入了“新颖性权重”：对已知反应数据集 \(X_K\) 的KL值赋予 **0.3权重**，而对未知反应 \(X_U\) 赋予 **0.7权重**。这种调整后的 **IQagent指标** 与诺贝尔奖级发现的相关系数达到 **0.82**，比传统度量高出 **29个百分点**。

## 复杂文档为何依赖长上下文？长序列又会带来哪些挑战？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

位置编码之外，长上下文是复杂文档理解的另一个前提。多页 PDF、研究报告、带表格和图表的长文，要求模型一次读入大量文本和多张高分辨率页面图，还要在跨页、跨模态的内容之间建立引用关系，上下文窗口不够长就装不下。长序列会带来两个挑战：

1. **token 预算容易超限。** 高分辨率页面图本身就要消耗大量视觉 token，多页叠加，再加上正文文本，序列长度很快超出常规的上下文窗口。

2. **算力和位置编码都有压力。** 注意力的计算量随序列长度二次增长，序列越长开销越大；位置编码在远超训练长度时能否稳定外推，也直接影响长序列建模的质量，[5.4.3](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/4_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E4%B8%BB%E6%B5%81%E6%A8%A1%E5%9E%8B%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5-4-3) 反复讨论 RoPE 外推，原因在这里。

> **面试速答**：多页 PDF、带图表的长报告要一次装进大量文本和多张高分辨率页面图，还要建立跨页、跨模态的引用，只能靠长上下文。挑战有两方面，一是视觉 token 多，序列很快超出窗口；二是注意力开销随长度二次增长，位置编码还要在超出训练长度时稳定外推。

## 多人音频驱动数字人为什么更难？

多人场景比单人难在“音频-人物绑定”和“空间-身份一致”。

核心挑战：

- 多路音频可能重叠，需要说话人分离或 diarization。
- 每个人的嘴型应该只跟自己的音频同步。
- 画面中人物位置会变化，需要稳定追踪 ID。
- 多人交互有遮挡、转头、远近变化和动作交叉。
- 文本提示、音频和人物 mask 之间要绑定正确。

常见方案：

1. 为每个人维护独立 ID embedding、face mask、audio feature。
2. 使用人物区域 mask 或 tracking ID 做条件路由。
3. 使用 Label RoPE / instance embedding 区分不同人物 token。
4. 多人数据训练中显式构造“谁在说话”的监督信号。
5. 在生成后用人脸检测和唇形同步指标逐人质检。

## 多尺度编码与自适应分辨率分别解决什么问题？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

这两类方案常被混为一谈，解决的问题并不相同：

1. **多尺度编码**：解决全局语义和局部细节难以兼顾的问题。同一张图用不同分辨率分别编码，低分辨率分支抓全局（这是一张办公桌的照片），高分辨率分支抓细节（桌上那本书封面上的字），再把两路特征融合。思路来自计算机视觉里的特征金字塔网络（FPN）[32]。多模态模型里的例子是 DeepSeek-VL，它用 384×384 输入的 SigLIP-L 提取语义特征，再用 1024×1024 输入的 SAM-B 提取高分辨率细节，两路特征合并后送进 LLM[33]。

2. **自适应分辨率编码**：解决统一缩放到固定尺寸带来的浪费和变形问题。它按图像原本的大小和长宽比编码，token 数跟着图像大小变，小图少、大图多。Qwen2-VL 提出的原生动态分辨率（Naive Dynamic Resolution）属于这一思路，图像只调整到 patch 尺寸的整数倍，在可配置的最小、最大像素范围内保持原始长宽比，避免强制缩放造成的变形[34]。Qwen2.5-VL、Qwen3-VL 都沿用了这套做法[35,36]。

多尺度处理的是同一张图的多种粒度，自适应分辨率处理的是不同图的不同尺寸，两者可以叠加使用。

> **面试速答**：多尺度编码解决全局语义和局部细节难兼顾的问题，同一张图用高低两种分辨率编码再融合，例如 DeepSeek-VL 的 SigLIP 加 SAM。自适应分辨率解决固定尺寸带来的浪费和变形，按原图尺寸编码，token 数随图大小变，Qwen2-VL 提出后一直沿用。两者可以叠加。

## 多模态下游应用可以按什么框架分类与定位？

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

下游应用可以从任务性质和产品位置两个维度定位，再据此选型，如图 6-1 所示。两个维度的划分依据如下：

**任务性质**

这一维度看模型交付的是什么，常见的有三种：

（1）感知增强。模型充当更强的感知器，替代或增强传统 CV 管线，输出仍是结构化的感知结果，OCR、文档解析、工业质检和开放词汇检测都属于这一类。

（2）认知与生成。模型完成理解和推理之后再产出内容，拍照解题、长文档问答、图文创作和视频剪辑都属于这一类。

（3）交互与决策。模型的输出是动作，GUI Agent、具身操作和自动驾驶都属于这一类；错误会直接作用于真实环境，因此这一类对可靠性的要求最高。

**产品位置**

这一维度看模型在产品中所占的比重，常见的有两种：

（1）模型即产品。豆包、ChatGPT 属于这一类，用户直接面对模型，模型的能力边界就是产品的能力边界，对话体验和安全约束都需要稳定。

（2）模型即组件。拍立淘中的重排模块、剪映中的高光检测属于这一类，模型只是管线中的一环，要求单点效果好、延迟低、成本低。

两个维度交叉之后，选型方向随之明确。工业质检属于「感知增强 × 模型即组件」，合理方案是零样本检测模型加产线专用小模型；把大型对话模型直接放上产线，延迟和成本都无法满足节拍要求。本章后续各节沿这张版图逐格展开。

## 多模态业务和纯文本大模型业务有什么区别？

**回答：**

纯文本大模型业务主要处理 token 序列，输入输出边界相对简单。多模态业务同时处理文本、图像、视频、音频，难点会从“语言生成”扩展到“跨模态对齐、时间同步、媒体工程和体验评测”。

第一，数据结构不同。文本是离散 token，视频是帧序列，音频是 waveform，图像是像素矩阵。多模态系统要处理分辨率、帧率、采样率、时间戳、编码格式等工程问题。

第二，对齐更难。视频剪辑里文案、字幕、配音、画面、BGM 必须在时间轴上对齐；纯文本问答没有这种强时间约束。

第三，评测更复杂。文本可以看事实一致性、格式正确性；多模态还要看画面质量、音画同步、字幕可读性、审美、节奏、平台风格。

第四，成本更高。视频和音频处理涉及 GPU、转码、存储、带宽和长任务队列，延迟也更敏感。

第五，交互方式不同。多模态业务常常需要可编辑中间结果，例如脚本、分镜、时间轴，而不是一次性输出最终答案。

所以多模态业务更像“模型能力 + 媒体工程 + 工作流系统”，纯文本业务更像“语言理解 + 知识检索 + 文本生成”。

## 多模态产品的评测体系与数据飞轮应如何设计？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

多模态产品的评测分为离线基准、上线前人评和线上指标三层，每层回答不同的问题；数据飞轮则把线上出现的错误沉淀为回归集。三层评测的做法分别是：

1. **离线基准。** MMMU、OCRBench、DocVQA 等公开榜单只做门槛筛查[9,10]，决定能否发布的是业务评测集，它从真实流量中分层抽样，由人工标注金标准，并覆盖长尾难例。公开测试题可能已经进入训练语料，榜单涨分与业务表现脱节的情况很常见。

2. **上线前人评。** 人评按正确性、有用性和安全性打分，标注一致性用 Cohen's Kappa 衡量，即 $`\kappa=(p_o-p_e)/(1-p_e)`$，其中 $`p_o`$ 为观测一致率，$`p_e`$ 为随机标注时的期望一致率。Landis 与 Koch 把 0.41 至 0.60 称为中等一致（moderate），把 0.61 至 0.80 称为高度一致（substantial）[11]。$`\kappa`$ 仍处于中等一致时，应先修订标注规范；主观维度需要多人背靠背标注。

3. **线上指标。** A/B 实验看任务完成率、点踩率、追问率和留存，线上指标是最终依据。离线指标上升而线上指标下降，多半是因为评测集的分布已经偏离真实流量。

数据飞轮由四步构成：线上负反馈回流，按分辨率不足、知识缺失或幻觉等原因聚类，定向补充数据或修改管线，再把同类错误写入回归集。每次模型更新都要全量通过回归集，避免修复一处问题时引入新的问题。回归集记录的是该产品真实出过的错误。

> **面试速答**：评测分三层：公开榜单只做门槛，业务评测集决定能否发布；上线前人评要用 Kappa 检查标注一致性，处于中等一致时先修订规范；线上完成率、点踩率和留存是最终依据。负反馈要聚类归因、补充数据并写入回归集，每次发布都全量回归。

## 多模态任务可以如何整体分类？分类依据是什么？

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐ (3/5)**

本书按输入输出模态之间的关系给多模态任务分类，即输入是什么模态、输出是什么模态、两者之间是检索、生成、理解还是对齐。按这个标准可以分成四类，各类的流程如图 1-5 所示，分别是：

1. **跨模态检索（Cross-modal Retrieval）**：输入一种模态，在另一种模态的已有数据中找出匹配的结果，典型如文搜图、图搜文。

2. **跨模态生成（Cross-modal Generation）**：以文本等模态为条件，生成图像、视频、音频等非文本模态的新内容，典型如文生图、文生视频、语音合成（TTS）。

3. **多模态理解与推理（Multimodal Understanding & Reasoning）**：接收图像、音频、视频等非文本模态（常附带文本指令），输出文本形式的理解或推理结果，典型如视觉问答（VQA）、图像描述、文档问答和语音识别（ASR）。

4. **跨模态对齐与同步（Cross-modal Alignment & Synchronization）**：在时间或空间上建立不同模态元素之间的对应关系，典型如唇形同步、视觉定位和语音-文本强制对齐。

**分类依据。** 按输入输出关系分类，有两个工程上的原因：

1. **技术路线差异大**：检索任务依靠对比学习得到的嵌入空间（CLIP 系）[5]；生成任务依靠扩散模型、流匹配（Flow Matching）或自回归解码器（Stable Diffusion、Wan 系）[37,52]；理解推理任务依靠"编码器 + 投影器 + LLM"三段式 MLLM（LLaVA 系）[2]；对齐同步任务依靠专门的对齐网络（Wav2Lip 等）[53]。类别确定后，技术选型的范围也随之确定。

2. **评测基准不同**：检索看 R@1、R@5，生成看 FID、CLIP-Score 和 MOS，理解推理看 VQA 准确率、MMBench 和语音识别的 WER，对齐看唇形同步的 LSE-D 或视觉定位的 IoU。类别分清后，评测方案也随之确定。四类任务的技术路线与评测指标对照如表 1-3 所示。

**与学术分类的对应。** Baltrušaitis 等人的综述把多模态机器学习的技术挑战归纳为表示、翻译、对齐、融合和协同学习五类[54]。本书的四类任务与其大致对应，跨模态检索依赖协调表示，跨模态生成对应翻译，多模态理解与推理对应融合，跨模态对齐与同步对应对齐。

**分类的边界。** 实际系统常常同时覆盖多类任务，统一多模态模型把理解与生成放进同一个网络（见 [5.1.4.2](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/1_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E7%90%86%E8%AE%BA%E5%9F%BA%E7%A1%80%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5142)），数字人系统同时包含语音合成和唇形同步。按图文、视频、音频这样的模态组合分类也可行，但同一类中会混入技术路线完全不同的任务，边界不如按输入输出关系清楚。

## 多模态大模型中输出映射器的主要功能是什么？

它负责将大型语言模型（LLM）处理的信号令牌转换成适合不同模态解码器的表示形式。这一过程确保了LLM的输出能够与相应的模态生成模块无缝对接，实现多模态内容的生成。

在多模态技术中，信号令牌是模型可以理解和生成的最小意义单位，它们是模型处理的基础单元。这些令牌可以代表单词、单词的一部分，甚至单个字符，并且被赋予数值或标识符，按序列排列，输入或输出于模型中
。输出映射器将这些信号令牌转换成适合不同模态解码器的格式，例如，将文本令牌转换成视觉或音频信号的表示形式。

输出映射器的关键在于其能够处理模态间的异质性，将LLM生成的抽象令牌表示转换为具体模态的表示形式。这通常涉及到复杂的数据融合方法，如数据级融合、特征级融合、决策级融合，以及深度学习中的多模态融合方法
。例如，在视觉问答（VQA）系统中，输出映射器可能需要将文本问题和图像内容融合，以生成准确的问题回答。

此外，输出映射器的设计还需要考虑模态间的关联与对齐问题。在多模态数据中，不同模态可能在时间、空间、语义上存在复杂的关联。因此，输出映射器必须能够精确地处理这些关联，以确保生成的内容在不同模态之间保持一致性和准确性。

## 多模态大语言模型（MLLMs）中幻觉现象的主要来源是什么？

幻觉现象在多模态大语言模型（MLLMs）中的主要来源包括数据、模型、训练和推理四个方面。

- 数据：数据的质量、数量和统计偏差可能导致幻觉。例如，数据集的噪声、缺乏多样性以及对象共现偏差都会影响模型的表现。
- 模型：模型的架构和组件（如视觉模型、语言模型和对齐接口）的弱点可能导致幻觉。视觉模型的感知能力不足、语言模型的知识先验以及弱对齐接口都是潜在的原因。
- 训练：训练目标和方法的选择不当也可能导致幻觉。例如，仅使用自回归下一个标记预测损失可能不足以处理视觉内容的复杂空间结构。
- 推理：在生成过程中，随着序列长度的增加，模型可能会更多地关注先前生成的文本标记，而忽略视觉内容，从而导致幻觉。

## 多模态大语言模型（MLLMs）中幻觉现象的具体类型有哪些？

幻觉现象在多模态大语言模型（MLLMs）中主要表现为对象幻觉，具体可以分为以下三类：

- 类别幻觉：模型识别出图像中不存在的对象类别或错误的对象类别。例如，模型描述图像中存在“一些长椅和一个篱笆”，而实际上图像中没有这些对象。
- 属性幻觉：模型正确识别了对象类别，但对对象的属性描述错误。例如，模型描述图像中的花朵为“粉红色的花朵”，而实际上花朵的颜色并不准确。
- 关系幻觉：模型正确识别了对象及其属性，但对象之间的关系描述不准确。例如，模型描述图像中的人物“站在她周围观看”，而实际上人物在图像中的位置关系并不如此。

## 多模态技术有哪些挑战?

多模态技术面临的挑战包括‌：‌

- **数据稀疏性（Data Sparseness)**：‌由于不同模态的数据量差异巨大，‌导致在训练和推理过程中需要进行大量的数据预处理和数据增强‌。‌
- **模态间的不匹配（Modality Mismatch)**：‌不同模态的数据之间存在差异和差异性，‌这需要使用多模态模型来处理‌。‌
- **模态间的干扰（Modality Interference)**：‌不同模态的数据之间存在干扰和冲突，‌这需要使用多模态模型来处理‌。‌
- **模态间的转换（Modality Conversion)**：‌不同模态的数据之间需要进行转换和整合，‌这需要使用多模态模型来处理‌。‌
- **模态间的融合（Modality Fusion)**：‌不同模态的数据之间需要进行融合和整合，‌这需要使用多模态模型来处理‌。‌

## 多模态文档智能与传统OCR在特征表示与任务范式上的本质差异是什么？

**技术焦点**：  
- **传统OCR**：基于序列建模（CRNN+CTC）或端到端检测（DBNet）的字符级识别，输出为无结构文本流，忽略视觉语义与跨模态关联。  
- **多模态智能**：  
  - **特征融合**：输入向量 $$\mathbf{h}_i = [\mathbf{w}_i; \mathbf{v}_i; \mathbf{p}_i]$$ ，其中 $$\mathbf{p}_i$$为归一化坐标 $$(\frac{x_1}{W}, \frac{y_1}{H}, \frac{x_2}{W}, \frac{y_2}{H})$$。  
  - **任务扩展**：联合完成实体识别（NER）、文档分类（如DocBERT）、表格重建（TableFormer）。  
**案例**：发票识别中，传统OCR无法区分“单价”与“总价”，而多模态模型通过布局分析（相对位置）和文本语义联合推断。

## 多模态条件通常如何注入视频生成模型？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

注入方式应由条件的信息结构和控制粒度决定，而不是按模态固定分配。同一种参考图既可以编码成语义 token，也可以作为空间对齐特征或独立参考分支。常见机制的边界见表6-3。

<p align="center">表6-3 多模态条件的主要注入机制</p>

| 注入机制 | 更适合的信息结构 | 优势 | 主要边界 |
| --- | --- | --- | --- |
| Cross-attention 或联合注意力 | 文本、音频语义、参考图 token 等非严格对齐条件 | 接口灵活，条件长度和类型容易扩展 | 缺少额外位置设计时，难以保证像素级或逐帧控制；长条件还会增加注意力开销 |
| 通道或序列拼接 | 首帧、源视频 latent、mask、深度等已对齐条件 | 坐标关系直接，适合强空间或时间锚定 | 要求分辨率、帧数和位置可对齐，也会改变输入形状与模型接口 |
| 控制分支或 Adapter | 姿态、边缘、深度、轨迹等稠密结构条件 | 可复用预训练主干，新增控制相对独立 | 增加训练与推理开销；多个控制分支叠加时仍可能互相干扰 |
| Reference attention 或特征检索 | 主体身份、服装、物体外观和风格参考 | 能从参考特征中读取细节 | 容易过度复制参考视角，也可能把外观与姿态绑定在一起 |
| 调制、门控或任务 token | 任务类型、全局风格、条件强度和路由信号 | 参数开销较小，便于控制不同层的响应 | 更适合全局或通道级调节，难以单独承担精细空间控制 |

实际系统经常组合多种机制：文本通过注意力提供语义，源视频与 mask 通过拼接确定可编辑范围，姿态控制由独立分支注入，参考主体再通过特征注意力保持外观。组合是否有效仍取决于训练数据是否覆盖该条件组合，以及各路径在空间、时间和网络层上的作用范围是否清楚。

注入越早、越密集，通常约束越强，但也更容易压制生成自由度或破坏预训练分布；只在少数高层注入对原模型改动较小，却可能丢失细粒度位置。工程上应通过条件强度扫描和路径消融，比较条件遵循、非目标区域保持、视频质量与运动幅度，不能只看某个控制指标。

> **面试速答**：条件注入主要有注意力、拼接、控制分支、参考特征读取和调制门控。选择依据是条件是否具有明确的空间与时间坐标，以及需要多强的约束。语义 token 适合注意力，已对齐的首帧、源视频和 mask 适合拼接，稠密结构控制常用独立分支；复杂任务通常会组合多条路径，并用消融确认每条路径确实生效。

参考资料：[ControlNet](https://arxiv.org/abs/2302.05543)、[VideoComposer](https://arxiv.org/abs/2306.02018)、[VACE](https://arxiv.org/abs/2503.07598)

## 多模态模型与 LLM 在应用能力边界上有何差异？

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐ (3/5)**

LLM 处理输入与输出均为文本的语言任务，MLLM 能处理需要整合多种模态信息的任务。MLLM 的任务覆盖面更广，但在纯文本任务和部分单项视觉任务上，不一定比 LLM 或专用模型强。两者的能力边界按任务类型分别如下：

1. **LLM 做语言任务。** 文本生成、写代码、摘要、翻译、对话都属于这一类，代表模型是 DeepSeek-V4-Pro。这些任务的输入和输出都是文本序列。

2. **MLLM 把能力扩展到了跨模态场景**，落地较多的有以下几类：

    （1）**视觉定位**：根据文字描述在图像中给出目标的边界框，Qwen-VL 通过图像、描述与边界框三元组的训练获得了这一能力[3]。
    （2）**医学影像辅助诊断**：把 CT、MRI 图像和病历文本放在一起生成诊断建议，例如 Med-PaLM M[26]。
    （3）**短视频内容合规审核**：同时理解画面、配文和语音，判断视频是否违规。
    （4）**文档与图表理解**：解析财报表格、流程图、发票等结构复杂的文档，InternVL3.5 和 Qwen3-VL 的技术报告都给出了文档与图表基准的结果[11,12]。

**两个常见误解**

1. **"MLLM 一定比 LLM 强"。** 在纯文本任务上，经过多模态训练的模型可能弱于自己的语言基座。[5.1.1.2](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/1_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E7%90%86%E8%AE%BA%E5%9F%BA%E7%A1%80%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5112) 提到的 LLaVA-1.5-13B 是一个例子，它的 MT-Bench 分数低于 Vicuna-v1.5-13B。该研究把这种下降归因于视觉指令微调对语言模型参数的改动，并用多模态偏好对齐加以缓解[25]。这种退化并非必然，它与数据配比和训练流程有关，第 5 章 [5.5.3.2](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/5_AI多模态原生模型高频考点.md#q5532) 讨论了联合训练如何保持纯文本能力。

2. **"MLLM 能替代所有视觉专家模型"。** 在目标检测、细粒度分类这类单项任务上，通用 MLLM 一般不如专用模型。文档解析领域的专用方案本身已经转向小参数的视觉语言模型：PaddleOCR-VL 的核心模型约 0.9B 参数，报告在页面级文档解析和元素级识别上取得最好结果[27]；MinerU2.5 为 1.2B 参数，报告在多个文档解析基准上超过通用模型和领域专用模型[28]。通用 MLLM 的长处在综合推理，任务需要同时看懂图像、理解问题、再结合常识作答时，专用模型难以替代它。

> **面试速答**：LLM 处理输入与输出均为文本的语言任务，MLLM 能做视觉定位、医学影像辅助诊断、文档理解等需要整合多种模态的任务。MLLM 在纯文本任务上可能弱于自己的语言基座，在检测和细粒度分类上一般不如专用模型。它的长处在综合推理。

## 多模态模型中文本生成器的过程和原理？

Text Generation 是指利用自然语言处理技术，特别是大型语言模型（LLM）来自动产生人类可读的文本。在现代人工智能领域，LLM 已经成为文本生成任务中的核心工具，它们通过学习大量的文本数据来理解语言的结构和语义，从而能够生成连贯、有意义的文本。

![](https://i-blog.csdnimg.cn/direct/501a3c0791d142f3822749e9caae9224.png)

LLM 本身就天然支持直接生成文本，这一能力主要得益于其内部的学习机制和训练目标。在生成文本时，LLM 可以采用多种解码策略，其中两种常见的方法是 BPE decoding 和 Beam search。

BPE decoding（Byte Pair Encoding decoding）是一种中间步骤，它将文本分割成子词序列，这样可以更好地处理罕见词汇和未知词汇。在生成文本时，LLM 会根据概率分布预测下一个子词，然后将这些子词拼接起来形成完整的句子。这种方法有助于提高生成文本的多样性和准确性。

Beam search 则是一种搜索算法，用于在生成文本的过程中找到最有可能的序列。与简单的贪婪搜索不同，Beam search 在每一步都会保留多个候选序列，并根据它们的概率进行排序。最终，它会选择概率最高的序列作为输出结果。这种方法可以在保证生成文本质量的同时，减少生成时间。

除了这两种方法，LLM 还可以采用其他解码策略，如 Top-K sampling 和 Top-p (nucleus) sampling，这些策略可以在一定程度上控制生成文本的多样性和创造性。

## 多模态特征怎么融合，早期融合还是晚期？

**回答：**

选择取决于跨模态交互强度、缺失情况和服务预算。早期融合让不同模态较早共同参与建模，晚期融合组合各模态独立输出的分数或决策，中间融合则先编码再用交叉注意力等模块交互。面试中要先说明命名口径：把独立编码后的特征拼接叫“早期融合”属于相对决策层而言的说法，不等于原始像素与文本直接拼接。

| 方案 | 核心机制 | 适用情况与代价 |
|---|---|---|
| 早期/联合 token 建模 | 较早学习图像、文本、音频之间的关系 | 交互能力强，对数据对齐与计算预算要求高 |
| 中间融合 | 独立编码后使用拼接、门控或交叉注意力 | 兼顾复用与细粒度交互，常用于精排和内容理解 |
| 晚期融合 | 校准后合并各模态分数 | 易缓存、易降级，但难表达复杂的局部对应关系 |

内容社区可以在召回阶段使用独立编码器和向量索引，在精排阶段使用更强交互模型。对于“文字说红色，图中实际是蓝色”这类矛盾，只有独立语义分数相加往往不够，需显式对齐实体、属性或区域。

缺失模态要有 mask 和训练覆盖，可用 modality dropout 模拟图像不可用、OCR 错误等情况；门控还应考虑质量信号，防止某一强势模态长期压制其他模态。评测必须包括单模态基线、模态缺失、模态冲突及额外延迟，证明融合收益来自有效信息，而非数据泄漏或更大参数量。

## 多模态特征融合有哪些常用方法

直接拼接不同模态的特征存在严重的局限性，这主要是因为不同模态数据具有不同的统计特性、特征维度和尺度。简单的特征拼接不仅忽视了模态间的复杂交互关系，还可能导致某个模态的特征主导最终的表示，使得模型无法充分利用多模态信息的互补性。此外，直接拼接也无法处理模态缺失或噪声等实际应用中常见的问题。

在实践中，研究者提出了多种高效的特征融合方法。注意力机制通过学习动态权重来选择性地关注不同模态的重要特征，虽然计算开销较大，但具有较强的可解释性和适应性。门控机制通过控制信息流动来处理模态间的交互，特别适合处理模态缺失的情况，但可能会损失一些细节信息。双线性池化则能够捕捉高阶的特征交互，但参数量大且优化困难。图神经网络通过构建模态间的关系图来实现特征融合，虽然灵活性强，但图的构建往往需要专门的领域知识。

选择合适的融合方法需要综合考虑多个因素，包括任务的特定需求、计算资源的可用性、数据的质量和规模，以及模态间的相关性程度等。在实际应用中，往往需要根据具体场景选择合适的融合方法，或将多种方法结合使用，以达到最佳的效果。此外，随着研究的深入，一些新的融合方法也在不断涌现，如基于神经架构搜索的自动化融合方法，以及考虑时序信息的动态融合策略等。

## 多模态生成器的角色分工是什么？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

多模态生成器在 MLLM 架构的输出端，负责把 LLM 的高层语义、隐状态或离散 token 变成具体模态的信号。任务不同，它承担的角色也不同，大致有三种：

1. **模态解码器（Decoder）。** 最基础的角色，把抽象表示还原成目标模态的原始信号。例如 Stable Diffusion 用 VAE 解码器把 64×64 的 latent 还原成 512×512 的图像[47]，HiFi-GAN 把梅尔谱还原成语音波形[48]，EnCodec 解码器把离散 token 还原成音频[25]。此时生成器基本是确定性的转换，看重保真度和速度，不负责创造内容。

2. **内容创造者（Creator）。** 文生图、文生视频、TTS 里，生成器要从噪声或初始状态出发，按条件生成全新的内容。比如 FLUX.2 从纯噪声出发迭代去噪生成图像[49]，Veo 3.1 根据文字生成视频[50]，VALL-E 只用 3 秒参考录音就能克隆陌生说话人的音色[51]。这时同样的条件应当能生成多种合理且不同的结果，多样性和保真度同样重要。

3. **条件控制响应器（Controller-aware Generator）。** 现在的生成器通常要同时响应多种条件，包括文本 prompt、参考图、姿态骨架、深度图、风格图、人脸 ID 图等。比如 SDXL 配 ControlNet 按线稿或深度图生成室内设计[52,53]，IP-Adapter 把参考图的风格融进新图[54]，InstantID、PuLID 在多张图里保持同一张脸[55,56]。这里可控性比多样性更重要。

> **面试速答**：生成器在 MLLM 的输出端，把 LLM 的语义或 token 变成具体模态的信号，大致有三种角色。模态解码器做确定性还原，看重保真和速度；内容创造者从噪声生成新内容，看重多样性；条件控制响应器要遵循参考图、姿态、深度等条件，可控性优先。

多模态的常用方法包括数据融合、‌多模态深度学习、‌多模态特征提取、‌多模态数据可视化和多模态信息检索。‌

- **数据融合**：‌将不同来源、‌不同类型的数据结合起来，‌以获得更全面、‌准确的信息。‌数据融合可以采用多种方法，‌如加权平均、‌贝叶斯估计、‌神经网络等。‌

‌如基于内容的检索(CBIR)‌、‌基于实例的检索(IBR)‌等。‌

## 多模态融合层的设计原则有哪些?

多模态融合层的设计需遵循三原则：1）层次化交互，通过浅层特征拼接、中层注意力融合和深层联合推理实现渐进式信息整合；2）动态门控机制，根据输入内容自适应调整各模态贡献权重；3）跨模态注意力，使用交叉注意力模块建立模态间细粒度关联。先进方法如Gated Multimodal Unit通过门控网络控制信息流，而Multimodal Transformer通过多头交叉注意力实现模态间双向交互。

## 多模态融合的常见方法有哪些？早期融合与晚期融合的优劣对比？

- **融合策略**：  
  - **早期融合（Early Fusion）**：在输入或低层特征阶段融合，如Concatenation或Cross-Attention。  
    - *优点*：捕捉细粒度跨模态交互。  
    - *缺点*：计算复杂度高，模态对齐困难。  
  - **晚期融合（Late Fusion）**：各模态独立编码后融合高层特征，如加权平均或门控机制。  
    - *优点*：灵活性强，适合异构模态。  
    - *缺点*：可能丢失跨模态细节关联。  
- **混合方法**：如UNITER模型在中间层引入跨模态注意力。

## 多模态词嵌入相比传统词嵌入的本质区别是什么？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

传统词嵌入只在文本这一种模态内表示语义，多模态词嵌入把文本、图像、音频等不同模态映射到同一个向量空间，使不同模态的内容可以直接计算相似度。

传统词嵌入有两类。Word2Vec（2013）、GloVe 给每个词分配一个固定向量，常见维度为 300[29,30]；BERT 输出的是上下文相关的向量，同一个词在不同句子里向量不同，BERT-base 的维度为 768[31]。两类词嵌入都满足语义相近的词向量接近，例如"猫"与"猫咪"的向量接近，与"汽车"的向量相距较远。传统词嵌入与多模态词嵌入的本质区别体现在两点：

1. **传统词嵌入只在单一模态内部有效。** 文本、图像、音频的嵌入分别位于各自的向量空间，相互之间无法直接比较，也就无法计算文本"猫"与一张猫的照片的相似度。

2. **多模态词嵌入（也称跨模态嵌入）把文本、图像、音频等不同类型的信息映射到同一个向量空间。** 和传统词嵌入相比，它在两个方向上做了扩展：

    （1）**输入的模态变多**：除了文本，图像、音频等模态也能转换为同一空间里的向量。
    （2）**"语义相近"的范围扩大**：语义相近则向量接近，这条原则不变，"语义相近"从同义词扩展到了不同模态里的同一个概念。一段猫叫的音频、一张猫的照片和文本"猫"，三者的向量应聚在同一区域，并远离与"汽车"相关的向量，如图 1-2 所示。

代表工作是 CLIP。在它之前，DeViSE（2013）、VSE++ 等已经做过图文联合嵌入，但训练数据规模小，泛化能力有限[32,33]。CLIP 在 4 亿图文对上训练，在大规模数据上验证了统一向量空间的可行性，并用它做零样本图像分类[5]。分类时不需要任何标注数据做微调，只需计算图像向量与一组候选文本向量的相似度。ImageBind 进一步把音频、深度、热成像和惯性测量数据接入同一个空间，而且只需要各模态与图像的配对数据，不需要所有模态两两配对[34]。

**两种含义的区分。** 在多模态大模型中，"嵌入"还有第二种含义。CLIP 式的联合嵌入为每张图像输出一个全局向量，目的是与文本向量直接比较，主要服务于检索和零样本分类。MLLM 中的视觉 token 则是投影器输出的一串向量，位于 LLM 的输入嵌入空间，与文本 token 一起组成语言模型的输入序列。LLaVA 把第一阶段描述为让视觉特征与 LLM 的词嵌入对齐[2]，但它的训练目标只要求语言模型能据此生成正确的文本，并不要求视觉 token 接近某个具体词的向量。投影器如何完成这一变换，见第 2 章 [5.2.5.1](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/2_AI多模态核心组件高频考点.md#q5-2-5-1)。

## 多模态词嵌入需要满足哪些核心条件？如何形式化描述？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

统一向量空间要同时满足两个条件：

1. **模态内一致性**：同一模态中语义相近的内容，向量也要接近，例如两张从不同角度拍摄的猫的照片。这一条与传统词嵌入的要求相同。

2. **跨模态对齐性**：不同模态中语义一致的内容，向量也要接近，例如文本"猫"、猫的照片和猫叫的音频要聚在一起，并远离与"汽车"相关的向量。传统词嵌入没有这项要求，它是多模态词嵌入特有的。

形式化地写，文本编码器 $`f_t(\cdot)`$ 和图像编码器 $`f_v(\cdot)`$ 分别把文本 $`t`$ 和图像 $`v`$ 映射到同一个 $`d`$ 维空间，输出向量经 L2 归一化后用余弦相似度 $`\text{sim}(\cdot,\cdot)`$ 比较[5]。对匹配的图文对 $`\langle t, v \rangle`$ 和不匹配的 $`\langle t, v' \rangle`$，要求满足：

$$\text{sim}(f_t(t), f_v(v)) > \text{sim}(f_t(t), f_v(v'))$$

对比学习损失直接优化这一不等式，拉近匹配对，推远不匹配对。CLIP 在一个批次内让 $`N`$ 个图文对互为负样本，计算 $`N\times N`$ 的相似度矩阵，再用交叉熵拟合对角线上的匹配对[5]，过程如图 1-3 所示。这一目标称为跨模态对比学习（Image-Text Contrastive，ITC），对称 InfoNCE 损失写作：

$$\mathcal{L}_{\text{ITC}} = -\frac{1}{2N}\sum_{i=1}^{N}\left[\log\frac{e^{\text{sim}(t_i,v_i)/\tau}}{\sum_{j=1}^{N}e^{\text{sim}(t_i,v_j)/\tau}}+\log\frac{e^{\text{sim}(t_i,v_i)/\tau}}{\sum_{j=1}^{N}e^{\text{sim}(t_j,v_i)/\tau}}\right]$$

$`\tau`$ 是温度系数，CLIP 把它设成可学习参数，初始值相当于 0.07；$`N`$ 是一个批次里的样本数，CLIP 取 32768[5]。方括号里的两项对应两个检索方向，第一项固定文本 $`t_i`$、在批内所有图像里找匹配，第二项固定图像 $`v_i`$、在批内所有文本里找匹配。两个方向都计入损失，文搜图和图搜文才能同时对齐。

![对比学习示意图](https://raw.githubusercontent.com/WeThinkIn/AIGC-Interview-Book/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/images/1-3-对比学习示意图.png)
<p align="center">图 1-3 对比学习示意图</p>

**对齐与均匀性。** Wang 和 Isola 证明，对比损失在负样本数量足够大时渐近地优化两个性质：一是对齐（alignment），即正样本对的嵌入相互接近；二是均匀性（uniformity），即全部嵌入在单位超球面上尽量均匀分布[35]。对齐对应上式中拉近匹配对的部分，均匀性对应推远不匹配对的部分，由 InfoNCE 分母中的负样本提供。

**缺少某一项时的后果。** 只有模态内一致性、没有跨模态对齐时，例如把 Word2Vec 与单独训练的 ResNet 组合，两个空间无法比较，跨模态检索无从实现。只有对齐、没有均匀性约束时，把所有输入映射到同一个点就能让正样本对完全重合，嵌入空间随之塌缩，相似度失去区分能力，对比损失依靠负样本避免这种塌缩[35]。CLIP 只优化跨模态的对称对比损失，模态内一致性没有单独的训练目标，是在大规模对比训练中间接形成的[5]；后续研究还发现，CLIP 的图像嵌入和文本嵌入在共享空间里分处两个区域，即模态鸿沟（modality gap）[36]。

很多下游任务建立在多模态词嵌入之上。跨模态检索直接比较嵌入向量的相似度，多模态理解在对齐后的嵌入上做语义交互，跨模态生成同样依赖它，Stable Diffusion 用文本编码器的嵌入作为生成条件[37]。

> **面试速答**：统一向量空间要同时满足模态内一致性和跨模态对齐性。形式化地说，匹配图文对的余弦相似度应高于不匹配对，CLIP 用对称 InfoNCE 损失实现这一点。按 Wang 和 Isola 的分析，对比损失同时优化对齐和均匀性，负样本防止嵌入塌缩；缺少跨模态对齐则无法做跨模态检索。

## 多路音频注入有哪些方式？为什么简单拼接通常不够？

常见多路音频注入方式：

1. 多路 audio embedding 直接拼接。
2. 每路音频单独 cross-attention 后相加。
3. 按画面左右或人物 bbox 分割 latent 后分别注入。
4. 使用人物 label / mask / L-RoPE 做结构化绑定。

简单拼接的问题：

- attention 不知道哪路音频对应哪个人。
- 多路音频特征会互相污染。
- 人物移动时静态区域分割失效。
- 训练中模型可能学成“所有音频驱动所有脸”。

因此多人音频驱动通常需要 mask、tracking ID、label embedding 或 L-RoPE 这类显式绑定机制。

## 如何判断一个视频系统实现了哪一层统一？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

判断统一程度，不能只看系统是否支持多个任务，而要追踪任务在接口、表示、参数和训练目标上究竟共享了什么。常见的四个层次见表6-1。

<p align="center">表6-1 统一视频系统的不同实现层次</p>

| 统一层次 | 实际共享的内容 | 不能据此推出的结论 |
| --- | --- | --- |
| 工作流或产品入口统一 | 用户入口、任务编排、项目资产与状态 | 底层模型或视频表示相同 |
| 条件与任务接口统一 | 输入格式、任务描述、条件协议与路由方式 | 所有任务共享模型参数 |
| 表示或主干统一 | tokenizer、视频编码器、部分时空主干 | 使用单一 checkpoint，或各任务质量都更好 |
| 训练与 checkpoint 统一 | 多项任务联合训练并由同一组核心权重执行 | 不存在任务专用适配器、输出头或外部工具 |

这四层描述的是不同系统边界，不是必须逐级达到的成熟度排名。一个系统可以统一工作流和条件接口，却在底层调用多个专用模型；也可以共享生成主干，但把理解、音频或高精度编辑交给独立组件。双流或多组件架构同样可以构成统一系统。

实际判断时可检查六个问题：不同任务是否使用同一组核心权重，是否联合训练，视频表示是否共享，条件是否映射到兼容协议，是否依赖任务专用适配器或解码器，以及跨任务状态由模型还是外部系统保存。只有这些实现信息明确，才适合使用“统一 backbone”或“单一 checkpoint”这样的具体表述。

> **面试速答**：先区分工作流统一、条件接口统一、表示或主干统一，以及训练与 checkpoint 统一。支持多个任务只能说明能力入口较多，不能证明底层参数共享。判断时要看核心权重、训练目标、视频表示、条件协议、任务专用分支和状态存储位置，并明确统一发生在哪一层。

参考资料：[VideoPoet](https://arxiv.org/abs/2312.14125)、[VACE](https://arxiv.org/abs/2503.07598)、[Omni-Video](https://arxiv.org/abs/2507.06119)、[UniVideo](https://arxiv.org/abs/2510.08377)

## 如何判断是哪一层在漂？

先按时间画出身份相似度、结构误差或轨迹偏差，而不是只比较首尾帧。若误差随距参考帧的时间间隔持续增大，再做最小对照：递推模型可将历史生成帧替换为真实帧；分段模型可缩短分段并增加参考锚点；编辑任务可替换运动估计或关闭多次传播。哪项对照显著压低误差增长，主因通常就在哪条链路。

缓解漂移通常依赖周期性重锚定、跨段状态或记忆、重叠区域一致性，以及更可靠的对应关系。具体方案要看偏差来自生成历史、条件衰减还是传播误差，不能统一归因于“模型不稳定”。

> **面试速答**：漂移是随时间累积的持续偏离。递推生成常见误差回灌，整段生成可能受长程交互和条件保持不足影响，视频编辑还会累积对应与传播误差；定位时要看误差随时间的增长曲线，并逐条替换历史输入、参考锚点或运动传播链路。

参考资料：[Video Diffusion Models](https://arxiv.org/abs/2204.03458)、[Phenaki](https://arxiv.org/abs/2210.02399)、[TokenFlow](https://arxiv.org/abs/2307.10373)

## 如何处理多模态数据中的噪声和不平衡问题？

- **数据噪声**：  
  - **清洗策略**：基于置信度过滤低质量样本（如图文不匹配对）。  
  - **鲁棒训练**：对抗训练（Adversarial Training）或添加噪声注入。  
- **数据不平衡**：  
  - **重采样**：对少数模态或任务过采样。  
  - **损失加权**：为稀有类别分配更高损失权重。  
**思考**：多模态数据噪声常来自标注不一致（如Alt文本与图像内容偏差），需结合自监督学习减少依赖。

## 如何检查整段保持能力

排查时先分开看：第1帧是否真的按输入写入；第1帧与第2帧是否连续；主体相似度和背景结构随时间如何变化；提高图像 guidance 后，保持度与运动幅度是否此消彼长。只检查首帧重建误差，无法证明模型具备整段 I2V 保持能力。

## 如何看待 QK-Clip？

QK-Clip 一类方法通过监控或约束 Q/K 投影，使 Attention Logits 不超过目标尺度。它与 QK-Norm 都服务于稳定性，但干预位置不同。是否适配 MLA 等结构取决于具体实现，不能把某个研究方案描述成所有长序列训练的通用必选项。

## 如何确认时空状态真的被使用

可以替换目标对象、修改时间范围或制造短暂遮挡，观察编辑作用域是否随之变化；同时检查非编辑区域和镜头运动是否保持。若指令改变后作用区域不变，或目标遮挡后无法继续编辑，问题通常出在目标绑定、跟踪或时间定位，而不只是生成质量。

> **面试速答**：视频理解把源视频转成对象、区域、轨迹、镜头和事件等时空状态，生成或编辑模块据此判断改什么、何时改、哪些内容要保留。它可以来自独立检测与跟踪模块，也可以内化在统一模型中；简单 T2V 并不要求单独执行视频理解。

## 如何设计全面的视频生成/编辑模型评估指标体系？

1. 基础质量：
   - 视觉保真度（FVD、PSNR）
   - 运动自然度（FID-Video）
   - 时间连贯性（FC-score）
2. 编辑特异性：
   - 目标完成度（Prompt-Accuracy）
   - 内容保持率（ROUGE-V）
   - 边界自然度（Edge-Consistency）
3. 实用指标：
   - 渲染速度：FPS@1080p    >24fps
   - 内存占用：VRAM@1min视频  <12GB
   - 用户满意度：MOS(1-5)    ≥4.0
4. 对抗测试：
   - 极端案例测试（快速镜头切换）
   - 长尾分布验证（罕见动作）
   - 多轮编辑压力测试
5. 评估流程建议：
   - 自动化指标初步筛选
   - 人工评估关键维度
   - 真实场景压力测试

## 定位漂移要看偏差如何随时间增长

- 按时间距离绘制身份相似度、状态正确率或轨迹误差，确认偏差是持续增长还是在某个边界突变。
- 对比自由递推与定期注入干净锚点的结果。重置后明显恢复，通常说明历史反馈链是主要问题。
- 分别统计 chunk 内部和边界附近的错误。错误集中在边界，更可能是状态传递或重叠融合不足；全程缓慢恶化，则更像长期条件利用不足。

> **面试速答**：漂移是身份、场景、运动或事件状态相对目标的偏差随时间持续增大。递推生成常见历史误差反馈，一次处理长上下文也可能因长期条件利用不足或长度外推而漂移；定位时应看误差增长曲线，并比较锚点重置、chunk 内部和片段边界的结果。

## 实时或流式视频生成会给模型和系统带来哪些新要求？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

实时生成不只是让离线模型跑得更快。许多离线模型一次生成完整视频片段，能够在片段内部利用双向时间信息；流式系统必须在未来内容尚未确定时生成当前帧或视频块，并及时响应新的控制输入。生成方式、服务状态和评估指标都会随之改变。

**模型需要支持因果展开**

当前输出只能依赖已经发生的内容和当前控制，常见做法包括因果注意力、帧级或分块自回归以及少步扩散蒸馏。历史特征和生成状态可以缓存复用，但误差也会沿自回归链路累积。训练阶段只看真实历史、推理阶段依赖自身输出时，还要警惕两种历史分布不一致造成的长期漂移。

**系统需要维护有状态会话**

同一会话要保存历史 latent、控制状态、随机性和可回滚节点；控制输入、生成、解码、显示和下一轮反馈必须形成低延迟闭环。排队、模型计算、VAE 解码、视频编码和网络传输都可能进入关键路径，不能只用主干每秒生成多少帧代表真实交互速度。

> **面试速答**：流式视频生成要求模型在看不到未来内容时因果地产生帧或视频块，并复用历史状态及时响应新动作；系统还要维护会话缓存、控制输入、解码显示、取消和回滚。评估不能只看 FPS，应同时看首帧延迟、控制响应延迟、持续吞吐和长程漂移，以及实时化带来的质量代价。

## 实际案例：百万token长视频生成

**任务**：生成一段10分钟的高清视频（约100万token），描述“星际旅行中的虫洞穿越”。  
**传统注意力机制的问题**：
- **显存爆炸**：单卡无法存储 $100万^2$ 的注意力矩阵（约3.8TB）。
- **计算耗时**：单次注意力计算需数小时，无法实用。

**RingAttention解决方案**：
1. **分块与分布**：将视频帧序列切分为100块，每块1万token，分布在100个GPU上。
2. **环形处理**：
   - GPU 1计算第1块查询 $Q_1$ 时，接收GPU 100的 $K_{100}, V_{100}$ 并计算局部注意力。
   - 同时，GPU 1将 $K_1, V_1$ 发送给GPU 2，GPU 2计算 $Q_2$ 与 $K_1, V_1$ 的注意力。
   - 依此类推，环形传递键值，经过100轮后，所有GPU累积完整的全局注意力。
3. **显存优化**：单卡仅需存储 $1万 \times 1万$ 的注意力矩阵（约400MB），总显存占用从3.8TB降至40GB。

**效果**：
- 生成速度：从无法处理到每小时生成1分钟视频。
- 质量提升：长程一致性（如虫洞特效连贯性）比RNN基线提升37%（人工评估）。

## 少样本与零样本缺陷检测有哪些基于多模态大模型的方案？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

新产线冷启动时，正常样本很多，缺陷样本很少甚至没有，监督检测器无法训练。可用的多模态方案有三类，即用语言描述代替缺陷标注的零样本检测、借助少量正常样本并支持对话的 MLLM，以及开放词汇检测加分割的组合，其原理和适用范围分别是：

1. **零样本。** 这类方法用语言描述代替缺陷标注。CLIP 的二类提示可以写成一个异常分数：

$$
a(x)=\frac{\exp\bigl(\cos(f(x),t_{+})/\tau\bigr)}{\exp\bigl(\cos(f(x),t_{+})/\tau\bigr)+\exp\bigl(\cos(f(x),t_{-})/\tau\bigr)}
$$

其中 $`t_{+}`$ 为异常描述的文本特征，$`t_{-}`$ 为正常描述的文本特征，$`f(x)`$ 为图像或窗口特征，$`\tau`$ 为温度系数。上式只是二类提示下的 CLIP 分数，WinCLIP 在此基础上组合了状态词与提示模板，并聚合窗口、patch 和整图三级特征[36]。论文报告，WinCLIP 在 MVTec-AD 上零样本的图像级 AUROC 为 91.8%，像素级 AUROC 为 85.1%[36]。模型没有见过该产线的缺陷图像，依靠的是对比学习预训练得到的图文对齐，见 [5.3 节](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/3_AI多模态基石模型核心技术高频考点.md)。

2. **少样本与可对话。** AnomalyGPT（AAAI 2024）用模拟的异常数据训练，不依赖真实缺陷标注；论文报告，模型在 VisA 上训练后迁移到 MVTec-AD，只给一张正常样本时，图像级 AUC 为 94.1%，像素级 AUC 为 95.3%[37]。它可以直接判断有无异常、指出异常位置，并进行多轮对话。

3. **开放词汇检测加分割。** 由 Grounding DINO 根据文本描述输出检测框，再由 SAM 把框细化为掩码[38,39]，无需为「表面划痕」这类新目标单独训练检测器。这类组合适合冷启动和巡检，不适合作为产线节拍上的在线检测器。

> **面试速答**：没有缺陷样本时可以用语言描述做零样本检测，WinCLIP 在 CLIP 二类提示上聚合多尺度窗口，MVTec-AD 的图像级 AUROC 为 91.8%。AnomalyGPT 用模拟异常训练，一张正常样本即可迁移并指出位置。Grounding DINO 加 SAM 适合新类别冷启动，不承担产线节拍。

## 开放视频基座走向工业系统，还需要补齐哪些环节？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

开放和工业不是互斥分类：Wan、HunyuanVideo、LTX-Video 可以同时是开放模型和工业系统的技术底座。真正差别在交付边界。开放基座通常交付权重、代码和离线能力；工业系统还要对质量分布、延迟、成本和失败恢复负责。主要差异见表3-7。

<p align="center">表3-7 开放视频基座与工业视频系统的交付边界</p>

| 环节 | 开放基座通常关注 | 工业系统还需补齐 |
| --- | --- | --- |
| 模型能力 | 平均生成质量、任务覆盖、可复现性 | 复杂提示可用率、失败切片、稳定版本管理 |
| 对齐 | 基础文本或图像条件 | SFT、偏好优化、安全策略与品牌风格 |
| 推理 | 可运行的采样代码 | 蒸馏、量化、并行、动态 batching 与资源隔离 |
| 服务 | 单次离线生成 | 排队、超时、重试、降级、缓存和容量规划 |
| 评测 | 公开 benchmark 与人工样例 | 离线切片、在线实验、用户反馈和回归门禁 |
| 创作链路 | 模型输入与输出 | 素材管理、编辑、续写、音频、审核与导出 |

**后训练、蒸馏和系统优化不能互相替代**

后训练改变输出偏好，但不会自然降低延迟；蒸馏减少采样成本，可能牺牲细节、多样性或条件遵循；量化和并行改善部署效率，也可能带来数值误差和通信开销。每次优化都应在固定任务切片上同时回归质量、延迟、显存、失败率和单位视频成本。

**服务稳定性也是交付能力的一部分**

服务稳定性同样属于模型效果。OOM、长尾超时、不同宽高比下吞吐骤降，最终都会表现为产品不可用。常见处理包括按 token 预算调度、规格分桶、超时降级、模型版本灰度和失败样本回流；只有平均延迟，没有 P95/P99 和错误率，无法判断系统是否能上线。

> **面试速答**：开放基座解决“模型能否训练和运行”，工业系统还要解决“能否稳定、低成本地交付”。需要补齐后训练、蒸馏与量化、推理服务、评测回归和创作工作流，并同时监控质量、尾延迟、失败率和单位成本。

## 扩散模型在视频编辑中的主要挑战是什么？

**扩散模型在视频编辑**中的主要挑战包括：

- **动态和时间维度**：将静态图像的扩散模型适应到动态和视频的时间维度是一个技术难题。视频包含连续的图像序列，需要处理帧间的动态变化和时间一致性。

## 投影器的输入输出形式是什么？设计目标有哪些？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

投影器的输入是编码器输出的向量序列，形状为 `(N, d_enc)`，N 是 token 数，`d_enc` 是编码器隐藏维度；输出是和 LLM token 嵌入同维度的向量序列 `(M, d_llm)`，可以直接拼进 LLM 的输入序列。要注意 N 和 M 的关系，线性投影和 MLP 保持 N=M，Q-Former、Pixel Shuffle 会把 N 压成更小的 M。

设计目标有四个：

1. **对齐**：输出向量要落进 LLM 能理解的语义空间，让 LLM 把多模态 token 和文本 token 放在一起处理，这是投影器最主要的目标。

2. **信息保真**：投影过程中尽量少丢原始模态的信息，别让编码器提取的细节在这一步被抹平。

3. **计算可控**：投影器自身要轻，还要能控制输出 token 数。高分辨率图像、长音频等场景里，token 压缩能力直接决定 LLM 端的推理成本。

4. **好训练**：对齐预训练阶段通常冻结编码器和 LLM，只训练投影器，跨模态对齐全靠它来学，所以结构要容易优化、容易收敛。

四个目标之间有取舍。Q-Former 表达力强，但参数多、难训练；线性投影训练稳，表达力有限。后面几问里各类方案的差别，基本都是在这几个目标之间做的取舍。

> **面试速答**：投影器输入 (N, d_enc) 的编码器输出，输出和 LLM 嵌入同维度的 (M, d_llm) 序列。线性投影和 MLP 保持 N=M，Q-Former、Pixel Shuffle 会压成更小的 M。设计目标有对齐、信息保真、计算可控、好训练四个，各方案在其间取舍。

## 拖拽编辑（Drag-and-Drop-Editing）在视频编辑中的应用是什么？

在视频编辑中，**拖拽编辑**（也称为点驱动编辑或交互式点编辑）提供了一种直观且灵活的方式来控制和操纵视频内容。这种方法的核心思想是通过用户在视频帧上直接操作（如拖拽）来指定编辑的目标和行为。以下是拖拽编辑在视频编辑中的几个应用场景：

- **对象移动和替换：**
用户可以通过在视频帧上点击并拖拽对象来移动它们，或者替换为其他对象。这种方法特别适用于需要精确控制对象位置和运动的场景。

- **实时交互：**
拖拽编辑允许用户在编辑过程中实时查看和调整效果，提供了一种直观的交互方式。这对于需要快速原型设计和即时反馈的场景非常有用。

- **非刚性变换：**
通过拖拽编辑，用户可以实现对视频中对象的非刚性变换，如缩放、旋转和形变。这对于需要精细调整的场景非常有用。

- **多对象编辑：**
用户可以同时选择和编辑多个对象，通过拖拽来协调它们的运动和位置关系。这对于复杂的场景和多角色视频尤其有用。

- **动态场景控制：**
在动态场景中，拖拽编辑可以帮助用户控制特定对象的运动路径，例如在体育比赛或动作视频中突出显示特定运动员的动作。

- **无监督编辑：**
拖拽编辑可以在不需要大量预训练或标注的情况下进行，适合快速原型开发和简单的视频编辑任务。

- **个性化定制：**
用户可以根据自己的喜好和需求进行个性化编辑，例如在社交媒体视频中添加或移除特定元素。

拖拽编辑通过提供直观的用户界面和灵活的控制方式，极大地提高了视频编辑的效率和创造性。这种方法特别适用于需要用户参与和实时反馈的编辑任务。

## 数字人生成为什么同时需要身份、动作、音频、表情和时序一致性？

数字人不像普通视频生成，只要求“画面合理”。用户会对人脸、嘴型、眼神、动作和身份非常敏感，因此需要同时满足多个一致性：

- **身份一致性**：脸像不像同一个人。
- **唇音一致性**：嘴型是否和音素、节奏匹配。
- **表情一致性**：情绪是否和语音内容、语调一致。
- **动作一致性**：头部、身体、手势是否自然。
- **时序一致性**：视频是否闪烁、漂移、身份逐渐变化。
- **场景一致性**：光照、背景、服装、遮挡关系是否稳定。

这些条件之间还会冲突。例如强行提升 ID 相似度可能降低表情动态，强音频 CFG 可能让嘴型更准但脸部变形，强姿态控制可能导致服装纹理拉伸。因此数字人模型设计的核心是多条件控制之间的平衡。

## 文本编码器在文生图、视频生成和多模态理解中有什么作用？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

文本编码器负责将 prompt 转换为语义条件。

在文生图中：

- 文本编码器输出 token embedding。
- 扩散模型通过 cross-attention 或 conditioning 接收文本条件。
- prompt 质量、tokenization、文本编码器能力会影响生成结果。

在视频生成中：

- 文本条件控制主体、动作、风格和场景。

在多模态理解中：

- 文本和图像被映射到共同空间或通过 cross-attention 融合。
- LLM 根据视觉 token 和文本指令生成答案。

面试要点：文本编码器不是简单“把字变数字”，而是提供生成模型理解用户意图的语义桥梁。

## 条件控制与内容创造的权衡如何处理？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

条件控制（生成结果严格遵循输入）和内容创造（保留多样性）此消彼长。条件分布 $`p(y|x)`$ 越尖锐，生成结果的熵越低，多样性越差。控制越强，模型越收敛到符合条件的窄分布；多样性越强，模型在条件之外保留的可能性越多。控制信号拉满，模型只会按条件机械复刻；控制信号为零，输出又和条件无关。

**常用的平衡机制**

1. **Classifier-Free Guidance（CFG）**：扩散和流匹配模型的标配。训练时以一定概率（常见 10%）丢掉条件[96]，推理时按 $`\hat\epsilon = \epsilon_{\text{uncond}} + s \cdot (\epsilon_{\text{cond}} - \epsilon_{\text{uncond}})`$ 调节。SD 系列的 scale 按经验常用 1 到 12，s=1 相当于不加引导（多样性高、对齐差），7 到 8 最常用，12 以上容易过饱和、出现塑料感。FLUX.1 [dev] 做了引导蒸馏，只接收一个 guidance 参数（官方示例为 3.5）[97]，取值范围和 SD 不能直接对照。

2. **ControlNet（Zhang 等，2023）**：复制一份 SD 主干的编码层作为可训练分支，通过零初始化卷积接回主干，注入边缘、深度、姿态等结构条件[53]，如图 2-8 所示。控制强度可以单独调（control scale 从 0 到 1），建筑、产品、姿态生成场景用得最多。

3. **IP-Adapter（腾讯，2023）**：用解耦的交叉注意力注入参考图特征，实现以图引导图[54]，常和 ControlNet 一起用。

4. **ReferenceNet / InstantID / PuLID（2023~2024）**：专门解决人物 ID 一致性，让多张生成图保持同一张脸[55,56,98]。

不同场景的常见取值如表 2-4 所示。这张表是 SD 系模型的经验范围，没有统一出处，具体数值要按模型和采样器调整。

<p align="center">表 2-4 不同场景的 CFG 经验取值</p>

| 场景 | CFG scale | 额外控制 | 设计哲学 |
|---|---|---|---|

电商、数字人等场景常把几种控制叠加起来，ControlNet 管结构，IP-Adapter 管风格，InstantID 管人脸。

## 核心要点回顾

本章不应被理解为模型名称清单，而应围绕以下技术演进主线建立认知：

```text
图像模型视频化 -> 视频基础模型 -> 统一多模态生成与编辑 -> 长视频/分镜叙事系统
```

第一阶段是 **从图像生成到短视频生成**。图像扩散模型已经具备高质量单帧生成能力，此时核心问题是如何补充时间维度建模。AnimateDiff、Motion Module、MotionLoRA、部分 I2V 路线都可以放在这一阶段理解。关键词是图像先验复用、运动模块和低成本视频化。

第二阶段是 **从短视频生成到视频基础模型**。模型不能只完成图像动画化，还需要学习视频分布、时序一致性和运动先验。Stable Video Diffusion、I2VGen-XL、CogVideoX、Open-Sora、HunyuanVideo、Wan 等路线都体现了这一点。关键词是 Video VAE、Latent Video Diffusion、Video DiT、数据流水线和 video tokenizer。

第三阶段是 **从单条件生成到统一多模态生成与编辑**。真实创作通常不是单一文本 prompt 驱动，模型需要同时处理文本、图像、视频、音频、主体、动作、镜头等条件，并在源视频状态上完成修改、保持与续写。Sora、Veo、Movie Gen、Seedance、Kling 等路线都体现了这一方向。关键词是统一条件建模、音视频联合、受约束编辑、媒体基础模型和创作系统。

第四阶段是 **从单段生成到长视频和分镜叙事系统**。模型不仅需要生成短片段视频，还要处理长程一致性、跨镜头主体稳定、故事级连贯和可控镜头组织。这部分与 4.4 直接衔接。

## 框坐标文本化与 SEG token 路由到下游解码器是怎么做的？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐ (3/5)**

多模态模型想用一个模型覆盖检测、定位、分割等上百种任务，不再为每类任务单独训练专家模型。InternVL2（2024）靠两种互补的机制做到这一点[21]：

1. **框坐标直接当作文本生成。** 视觉定位（grounding）被改写成看图写坐标，给定一句描述，模型以文本形式输出对应的边界框。InternVL 的格式是 `<ref>描述</ref><box>[[x1, y1, x2, y2]]</box>`，坐标按图像宽高归一化到 0~1000 并取整，官方 RefCOCO 评测用的提示词是 `Please provide the bounding box coordinate of the region this sentence describes: <ref>{}</ref>`[9]。这里没有检测专用的输出头，框就是序列里的几个数字 token，由 LLM 自回归生成。

2. **掩码等输出由特殊 token 路由到下游解码器。** InternVL2 借助 VisionLLM v2 的设计，把 MLLM 和多个任务解码器连起来，支持图像、边界框、掩码等输出格式[21]。VisionLLM v2 里，模型先生成 `[DET]`、`[SEG]`、`[GEN]` 等路由 token 来选定解码器，紧跟其后的一组可学习 super-link query 经 LLM 处理后，隐藏状态作为条件送进对应的解码器[22]。之后的 Sa2VA（2025）做得更直接，把 InternVL2/2.5 和 SAM 2 接在一起，取 `[SEG]` token 在 LLM 里的隐藏状态，作为提示送进 SAM 2 的解码器，完成图像和视频的指代分割，梯度可以经 `[SEG]` 回传到 MLLM[23]。

两种方式都留在以 LLM 为中心、自回归生成的框架里，答案要么直接写成坐标文本，要么由特殊 token 驱动专用解码器。

> **面试速答**：框坐标直接作为文本生成，InternVL 输出 ref 和 box 标签包住的坐标，归一化到 0~1000，无需检测头。掩码等输出靠特殊 token 路由：VisionLLM v2 用路由 token 把隐藏状态送给对应解码器，Sa2VA 把 [SEG] 的隐藏状态交给 SAM 2 生成掩码。
