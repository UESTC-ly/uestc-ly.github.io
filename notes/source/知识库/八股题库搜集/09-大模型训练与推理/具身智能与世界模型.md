## FOMM、Monkey-Net、TPSMM 这类一阶运动模型如何驱动肖像？

这类方法的核心是：从源图像和驱动视频中估计稀疏或密集运动，再把源图像的外观按照驱动运动变形到目标姿态。

典型流程：

1. **关键点估计**

   从源图和驱动帧中估计无监督关键点或局部仿射变换。

2. **运动场估计**

   根据关键点差异生成 dense motion field。

3. **特征变形**

   将源图特征 warp 到驱动姿态。

4. **遮挡预测**

   预测哪些区域不可见，需要网络补全。

5. **图像生成**

   通过生成器输出最终头像动画帧。

公式上可以理解为：

$$
I_t = G(I_s, \mathcal{W}_{s \rightarrow t}, O_t)
$$

其中 $I_s$ 是源图，$\mathcal{W}_{s \rightarrow t}$ 是运动场，$O_t$ 是遮挡图。

优点：

- 不需要明确的人脸 3D 标注。
- 泛化到不同物体类别的潜力较强。
- 推理速度相对快。

缺点：

- 大姿态和大遮挡下容易崩。
- 对身份细节和口腔内部建模不足。
- 长视频稳定性依赖运动估计质量。

## LLM/MLLM 在具身智能中扮演什么角色？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

LLM/MLLM 在具身智能中主要扮演认知层角色：

1. **指令理解**：把自然语言转成任务目标和约束。
2. **任务分解**：把复杂目标拆成子任务和执行顺序。
3. **常识推理**：利用世界知识判断物体用途、动作先后和风险。
4. **多模态理解**：结合图像、视频、语音和文本理解场景。
5. **交互解释**：向用户说明进度、失败原因和下一步计划。

但它们也有明显局限：

- 可能产生不符合物理约束的计划。
- 对精确几何、接触动力学、力控不擅长。
- 推理延迟和成本可能不满足实时控制。
- 没有闭环验证时容易“看似合理但不可执行”。

因此更稳妥的系统会把 LLM/MLLM 与世界模型、VLA 策略、控制器和安全模块组合起来。

## LLM/MLLM在具身智能中扮演什么角色？存在哪些局限性？

核心作用：
- 语义推理：解读多模态信息的语义（如识别物体、推断空间关系）；
- 任务分解：将复杂目标拆分为可执行的子任务（如 “打扫客厅” 拆为 “捡垃圾→擦桌子”）；
- 跨模态对齐：打通高层指令与底层动作的映射（如自然语言指令转化为机器人动作序列）。

局限性：
- 忽视物理约束：易生成不符合物理规律的计划（如忽略摩擦力导致物体滑落）；
- 实时适应性差：依赖静态预训练知识，难以快速响应环境变化（如环境突发障碍时无法及时调整动作）；
- 依赖固定动作库：难以自适应新机器人或新环境。

## OCR任务一般将图表类会解析成什么

**回答：**

图表不应该统一解析成一段纯文本。输出格式取决于下游是阅读、检索、计算、再编辑还是视觉定位。常见的目标表示有四类：

1. **Markdown/HTML 表格。** 适合简单二维表和人类阅读，但 Markdown 对合并单元格、复杂表头、跨行跨列和单元格内公式表达能力有限；HTML 可以用 `rowspan`、`colspan` 和更丰富的结构表达。
2. **结构化 JSON。** 适合数据库写入、问答和计算，通常包含表格标题、列定义、行、单元格文本、坐标、置信度、合并关系和脚注。例如：

```json
   {
     "type": "table",
     "title": "季度收入",
     "columns": ["季度", "收入"],
     "rows": [["Q1", "100"], ["Q2", "120"]],
     "cells": [{"row": 0, "col": 1, "text": "100", "bbox": [120, 80, 180, 110]}]
   }
```

3. **图表语义对象。** 对柱状图、折线图、饼图、散点图等，应输出图表类型、坐标轴、单位、图例、数据系列、数据点和文本标签；如果只有 OCR 文本而没有视觉几何关系，就无法可靠恢复“哪个数属于哪根柱”。
4. **文档布局与视觉引用。** 对复杂科研图、流程图和机器人场景中的图像，除了文本和表格，还要保留 `bbox`、polygon、阅读顺序、区域类别和图像引用，必要时输出 SVG/HTML 或结构化中间表示。

一个完整的文档解析结果往往是“文本 + 布局 + 语义结构”的组合：

$$
\text{Document}=\text{Text}+\text{Geometry}+\text{Reading Order}+\text{Structure}+\text{Confidence}.
$$

评测也不能只用字符准确率。表格要看单元格内容准确率、行列结构准确率、树编辑距离、表格识别 TEDS、数字和单位准确率；图表还要看数据点恢复、图例归属、坐标轴解析、关系问答和空间定位。机器人 VLM 场景中若下游要执行动作，必须保留目标区域和不确定性，不能把视觉结果压平为自然语言后直接控制机器人。

## OCR任务中将数学解析成latex格式，用markdown文件展示会存在问题

**回答：**

会存在问题，而且问题通常不在 OCR 单模型本身，而在“图像 -> LaTeX 字符串 -> Markdown 解析器 -> MathJax/KaTeX -> HTML/PDF”的跨层协议不一致。数学表达同时包含反斜杠、花括号、下划线、百分号、美元符号、换行和环境标记，任何一层转义错误都可能导致公式显示为普通文本、局部吞掉内容或破坏后续 Markdown。

常见问题包括：

1. **分隔符冲突。** 行内公式通常使用 `$...$` 或 `\\(...\\)`，块公式使用 `$$...$$` 或 `\\[...\\]`。OCR 文本中若包含孤立 `$`，会与 Markdown 数学分隔符配对错误。
2. **反斜杠被转义。** `\\frac`、`\\sqrt`、`\\begin` 等命令如果经过 JSON、Python 字符串或 HTML 属性，可能被再次转义或丢失；例如 `\\n` 可能被解释成换行。
3. **花括号和上下标不完整。** `x^{2}`、`a_{ij}` 中括号缺失会使 MathJax 后续解析失败；一处未闭合的 `{` 可能影响整段公式。
4. **Markdown 特殊字符。** `|` 可能被识别为表格列，`_` 可能被识别为强调，反引号可能进入代码，`#` 可能被识别为标题。公式必须放在明确的数学分隔符内，并避免把它混入 Markdown 表格。
5. **环境与渲染器差异。** `aligned`、`cases`、矩阵、`\text`、`\overline` 等命令在不同 MathJax/KaTeX 配置中支持程度不同；GitHub、Typora、Pandoc、浏览器和 PDF 引擎不一定使用同一套宏。
6. **OCR 语义错误。** 视觉识别可能把 `\sum` 识别成 `sum`，把 `l` 与 `1`、`O` 与 `0`、负号与短横线、分数线与减号混淆。字符串语法合法不代表数学含义正确。
7. **公式与文本结构脱节。** 表格中的公式、脚注、编号和引用关系如果只识别成一行字符串，后续无法保持原文布局；公式还可能需要语义等价而不是字符完全一致。

稳健处理应分为四步：

1. **解析后规范化。** 统一 Unicode 数学字符、负号、空格、命令和环境；为行内/块公式明确加分隔符，不能用简单字符串替换盲目补美元符号。
2. **语法校验。** 检查 `$`、`$$`、`\\(`、`\\)`、`\\[`、`\\]` 和花括号是否平衡，代码围栏是否闭合，禁止公式跨越 Markdown 表格单元格。
3. **渲染回归。** 用目标 Markdown 渲染器或本地 MathJax 生成 HTML/PDF，逐页检查公式是否为空、溢出、重叠或被当成文本；不要只检查原始字符串。
4. **数学语义评估。** 对公式 OCR 使用 exact match、树编辑距离、命令级准确率和渲染图相似度；对于等价变形，增加符号计算或人工核验。对高风险工程公式，必须保留原图裁剪和置信度供回查。

推荐的数据结构是同时保存 `latex`、`normalized_latex`、`bbox`、`confidence`、`display_mode` 和 `source_crop`。Markdown 只是展示层，不能成为唯一事实来源。最终目标是让公式在 GitHub/本地 Markdown、浏览器 HTML 和 PDF 中稳定渲染，并且渲染正确不代表识别数学含义一定正确。

## PaLM-E如何将连续传感器模态直接融入语言模型中，实现具身智能?

PaLM-E（Pathways Language Model with Embodied） 是一种将连续传感器模态直接融入语言模型的具身智能模型，其实现方式如下：
●多模态表示：PaLM-E 将视觉、听觉等连续传感器模态的信息编码成向量表示，并与文本信息一起输入到模型中。
●统一编码空间：通过统一的编码空间，PaLME 能够在文本和传感器模态之间建立联系，使得模型能够理解和生成与传感器数据相关的文本。
●强化学习：PaLM-E 使用强化学习算法来优化模型在具身环境中的行为，从而实现更智能的交互和决策。

## Pose Guider / Pose Encoder 如何影响动作跟随能力？

Pose Encoder 把姿态图编码到 latent 空间：

$$
F_{\text{pose}} = E_{\text{pose}}(P_{1:T})
$$

再注入到视频生成主干。

影响动作跟随的因素：

- 姿态检测质量：关键点错、漏、抖会直接影响生成。
- 姿态表示密度：骨架稀疏，DensePose 更密集。
- 时序平滑：姿态序列抖动会带来视频抖动。
- 注入层级：浅层影响结构，深层影响细节。
- 训练数据覆盖：极端动作和大幅转身需要足够数据。

**工程建议：**

姿态条件通常需要先做时序滤波、置信度过滤、缺失点补全，尤其是手部和脸部关键点。

## RL过程中的熵崩具体指什么，如何缓解熵崩

**回答：**

熵崩（Entropy Collapse）指强化学习训练过程中策略分布的熵快速下降，模型从“有一定探索”变成“几乎确定地重复少数动作或 token”。离散动作策略的熵为：

$$
H(\pi(\cdot|s))=-\sum_a\pi(a|s)\log\pi(a|s).
$$

对语言模型而言，动作通常是下一个 token，序列策略的熵还会受到温度、Top-$p$、重复惩罚、长度和 token-level reward 的共同影响。熵下降本身不一定是坏事：训练收敛时策略应减少不确定性；真正的问题是熵下降过早、过快，且伴随 reward 停滞、输出模式坍缩、重复回答、探索能力下降或泛化能力变差。

从机制上看，策略梯度会提高高回报动作的概率、压低低回报动作的概率。如果 reward 噪声较大、优势估计方差高、KL 约束太弱、学习率过大，或某个捷径被 reward 错误偏好，这个正反馈会把分布迅速推尖。GRPO 中同一 prompt 的组内 reward 若被一个不可靠的 verifier 拉开，模型可能专门优化可投机的表面模式；PPO 中 value/advantage 估计异常也会产生类似问题。

### 如何诊断

不能只看一个平均 entropy。至少要按训练 step、层、位置和任务分桶观察：

- token entropy、序列平均 entropy、perplexity 和输出多样性；
- KL$(\pi_\theta\|\pi_{ref})$、clip fraction、ratio 分布和梯度范数；
- reward 均值、方差、组内标准差、规则命中率和 reward 分量；
- 重复 n-gram、有效长度、拒答率、工具调用多样性和任务成功率；
- 新任务、旧任务、困难样本和安全集上的回归。

如果 entropy 下降但任务成功率、格式正确率和事实性都同步提升，可能只是正常收敛；如果 entropy 下降伴随 reward 被某个表面规则支配，就要检查 reward hacking 和优势估计。

### 缓解方法

1. **增加合理的熵或探索约束。** 在目标中加入熵正则：

   $$
   L=L_{policy}-\alpha H(\pi_\theta),
   $$

   其中 $\alpha$ 不宜固定拍脑袋，可采用退火或目标熵控制。生成阶段的 temperature、Top-$p$ 只能影响采样，不会替代训练目标中的探索约束。
2. **加强参考策略约束。** 调整 KL penalty、target KL 或 trust-region 范围，避免策略一次更新偏离 SFT/reference 太远。KL 太强会阻碍学习，太弱则容易坍缩，应结合 KL 曲线和任务收益调节。
3. **降低更新激进程度。** 减小学习率、PPO clip 范围、每批更新轮数或 advantage 尺度；做 advantage normalization、reward clipping、梯度裁剪，并检查 value loss 与 reward scale。
4. **修复 reward。** 将任务正确性、格式、事实、工具调用、安全和长度等信号拆开监控；增加 hard negative、对抗样本和人工抽检，避免模型通过重复、投机格式或无意义延长答案获得高分。
5. **提高组内信号质量。** 对 GRPO 增大或动态调整 group size 可能降低相对估计噪声，但会增加 Rollout 成本；若一组 reward 几乎相同，应改善采样温度、任务难度或 verifier，而不是盲目放大梯度。
6. **保留多样性与旧能力。** 混入高质量 replay、SFT 数据或旧任务约束，监控灾难性遗忘；对高风险任务保留拒答、人工确认和确定性校验。
7. **设置异常停止和回滚。** 当 entropy、KL、重复率或 reward 分量越过阈值时暂停更新，保存 checkpoint，回退到最近稳定版本，而不是让异常轨迹继续污染后续训练。

本质上，熵崩不是单纯“entropy 太小”的问题，而是探索压力、策略更新幅度、reward 质量和数据分布共同作用的训练动力学问题。缓解方案必须同时恢复有效探索和 reward 的可验证性，不能只在推理时把 temperature 调高。

## 一个典型具身智能系统如何从指令执行到动作？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

一个典型具身智能系统可以拆成以下流程：

```text
用户指令
  ↓
意图理解与任务解析
  ↓
多模态环境感知
  ↓
状态估计与世界表示
  ↓
任务分解与高层规划
  ↓
动作策略生成
  ↓
低层控制与执行
  ↓
环境反馈与异常检测
  ↺ 回到感知/规划
```

举例：用户说“把桌上的苹果放进篮子里”。

1. **意图理解**：系统识别目标是移动苹果到篮子。
2. **环境感知**：检测苹果、桌子、篮子、障碍物和机械臂自身状态。
3. **状态估计**：估计苹果的 3D 位姿、篮子位置、可抓取区域。
4. **任务规划**：生成“靠近苹果 → 抓取 → 抬起 → 移动到篮子 → 放下”的子任务。
5. **动作生成**：策略模型输出抓取姿态、轨迹或动作 token。
6. **低层控制**：控制器把轨迹转成关节角、速度、电机指令。
7. **反馈修正**：如果苹果滑落或被遮挡，系统重新感知并调整策略。

面试回答时要强调：**具身智能不是一条静态 pipeline，而是带反馈的动态闭环。**

## 世界模型(World-Models)在具身智能中的核心价值是什么？如何分类？

核心价值：
- 构建内部表征：压缩感官输入，捕捉物理规律、物体动态和空间结构（如重力、物体形状）；
- 未来预测：模拟动作序列的后果，规避风险（如预测 “推杯子” 会导致滑落，提前调整力度）。

分类：
- RSSM-based：基于循环状态空间模型，擅长捕捉时间动态，支撑机器人运动控制（如 Dreamer 系列）；
- JEPA-based：基于联合嵌入预测架构，注重语义特征提取，泛化能力强；
- Transformer-based：基于注意力机制，擅长长时序记忆和复杂场景推理（如 Google Genie）。

## 为什么具身智能常被认为是通向 AGI 的重要路径？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

具身智能被认为是通向 AGI 的重要路径，核心原因是：**很多人类智能并不是纯文本推理产生的，而是在与物理世界交互的过程中形成的。**

例如，人理解“重”“滑”“易碎”“挡住”“够不到”等概念，往往来自真实感知和动作经验。具身系统如果只依赖互联网文本和图像，很容易缺少物理 grounding，也就是缺少“这个概念在真实世界里意味着什么”的经验。

具身智能补齐的是以下能力：

1. **物理常识**：知道杯子会掉、液体会洒、物体有重量和摩擦。
2. **因果理解**：知道“推一下”会导致位置变化，“抓太松”会导致滑落。
3. **主动探索**：不只是被动看数据，而是通过行动制造新观测。
4. **长程任务执行**：把抽象目标拆成多步动作，并根据中间结果调整。
5. **真实世界泛化**：面对未见过的房间、物体和用户指令，也能做合理迁移。

所以面试中可以这样回答：**AGI 不应只会在屏幕里回答问题，还要能在开放物理世界中理解目标、约束和后果。具身智能正是把语言、视觉、行动和反馈连成闭环的方向。**

## 为什么时序连续不等于运动正确？如何判断模型是否真正利用了运动信息？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

时序连续只说明相邻帧衔接平滑、状态没有无故跳变；运动正确还要求方向、幅度、轨迹、速度和动作阶段符合条件与场景。一个视频可以非常稳定，却几乎不动，或者始终朝错误方向运动。

**连续但运动错误，通常有三种表现：**

- 连续重复或缓慢改变近似静态帧，画面稳定，但没有完成提示词要求的动作。
- 运动轨迹很平滑，方向、速度或幅度却与控制条件不一致。
- 全局画面随相机平移，像素变化很大，但主体没有产生预期的相对运动。

另一类反例是“变化很多但运动无效”：亮度闪烁、纹理抖动和身份漂移都会增大帧间差异，却不能说明模型掌握了物体运动或动作语义。

**判断模型是否真正利用运动信息，可以做三类检查：**

1. **反事实条件测试**：固定随机种子、主体和场景，只改变“向左/向右”“快/慢”或轨迹控制。输出运动应随条件稳定改变，否则运动条件可能没有被有效利用。
2. **时序扰动测试**：对需要输入视频或帧序列的任务，尝试倒序、打乱或重复部分帧。若任务本身依赖顺序，而模型输出或判断几乎不变，说明其可能主要依赖单帧外观。该方法不适用于所有任务，纯文本生成也没有可扰动的输入帧。
3. **拆分指标评估**：分别检查动态幅度、运动平滑度、动作或轨迹符合度，以及主体一致性、背景一致性和闪烁。单一的“时序一致性”分数无法覆盖这些能力。

面试中还可以补一句：光流、点轨迹或姿态序列能帮助量化运动，但它们各自带有不同假设，不能单独作为运动正确性的充分证据。

> **面试速答**：连续性看帧与帧是否平滑衔接，运动正确性看方向、幅度、轨迹和动作阶段是否符合条件。验证时应固定外观并改变运动条件，再结合时序扰动和分项指标，观察模型是否对运动信息产生可解释的响应。

参考资料：[VBench](https://arxiv.org/abs/2311.17982)、[Video Diffusion Models](https://arxiv.org/abs/2204.03458)

## 什么时候去触发这个总结动作？

**回答：**

总结触发应由预算风险和任务语义共同决定，而不是每隔固定轮数机械执行。

预算触发上，Context Builder 在每次调用前预估总 Token，并为输出、工具返回和误差保留余量。当预计下一步会超预算时触发压缩。可以设置软水位和硬水位：软水位提前异步生成候选摘要；硬水位则阻塞新调用，确保上下文完成一致性压缩后再继续。但具体比例要通过真实请求分布校准，不能把 70%/90% 当成通用答案。

语义触发包括：一个子任务完成、用户目标发生切换、工具产生大体量结果、连续失败需要重规划、对话即将转入人工审批，或者当前状态已经稳定到可以形成 checkpoint。这些时刻比“第 N 轮”更适合总结，因为信息边界清晰。

并发场景中，总结必须基于带版本号的不可变快照。生成摘要后使用 compare-and-swap 或事务检查：如果原会话版本已经变化，就不能直接覆盖最新状态，而要合并新增事件或重新生成。摘要落库后还应记录覆盖的事件范围，例如 `events[1:42]`，确保不会重复压缩或漏掉消息。

总结前后要运行一致性检查：目标、硬约束、未完成事项、关键实体和工具产物引用是否都保留。高风险字段可以规则化提取并单独存储，不完全依赖 LLM 摘要。

## 什么是 affordance？为什么它对机器人很重要？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

Affordance 通常翻译为“可供性”或“可操作性”，指的是：**环境或物体对智能体提供了哪些可能动作。**

例如：

- 杯柄 afford “抓握”。
- 椅子 afford “坐下”。
- 门把手 afford “旋转/拉开”。
- 平整桌面 afford “放置物体”。

对机器人来说，仅识别物体类别是不够的。机器人需要知道“能不能抓、从哪里抓、用什么力度、抓完能不能移动”。因此 affordance 是从感知走向行动的关键桥梁。

面试里可以这样总结：**语义识别回答“它是什么”，affordance 回答“我能对它做什么”。**

## 什么是 Sim2Real？常见方法有哪些？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

Sim2Real 指的是：**先在仿真环境中训练策略，再迁移到真实机器人和真实环境中执行。**

它的核心矛盾是 sim2real gap，也就是仿真与真实之间的差异：

- 视觉差异：纹理、光照、噪声、相机畸变不同。
- 物理差异：摩擦、质量、接触模型、柔性物体不同。
- 控制差异：电机延迟、关节误差、执行器磨损不同。
- 环境差异：真实场景更杂乱、更开放、更不可控。

常见方法：

1. **Domain Randomization**：在仿真中随机化纹理、光照、质量、摩擦，让策略适应变化。
2. **System Identification**：标定真实系统参数，让仿真更接近真实。
3. **Residual Learning**：用真实数据学习仿真误差的残差修正。
4. **Real-to-Sim-to-Real**：先重建真实环境，再仿真训练，再回到真实执行。
5. **少量真实数据微调**：用真实轨迹进行后训练或 LoRA/Adapter 微调。

面试中要强调：**仿真能降低试错成本，但真实世界的接触、摩擦、柔性物体和长尾场景仍然是迁移难点。**

## 什么是具身智能？它和传统 AI 最大的区别是什么？

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

具身智能（Embodied Intelligence / Embodied AI）指的是：**智能体拥有某种身体或行动载体，能够在真实或模拟环境中通过感知、行动和反馈形成闭环，从而完成任务并持续学习的智能系统。**

这里的“身体”不一定只指人形机器人，也可以是机械臂、移动机器人、自动驾驶汽车、无人机，甚至是虚拟环境中的 embodied agent。关键不在于外形像不像人，而在于它是否具备以下三点：

1. **可感知环境**：能通过视觉、深度、触觉、力觉、语音、IMU 等信号获取环境信息。
2. **可改变环境**：能通过移动、抓取、操作、导航等动作影响外部世界。
3. **可从反馈中调整行为**：动作执行后会观察结果，根据成功、失败或风险进行重规划。

传统 AI 更多是在静态数据集上做离线预测，例如图像分类、文本生成、目标检测；具身智能则强调**在线交互、物理约束和闭环决策**。一句话概括：

**传统 AI 主要回答“这是什么”，具身智能还要回答“我该怎么做、做完会怎样、失败后如何调整”。**

易混点：

- **机器人不等于具身智能**：传统工业机械臂可以非常精准，但如果只执行固定程序，智能性有限。
- **大模型不等于具身智能**：LLM 会推理和对话，但如果没有动作接口和环境反馈，仍然停留在数字世界。
- **具身智能也不等于端到端控制**：真实系统通常是高层推理、低层控制、安全约束、状态估计等模块协同。

## 什么是感知-行动循环？为什么它是具身智能的核心？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

感知-行动循环（Perception-Action Loop）指的是：

$$
o_t \rightarrow s_t \rightarrow a_t \rightarrow o_{t+1}
$$

其中：

- $o_t$ 是当前观测，例如图像、深度、触觉、语音、关节状态。
- $s_t$ 是系统估计出的内部状态，例如物体位置、任务进度、风险状态。
- $a_t$ 是动作，例如移动、抓取、旋转、导航。
- $o_{t+1}$ 是动作执行后产生的新观测。

这个循环重要，是因为真实世界具有不确定性：

1. **感知不完美**：摄像头可能遮挡，深度图可能有噪声。
2. **动作不完美**：机械臂会有误差，物体可能滑动。
3. **环境会变化**：人可能突然走入，物体位置可能改变。
4. **任务有长程依赖**：当前动作会影响后续是否可行。

如果系统没有感知-行动闭环，只按预先计划执行，很容易在真实环境中失败。真正的具身智能要能做到：**边看、边想、边做、边改。**

## 具身智能一定要有真实机器人身体吗？

**难度评分：⭐⭐ (2/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

不一定。具身智能强调的是**可行动的智能体与环境之间的闭环交互**，而不是必须拥有真实硬件。

常见载体可以分为三类：

| 类型 | 例子 | 特点 |
| --- | --- | --- |
| 真实机器人 | 机械臂、人形机器人、移动机器人、无人机 | 真实物理反馈强，但数据采集成本高、安全风险高 |
| 虚拟智能体 | Habitat、AI2-THOR、Minecraft、虚拟家居环境 | 便于大规模训练和评估，但存在 sim2real gap |
| 自动驾驶/具身车辆 | Robotaxi、配送车、仓储 AMR | 也是物理世界智能体，强调感知-预测-规划-控制闭环 |

因此，“具身”的重点是：

$$
\text{Embodiment} = \text{Perception} + \text{Action} + \text{Environment Feedback}
$$

只要智能体的行为会改变环境，并且后续决策依赖环境反馈，就具备具身智能的核心特征。

## 具身智能与自动驾驶落地面临哪些共性问题？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐ (3/5)**

具身智能与自动驾驶的硬件不同，落地时面临相同的三类约束，分别是：

1. **数据。** 机器人动作数据无法从网页上直接获取，目前有四条路线并行。遥操作采集以 ALOHA 为代表，低成本的双臂硬件降低了单条轨迹的采集成本[48]；跨本体聚合以 Open X-Embodiment 为代表，汇集了 22 种机器人形态的超过 100 万条轨迹[43]；仿真加域随机化在 Isaac 一类平台上批量生成数据，并随机化物理参数和纹理，以缩小仿真与真机之间的差距；世界模型用于补充数据，NVIDIA Cosmos 是面向物理 AI 的世界基础模型平台[49]，DeepMind 的 Genie 是可交互的生成式环境模型[50]，两者的输入输出形式并不相同。自动驾驶中对应的做法是影子模式回传和场景库合成：真实数据量有上限，合成数据用来补充长尾。

2. **长尾。** 自动驾驶中的快系统以高频处理常规驾驶，慢系统用视觉语言模型处理少见场景，如异形车辆、临时交通手势和语义复杂的路牌。DriveVLM 把场景描述、场景分析和分层规划放进 VLM，DriveVLM-Dual 再与传统自动驾驶管线并行，论文写明已在量产车上完成部署验证[51]。理想汽车在 2025 年 3 月的 NVIDIA GTC 上介绍了 MindVLA，它同样是端到端模型与 VLM 结合的双系统架构[52]。Waymo 的 EMMA 以 Gemini 这类多模态大模型为基础，把规划轨迹、感知目标和道路图元素等输出都表示为自然语言文本[53]；论文同时写明了它的限制，即模型最多只处理 4 帧图像，无法融合激光雷达或毫米波雷达，计算开销也高于传统模型[53]。这种快慢分工与 Helix 的 System 1、System 2 属于同一种拆分方式，各家的频率和规格不同。

3. **安全。** VLM 的输出不直接驱动执行器，要先经过规则层校验碰撞、动力学可行性和限速，越界时拒绝执行并切换到保守策略。评测同样要区分开环与闭环：开环轨迹误差（如 L2 位移误差）容易被拟合优化，与闭环驾驶表现的相关性弱；闭环评测要在仿真中走完全程，再进行实车路测。EMMA 论文也指出，闭环评测需要逼真且计算昂贵的传感器仿真[53]。这与 [5.6.5.3](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/AI%E5%A4%9A%E6%A8%A1%E6%80%81%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6_AI%E5%A4%9A%E6%A8%A1%E6%80%81%E4%B8%8B%E6%B8%B8%E5%BA%94%E7%94%A8%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md#q5653) 的终态判定是同一原则，物理世界中一次错误的代价更高。

> **面试速答**：具身智能和自动驾驶都缺乏动作数据，需要依靠遥操作、跨本体数据集、仿真和世界模型补充。长尾场景交给低频的视觉语言模型，常规驾驶交给高频策略，DriveVLM-Dual 在量产车上做过部署验证。VLM 的输出要先经过规则层，评测以闭环为准。

## 具身智能应该如何评估？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

具身智能评估要覆盖多个层面：

| 维度 | 评估指标 | 说明 |
| --- | --- | --- |
| 任务成功 | Success Rate、完成率、子任务完成率 | 最直观，但不能单独使用 |
| 长程能力 | 长任务成功率、步骤数、重规划次数 | 检验是否能完成多步任务 |
| 泛化能力 | 新物体、新场景、新指令、新机器人平台 | 检验是否只记住训练分布 |
| 鲁棒性 | 遮挡、噪声、扰动、物体位置变化 | 检验真实环境稳定性 |
| 安全性 | 碰撞率、越界率、违规动作率 | 真实部署必须关注 |
| 效率 | 推理延迟、执行耗时、能耗 | 影响端侧落地 |
| 可恢复性 | 失败检测、重试成功率、人工介入率 | 检验系统是否能从失败中恢复 |

单一 benchmark 往往不足，因为真实机器人面对的是开放分布、长尾事件和安全约束。面试里可以说：**具身智能评估应该从“单次任务成功”升级到“长程闭环可靠性”。**

## 具身智能系统通常由哪些模块组成？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

一个较完整的具身智能系统通常包括六类模块：

| 模块 | 作用 | 常见技术 |

## 具身系统中的状态、观测、动作分别是什么？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

具身任务常被抽象成 POMDP（Partially Observable Markov Decision Process，部分可观测马尔可夫决策过程）：

$$
\mathcal{M} = (\mathcal{S}, \mathcal{A}, \mathcal{O}, T, R, \Omega, \gamma)
$$

核心概念如下：

| 概念 | 含义 | 具身智能中的例子 |
| --- | --- | --- |
| 状态 $s$ | 环境真实状态，通常不可完全观测 | 所有物体 3D 位姿、摩擦、重量、机器人关节状态 |
| 观测 $o$ | 传感器能看到的信息 | RGB 图、深度图、触觉、力矩、语言指令 |
| 动作 $a$ | 智能体对环境施加的操作 | 末端位姿、关节速度、导航目标、抓取开合 |
| 转移 $T$ | 执行动作后状态如何变化 | 抓取后物体随手爪移动，推桌面物体产生位移 |
| 奖励 $R$ | 衡量任务完成程度的信号 | 成功放入篮子 +1，碰撞 -1，耗时惩罚 |

具身智能难就难在：**真实状态不可完全观测，动作效果不完全可控，奖励信号通常稀疏且延迟。**

所以工程上常会加入：

- 状态估计：从观测推断真实状态。
- 记忆模块：保存历史观测和任务进度。
- 世界模型：预测动作后果。
- 安全约束：限制危险动作。

## 场景表示、状态估计、世界模型三者有什么区别？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

这三个概念都和“理解环境”有关，但侧重点不同。

| 概念 | 主要回答的问题 | 典型形式 |
| --- | --- | --- |
| 场景表示 | 当前环境里有什么、在哪里、关系是什么 | 2D/3D map、scene graph、occupancy grid、NeRF/3DGS |
| 状态估计 | 当前真实状态最可能是什么 | SLAM、Kalman Filter、particle filter、learned state estimator |
| 世界模型 | 如果我执行某个动作，未来会怎样 | dynamics model、video/world model、RSSM、Transformer predictor |

可以用三句话区分：

- **场景表示偏静态结构**：物体、空间、关系。
- **状态估计偏当前时刻**：在噪声观测下估计真实状态。
- **世界模型偏未来预测**：模拟动作后果，辅助规划和安全评估。

在现代具身智能中，世界模型的作用越来越重要，因为它可以让机器人在真实执行前先“想象”几种可能结果，减少试错成本。

## 如何处理体型差异、手部动作和遮挡？

**体型差异：**

- 使用 pose retargeting 调整骨骼比例。
- 参考 T-pose 或标准姿态估计真实骨骼长度。

- 使用 DWPose/VitPose 提取手部关键点。
- 对手部区域增加损失权重。
- 使用手部关键点置信度和方差评估质量。
- 必要时引入手部局部修复模型。

**遮挡：**

- 使用人体 parsing / SAM 分割层级。
- 建模人物、衣服、手、头发、配饰之间的前后关系。
- 对遮挡区域做局部 inpainting。
- 视频中使用 tracking 保持遮挡关系稳定。

## 显式运动表征什么时候仍有价值？

需要像素级对齐、插帧、编辑传播、轨迹控制或分项评估时，光流和轨迹能提供清晰接口，也便于诊断条件是否生效。代价是估计误差会进入后续模块，光流本身也无法描述新显露区域的内容。因此，显式和隐式表征常被组合使用：隐式特征负责生成能力，显式线索提供局部约束或控制。

> **面试速答**：视频级训练目标和跨帧模块可以把运动隐式编码在时空特征中，所以模型不输入光流也能生成动态。显式光流或轨迹仍适合精确对齐、控制和诊断，但要处理遮挡与估计误差，二者通常是互补关系。

参考资料：[Video Diffusion Models](https://arxiv.org/abs/2204.03458)、[CoTracker](https://arxiv.org/abs/2307.07635)

## 线上发现纹理糊、头发遮挡、服饰动作冲突如何处理？

**纹理糊：**

- 服装图先超分。
- 模型多尺度训练。
- 局部 patch loss / perceptual loss。
- 高分辨率二阶段重绘。

**头发遮挡：**

- 单独做人发 segmentation。
- 换衣时保护头发 mask。
- 最后把头发层 alpha blend 回来。
- 边缘羽化或 Poisson blending。

**服饰动作冲突：**

- 建立服饰标签和动作模板规则。
- 用 VLM 判断服装是否有口袋、裙摆、袖长等。
- 过滤不合理模板，例如无口袋服装不要匹配插兜动作。
- 对复杂服装使用更保守的动作库。

**一句话：**

虚拟换衣上线不是只靠模型，商品理解、动作模板、分割层级、后处理和质检规则同样重要。

## 近几年具身智能的技术演进主线是什么？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

近几年具身智能的主线可以概括为：

```text
传统机器人模块化系统
  ↓
大规模视觉/语言预训练进入机器人
  ↓
VLA：视觉-语言-动作统一建模
  ↓
X-Embodiment：跨机器人、跨任务数据训练
  ↓
Diffusion / Flow Matching：更强连续动作生成
  ↓
Embodied Reasoning + World Model：推理、预测、安全评估
  ↓
Physical AI：仿真、合成数据、端侧部署、真实机器人闭环
```

几个关键节点：

| 时间 | 代表方向 | 核心意义 |
| --- | --- | --- |
| 2023 | RT-2 | 将 VLM 知识迁移到机器人控制，提出典型 VLA 路线 |
| 2023 | Open X-Embodiment / RT-X | 多机器人多任务数据集与跨 embodiment 泛化 |
| 2024 | Octo / OpenVLA | 开源通用机器人策略与可复现 VLA 训练 |
| 2024 | π0 | VLM backbone + flow matching action expert，强化连续动作生成 |
| 2025 | Gemini Robotics / GR00T N1 | 大厂级 VLA、ER、人形机器人基础模型进入主线 |
| 2025-2026 | Gemini Robotics-ER 1.6、GR00T N1.6、Cosmos | 强调空间推理、多视角理解、世界模型、合成数据和端侧/商业化部署 |

从趋势看，具身智能不再只是“单个机器人学一个任务”，而是在走向：

1. **基础模型化**：用更大模型和更多数据学习通用机器人能力。
2. **多具身泛化**：一个策略适配多个机器人平台。
3. **长程任务推理**：模型能分解、监控和修正多步任务。
4. **物理世界建模**：通过世界模型和仿真预测动作后果。
5. **工程闭环**：从模型、数据、仿真、控制、安全到部署一体化。

## 针对分类任务做 RL，具体有什么算法？

**回答：**

先判断分类任务是否真的需要 RL。普通静态分类有明确标签时，交叉熵、focal loss、代价敏感学习和校准通常比 RL 更稳定、更高效。只有当分类动作影响后续状态、标签延迟获得、类别选择有长期收益，或 reward 非可微且只能通过环境反馈得到时，RL 才有必要。

把类别集合看作离散动作空间 $\mathcal{A}$，分类器输出 $\pi_\theta(a|x)$。常见算法可以分为以下几类：

1. **上下文 bandit。** 每个样本是上下文 $x$，模型选择类别 $a$，立即得到 reward，下一样本状态不依赖当前动作。可用 epsilon-greedy、UCB、Thompson Sampling 或 policy gradient。适合推荐类别、动态路由、主动学习和代价随时间变化的分类。
2. **REINFORCE/策略梯度。** 用采样类别的回报更新：

   $$
   \nabla_\theta J(\theta)=
   \mathbb{E}\left[(R-b(x))\nabla_\theta\log\pi_\theta(a|x)\right].
   $$

   $b(x)$ 是 baseline，用于降低方差。实现简单，但样本效率和方差较差。
3. **Actor-Critic、A2C/A3C、PPO。** 当分类动作会影响后续状态或 reward 延迟时，用 Critic 估计 value/advantage；PPO 再用 clipped ratio 限制策略更新。若是大模型生成类别解释、调用工具后再分类，PPO 可处理多步轨迹，但成本和稳定性都高于监督学习。
4. **Value-based 方法。** 对离散动作学习 $Q(x,a)$，包括 Q-learning、DQN 及其改进。适合动作数量有限、环境可交互且状态转移明确的场景；若动作空间很大、输入是高维图文、环境是离线数据，则要警惕估计偏差和过估计。
5. **离线 RL。** 当不能在线试错时，使用 CQL、IQL 等方法在历史决策数据上学习保守策略，适合医疗、机器人和高风险业务，但依赖数据覆盖，不能凭空学出数据之外的好动作。
6. **偏好或可验证奖励优化。** 如果分类结果由规则、程序 verifier 或人类偏好评价，可以使用 DPO/IPO 等离线偏好方法，或 GRPO/PPO 等在线/交互式方法。它们学习的是相对偏好或环境回报，不等价于普通的多分类交叉熵。

算法选择可按任务结构判断：

$$
\text{Immediate labeled loss}\Rightarrow\text{supervised learning};\quad
\text{Immediate but label-free reward}\Rightarrow\text{bandit};\quad
\text{Delayed state-dependent reward}\Rightarrow\text{MDP RL}.
$$

分类用 RL 的难点包括探索代价、类别不均衡、reward 稀疏、策略概率校准、离线分布偏移和 reward hacking。工程上应先建立监督学习 baseline，再证明 RL 带来的长期目标收益；同时报告 macro-F1、少数类召回率、校准误差、决策成本、累计 reward 和线上约束违规率，不能只报告 reward 上升。

## 隐式运动从哪里来？

- **视频级学习目标提供信号**：扩散模型对视频张量或 latent 去噪，自回归模型预测视频 token。要拟合训练视频的联合分布，模型需要利用跨帧相关性。
- **时序模块提供信息通路**：3D 卷积、时间注意力或全时空注意力允许不同帧交换信息。若各帧始终独立处理，仅共享参数并不能保证学到运动。
- **数据分布提供运动先验**：动作、相机移动和物体交互在训练数据中反复出现，模型可以学到统计规律，无须先把它们转换成光流标签。

**能生成运动，不代表运动表征足够准确。**

隐式特征可以同时编码外观、语义和动态，表达能力强，但不保证存在可解释的像素对应。模型也可能依赖静态场景偏置、常见动作模板或相机运动等捷径，生成“看起来在动”的结果，却在遮挡恢复、局部形变和精确轨迹上出错。

## 面试中如何快速讲清楚具身智能的全局框架？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

可以用“三层两闭环”来回答：

**第一层：感知与表示层**

- 多模态传感器获取 RGB、深度、触觉、力觉、语音和自身状态。
- 感知模块完成目标检测、分割、定位、场景图和状态估计。
- 记忆/世界表示维护当前环境和历史交互。

**第二层：认知与规划层**

- LLM/MLLM 负责指令理解、任务分解、常识推理和对话交互。
- Embodied Reasoning 模型负责空间关系、可达性、任务进度和安全判断。
- 世界模型预测候选动作的未来结果。

**第三层：策略与控制层**

- VLA、Diffusion Policy、Flow Policy 等模型生成动作或轨迹。
- 控制器负责运动学、动力学和实时闭环控制。
- 安全模块负责碰撞约束、力限制、回退和人工确认。

**两个闭环：**

1. **执行闭环**：观测 → 决策 → 动作 → 新观测。
2. **学习闭环**：真实数据/仿真数据 → 模型训练 → 部署执行 → 失败样本回流。

面试最后可以总结一句：

**具身智能的本质，是把大模型的语义推理能力、多模态感知能力、机器人控制能力和真实环境反馈连接成可靠闭环。**

## 高层规划和低层控制有什么区别？

**难度评分：⭐⭐⭐ (3/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

高层规划关注的是**做什么、按什么顺序做、为什么这样做**；低层控制关注的是**具体怎么动、如何稳定且安全地执行**。

| 层级 | 输入 | 输出 | 时间尺度 | 例子 |
| --- | --- | --- | --- | --- |
| 高层规划 | 语言指令、场景语义、任务目标 | 子任务序列、约束、工具选择 | 秒级到分钟级 | “先拿杯子，再去水龙头接水” |
| 中层策略 | 视觉观测、目标物体、子任务 | 末端执行器轨迹、抓取姿态、动作 chunk | 100ms 到秒级 | “手爪移动到杯柄附近并闭合” |
| 低层控制 | 目标轨迹、关节状态、力反馈 | 电机控制量、关节速度、力矩 | 毫秒级 | PID/MPC 控制关节运动 |

高层规划可以用 LLM/MLLM 做语义推理，但低层控制必须满足实时性、稳定性和动力学约束。面试中要避免把两者混为一谈。
