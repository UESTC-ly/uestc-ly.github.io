## 自动指标和人工评测应该如何结合？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

自动指标适合高频回归和大规模切片，人工评测负责校准指标难以可靠判断的叙事、状态和整体可用性。二者不是简单相加：自动指标可能与人类判断偏离，人工评分也会受标准含糊、样本顺序和评审差异影响。

**自动评测用于定位和回归**

按维度选择指标，而不是把 FVD、CLIP 相似度或一个 VLM 分数当成万能质量分。视觉质量、运动、主体、轨迹、脚本和控制条件应分别评估，并保留提示类别、视频时长、镜头数量和运动幅度等切片。多模态大模型评审仍属于自动评测，需要检查帧采样、上下文长度、提示模板和位置偏差。

**人工评测要把标准写成可观察问题**

将“整体是否好”拆成主体是否稳定、事件是否完成、镜头是否连贯、控制是否持续生效等独立问题。评测时应隐藏模型名称并随机化左右位置，优先采用同提示下的成对比较，同时安排多名评审；报告中还要包含评审一致性和不确定性，不能只给一个胜率。

## 自动指标如何选择？

![](https://raw.githubusercontent.com/WeThinkIn/AIGC-Interview-Book/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/imgs/06-2.png)

| 任务类型 | 推荐指标 / 方法 | 注意事项 |
|---|---|---|
| 分类任务 | Accuracy、Precision、Recall、F1 | 类别不均衡时不能只看精度 |
| 抽取任务 | EM、token-level F1、字段准确率 | 边界错误和等价表达要单独分析 |
| 选择题 / 考试题 | Accuracy | 要防止评测集污染 |
| 翻译任务 | BLEU、chrF、COMET、人工评估 | BLEU 不足以反映语义和流畅性 |
| 摘要任务 | ROUGE、BERTScore、事实一致性检查 | ROUGE 高不代表摘要事实正确 |
| 代码生成 | Pass@1、Pass@k、单元测试通过率 | 测试用例质量决定指标可信度 |
| 数学推理 | Accuracy、Pass@k、答案校验器 | 要区分最终答案正确和过程正确 |
| RAG 问答 | Recall@k、Citation Accuracy、Faithfulness | 必须判断答案是否基于检索内容 |
| 对话助手 | Win Rate、人工偏好、LLM-as-a-Judge、安全评估 | 需要多轮、边界和安全测试 |
| 线上业务 | A/B、满意度、解决率、转人工率、成本 | 离线指标不一定等于线上效果 |

## 评估目标如何定义？

- 通用模型选型：看综合能力、成本、部署方式和安全性；
- 微调效果验证：看目标任务提升和通用能力是否退化；
- RAG 系统验收：看检索、忠实性、引用和拒答边界；
- 生产替换：看线上解决率、转人工率、用户满意度、延迟和成本。

## 评估结果应该用于什么决策？

- 比较不同模型、checkpoint、微调方案和提示方案；
- 判断微调、后训练或数据配比是否真正提升目标能力；
- 发现能力退化、格式不稳定、安全边界破坏和事实性问题；
- 决定模型是否可以进入灰度（先让少量真实用户试用新版本，确认没问题后再逐步扩大流量）、A/B 测试（50% 用户使用旧模型 A；50% 用户使用新模型 B）或正式上线；
- 为下一轮数据构造、训练策略、RAG 设计和安全策略提供依据。

> **注**：评估体系可以看作模型研发、产品上线和风险治理之间的反馈链路。

## 评估集应该如何构成？

- **常规样本**：代表主要用户需求和高频任务；
- **困难样本**：覆盖长上下文、多约束、复杂推理和领域专业问题；
- **边界样本**：测试拒答、不确定性表达、格式约束和权限边界；
- **对抗样本**：测试越狱、提示注入、干扰信息和鲁棒性；
- **回归样本**：固定旧版本已知能力，防止模型升级后退化；
- **业务样本**：来自真实应用分布，用于判断线上价值。

## 评测指标除了准确率你还看什么？

**回答：**

指标要跟随决策后果。类别极不均衡时，把所有样本判成多数类也可能有很高准确率；分类、检索、生成和推荐不能共用一个总分替代分析。

| 场景 | 主要指标 | 容易忽略的解释边界 |
|---|---|---|
| 分类/审核 | Precision、Recall、macro/micro-F1、PR-AUC、混淆矩阵 | 高风险类需单独约束漏报，PR-AUC 随正例比例变化 |
| 检索/排序 | Recall@K、MRR、NDCG@K、分用户 AUC | 无相关项查询、单类别用户的统计口径应明确 |
| 概率输出 | Log loss、Brier score、可靠性图和 ECE | 排序好不等于概率准，ECE 受分桶方式影响 |
| 生成内容 | 事实正确、指令遵循、完整性、安全性、人工偏好 | 文本相似度和模型评审分都不能直接代表事实正确 |
| 在线系统 | 满意度、留存、负反馈、p95/p99 延迟、单次成本 | 离线提升不构成线上因果收益证明 |

NDCG 通过位置折扣衡量相关内容是否靠前：

```math
\mathrm{DCG}@K=\sum_{j=1}^{K}\frac{2^{r_j}-1}{\log_2(j+1)},\qquad
\mathrm{NDCG}@K=\frac{\mathrm{DCG}@K}{\mathrm{IDCG}@K}
```

相关性等级的定义必须固定，IDCG 为零时明确约定跳过还是记为零。还应按新老用户、内容类型、长尾和模态质量分桶，并给出置信区间；相关样本按用户或文档聚类重采样，不能假装每次曝光都独立。

最终建立一个主目标、一组不可突破的护栏和辅助诊断指标。指标越多不等于评测越成熟，关键是知道哪种失败会被哪个指标发现，以及它会触发什么动作。

## 说明测试集搭建方案，AUC评估逻辑，模型效果提升判定标准

**回答：**

测试集要回答三个问题：在什么分布上评估、标签是否可信、离线提升是否具有统计和业务意义。不能随机切一份数据就称为测试集。

我会优先按时间切分，避免未来行为泄露；按 Query、User、Item 做去重或隔离，防止近重复样本跨集合。测试样本覆盖头部、腰部、长尾 Query，热门与冷启动 Item，明确意图、歧义意图以及正反馈、弱反馈和无反馈。负样本不能只有随机负例，还要有曝光未点击、同 Query 被跳过 Item 和模型易混淆的 hard negative，并记录采样来源。

AUC 表示随机抽取一个正样本和一个负样本时，模型把正样本打分更高的概率：

$$
\operatorname{AUC}=P\left(s(x^+)>s(x^-)\right)
$$

AUC 本质上是排序概率，不依赖固定阈值，对分数的单调变换不敏感。但它不等于 Top-K 检索效果，也不体现位置权重、召回覆盖和延迟。搜索还要看 Recall@K、MRR、nDCG、HitRate、无结果率、首屏命中；推荐还要结合 CTR、停留、转化、负反馈和长期价值。

效果提升不能只看 AUC 多了 0.001。应固定测试集、特征快照和评测脚本，比较核心指标、分桶指标、坏例和置信区间，必要时用 bootstrap 或配对检验。上线前做离线回放和 shadow，线上通过随机分流 A/B 观察主指标、护栏指标、P99、成本和异常率。

没有线上实验时，只能说“离线指标在预设阈值和多个分桶上稳定提升”，不能把离线 AUC 直接等同于业务收益。

## 通用设计流程是什么？

一个合理的大模型评估方案通常包括：

```text
明确评估目标 → 选择基线模型 → 构建评估数据 → 确定指标和评分标准 → 固定 prompt 与推理参数 → 执行自动评估 → 执行人工评估 / LLM-as-a-Judge → 做安全红队和回归测试 → 分析错误案例 → 小流量线上 A/B → 反馈回流并迭代
```

## 长上下文能力应该评估哪些任务、基准和指标？

**难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)**

长上下文能力是模型能否稳定利用长输入中的关键信息。常见任务包括：长文档问答；长文档摘要；多文档综合；信息定位；跨段落推理；长对话一致性；前后文矛盾检查；长代码或长表格理解。

以下述指标作为评估依据：长文档问答准确率；关键信息召回率；长距离依赖推理成功率；摘要忠实性和覆盖率；不同位置插入信息的召回差异；上下文长度增加时的性能衰减；延迟、显存和成本。

## 长时一致性应该如何评估？

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

长时一致性不能简化为任意两帧的特征相似度。评估对象应是脚本或条件中规定的状态：该保持的信息是否保留，该变化的信息是否按时更新。

**先建立状态锚点**

为每条测试样例标出主体、场景、关键物体和事件状态，并注明它们的有效时间。例如人物身份应长期保持，杯子打碎后应持续处于破碎状态，换装后则不应继续拿初始服饰做外观相似度。没有状态标注，自动指标很难区分合理变化和一致性错误。

**按时间距离和故障位置采样**

- **局部窗口**：检查相邻帧运动和外观稳定性。
- **片段边界**：检查 Chunk 交界处是否发生姿态、速度或纹理跳变。
- **远距离重现**：检查主体离场后再次出现，或场景间隔多个镜头后返回时，关键属性能否恢复。
- **状态变更**：检查动作结果、物体状态和人物关系是否在后续继续生效。

主体特征、场景检索、姿态、轨迹和 VLM 状态判断都可以作为信号，但必须加可见性和适用条件。例如人物背对镜头或被遮挡时，人脸相似度没有意义；镜头主动换景时，背景相似度下降也不是错误。

**不要让静止视频占便宜**

一致性高不等于动态正确。几乎不运动的视频可能获得很高的相邻帧相似度，却没有完成提示要求的动作或状态变化。实际报告应同时给出条件完成度、动态幅度，以及指标随时间间隔的变化曲线；边界失败率、首次明显漂移时间和长间隔切片通常比一个全局平均值更容易定位问题。

> **面试速答**：长时一致性评估先要定义哪些状态应保持、哪些状态应更新，再覆盖局部窗口、Chunk 边界、远距离重现和状态变更四类切片。特征相似度只能作为局部信号，还要做可见性过滤，并与动作完成度和动态幅度一起看，避免静止视频获得虚高分数。

参考资料：[VBench](https://arxiv.org/abs/2311.17982)、[MovieBench](https://arxiv.org/abs/2411.15262)、[ChronoMagic-Bench](https://arxiv.org/abs/2406.18522)

## 问答能力如何评估？

- **开放域问答**：模型依赖参数化知识或检索回答。
- **阅读理解问答**：答案应来自给定文本。
- **多跳问答**：需要整合多个证据片段。
- **专业领域问答**：需要领域知识和专家核查。
- **多轮问答**：需要理解历史对话、指代和上下文。

## 阐述Video-LLMs的评估指标体系，包括自动评估和人工评估的具体方案

自动评估指标：
- 文本生成质量：BLEU、ROUGE、METEOR、CIDEr
- 语义相似度：BERTScore、BLEURT
- 任务特定指标：时序定位的mAP、问答的准确率

人工评估维度：
- 相关性：回答与视频内容的相关程度
- 有用性：回答对用户的实际帮助价值
- 事实一致性：回答与视频事实的符合程度
- 流畅度：语言表达的自然流畅性

多维度评估协议：
- 配对比较：两个模型生成结果的人工偏好判断
- Likert量表：5分制或7分制的多维度评分
- 细粒度分析：分任务、分难度层次的评估
