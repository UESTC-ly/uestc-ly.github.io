# 大模型训练与推理

<a id="m45033f641d0c"></a>

## Tokenizer、Token 与模型输入

Tokenizer 把文本映射为离散 token ID，模型再将 ID 映射为向量。Token 可以对应字、子词、字节片段或特殊标记，因此 token 数与字符数、单词数并不相同；同一文本在不同词表下也可能长度不同。

子词方法在词表大小、未知词表示和序列长度之间取舍。训练和推理必须匹配 tokenizer、特殊 token 和对话模板；若新增 token，要同时考虑嵌入矩阵及对应参数训练。分词错误、模板不一致会改变模型实际看到的序列，不能仅从最终自然语言表面检查训练样本。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/03_%E9%A2%84%E8%AE%AD%E7%BB%83%EF%BC%9A%E8%AE%AD%E7%BB%83%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%A4%84%E7%90%86.md#L280)。

## Encoder、Decoder 与自回归建模

Encoder 常通过双向上下文形成输入表示；自回归 Decoder 在生成位置仅使用允许的历史上下文，预测下一个 token；Encoder-Decoder 将输入编码与条件生成分开。它们是注意力可见范围和任务组织的差异，不是模型能力高低的排序。

Decoder-only 便于使用统一的下一个 token 目标进行大规模预训练，也自然支持逐步生成。但它并不因此在所有分类、检索或表示学习任务上最合适。解释架构选择时应结合任务目标、输入输出形式、训练数据和推理成本，避免把当前常见方案当成唯一合法结构。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L259)。

## 缩放点积注意力的 Q、K、V

注意力用查询 Q 与各键 K 的匹配程度，计算对值 V 的加权汇总：$\mathrm{softmax}(QK^T/\sqrt{d_k})V$。Q、K、V 通常由输入经过不同可学习线性投影获得；“查询、键、值”是作用角色，并不是三份彼此独立的文本。

除以 $\sqrt{d_k}$ 用于控制内积分数随维度增大的尺度，减轻 softmax 过度饱和。self-attention 的三者来自同一序列；cross-attention 的查询与键值来自不同表示来源。普通完整注意力的分数矩阵随序列长度平方增长，长上下文会带来显存与计算开销，不能只看模型参数量估计推理成本。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L338)；[原论文：Attention Is All You Need](https://arxiv.org/abs/1706.03762)。

## 因果掩码、填充掩码与 Loss Mask

因果掩码控制一个位置能读取哪些位置，防止自回归训练看到未来答案；填充掩码屏蔽补齐位置；loss mask 决定哪些位置参与训练损失。它们解决的不是同一个问题，不能因为都叫 mask 就共用一份含义不明的张量。

指令微调通常让助手回复位置参与损失，但用户问题仍需要作为上下文被注意力读取。多轮对话应按模板明确哪些助手轮次、结束标记参与训练。Packing 多个独立样本时，还要检查样本间注意力是否按预期隔离、位置和损失边界是否正确；“将 padding 标签设为忽略值”并不自动完成这些工作。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/04_%E5%90%8E%E8%AE%AD%E7%BB%83%EF%BC%9A%E5%BE%AE%E8%B0%83%E4%B8%8E%E5%AF%B9%E9%BD%90.md#L288)；[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/03_%E9%A2%84%E8%AE%AD%E7%BB%83%EF%BC%9A%E8%AE%AD%E7%BB%83%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%A4%84%E7%90%86.md#L504)。

## 多头注意力、MQA 与 GQA

多头注意力把表示投影到多个子空间，使不同头能学习不同关系，再汇总各头输出。MQA 让多个查询头共享一组键值头；GQA 将查询头分组，每组共享键值头，在标准多头与完全共享之间取舍。

减少键值头主要降低 KV Cache 的存储和读取开销，尤其影响长序列和较大批次的解码。它不意味着查询头也同步减少，更不意味着注意力语义完全不变。实际速度和质量取决于模型训练、头数、算子以及硬件；不能用“GQA 总能无损加速”概括。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L414)。

## 位置编码与 RoPE

单纯对 token 集合做注意力并不能完整表达序列位置，位置编码向模型提供顺序信息。绝对位置编码将位置表示加入或结合到输入；RoPE 则按位置旋转查询和键，使内积能够体现相对位置信息。

RoPE 是位置关系的一种参数化方式，不会自动保证训练长度以外的任意外推。扩大上下文还受训练分布、频率设置、位置缩放和长文评测影响。回答“为什么支持长上下文”时，应分别说明位置表示、实际训练长度、服务上限和长文中检索与推理质量，不能只给一个最大 token 数。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L205)。

## Pre-Norm、Post-Norm 与 RMSNorm

Transformer 的残差和归一化可以采用不同顺序：Pre-Norm 在子层前归一化，Post-Norm 在残差相加后归一化。顺序改变了梯度传播与训练稳定性，实际优劣还与初始化、深度、学习率及整体架构有关。

LayerNorm 通常包含去均值和按方差缩放；RMSNorm 用均方根尺度归一化，省去显式中心化。二者都可能带可学习尺度参数，但具体是否有偏置应看实现。面试应抓住计算和统计维度的差异，而不是将“去掉均值”描述成对所有任务都无代价的改进。

## 预训练数据、去重与数据混合

预训练在大规模数据上学习通用分布，数据质量包括正确性、重复率、语言与领域覆盖、格式和授权等多个维度。重复样本会改变有效数据权重，也可能扩大记忆和评测污染风险，因此应区分文档级精确去重、近似去重和训练测试污染检查。

数据混合比例是在通用能力、领域能力、语言覆盖和预算之间分配训练信号。不能只按文件大小混合，需考虑 token 数、质量、采样次数和任务目标。去重也并非越激进越好：不同条件下的相似表述可能提供有用变化，应保留明确规则、抽查和消融结果。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/03_%E9%A2%84%E8%AE%AD%E7%BB%83%EF%BC%9A%E8%AE%AD%E7%BB%83%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%A4%84%E7%90%86.md#L214)。

## SFT 数据、对话模板与灾难性遗忘

监督微调用输入—目标输出样本，让已有模型学会任务格式、指令遵循和领域行为。高质量样本要在指令、上下文、目标输出及工具消息上自洽，并与推理时的对话模板匹配；只增加样本数量不能补偿错误答案和不一致格式。

只关注训练损失下降可能掩盖过拟合或原能力退化。应分别观察目标任务、通用能力、安全边界和长度分布，必要时减少训练轮次、调整学习率、混合通用样本或采用参数高效方法。SFT 擅长改变行为和使用已有能力，不能保证把大量实时事实永久、准确地写入参数。

## LoRA 的低秩更新、初始化与参数选择

LoRA 冻结原权重 $W$，训练低秩增量 $\Delta W=BA$，其中 $A\in\mathbb R^{r\times d_{in}}$、$B\in\mathbb R^{d_{out}\times r}$，且 $r$ 远小于两侧维度。训练参数量由 $d_{out}d_{in}$ 降至 $r(d_{in}+d_{out})$，主要节省可训练参数对应的梯度和优化器状态。

常见初始化让一侧随机、另一侧为零，使初始增量为零，同时通过训练逐步产生更新。rank 决定增量表示空间大小，缩放系数控制增量幅度，target modules 决定哪些线性变换被适配；三者与学习率和数据量共同影响效果。LoRA 仍需存储底座并计算激活，因此不能把“训练参数减少百倍”直接等同为“总显存减少百倍”。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/04_%E5%90%8E%E8%AE%AD%E7%BB%83%EF%BC%9A%E5%BE%AE%E8%B0%83%E4%B8%8E%E5%AF%B9%E9%BD%90.md#L445)；[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/04_%E5%90%8E%E8%AE%AD%E7%BB%83%EF%BC%9A%E5%BE%AE%E8%B0%83%E4%B8%8E%E5%AF%B9%E9%BD%90.md#L521)；[原论文：LoRA](https://arxiv.org/abs/2106.09685)。

## QLoRA 与量化底座微调

QLoRA 将低比特存储的冻结底座与可训练 LoRA 参数结合，进一步降低底座存储成本。计算时通常需要按实现将量化表示恢复到计算精度参与运算，因此“4 位微调”不表示全部激活、梯度和算子都以 4 位执行。

显存预算要同时算量化权重、量化元数据、适配器、梯度、优化器状态、激活和临时工作区。较长序列或较大 batch 仍可能由激活占主导。量化方式与硬件支持还会影响吞吐和精度，不能只比较模型文件大小；合并适配器、部署格式和导出后的精度也应独立验证。

## RLHF、PPO、DPO 与 GRPO 的区别

偏好对齐让模型的输出更符合给定评价目标。常见 RLHF 流程包含监督起点、偏好或奖励信号和策略优化；PPO 可用奖励模型或其他奖励配合策略优化，通常还涉及价值估计与约束。DPO 利用成对偏好数据直接优化策略相对参考策略的偏好目标，省去单独进行在线 PPO 的完整环节。

GRPO 在一类常用设置中，对同一问题采样多条回答，用组内奖励构造相对优势，减少对独立价值模型的依赖。但它仍依赖奖励质量和采样成本，也可能受奖励稀疏、投机和分布偏差影响。三者不是按年份严格替代的关系，应按是否有偏好数据、可验证奖励、在线探索预算和任务要求选择，评估也不能只看训练奖励。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/04_%E5%90%8E%E8%AE%AD%E7%BB%83%EF%BC%9A%E5%BE%AE%E8%B0%83%E4%B8%8E%E5%AF%B9%E9%BD%90.md#L991)；[DPO 原论文](https://arxiv.org/abs/2305.18290)。

## 数据并行、张量并行、流水线并行与 ZeRO

数据并行让设备处理不同样本并聚合梯度；张量并行把层内计算和参数切到多设备；流水线并行把不同层分到不同阶段。它们分别沿样本、层内张量和层序列划分工作，常可以组合，而非互斥选项。

ZeRO 类方法按阶段分片优化器状态、梯度和参数，降低数据并行副本的显存冗余。节省显存通常带来额外通信、调度或参数聚合开销；流水线还要考虑微批次和气泡。回答训练扩展性时，应从单卡瓶颈、设备互联、通信体积和有效计算比例出发，不能仅列“几 D 并行”。

## 混合精度、梯度缩放与数值稳定性

混合精度让适合的运算使用较低精度，以节省显存带宽和提高算力利用率，同时对敏感部分保留更高精度。FP16 的动态范围较窄，训练时常配合损失缩放，减少小梯度下溢；BF16 与 FP32 相同的指数位宽带来不同的范围取舍，但有效精度仍有限。

NaN 不应直接归咎于显卡或精度格式。应检查输入和标签、除零或取对数、异常激活、梯度范数、学习率及缩放状态。梯度累积也要按实际损失归一化，特别是变长序列和不同有效 token 数的微批次；简单平均多个 batch 的平均损失未必等于全体 token 的平均损失。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/03_%E9%A2%84%E8%AE%AD%E7%BB%83%EF%BC%9A%E8%AE%AD%E7%BB%83%E4%B8%8E%E6%95%B0%E6%8D%AE%E5%A4%84%E7%90%86.md#L638)。

<a id="m19e1dfb67b9a"></a>

## Prefill 与 Decode 的性能差异

Prefill 处理输入前缀并生成对应中间状态，通常能在输入位置上进行较多并行计算；Decode 逐个产生新 token，每一步依赖此前结果。二者的计算形态不同，因此长输入和长输出可能暴露不同瓶颈。

服务指标应区分首 token 延迟、后续 token 间隔、端到端延迟和整体吞吐。批处理可能提高设备利用率，却也可能增加单请求等待；把 prefill 与 decode 的调度影响混成一个平均耗时，会掩盖长提示对其他请求的干扰。优化应先用实际长度分布和并发观察瓶颈。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L122)。

<a id="m475e09e1ae60"></a>

## KV Cache 的原理、容量与复用边界

自回归生成时，历史 token 在各层产生的键和值可缓存起来，后续步骤仅计算新增 token 的查询及新增键值，避免重复执行整个历史前缀。历史注意力访问仍随已生成长度增长，缓存减少重复计算，并没有让长上下文变成常数成本。

忽略额外开销时，KV 存储约为 $2\times L\times B\times T\times H_{kv}\times d_h\times s$ 字节，依次表示键值两份、层数、batch、缓存长度、键值头数、头维度和每元素字节数。前缀复用要求实际 token 前缀和有关计算配置匹配；不能仅凭自然语言含义相似就共享 KV。权限和租户隔离也必须纳入缓存键与访问设计。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L191)。

<a id="mcbc54546fbed"></a>

## FlashAttention 与显存访问优化

FlashAttention 的核心是通过分块和在线 softmax 等方法减少高带宽显存读写，避免把完整注意力分数矩阵反复写回显存。它针对硬件 I/O 组织精确注意力计算，和通过丢弃连接或近似计算降低注意力规模的办法不同。

它能显著改善中间激活与访问成本，但普通完整注意力的算术复杂度仍随序列长度平方增长。收益与序列长度、头维度、精度、设备和算子实现有关。不能把“更少显存”解释成不需要 KV Cache，也不能将所有长文加速方案统称为 FlashAttention。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L802)。

<a id="m7047adab37eb"></a>

## 权重量化、激活量化与精度评估

量化用较少位宽表示数值，通常通过缩放与零点等参数在浮点数和整数或低比特表示间映射。权重量化主要降低模型存储与读取带宽，激活或 KV 量化还会改变运行时显存和算子需求；各部分应分别说明。

量化误差与异常值、粒度、校准样本和目标任务有关。逐张量、逐通道或分组量化在元数据、误差和硬件效率之间取舍；训练后量化和量化感知训练的成本也不同。部署评估应包括任务质量、长短输入、吞吐、延迟和峰值显存，不能只说“几乎无损”，也不能把低比特文件直接视为所有硬件都能加速执行。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L1142)；[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L1296)。

## 连续批处理与分页 KV 管理

连续批处理允许在生成迭代之间加入新请求、移出已完成请求，降低固定 batch 等待最长请求造成的资源空闲。分页 KV 管理把逻辑连续的缓存序列映射到物理块，减少连续大块分配带来的浪费，并为缓存共享等机制提供基础。

它们分别作用于调度和内存管理，不能互相替代。调度还需控制最大运行 token 数、排队公平性和 prefill 对 decode 的干扰；过度追求批量吞吐可能牺牲尾延迟。分页也有块粒度、元数据和访问开销，收益要放到真实并发与长度分布中衡量。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L343)；[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E5%9F%BA%E7%A1%80%EF%BC%88%E7%B2%BE%E5%8D%8E%E7%89%88%EF%BC%89/6.3%E5%A4%A7%E6%A8%A1%E5%9E%8B%E9%83%A8%E7%BD%B2%E6%8A%80%E6%9C%AF.md#L422)。

## Temperature、Top-k、Top-p 与解码策略

模型给出下一 token 分布后，解码策略决定如何选择输出。Temperature 在 softmax 前缩放 logits，改变分布尖锐程度；Top-k 保留概率最高的固定数量候选；Top-p 保留累计概率达到指定范围的候选集合。贪心解码每步选择最高概率 token，不等于全序列概率最高。

参数改变的是采样和搜索行为，不会凭空增加模型知识。低随机性也不能保证事实正确或严格可复现；硬件、算子、服务实现等还可能影响结果。结构化任务需同时使用输出约束和验证，创意生成则可能更看重多样性，不能只给一个通用温度值。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/05_%E6%8F%90%E7%A4%BA%E5%B7%A5%E7%A8%8B%EF%BC%9A%E5%BA%94%E7%94%A8%E5%A4%A7%E6%A8%A1%E5%9E%8B%E7%9A%84%E9%AB%98%E7%BA%A7%E6%96%B9%E6%B3%95.md#L378)。

<a id="mf0ead1a6f9c6"></a>

## 上下文窗口、有效利用率与长文评测

上下文窗口表示一次模型计算可处理的序列范围，而有效利用率描述模型是否能找到并正确使用其中的信息。服务允许输入更长，不代表中间位置的信息、跨段推理和指令遵循都保持同样质量。

长文评测应覆盖证据位置、干扰文档、问题难度和输入长度，区分直接检索事实与多步推理。处理溢出时可以检索、裁剪、分块和压缩，但压缩可能丢失限制条件或引用关系；需保留任务目标、已确认事实、未决问题与证据定位，不能只保留一段流畅摘要。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/06_%E6%A8%A1%E5%9E%8B%E8%AF%84%E4%BC%B0%EF%BC%9A%E5%A4%9A%E7%BB%B4%E8%AF%84%E4%BC%B0%E5%A4%A7%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B.md#L502)。

## MoE 的稀疏激活与负载均衡

混合专家模型用路由器为 token 选择部分专家，使每个 token 只执行一部分参数，从而将总参数容量与单次激活计算量部分分离。总参数量、激活参数量和实际 FLOPs 是不同口径，比较成本时必须明确。

稀疏激活带来路由、专家间负载不均和跨设备通信问题。路由过度集中会让部分专家拥塞、其他专家利用不足，因此常需要均衡目标和容量管理。MoE 并不等于总显存需求随激活参数同步降低：未激活专家的权重仍需以某种方式存储和调度。

参考资料：[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L611)；[WeThinkIn/AIGC-Interview-Book 原文](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/34e9ee6aa6d35d1e213099a7ae9f433b7b9e6fe6/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/02_%E6%A8%A1%E5%9E%8B%E6%9E%B6%E6%9E%84%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.md#L691)。
