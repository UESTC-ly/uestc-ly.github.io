## Python 3.13/3.14之后，GIL、JIT、t-string、延迟注解有哪些新变化？

截至 2026 年，3.14 已是稳定大版本。对 AI 工程有实际影响的变化：

1. **Free-threaded Python**：3.13 起可选关闭 GIL，3.14 继续推进；生态与 C 扩展兼容性仍需评估。
2. **实验性 JIT**：持续改进解释器性能，但不替代 CUDA/C++。
3. **t-string（3.14）**：模板字符串，返回可处理模板对象，适合安全 SQL/HTML/日志模板/DSL。
4. **延迟注解与多解释器**：类型注解求值更友好；标准库出现 `InterpreterPoolExecutor` 等方向，为 CPU 并行提供新选项。

误区：

- free-threaded ≠ 所有项目应立刻关 GIL。
- JIT ≠ Python 取代 GPU 内核；瓶颈常在矩阵计算与 IO 架构。

## python 并发，协程

**回答：**

Python 并发要先区分 I/O 密集和 CPU 密集。`asyncio` 协程适合非阻塞网络/文件 I/O；线程适合阻塞 I/O 或调用释放 GIL 的 C 扩展；CPU 密集的纯 Python 计算通常用多进程或原生扩展。协程只有在使用异步库并主动让出时才有并发收益，把同步阻塞函数直接放进事件循环会卡住所有任务。

工程上还要处理取消、超时、背压、异常传播、共享状态锁和资源上限。并发不是越多越好，应根据下游连接池、CPU、内存和 P95 延迟压测。

## 三、并发模型选择

- **I/O 密集**：`asyncio` + 异步 HTTP（调 LLM API、爬取、写库）优先。
- **CPU 密集**：多进程（`ProcessPoolExecutor`）或把计算下沉到 NumPy/原生库/GPU。
- **多线程**：受 GIL 限制，适合 I/O，不适合纯 Python CPU 并行。

```python
import asyncio
import httpx

async def fetch(client, url):
    r = await client.get(url)
    return r.json()

async def main(urls):
    async with httpx.AsyncClient(timeout=30) as client:
        tasks = [fetch(client, u) for u in urls]
        return await asyncio.gather(*tasks)
```

## 为什么选择 Python 和 Go 作为技术栈？在处理并发时有什么区别？

**回答：**

Python 和 Go 的定位不同，组合使用很常见。Python 生态强，适合大模型应用、RAG、数据处理、模型推理调用、实验验证和 AI 工具链集成。很多 LLM、embedding、rerank、向量库、数据处理框架都优先支持 Python。开发效率高，适合快速迭代算法和应用逻辑。

Go 更适合高并发后端服务、网关、任务调度、RPC 服务和基础设施。它编译部署简单，运行时开销低，goroutine 和 channel 原生支持并发，服务稳定性和工程可维护性好。

并发方面，Python 的主要限制是 GIL。对于 CPU 密集型多线程，Python 线程不能真正并行执行 Python 字节码，通常要用 multiprocessing、C 扩展、向量化计算或把 CPU 密集任务交给模型服务。对于 IO 密集型任务，Python 可以用 asyncio、异步 HTTP 客户端、事件循环来高效处理，例如并发调用大模型 API、数据库、对象存储等。

Go 的 goroutine 是轻量级协程，由 Go runtime 调度到多个 OS 线程上，可以利用多核并行。Go 的 channel、context、select、sync 包让并发控制比较自然，适合大量连接、限流、超时控制、取消传播和服务端并发处理。

所以选型可以是：Python 负责 AI 能力层和快速实验，例如 RAG pipeline、模型调用、评测脚本；Go 负责高并发服务层，例如 API 网关、限流、任务队列、流式转发和服务治理。两者通过 HTTP/gRPC/消息队列衔接。

## 什么是python的全局解释器锁GIL？

GIL 是 CPython 的全局解释器锁，保证同一时刻只有一个线程执行 Python 字节码。

影响：

1. CPU 密集多线程无法吃满多核。
2. I/O 时会释放 GIL，所以 I/O 多线程仍有效。
3. 许多 C 扩展（NumPy、加密、压缩）在内部计算时会主动释放 GIL。

```python
# CPU 密集：用进程
from concurrent.futures import ProcessPoolExecutor

def heavy(n):
    return sum(i * i for i in range(n))

if __name__ == "__main__":
    with ProcessPoolExecutor(4) as ex:
        list(ex.map(heavy, [10**6] * 4))
```

新进展：3.13+ 提供 free-threaded 构建（实验/逐步生产可用），但 C 扩展兼容性仍需评估。
