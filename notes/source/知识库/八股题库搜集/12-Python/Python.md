## 对象、名称绑定与可变性

常见问法：Python参数按值还是按引用传递；可变和不可变对象有什么区别。

Python 的名称绑定到对象，传参把对象引用作为参数绑定的基础。函数内把参数名重新绑定到新对象，不会自动改动调用方的名称；如果参数指向可变对象，对该对象执行原地修改，其他引用却可能看到变化。

因此“Python一律值传递”或“一律引用传递”容易遮住具体行为。判断例子时依次看：是否还是同一个对象、操作是重新绑定还是原地修改、是否还有别名共享它。不可变容器也可以包含可变对象，容器自身元素引用关系不变，不代表被引用对象的内容永远不变。

参考资料：[规范或原始文档校核](https://docs.python.org/3/reference/datamodel.html)。

## 身份、相等与哈希约定

常见问法：is和双等号有什么区别；可变对象为什么通常不能作为字典键。

is 比较对象身份，== 请求对象按其相等语义比较值，两者不能因为某些小整数或字符串复用现象就混为一谈。判断是否为 None 常用 is None，因为这里关心的是特定的单例对象。

哈希容器依赖相等与哈希值的契约：相等对象应有一致的哈希值，并且作为键使用期间相关哈希语义应稳定。许多可变内建容器不可哈希；自定义对象是否可哈希则取决于其协议实现。只实现一个看似可用的 __hash__，却让参与相等的字段不断改变，会破坏字典查找的前提。

参考资料：[wolverinn/Waking-Up：双等于和 is 有什么区别？](https://github.com/wolverinn/Waking-Up/blob/cf692b53e1b3d1b740a97dab0e4e71db801daf33/Python%20Handbook.md#L133)；[规范或原始文档校核](https://docs.python.org/3/reference/datamodel.html#object.__hash__)。

## 浅拷贝、深拷贝与共享子对象

常见问法：浅拷贝为什么仍会互相影响；deepcopy能否保证所有对象完全独立。

浅拷贝建立新的外层容器，但其中的元素仍可引用原有子对象；深拷贝尝试递归复制对象图，并用记忆机制处理共享关系与循环引用。因此浅拷贝后修改嵌套列表可能被另一侧看到，重新给外层元素赋值则是另一种操作。

深拷贝不是对任意外部资源都能产生独立副本：文件、锁、网络连接以及自定义对象可能不支持或自定义复制语义。先明确哪些状态需要共享、哪些需要隔离，通常比盲目 deepcopy 整个大型结构更清楚且更经济。

参考资料：[wolverinn/Waking-Up：什么是深拷贝和浅拷贝？](https://github.com/wolverinn/Waking-Up/blob/cf692b53e1b3d1b740a97dab0e4e71db801daf33/Python%20Handbook.md#L126)。

## 默认参数与闭包绑定

常见问法：默认可变参数有什么陷阱；循环里的lambda为什么可能拿到相同值。

函数的默认参数对象通常在定义函数时求值，不会在每次调用时自动重建。因此以列表作为默认值并在函数内修改它，可能让后续调用共享此前状态。需要每次新建时，通常用 None 等标记再在调用期间构造对象。

闭包保存对外层绑定的访问关系，循环中创建的多个函数可能在执行时读到同一绑定的后来值。若要保存每次迭代的值，应明确建立该次绑定或按需使用默认参数捕获。二者都应从求值时机和对象共享关系解释，而不是只背某段代码的输出。

参考资料：[规范或原始文档校核](https://docs.python.org/3/faq/programming.html)。

## 迭代器、生成器与惰性计算

常见问法：iterable和iterator有什么区别；yield怎样保存执行状态。

可迭代对象能产生迭代器，迭代器逐步给出元素并在结束时报告停止；生成器让函数在 yield 处暂停，把局部执行状态保存到后续恢复。惰性生成可避免一次构造整个结果，适合流式处理和大规模顺序消费。

惰性也意味着计算、异常和资源占用发生在消费阶段，而不一定在创建阶段。迭代器通常会被消耗，不能假定遍历一次后还能从头再来；生成器持有的文件或其他资源也应有明确关闭路径。省内存不等于免费，状态管理和逐项调用仍有开销。

参考资料：[wolverinn/Waking-Up：什么是 Python 生成器？](https://github.com/wolverinn/Waking-Up/blob/cf692b53e1b3d1b740a97dab0e4e71db801daf33/Python%20Handbook.md#L19)。

## 装饰器与上下文管理器

常见问法：装饰器解决什么问题；with如何确保资源释放。

装饰器在定义阶段把函数或类交给另一个可调用对象处理，常用于统一增加日志、权限检查或缓存等行为。包装函数需要考虑参数、返回值、异常和元数据，不能因为多包一层就悄悄改变被装饰接口的契约。

上下文管理器把进入与退出一段操作的行为显式绑定，with 在相应退出路径调用清理协议，适合文件、锁和事务边界。退出方法也可以按规则抑制异常，因此不能笼统认为 with 内的异常必然原样抛出。两者共同作用是把横切行为放到明确边界，而不是把控制流程隐藏得越深越好。

参考资料：[规范或原始文档校核](https://docs.python.org/3/reference/datamodel.html#context-managers)。

## 描述符、属性查找与类实例状态

常见问法：类变量和实例变量怎样区分；property为什么能拦截属性访问。

实例通常有自己的属性状态，类也保存供实例共享或查找的属性。读取属性会按类型与描述符等规则查找，给实例同名属性赋值可能遮蔽类属性，但并不会自动修改全部实例共享的那个类属性。

描述符通过 __get__、__set__ 等协议参与属性访问，property、方法绑定等行为都可从该机制理解。类属性若保存可变容器，多个实例可能共享并修改同一容器；需要每实例独立状态时应在实例初始化中建立。讨论属性行为时需区分查找、遮蔽和对共享对象的原地修改。

参考资料：[规范或原始文档校核](https://docs.python.org/3/reference/datamodel.html#implementing-descriptors)。

## CPython引用计数与循环回收

常见问法：Python怎样管理内存；引用计数为什么还需要循环垃圾回收。

CPython 的常见内存管理结合引用计数与循环垃圾回收等机制。引用计数帮助在引用消失时回收对象，循环对象却可能彼此维持非零计数，因此还需识别不可达的循环结构。其他 Python 实现不必采用相同机制。

内存对象被回收不保证进程占用立即下降，分配器可能保留已取得的内存用于后续复用；外部资源也应明确关闭，不能单靠等待垃圾回收。排查增长时应区分活对象、缓存、循环引用与分配器保留，观察长期趋势和引用路径。

参考资料：[规范或原始文档校核](https://docs.python.org/3/library/gc.html)。

## GIL、线程与构建差异

常见问法：GIL是否让Python线程安全；Python线程一定不能并行吗。

传统启用 GIL 的 CPython 构建在执行相关 Python 代码时有解释器级协调约束，这会限制多线程执行 CPU 密集 Python 字节码的并行度；线程在 I/O 等待或某些扩展释放 GIL 时仍可有用。

GIL 不等于业务状态线程安全，跨多步的检查再修改仍可能需要锁。也不能把上述行为推广到所有 Python 实现和所有 CPython 构建：自由线程构建及扩展兼容性需要按实际版本与构建方式确认。选线程、进程或其他并行方案时，应结合任务是否受 GIL、I/O、扩展代码和数据传输开销限制。

参考资料：[wolverinn/Waking-Up：GIL的设计初衷?](https://github.com/wolverinn/Waking-Up/blob/cf692b53e1b3d1b740a97dab0e4e71db801daf33/Python%20Handbook.md#L76)；[规范或原始文档校核](https://docs.python.org/3/howto/free-threading-python.html)。

## asyncio、线程池与CPU任务

常见问法：async和await为什么不会自动并行；协程里直接调用阻塞函数有什么影响。

asyncio 通过事件循环与可暂停任务组织协作式并发：一个任务等待可让出的操作时，循环可以推进其他任务。把函数写成 async 并不会自动把其中的 CPU 计算或阻塞系统调用变成并行或非阻塞操作。

若在事件循环线程中长时间计算或调用阻塞库，其他任务可能一起停滞。可按任务性质选择异步接口、线程池或进程池，并设置取消、超时和资源上限。取消通常在相应协作点传播，任务仍需正确处理清理，不能假定超时后所有下游工作都已被强行停止。

参考资料：[规范或原始文档校核](https://docs.python.org/3/library/asyncio.html)。

## 异常、生成器退出与清理

常见问法：finally什么时候执行；异常处理怎样保留真实失败原因。

异常把失败沿调用链传播到能够处理的位置，处理器应只捕获自己能解释或恢复的错误范围。finally 适合无论正常还是异常退出都需要执行的清理，但其中再次返回或抛出可能覆盖原有结果或异常，导致根因丢失。

记录日志、转换异常和释放资源应协调，避免同一个异常被多层重复打印却没有额外信息。生成器、异步任务和外部终止有各自的关闭边界，不能把正常语言级栈展开当成对断电、强制终止也成立的保证。资源清理应优先使用明确的上下文管理协议。

参考资料：[规范或原始文档校核](https://docs.python.org/3/reference/compound_stmts.html#the-try-statement)。
