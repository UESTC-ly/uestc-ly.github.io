# C++ 工程诊断专题

C++ 服务的运维问题往往跨越源代码、编译器、链接器、运行库、操作系统和生产负载。本组按“先保证产物一致，再让问题可诊断，最后建立性能防线”的顺序学习。

## 推荐顺序

1. [编译环境和 ABI 兼容](01-编译环境与二进制接口兼容.md)
2. [Debug/Release 差异与 Sanitizer](02-构建模式与运行时检测.md)
3. [Core Dump 定位崩溃](03-核心转储与崩溃分析.md)
4. [CPU 火焰图](04-处理器火焰图.md)
5. [内存泄漏和性能回归](05-内存泄漏与性能回归.md)

## 建议保留的构建产物

- 源码提交、构建配置、编译器及链接器版本。
- 依赖锁定信息、编译命令数据库 `compile_commands.json`。
- 可执行文件、共享库、未剥离符号文件及制品校验和。
- 容器镜像摘要、系统库/运行库信息。
- 性能基线、基准输入、原始 profile 与测试环境清单。
