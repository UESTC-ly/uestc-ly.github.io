# Redis 系统学习笔记

这组笔记用于从零开始系统学习 Redis，并逐步过渡到生产实践、性能优化和高可用架构。内容以 Redis 7.x 的通用能力为主，兼顾常见历史术语和版本差异。

## 推荐学习顺序

1. [[01-Redis概览与环境准备]]：理解 Redis 是什么、适用场景、安装与基础 CLI。
2. [[02-数据类型与核心命令]]：掌握 String、Hash、List、Set、ZSet、Stream 等核心数据结构。
3. [[03-持久化机制RDB-AOF]]：理解 RDB、AOF、混合持久化与数据恢复边界。
4. [[04-内存模型与淘汰策略]]：理解 Redis 内存使用、对象编码、过期删除与 maxmemory 策略。
5. [[05-事务Lua与管道]]：学习 MULTI/EXEC、Lua 脚本、Pipeline 的原子性与性能边界。
6. [[06-发布订阅Stream与消息队列]]：比较 Pub/Sub、List 队列、Stream 消费组与消息队列实践。
7. [[07-复制哨兵与高可用]]：理解主从复制、Sentinel、故障转移与高可用运维。
8. [[08-Cluster分片与扩展]]：掌握 Redis Cluster、槽位、分片、扩缩容与多 key 限制。
9. [[09-性能优化与监控]]：建立延迟、吞吐、慢查询、大 key、热 key、监控指标体系。
10. [[10-生产实践故障排查与学习路线]]：沉淀生产检查清单、典型故障排查路径与后续学习路线。

## 学习方法

- 先跑通本地 Redis，再阅读命令示例。
- 每章至少完成“实践检查清单”。
- 将命令、配置和现象对应起来：不要只背命令，要理解它解决什么问题、引入什么风险。
- 学到高可用与 Cluster 后，建议用 Docker 或本机多端口搭建小型实验环境。

## 生产使用底线

- Redis 默认不是无限容量数据库，必须设计 key、TTL、内存上限和淘汰策略。
- 持久化不等于零丢失，RPO/RTO 需要按业务目标验证。
- 高可用不等于强一致，复制延迟、故障转移窗口和客户端重试都要纳入设计。
- 性能优化先测量再调整，优先排查慢命令、大 key、热 key、网络 RTT、持久化抖动。
