# 质量门禁清单

## 证据原则

勾选项必须附路径、命令、报告或外部证据。未检查写 `pending`，不适用写明理由。
章节作者不能是该章唯一 reviewer。任何失败项未关闭时不得标记 `complete`。

## 技术门禁

- [ ] 核心概念、算法和术语准确，重要假设与限制已说明。
- [ ] 可变事实登记版本、核查日期和一手来源。
- [ ] 论文结论、官方 Benchmark、自行实验与工程经验明确区分。
- [ ] 没有虚构 API、功能、性能、引用或数据。
- [ ] 不声称 RAG 消除幻觉或穷尽所有技术。
- [ ] Advanced RAG 使用六维标签并消除术语歧义。
- [ ] 技术选型绑定具体场景、约束和替代方案。

## 教学门禁

- [ ] 目标读者、必须已会、难度、用时和学习结果明确。
- [ ] 首次出现术语在正文定义，未解释缩写没有提前出现。
- [ ] 抽象概念有具体例子，关键误区有反例或失败路径。
- [ ] 不存在隐藏前置、难度突增或依赖循环。
- [ ] 图表解决真实教学问题并有阅读说明。
- [ ] 读者能通过自测、实验或设计题检查结果。
- [ ] Windows PowerShell 与 macOS/Linux 差异已覆盖或链接。

## 代码门禁

- [ ] 路径、导入、Python 版本、依赖和配置一致。
- [ ] 安装、启动、输入、预期输出、测试、常见错误说明完整。
- [ ] 无硬编码密钥；外部服务有离线、Mock 或内存替代。
- [ ] 输入验证、超时、异常、资源释放和日志符合规范。
- [ ] 知识库文本不作为系统指令，权限和租户边界贯穿全链路。
- [ ] 单元、边界、错误、集成和冒烟测试按风险覆盖。
- [ ] 验证状态与真实执行证据一致。

## 编辑门禁

- [ ] Markdown、标题层级、表格、代码围栏和相对链接正确。
- [ ] 文件名、chapter-id、导航和术语一致。
- [ ] 文件、图、代码、摘要和审查已登记到 Manifest。
- [ ] 主解释章节唯一，交叉引用代替重复长解释。
- [ ] 每个目录有 README 或索引。
- [ ] Mermaid 状态没有把静态检查冒充渲染通过。

## 章节完成记录

每章在对应报告中记录：作者、四类 reviewer、日期、发现、修复提交、复核结果、
验证命令、已知限制和 Manifest 状态。四类检查可由不同批次完成，但缺一项时不得
标记 `complete`。
