# 内容清单

本文件记录仓库中已经存在的交付文件。计划中的章节以 `PROJECT_PLAN.md` 为
权威目录，在实际创建的同一批次加入本清单，避免把“计划”误报成“已存在”。
`.gitignore`、`AGENTS.md` 与 `.omx/` 下的运行时/编排上下文属于内部控制文件，不
作为教程内容登记；它们仍受 Git 状态和能力审计约束。

## 状态与证据

- 内容状态：`planned`、`drafting`、`reviewing`、`verified`、`complete`。
- 验证状态：`unverified`、`static-checked`、`unit-passed`、
  `integration-passed`、`external-verified`。
- 审查状态分别记录技术、代码、初学者和编辑结论；`n/a` 只用于确实不适用的
  情况，不能替代未完成。
- `complete` 要求所有适用门禁都有证据路径；仅创建文件不得标记 complete。

## 字段

每个后续章节或代码项目必须提供：路径、chapter-id、显示名称、内容类型、主线或
选修、难度、预计用时、负责人、状态、requirement-id、前置能力、外部服务或费用、
离线替代、图表、代码、摘要路径、验证状态、四类审查状态、上/下一章。

## 更新规则

1. 文件创建、改名、删除、状态变化必须在同一批次更新本清单。
2. requirement-id 必须存在于 `ACCEPTANCE_MATRIX.md`。
3. 任何 `verified` 或 `complete` 状态必须能定位到报告、命令或外部证据。
4. 作者不能把自己的章节标记为四类审查全部通过。
5. Manifest 检查失败时禁止开始下一批章节。
