完成本章后，你应该能够：

- 解释文档结构为什么能改善块的可理解性；
- 区分结构感知切分与递归切分；
- 设计从强边界到弱边界的分隔符优先级；
- 识别解析错误、标题丢失和跨权限合并等工程风险。

## 长度相同，结构可能完全不同

下面两段内容都可能只有几十个字：

> 适用范围：标准商品。

> 不适用范围：定制商品、已使用商品。

如果只按长度合并，它们可能与上一个“换货政策”标题放在一起。文本本身仍通顺，检索结果却
失去了所属章节。结构感知切分（structure-aware chunking）会利用标题、段落、列表、表格、
代码块等作者或文件格式提供的边界，先回答“这段属于哪里”，再决定“它是否太长”。

## 结构感知切分是什么

结构感知方法先从解析结果获取文档节点。例如 Markdown 可以有一级标题、二级标题、段落、
有序列表和代码围栏；HTML 可以有标题元素、段落、列表、表格和主内容区域；办公文档也可能
保留标题样式与段落层级。

一个实用块不一定对应单个节点。短标题通常需要与后续正文组合，多个连续列表项也可能需要
保留共同的引导句。关键是组合时不要跨越强边界，例如不同一级章节、不同表格，或不同权限
区域。

每个块可以保存一条标题路径：

```text
售后手册 > 退货政策 > 不适用范围
```

查询结果即使只显示正文，也能利用这条路径解释上下文。标题路径应作为元数据或受控前缀
保存，不能靠生成模型猜测。

## 递归切分是什么

递归切分（recursive splitting）按一组从强到弱的候选边界逐层处理超长内容。这里的“递归”
描述处理策略，不要求读者现在实现递归函数。

一套面向普通 Markdown 的示例优先级可以是：

1. 一级或二级章节边界；
2. 段落空行；
3. 列表项或句子边界；
4. 标点边界；
5. 固定词元或字符边界。

算法先尝试最强边界。如果一个章节仍超过硬上限，就在该章节内部尝试段落；某个段落仍过长，
再尝试句子。固定长度留在最后兜底。这样既有长度上限，又尽量减少不自然断点。

“递归”不等于“结构感知”。只对纯文本依次尝试空行、句号和空格，也属于递归切分；真正的
结构感知还需要知道某行是标题、代码或表格，而不只把它当成普通分隔符。两者经常组合使用。

## 一个逐层切分例子

假设“退货政策”章节包含三个小节：适用范围、不适用范围和申请步骤。目标是每块不超过当前
实验设定的预算。

1. 先把“退货政策”与下一个同级章节“维修政策”分开；
2. 若退货章节过长，再按三个小节分开；
3. 给每个小节块附上完整标题路径；
4. 若“申请步骤”仍过长，按步骤列表组合，而不是从步骤文字中间剪断；
5. 仅当单个步骤超限时，才在步骤内部按句子降级。

这套规则保留了业务结构，但仍需用真实查询验证。例如用户问“退货的全部步骤”时，多个小块
可能需要共同进入上下文；结构保存良好不代表召回一定完整。

## 合并短节点时要看什么

结构解析常产生很短的节点，例如单独标题、图片说明或只有一个词的列表项。不能简单地把所有
短节点向后合并。合并前至少检查：

- 节点是否属于同一标题路径；
- 内容类型是否兼容，例如正文与代码说明可以组合，两个独立表格通常不应混合；
- 权限、来源版本和语言是否一致；
- 合并后是否超过硬上限；
- 引导句与其列表、图片说明与图片引用是否仍相邻；
- 原文偏移是否仍能准确映射。

不同权限的节点即使相邻也不应合并，否则一个块无法获得清晰的访问控制标签。

## 解析器会制造假结构

结构感知方法依赖上游解析质量。PDF 常只有视觉布局，没有可靠的语义节点：字号较大的页眉
可能被误判为标题，每一行可能被误判为段落，多栏文本还可能交错。HTML 页面则可能混入导航、
页脚、隐藏文本和广告区域。

因此应保存并抽查“原始文件 -> 解析节点 -> 文本块”的映射。对下列异常设置可观察记录：

- 文档没有任何标题却突然产生几十级目录；
- 同一页的文本顺序与视觉阅读顺序不一致；
- 代码围栏未闭合，后续正文全部被标为代码；
- 列表编号消失，步骤顺序不可恢复；
- 表格单元被串成无法对应表头的长行。

发现异常时可以采用更保守的纯文本策略，并标记解析质量，而不是假装结构准确。

## 分隔符顺序不是通用常量

中文说明文档可优先空行和中文句末标点；源代码需要优先语言语法节点；聊天记录需要优先会话
和发言轮次。即使同为 Markdown，技术 API 文档与会议纪要也可能使用不同规则。

分隔符列表、解析器版本和合并策略都应进入索引配置。若配置变化，应能识别需要重建的块。
否则新旧切分结果混在同一索引中，实验和问题复现都会失去依据。

## 工程与安全边界

标题和目录可能包含用户输入，不能因为它们被解析为“结构”就获得更高可信度。恶意文档可以
伪造“系统消息”标题；这些内容仍然只是检索数据。解析器还可能遇到压缩炸弹、异常嵌套或超大
节点，实际系统需要文件大小、解析时间、节点数量和深度限制。

结构合并不能突破权限边界。调试记录也不应无条件保存完整敏感块；优先记录标识、长度、规则、
哈希或经过授权的摘录，并遵守项目的数据保留要求。

## 纸面练习

为下面的 Markdown 片段写出边界优先级：

```text
\# 售后手册
## 退货政策
适用范围说明……

### 申请步骤
1. 提交订单号
2. 上传凭证

## 维修政策
维修范围说明……
```

标出哪些节点应继承标题路径，哪条边界绝不能跨越，以及“申请步骤”过长时的下一层规则。再写
一个反例：如果解析器把 `## 维修政策` 当成普通正文，会产生什么错误。
