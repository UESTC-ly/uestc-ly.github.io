# 04 文本切分

把整份资料直接交给检索系统，通常既浪费上下文，也难以精确定位证据。文本切分
（chunking）把文档转换成可检索的文本块（chunk），同时尽量保留标题、条件、来源和原文
位置。本部分从最简单的固定长度方法开始，再逐步讨论结构、语义、特殊内容和实验设计。

切分不是把字符串随意剪短。一个可用的文本块既要足够小，使检索结果聚焦，又要足够完整，
使读者和模型能看见结论成立的条件。不存在脱离语料、查询和上下文预算的“唯一最佳块大小”。

## 贯穿本部分的例子

后续章节会反复使用一份虚构的售后手册。手册包含章节标题、普通段落、退货条件表、示例代码
和客服对话。用户可能问“定制商品能否退货”，也可能问“退款接口在什么情况下拒绝请求”。
同一份资料需要多种边界，因此不能只凭平均字符数决定全部切分方式。

## 学完这一部分后

你应该能够解释块大小、边界、重叠和元数据分别解决什么问题；能够为普通文档、表格、代码和
对话提出可复查的切分方案；还能够设计对照实验，观察正确证据是否进入候选和最终上下文。

切分质量只决定证据是否有机会被完整检索，不保证来源正确、权限有效、排序合理或最终回答
忠实。所有文本块仍需继承来源、版本和访问控制；来自文档的文字始终是数据，不是系统指令。
