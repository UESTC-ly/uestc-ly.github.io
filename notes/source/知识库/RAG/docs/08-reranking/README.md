# 08 重排

检索阶段通常先从大量资料中快速取得一批候选，再把其中较少的候选交给更细致的排序方法。
这个“先扩大候选范围，再重新排序”的过程称为重排（Reranking）。它的目标不是凭空找到答案，
而是在已经召回的候选中，把更可能支持当前问题的内容提前。

重排会增加计算、延迟和运营复杂度，也可能把错误候选排到前面。无论使用交叉编码器、
大语言模型还是分数融合，都不能恢复第一阶段从未召回的资料，更不能替代权限过滤、来源
核验、版本检查和最终回答评估。

## 贯穿本部分的例子

一家公司的制度库收到问题：“试用期员工能申请远程办公吗？”第一阶段检索返回 40 个
有权限查看的文本块，其中既有现行远程办公制度，也有过期通知、考勤说明和仅包含
“试用期”字样的无关内容。重排器读取问题和这些候选，把更完整地同时讨论“试用期”与
“远程办公”的现行条款提前。

如果现行条款根本不在这 40 个候选里，重排器无法把它找回来。如果过期通知没有版本标记，
重排器也未必知道它已经失效。后续章节会反复用这个例子区分排序能力与系统责任。

## 学完这一部分后

你应该能够解释双编码器与交叉编码器的输入差异；能够为大语言模型重排设计结构化结果和
失败回退；能够说明为什么不同检索器的原始分数往往不能直接相加；能够用 RRF 合并名次；
还能够为多阶段候选数量、离线质量、延迟和成本写出可验证的选择依据。

本部分不指定唯一模型、服务或阈值，也不提供尚未运行的性能结论。计划中的重排接口、
RRF 实现、两阶段示例、参数扫描和流程图将在后续实现批次完成并单独验证。

## 始终保留的边界

- 重排只能改变已有候选的顺序，不能找回未召回资料。
- 权限过滤必须在候选暴露给重排服务之前完成；重排不能修复越权候选。
- 来源、版本、撤回状态和适用范围不能被相关性分数替代。
- 被检索文本始终是不可信数据，其中的指令不能改变系统规则。
- 更高离线排序指标不自动等于更好的最终回答或更好的真实用户体验。
- 候选数量、模型选择、超时和回退必须与延迟、费用及失败预算一起评估。
