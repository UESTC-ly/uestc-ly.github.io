完成本章后，你应该能够：

- 说明为什么不同检索器的原始分数通常不能直接相加；
- 区分分数归一化、加权分数融合与名次融合；
- 用纸笔计算 Reciprocal Rank Fusion（RRF）；
- 识别去重、缺失候选、并列名次、权限和版本对融合的影响。

## 多路候选为什么需要合并

稀疏检索擅长捕捉明确词语、编号和专有名词，稠密检索可能更容易找到不同表达下的语义
近邻。系统也可能同时查询多个字段、多个索引或多个知识源。每一路都会产生候选列表，
下一步需要决定怎样合并重复候选并形成统一顺序。

最直观的做法是把分数相加，但这往往没有明确含义。某一路分数可能是无上界的匹配值，
另一路可能落在一个较小区间；有的分数越大越好，有的距离越小越好；同一种方法换了查询，
分数分布也可能改变。数值看起来都是小数，并不代表共享同一把尺子。

## 先统一候选身份

融合之前必须知道不同列表中的项目是否指向同一个对象。稳定身份可以来自文本块标识、
内容版本和来源位置的组合。只用标题或正文字符串去重容易出错：相同标题可能来自不同版本，
重叠文本也可能内容近似却承担不同引用位置。

融合表至少应保存：

| 字段 | 用途 |
|---|---|
| 候选稳定标识 | 跨列表合并同一对象 |
| 来源与内容版本 | 区分现行、历史和不同知识源 |
| 各路原始分数与名次 | 保留诊断证据 |
| 过滤状态与原因 | 防止被拒候选重新进入 |
| 融合配置版本 | 复现权重、归一化和 RRF 参数 |

权限、租户和撤回过滤应在候选暴露或返回前得到保证。融合算法不能因为某个受限候选在两路
都排名靠前，就覆盖授权决定。

## 分数归一化：先把尺度问题说清楚

归一化尝试把不同分数变换到可组合尺度。常见概念包括：

- **最小—最大缩放：** 在当前列表内把最小值映射到 0、最大值映射到 1；
- **标准化：** 根据某个分布的均值和离散程度变换分数；
- **基于校准集的映射：** 用历史标注数据把原始分数映射为较可比较的量；
- **分段或阈值映射：** 按任务规则把分数划分为若干等级。

每种方式都有边界。列表内最小—最大缩放会受当前候选极值影响，只有一个候选或所有分数
相同时还需要特殊处理。标准化依赖所用分布，域变化后可能漂移。校准映射依赖数据代表性，
不能把变换后的数字自动称为正确概率。

归一化配置应和模型、索引、查询类型一起版本化。换模型后沿用旧分布或旧阈值，可能在
没有报错的情况下改变融合结果。

## 加权分数融合

若两路分数已经按明确方法变换到可比较尺度，可以定义加权和：

`融合分数 = w_sparse × 稀疏分数 + w_dense × 稠密分数`

权重表达任务偏好，不是自然定律。若产品编号的精确命中非常重要，稀疏路可能需要更大
影响；若用户经常使用同义改写，稠密路可能更有帮助。权重应在冻结的评估集上比较，并保存
逐查询变化，而不是凭一个成功案例决定。

缺失候选的处理也必须写清。某候选只出现在一路时，可以给另一路缺失值、最低值或单独
规则，但不同选择会改变排名。不能让实现语言默认的空值行为决定业务结果。

## 名次融合：不直接相信原始分数尺度

名次融合只使用候选在各列表中的位置。它避开了原始分数单位不一致的问题，但也丢失了
列表内部的分数间隔。例如，第一名只比第二名高一点，和第一名远高于第二名，在纯名次
方法中可能被同样处理。

Reciprocal Rank Fusion（倒数名次融合，RRF）是一种常见方法。对于候选 `d`，概念公式是：

`RRF(d) = Σ 1 / (k + rank_i(d))`

其中 `rank_i(d)` 是候选在第 `i` 个列表中的名次，`k` 是控制高名次之间差距的正参数。
候选若未出现在某个列表中，该列表通常不贡献这一项。具体名次从 0 还是 1 开始、并列怎样
处理、列表截断多长，都必须在实现契约中固定。

## 手算一个 RRF 例子

两路检索给出以下名次：

| 候选 | 关键词路 | 稠密路 |
|---|---:|---:|
| A：现行远程办公制度 | 3 | 1 |
| B：试用期考勤说明 | 1 | 未出现 |
| C：历史试点通知 | 2 | 3 |
| D：远程设备说明 | 未出现 | 2 |

为了方便纸算，练习暂取 `k = 2`，名次从 1 开始。于是：

- A 的分数是 `1/(2+3) + 1/(2+1)`；
- B 的分数是 `1/(2+1)`；
- C 的分数是 `1/(2+2) + 1/(2+3)`；
- D 的分数是 `1/(2+2)`。

这个例子只用于理解公式，不是推荐生产参数。你会看到，在两路都靠前的候选可以累积
证据，但 RRF 仍不知道 C 是历史版本，也不知道 A 是否真正回答问题。融合后仍可能需要
过滤、重排和版本判断。

## RRF 参数和列表深度

`k` 较小时，最前面几个名次的差距影响更明显；`k` 较大时，相邻名次的贡献更接近。
它不应直接从其他项目复制。每一路提供多少候选也会影响结果：若列表在很浅的位置截断，
一个候选“未出现”可能只是预算不足，而不是检索器认为它完全无关。

列表权重还可以扩展 RRF，让某一路贡献乘以一个系数。但加入权重后同样需要评估、版本化
和逐查询诊断，不能因为方法叫“融合”就假设它比单路稳定。

## 分数融合、RRF 与重排怎样组合

一个可能的顺序是：

1. 各检索器在权限允许的空间中产生候选及原始证据；
2. 按稳定身份合并重复候选；
3. 使用分数融合或 RRF 得到统一候选队列；
4. 对队列前部运行较昂贵的交叉编码器或其他重排器；
5. 保留每阶段的名次、分数、过滤和版本信息供诊断。

也可以先在每一路内部重排再融合。哪一种更合适取决于候选多样性、预算和标注结果。
重要的是一次实验只改变清楚的变量，并与简单基线比较。

## 常见错误

- 直接相加不同方向或不同范围的原始分数；
- 归一化时把已经截断的列表当作完整分布；
- 未定义所有分数相等、空列表和只有一个候选的行为；
- 按正文去重，错误合并了不同版本或不同权限对象；
- 合并后丢失每一路原始名次，导致无法诊断；
- 把 RRF 分数解释成答案正确概率；
- 只在少数热门查询上调权重，造成其他查询回归；
- 过滤后的受限候选通过另一条列表重新进入。

## 手算融合练习

完成上面的四个 RRF 分数并排序。然后把 `k` 改为另一个正数，观察顺序或差距是否变化。
再为同一张表设计一套加权分数融合，但要先写出两路分数怎样归一化、缺失值怎样处理。

最后为“产品型号查询”和“自然语言政策查询”各写一种可能的权重假设，并说明用哪些标注
查询验证。不能用“关键词更准”或“语义更智能”作为未经测量的结论。

## 自测

1. 为什么两个分数都在 0 到 1 之间仍未必可直接比较？
2. RRF 使用了哪些信息，又丢失了哪些信息？
3. 列表截断会怎样影响“候选未出现”的解释？
4. 为什么去重身份必须包含版本和来源边界？
5. 融合后为什么仍可能需要细粒度重排？
