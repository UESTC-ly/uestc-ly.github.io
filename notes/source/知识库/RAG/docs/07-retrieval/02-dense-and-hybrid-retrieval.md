# 07-02 稠密检索与混合检索

完成本章后，你应该能够区分稠密检索（dense retrieval）和稀疏检索的信号来源，解释
混合检索（hybrid retrieval）为何组合两路候选，并设计不依赖原始分数可比性的排名合并。

## 语义接近不要求字面相同

稠密检索会把查询和文本块映射到稠密向量，再按约定的相似度寻找邻近候选。查询“收到货
以后最晚多久能退”和文档“标准商品签收后 30 天内可申请退货”字面不同，但合适的表示
可能让它们靠近。这可以缓解同义表达、口语和改写造成的词汇不匹配。

然而，语义模型也可能把主题相近但条件不同的文本放在一起。例如“个人账户退款”和
“企业账户退款”很接近，却可能适用不同政策。稠密相似度不是事实校验、权限校验或最终
相关性判断。

## 两类信号各自擅长什么

| 情况 | 稀疏信号通常更直接 | 稠密信号可能更有帮助 |
|---|---|---|
| 错误码、型号、条款号 | 精确词项具有高区分度 | 模型可能弱化罕见字符串 |
| 同义表达、口语问题 | 可能因词汇不匹配漏召回 | 可按语义邻近召回 |
| 否定、数值、限定条件 | 能观察具体词项是否出现 | 可能把主题相近内容排高 |
| 新领域术语 | 词项出现即可匹配 | 模型未适应该领域时可能漂移 |

这张表不是胜负结论。同一方法会随语言、模型、分词、切分、索引参数和语料变化。可靠做法
是保留两类可解释信号，并用代表性查询验证。

## 混合检索的基本流程

一个常见流程是：

1. 对原查询分别运行稀疏检索和稠密检索；
2. 每一路取一个受控数量的候选；
3. 按稳定文档或文本块标识去重；
4. 用排名或经过校准的分数融合；
5. 应用权限和有效范围约束；
6. 把候选及其召回路径交给后续重排或上下文选择。

候选记录应说明它来自哪一路、原始排名和分数是什么、是否被另一条路径重复召回。否则
混合之后只剩一个总分，排障时无法知道哪条信号真正起作用。

## 原始分数通常不能直接相加

BM25 分数和向量相似度来自不同定义，范围也可能随索引和查询改变。直接写成
`0.5 × BM25 + 0.5 × cosine` 看似平衡，实际上可能被量纲较大的那一路支配。

更稳妥的起点是基于排名的融合，例如让每一路排名靠前的候选获得较高贡献，而不是假设
原始分数天然可比。也可以在有标注数据时做分数归一化或校准，但必须记录方法、数据范围和
版本。后续 08-03 会进一步讨论分数融合与倒数排名融合。

## 候选预算不是越大越好

增加每一路 Top-K 可能提高召回机会，也会增加去重、过滤、重排和生成阶段的延迟与成本，
还可能把更多噪声送入后续步骤。候选预算应围绕“关键资料是否进入候选集”设置，而不是追求
一个孤立的大 K。

例如，稀疏路径负责保住错误码和精确名称，稠密路径负责补充口语改写。若评估显示精确查询
已稳定命中，就不必为它无限扩大稠密候选。

## 一个失败对比例子

查询：“不要关闭双重验证，怎样更换手机？”

- 稀疏检索可能命中包含“双重验证”和“更换手机”的操作说明；
- 稠密检索可能召回“关闭双重验证”的相近主题；
- 如果预处理删除“不要”，两路都可能忽略否定条件；
- 混合检索若只按主题分数合并，错误说明仍可能排在前面。

因此，混合不是自动正确。它只能增加和重组候选信号，仍需要保留否定条件、权限过滤、
重排与最终证据核对。

## 评估时分组看问题

把查询至少分成精确标识、同义改写、多条件、短查询、长问题和领域新词等组。分别观察每组
的相关候选是否进入 Top-K、首个相关候选位置以及两路贡献。若只看全体平均值，某一类用户
的严重漏召回可能被其他容易查询掩盖。

评估还要固定文档快照、嵌入版本、索引版本、过滤条件和融合配置。否则两次结果变化时无法
判断是策略改变还是数据改变。

## 实践与自测

给定稀疏排名 `A, B, C` 和稠密排名 `C, D, A`，手工设计一种只依赖名次的合并。记录每个
候选的来源，并说明为什么不能直接比较两个系统的原始分数。

1. 稠密检索能缓解什么类型的词汇不匹配？
2. 为什么错误码查询可能更适合保留稀疏路径？
3. 混合检索为什么不能保证相关候选一定排在首位？
4. 调大两路 Top-K 会带来哪些代价？
