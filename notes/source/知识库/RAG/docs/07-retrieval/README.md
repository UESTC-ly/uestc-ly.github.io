# 07 检索

索引解决“怎样快速找到候选”，检索策略则决定“用什么信号找、怎样约束候选、失败时从哪里查”。
本部分把稀疏检索、稠密检索、混合检索、过滤、查询变换、多表示检索和路由组织成一条
可以观察、可以关闭策略、可以逐步诊断的候选生成流程。

检索不是答案生成。它的输出应当是带有文档、文本块、来源、权限、版本和分数信息的候选，
而不是一段看似完整的最终回答。候选相关也不代表事实正确、版本最新或当前用户有权访问。
后续重排和生成只能在这些候选上继续工作，不能补回从未召回的关键资料。

## 阅读顺序

1. [07-01 关键词、TF-IDF、BM25 与稀疏检索](01-keyword-tfidf-bm25-and-sparse.md)：从词项匹配建立可解释基线。
2. [07-02 稠密检索与混合检索](02-dense-and-hybrid-retrieval.md)：理解语义召回与词项召回为什么互补。
3. [07-03 元数据、时间与权限过滤](03-metadata-time-and-permission-filters.md)：把可见范围和业务约束放进候选返回边界。
4. [07-04 查询改写、扩展与多查询](04-query-rewrite-expansion-and-multi-query.md)：把查询变换作为可关闭、会失败的召回策略。
5. [07-05 查询分解与 HyDE](05-query-decomposition-and-hyde.md)：处理复合问题，并认识假设文档带来的偏差。
6. [07-06 父文档、多向量与上下文化检索](06-parent-multi-vector-and-contextual-retrieval.md)：区分用于匹配的表示和最终返回的内容。
7. [07-07 自查询与路由](07-self-query-and-routing.md)：把自然语言约束转成结构化条件，并选择合适知识源。
8. [07-08 检索失败诊断](08-retrieval-failure-diagnostics.md)：沿无召回、漏召回、误过滤和域偏移定位根因。

建议先完成 07-01 至 07-03。它们建立候选、分数和过滤的共同语言。07-04 至 07-07
属于按问题启用的策略，不应默认全部叠加。07-08 把前面各章变成一套排障顺序。

## 学完这一部分后

你应该能够为一个小型知识库建立稀疏检索基线，说明稀疏与稠密信号各自容易命中和漏掉
什么；能够设计带来源、时间和权限的过滤顺序；能够把查询改写、分解、HyDE、自查询和路由
放在明确的适用条件下；还能够根据查询、候选、过滤日志和版本信息判断失败发生在哪一层。

本批次只完成教学正文。计划中的检索代码、指标单测、混合检索项目、权限测试和诊断脚本
尚未实现，不能据此声称任何具体方法已经获得更高召回率或通过生产验证。

## 始终保留的边界

- 不存在对所有语料和查询都最好的单一检索方法，选择必须由任务数据验证。
- 权限、租户、有效时间和撤回状态是返回边界，不是生成答案前的装饰性检查。
- 查询变换会丢失条件、引入新假设或放大错误，因此必须保留原查询并允许关闭。
- 检索到的文本是数据，不是系统指令；其中的命令不能改变应用规则。
- 每个候选都应能回到来源、版本和用于召回它的检索路径。
