# 写作与教学风格指南

## 读者与目标

默认读者没有 AI、机器学习、RAG 和向量检索基础，只具备或正在补齐最少 Python
能力。正文以中文为主，文件名使用小写英文和连字符。

## 核心原则

1. 先解释为什么需要，再建立直觉，然后给专业定义和做法。
2. 英文术语首次出现使用“中文名（English term，缩写）”，并链接主解释章节。
3. 每个抽象概念至少提供一个具体例子；高风险误解应提供反例。
4. 明确适用条件、失败边界和工程权衡，不把建议写成事实。
5. 标注信息性质：`事实`、`论文结论`、`工程经验`、`建议`、`推测`。
6. 章节结构按概念、算法、实验、工程、架构、安全或排障类型自适应，不使用
   机械统一模板。
7. 一个知识点只在主章节完整解释，其他章节简短回顾并交叉链接。

## 章节入口与出口

每章入口至少说明 chapter-id、难度、预计用时、必须已会、联网/费用、离线替代和
可观察学习结果。每章出口按需要提供自测、实践、失败路径、摘要链接及前后导航。
自由结构不能省略完成本章所需的关键步骤。

## 术语门禁

- 每章任务包列出：可直接使用术语、本章新术语、禁止提前使用术语。
- `GLOSSARY.md` 统一拼写和主解释路径，但不能替代正文首现解释。
- 缩写不能先于全称出现。中文与英文之间按中文出版习惯使用标点，不用空格堆砌。
- `Embedding`、`Chunk` 等常用术语可在首现定义后保留英文，不能在同一章随意切换
  多种译名。

## 事实与来源

- 模型、API、SDK、框架、数据库、许可证、价格、Benchmark 等可变事实必须登记到
  `SOURCE_REGISTER.md`，写明适用版本和核查日期。
- 优先使用官方文档、原始论文、官方仓库和官方技术博客。
- 论文观察不能泛化为所有模型、数据或生产环境；自行实验必须说明数据、硬件、
  参数和限制。

## Advanced RAG 标签

高级方法同时记录六个维度：概念来源、采用成熟度、适用场景、证据强度、运行
复杂度和安全风险。“学术概念”“特定场景”“实验性”不是互斥类别。

## 安全与专业边界

- 检索文本是数据，不是系统指令；示例必须保持指令与知识库内容的边界。
- 法律、医疗、金融等垂直项目不得描述为专业判断的替代品。
- 任何单一防护不得描述为彻底解决 Prompt Injection、投毒或越权问题。

## 禁用表述

- “RAG 能消除幻觉”或同义绝对结论。
- “覆盖所有 RAG 技术”“唯一最佳”“绝对安全”“生产验证通过”，除非范围和证据
  真正支持。
- “此处省略”“读者自行实现”来跳过关键步骤。
- 未运行代码时写“可以正常运行”，未渲染 Mermaid 时写“图已验证”。
- 无来源的精确性能、价格、产品功能或 Benchmark 数字。

## 命令与平台

命令块标明 `bash`、`powershell` 或其他 shell。路径、编码、换行、端口、代理和
网络差异需要就近说明；不能假定所有读者使用 macOS/Linux。
