完成本章后，你应该能够：

## 核心概念

- 容器的结构语义：list 表示有序可重复序列，tuple 表示固定结构，dict 表示键值映射，set 表示唯一元素集合。
- 对象关系语义：赋值通常共享引用；可变性、哈希性和拷贝深度决定对象能否安全共享、缓存或作为键。
- 算法直觉：列表适合顺序访问，字典和集合适合平均常数时间查找；数据规模和访问模式决定选择。
- Agent 边界：消息轨迹和运行状态需要明确的修改权限、复制边界和序列化规则。

## 1. 先建立对象与引用模型

Python 变量更像“贴在对象上的标签”。执行 `b = a` 时，通常只是让两个名字指向同一个对象，而不是复制对象。

```python
tasks = ["检索", "总结"]
alias = tasks
alias.append("回答")

print(tasks)             # ['检索', '总结', '回答']
print(tasks is alias)    # True：两个名字指向同一个列表对象

snapshot = tasks.copy()
snapshot.append("发送")
print(tasks)             # ['检索', '总结', '回答']
print(snapshot)          # ['检索', '总结', '回答', '发送']
print(tasks is snapshot) # False
```

`is` 判断是否为同一个对象，`==` 判断内容是否相等。业务代码应使用 `==` 比较值；`is` 通常只用于 `None`、单例或确实需要身份判断的场景：`value is None`。

### 名称、身份、相等与哈希

一句话直觉：名字只是引用，身份回答“是不是同一个对象”，相等回答“值是否相同”，哈希则为字典和集合提供快速定位。四者有关联，但不能混为一谈。

- `id(obj)` 在对象存活期间标识其身份；同一个对象的 `id` 不变，但对象销毁后这个整数可能被复用。
- `a is b` 不调用用户定义的比较逻辑，只比较身份；`a == b` 通常会调用 `a.__eq__(b)`，必要时再尝试反向比较。
- 可哈希对象必须在生命周期内保持哈希值稳定，并满足“相等对象哈希相等”。因此可变容器通常不可哈希。
- 字符串和小整数的驻留（interning）是实现优化，不能用来推断业务身份；不要写 `status is "ok"` 这类代码。

```python
class Value:
    def __init__(self, number: int) -> None:
        self.number = number

    def __eq__(self, other: object) -> bool:
        return isinstance(other, Value) and self.number == other.number


left = Value(1)
right = Value(1)
print(left == right)  # True：值相等
print(left is right)  # False：是两个实例

try:
    hash(left)
except TypeError as exc:
    print(type(exc).__name__)  # TypeError：定义 __eq__ 后默认不可哈希

missing = object()  # 每次创建都是独一无二的身份哨兵
value = None
print(value is None)  # True：推荐用 is 判断 None
print(value is missing)  # False
```

这个示例中，`Value.__eq__` 只表达值比较，没有承诺对象可作为缓存键。若确实需要可哈希值对象，应让它不可变（例如使用冻结的 `dataclass`），或自行实现稳定的 `__hash__`，并确保参与比较的字段不会改变。哈希表先按哈希值定位，再用相等比较确认，所以“哈希相等”不代表“对象相等”。

### 引用图与生命周期

容器不是把值“装进盒子”后与外界隔离，而是保存对其他对象的引用；嵌套列表、字典和 Agent 消息因此形成对象图。`del name` 只删除一个名字，不一定销毁对象；当没有可达引用时，CPython 通常会通过引用计数回收，循环引用则由垃圾回收器处理。引用计数是 CPython 实现细节，不应作为业务逻辑或资源释放机制。

真正需要关闭的文件、网络连接和锁，应使用上下文管理器；不要用“对象大概会被回收”代替显式清理。把这条原则带到 Agent 中，就是把状态容器和外部资源分开：状态可复制、可序列化，资源由 `with` 或 `async with` 管理。

### 可变与不可变

- 可变对象：列表、字典、集合，以及大多数自定义类实例；创建后可在原对象上修改。
- 不可变对象：整数、浮点数、布尔值、字符串、元组、`frozenset` 等；看起来像“修改”的操作实际上会返回新对象。
- 元组本身不可变，但其中可以放入可变对象，所以“元组完全深度不可变”是错误的。

```python
name = "agent"
old_id = id(name)
name += "-v1"
print(name)                 # agent-v1
print(old_id == id(name))   # False：字符串拼接产生新字符串

config = ("gpt", ["search"])
config[1].append("calculator")
print(config)               # ('gpt', ['search', 'calculator'])
```

在 Agent 中，外层消息常用列表，单条消息常用字典；如果一条消息需要作为缓存键或放进集合，必须将其规范化为只包含可哈希值的元组，或明确设计一个不可变数据结构。

“不可变”通常只描述对象自身的结构不能被原地改变，并不意味着引用永远不能指向别处，也不保证嵌套对象不可变。例如 `name += "-v1"` 是创建新字符串并让 `name` 重新绑定；而 `config[1].append(...)` 修改的是元组引用到的列表。

### 可变性与默认值的设计边界

函数参数、类属性和 Agent 状态都可能因为共享可变对象而产生跨请求污染。初始化函数里优先接收 `None` 再创建新容器；需要共享的只读配置则可以用元组、`MappingProxyType` 或明确的不可变模型。

```python
from types import MappingProxyType


def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    current = [] if tags is None else list(tags)
    current.append(tag)
    return current


first = add_tag("search")
second = add_tag("browser")
print(first)   # ['search']
print(second)  # ['browser']：两次调用不共享默认列表

base_config = {"timeout": 30}
read_only_config = MappingProxyType(base_config)
try:
    read_only_config["timeout"] = 10
except TypeError as exc:
    print(type(exc).__name__)  # TypeError：代理不允许通过此视图写入
base_config["timeout"] = 10
print(read_only_config["timeout"])  # 10：代理仍反映底层映射的变化
```

`MappingProxyType` 是只读视图而不是深度冻结：底层字典仍可被持有它的代码改变，嵌套值也未自动冻结。若边界需要真正不可变且可校验的结构，应该在边界处复制并使用合适的模型，而不是把代理当作安全沙箱。

## 2. 列表 `list`

列表是有序、可重复、可变的序列，适合表示“按顺序处理的一批对象”。索引从 `0` 开始，负索引从末尾开始。

### 创建、索引和切片

```python
steps = ["理解问题", "调用工具", "整理证据", "输出答案"]

print(steps[0])       # 理解问题
print(steps[-1])      # 输出答案
print(steps[1:3])     # ['调用工具', '整理证据']，左闭右开
print(steps[:2])      # 前两个元素
print(steps[::2])     # ['理解问题', '整理证据']，步长为 2
print(steps[::-1])    # 反向副本

steps[1] = "调用检索工具"
del steps[3]
steps.extend(["校验引用", "输出答案"])
print(steps)
```

切片产生一个新的列表；`steps[1:3]` 不会改变原列表。切片赋值却会修改原列表，并且允许替换不同长度的片段：

```python
items = ["a", "b", "c", "d"]
items[1:3] = ["B", "C", "C2"]
print(items)  # ['a', 'B', 'C', 'C2', 'd']
```

### 序列协议与常用增删查改

一句话直觉：`list` 是保存对象引用的可变动态数组；索引读取快，任意位置插入或删除要移动后续引用。它实现了序列协议，因此可以被 `len`、`in`、索引、切片和 `for` 统一使用。

- 读取：`items[i]`、`items[-1]`；越界抛 `IndexError`。
- 切片：`items[start:stop:step]` 左闭右开，结果是新列表；`step` 不能为 0。
- 追加：`append(x)` 加一个元素，`extend(iterable)` 逐个加入；二者都原地修改并返回 `None`。
- 删除：`pop(i)` 删除并返回元素，`remove(x)` 删除第一个相等项，`del items[i]` 只删除不返回，`clear()` 清空。
- 查询：`x in items` 线性扫描；`index(x)` 找首个位置，找不到抛 `ValueError`；`count(x)` 统计相等项。
- 复制：`items.copy()` 或 `items[:]` 只复制外层；它们不是深拷贝。

```python
events = ["start"]
events.append(["tool_call", "search"])  # 一个列表作为单个元素
events.extend(["tool_result", "finish"])  # 迭代加入两个字符串

print(events)
print(events[1][0])           # tool_call：嵌套索引
print(events[-2:])            # ['tool_result', 'finish']：新列表切片

last = events.pop()
print(last, events)
try:
    events.remove("missing")
except ValueError as exc:
    print(type(exc).__name__)  # ValueError：remove 找不到目标
```

这里 `append` 和 `extend` 的差异尤其容易影响 Agent 事件轨迹：一次工具调用通常应作为一个事件对象追加；若误用 `extend(event_dict)`，字典会被按键迭代，轨迹结构就会损坏。方法的返回值也要注意：原地方法通常返回 `None`，不要写 `events = events.append(...)`。

列表底层会预留一部分容量，尾部 `append` 在多数情况下是摊销 O(1)；扩容时会分配新数组并复制引用。这个实现细节解释了“多数时候快”，但不应依赖精确容量或内存布局。

### 常用方法与排序

```python
scores = [0.8, 0.3, 0.95]
scores.append(0.6)          # 尾部添加一个元素
scores.extend([0.7, 0.4])   # 尾部添加多个元素
scores.insert(0, 1.0)       # 指定位置插入；中间插入可能较慢
removed = scores.pop()      # 默认弹出末尾元素并返回它
scores.remove(0.3)          # 删除第一个等于 0.3 的元素
scores.sort(reverse=True)   # 原地排序，返回 None

print(removed)              # 0.4
print(scores)               # [1.0, 0.95, 0.8, 0.7, 0.6]
print(sorted(scores, key=lambda score: -score))
```

`list.sort()` 原地修改并返回 `None`；`sorted()` 接受任意可迭代对象并返回新列表。实际项目中，优先使用有含义的 `key`，不要依赖复杂的多次排序副作用。

排序使用 TimSort，并且是稳定排序：两个元素的 `key` 相同时，原来的相对顺序保留。`key` 函数对每个元素调用一次；用它代替在比较过程中反复计算通常更清晰、更快。

```python
records = [
    {"name": "A", "priority": 1, "arrival": 2},
    {"name": "B", "priority": 1, "arrival": 1},
    {"name": "C", "priority": 2, "arrival": 3},
]
ordered = sorted(records, key=lambda item: (-item["priority"], item["arrival"]))
print([item["name"] for item in ordered])  # ['C', 'B', 'A']

same_priority = sorted(records, key=lambda item: item["priority"])
print([item["name"] for item in same_priority])  # ['A', 'B', 'C']：稳定保留 A 在 B 前
```

若数据已经有序并且只需要插入一个元素，可考虑 `bisect`，避免每次重新排序；若要持续取出最高优先级任务，则 `heapq` 比“列表排序后弹出”更合适。两者都不替代对任务状态的显式去重和幂等校验。

### 易踩坑：重复初始化嵌套列表

```python
wrong = [[]] * 3
wrong[0].append("共享")
print(wrong)  # [['共享'], ['共享'], ['共享']]

right = [[] for _ in range(3)]
right[0].append("独立")
print(right)  # [['独立'], [], []]
```

`[[]] * 3` 复制的是同一个内层列表的引用；推导式才会为每次循环创建新列表。

## 3. 元组 `tuple`

元组是有序、可重复、不可变的序列，适合表示“结构固定的一条记录”，例如坐标、工具调用结果的固定字段或字典键。

```python
tool_result = ("search", 3, True)
name, count, ok = tool_result
print(name, count, ok)  # search 3 True

single = ("only",)      # 单元素元组必须有逗号
not_tuple = ("only")
print(type(single).__name__)     # tuple
print(type(not_tuple).__name__)  # str

cache_key = ("weather", "Shanghai", "celsius")
cache = {cache_key: "晴，27°C"}
print(cache[cache_key])           # 晴，27°C
```

元组能作为字典键的前提是其所有成员都可哈希。`("user", [1, 2])` 不能作为键，因为列表不可哈希。

### 命名元组：轻量记录

```python
from collections import namedtuple

Token = namedtuple("Token", ["text", "kind"])
token = Token("Python", "keyword")
print(token.text, token.kind)  # Python keyword
```

在新代码中，如果记录字段较多、需要验证或默认值，通常优先考虑 `dataclass` 或 Pydantic 模型；`namedtuple` 适合轻量、低依赖的不可变记录。

### 打包、解包与不可变记录

元组字面量的关键不是括号，而是逗号：`point = 1, 2` 与 `point = (1, 2)` 都会打包成元组。函数多返回值实际上也是打包，再由调用方解包。解包数量必须匹配，除非使用一个带 `*` 的目标收集剩余项。

```python
def split_tool_result() -> tuple[str, int, str]:
    return "search", 200, "ok"


name, status, message = split_tool_result()
print(name, status, message)  # search 200 ok

head, *body, tail = ("system", "user", "tool", "assistant")
print(head, body, tail)  # system ['user', 'tool'] assistant

try:
    first, second = (1, 2, 3)
except ValueError as exc:
    print(type(exc).__name__)  # ValueError：没有使用星号目标
```

元组拼接、切片和重复都会创建新元组；它适合小型固定结构，不适合频繁原地追加。若字段需要按名称读取，`namedtuple` 可提供轻量属性访问；若需要可读的默认值、校验、可变更新或序列化契约，`dataclass`/Pydantic 更合适。元组只保证外层不可变，放进其中的列表仍能变，也因此可能无法哈希。

在 Agent 中，可把“模型名、版本、温度”这类不会在一次调用中变化的缓存键表示成元组；把对外返回的消息记录表示成裸元组则可读性偏弱，通常应该使用带字段名的模型。

## 4. 字典 `dict`

字典是“键到值”的可变映射。Python 3.7+ 语言规范保证遍历顺序与插入顺序一致，但不要把它误解为按键排序。

### 创建与取值

```python
message = {
    "role": "user",
    "content": "帮我总结这段文本",
    "metadata": {"request_id": "req-001"},
}

print(message["role"])                    # user
print(message.get("tool_name"))           # None：缺失时不抛异常
print(message.get("tool_name", "none"))   # none

message["metadata"]["source"] = "chat"
message.setdefault("tags", []).append("summarize")
print(message["tags"])                    # ['summarize']

for key, value in message.items():
    print(f"{key}={value!r}")
```

`d[key]` 适合“缺失就是程序错误”的必填字段；`get` 适合可选字段。`setdefault` 会在缺失时插入默认值，但默认表达式会在调用前求值，复杂默认值不要滥用。

### 映射协议、更新与缺省值

一句话直觉：字典是通过哈希键定位值的可变映射；`key in data` 检查的是键，不是值。它实现映射协议，除了字面量外，也可以用 `collections.abc.Mapping` 只读地接收各种映射实现。

- `data[key]`：键必须存在，缺失抛 `KeyError`；适合必填字段。
- `data.get(key, default)`：缺失时返回默认值，不会写入字典；适合可选字段。
- `data[key] = value` / `update(other)`：新增或覆盖；`update` 接受映射或键值对可迭代对象。
- `pop(key[, default])`、`popitem()`、`clear()`：删除并可取回值；`popitem` 在现代 Python 中取最后插入项。
- `setdefault(key, default)`：存在时返回旧值，缺失时插入并返回默认值；默认表达式会先求值。
- `defaultdict(factory)`：读取不存在的键时按需创建值，适合分组/计数，但读取也可能改变数据。

```python
from collections import defaultdict

events = [
    {"tool": "search", "status": "ok"},
    {"tool": "search", "status": "error"},
    {"tool": "browser", "status": "ok"},
]

counts: dict[str, int] = {}
for event in events:
    tool = event["tool"]
    counts[tool] = counts.get(tool, 0) + 1
print(counts)  # {'search': 2, 'browser': 1}

grouped: defaultdict[str, list[str]] = defaultdict(list)
for event in events:
    grouped[event["status"]].append(event["tool"])
print(dict(grouped))  # {'ok': ['search', 'browser'], 'error': ['search']}

removed = counts.pop("browser")
print(removed, counts)  # 1 {'search': 2}
```

`defaultdict` 的“缺失即创建”很方便，但在只读检查或拼写错误场景可能悄悄产生新键；Agent 的输入校验通常更适合普通字典加显式错误。对于纯计数还可考虑 `collections.Counter`，它表达意图更清晰。

### 合并、解包与字典视图

```python
base = {"temperature": 0.2, "timeout": 30}
override = {"timeout": 10, "model": "gpt"}
merged = base | override       # Python 3.9+；右侧同名键覆盖左侧
base |= {"retries": 2}         # 原地合并

request = {"messages": [], **merged}
print(request)
print(list(merged.keys()))
```

`keys()`、`values()`、`items()` 返回动态视图；在遍历字典时直接增删键会触发 `RuntimeError`。若需要修改，先复制键列表：`for key in list(data): ...`。

字典的键必须可哈希且相等性稳定，常用键是字符串、整数、元组。可变列表、字典、集合不能作为键。

### 合并策略与动态视图

`left | right` 和 `{**left, **right}` 都返回新字典，右侧值覆盖左侧同名键；`left |= right` 原地更新左侧。这个“最后写入者覆盖”规则适合分层配置，但不等于递归合并：嵌套字典会整体替换。

```python
base = {"model": "small", "limits": {"tokens": 1000}}
override = {"limits": {"tokens": 2000}}
merged = base | override
print(merged)  # {'model': 'small', 'limits': {'tokens': 2000}}
print(base)    # {'model': 'small', 'limits': {'tokens': 1000}}：| 不修改左侧

data = {"a": 1, "b": 2}
keys = data.keys()  # 动态视图，不是创建时的静态列表
data["c"] = 3
print(list(keys))  # ['a', 'b', 'c']

for key in list(data):  # 先复制键，允许在循环中删除
    if key == "b":
        del data[key]
print(data)  # {'a': 1, 'c': 3}
```

字典视图会反映后续变化，`keys`/`items` 在一定条件下还支持集合运算；若需要稳定快照，显式调用 `list(...)` 或 `dict(...)`。遍历期间改变字典大小会抛 `RuntimeError`，即使某些“只改值不改键”的操作看起来能工作，也应保持代码简单、避免依赖细节。

API 边界若只需要读取，可把参数标注为 `Mapping[str, object]`，这样调用方可以传入普通字典或其他映射；若函数要修改，就明确标注/接收 `MutableMapping`，并记录副作用。

## 5. 集合 `set` 与 `frozenset`

集合是无序（不应依赖显示顺序）、不重复、可变的元素集合；底层哈希结构使成员测试通常很快。`frozenset` 是不可变集合，可以作为字典键或另一个集合的元素。

```python
requested = {"search", "calculator", "search"}
available = {"search", "browser", "calculator"}

print(requested)                    # {'search', 'calculator'}，顺序不作保证
print("search" in requested)        # True
print(requested & available)        # 交集：共同支持的工具
print(requested - available)        # 差集：不可用工具
print(requested | available)        # 并集
print(requested <= available)       # 是否为子集

immutable = frozenset({"read", "write"})
permissions = {immutable: "文件权限集合"}
print(permissions[immutable])
```

集合元素也必须可哈希，因此不能直接放入列表或字典。对于 Agent 的“去重工具名、已访问 URL、已处理消息 ID”，集合通常比列表更直接；如果需要稳定输出，去重后再排序或保留原顺序（见下方示例）。

### 哈希集合的操作与边界

集合用元素的哈希值定位槽位，再用相等比较确认是否已存在，所以 `add`、`in`、`remove` 通常是平均 O(1)。这是平均复杂度而不是排序保证；集合显示顺序不属于业务契约，跨进程运行还可能受哈希随机化影响。

- `add(x)` 加入一个元素，重复加入没有额外效果；`update(iterable)` 批量加入。
- `remove(x)` 不存在时抛 `KeyError`；`discard(x)` 不存在时静默忽略，清理不确定输入时更安全。
- `pop()` 删除并返回某个元素，但不要把它当作“第一个”；`clear()` 清空。
- `&`、`|`、`-`、`^` 表示交集、并集、差集、对称差；`issubset`/`<=` 和 `issuperset`/`>=` 比较包含关系。

```python
allowed = {"search", "browser"}
requested = {"search", "search", "calculator"}
print(requested & allowed)  # {'search'}

requested.add("calculator")  # 重复 add 不增加元素
requested.discard("missing")  # 不抛异常
try:
    requested.remove("missing")
except KeyError as exc:
    print(type(exc).__name__)  # KeyError

print(requested >= {"search"})  # True：requested 是超集
```

集合元素必须可哈希，但“可哈希”不等于“业务上适合去重”：两个不同格式的 URL 可能语义等价，却仍会被视为不同字符串。Agent 去重前要先规范化大小写、尾斜杠或事件 ID，并在需要稳定展示时使用 `sorted` 或稳定去重列表。

## 6. 推导式：简洁但要保持可读

列表、集合、字典和生成器都有推导式。推导式适合“一次映射 + 可读过滤”，不适合塞入多个副作用或三层嵌套逻辑。

```python
raw_tools = [" search ", "", "browser", "search"]

clean_tools = [name.strip() for name in raw_tools if name.strip()]
unique_tools = {name.strip() for name in raw_tools if name.strip()}
tool_lengths = {name: len(name) for name in unique_tools}

print(clean_tools)    # ['search', 'browser', 'search']
print(unique_tools)   # {'search', 'browser'}，顺序不保证
print(tool_lengths)   # {'search': 6, 'browser': 7}，键顺序不应作为逻辑依据

# 保留首次出现顺序的去重：dict 的键保持插入顺序
stable_unique = list(dict.fromkeys(clean_tools))
print(stable_unique)  # ['search', 'browser']
```

如果推导式需要在同一表达式中重复调用昂贵函数，先用普通循环保存中间结果；可读性和可观测性通常比少写一行更重要。

### 求值顺序、作用域与惰性

一句话直觉：推导式把“遍历、变换、过滤”压缩成一个表达式；它仍按从左到右、外层到内层的顺序求值。列表/集合/字典推导式会立即创建结果，生成器表达式只在迭代时计算。

推导式的循环变量在 Python 3 中有独立的隐式作用域，不会覆盖外层同名变量；但推导式里的函数调用、对象属性修改等副作用仍然会发生。赋值表达式（`:=`）为了让结果在外层可用有特殊规则，初学时应慎用，复杂逻辑直接写普通循环更易调试。

```python
items = [1, 2, 3]
n = "outer"
squares = [item * item for item in items]
print(squares, n)  # [1, 4, 9] outer：item 没有泄漏到外层

rows = [(row, col) for row in range(2) for col in range(2)]
print(rows)  # [(0, 0), (0, 1), (1, 0), (1, 1)]：外层循环先变化

mapping = {word: len(word) for word in ["ai", "agent", "ai"]}
print(mapping)  # {'ai': 2, 'agent': 5}：重复键由最后一次写入覆盖

lazy = (item * 2 for item in range(3))
print(next(lazy))  # 0：此时才计算第一个值
print(list(lazy))  # [2, 4]：生成器已消耗一个元素
```

生成器表达式适合把大批工具结果串成流水线，避免一次性把全部结果放进内存；它是一次性的，若需要多次遍历应保存数据或重新创建表达式。推导式中不要隐藏网络请求、写日志、修改全局状态等副作用，否则重读代码时很难判断执行时机。

## 7. 解包与结构化数据流转

```python
first, *middle, last = ["system", "user", "assistant", "tool"]
print(first)   # system
print(middle)  # ['user', 'assistant']
print(last)    # tool

defaults = {"timeout": 30, "retries": 2}
user_config = {"timeout": 10}
final_config = {**defaults, **user_config}
print(final_config)  # {'timeout': 10, 'retries': 2}

def run_tool(name: str, *, timeout: int, retries: int) -> str:
    return f"{name}: timeout={timeout}, retries={retries}"

print(run_tool("search", **final_config))
```

星号解包能表达“保留剩余元素”，双星号解包能组合映射。对于工具调用参数，使用关键字参数和 `**payload` 能减少参数位置错位；但仍要先验证外部输入，不要让任意用户字段无检查地传入敏感函数。

### 星号解包的规则与边界

序列解包要求可迭代对象；普通目标数量必须精确匹配。一个解包目标可以带一个 `*`，它总是接收一个新建的列表（即使只剩一个或零个元素），并且同一层不能出现两个星号目标。映射解包要求键是字符串且不能出现重复关键字，后者会在函数调用时抛 `TypeError`。

```python
tools = ["search", "browser", "calculator"]
first, *rest = tools
print(first, rest)  # search ['browser', 'calculator']

def call_tool(name: str, *, timeout: int, trace_id: str) -> str:
    return f"{name}:{timeout}:{trace_id}"

payload = {"timeout": 10, "trace_id": "t-1"}
print(call_tool("search", **payload))  # search:10:t-1

try:
    call_tool("search", **{"timeout": 10, "trace_id": "t-1", "debug": True})
except TypeError as exc:
    print(type(exc).__name__)  # TypeError：未知关键字不能越过函数签名
```

解包只负责结构展开，不负责信任边界校验。来自模型或用户的工具参数仍应先做 schema 校验、白名单过滤和权限检查；不要因为写成 `**payload` 就把任意键传进高权限函数。需要合并配置时，先用字典合并得到允许字段，再用关键字专用参数调用。

## 8. 浅拷贝、深拷贝与不可变边界

浅拷贝只复制最外层容器；嵌套对象仍然共享。深拷贝会递归复制（但对锁、连接、生成器等对象并不适用）。

```python
from copy import copy, deepcopy

original = {
    "messages": [{"role": "user", "content": "你好"}],
    "tags": ["new"],
}
shallow = copy(original)
deep = deepcopy(original)

shallow["messages"][0]["content"] = "被浅拷贝修改"
shallow["tags"].append("shallow")
deep["messages"][0]["content"] = "只改深拷贝"

print(original["messages"][0]["content"])        # 被浅拷贝修改
print(original["tags"])                            # ['new', 'shallow']
print(deep["messages"][0]["content"])             # 只改深拷贝
print(original is shallow)                         # False
print(original["messages"] is shallow["messages"]) # True
```

在 Agent 中，常见的错误是为了“试运行一个分支”而浅拷贝整个状态，然后在分支里追加消息，结果主轨迹也被修改。更稳妥的策略是：

- 状态结构简单时，明确复制会被修改的嵌套层：`{**state, "messages": [*state["messages"], new_message]}`。
- 状态复杂且要求隔离时使用 `deepcopy`，并测试其中是否包含不可复制对象。
- 更进一步，使用不可变消息对象或 Pydantic/dataclass 的 `frozen` 设计，把“修改”变成创建新状态。

### copy 协议、循环引用与不可变更新

`copy.copy` 先创建外层对象，再复用内部引用；`copy.deepcopy` 递归复制，并通过备忘录避免同一对象重复复制以及循环引用无限递归。自定义类可以实现 `__copy__`/`__deepcopy__` 控制行为，但文件句柄、锁、套接字、生成器和事件循环等资源通常不应复制。

```python
from copy import deepcopy
from dataclasses import dataclass, replace

graph: list[object] = []
graph.append(graph)  # 循环引用
clone = deepcopy(graph)
print(clone is clone[0])  # True：deepcopy 保留了循环结构

@dataclass(frozen=True)
class AgentState:
    step: int
    status: str


state = AgentState(step=1, status="running")
next_state = replace(state, step=2)
print(state)       # AgentState(step=1, status='running')
print(next_state)  # AgentState(step=2, status='running')
```

深拷贝解决的是 Python 对象图的隔离，不等于安全序列化：它可能保留自定义对象、执行自定义复制逻辑，且成本随图大小增长。跨进程或持久化边界应使用明确 schema（例如 JSON 可表示结构或模型的序列化），并单独处理资源引用、密钥和大对象。

对于 Agent 分支状态，“复制整棵树”常常过贵；可以采用结构共享加局部复制（只复制将要追加的消息列表），或用不可变模型和 `replace` 形成新版本。关键是明确哪些字段是值、哪些字段是外部资源，以及重试时是否需要同一快照。

## 9. 复杂度直觉

下表是对常见操作的平均情况直觉；哈希冲突、扩容和具体实现会影响常数，不应把它当作绝对保证。

| 容器/操作 | 平均复杂度 | 说明 |
| --- | ---: | --- |
| 列表按索引读取 `items[i]` | O(1) | 连续数组定位 |
| 列表尾部 `append/pop()` | O(1) 摊销 | 偶尔扩容，但平均很快 |
| 列表中间插入/删除 | O(n) | 后续元素需要移动 |
| 列表成员测试 `x in items` | O(n) | 从头到尾线性查找 |
| 字典按键读取/写入 | O(1) 平均 | 基于哈希表 |
| 集合成员测试 `x in values` | O(1) 平均 | 基于哈希表 |
| 字典/集合遍历 | O(n) | n 是元素数量 |
| 排序 `sorted(items)` | O(n log n) | TimSort，返回新列表 |

如果 Agent 要频繁判断“某 ID 是否处理过”，使用集合；如果要按 ID 找消息，使用字典；如果要维护顺序队列，使用列表或 `collections.deque`。不要在大列表中反复用 `in` 再线性扫描，必要时预先建立索引。

### 平均复杂度、最坏情况与内存取舍

复杂度是随着元素数量 `n` 增长的尺度，不是一次运行的精确耗时。字典/集合的 O(1) 是平均情况；恶意或极端哈希冲突可能退化，扩容也会产生阶段性的复制成本。列表的 O(n) 扫描在小数据上可能比建立索引更省内存和常数，因此要结合规模、访问频率和生命周期衡量。

| 操作模式 | 常见选择 | 原因与边界 |
| --- | --- | --- |
| 顺序追加、按索引读取 | `list` | 连续存储、索引 O(1)；中间删除需移动元素 |
| 两端反复入队/出队 | `collections.deque` | 两端操作 O(1)；不适合任意位置索引 |
| 已排序序列中插入/查找位置 | `bisect` + `list` | 二分查找位置 O(log n)，真正插入仍需移动 O(n) |
| 持续取优先级最高项 | `heapq` | 原生是最小堆：最小值在堆顶；最大优先级通常存负优先级或包装比较规则。取堆顶 O(1)，插入/弹出 O(log n)，不保证整体有序 |
| 按 ID 高频定位 | `dict` | 平均 O(1)；需考虑键规范化和内存占用 |
| 只判断是否见过 | `set` | 平均 O(1) 成员测试；不提供稳定顺序 |

Agent 任务队列常同时维护多个索引：队列保存处理顺序，字典保存任务详情，集合保存幂等 ID。索引不是“多余复制”，而是用内存换查找时间；完成、取消或过期时必须同步更新，否则会出现幽灵任务。

```python
from collections import deque

pending = deque(["task-1", "task-2"])
details = {"task-1": {"prompt": "查天气"}, "task-2": {"prompt": "总结"}}
finished: set[str] = set()

task_id = pending.popleft()
details[task_id]["attempt"] = 1
finished.add(task_id)
print(task_id, task_id in finished)  # task-1 True

details.pop(task_id)
print(list(pending), details)  # ['task-2'] {'task-2': {'prompt': '总结'}}
```

如果任务状态需要落库或跨进程传输，`deque`、集合和堆的内部结构都不应直接序列化为公共协议；先转换为带版本字段的列表/字典模型。

## 10. 容器选择指南

| 需求 | 推荐 | 原因 |
| --- | --- | --- |
| 有序、允许重复、需要修改 | `list` | 顺序明确，支持索引和追加 |
| 固定结构记录、希望不可变 | `tuple` | 可解包，可作为键（成员可哈希时） |
| 按名称查找字段 | `dict` | 键值映射，平均 O(1) 查找 |
| 去重、交集/差集、快速成员判断 | `set` | 哈希集合语义清晰 |
| 不可变权限集合或集合键 | `frozenset` | 可哈希、不可变 |
| 两端高效进出队列 | `collections.deque` | 左右端操作 O(1) |
| 结构化且需要校验的记录 | `dataclass`/Pydantic | 字段名、默认值和校验更明确 |

一个面向 Agent 的典型状态可以是：

```python
state = {
    "messages": [
        {
            "role": "system",
            "content": "你是一个可靠的助手",
        },
        {"role": "user", "content": "查询订单"},
    ],
    "visited_tool_ids": set(),
    "metadata": {"request_id": "req-001"},
}
```

这里列表表达时序，字典表达字段，集合表达去重状态。若状态需要跨进程、写入数据库或作为 API 输入输出，应进一步转换为可序列化且有 schema 的模型，并避免把集合直接暴露给只支持 JSON 的边界。

### 一个可复用的选型流程

拿到新字段时按四个问题判断：是否有顺序？是否允许重复？是否按键查找？是否需要原地更新？前两问决定序列/集合，第三问决定映射，第四问再决定可变容器或不可变记录。若字段要跨模块传递，还要再问“是否需要 schema、JSON 或哈希键”。

例如：

1. `messages` 是按时间排列且会追加，优先 `list`；如果分支之间共享，改用局部复制或不可变状态更新。
2. `tools_by_name` 需要按名称定位，使用 `dict[str, Tool]`；不要用列表每次线性扫描。
3. `allowed_tools` 只关心包含关系，使用 `set[str]`；需要公开稳定顺序时额外维护排序结果。
4. `cache_key` 必须稳定、可哈希，使用由字符串/数字/元组组成的规范化元组；不要直接把输入字典的字符串表示当键。
5. `message` 需要校验、版本和序列化时，裸 `dict` 适合边界早期，成熟接口应升级为 `dataclass` 或 Pydantic 模型；这不是容器“性能更好”，而是契约更明确。

容器选型没有“永远最快”的答案。列表扫描可能胜过字典索引的构建成本，小型固定记录用元组可能比模型轻，但工具调用边界更看重错误可见性和可观测性。先用访问模式与契约做决定，再用基准测试验证热点。

## 常见坑

1. `a = b` 不是复制；修改可变对象时要先确认是否存在别名。
2. `is` 不用于普通值比较；`x is None` 才是典型写法。
3. `[[0] * 3] * 3` 会共享内层列表；嵌套容器优先用推导式创建。
4. `dict[key]` 缺键会抛 `KeyError`，`get` 缺键返回默认值；不要为掩盖 schema 错误而到处使用 `get`。
5. 字典和集合的顺序不是排序结果；集合不应依赖显示顺序。
6. `list.sort()` 返回 `None`；需要新列表时用 `sorted()`。
7. 遍历字典时增删键会报错；先取 `list(data)` 再修改。
8. 可变对象作为默认参数会跨调用共享：`def f(items=[]): ...` 应改为 `items: list[str] | None = None`，在函数体内初始化。
9. `copy.copy` 只复制一层；Agent 状态含嵌套消息时应明确复制边界。
10. 直接把用户输入拼接到列表或字典并不等于验证；进入工具调用前要检查类型、长度、允许值和权限。

### 容器状态的排错清单

当 Agent 出现“上一轮消息被改写”“重试重复执行”或“输出顺序偶尔变化”时，按顺序检查：

1. 打印对象的 `id` 和关键嵌套字段的 `id`，确认是否存在别名；不要只打印值，因为值相同不代表对象独立。
2. 检查所有分支是否共享 `messages`、`metadata` 或工具参数；浅拷贝只隔离第一层。
3. 检查集合/字典的遍历结果是否被误当作排序结果；对用户可见输出显式排序。
4. 检查缓存键是否包含列表、字典等不可哈希成员，或是否把顺序不同但语义相同的配置视为不同键。
5. 检查状态是否混入连接、锁、生成器等资源；把资源生命周期移到上下文管理器，而不是复制或序列化它们。

排错时优先写一个最小状态对象和断言，再扩大到真实工作流。这样可以把“容器语义错误”与模型输出、网络时序等其他变量分开。

## 面向 AI Agent 的应用提示

- **消息轨迹**：用 `list[dict]` 表达顺序，但不要在多个分支之间共享并原地修改同一列表；分支执行前创建明确的状态副本。
- **工具注册表**：用 `dict[str, Tool]` 按名称索引工具，用 `set[str]` 管理允许调用的工具名；调用前做白名单检查。
- **去重与幂等**：用集合保存已经处理的事件 ID、工具调用 ID 或 URL；需要持久化时转换为列表并排序，避免依赖集合顺序。
- **缓存键**：用由字符串、数字和元组组成的不可变键；不要把可变请求字典直接当键。若要缓存结构化请求，可规范化排序后构造元组。
- **状态快照**：日志和重试通常需要快照。浅拷贝只够复制“不会继续修改的嵌套部分”；涉及消息树时优先设计不可变边界或测试深拷贝。
- **JSON 边界**：JSON 原生支持对象、数组、字符串、数字、布尔和 `null`，不直接支持集合、元组语义或任意 Python 对象；API 输出前要显式转换。

## 练习题

1. 写函数 `deduplicate_preserve_order(items)`，在不改变首次出现顺序的前提下去重，并说明它对不可哈希元素的限制。
2. 给定 `messages: list[dict]`，统计每个 `role` 的消息数，要求缺少 `role` 时给出清晰错误，而不是静默跳过。
3. 实现 `merge_config(defaults, override)`：返回新字典，不修改任一输入；对 `timeout`、`retries` 做非负整数校验。
4. 给出一个会因浅拷贝而污染主 Agent 状态的最小复现，再用“只复制必要层”的方式修复，并写断言证明两个分支互不影响。
5. **综合题**：设计一个待处理任务队列，任务包含 `id`、`prompt`、`priority`。要求支持按 ID 去重、快速判断已完成任务、按优先级取出任务，并解释你选择 `list`、`dict`、`set` 或 `deque` 的原因。可以先实现简单版本，再讨论如何用堆优化取出最高优先级任务。
6. **综合题**：设计一个 Agent 状态快照函数，只保留 `messages`、`tool_calls`、`metadata` 三个字段，并保证调用者修改返回值不会影响原状态。请讨论深拷贝成本、不可序列化对象和更适合生产环境的模型化方案。

### 练习提示与验收标准

- 第 1 题：提示：用一个集合记录已见值，再按原序遍历输入。验收：重复字符串只保留首次出现；对不可哈希输入要么明确报错，要么在题目中定义规范化规则。
- 第 2 题：提示：先用 `message["role"]` 访问必填字段，再决定是否捕获 `KeyError`。验收：缺失字段不会被静默跳过，空输入返回空统计。
- 第 3 题：提示：用新字典合并，再对覆盖后的字段统一验证。验收：两个输入的 `id` 和嵌套值均不因调用而改变；负数、布尔值和非整数被拒绝。
- 第 4 题：提示：先故意只复制外层，再对嵌套列表追加事件。验收：测试能先稳定复现污染，再证明局部复制后的主分支和子分支互不影响。
- 第 5 题：提示：先区分“任务详情索引”“已完成集合”“待处理顺序”，再考虑 `heapq`。验收：重复任务 ID 不会重复入队；取出、完成、取消后所有索引保持一致。
- 第 6 题：提示：先定义允许复制的字段和复制深度，再选择局部复制、`deepcopy` 或不可变模型。验收：修改快照中的任意嵌套消息、调用参数和元数据都不能改动原状态，并说明不能复制资源时的处理策略。

## 小结

列表表达顺序，元组表达固定结构，字典表达映射，集合表达唯一性与集合运算。真正需要掌握的是它们背后的语义：赋值共享引用，可变对象可能被意外修改，哈希性决定能否作为键，复杂度决定循环中的成本。把这些原则应用到消息轨迹、工具注册、缓存键和 Agent 状态中，就能少掉大量难以定位的状态污染和性能问题。
