## 第 1 章：C++ 基本语法

### 1.1 一句话抓本质
C++ 程序本质上就是：**先让编译器知道你要用什么功能，再告诉它从哪里开始执行，最后按语句顺序一步一步运行。**

很多初学者一上来就把注意力放在“语法长得像什么”，但真正要记住的是：
- `#include` 解决“功能从哪里来”
- `main()` 解决“程序从哪里开始”
- `{}` 解决“哪些语句属于一组”
- `;` 解决“一条语句到哪里结束”

如果把程序看成写给编译器的一封结构化说明书，那么这些符号就是说明书的格式规则。

---

### 1.2 最小可运行程序
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, C++!" << endl;
    return 0;
}
```

这个程序虽然短，但已经包含了最核心的骨架。

### 1.3 逐行拆解
#### （1）`#include <iostream>`
作用：引入输入输出库。

如果没有这行，编译器通常就不认识 `cout`、`cin`、`endl` 这些名字。

你可以把它理解成：
> “我接下来要用标准输入输出功能，请提前把工具箱给我。”

#### （2）`using namespace std;`
作用：告诉编译器，后面默认从标准命名空间 `std` 里找名字。

如果不写这句，也能写程序，只是要改成：
```cpp
std::cout << "Hello, C++!" << std::endl;
```

初学阶段常写 `using namespace std;`，代码更短；
但稍微正式一点的项目里，很多人更偏向直接写 `std::cout`，因为更清晰，也能避免名字冲突。

#### （3）`int main()`
作用：主函数，程序入口。

几乎所有基础 C++ 程序都从 `main` 开始执行。`int` 表示这个函数最终要返回一个整数值给操作系统。

#### （4）`{ ... }`
作用：表示一个代码块。

花括号里的语句属于同一个函数或逻辑范围。以后你会在 `if`、`for`、`while`、函数、类中反复见到它。

#### （5）`cout << "Hello, C++!" << endl;`
作用：向屏幕输出一行文字。

可以先粗略理解成：
- `cout`：控制台输出对象
- `<<`：把右边内容送到左边输出流中
- `endl`：换行并刷新缓冲区

#### （6）`return 0;`
作用：告诉系统“程序正常结束”。

很多现代编译器在 `main` 结尾即使不写 `return 0;` 也会默认补上，但初学阶段建议显式写出，逻辑更完整，也更容易形成规范习惯。

---

### 1.4 语句、表达式、代码块
初学时容易把这些词混成一团，最好一开始就区分。

#### 语句（statement）
一条完整执行命令，通常以分号结尾。
```cpp
int a = 10;
cout << a << endl;
```

#### 表达式（expression）
能计算出一个值的部分。
```cpp
3 + 5
x * 2
age > 18
```

#### 代码块（block）
用 `{}` 括起来的一组语句。
```cpp
{
    int x = 1;
    cout << x << endl;
}
```

记忆时可以这样想：
- 表达式像“算一个结果”
- 语句像“做一件事”
- 代码块像“把几件事打包”

---

### 1.5 程序执行顺序
默认情况下，C++ 程序是**自上而下顺序执行**的。

例如：
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "第一句" << endl;
    cout << "第二句" << endl;
    cout << "第三句" << endl;
    return 0;
}
```

输出顺序就是：
```cpp
第一句
第二句
第三句
```

以后虽然会学到条件判断、循环、函数调用，让执行顺序看起来更复杂，但最底层的理解依然是：
> 编译器和 CPU 不会“猜你想干嘛”，它们只会按规则执行你写出来的结构。

---

### 1.6 第一个小练习：输出多项内容
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "姓名：小明" << endl;
    cout << "年龄：18" << endl;
    cout << "成绩：95.5" << endl;
    return 0;
}
```

这个例子看起来简单，但它帮你建立两个意识：
1. 一条输出语句就是一条完整语句
2. 多条语句放在同一个代码块里，程序会顺序执行

---

### 1.7 常见错误与原因
#### 错误 1：漏分号
```cpp
int a = 10
cout << a << endl;
```
原因：C++ 用分号标记语句结束，少了它，编译器无法准确判断边界。

#### 错误 2：花括号不匹配
```cpp
int main() {
    cout << "Hi" << endl;
```
原因：函数开始了却没正常结束。

#### 错误 3：头文件没写
```cpp
using namespace std;
int main() {
    cout << "Hi" << endl;
    return 0;
}
```
原因：`cout` 来自 `<iostream>`，没引入就可能找不到定义。

#### 错误 4：把双引号、单引号混用
```cpp
cout << 'Hello';
```
原因：单引号通常用于单个字符，不适合普通字符串文本。

---

### 1.8 初学者最该养成的语法习惯
- 每写完一条语句，检查一次分号
- 每写完一个 `{`，心里同步记一个 `}`
- 先让程序“能编译”，再让程序“更漂亮”
- 报错时优先检查最近改动的那几行
- 把代码缩进写整齐，肉眼更容易发现结构问题

---

### 1.9 记忆口诀
> **头文件给功能，main 函数是入口；花括号管范围，分号负责收口。**

---

### 1.10 本章易混点
- `#include` 不是普通代码语句，而是预处理指令
- `main` 不是随便起的函数名，它有特殊意义
- `endl` 不只是“换行”，还会刷新输出缓冲
- 能运行不等于写得规范，规范会影响以后调试和协作

---

## 第 2 章：C++ 注释

### 2.1 一句话抓本质
注释是写给“人”看的辅助说明，**不会参与程序执行**。

也就是说，编译器在真正编译代码时，通常会忽略注释内容。注释的主要作用不是让机器看懂，而是让你自己、同学、同事、未来的你更快看懂这段代码在做什么、为什么这么做。

---

### 2.2 两种常见注释方式
#### （1）单行注释
```cpp
// 这是单行注释
int age = 18; // 变量 age 表示年龄
```

适合：
- 一句提醒
- 给当前行补充说明
- 标记待办事项

#### （2）多行注释
```cpp
/*
这是多行注释。
可以写多行说明，
常用于解释一段逻辑。
*/
```

适合：
- 比较长的解释
- 模块说明
- 教学型代码中的补充描述

---

### 2.3 注释到底该写什么
初学者常犯的一个问题是：**把代码翻译一遍当作注释。**

例如：
```cpp
int age = 18; // 定义一个 age 等于 18
```
这种注释不能说错，但价值不大，因为代码本身已经说得很清楚。

更好的注释应该解释：
- 为什么这样写
- 这段代码的目的是什么
- 哪些地方要特别小心
- 后续可能有哪些扩展

例如：
```cpp
int retryCount = 3; // 限制重试次数，避免程序陷入无限重试
```
这类注释才真正有信息量。

---

### 2.4 注释的正确使用场景
#### 场景 1：解释复杂逻辑
```cpp
// 这里先判断输入是否合法，再进入后续计算
if (score >= 0 && score <= 100) {
    cout << "成绩有效" << endl;
}
```

#### 场景 2：标记临时任务
```cpp
// TODO: 后面把这里改成从文件读取
```

#### 场景 3：提醒风险点
```cpp
// 注意：这里不能除以 0，调用前必须保证 count != 0
```

#### 场景 4：教学代码中补充思路
```cpp
// 先声明变量，再从输入中读取值
int x;
cin >> x;
```

---

### 2.5 注释不是越多越好
很多人以为“注释越多越专业”，其实不是。

低质量注释会带来两个问题：
1. **噪音太大**：真正重要的信息被淹没
2. **代码和注释不一致**：以后改了代码，忘了改注释，反而误导读者

例如：
```cpp
int maxSize = 100; // 数组长度是 50
```
这就很危险，因为注释已经变成错的了。

所以要记住：
> **错误的注释比没有注释更可怕。**

---

### 2.6 单行注释和多行注释怎么选
经验上可以这样分：
- 一句就能说清：用 `//`
- 一段背景说明：用 `/* ... */`
- 写教学笔记或函数说明：多行注释更清楚
- 日常代码局部提醒：单行注释更自然

在现代 C++ 代码里，单行注释 `//` 用得通常更多，因为它简洁、直观，也不容易把结束符漏掉。

---

### 2.7 临时“注释掉代码”要谨慎
有时你会这样做：
```cpp
// cout << "调试信息" << endl;
```
或：
```cpp
/*
cout << "A" << endl;
cout << "B" << endl;
*/
```

这在调试时很常见，但别把它当作长期管理方式。原因是：
- 被注释掉的大段旧代码会让文件越来越乱
- 以后回来看，分不清哪些逻辑还有效
- 真正需要历史版本时，应该依赖版本控制工具，而不是把旧代码永久注释在文件里

---

### 2.8 注释与可读代码的关系
优秀代码应当尽量做到：**代码本身就有可读性，注释只补充关键背景。**

例如：
```cpp
int s = 0;
for (int i = 0; i < n; i++) {
    s += arr[i];
}
```

比起写注释说“这里是求和”，更好的方式往往是把变量起名改好：
```cpp
int totalScore = 0;
for (int i = 0; i < studentCount; i++) {
    totalScore += scores[i];
}
```

这说明：
> 有时好的命名比额外注释更重要。

---

### 2.9 常见错误与坑
#### 错误 1：注释和代码不一致
最常见，也最坑人。

#### 错误 2：把废话写成注释
```cpp
int x = 5; // x 等于 5
```
信息量接近 0。

#### 错误 3：多行注释没闭合
```cpp
/* 这是说明
int a = 10;
```
会导致后面大量代码都被错误吞掉。

#### 错误 4：把注释当文档系统
注释适合解释局部背景，不适合承载整篇需求说明、会议记录、长篇流程文档。

---

### 2.10 记忆口诀
> **单行快，多行长；注释讲原因，不讲废话。**

再补一句更实用的：
> **代码写“做什么”，注释写“为什么”。**

## 第 3 章：C++ 数据类型

### 3.1 一句话抓本质
数据类型决定一个值：**能表示什么、怎么存、能做什么运算。**

换句话说，编程里不是“随便放一个值进去”就完事了。编译器要先知道：
- 这是整数还是小数？
- 是一个字符还是一段文本？
- 只有真和假，还是可以取很多数字？

类型就像“容器标签”。标签不同，能装的内容和处理方式就不同。

---

### 3.2 常见基本数据类型
#### （1）`int`
表示整数。
```cpp
int age = 18;
int count = 100;
```
适用场景：年龄、数量、下标、次数等没有小数部分的数据。

#### （2）`float`
表示单精度浮点数。
```cpp
float price = 19.9f;
```
注意：很多时候会在数字后加 `f`，明确告诉编译器它是 `float`。

#### （3）`double`
表示双精度浮点数。
```cpp
double pi = 3.1415926;
```
在实际开发里，`double` 常比 `float` 更常用，因为精度更高。

#### （4）`char`
表示单个字符。
```cpp
char grade = 'A';
char ch = 'x';
```
注意它装的是**单个字符**，不是字符串。

#### （5）`bool`
表示布尔值，只有两个取值：`true` 和 `false`。
```cpp
bool isPassed = true;
bool isEmpty = false;
```
适合：开关状态、条件结果、是否成功等。

#### （6）`void`
表示“没有类型”或“没有返回值”。
```cpp
void showMessage() {
    cout << "Hello" << endl;
}
```
在初学阶段，先把它理解成：
> 这个函数负责做事，但不返回具体结果。

---

### 3.3 为什么必须区分类型
因为不同类型在计算机里的存储方式和使用规则不同。

例如：
- `18` 和 `18.0` 看起来接近，但一个是整数，一个是浮点数
- `'A'` 和 `"A"` 看起来像同一个字母，但前者是字符，后者是字符串
- `true` 不是字符串 `"true"`，也不是整数 1 的字面意义替代

如果类型混淆，你的程序就容易出现：
- 编译报错
- 精度丢失
- 逻辑判断错误
- 输出结果和预期不一致

---

### 3.4 示例：不同类型长什么样
```cpp
#include <iostream>
using namespace std;

int main() {
    int age = 20;
    double height = 175.5;
    char grade = 'A';
    bool isStudent = true;

    cout << age << endl;
    cout << height << endl;
    cout << grade << endl;
    cout << isStudent << endl;

    return 0;
}
```

运行时你会看到：
- 整数按整数形式输出
- 小数按浮点形式输出
- 字符输出字符本身
- `bool` 默认常输出成 `1` 或 `0`

这也提醒你：
> “内部是布尔逻辑”与“显示给用户的形式”不一定完全一样。

---

### 3.5 整数与浮点数的区别
这是最重要的基础区别之一。

#### 整数类型
特点：
- 不带小数点
- 适合计数
- 运算通常更直接

#### 浮点类型
特点：
- 可以表示小数
- 适合测量值、平均值、比例等
- 计算时可能存在精度误差

例如：
```cpp
double a = 0.1 + 0.2;
```
结果在计算机里未必永远“完美等于 0.3”。这不是 C++ 独有问题，而是浮点数表示方式决定的。

所以一个很重要的认知是：
> **浮点数适合表示近似值，不适合要求绝对精确的十进制金额逻辑。**

---

### 3.6 `char` 和字符串不要混
```cpp
char ch = 'A';
```
这是单个字符。

```cpp
string name = "Alice";
```
这是一串字符构成的字符串。

初学者经常写错成：
```cpp
char ch = "A";
```
这通常不对，因为双引号表示字符串字面量，不是单个字符。

记忆方法：
- 单引号 `' '`：一个字符
- 双引号 `" "`：一串文本

---

### 3.7 `bool` 的实际意义
`bool` 虽然只有两个值，但它非常重要，因为程序世界里大量逻辑都能抽象成“是/否”“真/假”“开/关”。

例如：
```cpp
bool hasTicket = true;
bool isLoggedIn = false;
```

以后学 `if`、循环条件、函数返回结果时，你会发现布尔类型几乎无处不在。

可以把它当作程序的“判断信号灯”：
- `true`：可以继续
- `false`：不能继续

---

### 3.8 类型选择的直觉
当你写变量时，可以这样判断：
- 没小数 → 优先考虑 `int`
- 有小数 → 优先考虑 `double`
- 单个字符 → `char`
- 真假状态 → `bool`
- 没有返回值 → `void`

这不是全部规则，但作为入门判断已经很好用。

---

### 3.9 常见坑
#### 坑 1：把字符当字符串
```cpp
char c = "B";
```

#### 坑 2：把浮点数塞给整数
```cpp
int x = 3.14;
```
可能发生截断，结果变成 `3`。

#### 坑 3：误以为浮点数一定精确
```cpp
double money = 0.1 + 0.2;
```
不要轻易直接拿它和 `0.3` 做绝对相等判断。

#### 坑 4：不理解 `bool` 输出
```cpp
bool ok = true;
cout << ok << endl;
```
输出常是 `1`，不是文字 `true`。

---

### 3.10 记忆口诀
> **int 管整数，double 管小数，char 管单字，bool 管真假。**

补充一个更完整的版本：
> **有无小数先分家，字符真假别混搭。**

---

## 第 4 章：C++ 变量类型

### 4.1 一句话抓本质
变量就是一个**带名字的存储位置**，而变量类型决定它能存什么值、怎么解释这个值。

如果把内存想成一排排小盒子，那么变量就是：
- 给某个盒子起名字
- 规定这个盒子装哪类东西
- 以后可以通过名字反复访问它

---

### 4.2 为什么需要变量
程序不是只打印固定文字，它常常要处理“会变化的数据”：
- 用户输入的年龄
- 商品价格
- 当前计数
- 某次计算结果

这些会变化的内容不能都写死在代码里，所以要放进变量。

例如：
```cpp
int age = 18;
```
意思就是：
- 创建一个名叫 `age` 的变量
- 它的类型是整数 `int`
- 初始值是 `18`

---

### 4.3 声明、定义、初始化
这三个词很容易混，必须尽早分清。

#### （1）声明
告诉编译器：有这么个名字、它是什么类型。

#### （2）定义
真正为变量分配存储空间。

#### （3）初始化
变量第一次获得一个明确值。

在初学阶段，很多语句会同时完成几件事：
```cpp
int a = 10;
```
这通常既是定义，也是初始化。

而：
```cpp
int a;
a = 10;
```
第一行先定义，第二行再赋值。

你可以先把它记成：
- 定义：把盒子准备好
- 初始化：第一次往盒子里放东西
- 赋值：后续再改盒子里的内容

---

### 4.4 常见变量定义方式
```cpp
int x = 10;
double pi = 3.14;
char ch = 'C';
bool ok = false;
```

这些都是“定义并初始化”的基本形式。

还可以写：
```cpp
int score(100);
int level{3};
```

对初学者来说，先掌握最常见的 `=` 写法即可；之后再逐步认识圆括号初始化、花括号初始化。

---

### 4.5 `auto` 是什么
```cpp
auto n = 100;
auto price = 19.9;
auto flag = true;
```

`auto` 的含义是：**让编译器根据右边的值自动推导类型。**

例如：
- `100` 推导成整数类型
- `19.9` 推导成浮点类型
- `true` 推导成布尔类型

优点：
- 少写类型名
- 某些复杂类型下非常方便

但入门阶段要注意：
> `auto` 虽然省事，但前提是你心里仍然要清楚变量最后到底是什么类型。

否则很容易“代码能写，脑子没跟上”。

---

### 4.6 变量命名规则
变量名不是随便写的，至少要遵守语法规则。

#### 基本规则
- 可以包含字母、数字、下划线
- 不能以数字开头
- 不能使用 C++ 关键字
- 大小写敏感

例如：
```cpp
int age;
int student_count;
int studentCount;
```

合法；而：
```cpp
int 2age;
int int;
```
不合法。

---

### 4.7 变量命名建议
“能运行”和“好维护”之间，差别常常就在命名。

#### 不推荐
```cpp
int a;
double x1;
bool t;
```

除非是非常短的小范围临时变量，否则这种命名信息量太低。

#### 更推荐
```cpp
int age;
double averageScore;
bool isPassed;
```

好的变量名应该做到：
- 看名字就大致知道含义
- 不用额外猜测单位或用途
- 让阅读速度变快

经验口诀：
> **变量名不是为了少打字，而是为了少误解。**

---

### 4.8 赋值与修改
变量的意义就在于“可以变”。

```cpp
int count = 1;
count = 2;
count = count + 3;
```

执行后，`count` 的值会逐步变化。

重点理解第三句：
```cpp
count = count + 3;
```
它不是数学里的“左右永远相等”的陈述，而是：
1. 先取出当前 `count` 的值
2. 加上 3
3. 再把结果放回 `count`

这是编程里最重要的思维转换之一。

---

### 4.9 未初始化变量的风险
```cpp
int num;
cout << num << endl;
```

这种写法在初学阶段要尽量避免。因为局部变量如果没有初始化，它的值可能是不确定的。你看到的输出可能是“某个莫名其妙的数字”。

最安全的习惯是：
> **定义变量时尽量马上初始化。**

例如：
```cpp
int num = 0;
double price = 0.0;
char ch = ' ';
bool ok = false;
```

---

### 4.10 多个变量的定义
可以写成：
```cpp
int a = 1, b = 2, c = 3;
```

虽然语法上没问题，但入门阶段不建议过度这样写，因为：
- 可读性下降
- 调试不方便
- 以后改类型或加注释不方便

通常更清晰的写法是：
```cpp
int a = 1;
int b = 2;
int c = 3;
```

代码多几行没关系，关键是结构清楚。

---

### 4.11 常见错误与坑
#### 错误 1：名字不合法
```cpp
int 3num = 10;
```
变量名不能以数字开头。

#### 错误 2：类型和值不匹配
```cpp
int age = "18";
```
左边要整数，右边却是字符串形式。

#### 错误 3：字符忘了单引号
```cpp
char grade = A;
```
应写成：
```cpp
char grade = 'A';
```

#### 错误 4：未初始化直接使用
```cpp
int x;
cout << x << endl;
```
结果不可依赖。

#### 错误 5：滥用 `auto`
```cpp
auto x = 3.14;
auto y = x + 1;
```
如果你不知道推导结果，后面就容易误判类型行为。

---

### 4.12 学习变量时最重要的四个意识
1. **变量有名字**：为了后续访问和理解
2. **变量有类型**：决定保存和运算方式
3. **变量有值**：程序运行时真正处理的是值
4. **变量会变化**：这正是“变量”之所以叫变量的原因

只要把这四点抓住，后面学表达式、条件、循环、函数时会轻松很多。

---

### 4.13 记忆口诀
> **变量先有名，再有类型，再有值；定义尽量初始化，后续修改看赋值。**

再补一句实战提醒：
> **变量名写清楚，程序就先成功一半。**

## 5. C++ 变量作用域

**一句话理解：** 作用域就是“这个名字在哪一段代码里能被看见、能被使用”。

作用域（scope）是初学 C++ 时最容易“看起来简单、实际很容易踩坑”的主题之一。很多编译错误、变量值不对、名字冲突、调试困难，本质上都和作用域有关。

### 为什么要有作用域
如果程序里所有变量都能在任何地方被访问：
- 代码会非常混乱；
- 不同函数之间很容易互相影响；
- 改一个地方，另一个地方可能悄悄坏掉；
- 调试时很难判断“这个变量到底是哪一个”。

所以，C++ 用作用域来约束变量的**可见范围**，让代码更安全、更容易维护。

### 常见作用域

#### 1）局部作用域（local scope）
在函数内部定义的变量，只能在该函数内部使用。

```cpp
#include <iostream>
using namespace std;

void show() {
    int x = 10;
    cout << x << endl;
}

int main() {
    show();
    // cout << x << endl;   // 错误：x 只在 show() 里有效
    return 0;
}
```

**理解重点：**
- 局部变量“出生”在函数内部；
- 函数执行结束后，它通常也随之“失效”；
- 别的函数看不见它。

#### 2）块作用域（block scope）
凡是 `{}` 包起来的代码块，都可以形成自己的作用域，例如 `if`、`for`、`while`、单独的大括号块。

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 5;

    if (a > 0) {
        int b = 100;
        cout << "块内 b = " << b << endl;
    }

    // cout << b << endl;   // 错误：b 只在 if 代码块内存在
    return 0;
}
```

**记住：** `b` 不是“在 main 里定义的”，而是“在 if 这个小块里定义的”。

#### 3）全局作用域（global scope）
在所有函数外部定义的变量，通常从定义位置开始，在当前源文件中都可以使用。

```cpp
#include <iostream>
using namespace std;

int g = 100;   // 全局变量

void printG() {
    cout << "g = " << g << endl;
}

int main() {
    printG();
    cout << g << endl;
    return 0;
}
```

**优点：** 使用方便，多个函数都能访问。  
**缺点：** 太方便了，所以也更危险——任何地方都可能把它改掉。

### 变量遮蔽（shadowing）
当内层作用域里定义了一个和外层同名的变量时，内层变量会“遮住”外层变量。

```cpp
#include <iostream>
using namespace std;

int value = 50;   // 全局变量

int main() {
    int value = 10;   // 局部变量，遮蔽全局变量
    cout << value << endl;      // 输出 10
    cout << ::value << endl;    // 输出 50，:: 表示全局作用域
    return 0;
}
```

### `::` 作用域解析运算符
如果你真的需要访问被遮蔽的全局变量，可以用：

```cpp
::变量名
```

例如：

```cpp
cout << ::value << endl;
```

不过初学阶段的建议是：**尽量避免写出需要靠 `::` 才能看懂的代码。**

### `for` 循环里的作用域
很多新手会忽略循环变量也是有作用域的。

```cpp
#include <iostream>
using namespace std;

int main() {
    for (int i = 0; i < 3; i++) {
        cout << i << endl;
    }

    // cout << i << endl;   // 错误：i 只在 for 循环中有效
    return 0;
}
```

这里的 `i` 只在 `for` 循环这一个语句块中有效，循环结束后就不能再用了。

### 生命周期 vs 作用域：别混淆
这两个词很像，但不是一回事：

- **作用域**：变量“在哪儿能访问”；
- **生命周期**：变量“从什么时候存在，到什么时候消失”。

例如局部变量：
- 作用域：函数内部；
- 生命周期：函数开始执行到函数结束。

`static` 局部变量则不同：
- 作用域：仍然只在函数内部；
- 生命周期：整个程序运行期间都存在。

这就是为什么后面学 `static` 时要特别小心。

### 示例：综合观察不同作用域
```cpp
#include <iostream>
using namespace std;

int g = 100;

int main() {
    int a = 10;

    cout << "全局 g = " << g << endl;
    cout << "局部 a = " << a << endl;

    if (a > 0) {
        int b = 20;
        cout << "块内 b = " << b << endl;
        cout << "块内 a = " << a << endl;
        cout << "块内 g = " << g << endl;
    }

    // cout << b << endl;   // 错误：b 超出作用域
    return 0;
}
```

观察规律：
- 内层能看见外层；
- 外层看不见内层；
- 同名时，近处优先。

### 易错点
- **在作用域外访问变量**：最常见的编译错误之一；
- **同名遮蔽没注意**：以为改的是全局变量，实际上改的是局部变量；
- **滥用全局变量**：程序规模一大就很难维护；
- **把块变量带到块外使用**：尤其常见于 `if`、`for`、`while`。

### 实战建议
- 变量尽量在**最小必要范围内**定义；
- 能写成局部变量，就不要写成全局变量；
- 尽量避免不同层级里使用同名变量；
- 当你发现“这个变量到处都要用”，先考虑是否应该作为函数参数传入，而不是直接做全局变量。

### 记忆口诀
> **“哪儿定义，哪儿生效；层层向外能看到，反向访问做不到。”**

### 记忆小贴士
把作用域想成“办公室门禁”：
- 局部变量：只有本房间的人能进；
- 块变量：只有更小的会议室里的人能进；
- 全局变量：整层楼都能看见；
- 同名遮蔽：新贴了一张同名门牌，你先看到最近那张。

## 6. C++ 常量

**一句话理解：** 常量就是“创建后不允许随意修改”的值，它的意义是让程序更安全、更清楚。

很多初学者会把常量理解成“不能改的变量”，这不算错，但还不够完整。更准确地说，常量的核心价值有两个：
1. **约束修改**：防止误操作；
2. **表达意图**：告诉读代码的人“这个值本来就不该变”。

### 为什么不要乱写魔法数字
看下面两段代码：

```cpp
if (score >= 60) {
    cout << "及格" << endl;
}
```

```cpp
const int PASS_SCORE = 60;
if (score >= PASS_SCORE) {
    cout << "及格" << endl;
}
```

第二种更好，因为：
- `60` 的含义明确了；
- 以后如果标准改成 `70`，只改一个地方；
- 代码更容易读。

这种没有名字、直接写在代码里的数字，常被叫做**魔法数字（magic number）**。

### 常见常量写法

#### 1）`const`
```cpp
const double PI = 3.14159;
const int DAYS = 7;
```

含义：变量只读，初始化后不能再赋新值。

```cpp
const int x = 10;
// x = 20;   // 错误：const 常量不能修改
```

#### 2）`constexpr`
```cpp
constexpr int MAX_SIZE = 100;
constexpr double RATE = 0.85;
```

它表示“编译期就能确定的常量”。通常比 `const` 更严格，也更适合需要编译期常量的场景。

### `const` 和 `constexpr` 的区别
可以先这样记：

- `const`：强调“只读”；
- `constexpr`：强调“编译期就确定”。

更直白一点：
- `const` 不一定是编译期常量；
- `constexpr` 一定要能在编译阶段求值。

例如：

```cpp
int n;
cin >> n;
const int a = n;        // 可以，a 是只读，但值来自运行时
// constexpr int b = n; // 不行，n 不是编译期常量
```

### 什么时候优先用 `constexpr`
如果一个值：
- 固定不变；
- 和用户输入无关；
- 编译时就能确定；

那么优先考虑 `constexpr`，例如：
- 数组固定长度；
- 数学常量；
- 编译期配置值。

### 示例：数组长度
```cpp
constexpr int SIZE = 5;
int arr[SIZE] = {1, 2, 3, 4, 5};
```

如果你只是初学，先记住一句：**数组长度、模板参数这类“编译前就得知道”的位置，`constexpr` 更合适。**

### 常量的好处
- 防止误改；
- 提高代码可读性；
- 降低维护成本；
- 帮助编译器做更多优化；
- 让程序意图更清晰。

### 命名建议
常量一般要起一个“像规则、像配置、像标准”的名字，例如：
- `MAX_STUDENTS`
- `PI`
- `PASS_SCORE`
- `DEFAULT_PORT`

项目里风格可能不同：
- 有的喜欢全大写加下划线；
- 有的喜欢 `kMaxSize`；
- 有的喜欢驼峰命名。

**重点不是格式统一成哪一种，而是整个项目保持一致。**

### 常量引用（先知道概念）
在后面学函数参数时，你会经常见到：

```cpp
const string& name
```

它的意思是：
- 不拷贝原对象；
- 也不允许在函数里修改它。

现在先记住：**`const` 不只修饰普通变量，还能修饰引用、指针、成员函数等。**

### 示例：一个更像真实代码的常量用法
```cpp
#include <iostream>
using namespace std;

int main() {
    const int PASS_SCORE = 60;
    int score;

    cin >> score;

    if (score >= PASS_SCORE) {
        cout << "通过" << endl;
    } else {
        cout << "未通过" << endl;
    }

    return 0;
}
```

### 易错点
- **定义了 `const` 还想修改**：编译器会直接报错；
- **把所有常量都无脑写成 `constexpr`**：如果值来自运行时，不行；
- **仍然大量使用魔法数字**：可读性会很差；
- **常量名太随意**：如 `a`、`b`、`x1`，等于白起名。

### 实战建议
- 能命名的重要固定值，尽量命名；
- 能明确不改的变量，就尽量加 `const`；
- 不要为了“省事”到处写裸数字；
- 初学阶段分不清时，可以先用 `const`，后续再理解 `constexpr` 的编译期意义。

### 记忆口诀
> **“会变的是变量，不变的是规则；规则要起名，别让数字裸奔。”**

### 记忆小贴士
把常量想成“贴了封条的参数”：
- `const`：贴了封条，不能乱改；
- `constexpr`：出厂前就已经固定好，运行时不临时决定。

## 7. C++ 修饰符类型

**一句话理解：** 修饰符是给基础类型“加说明书”的词，用来改变数据范围、符号属性或精度表现。

很多人刚接触这一章时会觉得陌生，因为“修饰符”不像 `if`、`for` 那样立刻有行为表现。它更像是在告诉编译器：
- 这个整数要不要带负号；
- 这个数范围大一点还是小一点；
- 这个浮点数精度要不要更高。

### 常见修饰符
- `signed`：有符号，可以表示正数、负数和 0；
- `unsigned`：无符号，只表示 0 和正数；
- `short`：较短整数类型；
- `long`：较长整数类型；
- `long long`：更长整数类型；
- `long double`：更高精度浮点类型。

### 从“带不带负号”理解 `signed` / `unsigned`

#### `signed`
通常普通 `int` 默认就是 `signed int`。

```cpp
signed int temperature = -5;
int score = 95;   // 默认也是有符号整数
```

#### `unsigned`
只能表示非负数。

```cpp
unsigned int age = 18;
// unsigned int x = -1;   // 这样写会产生你不想要的结果
```

**重点提醒：** `unsigned` 不是“更大更好”，而是“没有负数这半边范围，所以正数范围更大”。

### `short` / `long` / `long long`
它们主要修饰整数范围。

```cpp
short year = 2024;
long population = 1000000;
long long stars = 1234567890123LL;
```

可以先记趋势，不要死背字节数：

- `short`：范围通常比 `int` 小；
- `long`：通常不小于 `int`；
- `long long`：通常不小于 `long`。

### 为什么不建议死记“占几个字节”
因为类型大小和平台、编译器实现有关。你在不同系统上看到的结果可能不完全一样。

初学时正确的认识是：
- **修饰符影响范围和表示能力；**
- **具体大小可能因平台而异。**

如果真要查看，可以用：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << sizeof(short) << endl;
    cout << sizeof(int) << endl;
    cout << sizeof(long) << endl;
    cout << sizeof(long long) << endl;
    return 0;
}
```

### `long double`
它用于比 `double` 更高精度的小数表示。

```cpp
long double pi = 3.141592653589793238L;
```

注意字面量后面的 `L`，表示这是一个 `long double` 字面量。

### 示例：不同修饰符的使用
```cpp
#include <iostream>
using namespace std;

int main() {
    unsigned int score = 90;
    short level = 3;
    long long bigNum = 1234567890123LL;
    long double x = 3.141592653589793238L;

    cout << score << endl;
    cout << level << endl;
    cout << bigNum << endl;
    cout << x << endl;
    return 0;
}
```

### 有符号和无符号的常见坑
这部分非常值得记住，因为很多线上 bug 都和它有关。

#### 坑 1：`unsigned` 不能表示负数
```cpp
#include <iostream>
using namespace std;

int main() {
    unsigned int x = 5;
    cout << x - 10 << endl;
    return 0;
}
```

很多新手以为输出是 `-5`，实际上通常会得到一个很大的正数，因为发生了无符号运算。

#### 坑 2：比较时出现意外结果
```cpp
int a = -1;
unsigned int b = 1;
// if (a < b) ...
```

你以为 `-1 < 1` 必然为真，但在混合比较时可能因为类型转换出现意外。初学阶段最安全的策略是：
- **少混用 signed 和 unsigned；**
- 用时要明确知道转换规则。

### 什么时候用 `unsigned`
适合天然不可能为负的量，例如：
- 数量；
- 编号；
- 字节数；
- 容器大小（标准库里很多 size 相关值就是无符号的）。

但即便如此，实际开发中也不是“见数量就一定上 unsigned”，因为它会带来比较和减法陷阱。**清楚风险，比盲目使用更重要。**

### 实战建议
- 新手主力先用 `int`、`double`，别一开始把类型组合搞太复杂；
- 明确不会有负数时，再考虑 `unsigned`；
- 遇到超大整数时，再考虑 `long long`；
- 不要把“类型更长”当作“代码更高级”。选合适的才对。

### 记忆口诀
> **“signed 可正负，unsigned 没负数；short 偏小，long 偏大，long long 管大整数。”**

### 记忆小贴士
把修饰符想成衣服尺码和标签：
- `signed` / `unsigned`：有没有“负号口袋”；
- `short` / `long`：尺码大一点还是小一点；
- `long double`：更精细的刻度尺。

---

## 8. C++ 存储类

**一句话理解：** 存储类决定一个名字“存在哪里、活多久、谁能访问”。

如果说“作用域”解决的是**看得见谁**，那么“存储类”更多解决的是：
- 这个变量保存在哪；
- 程序运行多久它还在；
- 它能不能被其他文件使用；
- 它是不是每个线程各有一份。

这是连接“语法层面”和“程序运行机制”的一章，非常重要。

### 常见存储类关键字
- `static`
- `extern`
- `register`（历史上常见，现代基本了解即可）
- `thread_local`

### 先建立一个大框架
学习存储类时，建议每次都问自己三个问题：
1. **作用域在哪？**
2. **生命周期多长？**
3. **链接性/可见性如何？**

这样你就不会只会背关键字，不会真正理解。

---

### 一、`static`
`static` 是初学阶段最重要、也最容易混淆的存储类关键字。因为它在不同位置有不同效果。

#### 1）函数内的 `static` 局部变量
```cpp
#include <iostream>
using namespace std;

void visit() {
    static int count = 0;
    count++;
    cout << count << endl;
}

int main() {
    visit();
    visit();
    visit();
    return 0;
}
```

输出：
```cpp
1
2
3
```

### 为什么不是每次都输出 1？
因为：
- 普通局部变量，每次进入函数都会重新创建；
- `static` 局部变量，只初始化一次；
- 函数执行结束后，它的值不会消失；
- 下次再进函数，会沿用上次的值。

### 它的特点
- **作用域**：仍然只在函数内部；
- **生命周期**：整个程序运行期间；
- **初始化**：只做一次。

这类变量很适合“函数调用计数”“缓存上次结果”等场景，但也容易让函数带上“隐藏状态”。

### 易错理解
很多人误以为：
> `static` = 全局变量

这是错的。函数内 `static` 变量：
- **不是全局可见**；
- 只是“活得更久”；
- 作用域仍然是局部。

---

#### 2）文件作用域的 `static` 变量
当 `static` 出现在函数外面时，含义变成：
- 这个名字只在当前源文件可见；
- 别的源文件不能直接访问它。

```cpp
static int fileCount = 0;
```

### 作用
- 避免和别的文件中的同名全局变量冲突；
- 限制外部访问，减少耦合；
- 表示“这是当前文件的内部实现细节”。

你可以把它理解成“文件私有的全局变量”。

---

### 二、`extern`
`extern` 表示：
> “这个变量/函数不是在这里定义的，而是在别处定义的，我这里只是声明一下，告诉编译器它存在。”

例如，假设在另一个源文件里有：

```cpp
int g = 100;
```

那么在当前文件里可以写：

```cpp
extern int g;
```

这样当前文件就知道有个 `g` 可以用。

### `extern` 的核心用途
- 多个 `.cpp` 文件共享同一个全局变量；
- 将“定义”和“使用”分离；
- 也是多文件程序组织中常见的基础机制。

### 注意：`extern` 是声明，不是定义
```cpp
extern int g;   // 声明
int g = 100;    // 定义
```

如果你在多个地方都写定义，就会重复定义报错。

### 常见误区
- 以为 `extern` 会“创建变量”——不会；
- 以为声明了就一定有定义——如果链接时找不到真正定义，也会报错。

---

### 三、`register`
`register` 是一个历史上的建议关键字，意思大概是：
> “这个变量用得很频繁，建议放寄存器里。”

```cpp
register int i;
```

但现代编译器优化远比人工判断强，这个关键字现在几乎不需要手动使用。你只需要知道：
- 它是早期 C/C++ 里出现过的关键字；
- 现代开发中很少依赖它；
- 学到这里了解即可，不必当主力知识点。

---

### 四、`thread_local`
`thread_local` 表示：
> 每个线程都有自己独立的一份变量副本。

```cpp
thread_local int value = 0;
```

如果程序开了多个线程：
- 线程 A 改自己的 `value`；
- 线程 B 改自己的 `value`；
- 它们互不影响。

### 初学阶段如何看待它
如果你还没学多线程，这个关键字先做到：
- 认识；
- 知道它和“线程局部存储”有关；
- 暂时不用深究。

---

### 示例：对比普通局部变量和静态局部变量
```cpp
#include <iostream>
using namespace std;

void testNormal() {
    int x = 0;
    x++;
    cout << "normal: " << x << endl;
}

void testStatic() {
    static int x = 0;
    x++;
    cout << "static: " << x << endl;
}

int main() {
    testNormal();
    testNormal();
    testStatic();
    testStatic();
    return 0;
}
```

输出通常是：
```cpp
normal: 1
normal: 1
static: 1
static: 2
```

这组对比非常经典，必须真正看懂。

### 存储类和作用域的组合记忆

| 写法                | 作用域           | 生命周期     | 典型特点     |
| ----------------- | ------------- | -------- | -------- |
| 普通局部变量            | 函数/代码块内       | 进入块到离开块  | 用完即销毁    |
| `static` 局部变量     | 函数/代码块内       | 整个程序期间   | 值会保留     |
| 普通全局变量            | 文件范围/可跨文件声明使用 | 整个程序期间   | 容易被多处访问  |
| `static` 全局变量     | 当前文件内         | 整个程序期间   | 文件私有     |
| `extern` 声明       | 取决于定义处        | 取决于定义处   | 表示“别处定义” |
| `thread_local` 变量 | 取决于声明位置       | 线程生命周期相关 | 每线程一份    |
|                   |               |          |          |

### 易错点
- **把 `static` 的两种含义混为一谈**；
- **以为函数内 `static` 就等于全局变量**；
- **声明 `extern` 但没有对应定义**；
- **在多个文件里重复定义同一个全局变量**；
- **还没理解生命周期，就只死背关键字名字。**

### 实战建议
- 普通函数逻辑优先用普通局部变量；
- 真有“保留上次值”的需要，再考虑 `static` 局部变量；
- 多文件共享变量时要克制，能少共享就少共享；
- 能把数据作为参数传递，就尽量少依赖全局状态；
- 对 `register` 和 `thread_local`，初学阶段以理解概念为主。

### 记忆口诀
> **“static 记住上次，extern 去别处找；register 是旧时代，thread_local 各线程各管各。”**

### 记忆小贴士
把存储类想成“变量的户口”：
- 住多久；
- 住哪儿；
- 谁能查到；
- 是不是全家共用，还是每个线程各有一套。

## 9. C++ 运算符

**一句话理解：** 运算符就是把“值”变成“动作”的按钮；同样的数字，换一个运算符，结果就完全不同。

### 先分清：运算符在做什么
- **算术运算符**：算数计算，例如加减乘除
- **关系运算符**：比较大小、是否相等
- **逻辑运算符**：把多个条件组合起来
- **赋值运算符**：给变量重新写入值
- **位运算符**：直接按二进制位操作，偏底层
- **其他常用运算符**：条件运算符、`sizeof`、自增自减、下标、成员访问等

### 常见运算符总览
```cpp
+   -   *   /   %
==  !=  >   <   >=  <=
&&  ||  !
=   +=  -=  *=  /=  %=
&   |   ^   ~   <<  >>
?:  sizeof  ++  --  []  ->  .
```

### 1）算术运算符
```cpp
int a = 10, b = 3;
cout << a + b << endl;   // 13
cout << a - b << endl;   // 7
cout << a * b << endl;   // 30
cout << a / b << endl;   // 3
cout << a % b << endl;   // 1
```

#### 重点理解
- `/` 在两个整数之间使用时，结果还是整数，小数部分会直接丢掉
- `%` 只能用于整数类型，表示“余数”
- 如果想得到小数结果，要让至少一个操作数是浮点数：`10.0 / 3`

#### 常见坑
- `5 / 2` 得到的是 `2`，不是 `2.5`
- `a % b` 中 `b` 不能是 0，否则出错
- 浮点数计算会有精度误差，别拿它做“严格相等”判断

### 2）关系运算符
```cpp
int x = 8, y = 10;
cout << (x == y) << endl;  // 0
cout << (x != y) << endl;  // 1
cout << (x < y) << endl;   // 1
cout << (x >= y) << endl;  // 0
```

#### 重点理解
- 关系运算符的结果只有两种：真或假
- 在 `cout` 里输出布尔值时，默认常常显示为 `1` 和 `0`
- `=` 和 `==` 完全不是一回事：前者是赋值，后者是比较

### 3）逻辑运算符
```cpp
int age = 20;
bool hasId = true;

cout << (age >= 18 && hasId) << endl;  // 1
cout << (age < 18 || hasId) << endl;    // 1
cout << !hasId << endl;                 // 0
```

#### 重点理解
- `&&`：两个条件都成立才为真
- `||`：只要有一个条件成立就为真
- `!`：取反，把真变假、把假变真

#### 短路特性
逻辑运算有“短路”行为：
- `&&` 左边已经是假，右边通常不再继续判断
- `||` 左边已经是真，右边通常不再继续判断

这在写复杂条件时很重要，也能避免一些无意义甚至危险的计算。

### 4）赋值运算符
```cpp
int n = 10;
n += 5;  // 等价于 n = n + 5
n *= 2;  // 等价于 n = n * 2
```

#### 重点理解
- 赋值运算符是“把新值放回变量里”
- 复合赋值写法更简洁，也更容易读
- 但不要为了短而短，复杂表达式还是要拆开

### 5）位运算符
位运算是直接操作二进制位，初学时先认识用途即可：
- `&`：按位与
- `|`：按位或
- `^`：按位异或
- `~`：按位取反
- `<<`：左移
- `>>`：右移

```cpp
int a = 6;   // 二进制 110
int b = 3;   // 二进制 011

cout << (a & b) << endl; // 2，010
cout << (a | b) << endl; // 7，111
cout << (a ^ b) << endl; // 5，101
```

#### 理解要点
- 位运算常用于底层控制、压缩状态、性能敏感场景
- 如果你是初学者，先把“会看懂”放在第一位，不必一开始就硬背所有二进制技巧

### 6）条件运算符 `?:`
```cpp
int score = 85;
string result = (score >= 60) ? "及格" : "不及格";
```

#### 重点理解
- 形式是：`条件 ? 结果1 : 结果2`
- 条件成立，取前半部分；不成立，取后半部分
- 适合简单分支，不适合太复杂的判断

### 7）其他常见运算符
#### `sizeof`
```cpp
cout << sizeof(int) << endl;
```
- 查看类型或变量占用多少字节
- 记住它更适合“查询”，不是“猜测”

#### `++` 和 `--`
```cpp
int i = 1;
cout << i++ << endl; // 先用再加
cout << ++i << endl; // 先加再用
```
- 前置和后置的结果不一样
- 在复杂表达式里尽量少混用，容易绕晕

### 记忆口诀
> **“算术算结果，关系出真假；逻辑连条件，赋值改变量。”**

### 典型错误
- 把 `=` 写成比较
- 把整数除法当成小数除法
- 把 `&&`、`||` 和 `&`、`|` 混用
- 在复杂表达式中滥用自增自减

---

## 10. C++ 循环

**一句话理解：** 循环就是“同一段逻辑反复做”，直到条件不满足为止；学会循环，程序就从“只会算一次”变成“能批量处理”。

### 为什么要用循环
很多任务都不是做一次就结束，比如：
- 打印 1 到 100
- 统计一组数据
- 反复读入输入直到结束
- 处理数组里的每个元素

如果不用循环，就只能把同样的代码写很多遍，既累又容易错。

### 三种常见循环

#### 1）while：先判断，再执行
```cpp
int i = 1;
while (i <= 5) {
    cout << i << endl;
    i++;
}
```

#### 2）do-while：先执行，再判断
```cpp
int i = 1;
do {
    cout << i << endl;
    i++;
} while (i <= 5);
```

#### 3）for：适合“次数明确”的重复
```cpp
for (int i = 1; i <= 5; i++) {
    cout << i << endl;
}
```

### 三种循环怎么选
- **次数明确**：优先用 `for`
- **条件驱动**：优先用 `while`
- **必须先执行一次**：用 `do-while`

### 重点理解：循环三要素
写循环时，脑子里要同时想三件事：
1. **初始化**：从哪里开始
2. **条件**：什么时候停
3. **更新**：每次怎么变化

如果少了更新，循环就很容易变成“死循环”。

### 示例：累加求和
```cpp
int sum = 0;
for (int i = 1; i <= 100; i++) {
    sum += i;
}
cout << sum << endl;
```

#### 这段代码在做什么
- `sum` 负责保存结果
- `i` 负责从 1 走到 100
- 每一轮把当前的 `i` 加到 `sum` 上

### 示例：while 更适合条件不固定的场景
```cpp
int n = 0;
while (n >= 0) {
    cin >> n;
    if (n < 0) break;
}
```

### `break` 和 `continue`
- `break`：直接跳出整个循环
- `continue`：跳过本次循环的剩余部分，进入下一轮

```cpp
for (int i = 1; i <= 10; i++) {
    if (i == 5) continue;
    if (i == 8) break;
    cout << i << endl;
}
```

### 典型错误
- 忘记更新循环变量，导致死循环
- 循环条件写反，次数少了或多了
- 把 `break` 和 `continue` 搞混
- 需要从 1 开始却从 0 开始，导致结果偏一位

### 小技巧：把循环想成“闸门”
- 条件像闸门开关
- 更新像每次往前走一步
- 走到终点后闸门关闭，循环结束

### 记忆口诀
> **“先定起点，再看终点，中间记得迈一步。”**

---

## 11. C++ 判断

**一句话理解：** 判断就是“遇到不同情况，走不同分支”；它让程序不再只有一条直线。

### 为什么要判断
程序经常需要根据条件作出选择，例如：
- 分数是否及格
- 年龄是否成年
- 输入值是否合法
- 某个开关是否开启

没有判断，程序只能机械执行，无法对现实情况做响应。

### 1）`if / else`
```cpp
int score = 85;
if (score >= 60) {
    cout << "及格" << endl;
} else {
    cout << "不及格" << endl;
}
```

### 2）`else if` 多分支
```cpp
if (score >= 90) {
    cout << "优秀" << endl;
} else if (score >= 60) {
    cout << "及格" << endl;
} else {
    cout << "需要努力" << endl;
}
```

#### 重点理解
- 条件从上往下依次判断
- 一旦某个条件成立，后面的分支通常就不再执行
- 条件顺序很重要，范围写错会影响结果

### 3）`switch`
```cpp
int day = 1;
switch (day) {
    case 1:
        cout << "周一" << endl;
        break;
    case 2:
        cout << "周二" << endl;
        break;
    default:
        cout << "其他" << endl;
        break;
}
```

### `switch` 的适用场景
- 离散的固定值
- 菜单选项
- 枚举类型
- 简单编号判断

### `switch` 的关键点
- `case` 后面通常要跟 `break`
- 没有 `break` 可能发生“贯穿执行”
- `default` 用来处理“都不匹配”的情况

### 什么时候用 `if`，什么时候用 `switch`
- **区间判断**：用 `if`
- **固定选项**：用 `switch`

### 复杂条件写法
```cpp
int age = 20;
bool hasId = true;

if (age >= 18 && hasId) {
    cout << "可以进入" << endl;
}
```

#### 重点理解
- 多个条件可以组合
- 括号能帮助阅读，也能避免优先级误解
- 条件太长时最好拆开，先算出中间变量再判断

### 典型错误
- 把 `=` 写进判断条件里
- `if` 的条件范围写重叠，导致某些分支永远进不去
- `switch` 忘记写 `break`
- 复杂条件没有加括号，读起来像谜语

### 记忆口诀
> **“if 看区间，switch 看选项；条件先想清，分支才不乱。”**

---

## 12. C++ 函数

**一句话理解：** 函数就是把一段“能重复用的逻辑”打包起来，起名后就能随时调用。

### 为什么要用函数
如果没有函数：
- 同样的代码要写很多遍
- 修改一个小逻辑时要改很多地方
- 代码会越来越乱

有了函数：
- 复用性更高
- 结构更清晰
- 逻辑更容易测试和维护

### 函数的三步
1. **声明**：先告诉编译器有这个函数
2. **定义**：写出具体实现
3. **调用**：在需要的时候使用它

```cpp
#include <iostream>
using namespace std;

int add(int a, int b);   // 声明

int add(int a, int b) {  // 定义
    return a + b;
}

int main() {
    cout << add(2, 3) << endl;
    return 0;
}
```

### 函数的组成
- **函数名**：函数的名字
- **参数**：传进去的数据
- **返回值**：处理后交回来的结果
- **函数体**：具体执行的代码

### 参数传递方式

#### 1）值传递
```cpp
void f(int x) {
    x = x + 1;
}
```
- 传进去的是“副本”
- 函数内部改了，不会影响外面的原变量

#### 2）引用传递
```cpp
void addOne(int& x) {
    x += 1;
}
```
- 直接操作原变量
- 适合需要修改调用者数据的场景

#### 3）指针传递
```cpp
void addOne(int* x) {
    if (x != nullptr) {
        (*x) += 1;
    }
}
```
- 通过地址访问原数据
- 更接近底层，也更需要小心空指针

### 返回值
```cpp
int maxValue(int a, int b) {
    return (a > b) ? a : b;
}
```

#### 重点理解
- `return` 后面可以带结果
- 一旦执行 `return`，函数就结束
- `void` 函数没有返回值，但仍然可以 `return;` 提前结束

### 函数重载
同一个函数名，可以对应不同参数形式：
```cpp
int maxValue(int a, int b) { return a > b ? a : b; }
double maxValue(double a, double b) { return a > b ? a : b; }
```

#### 重点理解
- 重载强调“同名不同参”
- 让函数名更贴近业务含义，而不是为了类型拼很多名字

### 形参与实参
- **形参**：函数定义时写的参数，相当于“占位符”
- **实参**：调用函数时传入的真实值

```cpp
int sum(int a, int b) {   // a、b 是形参
    return a + b;
}

int result = sum(4, 5);   // 4、5 是实参
```

### 常见问题
- 只声明没定义，链接时出错
- 参数个数或类型不匹配
- 忘记写 `return`
- 本来想改外部变量，却用了值传递

### 调试函数的小方法
- 先把函数想成“黑盒子”
- 只检查：输入对不对、输出对不对
- 出错时先测试函数本身，再看调用位置

### 记忆口诀
> **“函数像小工厂，参数是原料，返回值是成品；会封装，代码才整齐。”**

## 13. C++ 数字

**一句话理解：** 数字处理本质上就是“选对类型、算对范围、处理好精度”。

### 13.1 常见数字类型
- `int`：整数，最常用
- `short` / `long` / `long long`：根据范围选择
- `float` / `double`：小数，`double` 更常用

### 13.2 整数和小数的区别
```cpp
int a = 10;
double b = 3.14;
```
- 整数不会保留小数部分
- 小数计算要注意精度误差
- 例如 `0.1 + 0.2` 在计算机里不一定刚好等于 `0.3`

### 13.3 运算时的隐式转换
```cpp
int x = 5;
double y = 2.0;
auto z = x / y;
```
- 不同类型参与运算时，编译器可能自动转换
- 若两个整数相除，结果还是整数，余数会被丢掉
- 想保留小数，至少要让其中一个数变成浮点数

### 13.4 取整与精度提醒
- `int(3.9)` 会变成 `3`
- 浮点数适合表示“近似值”，不适合要求绝对精确的金额累计
- 做比较时不要直接迷信 `==`

### 13.5 常用数学函数
通常会配合 `<cmath>` 使用，例如：
```cpp
#include <cmath>
cout << sqrt(16) << endl;
cout << abs(-8) << endl;
```
- `sqrt`：平方根
- `abs`：绝对值
- `pow`：次方

### 13.6 记忆提示
> **“整型看范围，小数看精度；相除先分清，比较少直接等。”**

### 13.7 易错点
- 把整数除法当成小数除法
- 忘记浮点误差
- 乱用很小的类型导致溢出
- 数学函数没包含对应头文件

### 13.8 小练习思路
- 计算半径为 3 的圆面积
- 计算两个整数相除后的商和余数
- 比较两个小数是否“足够接近”

## 14. C++ 数组

**一句话理解：** 数组就是“同类型、连续存放、按下标访问的一排变量”。

### 14.1 为什么需要数组
如果要保存 100 个学生分数，不能写 100 个独立变量，数组更方便：
```cpp
int score[100];
```

### 14.2 数组的基本写法
```cpp
int arr[5] = {1, 2, 3, 4, 5};
```
- 方括号里的数字是长度
- 下标从 `0` 开始，不是从 `1`
- `arr[0]` 是第一个元素，`arr[4]` 是最后一个元素

### 14.3 遍历数组
```cpp
for (int i = 0; i < 5; i++) {
    cout << arr[i] << endl;
}
```
- `i < 5` 是为了避免越界
- 越界访问是数组最常见、也最危险的错误之一

### 14.4 输入和输出数组
```cpp
int a[3];
for (int i = 0; i < 3; i++) {
    cin >> a[i];
}
```
- 常见做法是用循环批量输入
- 也适合批量求和、求最大值、求平均值

### 14.5 二维数组的直觉
二维数组可以理解成“表格”或“矩阵”：
```cpp
int m[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
```
- 第一维表示“第几行”
- 第二维表示“第几列”

### 14.6 常见应用场景
- 记录成绩
- 保存月份天数
- 图像像素矩阵
- 表格数据

### 14.7 记忆提示
> **“数组是排队的变量，下标从零开始走；循环访问最常见，越界一定要小心。”**

### 14.8 易错点
- 把长度和最后一个下标弄混
- 下标从 `1` 开始写
- 访问超出范围
- 二维数组行列顺序写反

## 15. C++ 字符串

**一句话理解：** 字符串就是“很多字符连在一起的一段文本”。

### 15.1 两种常见字符串方式
#### `char` 数组风格
```cpp
char s[20] = "hello";
```
- 传统 C 风格字符串
- 结尾有一个隐藏的 `\0`

#### `string` 风格
```cpp
#include <string>

```
- 更现代、更方便
- 更适合日常开发

### 15.2 为什么 `string` 更常用
- 直接拼接更方便
- 长度管理更自然
- 更少手动处理结尾符号的问题

### 15.3 常见操作
```cpp
string a = "hello";

cout << a + " " + b << endl;
cout << a.size() << endl;

- 拼接
- 求长度

for (int i = 0; i < (int)name.size(); i++) {
    cout << name[i] << endl;
}
```
- 字符串也可以像数组一样按下标访问
- 适合查找、统计、过滤

### 15.5 常见输入问题

- `char[]` 更底层，容易出错
- `string` 更安全、更好用
- 初学阶段建议优先掌握 `string`

### 15.8 易错点
- 忘记字符串结尾 `\0`
- 把 `cin` 和 `getline` 混用后没处理换行
- 把字符串当成单个字符
- 访问越界

### 15.9 小练习思路
- 统计一句话有多少个字符
- 把名字和问候语拼接输出
- 判断字符串里是否包含某个字母

## 16. C++ 指针

**一句话理解：** 指针不是数据本身，而是“数据住在哪里”的门牌号；你拿着门牌号，才能去访问或修改真正的数据。

### 为什么这一章重要
很多初学者一看到 `*` 和 `&` 就慌，其实指针的核心只有一句：**变量有值，也有地址；指针专门保存地址。**

C++ 之所以比很多高级语言更强大，一个重要原因就是它允许程序员更直接地控制内存。数组、函数参数、动态内存、链表、树、回调、底层库接口，背后都离不开指针。如果这章理解不牢，后面很多内容都会感觉“看得懂代码，但不知道为什么这样写”。

### 先建立一个脑内画面
把内存想成一排带编号的柜子：
- 普通变量 `int a = 10;`：表示某个柜子里放了 `10`
- `&a`：表示这个柜子的编号
- `int* p = &a;`：表示 `p` 这个变量里装的不是 `10`，而是 `a` 的地址
- `*p`：表示“顺着地址找到那个柜子，再把里面的值拿出来”

如果你脑子里总能想象“地址 -> 找到变量 -> 读写值”的过程，指针就不会乱。

### 基本写法
```cpp
int a = 10;
int* p = &a;

cout << a << endl;   // 10
cout << &a << endl;  // a 的地址
cout << p << endl;   // p 中存的地址
cout << *p << endl;  // 10，解引用后得到真正的值
```

### 三个必须彻底记住的符号
- `&a`：取地址，读作“a 的地址”
- `*p`：解引用，读作“p 指向位置里的值”
- `nullptr`：空指针，表示“当前没有指向任何合法对象”

### 一个最基础、最重要的例子
```cpp
int a = 10;
int* p = &a;
*p = 20;

cout << a << endl;   // 20
cout << *p << endl;  // 20
```

这里最关键的理解不是“输出了 20”，而是：
- `p` 保存的是 `a` 的地址
- `*p = 20` 相当于“通过地址找到 a，再改它的值”
- 所以改的是原变量，不是副本

### 指针最常见的用途
#### 1）间接访问和修改原对象
有时你不想直接传整个对象，而是把它的地址交给别人处理。

#### 2）函数参数传递
如果想让函数内部改掉外部变量，指针是一种经典写法。

```cpp
void setZero(int* p) {
    if (p != nullptr) {
        *p = 0;
    }
}

int main() {
    int x = 5;
    setZero(&x);
    cout << x << endl; // 0
}
```

#### 3）处理数组
数组名在很多场景下会退化成指向首元素的指针。

```cpp
int arr[3] = {10, 20, 30};
int* p = arr;

cout << *p << endl;       // 10
cout << *(p + 1) << endl; // 20
cout << *(p + 2) << endl; // 30
```

这里要理解：
- `p + 1` 不是地址简单加 1 个字节
- 而是跳到“下一个同类型元素”的位置
- `int*` 每次移动一个 `int` 的跨度

#### 4）动态内存
当程序运行时才知道要开多大空间，就会用到动态分配。

```cpp
int* p = new int(42);
cout << *p << endl; // 42

delete p;
p = nullptr;
```

### 为什么 `delete` 后最好置空
因为 `delete p;` 只是释放了那块内存，**不会自动把变量 `p` 变成空指针**。
此时 `p` 还保留着旧地址，但那个地址已经不再归你安全使用，这叫**悬空指针（dangling pointer）**。

正确习惯：
```cpp
delete p;
p = nullptr;
```

这样后面即使误用，也更容易被发现，而不是偷偷造成未定义行为。

### 指针和数组的关系：初学者高频考点
```cpp
int arr[4] = {1, 2, 3, 4};
cout << arr[0] << endl;      // 1
cout << *(arr + 0) << endl;  // 1
cout << arr[2] << endl;      // 3
cout << *(arr + 2) << endl;  // 3
```

记忆点：
- `arr[i]` 和 `*(arr + i)` 在效果上等价
- 数组名很多时候可以看作“指向首元素的地址”
- 但数组**不是**普通指针变量，数组名本身不能像普通指针那样被重新赋值

### 常见坑 1：野指针
```cpp
int* p;
cout << *p << endl; // 危险！p 未初始化
```

这里的 `p` 没有明确指向合法对象，它可能是任意垃圾地址。这种未初始化指针叫**野指针**。

安全习惯：
```cpp
int* p = nullptr;
```

先置空，再在需要时指向合法对象。

### 常见坑 2：空指针解引用
```cpp
int* p = nullptr;
cout << *p << endl; // 错误
```

空指针表示“没有对象”，所以不能拿它去解引用。

### 常见坑 3：多个变量声明看错
```cpp
int* p1, p2;
```

这行代码里：
- `p1` 是 `int*`
- `p2` 是 `int`

不是两个指针。

如果想都声明成指针，写成：
```cpp
int *p1, *p2;
```

### 常见坑 4：返回局部变量地址
```cpp
int* bad() {
    int x = 10;
    return &x; // 错误
}
```

函数结束后，局部变量 `x` 已经失效，返回它的地址就是返回一个失效地址。

### 指针参数和引用参数怎么选
- **只需要“能改原值”，并且语义更安全、更简洁**：优先考虑引用
- **需要表示“可能没有对象”**：用指针
- **需要手动处理动态内存、数组、底层接口**：指针更常见

一个实战判断法：
- “一定有对象” -> 引用常更自然
- “对象可能不存在” -> 指针更自然

### 记忆口诀
> **“变量装值，指针装址；见星号取值，见取址拿门牌。”**

### 本章最该记住的 4 句话
1. 指针里存的是地址，不是对象本身
2. `&` 取地址，`*` 解引用
3. 指针一定要先初始化，再使用
4. `new` 配 `delete`，删除后最好置 `nullptr`

## 17. C++ 引用

**一句话理解：** 引用就是给同一块数据再起一个名字；它不像指针那样保存地址的值，而更像“这个变量的另一个称呼”。

### 为什么引用是 C++ 初学者的福音
如果说指针像“拿着门牌号去找房间”，那引用更像“一个人有两个名字”。

```cpp
int a = 10;
int& r = a;
```

这里不是复制了一份 `a`，而是说：以后 `r` 这个名字，也代表 `a`。

所以：
```cpp
r = 20;
cout << a << endl; // 20
```

你改的是同一个对象，只是换了个称呼去改。

### 基本写法
```cpp
int a = 10;
int& r = a;

cout << a << endl; // 10
cout << r << endl; // 10

r = 99;
cout << a << endl; // 99
```

### 引用的三个核心特点
#### 1）引用必须初始化
```cpp
int& r; // 错误
```

引用不是一个“空壳”，它一出现就必须说明“我是谁的别名”。

#### 2）引用一旦绑定，通常不能改绑
```cpp
int a = 10;
int b = 20;
int& r = a;
r = b;
```

这不是让 `r` 改成引用 `b`，而是把 `b` 的值赋给 `a`。执行后：
- `a` 变成 `20`
- `r` 仍然是 `a` 的别名

#### 3）引用用起来像原变量
你不需要写 `*` 去解引用，所以代码通常更自然。

### 引用最常见的用途
#### 1）函数参数：避免拷贝
如果一个对象很大，按值传递会复制一份，浪费时间和空间。

```cpp
void print(const string& s) {
    cout << s << endl;
}
```

这里的 `const string&` 有两个好处：
- 不拷贝整个字符串
- 保证函数里不会修改原字符串

这在现代 C++ 里是非常常见的写法。

#### 2）函数参数：需要修改实参
```cpp
void swapInt(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}
```

调用：
```cpp
int a = 3, b = 5;
swapInt(a, b);
```

函数内部直接改到外面的 `a` 和 `b`。

#### 3）范围 for 循环中避免复制
```cpp
vector<string> names = {"Tom", "Jack", "Lucy"};
for (string& name : names) {
    name += "!";
}
```

这里如果不用引用，循环变量只是每个元素的副本，修改不会落回原容器。

### const 引用特别重要
```cpp
const int& r = 10;
```

普通引用通常不能直接绑定字面量或临时对象，但 `const 引用` 可以。它的意义很大：
- 能接收临时值
- 不允许修改绑定对象
- 常用于高效传参

### 引用 vs 指针：初学阶段最实用的对比
| 维度 | 指针 | 引用 |
|---|---|---|
| 是否可为空 | 可以，`nullptr` | 通常不为空 |
| 是否必须初始化 | 最好初始化，但语法上可不初始化 | 必须初始化 |
| 是否能改指向 | 可以 | 不能重新绑定 |
| 访问方式 | 需要 `*` 解引用 | 像普通变量一样用 |
| 适合场景 | 底层控制、可空对象、动态内存 | 参数传递、别名、代码简洁 |

### 常见坑 1：以为引用是复制
```cpp
int a = 10;
int& r = a;
```

这不是创建了另一个整数，而是给 `a` 起别名。如果你把它理解成拷贝，后面很多代码都会判断错。

### 常见坑 2：返回局部变量引用
```cpp
int& bad() {
    int x = 10;
    return x; // 错误
}
```

局部变量离开函数后就失效，返回它的引用和返回它的地址一样危险。

### 常见坑 3：忘记加 const
```cpp
void print(string s);        // 会拷贝
void print(const string& s); // 更常见
```

如果函数只是读取大型对象，不修改，优先用 `const T&`。

### 一个很实用的记忆法
- 指针：可以理解为“可变门牌号”
- 引用：可以理解为“固定外号”

### 记忆口诀
> **“引用像外号，绑定就不跑；想省拷贝、改原值，引用最顺手。”**

### 本章最该记住的 4 句话
1. 引用是别名，不是副本
2. 引用必须初始化
3. `const 引用` 是高频实用写法
4. 需要“可空、可改指向”时用指针，需要“简洁、安全”时优先想引用

## 18. C++ 日期 & 时间

**一句话理解：** 日期时间处理分两类：**拿到某个时间点**，以及**计算两个时间点之间的间隔**。

### 为什么这章容易学乱
因为 C++ 里有两套常见思路：
- 老风格：`<ctime>`
- 现代风格：`<chrono>`

初学时容易把两套接口混在一起记，结果越记越乱。最好的办法是先分清职责：
- **`<ctime>` 更像传统日历时间**：年、月、日、时、分、秒
- **`<chrono>` 更像现代计时工具**：时间点、时间段、性能计时

### 旧风格：`<ctime>`
```cpp
#include <iostream>
#include <ctime>
using namespace std;

int main() {
    time_t now = time(nullptr);
    tm* local = localtime(&now);

    cout << 1900 + local->tm_year << "-"
         << 1 + local->tm_mon << "-"
         << local->tm_mday << " "
         << local->tm_hour << ":"
         << local->tm_min << ":"
         << local->tm_sec << endl;
}
```

### 上面代码要真正看懂什么
- `time(nullptr)`：获取当前时间点，结果是 `time_t`
- `localtime(&now)`：把时间点拆成本地时间结构
- `tm_year`：从 1900 年开始算，所以显示时要 `+1900`
- `tm_mon`：从 0 开始计月，所以显示时要 `+1`

### 初学者高频坑
#### 1）月份不是从 1 开始，而是从 0 开始
也就是：
- 0 表示 1 月
- 11 表示 12 月

#### 2）年份不是直接年份
`tm_year` 存的是“当前年份 - 1900”。

#### 3）`localtime` 返回的是指针
这意味着你拿到的是某块内部结构，写代码时要注意它不是普通对象。

### 现代风格：`<chrono>`
如果你要测代码运行了多久，`<chrono>` 更合适。

```cpp
#include <iostream>
#include <chrono>
using namespace std;
using namespace chrono;

int main() {
    auto start = high_resolution_clock::now();

    long long sum = 0;
    for (int i = 0; i < 1000000; ++i) {
        sum += i;
    }

    auto end = high_resolution_clock::now();
    auto cost = duration_cast<microseconds>(end - start);

    cout << "耗时: " << cost.count() << " us" << endl;
}
```

### `chrono` 最该掌握的三件事
#### 1）`now()`：获取当前时间点
```cpp
auto t = chrono::steady_clock::now();
```

#### 2）时间点相减得到持续时间
```cpp
auto diff = end - start;
```

#### 3）用 `duration_cast` 转换单位
```cpp
auto ms = duration_cast<milliseconds>(diff);
```

### 为什么计时常推荐 `steady_clock`
有些时钟可能会被系统时间调整影响，而 `steady_clock` 更适合测“经过了多久”。

简单记：
- **看现在几点**：偏向系统时间
- **测程序跑了多久**：偏向 `steady_clock`

### 一个非常实用的测速模板
```cpp
auto start = chrono::steady_clock::now();

// 这里放要测的代码

auto end = chrono::steady_clock::now();
auto cost = chrono::duration_cast<chrono::milliseconds>(end - start);
cout << cost.count() << " ms" << endl;
```

### 时间单位别混
`chrono` 里常见单位有：
- `seconds`
- `milliseconds`
- `microseconds`
- `nanoseconds`

不要把“数字大小”直接当成时间含义，一定看单位。

### 常见坑
- 忘了 `tm_year + 1900`
- 忘了 `tm_mon + 1`
- 用错误的时间单位解释结果
- 测性能时使用了不合适的时钟

### 记忆口诀
> **“`ctime` 看日历，`chrono` 看计时；时间点相减，得到时间差。”**

### 本章最该记住的 4 句话
1. `time_t` 更像传统时间点表示
2. `tm` 结构体里年份和月份都要修正显示
3. `chrono` 更适合现代计时和性能测量
4. 计时看“时间差”，显示看“时间点”

## 19. C++ 基本的输入输出

**一句话理解：** 输入输出就是程序和用户、文件、终端之间交换信息的通道；在入门阶段，最重要的是把 `cin`、`cout`、`getline`、缓冲行为理解清楚。

### 最基础的输出：`cout`
```cpp
cout << "Hello" << endl;
cout << "age = " << 18 << endl;
```

这里的 `<<` 可以理解成“把右边内容送进输出流”。

### 连续输出
```cpp
string name = "Alice";
int age = 20;
cout << "姓名: " << name << ", 年龄: " << age << endl;
```

你可以把多个内容拼在一起输出来，不需要手动转字符串。

### 最基础的输入：`cin`
```cpp
int a, b;
cin >> a >> b;
```

这表示从标准输入中读取两个整数。只要用户输入格式合法，空格、回车通常都能作为分隔。

### 为什么很多人第一次会踩坑
因为 `cin >>` 和 `getline` 的读取规则不同。

#### `cin >>` 的特点
- 会跳过前导空白
- 默认读到空格、回车、制表符就停
- 适合读“一个词”或基本类型

```cpp
string name;
cin >> name;
```

如果用户输入：
```text
Tom Hanks
```
那么只会读到 `Tom`。

#### `getline` 的特点
- 一直读到整行结束
- 适合读取带空格的文本

```cpp
string fullName;
getline(cin, fullName);
```

### 最常见的坑：`cin >>` 后紧接 `getline`
```cpp
int age;
string name;
cin >> age;
getline(cin, name); // 可能直接读到空串
```

为什么？
因为 `cin >> age` 读完数字后，输入缓冲区里往往还留着一个回车符，`getline` 一看“这一行结束了”，就直接返回空串。

### 解决方法
```cpp
cin >> age;
cin.ignore();
getline(cin, name);
```

更稳妥一点可以写：
```cpp
cin.ignore(numeric_limits<streamsize>::max(), '\n');
```

### 错误输出和日志输出
除了 `cout`，还常见：
- `cerr`：标准错误输出，适合输出错误信息
- `clog`：日志输出

```cpp
cerr << "输入错误！" << endl;
clog << "程序开始运行" << endl;
```

### 为什么 `endl` 不只是换行
`endl` 做两件事：
1. 换行
2. 刷新缓冲区

如果你只是想换行，更轻量的写法是：
```cpp
cout << "hello\n";
```

在大量输出时，频繁使用 `endl` 可能影响性能。

### 加速输入输出的常见写法
```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

### 这两句到底干了什么
- `ios::sync_with_stdio(false);`：关闭 C 和 C++ 标准流同步，提高速度
- `cin.tie(nullptr);`：解除 `cin` 和 `cout` 的绑定，减少不必要刷新

这在算法题或大数据输入场景中非常常见。

### 注意事项
如果你关闭同步后，又混用 `scanf/printf` 和 `cin/cout`，可能导致输出顺序混乱。初学者最好统一用一套。

### 格式化输出小例子
```cpp
#include <iomanip>

double price = 3.1415926;
cout << fixed << setprecision(2) << price << endl; // 3.14
```

这说明输出流还能控制格式，不只是简单打印。

### 输入失败怎么判断
```cpp
int x;
if (!(cin >> x)) {
    cerr << "读取失败" << endl;
}
```

这在处理不可靠输入时很有用。

### 记忆口诀
> **“`cin` 读到空白停，`getline` 一口吞整行；`endl` 会刷新，提速要解绑。”**

### 本章最该记住的 5 句话
1. `cout` 用于输出，`cin` 用于输入
2. `cin >>` 适合读单词和基本类型
3. `getline` 适合读整行文本
4. `cin >>` 后接 `getline` 要小心残留换行
5. 大量 I/O 时可以用 `ios::sync_with_stdio(false); cin.tie(nullptr);`

## 20. C++ 结构体(struct)

**一句话理解：** 当多个数据天然属于同一件事时，就别让它们散在各处；`struct` 就是把这些相关数据打包成一个有名字的整体。

### 为什么结构体特别适合入门阶段
写简单程序时，你可能会这样存学生信息：
```cpp
string name = "小明";
int age = 18;
double score = 98.5;
```

如果只有一个学生还行，但一旦学生变多，变量就会爆炸：
- `name1`, `age1`, `score1`
- `name2`, `age2`, `score2`

这时你会发现：**问题不是数据太多，而是数据之间缺少组织。**

结构体就是解决“相关数据应该放在一起”的工具。

### 基本定义与使用
```cpp
#include <iostream>
#include <string>
using namespace std;

struct Student {
    string name;
    int age;
    double score;
};

int main() {
    Student s{"小明", 18, 98.5};
    cout << s.name << " " << s.age << " " << s.score << endl;
}
```

### 怎么理解 `s.name`
- `s` 是一个 `Student` 对象
- `name` 是结构体里的一个成员
- `s.name` 表示访问这个对象的 `name` 字段

也就是说，结构体像一个“大箱子”，成员变量是箱子里的不同格子。

### 什么时候该想到结构体
#### 1）一条记录有多个属性
比如：
- 学生：姓名、年龄、成绩
- 商品：名称、价格、库存
- 坐标点：x、y
- 订单：编号、买家、金额、状态

#### 2）想把一组数据整体传给函数
```cpp
struct Point {
    int x;
    int y;
};

void printPoint(const Point& p) {
    cout << "(" << p.x << ", " << p.y << ")" << endl;
}
```

这样函数参数就更清晰，不用拆成很多零碎变量。

### 结构体数组：很常见
```cpp
Student arr[2] = {
    {"Alice", 20, 91.5},
    {"Bob", 19, 88.0}
};

cout << arr[0].name << endl;
cout << arr[1].score << endl;
```

这在“多条记录”场景里特别实用。

### 结构体指针怎么访问成员
```cpp
Student s{"Tom", 18, 90};
Student* p = &s;

cout << p->name << endl;
cout << p->score << endl;
```

这里的 `->` 可以理解成：
- 先通过指针找到对象
- 再访问对象成员

它和下面写法等价：
```cpp
cout << (*p).name << endl;
```

但 `->` 更简洁。

### `struct` 和 `class` 初学阶段怎么记
在 C++ 里它们非常像，入门阶段先记住一个最实用区别：
- `struct` 默认成员是 `public`
- `class` 默认成员是 `private`

如果你只是想表达“一组相关数据”，`struct` 很自然。

### 常见坑 1：以为结构体只能放数据
其实结构体里也可以放函数（成员函数），只是入门教程常先从“数据打包”开始。

### 常见坑 2：忘记对象和指针的访问写法不同
- 对象用 `.`
- 指针用 `->`

### 常见坑 3：声明完结构体忘了创建对象
```cpp
struct Student {
    string name;
    int age;
};
```

这只是定义了“类型”，不是自动创建变量。你还要写：
```cpp
Student s;
```

### 结构体为什么能让代码更好
- 数据不再散乱
- 名字更有语义
- 函数参数更清晰
- 后期更容易扩展

### 记忆口诀
> **“相关数据装一盒，对象点号取成员；若是指针来访问，箭头符号最顺手。”**

### 本章最该记住的 4 句话
1. 结构体用于组织相关数据
2. `对象.成员`，`指针->成员`
3. `struct` 是自定义类型，不是自动创建变量
4. 当多个字段本来属于同一件事时，应优先考虑结构体

## 21. C++ vector 容器

**一句话理解：** `vector` 可以看成“加强版数组”：保留数组按下标访问的方便，同时支持运行时动态扩容。

### 为什么很多场景里 `vector` 比数组更常用
普通数组有一个明显限制：长度通常要提前确定。

```cpp
int arr[100];
```

如果你一开始不知道将来会放多少元素，固定数组就不灵活。`vector` 的优势就在于：
- 可以一边运行一边增长
- 提供很多常用操作
- 与 STL 生态配合很好

### 基本写法
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v = {1, 2, 3};
    v.push_back(4);

    for (int x : v) {
        cout << x << " ";
    }
    cout << endl;
}
```

### 最常见的几个操作
#### 1）尾部追加：`push_back`
```cpp
v.push_back(10);
```

#### 2）删除尾部：`pop_back`
```cpp
v.pop_back();
```

注意：它不返回被删元素，只是删掉最后一个。

#### 3）查看大小：`size`
```cpp
cout << v.size() << endl;
```

#### 4）判断是否为空：`empty`
```cpp
if (v.empty()) {
    cout << "空" << endl;
}
```

#### 5）清空：`clear`
```cpp
v.clear();
```

### 下标访问
```cpp
cout << v[0] << endl;
```

这和数组很像，但要记住：**下标越界仍然是严重问题。**

如果想要更安全一点的检查式访问，可以用：
```cpp
cout << v.at(0) << endl;
```

`at()` 在越界时会进行范围检查，更适合调试阶段帮助发现错误。

### 遍历方式
#### 1）普通下标循环
```cpp
for (size_t i = 0; i < v.size(); ++i) {
    cout << v[i] << " ";
}
```

#### 2）范围 for
```cpp
for (int x : v) {
    cout << x << " ";
}
```

#### 3）引用遍历并修改
```cpp
for (int& x : v) {
    x *= 2;
}
```

### `vector` 底层为什么常说“连续内存”
这表示它在内存里通常像数组一样连续存放，所以：
- 按下标访问快
- 和 C 风格数组思路接近
- 但中间插入删除代价可能高，因为后面元素要移动

### `reserve` 和 `resize` 别混
#### `reserve(n)`
表示预留至少 `n` 个元素的容量，**不改变当前元素个数**。

#### `resize(n)`
表示把元素个数改成 `n`。
- 如果变大，会补默认值
- 如果变小，会截断多余元素

这两个名字很像，初学者非常容易记混。

### 一个例子看清区别
```cpp
vector<int> v;
v.reserve(10);
cout << v.size() << endl; // 0

v.resize(10);
cout << v.size() << endl; // 10
```

### 常见坑 1：空 vector 上取下标
```cpp
vector<int> v;
cout << v[0] << endl; // 错误
```

有下标不等于一定有元素。

### 常见坑 2：遍历时增删导致迭代器/引用失效
`vector` 扩容或中间插入删除时，原来的地址、指针、引用、迭代器可能失效。

入门阶段先记一句：
> **如果容器结构变了，之前拿着的“位置凭证”可能就不可靠了。**

### 常见坑 3：误以为中间插入很便宜
`vector` 最擅长的是：
- 尾部追加
- 按下标访问

如果你总在中间频繁插入删除，可能并不是最优结构。

### 什么时候优先想到 `vector`
- 元素个数不固定
- 需要频繁按下标访问
- 主要在尾部追加元素
- 想使用 STL 常见算法与容器风格

### 记忆口诀
> **“vector 像会长大的数组：查得快，尾插顺，中间改动成本高。”**

### 本章最该记住的 5 句话
1. `vector` 是动态数组
2. `push_back` 很常用，尾部追加最自然
3. `size` 看个数，`empty` 看是否为空
4. `reserve` 改容量倾向，`resize` 改实际元素个数
5. `vector` 适合随机访问和尾部增长，不擅长频繁中间插删

## 22. C++ 数据结构

**一句话理解：** 数据结构不是为了背定义，而是为了回答一个实战问题：**这批数据应该怎样组织，程序写起来才更快、更省、更不容易乱？**

### 为什么这章不该死背
很多初学者学数据结构时容易陷入一种误区：
- 数组要背
- 链表要背
- 栈队列要背
- 树图也要背

结果背了一堆名词，做题时还是不知道该选谁。

真正高效的学习方式是从“需求”出发：
- 你更常查找？
- 更常插入删除？
- 有没有先来后到顺序？
- 是不是层级关系？
- 节点之间是不是网状关系？

### 1）数组（Array）
#### 特点
- 连续存储
- 可以通过下标快速访问
- 插入删除通常要移动元素

#### 适合场景
- 已知元素个数或变化不大
- 需要频繁随机访问
- 数据逻辑上天然按编号访问

#### 心里记成一句话
> **“数组的优势是查得快。”**

### 2）链表（Linked List）
#### 特点
- 元素不是连续放的
- 每个节点知道下一个节点在哪
- 插入删除某个位置附近通常更灵活
- 但查找某个位置往往要一个个走过去

#### 适合场景
- 经常插入删除
- 不太依赖按下标随机访问

#### 初学者理解重点
链表的强项不是“查得快”，而是“改结构方便”。

### 3）栈（Stack）
#### 特点
- 后进先出（LIFO）
- 最后进去的元素最先出来

#### 典型场景
- 函数调用栈
- 撤销操作
- 括号匹配
- 深度优先搜索

#### 生活类比
像一摞盘子，只能从最上面拿。

### 4）队列（Queue）
#### 特点
- 先进先出（FIFO）
- 最早进入的最先离开

#### 典型场景
- 排队系统
- 任务调度
- 广度优先搜索
- 消息处理

#### 生活类比
像食堂排队，先来先服务。

### 5）哈希表（Hash Table）
C++ 里常见代表是：
- `unordered_map`
- `unordered_set`

#### 特点
- 常用于“键 -> 值”的快速映射
- 平均查找速度很快
- 适合通过 key 快速找到 value

#### 典型场景
- 统计次数
- 快速判重
- 建立编号与对象的对应关系

#### 要注意
哈希表非常强，但不是万能：
- 它不保证有序
- 某些场景下空间开销较大

### 6）树（Tree）
#### 特点
- 适合表达层级关系
- 有父节点、子节点的概念

#### 典型场景
- 文件目录
- 组织架构
- 表达式树
- 搜索结构

#### 初学重点
看到“层层往下分”的结构，就该联想到树。

### 7）图（Graph）
#### 特点
- 节点与节点之间的关系更自由
- 不一定是单一父子关系
- 可以表示复杂连接网络

#### 典型场景
- 地图路径
- 社交关系
- 网络拓扑
- 推荐系统关系建模

#### 初学重点
看到“点和点之间可以任意连”，就该想到图。

### 选结构时最实用的思考顺序
#### 第一问：是否需要按位置快速访问？
- 是：先想数组 / `vector`

#### 第二问：是否经常插入删除中间元素？
- 是：考虑链表或别的更适合修改结构的容器

#### 第三问：是否有明显先来后到顺序？
- 后进先出：栈
- 先进先出：队列

#### 第四问：是否需要通过 key 快速查？
- 是：哈希表

#### 第五问：是否是层级结构或网络关系？
- 层级：树
- 网络：图

### 一个入门级对照表
| 结构 | 最大特点 | 擅长什么 |
|---|---|---|
| 数组 / vector | 连续、按下标访问快 | 快速随机访问 |
| 链表 | 插删灵活 | 频繁结构修改 |
| 栈 | 后进先出 | 撤销、递归、匹配 |
| 队列 | 先进先出 | 排队、调度、BFS |
| 哈希表 | 按 key 快找 | 判重、计数、映射 |
| 树 | 层级结构 | 目录、分层组织 |
| 图 | 关系复杂 | 路径、网络、关联 |

### 本章最重要的学习观念
**数据结构的本质不是“哪个高级”，而是“哪个更适合当前操作模式”。**

别问“哪个最好”，要问：
- 我最常做什么操作？
- 这类操作的成本高不高？
- 代码会不会因此更清晰？

### 初学者常见误区
#### 1）以为数据结构就是考试名词
其实它是写程序时的“组织策略”。

#### 2）以为数组落后、图很高级
不是。合适的才是好的。简单场景用数组反而最清楚。

#### 3）只背定义，不结合场景
真正能记住的，不是抽象定义，而是“什么问题该想到什么结构”。

### 记忆总口诀
> **“快查想数组，快改想链表；后进用栈，先进用队；按键快找用哈希，分层是树，连网是图。”**

### 本章最该记住的 5 句话
1. 数据结构是为操作服务的，不是为背诵服务的
2. 数组 / vector 擅长随机访问
3. 栈和队列处理顺序问题最自然
4. 哈希表擅长快速查找映射关系
5. 树和图适合表达复杂关系，但不要在简单问题上过度使用复杂结构

- **数据类型**：决定能装什么
- **变量**：有名字的存储位置
- **作用域**：在哪儿有效
- **常量**：值不能随便改
- **修饰符**：给类型加范围/符号
- **存储类**：控制生命周期和可见性
- **运算符**：让数据参与运算
- **循环**：重复执行
- **判断**：分支选择
- **函数**：复用代码
- **数字**：整数、小数、数学函数
- **数组**：连续同类型数据
- **字符串**：字符序列
- **指针**：地址
- **引用**：别名
- **日期 & 时间**：时间点与时间差
- **输入输出**：程序和外界对话
- **结构体**：打包相关数据
- **vector**：动态数组
- **数据结构**：按问题选工具

## 学习建议
先把这些关键词真正说顺：**地址、别名、作用域、常量、数组、字符串、指针、引用、vector**。

只要你能用自己的话讲清楚它们，后面做题和写代码都会顺很多。
