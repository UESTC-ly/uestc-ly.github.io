## 1. C++ 类 & 对象

### 1.1 一句话抓本质
**类是蓝图，对象是按蓝图造出来的具体东西。**

学面向对象时，最先要弄清的不是语法，而是角色：
- **类**负责描述“这类东西应该有什么属性、会做什么事情”
- **对象**负责把类里的定义变成一个真正能用的实例

你可以把类想成“设计图”，把对象想成“按图纸做出来的房子”。设计图本身不能住人，但房子可以；同样，类本身不能直接存一个“具体学生的名字”，但它可以定义“学生应该有哪些属性”。

### 1.2 类到底是什么
类（class）是一种**自定义数据类型**。它把“属性”和“行为”放在一起，避免你把很多零散变量散得到处都是。

比如“人”这个类，通常可以有：
- 属性：姓名、年龄、身高、性别
- 行为：说话、走路、吃饭、学习

如果用过程式写法，你可能会写一堆零散变量：
```cpp
string name;
int age;
double height;
```
面向对象更希望你把这些信息包进一个类里，让它们属于“同一个概念”。

### 1.3 对象到底是什么
对象（object）是类的实例。

也就是说：
- 类只是“定义”
- 对象才是“使用”

例如：
- 张三是一个对象
- 李四是一个对象
- 它们都属于“Person”这个类，但各自的数据不同

### 1.4 最小可运行示例
```cpp
#include <iostream>
#include <string>
using namespace std;

class Person {
public:
    string name;
    int age;

    void introduce() {
        cout << "我叫" << name << ", 今年" << age << "岁" << endl;
    }
};

int main() {
    Person p1;
    p1.name = "小明";
    p1.age = 18;
    p1.introduce();

    Person p2;
    p2.name = "小红";
    p2.age = 20;
    p2.introduce();

    return 0;
}
```

### 1.5 这段代码怎么读
- `class Person`：定义一个类
- `public:`：表示这里面的成员可以被外部访问
- `string name; int age;`：属性
- `void introduce()`：行为
- `Person p1;`：创建对象
- `p1.name = "小明";`：给对象赋值

### 1.6 成员变量和成员函数
类里面的变量叫**成员变量**，类里面的函数叫**成员函数**。

#### 成员变量
对象自己的状态，比如：
- `name`
- `age`
- `score`

#### 成员函数
对象自己的行为，比如：
- `introduce()`
- `run()`
- `sleep()`

### 1.7 `this` 指针先有个概念
在成员函数里面，`this` 代表“当前这个对象自己”。

比如：
```cpp
class Student {
public:
    string name;

    void show() {
        cout << this->name << endl;
    }
};
```
初学阶段先记住：
- 成员函数调用的是“某个对象自己的数据”
- `this` 可以理解成“当前对象的地址”

### 1.8 封装之前先感受“为什么要封装”
如果一个类里的数据全部都能随便改，代码会很容易失控。

例如：
```cpp
class BankAccount {
public:
    double balance;
};
```
这样外部代码就能直接写：
```cpp
account.balance = -999999;
```
这显然不合理。后面学“封装”时，解决的就是这类问题。

### 1.9 构造函数：对象出生时先做初始化
构造函数（constructor）是对象创建时自动执行的函数，常用来初始化成员变量。

```cpp
class Student {
public:
    string name;
    int age;

    Student(string n, int a) {
        name = n;
        age = a;
    }
};
```

构造函数的好处：
- 不用每次创建对象后再一行一行赋值
- 一出生就有合理状态

### 1.10 默认构造、带参构造、拷贝构造先知道名字
这里先记住这三个名字：
- **默认构造函数**：不传参数就能创建对象
- **带参构造函数**：创建时带参数
- **拷贝构造函数**：用一个对象初始化另一个对象

初学阶段不要求一次全背会，但要知道它们都是“对象出生时”会用到的函数。

### 1.11 类和结构体的差别
在 C++ 里，`class` 和 `struct` 很像，主要区别通常是默认访问权限：
- `class` 默认是 `private`
- `struct` 默认是 `public`

初学阶段可以先记：
> `class` 更常用于面向对象建模，`struct` 常用于简单数据打包。

### 1.12 记忆口诀
> **类是图纸，对象是成品；属性放数据，函数放动作。**

### 1.13 本章常见坑
- 把类和对象混成一回事
- 忘了对象要先创建再访问成员
- 把成员变量直接暴露给外部随便改
- 没初始化对象状态就开始使用

### 1.14 小练习
1. 写一个 `Car` 类，包含品牌、颜色、价格三个属性。
2. 给 `Car` 写一个 `show()` 函数输出信息。
3. 创建两个对象，分别设置不同属性并输出。

## 2. C++ 继承

### 2.1 一句话抓本质
**继承的本质是：让新类复用旧类的能力，并在此基础上增加自己的新能力。**

如果说类和对象是在定义“一个具体的东西”，那继承就是在定义“这一类东西之间的关系”。它最常见的语义是 **is-a（是一个）**：
- `Dog` 是一个 `Animal`
- `Student` 是一个 `Person`
- `Teacher` 也是一个 `Person`

如果两个类不是“是一个”的关系，通常就不要乱用继承。

### 2.2 为什么要有继承
继承最直接的作用是减少重复代码。

比如：
- 猫和狗都属于动物
- 它们都有名字、年龄、吃饭等共性
- 但又各自有不同特征

如果不使用继承，你可能会在多个类里重复写一模一样的成员。

### 2.3 最基础写法
```cpp
class Animal {
public:
    void eat() {
        cout << "Animal is eating" << endl;
    }
};

class Dog : public Animal {
public:
    void bark() {
        cout << "Dog is barking" << endl;
    }
};
```

### 2.4 调用父类能力
```cpp
int main() {
    Dog d;
    d.eat();
    d.bark();
    return 0;
}
```

这说明子类不仅有自己的能力，也能复用父类的能力。

### 2.5 public / protected / private 继承先有个概念
继承时最常见的是 `public` 继承：
```cpp
class Dog : public Animal {
};
```
它表达“Dog 是一种 Animal”。

简单理解：
- `public` 继承：最常见，语义最清晰
- `protected` 继承：较少见，初学阶段先认识名字即可
- `private` 继承：更少见，通常不作为初学重点

### 2.6 构造顺序和析构顺序
继承里一个很重要的规则：
- **先构造父类，再构造子类**
- **先析构子类，再析构父类**

你可以把它理解成：
- 房子先把地基打好，再盖上层
- 拆房子时先拆上层，再拆地基

### 2.7 方法重写（override）
子类可以重新定义父类同名函数，让行为更符合自己的特点。

```cpp
class Animal {
public:
    void speak() {
        cout << "Animal speaks" << endl;
    }
};

class Cat : public Animal {
public:
    void speak() {
        cout << "Cat says meow" << endl;
    }
};
```

### 2.8 继承中的访问控制
父类的 `public` 成员在子类中通常可以直接访问；但 `private` 成员不能直接访问。

```cpp
class Base {
private:
    int secret = 10;
public:
    int value = 20;
};
```

子类通常只能直接访问父类允许它访问的部分。

### 2.9 继承不是复制粘贴
这是很重要的观念：
- 继承不是把父类代码复制一份
- 而是建立一种“从父类到子类”的关系
- 子类对象里会包含父类部分

### 2.10 什么时候该用继承
适合继承的场景：
- 子类就是父类的一种
- 需要复用公共代码
- 需要统一接口，具体实现不同

不适合继承的场景：
- 两个类只是“有一点相似”
- 更适合“组合”而不是“是一个”

### 2.11 常见坑
- 以为所有复用都应该用继承
- 把“has-a（有一个）”关系硬写成继承
- 忘了构造顺序
- 把父类函数重写和函数重载混为一谈

### 2.12 记忆口诀
> **父类放共性，子类加个性；先看“是不是”，再决定继承。**

### 2.13 小练习
1. 写一个 `Animal` 基类，包含 `eat()`。
2. 写 `Dog` 和 `Cat` 两个子类，分别增加自己的行为。
3. 让子类对象同时调用父类函数和自己的函数。

## 3. C++ 重载运算符和重载函数

### 3.1 一句话先抓本质
**重载的本质是：让同一个名字在不同场景下更自然地工作。**

重载通常分两类：
- **函数重载**：函数名相同，但参数不同
- **运算符重载**：让 `+`、`==` 这类运算符适用于自定义类型

### 3.2 函数重载
函数重载（overload）要求函数名一样，但参数列表不同。

```cpp
#include <iostream>
using namespace std;

void print(int x) {
    cout << "整数：" << x << endl;
}

void print(double x) {
    cout << "小数：" << x << endl;
}

void print(string x) {
    cout << "字符串：" << x << endl;
}
```

这样写的好处是：
- 不用想一堆奇怪函数名
- 同类功能用同一个名字更好记
- 调用时编译器会根据参数自动选择版本

### 3.3 函数重载的核心规则
只要参数列表不同，就可能构成重载。

常见形式：
- 参数个数不同
- 参数类型不同
- 参数顺序不同

但要注意：
- 仅仅返回值不同，**不能**构成重载

### 3.4 运算符重载
运算符重载就是把普通的符号运算能力扩展到自定义类型。

例如，两个复数对象也希望能相加：
```cpp
class Complex {
public:
    double real;
    double imag;

    Complex(double r = 0, double i = 0) {
        real = r;
        imag = i;
    }

    Complex operator+(const Complex& other) {
        return Complex(real + other.real, imag + other.imag);
    }
};
```

### 3.5 为什么要重载运算符
如果不重载，你可能只能写：
```cpp
c3 = addComplex(c1, c2);
```
重载后可以更自然：
```cpp
c3 = c1 + c2;
```
这更接近人类书写习惯，也更容易读。

### 3.6 常见可重载的运算符
常见如：
- `+`
- `-`
- `==`
- `<<`
- `>>`
- `[]`

但不是所有运算符都能随便改得天翻地覆，通常要遵循它本来的语义。

### 3.7 `<<` 输出重载的经典例子
```cpp
class Point {
public:
    int x;
    int y;

    Point(int px = 0, int py = 0) {
        x = px;
        y = py;
    }

    friend ostream& operator<<(ostream& os, const Point& p) {
        os << "(" << p.x << ", " << p.y << ")";
        return os;
    }
};
```

这样就能：
```cpp
Point p(3, 4);
cout << p << endl;
```

### 3.8 为什么 `friend` 常会出现
有些运算符重载写成普通成员函数不方便，比如 `cout << p` 这种形式中，左边是流对象，右边才是自定义对象，所以常写成友元函数。

### 3.9 重载时最重要的原则
- 保持语义自然
- 不要让运算符“表面像加法，实际干别的事”
- 能用普通函数表达清楚时，不要硬重载

### 3.10 常见坑
- 把返回值类型写错
- 忘记返回对象或流引用
- 过度重载，导致代码不好理解
- 把“函数重载”和“运算符重载”混成一回事

### 3.11 小练习
1. 写一个 `add` 函数重载，分别处理两个 `int`、两个 `double`。
2. 写一个 `Complex` 类，实现 `+` 运算符重载。
3. 写一个 `Point` 类，实现 `<<` 输出重载。

## 4. C++ 多态

### 4.1 一句话抓本质
**多态的核心是：同样的调用接口，在运行时可以表现出不同的行为。**

多态真正有价值的地方在于：
- 调用者只关心“调用什么接口”
- 具体做什么由不同子类自己决定
- 这样代码更灵活，也更适合扩展

### 4.2 为什么需要多态
假设你要让不同动物“叫”一声。
如果不用多态，你可能得写很多分支：
```cpp
if (type == "cat") { ... }
else if (type == "dog") { ... }
```
当动物种类越来越多时，代码会越来越臃肿。

多态想解决的就是：
> 让“调用方”不必关心“具体是谁”，只要知道“它会叫”就行。

### 4.3 运行时多态的基本思路
C++ 最常见的是**通过基类指针或基类引用**来实现运行时多态。

```cpp
class Animal {
public:
    virtual void speak() {
        cout << "Animal speaks" << endl;
    }
};

class Cat : public Animal {
public:
    void speak() override {
        cout << "Cat says meow" << endl;
    }
};

class Dog : public Animal {
public:
    void speak() override {
        cout << "Dog says woof" << endl;
    }
};
```

### 4.4 为什么要加 `virtual`
`virtual` 告诉编译器：这个函数希望在运行时根据真实对象类型决定调用谁。

没有 `virtual`，父类指针/引用可能只会按父类版本执行；有了 `virtual`，才能体现多态。

### 4.5 `override` 的意义
`override` 的作用是告诉编译器：
- 我就是在重写父类函数
- 如果签名写错了，请直接报错

这能显著减少低级错误。

### 4.6 一个典型例子
```cpp
Animal* a1 = new Cat();
Animal* a2 = new Dog();

a1->speak();
a2->speak();
```

输出结果会根据真实对象决定。

### 4.7 虚析构函数很重要
如果父类会被当成基类指针使用，析构函数通常要写成 `virtual`，否则可能只调用父类析构，不完整释放资源。

### 4.8 多态不是“到处都能变”
多态的关键不是“对象随便变”，而是“通过统一接口，运行时决定具体行为”。

### 4.9 常见坑
- 忘记写 `virtual`
- 重写函数签名写错
- 用对象值传递，切片导致多态失效
- 忘记虚析构函数

### 4.10 记忆口诀
> **编译看接口，运行看对象；virtual 开门，override 防错。**

### 4.11 小练习
1. 写一个 `Animal` 基类和 `Cat`、`Dog` 子类。
2. 用 `Animal*` 指向不同子类对象，调用同一个函数。
3. 给基类加虚析构函数，观察结构上的变化。

## 5. C++ 数据抽象

### 5.1 一句话抓本质
**数据抽象就是：对外只展示“能做什么”，不强行让使用者关心“内部怎么做”。**

抽象的目标不是“神秘”，而是“简单”。好的抽象会把复杂细节藏起来，只留下最有意义的接口。

### 5.2 抽象到底在抽什么
抽象不是把东西变少，而是把“无关紧要的细节”先拿掉，只保留关键特征。

比如你用电风扇时通常只关心：
- 开关
- 风速
- 摇头

你不会想知道电机每一根线怎么绕。程序设计也是一样：调用者只想知道“怎么用”，不想先研究“里面怎么转”。

### 5.3 抽象的价值
- 降低理解成本
- 降低使用错误
- 提高代码复用
- 让接口更稳定

### 5.4 用一个类来理解抽象
```cpp
class Fan {
public:
    void turnOn() {
        cout << "风扇打开" << endl;
    }

    void setSpeed(int level) {
        cout << "风速设置为" << level << endl;
    }
};
```

使用者只要知道 `turnOn()` 和 `setSpeed()` 就够了。

### 5.5 抽象和封装的区别先有个感觉
- 抽象：强调“抓住本质能力”
- 封装：强调“把内部细节保护起来”

这两个概念很接近，但关注点不同。

### 5.6 抽象类先埋个伏笔
很多时候抽象会通过“接口/抽象类”体现出来：
- 先规定“必须有什么能力”
- 具体怎么做，留给子类

### 5.7 记忆口诀
> **抽象先看能力，不先看细节；越是能复用的接口，越值得抽象。**

### 5.8 常见坑
- 把抽象理解成“写得很少”
- 把抽象和封装完全混为一谈
- 过度抽象，接口多到自己都记不住

### 5.9 小练习
1. 想一个你熟悉的对象（例如风扇、手机、闹钟），列出它对外最关键的 3 个能力。
2. 试着用一个类把这些能力表示出来。

## 6. C++ 数据封装

### 6.1 一句话抓本质
**封装就是：把数据和操作包在一起，并且尽量不让外部直接乱改内部状态。**

如果说抽象关注“对外展示什么”，那封装更关注“怎么保护内部数据”。

### 6.2 为什么要封装
如果类里的数据完全公开，外部代码可能随手就把它改坏：
```cpp
class BankAccount {
public:
    double balance;
};
```
这样的话，任何人都能把余额改成负数，逻辑就会崩。

封装要解决的核心问题就是：
> 让对象自己管理自己的状态，不要让外部直接随便碰。

### 6.3 访问控制修饰符
最常见的封装方式是用访问控制：
- `public`：外部可见
- `private`：仅类内部可见
- `protected`：子类可见（初学阶段先认识即可）

### 6.4 一个更合理的例子
```cpp
class BankAccount {
private:
    double balance;

public:
    BankAccount(double b = 0) {
        balance = b;
    }

    void deposit(double money) {
        if (money > 0) {
            balance += money;
        }
    }

    void withdraw(double money) {
        if (money > 0 && money <= balance) {
            balance -= money;
        }
    }

    double getBalance() const {
        return balance;
    }
};
```

### 6.5 封装的关键：保持不变量
“**不变量**”可以理解为对象必须一直满足的规则。

比如银行账户的余额：
- 不能随便变成负数
- 不能被外部直接乱改

封装的价值就在于维护这种规则。

### 6.6 getter / setter
很多类会提供：
- `getXXX()`：读取数据
- `setXXX()`：修改数据

但要注意：
- 不是所有字段都必须提供 setter
- 有些数据只读更安全

### 6.7 封装和“写得复杂”不是一回事
好的封装不是把代码搞复杂，而是把“该让谁改、该让谁看”说清楚。

### 6.8 常见坑
- 把所有成员都写成 public
- getter / setter 滥用到没有原则
- 为了封装而封装，接口反而很难用

### 6.9 记忆口诀
> **封装像上锁：外部能用，但不能乱拆；重要数据不外露，规则由类自己守。**

### 6.10 小练习
1. 写一个 `Student` 类，把成绩设成 `private`。
2. 只允许通过函数修改成绩，并保证成绩在 0~100 之间。

## 7. C++ 接口（抽象类）

### 7.1 一句话抓本质
**接口（抽象类）就是先规定“你必须会哪些功能”，至于“怎么实现”，留给具体子类自己决定。**

接口思想最适合用来统一标准：
- 不同对象遵守同一套规则
- 调用方只依赖规则，不依赖具体实现
- 这样扩展性更强

### 7.2 什么是抽象类
抽象类是**不能直接实例化**的类，通常用来定义接口规范。

```cpp
class Shape {
public:
    virtual void draw() = 0;
};
```

这里 `= 0` 表示纯虚函数。只要类里有纯虚函数，这个类通常就是抽象类。

### 7.3 为什么需要接口
比如我们想让不同形状都能“画出来”：
- 圆形怎么画
- 矩形怎么画
- 三角形怎么画

它们具体画法不同，但都应该有一个统一入口：`draw()`。

### 7.4 一个典型接口例子
```cpp
class Shape {
public:
    virtual void draw() = 0;
    virtual double area() = 0;
    virtual ~Shape() {}
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Draw Circle" << endl;
    }

    double area() override {
        return 3.14 * 1 * 1;
    }
};
```

### 7.5 接口的作用
- 统一调用方式
- 降低耦合
- 方便扩展新实现

### 7.6 抽象类和普通类的区别
普通类：可以直接创建对象。抽象类：通常不能直接创建对象，只能给子类继承并实现。

### 7.7 虚函数表先有个概念
多态和接口常常一起出现，它们背后依赖虚函数机制。初学阶段不必钻得太深，只要知道：
- `virtual` 让运行时决定调用哪个版本
- 抽象类用纯虚函数定义统一接口

### 7.8 常见坑
- 忘记给抽象类写虚析构函数
- 纯虚函数写了 `= 0` 但子类没实现
- 把接口和“只是写几个 public 函数”混成一回事

### 7.9 记忆口诀
> **接口先定标准，实现交给子类；抽象类不直接用，靠继承来补齐。**

### 7.10 小练习
1. 设计一个 `Shape` 接口，至少包含 `draw()` 和 `area()`。
2. 实现 `Circle` 和 `Rectangle` 两个子类。
3. 用基类指针统一调用它们。

## 复习小抄
- **类 & 对象**：类是蓝图，对象是成品
- **继承**：子类复用父类能力，表达 is-a 关系
- **重载**：同名函数不同参数；运算符也能变得更自然
- **多态**：同一接口，运行时表现不同
- **数据抽象**：对外只保留关键能力
- **数据封装**：保护内部数据和不变量
- **接口（抽象类）**：统一标准，子类负责实现

## 学习建议
先把这几个关键词真正说顺：**蓝图、成品、共性、个性、接口、封装、抽象、多态**。

只要你能用自己的话讲清楚它们，后面的类设计、代码复用和架构思维都会顺很多。
