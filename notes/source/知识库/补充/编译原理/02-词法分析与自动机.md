## 分章节讲解
### 1. Token
**核心定义：** Token 是词法单元，包括类别和属性值，如标识符、关键字、数字字面量。

**理解路径：**
- 先明确它解决的具体问题，再判断它依赖的前提条件。
- 把它放回“词法分析把字符流切成带类别和属性的 Token 流。”这条主线中理解，不要孤立记忆。
- 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

**常见误区：** Token 不是单个字符；空白和注释通常被过滤但仍影响位置信息。

### 2. 正则表达式
**核心定义：** 正则表达式描述词法模式，可系统转换为有限自动机。

**理解路径：**
- 先明确它解决的具体问题，再判断它依赖的前提条件。
- 把它放回“词法分析把字符流切成带类别和属性的 Token 流。”这条主线中理解，不要孤立记忆。
- 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

**常见误区：** 正则无法表达任意嵌套结构，括号匹配属于语法分析范畴。

### 3. NFA 与 DFA
**核心定义：** NFA 可有 ε 转移和多条选择，DFA 每个状态每个输入只有唯一转移；二者表达能力等价。

**理解路径：**
- 先明确它解决的具体问题，再判断它依赖的前提条件。
- 把它放回“词法分析把字符流切成带类别和属性的 Token 流。”这条主线中理解，不要孤立记忆。
- 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

**常见误区：** DFA 可能状态爆炸；实现词法器时常用表压缩。

### 4. 最长匹配原则
**核心定义：** 词法器通常采用最长匹配和优先级规则解决关键字、标识符、操作符冲突。

**理解路径：**
- 先明确它解决的具体问题，再判断它依赖的前提条件。
- 把它放回“词法分析把字符流切成带类别和属性的 Token 流。”这条主线中理解，不要孤立记忆。
- 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

**常见误区：** 只按最先匹配规则会把 >= 错切成 > 和 =。

## 实战深化：正则、自动机与最长匹配

### 1. 底层机制拆解
词法分析把字符流分成 Token；DFA 的状态转移让匹配过程线性化，最长匹配和优先级解决冲突。

```mermaid
flowchart LR
  A[输入/前提] --> B[核心结构]
  B --> C[处理规则]
  C --> D[输出结论]
  D --> E[验证边界]
```

### 2. 适用与不适用
| 判断点 | 适用信号 | 不适用/风险信号 |
|---|---|---|
| 前提 | 对象、约束和目标清晰 | 概念边界含糊或约束缺失 |
| 机制 | 能说明中间状态如何变化 | 只能背结论，无法解释过程 |
| 成本 | 复杂度、维护成本或风险可接受 | 资源、复杂度或安全边界失控 |
| 验证 | 有样例、测试、证明或观测证据 | 无法复现、无法审计、无法回滚 |

### 3. 案例理解
关键字 if 与标识符 ifx 冲突时，词法器应先最长匹配，再用关键字表判定类别。

### 4. 常见误区与纠正
- **误区：** 只记概念定义，不问前提。**纠正：** 每次回答都先说适用条件。
- **误区：** 用单个样例证明普遍正确。**纠正：** 补充边界样例、反例或不变量。
- **误区：** 忽略工程成本。**纠正：** 同时说明性能、可靠性、安全性和维护代价。
