## 本轮扩写：安全、成本与改进闭环

### 1. LLM 成本治理要看单次成本和失败重试成本
| 成本来源 | 典型原因 | 控制方式 | 误区 |
|---|---|---|---|
| Prompt token | 上下文过长 | 摘要、裁剪、结构化上下文 | 盲目塞全量文档 |
| Completion token | 输出无约束 | 限制格式和长度 | 让模型自由发挥 |
| 检索成本 | 召回过宽、重排过重 | 分层召回、缓存、TopK 控制 | 每次都全量重排 |
| 工具调用 | Agent 循环调用 | 最大步数、状态缓存 | 只看模型费用不看工具费用 |
| 失败重试 | 输出不合规 | schema 校验、少量重试 | 无限重试直到成功 |

### 2. 数据保护边界
- 训练数据、评测数据、线上日志和用户输入要分别定义保留周期和脱敏策略。
- Prompt 和 RAG 上下文可能携带隐私，不能默认写入可共享日志。
- 权限要在检索前和生成前双重检查，避免“搜不到但上下文已泄露”。
- 审计日志要记录谁在什么场景访问了什么数据，但不能记录明文敏感内容。

### 3. 持续改进闭环
```mermaid
flowchart LR
  A[线上失败样本] --> B[归因分类]
  B --> C[补充评测集]
  C --> D[改 Prompt/RAG/模型]
  D --> E[离线回归]
  E --> F[灰度发布]
  F --> A
```

- 失败样本要按检索、事实、格式、安全、工具、权限、成本分类。
- 每次改动都要记录版本和动机，避免“感觉变好”。
- 评测集要保留长尾和反例，不能只保留容易通过的样本。

- “如何降低 LLM 成本？”——回答模型路由、上下文压缩、缓存、批处理、工具预算和失败重试控制。
- “如何处理用户隐私？”——回答最小化收集、脱敏、权限、审计、保留周期和删除机制。
- “如何持续提升效果？”——回答失败归因、评测集扩充、版本化、灰度和回滚。
