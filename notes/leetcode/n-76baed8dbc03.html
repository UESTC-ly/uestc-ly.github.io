一、215. 数组中的第 K 个最大元素

1. 题意

给定整数数组 nums 和整数 k，返回数组排序后的第 k 个最大元素。

注意：

求的是第 k 个最大元素，而不是第 k 个不同的元素，重复值也要参与排名。

例如：

nums = [3,2,3,1,2,4,5,5,6], k = 4

降序排列：[6,5,5,4,3,3,2,2,1]
第 4 大元素：4

2. 核心思路：大小为 k 的小顶堆

维护一个元素数量不超过 k 的小顶堆，保存遍历到目前为止最大的 k 个元素。

处理每个数字时：

1. 将当前数字加入小顶堆；
2. 如果堆的大小超过 k，删除堆顶；
3. 遍历结束后，堆顶就是第 k 大元素。

为什么使用小顶堆？

  • 我们希望保留最大的 k 个元素；
  • 当堆中暂时有 k + 1 个元素时，应淘汰其中最小的元素；
  • 小顶堆可以通过 top() 和 pop() 快速删除最小值。

最终堆中保存整个数组最大的 k 个元素，其中最小的一个正是第 k 大元素。

3. 示例推演

nums = [3,2,1,5,6,4], k = 2

为了便于理解，下表按从小到大展示堆中保留的元素；堆的底层数组并不保证完全有序。

当前数字 处理后的堆中元素 说明
3 [3] 加入 3
2 [2,3] 堆大小为 2
1 [2,3] 加入后删除最小值 1
5 [3,5] 加入后删除最小值 2
6 [5,6] 加入后删除最小值 3
4 [5,6] 加入后删除最小值 4

最终堆顶为 5，即第 2 大元素。

4. C++ 代码

class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        // 小顶堆：堆顶是当前堆中的最小元素
        priority_queue<int, vector<int>, greater<int>> minHeap;

        for (int num : nums) {
            minHeap.push(num);

            // 始终只保留最大的 k 个元素
            if (minHeap.size() > k) {
                minHeap.pop();
            }
        }

        // 最大的 k 个元素中最小的一个，就是第 k 大元素
        return minHeap.top();
    }
};

5. 复杂度

时间复杂度：O(n log k)
空间复杂度：O(k)

堆解法简单、稳定且常用，但严格来说不是题目要求的线性时间；若必须达到期望 O(n)，可使用快速选择。

6. 记忆

第 k 大：用大小为 k 的小顶堆保留最大的 k 个元素，最后返回堆顶。

7. 补充解法：快速选择

以下内容合并自《专题/快速选择专题.md》。堆适合保留 Top K；快速选择适合只求第 K 个元素。

题型判断

这题也是：快速选择 / 第 k 大元素。

关键信号很明显：

  • 要第 k 大
  • 不要求整体排序
  • 要求时间复杂度 O(n)

这种题不要第一反应就全排序，优先想快速选择。

题目白话

把数组从大到小排一遍：

  • 第 1 大就是最大的数
  • 第 2 大就是第二大的数
  • 第 k 大就是排在第 k 个位置的数

例如：

nums = [3,2,1,5,6,4], k = 2

从大到小排序后是：

[6,5,4,3,2,1]

第 2 大是 5。

注意：题目说的是“第 k 个最大元素”，不是“第 k 个不同元素”，所以重复元素要算进去。

为什么想到快速选择

如果直接排序，时间复杂度是：

O(n log n)

但题目要求设计 O(n) 的算法，所以要用快速选择。

核心仍然是：

  • 用 partition 把数组切开
  • 只关心某个排名位置
  • 不把整个数组排完

关键转化

这题最关键的一步是把“第 k 大”转成“升序下标 n - k”（按从 1 开始的名次，是第 n - k + 1 小）。

如果数组按升序排好，第 k 大元素对应的下标是：

target = nums.size() - k;

例如：

[1,2,3,4,5,6], k = 2

第 2 大是 5，它在升序数组里的下标是 6 - 2 = 4。

所以这题就变成了：

找数组中下标 n - k 的那个数。

核心思路

每次做一次 partition，得到 pivot 最终位置 p：

  • 如果 p == target，直接返回 nums[p]
  • 如果 p > target，说明答案在左边，继续缩小到左半边
  • 如果 p < target，说明答案在右边，继续缩小到右半边

这一套和前面的 LCR 159 本质完全一样，只是目标下标换成了 n - k。

C++ 代码实现

class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        int target = nums.size() - k;
        int left = 0, right = nums.size() - 1;

        while (left <= right) {
            int p = partition(nums, left, right);
            if (p == target) {
                return nums[p];
            } else if (p > target) {
                right = p - 1;
            } else {
                left = p + 1;
            }
        }

        return -1;
    }

private:
    int partition(vector<int>& nums, int left, int right) {
        int pivotIndex = left + rand() % (right - left + 1);
        swap(nums[left], nums[pivotIndex]);

        int pivot = nums[left];
        int i = left, j = right;

        while (i < j) {
            while (i < j && nums[j] >= pivot) j--;
            while (i < j && nums[i] <= pivot) i++;
            if (i < j) swap(nums[i], nums[j]);
        }

        swap(nums[left], nums[i]);
        return i;
    }
};

关键细节

1. 为什么 target = n - k

因为题目问的是“第 k 大”，不是“第 k 小”。

升序数组里，第 k 大的位置正好是：

n - k

这个转化一定要先想清楚，再去写快速选择。

2. 为什么返回 nums[p]

当 partition 返回的 p == target 时，说明这个位置上的数就是第 k 大。

这时直接返回 nums[p] 就行。

3. 为什么和 LCR 159 是同一套路

LCR 159 是：

  • 找最小的 cnt 个数
  • 目标下标是 cnt - 1

这题是：

  • 找第 k 大
  • 目标下标是 n - k

本质都在找“某个排名边界”。

复杂度分析

  • 时间复杂度：平均 O(n)，最坏 O(n^2)
  • 空间复杂度：O(1)

随机 pivot 能缓解有序输入造成的极端划分；但上面两路划分在大量重复值（例如全相等）时仍可能反复只排除一个元素，随机选取不能消除这种退化。下面的三路版本一次处理整个相等区间。

记忆口诀 / 一眼识别信号

口诀：

第 k 大，先转成升序下标 n-k，再用快选找边界。

一眼识别信号：

  • 第 k 大
  • 第 k 小
  • Top K
  • 返回顺序不限

一类题总结

这题和 LCR 159 一起记最好：

  • LCR 159：找最小的 cnt 个，目标是 cnt - 1
  • 215：找第 k 大，目标是 n - k

它们都是：

不全排，只找目标排名位置。

快速选择的真正用途就是把“找第几个”这类问题，压缩成一次或几次 partition。

快速选择的本质：

用快速排序的 partition，只排答案所在的一边。

这题最容易混的点

  • p 是 partition 后 pivot 的最终位置，不是扫描指针位置。
  • partition 不是完整快排，它只负责“切一刀”。
  • 这里用的是交换法 partition，不是挖坑法，但两者目标一致。
  • 本题只要升序下标 n-k 对应的值，不要求整体排序；返回最小的 cnt 个数是 LCR 159 的需求。

8. 增量补充：随机三路快速选择

主堆解法保留不变；若希望期望 O(n)，可用本次讲解的三路快选，将重复值一次归到等于区域。

[left, lt-1]：小于 pivot
[lt, i-1]：等于 pivot
[i, gt]：尚未处理
[gt+1, right]：大于 pivot

遇到小值，与 lt 交换，lt、i 一起前进；遇到等值，只前进 i；遇到大值，与 gt 交换并缩小 gt，i 不前进，因为右边换来的元素还未检查。

class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        int n = nums.size();
        int target = n - k;
        int left = 0, right = n - 1;
        mt19937 gen(random_device{}()); // 需要 <random>

        while (left <= right) {
            uniform_int_distribution<int> dist(left, right);
            int pivot = nums[dist(gen)]; // 保存值，不使用元素引用
            int lt = left, i = left, gt = right;

            while (i <= gt) {
                if (nums[i] < pivot) {
                    swap(nums[i], nums[lt]);
                    lt++;
                    i++;
                } else if (nums[i] > pivot) {
                    swap(nums[i], nums[gt]);
                    gt--; // i 不动，检查交换过来的值
                } else {
                    i++;
                }
            }

            if (target < lt) {
                right = lt - 1;
            } else if (target > gt) {
                left = gt + 1;
            } else {
                return pivot;
            }
        }
        return -1; // k 合法时不会执行到这里
    }
};

划分后，等于区域为 [lt, gt]。target 位于其中就返回 pivot，否则只继续处理目标所在的一边；target 一直是原数组的绝对下标，不随区间缩小而变化。

例如 [3,2,1,5,6,4]、k=2，target=4：取 pivot=4，分成 [3,2,1] [4] [6,5]，继续查右侧；再取 pivot=5，目标落入等于区域，返回 5。全相等输入会在第一次划分后返回。

随机三路快选期望时间 O(n)，最坏 O(n²)，迭代实现额外空间 O(1)，会修改原数组。堆解法不修改原数组，时间为 O(n log(k+1))（通常简记 O(n log k)）。

大顶堆的独立声明、push/top/pop 示例及复杂度见 C++ priority_queue 基础。

二、347. 前 K 个高频元素

1. 题意

给定整数数组 nums 和整数 k，返回出现频率最高的 k 个不同元素，答案可以按任意顺序返回。

例如：

nums = [1,1,1,2,2,3], k = 2

1 出现 3 次
2 出现 2 次
3 出现 1 次

答案：[1,2]

本题比较的是出现频率，而不是元素值本身。

2. 核心思路：哈希表 + 小顶堆

分为两步：

1. 使用哈希表统计每个不同元素的出现次数；
2. 使用大小为 k 的小顶堆，维护频率最高的 k 个元素。

堆中保存：

{频率, 元素值}

把频率放在 pair.first 中，是为了让堆优先按照频率比较。

3. 哈希表与堆中 pair 的含义不同

哈希表声明为：

unordered_map<int, int> frequency;

遍历哈希表时：

entry.first  = num
entry.second = count

也就是：

哈希表保存 {元素值, 频率}

但是放入堆时主动交换了顺序：

int num = entry.first;
int count = entry.second;
minHeap.push({count, num});

因此堆中的含义是：

pair.first  = count
pair.second = num

完整数据流：

哈希表：元素值 → 频率
堆：    {频率, 元素值}

例如数字 1 出现 3 次：

哈希表条目：{1, 3}  // {num, count}
放入堆中：{3, 1}    // {count, num}

4. greater<pair<int, int>> 如何比较

pair 默认按照字典序比较：

1. 先比较 first；
2. first 相同时，再比较 second。

因此：

greater<pair<int, int>>

构成的小顶堆会让最小的 pair 位于堆顶。

因为本题将频率放在 first 中，所以堆顶优先是频率最低的元素。频率相同时，再以元素值决定次序，但题目允许答案按任意顺序返回，因此不影响正确性。

如果错误地写成：

minHeap.push({num, count});

堆就会优先按照元素值比较，而不是频率，无法正确筛选前 k 个高频元素。

5. C++ 代码

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        // frequency[num] 表示 num 出现的次数
        unordered_map<int, int> frequency;

        for (int num : nums) {
            frequency[num]++;
        }

        // 堆中保存 {频率, 元素值}
        // 频率最低的元素位于堆顶
        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > minHeap;

        for (const auto& entry : frequency) {
            int num = entry.first;
            int count = entry.second;

            // 注意：哈希表是 {num, count}，堆中改为 {count, num}
            minHeap.push({count, num});

            // 只保留频率最高的 k 个不同元素
            if (minHeap.size() > k) {
                minHeap.pop();
            }
        }

        vector<int> answer;

        while (!minHeap.empty()) {
            // second 才是元素值
            answer.push_back(minHeap.top().second);
            minHeap.pop();
        }

        return answer;
    }
};

6. 正确性说明

每当堆中出现 k + 1 个候选元素时，删除频率最低的堆顶。这个元素不可能属于当前频率最高的 k 个元素，因此可以安全淘汰。

遍历完所有不同元素后，堆中留下的就是整个数组中频率最高的 k 个不同元素。

7. 复杂度

设 n 为数组长度，m 为不同元素数量：

统计频率：O(n)
维护堆：  O(m log k)
总时间：  O(n + m log k)，通常简写为 O(n log k)
空间：    O(m + k)，通常简写为 O(m)

8. 记忆

前 K 个高频元素：先用哈希表统计频率，再用大小为 K 的小顶堆筛选；堆中保存 {频率, 元素值}。

三、295. 数据流的中位数

1. 题意

实现 MedianFinder 类，支持：

void addNum(int num);   // 添加数字
double findMedian();    // 查询当前所有数字的中位数

中位数定义：

  • 元素数量为奇数：排序后最中间的元素；
  • 元素数量为偶数：排序后中间两个元素的平均值。

例如：

[2,3,4] 的中位数是 3
[2,3] 的中位数是 2.5

2. 核心思路：双堆

把数据分为两半：

较小的一半 | 较大的一半

使用两个堆：

priority_queue<int> leftHeap;
  • leftHeap 是大顶堆；
  • 保存较小的一半；
  • leftHeap.top() 是左半部分最大值。
priority_queue<int, vector<int>, greater<int>> rightHeap;
  • rightHeap 是小顶堆；
  • 保存较大的一半；
  • rightHeap.top() 是右半部分最小值。

结构可理解为：

较小的一半                       较大的一半
leftHeap（大顶堆）              rightHeap（小顶堆）

... 1 2 3 [4]        |        [5] 6 7 8 ...
          ↑                     ↑
 leftHeap.top()          rightHeap.top()

两个堆顶正好是最接近中间位置的两个数字。

3. priority_queue<int> 默认是大顶堆

priority_queue<int> leftHeap;

默认等价于：

priority_queue<int, vector<int>, less<int>> leftHeap;

因此：

leftHeap.top();  // 返回最大值

常用写法对比：

类型 C++ 写法 top() 返回
大顶堆 priority_queue<int> 最大值
小顶堆 priority_queue<int, vector<int>, greater<int>> 最小值

记忆：

较小的一半需要找到其中最大值  → 大顶堆
较大的一半需要找到其中最小值  → 小顶堆

4. 必须维护的两个不变量

不变量一：数值顺序

leftHeap 中所有元素 <= rightHeap 中所有元素

插入时可以根据左堆堆顶判断：

if (leftHeap.empty() || num <= leftHeap.top()) {
    leftHeap.push(num);
} else {
    rightHeap.push(num);
}

不变量二：数量平衡

规定左堆负责在总数为奇数时多保存一个元素：

leftHeap.size() == rightHeap.size()

或者：

leftHeap.size() == rightHeap.size() + 1

因此：

  • 总数为偶数：两堆大小相等；
  • 总数为奇数：左堆比右堆多一个。

5. 添加数字的完整步骤

1. 根据 num 与 leftHeap.top() 的关系，把 num 放入合适的堆；
2. 如果左堆比右堆多两个，将左堆堆顶移到右堆；
3. 如果右堆比左堆多，将右堆堆顶移到左堆。

两种平衡方向都不能遗漏：

if (leftHeap.size() > rightHeap.size() + 1) {
    rightHeap.push(leftHeap.top());
    leftHeap.pop();
} else if (rightHeap.size() > leftHeap.size()) {
    leftHeap.push(rightHeap.top());
    rightHeap.pop();
}

每次添加之前两堆的大小差不超过 1，而每次只添加一个元素，所以最多移动一个堆顶就能恢复平衡。

6. 查询中位数

如果两堆大小相等，总数为偶数：

(leftHeap.top() + rightHeap.top()) / 2.0

如果左堆多一个元素，总数为奇数：

leftHeap.top()

7. 示例推演

操作：

addNum(1)
addNum(2)
findMedian()
addNum(3)
findMedian()

添加 1

leftHeap  = [1]
rightHeap = []

添加 2

2 > leftHeap.top()，放入右堆：

leftHeap  = [1]
rightHeap = [2]

两堆大小相等：

中位数 = (1 + 2) / 2.0 = 1.5

添加 3

3 > leftHeap.top()，先放入右堆：

leftHeap  = [1]
rightHeap = [2,3]

此时右堆比左堆多，将右堆最小值 2 移到左堆：

leftHeap  保存 [1,2]，堆顶为 2
rightHeap 保存 [3]，堆顶为 3

左堆比右堆多一个，所以中位数为：

leftHeap.top() = 2

8. 常见错误：只处理一个方向的平衡

错误代码只处理了左堆元素过多：

if (leftHeap.size() > rightHeap.size() + 1) {
    rightHeap.push(leftHeap.top());
    leftHeap.pop();
}

却遗漏了右堆元素更多的情况。对于依次加入 1、2、3：

leftHeap  = [1]
rightHeap = [2,3]

如果不把 2 移入左堆，代码会错误返回 leftHeap.top() = 1，而正确中位数应为 2。

必须补上：

else if (rightHeap.size() > leftHeap.size()) {
    leftHeap.push(rightHeap.top());
    rightHeap.pop();
}

9. C++ 完整代码

class MedianFinder {
private:
    // 保存较小的一半，大顶堆
    priority_queue<int> leftHeap;

    // 保存较大的一半，小顶堆
    priority_queue<int, vector<int>, greater<int>> rightHeap;

public:
    MedianFinder() {
    }

    void addNum(int num) {
        // 第一步：放入合适的堆，维持左右数值顺序
        if (leftHeap.empty() || num <= leftHeap.top()) {
            leftHeap.push(num);
        } else {
            rightHeap.push(num);
        }

        // 第二步：平衡数量
        if (leftHeap.size() > rightHeap.size() + 1) {
            // 左堆过多：把左边最大值移到右边
            rightHeap.push(leftHeap.top());
            leftHeap.pop();
        } else if (rightHeap.size() > leftHeap.size()) {
            // 右堆过多：把右边最小值移到左边
            leftHeap.push(rightHeap.top());
            rightHeap.pop();
        }
    }

    double findMedian() {
        if (leftHeap.size() == rightHeap.size()) {
            // 偶数个元素：取两个堆顶的平均值
            return (static_cast<double>(leftHeap.top())
                    + rightHeap.top()) / 2.0;
        }

        // 奇数个元素：左堆多一个，中位数是左堆堆顶
        return leftHeap.top();
    }
};

10. 为什么除以 2.0，而不是 2

如果参与除法的两个操作数都是整数，C++ 会执行整数除法：

double result = 3 / 2;

先计算：

3 / 2 = 1

再把整数 1 转换为 double，最终得到 1.0，小数部分已经丢失。

使用：

3 / 2.0

因为 2.0 是 double，会执行浮点除法，结果为 1.5。

11. 为什么只转换一个堆顶为 double

推荐写法：

return (static_cast<double>(leftHeap.top())
        + rightHeap.top()) / 2.0;

只转换一个操作数就够了，因为：

double + int

运算时，int 会自动转换为 double，于是整个加法会使用浮点运算。

它等价于：

return (static_cast<double>(leftHeap.top())
        + static_cast<double>(rightHeap.top())) / 2.0;

但前一种写法更简洁。

12. 为什么不能只写 (a + b) / 2.0

下面的代码在数值较小时可以得到正确的小数：

return (leftHeap.top() + rightHeap.top()) / 2.0;

但括号内会先执行两个 int 的加法，可能在除法之前就发生整数溢出。

例如两个堆顶都接近 int 最大值时：

2,000,000,000 + 2,000,000,000

已经超过 int 范围。

提前将一个操作数转为 double：

static_cast<double>(leftHeap.top()) + rightHeap.top()

可以让加法直接使用浮点运算，避免两个 int 先相加导致的溢出。

由于加法结果已经是 double，此后除以 2 或 2.0 都会执行浮点除法；写成 2.0 更清楚地表达“求平均值需要保留小数”。

addNum：     O(log n)
findMedian： O(1)

14. 记忆

数据流中位数：大顶堆保存较小的一半，小顶堆保存较大的一半；保证左堆与右堆等大，或左堆多一个。两个堆顶就是最靠近中间的数字。
