一、什么是贪心

贪心的特点是：从左到右处理问题，在每一步都做当前看来最有利、且不会破坏全局最优的选择。

它通常不需要保存完整的历史状态，也不需要枚举全部方案；只维护少量“到目前为止最关键的信息”。

常见的贪心维护对象：

  • 最优历史值：此前最小值、最大值等；
  • 最远边界：当前能到达的最远位置；
  • 当前区间的最优扩展：在一段可选范围内，找下一步最远能扩展到哪里；
  • 约束边界：为了保证某种元素不跨段，当前片段至少要延伸到哪里。

二、识别贪心题的一般思路

遇到题目时，可按以下顺序思考。

1. 明确每一步要解决什么

问自己：

  • 当前处理到位置 i 时，过去的信息中，哪些会影响未来？
  • 是否只需保留一个最优值或一个边界，而不必保留所有方案？

例如：

  • 股票题：未来卖出时，只关心此前的最低买入价；
  • 跳跃题：只关心当前最远能到哪里；
  • 分区题：只关心当前片段必须覆盖到的最右边界。

2. 设计“维护量”并写清不变量

不变量是遍历过程中始终正确的一句话。

常见形式：

minValue：到当前位置之前的最小值。
farthest：已扫描的可达位置中，能够到达的最远下标。
end：使用当前跳数能够覆盖到的最远边界。
right：当前片段内所有字符最后出现位置的最大值。

3. 每次遍历只做两件事

1. 用当前位置更新维护量；
2. 判断是否达到“结算时机”：更新答案、切分区间、增加次数或提前返回。

4. 验证局部选择是否安全

贪心不是“看起来最优”就可以使用。需要说明：当前选择不会错过更优解。

常见证明角度：

  • 保留历史最优值：比它更差的历史状态永远不会更有用；
  • 扩展最远边界：在同样的步数下，能到得更远一定不劣；
  • 尽早切分：若当前位置已满足约束，晚切只会减少片段数。

三、通用模板

模板 1：维护历史最优值

适用特征：当前位置的最优答案，取决于“当前位置之前的某个最优状态”。

int bestHistory = 初始值;
int answer = 初始答案;

for (int i = 0; i < n; i++) {
    // 用此前的 bestHistory 计算当前位置的候选答案
    answer = 更新答案(answer, 当前位置, bestHistory);

    // 再把当前位置纳入历史信息
    bestHistory = 更新历史最优(bestHistory, 当前位置);
}

注意更新顺序：若题目要求“先发生历史操作，再发生当前位置操作”，要先利用旧的历史信息计算答案，再更新历史信息。

模板 2：维护最远可达边界

适用特征：从位置 i 可以向右扩展到某个范围，问题关注“是否能继续到达”。

int farthest = 0;

for (int i = 0; i < n; i++) {
    if (i > farthest) {
        return false;  // 当前位置不可达
    }

    farthest = max(farthest, i + nums[i]);

    if (farthest >= n - 1) {
        return true;   // 已覆盖终点
    }
}

模板 3：按可达区间分层，求最少次数

适用特征：每次操作能覆盖一个区间，要求到达终点的最少操作次数。

int steps = 0;
int end = 0;       // 当前 steps 次操作可覆盖的右边界
int farthest = 0;  // 在当前覆盖区间内，下一次可覆盖的最远位置

for (int i = 0; i < n - 1; i++) {
    farthest = max(farthest, i + nums[i]);

    if (i == end) {
        steps++;
        end = farthest;
    }
}

模板 4：维护当前片段的约束右边界

适用特征：题目要求划分连续区间，且区间内元素会决定该区间最少延伸到哪里。

int start = 0;
int right = 0;

for (int i = 0; i < n; i++) {
    right = max(right, 当前位置对应的约束边界);

    if (i == right) {
        记录区间 [start, right];
        start = i + 1;
    }
}

四、题目整理

1. 121. 买卖股票的最佳时机

题意

给定数组 prices，prices[i] 是第 i 天的股价。只能进行至多一次交易：先买入、后卖出，求最大利润；无法获利时返回 0。

贪心思路

遍历每个卖出日。若今天卖出，要使利润最大，就应在今天之前的最低价格买入。

维护：

minPrice   // 到当前天为止的最低股价
maxProfit  // 到当前天为止的最大利润

不变量

遍历到第 i 天后：

minPrice 是 prices[0..i] 中的最小值；
maxProfit 是在前 i+1 天内完成至多一次交易的最大利润。

代码

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int minPrice = prices[0];
        int maxProfit = 0;

        for (int i = 1; i < prices.size(); i++) {
            // 以第 i 天卖出时的最大利润
            maxProfit = max(maxProfit, prices[i] - minPrice);

            // 更新未来卖出时可用的最低买入价
            minPrice = min(minPrice, prices[i]);
        }

        return maxProfit;
    }
};

易错点

不能直接用“全局最大值 - 全局最小值”，因为最低价格可能出现在最高价格之后，违反“先买后卖”的顺序。

记忆

枚举卖出日，维护卖出日之前的最低买入价。

2. 55. 跳跃游戏

题意

nums[i] 表示站在下标 i 时最多能向右跳几步。初始在下标 0，判断能否到达最后一个下标。

贪心思路

不必记录具体跳法，只维护到目前为止能到达的最远下标。

若遍历到下标 i 时：

i > farthest

说明连 i 都无法到达，后续位置也不可能到达。

不变量

扫描完已处理的可达位置后：

farthest 是从这些位置出发能够到达的最远下标。

代码

class Solution {
public:
    bool canJump(vector<int>& nums) {
        int farthest = 0;

        for (int i = 0; i < nums.size(); i++) {
            if (i > farthest) {
                return false;
            }

            farthest = max(farthest, i + nums[i]);

            if (farthest >= nums.size() - 1) {
                return true;
            }
        }

        return true;
    }
};

记忆

扫描所有可达位置，持续更新最远可达位置；当前位置越过边界就失败。

闪卡复习

Q:: 在“跳跃游戏”中，nums[i] 表示什么？ A:: 位于下标 i 时最多能向右跳的长度。

Q:: “跳跃游戏”的起点和目标分别是什么？ A:: 从数组第一个下标出发，判断能否到达最后一个下标。

Q:: 对 nums = [2,3,1,1,4]，应返回什么？一种可行跳法是什么？ A:: 返回 true；可从下标 0 跳到下标 1，再跳到最后一个下标。

Q:: 为什么 nums = [3,2,1,0,4] 不能到达最后一个下标？ A:: 无论如何都会到达下标 3，但 nums[3]=0，无法继续跳到最后一个下标。

3. 45. 跳跃游戏 II

题意

nums[i] 表示从下标 i 最多能跳多远。初始在下标 0，返回到达最后一个下标所需的最少跳跃次数。题目保证可以到达终点。

与 55 题的区别

题目 问题 核心维护量
55. 跳跃游戏 能否到达终点 farthest
45. 跳跃游戏 II 最少跳几次 end、farthest、steps

贪心思路：把一次跳跃看成一个可达区间

end       // 跳了 steps 次后，当前最多覆盖到哪里
farthest  // 在当前覆盖区间内再跳一次，最远能覆盖到哪里
steps     // 已使用的跳跃次数

当 i == end 时，当前这一次跳跃覆盖的区间已经全部考察完；若还未到终点，就必须进行下一跳，并把边界扩展到 farthest。

不变量

在处理当前区间 [上一层边界 + 1, end] 时：

farthest 表示从当前层任意可达位置再跳一次，能到达的最远下标。

在边界处跳跃，能使下一层覆盖范围最大，因此不会增加跳跃次数。

代码

class Solution {
public:
    int jump(vector<int>& nums) {
        int steps = 0;
        int end = 0;
        int farthest = 0;

        // 不处理终点：到达终点后无需再跳
        for (int i = 0; i < nums.size() - 1; i++) {
            farthest = max(farthest, i + nums[i]);

            // 当前跳数能覆盖的范围已扫描完
            if (i == end) {
                steps++;
                end = farthest;
            }
        }

        return steps;
    }
};

示例：[2,3,1,1,4]

初始：steps = 0, end = 0, farthest = 0

i = 0：farthest = 2，走到 end，跳 1 次，end = 2
i = 1：farthest = 4
i = 2：走到 end，跳 2 次，end = 4（已覆盖终点）

答案为 2。

记忆

当前边界内挑出下一跳能到的最远位置；走到当前边界时，跳跃次数加一并更新边界。

4. 763. 划分字母区间

题意

将字符串划分为尽可能多的连续片段，要求同一个字母最多只出现在一个片段中，返回每个片段的长度。

例如：

"ababcbacadefegdehijhklij" → [9, 7, 8]

贪心思路

先记录每个字母最后出现的位置。

扫描当前片段时，只要遇到一个字符，就必须把片段右边界扩展到该字符的最后出现位置。直到扫描位置 i 到达边界 end，说明片段中的所有字母都不会在后面再次出现，此时可以切分。

不变量

遍历到 i 时：

end 是当前片段内所有字符的最后出现位置的最大值。

因此，i < end 时不能切分；i == end 时可以安全切分。

代码

class Solution {
public:
    vector<int> partitionLabels(string s) {
        vector<int> last(26, 0);

        // 每个字母最后一次出现的位置
        for (int i = 0; i < s.size(); i++) {
            last[s[i] - 'a'] = i;
        }

        vector<int> result;
        int start = 0;
        int end = 0;

        for (int i = 0; i < s.size(); i++) {
            end = max(end, last[s[i] - 'a']);

            if (i == end) {
                result.push_back(end - start + 1);
                start = i + 1;
            }
        }

        return result;
    }
};

为什么片段长度是 end - start + 1？

片段是两端都包含的闭区间 [start, end]。例如 [0, 2] 包含下标 0、1、2，共 2 - 0 + 1 = 3 个字符；单字符时 start == end，长度仍为 1。

end - start 表示两端下标的距离；左闭右开区间 [start, end) 的元素个数才是 end - start。这与每日温度的“等待几天”不同，后者只计算日期差，不加 1。

本代码使用 26 个槽位，适用于小写英文字母；若字符范围不同，可以用 unordered_map<char, int> 保存最后位置。时间 O(n)，固定字符集下额外空间 O(1)，返回的片段长度列表另占 O(m)，m 为片段数。

为什么要在 i == end 时立刻切分？

此时已经满足“当前片段中的字母不会再出现”的要求：

  • 若更早切分，会把同一字母分到两个片段，非法；
  • 若更晚切分，虽然可能仍合法，但片段数会变少。

所以在第一个可切分位置立刻切分，能得到最多片段。

记忆

记录字母最后位置；当前片段右边界取最大值，扫描到边界就切分。

六、做题自检清单

  1. 维护量是什么？ 是最小值、最大值、最远边界，还是区间右边界？
  2. 它的准确含义是什么？ 要能用一句不变量描述。
  3. 什么时候更新维护量？ 当前元素带来了什么新的候选信息？
  4. 什么时候结算？ 是更新利润、判断失败、跳跃次数加一，还是切分区间？
  5. 局部最优为什么安全？ 能否说明更差的选择一定不会更优？
  6. 边界是否正确？ 空间、首元素、最后一个元素、不能到达、全递减或单字符等情况是否考虑？

七、专题总结

这 4 道题表面不同，但都遵循同一套路：

从左到右扫描 → 维护过去或当前区间的关键信息 →
在边界到达时结算 / 决策 → 不回头地完成最优选择。

核心不是记住代码，而是先明确：

为了让未来始终拥有最优选择，现在必须维护的最少信息是什么？

找到这个信息，并证明“只保留它不会丢失最优解”，就找到了贪心的突破口。
