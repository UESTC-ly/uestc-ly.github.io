LeetCode 207 的本质是：把课程依赖建成有向图，通过拓扑排序判断图中是否存在环。

总览：图论专题｜相关：网格图搜索（200、994）

一、题意

共有 numCourses 门课程，编号为：

0 ～ numCourses - 1

先修关系：

prerequisites[i] = {a, b};

表示学习课程 a 之前，必须先学习课程 b。需要判断能否完成所有课程。

二、把课程关系转换成有向图

每门课程是一个节点。对于：

[a, b]

正确的有向边是：

b → a

因为 b 是先修课程，完成 b 后才能学习 a。

对应代码：

graph[b].push_back(a);
++indegree[a];

记忆：

先修课指向后续课；后续课的入度加一。

三、为什么问题等价于判断有向图是否有环

如果依赖关系形成环，例如：

0 → 1
↑   ↓
└───┘

就表示：

学 1 前必须先学 0；
学 0 前又必须先学 1。

两门课程互相等待，无法开始。因此：

有环：不能完成所有课程；
无环：可以得到合法的课程学习顺序。

四、核心概念：入度

课程 x 的入度表示：

学习课程 x 前，还有多少门先修课程没有完成。

例如：

0 → 2
1 → 2

课程 2 有两门先修课程，所以：

indegree[2] = 2;

入度为 0 的课程没有未完成的前置要求，可以立即学习。

五、BFS 拓扑排序步骤

  1. 根据先修关系建立邻接表 graph 和入度数组 indegree；
  2. 将所有入度为 0 的课程加入队列；
  3. 每次从队列取出一门课程，视为完成该课程；
  4. 遍历它指向的所有后续课程，将这些课程的入度减一；
  5. 某门后续课程的入度变为 0 时，将它加入队列；
  6. 最后比较已完成课程数与课程总数： - 相等：不存在环，返回 true； - 不相等：仍有课程互相依赖，返回 false。

统一过程：

所有入度为 0 的课程入队
→ 取出并完成一门课
→ 后续课程入度减一
→ 新的入度为 0 的课程入队
→ 比较最终完成数量

六、示例推演

示例 1

numCourses = 2;
prerequisites = {{1, 0}};

建图：

0 → 1

初始入度：

indegree[0] = 0
indegree[1] = 1

处理过程：

课程 0 入队
→ 完成 0
→ 课程 1 的入度从 1 变成 0
→ 课程 1 入队并完成

最终完成 2 门课程，返回 true。

示例 2

numCourses = 2;
prerequisites = {{1, 0}, {0, 1}};

建图：

0 → 1
1 → 0

两门课程的入度都为 1，初始队列为空，无法开始拓扑排序，最终完成数量为 0，返回 false。

七、C++ 代码

class Solution {
public:
    bool canFinish(int numCourses,
                   vector<vector<int>>& prerequisites) {
        // graph[x]：完成课程 x 后，可以继续学习哪些课程。
        vector<vector<int>> graph(numCourses);

        // indegree[x]：课程 x 还有多少门先修课程未完成。
        vector<int> indegree(numCourses, 0);

        // [course, preCourse] 表示 preCourse → course。
        for (const auto& prerequisite : prerequisites) {
            int course = prerequisite[0];
            int preCourse = prerequisite[1];

            graph[preCourse].push_back(course);
            ++indegree[course];
        }

        queue<int> courseQueue;

        // 所有入度为 0 的课程都可以立即学习。
        for (int course = 0; course < numCourses; ++course) {
            if (indegree[course] == 0) {
                courseQueue.push(course);
            }
        }

        int completedCourses = 0;

        while (!courseQueue.empty()) {
            int currentCourse = courseQueue.front();
            courseQueue.pop();

            ++completedCourses;

            // 完成当前课程后，后续课程少一个未完成的前置要求。
            for (int nextCourse : graph[currentCourse]) {
                --indegree[nextCourse];

                if (indegree[nextCourse] == 0) {
                    courseQueue.push(nextCourse);
                }
            }
        }

        return completedCourses == numCourses;
    }
};

八、为什么处理数量不足就说明有环

拓扑排序只会处理入度为 0 的节点。如果队列已经为空，但仍有课程没有完成，那么剩余课程的入度都大于 0，说明它们仍在互相等待。

即使图中只有一部分节点成环，最终完成数量也会小于总课程数。例如：

0 → 1

2 → 3
↑   ↓
└───┘

课程 0、1 可以完成，但 2、3 形成环，所以仍应返回 false。

因此不能只判断初始队列是否为空，必须使用：

return completedCourses == numCourses;

九、常见错误

1. 把边的方向写反

对于 [a, b]：

正确：b → a
错误：a → b

正确代码：

graph[b].push_back(a);
++indegree[a];

2. 只把一个入度为 0 的课程入队

可能有多门互不依赖的课程可以同时开始，初始化时必须遍历所有课程。

3. 入度减到 0 后没有入队

--indegree[nextCourse];
if (indegree[nextCourse] == 0) {
    courseQueue.push(nextCourse);
}

只有这样，后续课程才能继续进入拓扑序列。

4. 只判断初始队列是否为空

初始队列非空并不代表整个图无环，因为图的一部分仍可能成环。应比较最终处理数量。

5. 不需要按层记录 BFS

本题不求经过多少轮，只判断所有课程能否被处理，因此不需要：

int levelSize = courseQueue.size();

十、复杂度

设：

V = numCourses
E = prerequisites.size()
  • 时间复杂度：O(V + E)；
  • 空间复杂度：O(V + E)。

每门课程最多入队、出队一次，每条先修关系最多遍历一次。

十一、方法归纳

看到以下描述时，优先考虑拓扑排序：

  • 任务之间存在先后依赖；
  • 判断是否能够完成全部任务；
  • 判断依赖关系中是否存在循环；
  • 安排课程、任务或构建顺序。

通用模板：

建立邻接表和入度数组;
将所有入度为 0 的节点加入队列;

while (队列不为空) {
    取出并处理一个节点;
    已处理节点数加一;

    for (当前节点指向的后续节点) {
        后续节点入度减一;
        if (后续节点入度变成 0) {
            后续节点入队;
        }
    }
}

return 已处理节点数 == 总节点数;

复习口诀：

[a,b] 表示 b→a；
入度为 0 才能学；
学完一门，后续入度减一；
处理数量不足，说明图中有环。
