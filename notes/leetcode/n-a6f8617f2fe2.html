一、200. 岛屿数量

1. 题意

网格中：

'1'：陆地
'0'：水

只有水平或竖直相邻的陆地相连，对角线不算。需要统计由 '1' 组成的四方向连通块数量。

2. 核心思路：发现一座岛，标记整座岛

从左到右、从上到下遍历网格：

  1. 如果当前位置是 '0'，跳过；
  2. 如果当前位置是 '1'，说明发现了一座尚未统计的新岛，答案加一；
  3. 从当前位置开始 DFS，将与它连通的所有 '1' 改为 '0'；
  4. 继续遍历时，这座岛不会被重复统计。

统一过程：

遇到未访问的陆地
→ 岛屿数量 +1
→ DFS 标记整个连通块

3. 为什么不恢复现场

这里把：

grid[row][col] = '0';

作为永久访问标记。每块陆地全局只需要访问一次，所以递归返回后不应恢复。

这与需要枚举不同路径的回溯题不同：

连通块统计：标记后不恢复；
枚举不同路径：通常需要恢复现场。

4. C++ 代码

class Solution {
private:
    void dfs(vector<vector<char>>& grid, int row, int col) {
        int rows = grid.size();
        int cols = grid[0].size();

        // 越界，或者当前位置不是未访问的陆地，停止搜索。
        if (row < 0 || row >= rows ||
            col < 0 || col >= cols ||
            grid[row][col] != '1') {
            return;
        }

        // 永久标记为已经访问，防止重复进入。
        grid[row][col] = '0';

        dfs(grid, row - 1, col); // 上
        dfs(grid, row + 1, col); // 下
        dfs(grid, row, col - 1); // 左
        dfs(grid, row, col + 1); // 右
    }

public:
    int numIslands(vector<vector<char>>& grid) {
        if (grid.empty() || grid[0].empty()) {
            return 0;
        }

        int rows = grid.size();
        int cols = grid[0].size();
        int islandCount = 0;

        for (int row = 0; row < rows; ++row) {
            for (int col = 0; col < cols; ++col) {
                if (grid[row][col] == '1') {
                    ++islandCount;
                    dfs(grid, row, col);
                }
            }
        }

        return islandCount;
    }
};

5. 复杂度

设网格有 m 行、n 列：

  • 时间复杂度：O(m × n)，每个格子最多被处理一次；
  • 空间复杂度：最坏为 O(m × n)，来自 DFS 递归栈。

二、994. 腐烂的橘子

1. 题意

网格中：

0：空格
1：新鲜橘子
2：腐烂橘子

每过一分钟，腐烂橘子会让上下左右相邻的新鲜橘子腐烂。求所有新鲜橘子腐烂所需的最少分钟数；如果无法全部腐烂，返回 -1。

2. 为什么是多源 BFS

腐烂过程按距离逐层扩散：

第 0 分钟：所有初始腐烂橘子
第 1 分钟：与任意初始腐烂橘子相邻的新鲜橘子
第 2 分钟：再向外一层的橘子
……

网格中可能存在多个初始腐烂橘子，它们会同时传播，因此必须把它们全部放入初始队列。这就是多源 BFS。

所有初始腐烂橘子共同组成 BFS 的第 0 层；每完成一层向下一层的传播，就经过一分钟。

3. 算法步骤

  1. 遍历网格，将所有 2 加入队列，并统计 1 的数量 freshCount；
  2. 如果一开始没有新鲜橘子，直接返回 0；
  3. 按层执行 BFS，当前层的腐烂橘子同时向四个方向传播；
  4. 新鲜橘子入队时立即改成 2，并将 freshCount 减一；
  5. BFS 结束后： - freshCount == 0：返回分钟数； - freshCount > 0：仍有无法到达的新鲜橘子，返回 -1。

4. C++ 代码

class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        if (grid.empty() || grid[0].empty()) {
            return 0;
        }

        int rows = grid.size();
        int cols = grid[0].size();

        queue<pair<int, int>> rottenQueue;
        int freshCount = 0;

        // 所有初始腐烂橘子同时入队，并统计新鲜橘子。
        for (int row = 0; row < rows; ++row) {
            for (int col = 0; col < cols; ++col) {
                if (grid[row][col] == 2) {
                    rottenQueue.push({row, col});
                } else if (grid[row][col] == 1) {
                    ++freshCount;
                }
            }
        }

        if (freshCount == 0) {
            return 0;
        }

        int directions[4][2] = {
            {-1, 0},
            {1, 0},
            {0, -1},
            {0, 1}
        };

        int minutes = 0;

        // 当前队列中的元素属于同一 BFS 层。
        while (!rottenQueue.empty() && freshCount > 0) {
            int currentLevelSize = rottenQueue.size();

            // 尝试让当前层向下一层传播，代表进入下一分钟。
            ++minutes;

            for (int i = 0; i < currentLevelSize; ++i) {
                auto [row, col] = rottenQueue.front();
                rottenQueue.pop();

                for (const auto& direction : directions) {
                    int nextRow = row + direction[0];
                    int nextCol = col + direction[1];

                    if (nextRow < 0 || nextRow >= rows ||
                        nextCol < 0 || nextCol >= cols) {
                        continue;
                    }

                    if (grid[nextRow][nextCol] != 1) {
                        continue;
                    }

                    // 入队时立即标记，防止被多个橘子重复加入队列。
                    grid[nextRow][nextCol] = 2;
                    --freshCount;
                    rottenQueue.push({nextRow, nextCol});
                }
            }
        }

        // 这个判断必须在整个 BFS 结束后执行。
        if (freshCount > 0) {
            return -1;
        }

        return minutes;
    }
};

5. ++minutes 为什么可以写在每层开头

考虑不连通的情况：

2 0 1

初始时：

队列中有腐烂橘子
freshCount = 1
minutes = 0

代码会进入 while，并让 minutes 暂时变成 1。这一层无法传播，处理后队列为空，但 freshCount 仍为 1，最终执行：

if (freshCount > 0) {
    return -1;
}

因此返回的是 -1，而不是临时的 minutes。可以这样理解：

能够全部腐烂：minutes 是有效答案；
无法全部腐烂：minutes 作废，返回 -1。

下面两种结尾完全等价：

if (freshCount > 0) {
    return -1;
}
return minutes;

return freshCount == 0 ? minutes : -1;

如果更希望代码严格表达“确实发生传播才增加一分钟”，也可以用 bool spread 记录本层是否感染了新橘子；但标准写法配合最终的 freshCount 判断已经正确，而且更简洁。

6. 为什么最终判断必须放在 while 外

错误结构：

while (!rottenQueue.empty() && freshCount > 0) {
    // 只传播了一分钟

    if (freshCount > 0) {
        return -1; // 错误
    }
}

一层结束后仍有新鲜橘子很正常，因为新腐烂的橘子还可以在下一分钟继续传播。只有当整个 BFS 结束，也就是已经没有腐烂橘子可以继续扩散时，才能判断剩余新鲜橘子是否永远无法到达。

正确结构：

while (!rottenQueue.empty() && freshCount > 0) {
    // 不断按层传播
}

if (freshCount > 0) {
    return -1;
}

return minutes;

一层结束后还有新鲜橘子，不代表无解；队列耗尽后还有新鲜橘子，才代表无解。

7. 为什么入队时立即标记

必须把标记和入队放在一起：

grid[nextRow][nextCol] = 2;
--freshCount;
rottenQueue.push({nextRow, nextCol});

如果等到出队时才标记，同一个新鲜橘子可能同时被多个腐烂橘子发现并重复入队，导致 freshCount 被多次减少。

BFS 的常用原则是：

节点第一次加入队列时，就立即标记为已访问。

8. 复杂度

设网格有 m 行、n 列：

  • 时间复杂度：O(m × n)；
  • 空间复杂度：O(m × n)，最坏情况下队列保存大量橘子位置。

三、两道题的统一归纳

对比项 200. 岛屿数量 994. 腐烂的橘子
目标 统计连通块数量 求多源扩散的最短时间
主流方法 DFS / BFS 多源 BFS
是否按层 不需要 需要，一层代表一分钟
初始起点 外层遍历逐个发现 所有初始腐烂橘子同时入队
访问标记 '1' 改成 '0' 1 改成 2
标记后是否恢复 不恢复 不恢复

记忆：

统计连通块：发现一个起点，搜索并标记整个区域；
求最短传播时间：所有源点同时入队，按层 BFS；
加入队列就立即标记，防止重复处理。
