本课主线：大语言模型如何从“根据上下文续写文本的基础模型”，逐步变成“能够遵循指令、体现人类偏好并满足安全要求的助手模型”。

一、整体训练流程

海量无标注文本
  ↓
预训练（Pretraining）
  ↓
基础模型（Base Model）
  ↓
指令微调（SFT）
  ↓
指令模型 / 聊天模型
  ↓
偏好对齐
  ├── RLHF：奖励模型 + 强化学习
  └── DPO：直接使用偏好数据优化
  ↓
对齐后的助手模型
阶段 主要数据 主要目标 解决的问题
预训练 海量普通文本、代码等 预测下一个 Token 学习语言、知识和通用能力
SFT 指令—回答样本 模仿高质量回答 学会理解并执行指令
RLHF 人类偏好排序数据 最大化奖励模型评分 让回答更符合人类偏好
DPO 优选回答与较差回答 提高优选回答的相对概率 用更简单的方式进行偏好对齐

一句话记忆：

  • 预训练让模型“有能力”；
  • SFT让模型“会按要求回答”；
  • RLHF / DPO让模型“更倾向于给出人类喜欢的回答”。

二、预训练：获得基础能力

2.1 核心任务：预测下一个 Token

GPT 类模型通常使用自回归语言建模，根据前面的 Token 预测下一个 Token：

输入：机器学习是人工智能的一个
目标：分支

模型学习的条件概率为：

\[ P(x_t\mid x_1,x_2,\ldots,x_{t-1}) \]

常见的训练损失为：

\[ \mathcal{L}_{\text{pretrain}} = -\sum_{t=1}^{T} \log P_\theta(x_t\mid x_{<t}) \]

其中：

  • \(x_t\)：第 \(t\) 个 Token；
  • \(x_{<t}\)：它之前的 Token；
  • \(\theta\)：模型参数；
  • \(T\)：序列长度。

正确 Token 的预测概率越高，损失越小。

2.2 为什么称为自监督学习？

预训练通常不需要人工逐条标注答案。原始文本本身就能自动构造预测目标：

原文：今天天气很好。

今天        → 天气
今天天气    → 很
今天天气很  → 好
今天天气很好 → 。

因此，预训练并非完全没有监督信号，而是监督信号由数据本身自动生成，不需要人工为每个样本提供标签。

2.3 预训练数据与数据处理

数据可能包括：

  • 网页文本、书籍、新闻和百科内容；
  • 论坛、问答和学术论文；
  • 程序代码；
  • 数学、推理和多语言文本。

训练前通常还要进行：

  • 去重；
  • 质量过滤；
  • 隐私信息过滤；
  • 有害内容处理；
  • 数据配比；
  • Tokenization；
  • 文档打包和序列切分。

数据不是简单地越多越好，还需要考虑质量、覆盖范围、重复比例和不同来源的配比。

2.4 预训练得到什么？

通过不断预测下一个 Token，模型可能学习到：

  • 语法和词义；
  • 事实知识；
  • 文本风格；
  • 代码结构；
  • 常见推理模式；
  • 概念之间的关联；
  • 一定程度的上下文学习能力。

虽然训练目标表面上只是预测 Token，但为了提高预测准确率，模型需要学习文本背后的复杂规律。

2.5 基础模型为什么不一定适合聊天？

预训练后的 Base Model 更像一个强大的文本续写器。面对：

请解释什么是神经网络。

它可能给出解释，也可能继续生成一份“请解释……”的题目列表，因为预训练语料中可能出现过这种文本模式。

因此：

预训练让模型获得知识和生成能力，但不保证模型稳定理解并执行用户指令。

三、指令微调 SFT

SFT 是 Supervised Fine-Tuning（监督微调）。它使用人工编写、筛选或合成的“指令—回答”样本，让模型学习高质量助手的行为。

3.1 典型数据格式

单轮样本可以是：

{
  "instruction": "用一句话解释什么是过拟合。",
  "response": "过拟合是模型过度记住训练数据，导致它在新数据上的表现变差。"
}

多轮对话通常包含角色：

{
  "messages": [
    {
      "role": "system",
      "content": "你是一名耐心的编程教师。"
    },
    {
      "role": "user",
      "content": "Python 中列表和元组有什么区别？"
    },
    {
      "role": "assistant",
      "content": "列表可以修改，元组通常不可修改。"
    }
  ]
}

训练前，Tokenizer 会通过模型对应的 Chat Template 将消息转换为 Token 序列。不同模型的角色标记和模板可能不同，不能随意混用。

3.2 SFT 的训练目标

SFT 本质上仍然使用下一个 Token 预测，但通常只重点计算 Assistant 回答部分的损失：

用户问题：通常不计算或屏蔽损失
助手回答：计算损失

可表示为：

\[ \mathcal{L}_{\text{SFT}} = -\sum_{t\in\text{assistant}} \log P_\theta(y_t\mid x,y_{<t}) \]

其中：

  • \(x\)：用户指令和上下文；
  • \(y_t\)：助手回答中的第 \(t\) 个 Token；
  • \(y_{<t}\)：已经生成的回答 Token。

模型通过训练提高标准回答的生成概率。

3.3 SFT 能教给模型什么？

  • 识别用户指令；
  • 使用问答格式；
  • 遵守输出格式；
  • 按指定风格回答；
  • 完成摘要、分类、提取、改写等任务；
  • 在多轮对话中维持角色；
  • 学习基础的安全拒答方式；
  • 学习工具调用格式。

3.4 SFT 的局限

  1. 高质量回答需要较高的人工成本。
  2. 多个合理答案难以全部展示，模型容易偏向训练样本中的表达。
  3. SFT 主要告诉模型“应该模仿什么”，不擅长表达“两个答案都可以，但哪个更好”。
  4. 学会回答形式不等于事实一定正确，模型仍可能产生幻觉、伪造引用或忽略复杂指令。

四、偏好对齐的目标

对齐（Alignment）通常指让模型的行为更符合人类意图、价值偏好和安全要求。常见目标包括：

  • Helpful：有帮助；
  • Honest：尽量诚实，不知道时避免编造；
  • Harmless：减少危险和伤害。

人类偏好并不总是一致。例如，有人喜欢详细回答，有人喜欢简洁回答；安全性和实用性有时也存在冲突。因此，对齐应被视为持续的数据、训练和评估过程，而不是一次完成的步骤。

五、RLHF：基于人类反馈的强化学习

RLHF 是 Reinforcement Learning from Human Feedback。经典流程通常分为三个阶段。

5.1 阶段一：先训练 SFT 模型

使用高质量指令数据训练模型，使其具备基本的对话和指令遵循能力。基础行为太差时，后续生成的候选回答也会很差。

5.2 阶段二：收集人类偏好数据

针对同一个问题，让模型生成多个候选回答，再由标注人员比较：

问题：什么是过拟合？

回答 A：过拟合是模型在训练集表现很好，但在新数据上表现较差。
回答 B：过拟合就是模型训练时间太长。

偏好：A 优于 B

偏好样本可表示为：

\[ (x,y_w,y_l) \]

其中：

  • \(x\)：提示词；
  • \(y_w\)：优选回答（chosen / preferred）；
  • \(y_l\)：较差回答（rejected）。

比较已有回答通常比从零编写完美回答更容易，因此偏好标注是一种实用的数据收集方式。

5.3 阶段三：训练奖励模型

奖励模型接收问题和回答，输出近似人类偏好的分数：

\[ r_\phi(x,y) \]

训练目标是让优选回答得分高于较差回答：

\[ r_\phi(x,y_w)>r_\phi(x,y_l) \]

一种常见损失为：

\[ \mathcal{L}_{\text{RM}} = -\log \sigma \left( r_\phi(x,y_w)-r_\phi(x,y_l) \right) \]

5.4 阶段四：使用强化学习优化语言模型

让语言模型生成回答，再用奖励模型评分，并使用 PPO 等强化学习算法更新策略模型。一个简化的目标是：

\[ \max_\theta \mathbb{E}_{y\sim\pi_\theta(\cdot\mid x)} \left[ r_\phi(x,y) -\beta D_{\mathrm{KL}} \left(\pi_\theta\Vert\pi_{\mathrm{ref}}\right) \right] \]

其中：

  • \(\pi_\theta\)：正在训练的策略模型；
  • \(\pi_{\mathrm{ref}}\)：参考模型，通常来自 SFT 模型；
  • \(r_\phi(x,y)\)：奖励模型分数；
  • \(D_{\mathrm{KL}}\)：当前模型与参考模型的差异；
  • \(\beta\)：控制偏离程度的系数。

5.5 为什么需要 KL 约束？

如果只追求奖励模型高分，模型可能利用奖励模型漏洞，例如：

  • 回答越长，奖励越高；
  • 重复某些关键词；
  • 过度使用礼貌用语；
  • 生成看似完整但实际没有信息的内容。

这类现象称为 Reward Hacking（奖励投机）。KL 约束限制模型不要偏离 SFT 模型太远，在提高偏好得分的同时尽量保留原有语言能力和稳定性。

六、DPO：直接偏好优化

DPO 是 Direct Preference Optimization（直接偏好优化）。核心思想是：

不显式训练奖励模型，也不运行复杂的在线强化学习，而是直接使用偏好回答对优化语言模型。

DPO 使用同样的偏好数据：

\[ (x,y_w,y_l) \]

目标是：

  • 提高优选回答 \(y_w\) 的相对概率；
  • 降低较差回答 \(y_l\) 的相对概率；
  • 参考原始模型，避免模型偏离过远。

6.1 直观理解

SFT 更接近：

请学习回答 A。

DPO 则进一步表达：

面对同一个问题，在 A 和 B 之间应该更偏向 A。

DPO 学习的是回答之间的相对偏好。

6.2 常见目标函数

\[ \mathcal{L}_{\text{DPO}} = -\mathbb{E} \left[ \log\sigma \left( \beta \left[ \log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)} \right] \right) \right] \]

理解公式时只需抓住三点：

  1. 比较优选回答和较差回答；
  2. 提高模型对优选回答的相对偏好；
  3. 使用参考模型约束变化范围。

七、RLHF 与 DPO 对比

比较项 经典 RLHF DPO
数据 偏好回答对 偏好回答对
是否显式训练奖励模型 通常需要 不需要
是否需要 PPO 等在线强化学习 通常需要 不需要
训练复杂度 较高 相对较低
训练稳定性 较难控制 通常更稳定
是否使用参考模型 通常使用 通常使用
是否属于偏好对齐 是 是

常见路线为：

预训练 → SFT → RLHF

或：

预训练 → SFT → DPO

RLHF 和 DPO 通常是两种偏好优化路线，并不要求二者必须连续执行。DPO 更依赖已有的离线偏好数据，而 RLHF 可以通过在线采样探索新的回答；实际系统也可能组合多种方法。

八、预训练、持续预训练与 SFT 的区别

方法 数据形式 主要目的
预训练 大规模普通文本 从头建立基础能力
持续预训练 某领域的大量普通文本 加强领域语言和知识
SFT 指令—回答样本 学习具体任务和回答方式
DPO / RLHF 偏好回答对 学习人类偏好

例如，适应医疗领域时可以分别使用：

  • 医学论文进行持续预训练，增强领域语言和知识；
  • 医学问答进行 SFT，学习回答任务；
  • 医生偏好数据进行 DPO，提升质量和安全性。

九、什么时候用 RAG，什么时候用微调？

9.1 适合使用 RAG

以下目标通常优先考虑 RAG：

  • 获取最新信息；
  • 回答企业私有文档问题；
  • 提供可追溯的资料来源；
  • 应对经常更新的知识；
  • 减少重新训练成本。
用户问题
  ↓
检索相关文档
  ↓
将文档放入上下文
  ↓
模型基于文档回答

9.2 适合使用 SFT

  • 固定输出格式；
  • 学习特定任务；
  • 学习专业回答风格；
  • 提高工具调用稳定性；
  • 遵循业务流程。

9.3 适合使用 DPO / RLHF

当回答“基本能用”，但希望模型更：

  • 简洁；
  • 安全；
  • 有帮助；
  • 符合品牌风格；
  • 倾向某种回答策略；

可以考虑偏好优化。

快速判断：

缺少最新或私有知识 → RAG
不会稳定完成任务   → SFT
回答能用但偏好不佳 → DPO / RLHF
缺少领域基础能力   → 持续预训练

微调通常不是注入少量动态知识的首选方案；需要频繁更新且要求可追溯的事实，更适合放在外部知识库中。

十、训练后的多维度评估

训练损失下降并不等于模型整体变好，还应评估：

10.1 基础能力

  • 语言理解；
  • 代码能力；
  • 数学和推理；
  • 多语言能力。

10.2 指令遵循

  • 是否完成用户要求；
  • 是否遵守输出格式；
  • 是否处理多项约束；
  • 是否正确理解系统、用户和助手角色。

10.3 偏好质量

  • 是否有帮助；
  • 是否简洁清晰；
  • 是否避免重复；
  • 是否符合目标风格。

10.4 事实性与安全性

  • 是否产生幻觉；
  • 是否伪造引用；
  • 是否能表达不确定性；
  • 是否生成危险内容；
  • 是否泄露隐私；
  • 是否容易被提示注入绕过。

10.5 回归测试

改善安全性和指令遵循后，还要检查原有能力是否下降。例如，模型变得更保守后，是否错误拒绝了正常的编程、科普或安全研究问题。

十一、常见误区

  1. 大模型的知识都来自 SFT。 大部分通用语言能力和广泛知识通常来自预训练；SFT 主要教模型如何调用和表达这些能力。
  2. SFT 数据越多越好。 少量高质量、一致的数据可能比大量低质量、互相矛盾的数据更有效。
  3. RLHF 会让模型永远正确。 RLHF 优化的是人类或奖励模型的偏好，不是直接验证每个事实。
  4. DPO 不需要偏好数据。 DPO 虽不需要显式奖励模型，但仍需要优选回答和较差回答组成的偏好数据。
  5. DPO 完全不受参考模型约束。 标准 DPO 通常使用参考模型比较相对概率。
  6. 对齐后能力一定全面提升。 对齐可能带来过度拒答、模板化和部分能力退化，因此必须进行回归评估。
  7. 微调可以替代知识库。 参数中的知识难以精确更新和追溯，企业知识问答通常需要结合 RAG、权限控制和事实验证。

十二、核心知识链

预训练：学习语言、知识和通用能力
  ↓
SFT：学习遵循指令和生成高质量回答
  ↓
RLHF / DPO：学习人类对不同回答的相对偏好
  ↓
评估：验证能力、事实性、安全性和回归表现

十三、自测题

  1. 预训练为什么可以不依赖人工逐条标注？
  2. 为什么基础模型不一定会稳定回答用户问题？
  3. SFT 和 DPO 在训练信号上有什么差异？
  4. RLHF 中奖励模型的作用是什么？
  5. RLHF 为什么需要 KL 约束？
  6. DPO 与经典 RLHF 的主要流程差异是什么？
  7. 如果企业知识经常更新，为什么通常优先考虑 RAG 而不是微调？
  8. 人类偏好得分高为什么不等于事实一定正确？

十四、本课总结

  • 预训练以预测下一个 Token 为核心，让模型获得语言、知识和通用能力。
  • SFT 使用指令—回答样本，让基础模型学会对话、遵循指令和执行格式要求。
  • RLHF 通过人类偏好数据训练奖励模型，再用强化学习优化策略模型。
  • DPO 直接利用优选/较差回答对优化相对概率，通常比经典 RLHF 流程简单。
  • RAG 适合补充动态、私有且需要追溯的知识；微调更适合改变任务行为、输出格式和回答风格。
  • 训练后的模型必须同时评估能力、指令遵循、事实性、安全性和回归表现。
