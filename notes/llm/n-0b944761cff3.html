大模型微调（LLM Fine-tuning）技术清单

这是一份为您系统整理的大模型微调（LLM Fine-tuning）全图景知识清单。

这份清单从基础概念、技术路线、数据准备到工程落地进行了结构化拆解，不仅涵盖了您前面学到的 SFT 等概念，还补充了目前工业界主流的进阶技术。

模块一：核心概念与动机（Why & What）

  • [ ] 定义： 在预训练模型（Base Model）的基础上，使用特定领域的数据集进行进一步的训练，通过更新模型内部的权重参数，使其适应特定任务或对齐人类偏好。
  • [ ] 微调的动机（解决什么问题）：
    • 定制化输出格式： 让模型严格按照 JSON、代码或特定模版输出。
    • 语气与角色扮演： 赋予模型特定的性格、语气（如：傲娇客服、严谨律师）。
    • 注入领域深层逻辑： 让模型掌握医疗诊断、法律推理等专业领域的思考方式。
    • 降低推理成本： 把复杂的 Prompt（如 Few-shot 示例）内化到模型权重中，从而减少每次调用的 Token 消耗。
  • [ ] 边界认知（微调 vs RAG）：
    • 微调（Fine-tuning）： 适合教模型“怎么做”（能力与格式）。
    • 检索增强生成（RAG）： 适合给模型补充“是什么”（外部实时知识与事实）。
    • 业界最佳实践：通常是微调 + RAG 结合使用。

模块二：微调的生命周期（三个核心阶段）

大模型的后训练（Post-training）通常包含以下阶段：

  • [ ] 1. 增量预训练 (Continual Pre-Training, CPT / DAPT)：
    • 目的： 给模型注入海量垂直领域的专业知识（如大量医学论文、法律条文）。
    • 数据形式： 无监督的纯文本（与预训练阶段类似）。
  • [ ] 2. 监督微调 (Supervised Fine-Tuning, SFT)：
    • 目的： 教会模型听懂人类的指令（Instruction Tuning），把知识转化为一问一答的能力。
    • 数据形式： 高质量的“指令-输入-输出”（Prompt-Response）对话对。
  • [ ] 3. 人类偏好对齐 (Alignment)：
    • 目的： 消除有害输出，让模型的回答更符合人类价值观和偏好（例如：更有礼貌、不拒绝回答安全问题、不产生幻觉）。
    • 主流技术 1 - RLHF： 基于人类反馈的强化学习（训练奖励模型 + PPO 算法更新，流程复杂）。
    • 主流技术 2 - DPO (Direct Preference Optimization)： 直接偏好优化（目前开源界最火，跳过了奖励模型，直接用“好回答”和“坏回答”的数据对进行训练，成本低且稳定）。

模块三：参数更新策略（技术流派）

根据“到底要更新多少参数”，微调分为两派：

  • [ ] 1. 全参微调 (Full Fine-Tuning, FFT)：
    • 更新模型的所有参数（权重）。
    • 特点： 效果天花板最高，但极其昂贵，需要庞大的 GPU 算力集群，容易发生“灾难性遗忘”。
  • [ ] 2. 参数高效微调 (Parameter-Efficient Fine-Tuning, PEFT)：
    • 冻结原始模型的大部分参数，只训练极小部分（通常 < 1%）的新增参数。目前个人开发者和中小企业的绝对主流。
    • LoRA (Low-Rank Adaptation)： 最核心的 PEFT 技术。通过在模型的线性层旁边增加旁路（降维再升维的矩阵），只训练这个旁路。
    • QLoRA： LoRA 的进阶版，结合了量化技术（Quantization）。把基座模型压缩到 4-bit 精度加载，然后在上面跑 LoRA，单张消费级显卡（如 RTX 4090）就能微调百亿参数模型。
    • P-Tuning / Prefix Tuning： 不改变模型权重，而是在输入的 Prompt 层面增加可训练的连续向量（Soft Prompt）。
    • Adapter： 在 Transformer 的网络层之间插入小型的可训练前馈网络。

模块四：数据工程（Data Engineering）

在微调中，“Garbage in, garbage out（垃圾进，垃圾出）”是铁律。数据质量比数量重要得多（LIMA 论文证明：1000条极高质量数据胜过几十万条劣质数据）。

  • [ ] 数据格式标准：
    • Alpaca 格式： 包含 instruction (指令), input (上下文补充), output (预期回答)。
    • ShareGPT 格式： 更适合多轮对话的数据格式。
  • [ ] 数据构建方法：
    • 人工标注： 成本最高，质量最好。
    • Self-Instruct (蒸馏)： 利用 GPT-4 或 Claude 3 等最顶尖的闭源模型，自动生成提问和回答，用来训练自己的小模型（目前开源界广泛采用）。
  • [ ] 数据清洗： 去重、去除格式错误、过滤有害内容、控制文本长度分布。

模块五：主流框架与工具

  • [ ] 核心代码库：
    • Hugging Face 生态： Transformers (基座), PEFT (LoRA等实现), TRL (SFT/RLHF/DPO算法库), Datasets (数据加载)。
  • [ ] 分布式训练加速框架（多卡必用）：
    • DeepSpeed (微软)： 核心是 ZeRO 优化技术，通过显存切分大幅降低多卡训练的显存占用。
    • FSDP (PyTorch原生)： 全称 Fully Sharded Data Parallel，类似 ZeRO3。
    • Megatron-LM (Nvidia)： 适用于千亿参数以上极大规模集群训练。 [ ] 低代码/可视化微调工具（新手推荐）：*
    • LLaMA-Factory： 目前国内/GitHub 最火爆的开源项目。提供 Web UI 界面，只需点点鼠标、传个数据集就能完成上述所有复杂流程（支持百种大模型和QLoRA等技术）。
    • Swift (ModelScope社区)： 阿里推出的轻量级微调框架。

模块六：评估与常见坑点（Pitfalls）

  • [ ] 如何评估微调效果？
    • 传统 NLP 指标： BLEU, ROUGE, Perplexity (困惑度) —— 目前已逐渐被边缘化，因为无法真实反映大模型对话质量。
    • 客观 Benchmark 跑分： C-Eval (中文能力), MMLU (英文综合), HumanEval (代码) —— 防止模型微调后变成只会干一件事的“傻子”。
    • LLM-as-a-judge： 让 GPT-4 作为裁判，给微调模型和基座模型的回答打分盲测。 [ ] 必须警惕的坑点：*
    • 灾难性遗忘 (Catastrophic Forgetting)： 模型学会了垂直领域知识，却忘记了原本的通用常识（比如变成了写代码高手，但连简单的翻译都不会了）。对策：在微调数据中掺杂一定比例的通用域预训练数据。
    • 过拟合 (Overfitting)： 训练轮数（Epoch）过多或数据量太少，导致模型死记硬背了训练集，对没见过的问题胡言乱语。
    • 格式崩溃： 微调破坏了基座模型原本良好的对话模版（Chat Template）。
