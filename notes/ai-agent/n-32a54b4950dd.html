完成本章后，你应该能够：

  • 读懂由对象、数组、字符串、数字、布尔值和 null 组成的 JSON；
  • 指出 HTTP 请求和响应中的方法、地址、头、正文与状态码；
  • 把 API 理解为双方约定的接口，而不是某个特定网站或模型；
  • 识别超时、限流、鉴权失败和服务端错误，并避免盲目重试。

从“点餐单”理解 API

在餐厅里，顾客不会直接进入厨房操作设备，而是按菜单提交订单。菜单说明可选项目、 填写方式和价格；服务员把订单交给厨房，再带回结果或错误说明。

应用程序接口（Application Programming Interface，API）也提供类似约定：调用方按 规定格式提交请求，服务方返回规定格式的响应。双方不必知道对方内部每一步怎样实现， 但必须对字段、类型、错误和权限有共同理解。

JSON 是常见的数据表示

JSON（JavaScript Object Notation）是一种文本数据格式。下面是一份问答请求：

{
  "question": "怎样重置密码？",
  "top_k": 3,
  "include_sources": true,
  "filters": {
    "language": "zh-CN"
  }
}

这里包含：

  • 对象：最外层以及 filters，使用花括号；
  • 字符串：question 和 language 的值；
  • 数字：top_k 的值；
  • 布尔值：include_sources 的值；
  • 键值对：例如 "top_k": 3。

JSON 的键和字符串使用双引号。末尾多余逗号、单引号或 Python 专用的 True 都不是 标准 JSON 写法。

一次 HTTP 请求包含什么

HTTP 是客户端与服务端交换请求和响应的常见协议。一次请求至少要关注：

部分 作用 示例问题
方法 表示希望执行的动作 是读取 GET，还是提交 POST？
地址 指向服务与资源 请求发到哪个主机和路径？
头 携带内容类型、鉴权等元信息 正文是不是 JSON？令牌放在哪里？
正文 携带问题、参数等数据 字段名和类型是否符合契约？
超时 限制等待时间 服务没有响应时多久停止？

例如，调用方可能向 /answers 发送 POST 请求，正文使用前面的 JSON。这个路径只是 教学示例，不对应仓库中已经运行的服务。

响应不只有正文

服务端会返回状态码、响应头和正文。成功响应可能是：

{
  "answer": "请在登录页选择“忘记密码”。",
  "sources": ["handbook-7"]
}

但调用方不能只检查有没有 answer 字段，还要先处理 HTTP 状态：

  • 2xx：请求通常已被服务接受并处理，但仍要校验响应结构；
  • 4xx：请求、权限或调用频率存在问题，例如参数错误、未授权或限流；
  • 5xx：服务端处理失败；是否重试要结合请求性质和退避策略；
  • 超时或网络错误：没有获得完整响应，不能当作空答案或成功。

状态码只提供一层信号。具体错误字段和是否可重试应以目标 API 契约为准。

为什么不能见错就重试

读取请求重复一次通常风险较低，但创建订单、扣款或发送消息可能产生重复副作用。安全的 重试需要考虑：

  • 请求是否幂等，也就是重复执行是否仍保持同一结果；
  • 服务是否支持幂等键；
  • 错误是否短暂，例如服务繁忙，而不是永久参数错误；
  • 是否采用有限次数和逐步等待，而不是无限快速重试；
  • 是否记录请求编号，便于追踪重复与失败。

对 401 未授权或明显的 400 参数错误反复重试，通常不会解决问题，还可能触发更多 限制。

鉴权信息不是普通字段

很多 API 使用密钥或访问令牌确认调用身份。密钥不应写入教程正文、提交到 Git 或混入 用户问题。应用应从受控配置中读取，并避免在日志和错误信息中完整打印。

拥有令牌也不等于拥有所有数据权限。服务端仍需根据身份、资源和操作执行授权检查。

调试时按层检查

遇到失败时，可以按下面顺序缩小范围：

  1. 地址和网络是否可达；
  2. 方法、头和内容类型是否正确；
  3. JSON 是否能解析，字段名与类型是否符合契约；
  4. 鉴权是否存在、有效且未泄露；
  5. 状态码和错误正文说明了什么；
  6. 是否超时、限流或发生服务端故障；
  7. 当前请求是否适合重试。

这种分层检查比只看最后一行错误更容易定位问题。

自测与实践

  1. 在第一个 JSON 中，把 top_k 改成 5，并增加字符串字段 user_id。
  2. 解释 POST、请求头、正文和状态码分别解决什么问题。
  3. 为什么超时不能直接解释为“知识库没有答案”？
  4. 给出一个不适合盲目重试的请求，并说明可能的副作用。
  5. 找出这段无效 JSON 的两个问题：{'ok': True,}。

本章小结

JSON 是常见的数据表示，HTTP 负责传输请求与响应，API 则是调用双方的接口契约。可靠 调用不仅要处理成功正文，还要处理状态码、超时、限流、鉴权、授权和重试副作用。
