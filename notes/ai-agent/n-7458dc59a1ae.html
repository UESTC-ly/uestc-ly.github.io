MCP 是由 Anthropic 提出的开放标准协议，用于将 AI 模型与外部工具和数据源连接起来。

一、核心概念

MCP 的全称是 Model Context Protocol（模型上下文协议），它定义了一套标准化的通信协议，使 AI 模型能够安全、统一地与外部系统进行交互。

可以把 MCP 类比为 "AI 的 USB 接口"：

类比 对应角色
USB 标准 MCP 协议
电脑 USB 口 MCP 客户端
USB 设备 MCP 服务器
操作系统 模型（LLM）
使用电脑的人 用户（User）

二、架构全景

┌─────────┐     自然语言      ┌──────────────────────────────────┐
│         │ ◄──────────────► │          宿主应用程序              │
│  用户    │                  │  (Host Application)              │
│ (User)  │                  │  如: VS Code, Claude Desktop     │
└─────────┘                  │                                  │
                             │  ┌────────────┐  ┌────────────┐  │
                             │  │   模型      │  │ MCP 客户端  │  │
                             │  │  (LLM)     │◄►│ (Client)   │  │
                             │  └────────────┘  └─────┬──────┘  │
                             └────────────────────────┼─────────┘
                                                      │ MCP 协议
                                          ┌───────────┼───────────┐
                                          │           │           │
                                    ┌─────▼─────┐ ┌──▼────┐ ┌───▼─────┐
                                    │ MCP Server│ │Server │ │ Server  │
                                    │ (文件系统) │ │(数据库)│ │(Cloud   │
                                    │           │ │       │ │  Run)   │
                                    └───────────┘ └───────┘ └─────────┘

MCP 采用 客户端-服务器架构，一个宿主应用可以内嵌多个 MCP 客户端，每个客户端与一个 MCP 服务器建立 1:1 的连接。

三、四大角色详解

1. 用户（User）

用户是整个流程的发起者和最终接收者。

  • 输入：发起自然语言请求（如"帮我部署项目到 Cloud Run"）
  • 审批：对敏感操作进行确认（如确认项目 ID、同意执行命令）
  • 输出：接收模型整理后的自然语言回答

2. 模型（Model / LLM）

模型是整个流程的 "大脑"，负责理解和决策。

  • 理解用户的自然语言意图
  • 自主决定 是否需要调用工具，以及调用哪些工具
  • 将用户请求转化为具体的工具调用（function call）
  • 整合工具返回的结果，生成用户友好的回答

⚠️ 关键点：是 模型 决定调用什么工具，而不是用户直接指定。

3. MCP 客户端（MCP Client）

MCP 客户端是 协议层的桥梁，内置在宿主应用程序中。

  • 与 MCP 服务器建立 1:1 连接
  • 将模型的工具调用请求按 MCP 协议格式发送给服务器
  • 将服务器的响应返回给模型
  • 管理服务器的生命周期（启动、连接、断开）

常见的宿主应用： - Claude Desktop - VS Code（通过插件） - 其他支持 MCP 的 IDE 或应用

4. MCP 服务器（MCP Server）

MCP 服务器是 能力的提供者，负责与外部系统交互。

服务器暴露三类能力：

能力类型 说明 示例
Tools（工具） 可执行的操作 deploy_local_folder、list_projects
Resources（资源） 可读取的数据 文件内容、数据库记录、API 数据
Prompts（提示模板） 预定义的交互模板 代码审查模板、翻译模板

四、完整工作流程示例

以 Cloud Run MCP Server 为例，用户请求 "帮我列出所有 GCP 项目"：

步骤 1: 用户
        │
        │  "帮我列出所有 GCP 项目"
        ▼
步骤 2: 宿主应用 ──► 将用户消息 + 可用工具列表一起发送给模型
        │              （工具列表: list_projects, deploy_local_folder, ...）
        ▼
步骤 3: 模型 (LLM)
        │  理解意图 → 决定调用 list_projects 工具
        │  生成 tool_call: list_projects()
        ▼
步骤 4: MCP 客户端
        │  按 MCP 协议格式封装请求
        │  发送给 Cloud Run MCP Server
        ▼
步骤 5: Cloud Run MCP Server
        │  调用 GCP API
        │  获取项目列表
        ▼
步骤 6: 原路返回
        MCP Server → MCP 客户端 → 模型
        ▼
步骤 7: 模型整合结果
        │  将原始 JSON 数据整理为自然语言
        │  "您有以下 GCP 项目: project-a, project-b, ..."
        ▼
步骤 8: 用户看到最终回答 ✅

五、关键设计理念

5.1 标准化协议

MCP 定义了统一的通信协议，任何服务器只要遵循该协议就能被任何客户端使用，实现 即插即用。

5.2 模型驱动（Model-Driven）

与传统 API 由程序员直接调用不同，MCP 的工具描述包含 自然语言说明，由 AI 模型自主决定何时、调用哪个工具。

5.3 安全边界

  • MCP 服务器运行在本地或受控环境中
  • 敏感操作需要 用户确认（human-in-the-loop）
  • 权限由宿主应用控制

5.4 可组合性

一个客户端可以同时连接 多个 MCP 服务器，获得不同领域的能力：

MCP 客户端 ──► 文件系统 MCP Server（读写文件）
           ──► 数据库 MCP Server（查询数据）
           ──► Cloud Run MCP Server（部署服务）
           ──► GitHub MCP Server（管理仓库）

5.5 与传统 API 的区别

对比项 传统 API MCP
使用者 程序员 AI 模型
调用方式 硬编码调用 模型自主决策
接口描述 OpenAPI/Swagger 自然语言 + JSON Schema
发现机制 文档查阅 协议内自动发现
交互模式 请求-响应 对话式、上下文感知

六、MCP 服务器配置

MCP 服务器通常通过 JSON 配置文件来管理。配置文件定义了要连接哪些服务器、启动命令、环境变量等。

{
  "mcpServers": {
    "server-name": {
      "command": "启动命令",
      "args": ["参数1", "参数2"],
      "env": {
        "API_KEY": "your-api-key"
      }
    }
  }
}

常见的 MCP 服务器类型： - 云服务：Cloud Run、AWS Lambda - 开发工具：GitHub、GitLab - 数据库：PostgreSQL、MongoDB - 文件系统：本地文件读写 - 搜索引擎：Brave Search、Google Search - 自定义服务：任何遵循 MCP 协议的服务

七、总结

用户 ←→ 宿主应用（模型 + MCP客户端）←→ MCP服务器 ←→ 外部系统
  • 用户 只需用自然语言表达需求
  • 模型 理解意图并决定使用什么工具
  • MCP 客户端 负责协议通信
  • MCP 服务器 提供具体能力并执行操作

MCP 的核心价值在于：让 AI 模型能够以 标准化、安全、可扩展 的方式与外部世界交互，而无需为每个工具编写专门的集成代码。
