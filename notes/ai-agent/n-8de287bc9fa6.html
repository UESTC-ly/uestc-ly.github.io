记忆句：路由接请求，函数做处理，返回值变响应。

1. 为什么要有一个接口

假设你写了一个 Python 函数，用来查询今天的任务。在同一个程序里，直接调用函数就够了；但手机 App、浏览器和另一台机器上的程序，不能直接调用你进程里的函数。它们需要一个约定好的入口：向什么地址发送什么信息，最后能得到什么结果。HTTP API 就是这样的入口。

因此，学习 FastAPI 的第一步，是把“本地函数调用”和“网络请求”联系起来。客户端发来的不是 Python 对象，而是一条 HTTP 请求；服务端返回的也不只是一个字典，而是一条带有状态码、响应头和响应体的 HTTP 响应。FastAPI 帮我们完成中间的衔接，让业务逻辑仍然可以写成普通函数。

可以把接口想成办事窗口：地址说明去哪个窗口，HTTP 方法说明办什么事，参数是提交的材料，响应是办理结果。类比的边界是：同一个地址可以对应多种方法，窗口也不会替你决定业务规则。例如“任务标题不能重复”仍然需要自己实现。

2. 三个角色各做什么

角色 负责什么 在本章中如何出现
FastAPI 登记接口、组织请求处理与响应生成 app 和路由装饰器
Pydantic 按类型和规则校验、组织数据 后续请求体章节会重点使用
Uvicorn 运行应用，接收网络请求并交给应用处理 终端中的启动命令

可以先记成“服务器把请求接进来，框架安排谁处理，数据模型检查材料”。它们协同工作，但不是三个必须手动逐个调用的步骤。本章没有复杂输入，暂时看不到 Pydantic 模型，也照样能够提供接口。

app = FastAPI() 创建的是应用对象，并不会单独启动监听端口。执行一次 python main.py 后立即退出，通常不是程序坏了，而是你只创建了应用，还没有让服务器持续运行它。

3. 一条请求到底经过了什么

程序启动时，Python 执行模块，创建 app，并执行装饰器。@app.get("/hello") 的意思是登记一条规则：收到指向 /hello 的 GET 请求，就调用下面的函数。它不是在登记时立即执行函数，也不是每收到一次请求就重新定义函数。

请求到达后，框架根据路径和 HTTP 方法寻找匹配规则，然后调用处理函数。本章函数返回 Python 字典；框架再把字典转换为 JSON 响应，交回客户端。客户端看到的是 JSON 数据，并不知道服务端的函数叫什么名字。

这就解释了一个很实用的区别：把函数名 hello 改成 say_hello，只要装饰器不变，请求地址仍是 /hello；把装饰器中的地址改成 /ping，客户端就必须访问新地址。接口地址由路由声明决定，不由函数名决定。

4. HTTP 方法表达操作意图

方法 常见意图 任务系统中的例子
GET 读取数据 查询某个任务
POST 创建资源或触发动作 新建任务
PUT 整体替换资源 提交一份完整任务资料
PATCH 局部修改资源 只修改任务标题
DELETE 删除资源 删除任务

这些是接口设计约定，不是写上方法后就会自动发生的业务行为。写一个 POST 路由不会自动保存到数据库；写 DELETE 也不会自动删除记录。方法表达意图，函数落实行为。

浏览器地址栏通常发出 GET 请求，所以它适合试读接口。需要提交 JSON 的 POST 请求时，用 /docs 更直观。访问存在的路径但使用未支持的方法，通常得到 405；根本没有匹配的路径，则通常得到 404。

5. 最小 demo：只验证一次请求和响应

完成学习地图中的环境安装后，将下面代码复制到 main.py，在该文件所在目录运行 python -m uvicorn main:app --reload。每次只运行一章，切换前按 Ctrl+C 停止服务。

from fastapi import FastAPI

app = FastAPI(title="第一个接口")


@app.get("/hello")
def hello():
    return {"message": "Hello FastAPI"}

命令中的 main:app 可以读成“导入 main 模块，找到其中的 app 对象”，不是文件路径。--reload 用于开发：保存修改后自动重新加载应用。重新加载会重新创建内存变量，因此不要把它当作持久保存数据的方法。

打开 交互文档，展开 GET /hello，点击 Try it out → Execute。观察两件事：状态码是 200，响应体中的 message 是 Hello FastAPI。先建立“成功状态 + 返回数据”这一完整印象，不必背命令行请求写法。

把返回内容改成自己的问候语，再执行一次。随后仅修改函数名，确认地址不变；最后把路由地址改成 /ping，刷新 /docs，确认文档也跟着更新。

可选配套：demos/ch01.py。配套文件独立于正文，可能包含更完整的演示内容。

6. 为什么文档能自动生成

路由已经声明了地址与方法，后续的类型标注还会声明输入和输出结构。FastAPI 根据这些声明生成 OpenAPI 描述，/docs 再把描述展示成可以试调用的页面。/openapi.json 是机器可读的接口说明；/redoc 是另一种阅读页面。

自动生成文档能减少重复维护，但不能代替解释业务语义。例如一个叫 status 的字段有哪些状态、什么时候会改变，仍需要开发者说明。文档页面可以打开，也不等于数据库、登录等所有业务功能都已正常。

7. 合上笔记，检查是否真的理解

为什么只创建 app 还不能让别人访问？ 因为应用对象描述如何处理请求，仍需要服务器运行它并接收请求。

返回字典为什么能让浏览器看到 JSON？ 字典是处理函数的 Python 返回值，框架负责把它序列化为 HTTP 响应。

Python 类型标注会让所有普通函数自动校验吗？ 不会。FastAPI 和 Pydantic 在相应边界读取标注并执行校验；普通 Python 函数不会仅因写了 int 就自动拒绝字符串。
