1. 为什么需要 Human-in-the-loop

模型适合处理开放式理解和候选方案，但以下情况不应完全自动化：

  • 扣款、退款、删除、发布、发送外部消息等有副作用操作；
  • 低置信度或多个方案都合理；
  • 涉及法律、医疗、财务或高敏感个人数据的关键判断；
  • 工具结果冲突、策略拒绝或重试耗尽；
  • 自动化动作可能造成不可逆损失。

Human-in-the-loop（HITL）不是简单地在 Prompt 里说“请用户确认”，而是一个可持久化、可审计、可过期的业务状态。

2. 审批状态

一个可恢复的审批流程可以包含：

RUNNING
  ↓
WAITING_APPROVAL
  ├─ APPROVED → RUNNING
  ├─ REJECTED → CANCELLED / REPLAN
  ├─ EXPIRED → FAILED / NEEDS_REVIEW
  └─ EDITED → 重新校验 → WAITING_APPROVAL

审批请求至少包含：

  • 任务 ID、步骤 ID 和审批范围；
  • 将要执行的工具、资源和参数摘要；
  • 风险说明、预计影响和有效期；
  • 请求人、审批人、时间和决定；
  • 参数被修改时的版本号或哈希。

审批只对明确的动作和参数有效。审批后如果参数、资源或用户身份发生变化，必须重新审批。

3. 风险分级

可以先采用简单分级：

风险 示例 处理
低 查询公开资料、读取用户自己的订单 自动执行并记录
中 批量生成草稿、修改可恢复配置 用户确认或抽样复核
高 扣款、退款、删除、发布、对外发送 明确审批、幂等和审计
不允许 越权访问、导出密钥、绕过审计 直接拒绝

风险分级应由应用策略决定，不能让模型自行声明“这是低风险”。

4. 长任务的基本架构

长任务不能绑定在一次同步 HTTP 请求中。推荐拆成：

API 接收请求
  ↓ 创建 task 记录并返回 task_id
队列投递任务
  ↓
Worker 领取并处理一个或多个状态节点
  ↓ 保存检查点、进度和事件
需要审批则暂停并通知用户
  ↓ 用户通过 API/UI 恢复
Worker 从检查点继续
  ↓
完成、失败、取消或转人工

状态至少应有：QUEUED、RUNNING、WAITING_APPROVAL、RETRYING、SUCCEEDED、FAILED、CANCEL_REQUESTED、CANCELLED。

5. 任务 API 的最小设计

POST /tasks
→ {"task_id": "task_001", "status": "QUEUED"}

GET /tasks/task_001
→ 返回当前状态、进度、可展示结果和下一步动作

POST /tasks/task_001/approve
→ 带 approval_id、版本号和审批决定

POST /tasks/task_001/cancel
→ 写入取消请求，由 Worker 在安全点处理

不要让前端通过提交任意状态值来改变任务；服务端应根据事件和当前状态执行合法转移。

6. 进度与用户体验

进度应基于可验证阶段，而不是模型随口生成的百分比：

{
  "phase": "checking_order",
  "completed_steps": 2,
  "total_steps": 5,
  "message": "正在核对订单资格",
  "updated_at": "..."
}

对不确定的 Agent 任务，可以展示“已完成的阶段”和“当前等待事项”，不要伪造精确进度。用户应能看到失败原因、是否可重试、是否需要补充信息和取消入口。

7. 取消、恢复和并发

  • 取消通常是请求，不一定能立即中止已发出的外部请求；
  • Worker 在工具调用前、调用后和长循环间检查取消标志；
  • 同一任务只能有一个有效执行者，或使用租约和版本锁；
  • Worker 崩溃后由队列重新投递，但必须依赖幂等处理；
  • 恢复时重新确认截止时间、权限、审批有效期和外部状态；
  • 不要从任意消息中间恢复 Tool Calling 链，必须从一致检查点恢复。

8. HITL 与模型的配合

模型可以生成给人的说明、候选选项和风险摘要，但应用应生成最终审批单，并从可信业务状态中填充金额、资源和权限信息。审批结果回传模型时，只需提供必要的结构化事实，不要把内部审计细节全部暴露给模型。

9. 典型失败场景

  • 审批通过后任务重复执行：缺少幂等键或审批版本校验；
  • 页面刷新后审批状态丢失：审批未持久化；
  • Worker 重启导致重新扣款：没有检查点和外部状态查询；
  • 用户取消但任务仍继续：取消只改了前端状态，没有服务端取消标志；
  • 审批内容与实际参数不一致：审批绑定的是模糊描述而非参数版本。
