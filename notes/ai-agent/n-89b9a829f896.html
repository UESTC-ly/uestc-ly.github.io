完成本章后，你应该能够：

  • 区分参数化知识和外部知识，不把大语言模型等同于知识库；
  • 从新鲜度、可追溯性、覆盖范围和运行代价比较两类知识来源；
  • 解释为什么“接入外部资料”仍然不能保证答案正确；
  • 为一个具体问题写出知识来源、更新时间、权限和冲突处理要求。

先想象闭卷考试和开卷办事

闭卷考试时，你只能依靠已经记住的内容。开卷办事时，你仍然需要理解问题和组织答案， 但可以查阅当前有效的制度、手册或记录。

大语言模型直接回答问题，有点像一次非常复杂的“闭卷作答”：它利用训练过程中形成的 内部能力和知识模式来预测后续内容。RAG 则给回答过程增加了“开卷查资料”的机会。模型 并没有因此失去内部能力；它仍要理解问题、阅读材料并组织语言，只是多了一组在请求时 提供的外部证据。

这个类比只用于建立直觉。模型参数不是一本可以逐页翻阅的书，外部知识也不一定真的 正确。两者都需要边界和验证。

什么是参数化知识

参数化知识（parametric knowledge）指模型在训练后以参数模式承载、并在生成时表现出来 的知识和能力。你通常不能像查询数据库那样，准确指出某条回答来自哪一个训练样本，也 不能通过替换一份业务文档就精确修改模型参数中的单个事实。

参数化知识适合提供通用语言能力、常见概念关系、表达风格和推理模式。例如，模型可能 知道“报销”通常涉及申请、凭证和审批这些概念，也能把零散材料改写成通顺的说明。

但它有几个重要边界：

  • 更新时间不透明。 模型不一定包含组织今天刚发布的制度。
  • 来源难以逐条回查。 流畅表达不能证明事实来自哪个权威来源。
  • 修改成本高。 不能把训练或微调理解为编辑一行配置文件。
  • 记忆不等于授权。 即使模型似乎知道某件事，也不代表当前用户有权获得它。

这些边界不表示参数化知识“没有用”，而是说明不能把它当作实时、权威、可审计的业务 数据库。

什么是外部知识

外部知识（external knowledge）指在模型参数之外保存，并在请求前或请求中读取的资料。 它可以是本地 Markdown、产品手册、数据库记录、经过授权的内部页面，也可以是某个系统 通过 API 返回的当前状态。

在典型 RAG 中，外部资料会先被处理成可检索单元；查询到来时，系统找出候选内容，再把 选中的上下文交给回答步骤。由于原始资料仍然存在，系统有机会返回来源、版本、页码或 文本块位置，供人核对。

外部知识的价值通常来自四点：

  1. 可更新。 替换或新增资料后，可以重新处理相关内容，而不必重新训练整个模型。
  2. 可追溯。 答案可以关联到具体来源位置。
  3. 可限定范围。 系统能够只检索某个产品、地区、租户或权限范围内的内容。
  4. 可观察。 可以分别检查检索候选、上下文和最终回答。

然而，“外部”不等于“正确”。过期文件、错误 OCR、未经批准的草稿和恶意文本都可能 进入知识源。如果系统只追求“搜到内容”，却没有来源治理和权限控制，RAG 可能让错误 信息看起来更有根据。

用一条报销制度理解差异

假设公司去年规定“差旅报销须在 30 天内提交”，今年将期限改为 15 天。

只依赖参数化知识的回答器，可能给出常见但不适用于本公司的步骤，也可能说出已经过期 的期限。接入外部知识后，系统有机会检索今年生效的制度，并返回具体章节。

但下面四种情况仍然会失败：

  • 新制度尚未进入知识库，索引中只有旧版；
  • 新旧制度都在，但没有版本和生效日期，检索把旧版排在前面；
  • 检索找到了新版，回答却把“15 天”改写成“15 个工作日”；
  • 用户无权查看该制度，系统却在检索后泄露了内容。

所以真正的问题不是“模型记忆还是知识库，二选一”，而是：什么信息由哪一层负责，哪 个来源在什么条件下具有权威性，如何证明答案没有超出证据和权限。

两类知识来源怎样配合

比较维度 参数化知识 外部知识
主要作用 提供通用能力和已学习模式 提供请求时可读取的具体资料
更新方式 训练、继续训练或其他模型更新 更新数据并重新处理相关索引
来源回查 通常难以逐条定位 可以保留文档、版本和位置
新鲜度 受训练与发布周期影响 取决于采集、同步和索引流程
运行依赖 模型本身即可生成 依赖数据源、检索和上下文构造
典型风险 记忆过时、无依据补全 数据过期、召回失败、权限泄露

工程上常见的做法是让模型负责理解与表达，让外部系统负责保存需要更新、审计或授权的 事实。这是一条设计倾向，不是适用于所有项目的绝对规则。对于极小且稳定的规则，配置 或普通程序可能比 RAG 更简单；对于实时余额、库存或订单状态，调用权威业务 API 往往比 检索文档更合适。

当来源互相冲突时

如果同一个问题检索到两个不同答案，系统不能只因为某一段相似度更高就宣布它正确。 冲突处理至少需要考虑：

  • 来源是否经过批准，草稿和正式制度不能同级；
  • 版本号、生效时间和失效时间是否明确；
  • 来源是否适用于当前产品、地区、角色和用户；
  • 是否应该展示冲突并拒绝给出单一确定结论；
  • 是否有负责人可以确认并修复上游资料。

工程建议： 把来源身份、版本、时间和权限作为数据的一部分保留下来，不要等到最终 回答阶段才猜测哪份材料可信。具体优先级必须由业务规则决定，不能由教程替项目代定。

一个离线知识来源清单

任选一个熟悉的场景，例如课程安排、家电说明书或团队值班表，写下：

  1. 哪些内容可以依赖通用语言能力；
  2. 哪些事实必须来自外部资料；
  3. 谁负责更新资料，多久可能变化一次；
  4. 用户需要什么权限；
  5. 两份资料冲突时应该显示什么，而不是猜什么。

如果这五项写不清楚，直接开始选择向量数据库或调整 Prompt 通常为时过早。

常见误解

误解一：模型参数里保存着一套可以精确搜索的百科全书。

不成立。模型可以表现出知识，但不能默认提供数据库式的来源、版本和精确更新能力。

误解二：只要文档是外部的，答案就一定最新。

不成立。采集延迟、索引延迟、旧版本残留和错误排序都会破坏新鲜度。

误解三：有引用就代表来源权威。

不成立。引用只能帮助定位，仍需判断来源身份、适用范围以及引用是否真的支持结论。

误解四：RAG 会让模型只复述资料，完全不再使用参数化能力。

不成立。模型仍会利用内部语言和推理模式理解、选择和组织内容，因此仍可能误读或补写。

自测

  1. 参数化知识与外部知识最核心的区别是什么？
  2. 为什么“能够更新知识库”不等于“答案已经最新”？
  3. 报销制度新旧版本同时被检索到时，为什么不能只看相似度？
  4. 哪类数据更适合直接调用权威 API，而不是从说明文档中检索？
