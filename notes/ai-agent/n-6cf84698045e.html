这套笔记以 Python 3.11+ 为基线，目标不是只记住语法，而是逐步具备以下能力：

  1. 能写出清晰、类型明确、可测试的 Python 程序；
  2. 能正确选择同步、线程、进程和协程；
  3. 能处理结构化数据，并用 API 暴露服务；
  4. 能构建具备工具调用、状态管理、超时、重试、日志和测试的 AI Agent；
  5. 能管理项目环境和依赖，让代码可以被他人稳定复现。

当前版本已经按“概念直觉 → 运行机制 → API/语法 → 示例 → 边界与反例 → Agent 场景 → 练习验收”的结构进行详细扩写。阅读时不必一次记住所有 API，重点是建立选择方案和定位错误的心智模型。

适合谁

  • Python 初学者，希望学习路线不止停留在基础语法；
  • 已经会写简单脚本，但对类型、测试、异步和工程结构不熟悉的人；
  • 准备使用大模型 API、Agent 框架或自研 Agent Runtime 的开发者。

如果你从未接触编程，建议先补充变量、条件、循环、输入输出等最基础内容，再从第 1 章开始。本笔记的代码默认在项目根目录执行，命令中的 python 在部分系统上可能需要替换为 python3。

每章怎么学

建议用“读—敲—改—测—讲”五步法：

  1. 读：先看学习目标和概念，不急着记忆所有 API；
  2. 敲：手动输入示例，不要只复制；
  3. 改：改变输入、删除一个保护条件，观察行为；
  4. 测：为核心函数补一个正常用例和一个错误用例；
  5. 讲：不用术语堆砌，向别人解释“为什么这样设计”。

详细章节中通常会同时出现“教学最小例子”和“更稳健的 Agent 例子”。前者用于隔离语义，后者用于展示边界；不要因为生产代码更长就跳过最小例子，也不要把最小例子未经补强直接部署。

建议的笔记方式

每个知识点单独记录四栏：

概念：它解决什么问题？
机制：Python 在运行时做了什么？
选择：什么时候用，什么时候不用？
证据：我运行了什么例子或测试？

遇到错误时追加“错误输入、异常、根因、修复后的回归测试”。这种记录比只摘抄 API 更容易在 Agent 项目中复用。

统一示例约定

  • Python 版本：3.11 或更高；
  • 类型标注采用 list[str]、X | None 等现代语法；
  • shell 命令以 macOS/Linux 为例，Windows PowerShell 的虚拟环境激活命令会单独说明；
  • 代码中的模型调用会优先使用可测试的假实现，避免学习过程依赖密钥和网络；
  • 涉及第三方库时，优先参考当前项目锁文件与官方文档，不在笔记中写死易过期的版本号。

最终能力自测

学完后，你应该能独立回答并实践：

  • 为什么 Agent 的消息历史适合 list，工具注册表适合 dict，能力标签适合 set？
  • dataclass 和 Pydantic 分别适合内部对象还是外部数据边界？
  • 一个工具失败时，应该在哪里捕获异常、记录什么日志、向模型暴露什么错误？
  • 为什么在 async def 中直接调用阻塞 SDK 会拖慢整个服务？
  • I/O 密集任务、CPU 密集任务分别优先考虑线程、进程还是协程？
  • 如何给模型调用设置总超时、限制并发、传播取消，并保证资源被释放？
  • 如何把 Agent 的请求/响应建模成 Pydantic 模型并用 FastAPI 暴露？
  • 如何在没有真实模型 API 的情况下，对 Agent 循环、工具调度和失败路径做确定性测试？
  • 如何使用锁文件重建一致的环境，并在提交前自动执行格式化、静态检查和测试？

完成这些自测并通过第 10 章项目验收，就具备了进入具体模型 SDK 和 Agent 框架的基础。
