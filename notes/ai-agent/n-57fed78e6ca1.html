先建立项目目录的心智模型

后续示例通常包含正文、Python 文件、测试和依赖说明。命令行会在一个“当前工作目录”中 执行；相对路径都从这里开始解释。很多“文件不存在”错误并不是文件真的消失，而是命令 在错误目录运行。

进入项目后，先确认三件事：当前位置、目录内容、Python 版本。macOS 和 Linux 常用：

pwd
ls
python3 --version

Windows PowerShell 常用：

Get-Location
Get-ChildItem
py --version

不同系统和安装方式可能没有 python3、python 或 py 中的某一个命令。不要在报错后 随机重复；先根据安装文档确认本机实际入口。教程后续若给出命令，也应标明使用的 shell。

Python 解释器与脚本

Python 解释器读取代码并执行。下面的程序把两个数字相加：

numbers = [2, 3]
total = sum(numbers)
print(total)

保存为 sum_demo.py 后，macOS 或 Linux 可运行 python3 sum_demo.py；Windows 常见入口是 py sum_demo.py。预期输出是 5。如果入口不同，应替换解释器命令，而不是修改程序逻辑。

为什么需要虚拟环境

项目 A 可能需要某个包的旧版本，项目 B 需要新版本。全部安装到同一全局环境会让升级 一个项目时破坏另一个项目。虚拟环境为当前项目提供隔离的解释器和包目录。

在 macOS 或 Linux 中创建并激活 .venv：

python3 -m venv .venv
source .venv/bin/activate
python -m pip --version

在 Windows PowerShell 中：

py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip --version

命令验证范围：本章的 Bash 示例已在 macOS 的 zsh 环境执行；当前编写环境没有 PowerShell，因此 Windows 示例只完成了静态核对，仍需在 Windows 环境再次运行验证。

激活后使用 python -m pip，可以更明确地让 pip 跟随当前解释器。关闭终端或执行 deactivate 后，环境会退出；.venv 通常不提交到 Git，因为它可以根据依赖说明重建。

虚拟环境只隔离 Python 包，不自动隔离系统服务、GPU 驱动、网络或密钥。

安装依赖前先看说明

不要看到导入错误就随意安装同名包。先检查项目维护的依赖文件、支持的 Python 版本和 启动说明。安装完成后还要运行项目提供的测试或最小检查；“安装命令没有报错”不等于 整个项目可用。

遇到问题时记录：

  • 操作系统和 shell；
  • Python 版本与解释器路径；
  • 当前目录；
  • 执行的完整命令；
  • 完整错误输出，而不是只截最后一行。

命令行中的成功与失败

命令执行结束时通常返回退出码：0 常表示成功，非零表示失败。脚本即使打印了部分正常 内容，也可能最后失败。自动化测试和持续集成主要依赖退出码，而不是猜测屏幕文字颜色。

还要注意：命令行中的空格、引号、路径分隔符和换行都有意义。路径包含空格时需要正确 引用；PowerShell 与 Bash 的激活命令不能混用。

Git 保存的是版本历史

Git 用来记录文件变化。最常见的观察命令是：

git status
git diff

git status 告诉你哪些文件已修改、已暂存或未跟踪；git diff 展示尚未暂存的文本差异。 一次提交把选定改动保存到本地历史，并附带说明。提交前应确认没有把 .venv、密钥、 大型数据或无关文件混进去。

提交不等于上传。只有在配置远端并执行推送后，远端仓库才可能收到历史；是否允许推送、 推送到哪个分支属于项目协作规则。

一条安全的练习路径

  1. 新建一个空练习目录并进入它。
  2. 确认 Python 版本和当前目录。
  3. 创建并激活 .venv。
  4. 运行 sum_demo.py，核对输出是否为 5。
  5. 初始化一个练习 Git 仓库，使用 git status 观察新文件。
  6. 新增忽略规则，确保 .venv 不进入提交范围。
  7. 删除整个练习目录即可清理；不要在真实项目中练习危险的删除或历史改写命令。

常见失败与边界

现象 先检查什么
command not found 命令是否安装、名称是否适合当前系统、PATH 是否正确
No such file 当前目录和相对路径
导入包失败 是否激活正确虚拟环境、是否按项目依赖安装
权限错误 文件权限和目录所有者；不要默认使用管理员权限绕过
Git 出现大量无关文件 是否在正确目录初始化、忽略规则是否生效
本地提交远端看不到 是否配置远端并推送；不要把提交和推送混为一谈

自测

  1. 虚拟环境解决什么问题，又不解决什么问题？
  2. 为什么运行命令前要确认当前目录？
  3. git status 和 git diff 分别帮助你观察什么？
  4. 为什么不应把密钥或 .venv 提交进仓库？
  5. 一条命令打印了部分结果但退出码非零，你会把它记为成功吗？为什么？

本章小结

Python 解释器执行代码，虚拟环境隔离项目包，命令行把操作放在明确目录和 shell 中，Git 记录可审查的本地历史。先确认环境、路径和退出状态，再判断操作是否成功。
