1. 为什么还需要请求体

上一章把编号和查询条件放在 URL 里。但创建一个任务时，客户端可能要提交标题、优先级和标签列表。把这些内容全部塞进查询字符串，读起来不方便，表达嵌套结构也不自然。请求体就是随请求一起发送的一份数据，常见格式是 JSON，适合承载这样的结构化内容。

可以把 URL 看成投递地址，把请求体看成信封里的表格。地址决定交给谁处理，表格提供这次处理所需的资料。它们并不互斥：修改第 3 个任务时，路径可以携带编号，请求体携带要修改的内容。

本章使用 POST 演示 JSON 请求体。不要因为“请求体里放了数据”，就认为数据已经保存：接收、校验和持久化是不同步骤。本章只把处理结果返回，数据库保存留到数据库章节。

2. 数据模型是一份可执行的约定

继承 BaseModel 的类描述数据结构：字段名规定有哪些信息，类型规定每份信息是什么，默认值规定缺失时怎么办，Field 则补充长度和范围等要求。它不只是文档，也会参与实际请求校验。

请求到达时，框架先读取 JSON，再按模型解析和校验。通过以后，函数拿到的是一个模型对象，可以用 task.title 访问字段。没有通过时，默认返回 422，并指出出错字段；本次请求不会正常进入处理函数的业务逻辑。

这里可以把模型理解为“带检查规则的表格”。类比的边界是，模型不仅核对字段，还可能转换输入。例如默认的宽松校验可能把可解析的数字字符串转换为整数。所以校验通过通常表示“能解析成规定的数据”，不一定表示“原始输入的类型与声明一模一样”。确实需要拒绝这种转换时，再考虑严格模式。

3. 最容易混淆的是缺失和 null

字段声明 可以缺失吗 可以传 JSON null 吗 应如何理解
name: str 不可以 不可以 必须提供字符串
name: str = "未命名" 可以 不可以 不提供就用默认字符串
name: str \| None 不可以 可以 必须交这个字段，但可明确置空
name: str \| None = None 可以 可以 不交与明确置空都可接受

“字段缺失”是 JSON 中根本没有这个键；“字段为 null”是键存在，但值为空。它们代表的意图可能不同。例如修改用户资料时，不传昵称可能意味着保持原值，传 null 可能意味着清空昵称。暂时不必实现更新接口，但应先保留这个区别。

本系列采用 Pydantic v2。不要把 str | None 自动读成“选填”：允许空值与是否必须提供是两件事。先看有没有默认值，再看类型是否包含 None，就不容易判断反了。

4. 哪些规则适合放进模型

标题的最大长度、优先级的取值范围，属于单份输入就能判断的规则，适合放在模型里。某个任务是否已存在、当前用户能否创建任务，则需要数据库或登录上下文，通常由业务逻辑和权限逻辑处理。

模型校验也不能靠规则名称想当然。min_length=1 能拒绝空字符串，但一个空格仍然占一个字符；若业务要求“去掉两端空白后仍有内容”，就需要额外规范化或校验。先说明业务真正要求什么，再选择校验方式。

额外字段也是一种约定。Pydantic 默认通常忽略未声明的输入字段；设置 extra="forbid" 可以改成拒绝。例如客户端把 priority 拼成 prioroty，默认忽略可能让系统悄悄使用优先级默认值，而拒绝额外字段能更早暴露拼写问题。本章最小示例保留默认行为，配套示例展示拒绝方式。

5. 最小 demo：标题必填，优先级有默认值

完成环境安装后，将代码复制到 main.py，在该文件所在目录运行 python -m uvicorn main:app --reload。切换章节前按 Ctrl+C 停止上一章。

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=30)
    priority: int = Field(default=1, ge=1, le=3)

@app.post("/tasks", status_code=201)
def create_task(task: TaskCreate):
    return task.model_dump()

打开 交互文档，展开 POST /tasks，点击 Try it out。把请求体改为 {"title":"学习 FastAPI"} 后执行。状态码为 201，响应中除了标题，还会出现默认的 priority: 1。

接下来每次只改变一个条件：把标题改为空字符串，观察长度错误；删掉标题，观察必填错误；把优先级改成 9，观察范围错误。它们都返回 422，但错误位置和原因不同。读错误时，先找到字段位置，再看约束，不必背完整的错误 JSON。

这里的 201 是为了演示创建接口常用的成功状态；示例只返回校验后的数据，没有保存任务。最小示例的目标是看清请求体如何变成模型对象。

可选配套：demos/ch03.py，额外展示标签列表与禁止未知字段，比正文示例完整。

6. 模型、字典和 JSON 是三种东西

模型对象便于在 Python 中按字段访问，并携带模型定义的结构信息；model_dump() 返回 Python 字典，适合交给后续处理；JSON 是网络传输时常用的文本表示。三者关系密切，但不能混为同一种类型。

本章返回字典后，FastAPI 负责生成 JSON 响应。model_dump_json() 才会直接生成 JSON 字符串。若在普通接口里把这类字符串当普通返回值再交给框架，可能得到被再次编码的字符串，所以入门时直接返回模型或字典更清楚。

model_validate() 用于根据一份输入构造并校验模型。路由参数已经声明为模型时，框架会完成相应解析，通常不需要在函数里对同一份请求再手动校验一次。

列表默认值也有一个易记写法：Field(default_factory=list) 表达“创建每个对象时，都调用 list 生成自己的列表”。Pydantic 对部分可变默认值有保护机制，但工厂写法能直接说清意图，也方便扩展为其他动态默认值。

7. 合上笔记，检查三条边界

模型校验通过，数据就进入数据库了吗？ 没有。校验只保证数据符合声明，保存需要单独实现。

model_dump() 返回 JSON 字符串吗？ 返回 Python 字典，最终网络响应由框架序列化。

只给函数写一个普通字符串参数，它会自动从 JSON 请求体取吗？ 通常不会，普通标量默认会按查询参数处理；单独的请求体标量需要显式使用 Body。本章的 BaseModel 参数则默认作为请求体。
