02 RAG 原理

← 返回专题下载 Markdown ↓
本篇目录
  • 阅读顺序
  • 配套观察入口
  • 学完这一部分后

这一部分回答五个入门问题：RAG 是什么、模型“记住的知识”和外部资料有什么不同、 一条请求怎样经过索引与查询阶段、什么场景值得使用 RAG，以及整条链路会在哪里失败。

建议按顺序阅读。前两章建立直觉，第三章把直觉连接成数据流，最后两章训练选型和排障 能力。这里讲的是通用原理，不把任何单一框架、模型或数据库当作唯一答案。

阅读顺序

  1. 02-01 什么是 RAG：建立“先找证据，再组织答案”的最小直觉。
  2. 02-02 参数化知识与外部知识：理解知识从哪里来，以及新鲜度和可追溯性的边界。
  3. 02-03 索引阶段与查询阶段：看清文档准备和在线问答两条流水线。
  4. 02-04 适用场景与不适用场景：用业务约束判断是否应该采用 RAG。
  5. 02-05 失败模式与系统边界：沿数据、检索、上下文、生成和安全链路定位问题。

配套观察入口

  • 运行 minimal-rag 示例：离线观察最小数据流。
  • 查看 D01 端到端流程源文件：当前是 Mermaid 图源，是否完成渲染以项目验证记录为准。
  • 本部分章节摘要：从 02-01 摘要开始，可快速回顾每章新增结论。

学完这一部分后

你应该能够把一个 RAG 系统拆成知识来源、索引阶段、查询阶段和回答阶段，说明每一步的 输入与输出；你也应该能够在“需要最新资料”“必须引用来源”“数据受权限控制”等约束下 做出初步选型，并在答案错误时先定位链路，而不是只调整提示词。

需要始终记住：RAG 增加了一条可更新、可核对的外部证据路径，但不会自动保证资料正确、 检索相关、引用成立或生成忠实。它可能降低部分无依据回答的风险，不能消除幻觉。
