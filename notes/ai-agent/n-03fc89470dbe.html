完成本章后，你应该能够：

  • 解释为什么不同来源需要统一的文档模型；
  • 区分 Loader 与 Parser 的责任；
  • 为一个 Document 列出内容、来源、格式和处理状态；
  • 识别“读到了文本，但丢了证据”的不完整摄取结果。

先把快递包裹和里面的物品分开

收到快递时，包裹外面有寄件人、运单号和到达时间，里面才是实际物品。仓库不会为了 记录物品而扔掉运单，因为运单帮助它追踪来源、处理退货和排查丢件。

原始文件也有两层信息。正文是之后要检索的内容；文件路径、对象编号、格式、版本和 访问范围则像运单。只返回一个字符串虽然方便，却会让系统失去引用、更新和授权所需的 依据。因此摄取管线通常先建立统一的文档（Document）对象。

Document 是管线中的交接对象

这里的 Document 不是特指 Word 文件，而是一个概念模型：它把一份来源的内容与描述 这份内容的元数据放在同一个可追踪对象中。最小模型可以包含：

字段 回答的问题 示例
document_id 这份逻辑文档是谁 policy-return-cn
content 当前提取到了什么 退货政策正文
source_uri 从哪里读到 受控文件路径或对象地址
media_type 应该按什么格式解释 text/markdown
version 这是哪个版本 业务版本或内容摘要
metadata 还有哪些结构与约束 标题、语言、权限、更新时间
status 处理是否完整 成功、部分成功或失败

工程建议： 内容字段与元数据字段应有清楚的类型和必填规则。不要把所有信息拼进 一个不可检查的长字符串，也不要因为某字段暂时用不到就永久丢弃。

Document 与后续的文本块（Chunk）不是同一个对象。一份 Document 可以切成多个 Chunk； 每个 Chunk 仍需保留回到原 Document 的标识和位置。切分策略将在 04 部分展开。

Loader 负责取得字节或记录

加载器（Loader）回答“去哪里拿数据，怎样拿到”。常见 Loader 会：

  • 从允许的本地目录读取文件；
  • 从对象存储读取指定对象；
  • 从数据库按游标读取记录；
  • 从经过授权的接口接收响应；
  • 记录来源、读取时间、大小和读取错误。

Loader 不应该猜测复杂文件内部的语义。例如，它可以读取一份 PDF 的字节并标注媒体 类型，但不必同时决定页眉是否属于正文。把获取与解释分开，才能分别测试网络失败、权限 失败和格式失败。

Parser 负责解释格式

解析器（Parser）回答“这些字节或字符代表什么”。它根据格式提取文本、标题、页码、 表格或其他结构，并报告无法解释的部分。

同一来源可以经过不同 Parser。例如一份带文本层的 PDF 可直接提取文字；扫描版 PDF 可能需要 OCR。两条路径的错误性质和成本不同，但 Loader 仍然可以是同一个。

一个清楚的责任边界是：

  1. Loader 取得来源并创建原始记录；
  2. 格式识别步骤校验声明类型与实际内容是否一致；
  3. Parser 产生内容和结构；
  4. 规范化步骤把结果映射到统一 Document；
  5. 验证步骤决定成功、部分成功还是隔离。

具体例子：读取一份员工手册

假设 handbook.pdf 位于允许的上传区。Loader 先检查路径是否仍在允许目录内，限制可 读取大小，记录来源标识，然后读取字节。格式识别发现它确实像 PDF，Parser 再逐页提取 标题和段落。

第 8 页如果提取失败，系统不应默默返回其余页面并标成完整成功。更诚实的 Document 可以保留已提取内容，同时记录 partial 状态、失败页码和解析器版本。这样后续索引可以 按策略拒绝这份文档，或明确接受“部分内容”，而不是把缺页当作原文不存在。

稳定标识与内容标识不要混为一谈

稳定的 document_id 表示“同一份逻辑文档”，内容摘要则表示“这次内容是否改变”。若 每次编辑都生成全新文档身份，删除旧版本会很困难；若所有版本共享同一个内容摘要，又 无法判断是否需要重新处理。

可以把它们理解为书号与版次：书仍是同一本书，但修订版的内容已经变化。03-07 会继续 讨论版本和增量更新。

失败与安全边界

  • 文件扩展名只是提示，不能替代实际格式校验；
  • 来源路径、下载地址和数据库查询都需要授权与范围限制；
  • 解析成功不等于内容可信，知识库文本仍是不可信数据；
  • 部分成功必须可见，不能为了提高“成功率”吞掉错误；
  • 原始文件可能包含敏感信息，调试日志不应默认保存全文；
  • 第三方 Parser 的能力、限制和版本需要在项目中登记并用样本验证。

建模练习

选择一份本地 Markdown 文件和一条数据库记录，分别写出 Loader 输入、Loader 输出、 Parser 输入、Parser 输出。然后为两者设计同一套 Document 字段，并回答：

  1. 哪个字段能让引用回到原始来源？
  2. 哪个字段能判断内容是否改变？
  3. 解析一半失败时，状态和错误放在哪里？
  4. 后续 Chunk 怎样回到 Document？

自测

  1. 为什么 Document 不能只是正文字符串？
  2. Loader 和 Parser 的失败为什么要分开记录？
  3. 文件扩展名为什么不能证明真实格式？
  4. 稳定文档 ID 与内容摘要分别解决什么问题？
  5. “提取到部分页面”为什么不能默认等同于成功？
