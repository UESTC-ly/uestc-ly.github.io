先理解“为什么需要它”，再用一个最小 demo 验证。 适用：Python 3.11+、Pydantic v2；官方资料核对日期：2026-09-17。

1. 这套笔记怎么读

这套笔记以讲解为主。每章围绕一个实际问题展开：它在解决什么、框架做了哪些事、什么情况下该用它，以及它和相似概念有什么区别。正文只保留一个最小 demo，让代码帮助理解概念，不要求一开始就记住完整项目写法。

可以把整套内容理解为搭建一个“接待请求的服务”。首先让请求找到正确的函数，然后读懂来访者提供的数据，执行工作，再给出清楚的结果。接口变多后，需要公共准备流程、持久存储和模块划分；服务长期运行后，还需要管理资源、验证行为和配置运行环境。

首次阅读不必安装所有工具，也不必一边读一边输入代码。先能用自己的话说出每章的记忆句，再运行 demo，通常比逐行抄代码更容易建立理解。

2. 学习顺序与章节导航

第一阶段：看懂一次请求

前四章回答四个连贯的问题：请求交给谁？数据从哪里来？数据是否合法？应该返回什么？这是后续所有内容的基础。

章节 带着这个问题阅读
01 入门与第一个接口 一个 Python 函数怎样成为别人能调用的接口？
02 路径参数与查询参数 为什么“查哪个任务”和“怎么查”放在不同位置？
03 请求体与Pydantic校验 怎样在进入业务前发现缺字段、错类型和非法取值？
04 响应模型与异常处理 怎样让调用者分清成功、失败，以及能看见哪些字段？

第二阶段：组织接口与业务

当几个接口开始重复准备工作、等待外部服务、操作同一份数据时，就会自然遇到第 05—08 章的问题。先理解重复和等待发生在哪里，再理解框架提供的工具。

章节 带着这个问题阅读
05 依赖注入Depends 每个接口都要准备的东西，能否统一取得？
06 同步异步与流式响应 等待期间能否接待其他请求？结果能否分批返回？
07 APIRouter与项目拆分 接口多了以后，如何让文件仍然容易找到和修改？
08 数据库与最小CRUD 为什么数据要放进数据库，为什么修改后还要提交？

第三阶段：理解服务的边界

后四章把视角从“一个函数能跑”扩展到“一个服务怎样被使用和维护”。重点理解职责和时机，不急于背出所有配置参数。

章节 带着这个问题阅读
09 认证与权限 知道来访者是谁，是否就能允许他做任何事？
10 表单文件与请求头 同样是提交数据，为什么文件、表单和 JSON 的接收方式不同？
11 中间件生命周期与后台任务 一段工作应该在每次请求、应用启动还是响应之后执行？
12 测试配置与启动部署 怎样确认行为正确，并让同一份代码适应不同环境？
13 速查与自测 能否从场景判断该用哪个机制，并解释原因？

3. 怎样使用最小 demo

第 01—11 章的正文示例彼此独立，通常复制到一个 main.py 就能运行。每次只放一章代码，先停止上一个服务，再启动当前例子。第 12 章使用 python -m pytest -q main.py 运行测试示例，不需要先启动服务器。

第一次准备环境时，在本笔记文件夹打开终端，执行下面四行。后续不必反复创建环境，只需在新终端中激活它。

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload

最后一行需要先把当章代码保存为 main.py。Windows PowerShell 的激活命令改为 .venv\Scripts\Activate.ps1。main:app 表示 main.py 文件中的 app 对象，这个写法会在第 01 章解释。

启动后打开 交互文档，根据章节说明填参数并执行请求。这样能直接看见输入位置、返回数据和状态码，不必先掌握 curl。每次只改变一个输入，再观察结果变化。

4. 怎样检查自己真的理解了

读完一章，先不看代码，用三句话回答：这个功能解决什么问题？请求经过它时发生什么？什么时候它解决不了问题？能回答这三点，说明你已经形成了可迁移的理解。

然后做一个小变化。例如把可选参数改成必填、请求一个不存在的 ID、去掉认证凭证。先预测结果，再执行验证。预测出错时回到解释部分找原因，而不是只记住新的输出。

章末自测和第 13 章的场景题用于复习。基础阶段不要求默写完整 CRUD、登录流程或部署配置；能够选对机制并说清理由，更适合作为第一轮学习目标。

5. 配套文件如何使用

正文的最小 demo 是主要学习材料。demos/ 保留此前较完整的示例作为可选练习资料，正文现在已经精简，二者不再逐行相同，接口与字段也可能不同。只想理解概念时可以跳过该目录。

需要尝试配套练习时，在本目录运行 python -m uvicorn demos.ch01:app --reload，将 ch01 换为对应章号。demos/test_demos.py 验证这些配套文件，不代表自动验证正文中所有新例子；具体检查范围见 验证记录。

requirements.txt 列出安装依赖；requirements-verified.txt 保存上一轮实测环境的完整版本快照。两份文件任选其一安装即可，一般学习使用前者。
