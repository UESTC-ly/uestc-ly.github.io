记忆句：路径定位谁，查询决定怎么查；类型管取值，默认值管能否省略。

1. 先读懂 URL，而不是先背语法

看到 /tasks/3?detail=true，可以先读成一句话：“查第 3 个任务，并要求详细信息。”这里的 3 在路径中，detail=true 在问号后的查询字符串中。两者都可以传值，但表达的意图不同。

路径参数通常用于确定资源身份，例如任务编号。查询参数通常用于附加条件，例如关键词、分页、排序或是否包含详情。查询任务列表时，/tasks?limit=10 表达“取列表，但最多取十条”；查询单个任务时，/tasks/3 表达“取编号为 3 的任务”。

可以把路径看成书架上的书号，把查询参数看成阅读要求。这个类比只是帮助设计接口，并不意味着查询参数不能传编号。技术上能够做到，不代表接口意图同样清楚；设计时优先让地址容易读懂。

2. FastAPI 如何知道去哪里取参数

对本章这种没有额外声明的普通参数，先看参数名是否出现在路由模板中。模板 /tasks/{task_id} 中有 task_id，同名函数参数就从路径读取；detail 没有出现在模板中，且是普通标量类型，就默认从查询字符串读取。

这里的“同名”很重要。花括号里的名字与函数参数名应该对应起来；把函数参数改名，却没有修改路由模板，不能指望框架自动猜到两者的关系。

Path 和 Query 可以明确来源，并附加规则。读 Annotated[int, Path(gt=0)] 时不用把整行当成一个复杂语法：先读出“这是整数”，再读出“来自路径，并且大于零”。Annotated 是把额外说明附在类型上；gt 表示大于，ge 表示大于等于，le 表示小于等于。

3. URL 里是文本，进入函数时可以是整数

URL 中的 3 起初是文本。声明 task_id: int 后，FastAPI 会尝试把这份输入解析成整数，再把得到的值交给函数。因此业务代码通常不需要再手写一次整数转换。

但“能转换成整数”和“业务上有效”是两层要求。-1 可以是合法整数，却可能不是合法任务编号，所以还需要 Path(gt=0)。进一步说，3 能通过正整数校验，也不代表数据库里存在第 3 个任务：输入格式校验回答“像不像编号”，业务查询回答“有没有这个任务”。 后一种情况会在下一章的异常处理里区分。

如果请求不能通过校验，框架会返回 422，处理函数不会正常进入本次业务处理。理解这个执行顺序，可以避免在函数里重复写所有已经声明过的格式检查。

4. 必填、默认值、允许空值要分开看

参数声明 请求里能否省略 省略后的结果
q: str 不能 缺少必填参数，校验失败
limit: int = 10 可以 使用默认值 10
keyword: str \| None = None 可以 使用 Python 的 None

类型回答“允许什么值”，默认值回答“没提供时怎么办”。str | None 只是声明允许空值；如果没有默认值，不能仅凭这个联合类型就认为参数可省略。路径参数用于组成路径，本身始终必填；没有那一段，通常连同一条路由都匹配不到。

还要注意，查询字符串没有 JSON 那样原生的 null：URL 中写 keyword=null，通常得到的是文本 "null"；完全不传参数，才可能触发默认的 None。同样，keyword= 表示提供了一个空字符串，并不等于没有提供。排查输入问题时，应先区分“缺失、空字符串、文字 null”。

5. 最小 demo：看见解析、默认值与失败

完成环境安装后，将代码复制到 main.py，在该文件所在目录运行 python -m uvicorn main:app --reload。切换章节前先按 Ctrl+C 停止上一章。

from typing import Annotated
from fastapi import FastAPI, Path

app = FastAPI()

@app.get("/tasks/{task_id}")
def read_task(
    task_id: Annotated[int, Path(gt=0)],
    detail: bool = False,
):
    return {"task_id": task_id, "detail": detail}

打开 交互文档，展开接口并选择 Try it out。填 task_id=3、detail=true 后执行，响应中的 task_id 是数字 3，detail 是布尔值 true。注意它们不再是带引号的字符串。

接着在浏览器访问 /tasks/3，观察不提供查询参数时使用默认的 false；访问 /tasks/0，观察正数规则导致 422；访问 /tasks/abc，观察整数解析导致 422。浏览器完整地址前缀为 http://127.0.0.1:8000。这些对照分别验证了“能省略”“范围错误”“类型错误”，比重复看成功请求更容易记住规则。

可选配套：demos/ch02.py，包含查询约束等更完整内容，接口与正文最小示例有所不同。

6. 路由顺序为什么会造成意外

假设既有固定地址 /tasks/search，也有动态地址 /tasks/{task_id}。如果动态路由先登记，文本 search 可能先被当成 task_id 的值去匹配，随后因为无法转换成整数而失败。框架不会因为整数转换失败就自动退回去寻找你本来想调用的搜索接口。

因此，固定而具体的路由应放在可能覆盖它的动态路由前面。可以记成“先登记特殊入口，再登记通用入口”。另一种设计方式是避免路径含义重叠，例如把搜索条件放到任务列表的查询参数中。

7. 合上笔记，做三个判断

/tasks/3?detail=true 中谁决定查哪个任务？ 路径里的 3；查询参数决定返回方式。

limit: int = 10 为什么可以不传？ 因为有默认值，而不是因为它的类型是整数。

校验通过就代表任务存在吗？ 不代表。校验保证输入满足声明的格式和范围，存在性需要业务代码检查。
