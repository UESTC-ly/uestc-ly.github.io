完成本章后，你应该能够：

  • 为自己选择一条不会跳过关键前置的学习路线；
  • 区分“读过”“运行过”“有证据通过”和“经过独立审查”；
  • 在环境、网络或费用受限时选择离线路线；
  • 遇到卡点时缩小问题，而不是盲目重装全部工具。

这不是一本只需要从头翻到尾的书

学习 RAG 同时包含概念、代码、实验和工程判断。只看文字，你可能觉得自己理解了； 真正看到输入、检索结果、上下文和回答后，才会发现哪些步骤仍然模糊。因此，本教程 使用一个反复出现的小循环：

  1. 先建立直觉：知道这一章在解决什么问题。
  2. 再学习术语：把直觉对应到准确名称，而不是先背缩写。
  3. 亲手观察：运行离线示例、查看中间结果或完成纸笔练习。
  4. 留下证据：记录命令、输出、测试或自己的解释。
  5. 回看边界：确认哪些结论尚未被证明，哪些失败情况仍需处理。

例如，“我看懂了 Top-K”只是主观感受；“我能解释 K 大于候选数量时为什么不能制造 结果，并能在示例输出中指出候选列表”才是可观察的学习证据。

主线应该怎样走

零基础读者建议按下面的顺序推进：

  1. 00 前言：选路线、做准备度检查、建立安全基线。
  2. 01 基础知识：补齐 AI/LLM 直觉、Python、命令行、JSON、HTTP 和最小测量能力。
  3. 02 RAG 原理：理解“先检索证据，再组织回答”的主链路与失败边界。
  4. 最小离线试跑：观察一个确定性实现，不把网络和付费 API 混入第一次实验。
  5. 数据到回答的工程主线：依次学习数据接入、切分、向量表示、索引、检索、重排、 上下文和生成。
  6. 项目、评估、安全与生产：用测试和评估检查效果，再讨论框架、高级方法、安全 治理和生产部署。

高级 RAG 不是所有项目的硬前置。第一次通关时，不需要把每个论文术语和框架插件都 学完。先完成一条可解释、可测试的小闭环，再按项目需求深入。

规划中的 D20 学习路线图尚未在本批次交付；以上文字路线是当前可用入口，不声称图表 已经渲染或验证。

怎样理解“状态”和“通过”

仓库中的内容会经历不同阶段。它们不能混为一谈。

表述 实际含义 不能推出什么
已编写 文件中已有实质内容 不代表链接、命令或事实都正确
static-checked 做过标题、空白、链接等静态检查 不代表代码运行通过
unit-passed 对局部行为运行过单元测试 不代表端到端场景通过
integration-passed 组合路径按记录的环境运行通过 不代表所有平台或生产负载都通过
已审查 独立角色检查过指定范围 不代表超出该范围的结论也成立
complete 所有适用门禁都有可定位证据 不代表技术从此不会变化

读到“计划”“待实现”或“未验证”时，不必失望。诚实状态比一张看起来全绿、实际上 无法追溯的表更有用。

离线、本地和云端路线

教程优先提供离线或本地路径，是为了把变量减少到最少：没有 API Key、余额、限流、 网络抖动和远端版本变化，初学者更容易判断错误来自哪里。

这不表示云端服务没有价值。进入需要真实生成模型、托管向量库或部署能力的章节时， 教程应同时说明：

  • 外部服务解决了什么问题；
  • 是否收费、是否需要账号和密钥；
  • 输入会不会离开本机；
  • 有什么 Mock、本地实现或跳过方案；
  • 版本和功能事实何时核查。

如果你暂时没有云端条件，先完成离线主线。不要为了“跟上教程”把个人密钥、工作文档 或含隐私的数据粘贴到不清楚处理方式的服务中。

一个 30 分钟学习单元

假设小林今晚只有 30 分钟。他不需要强迫自己读完整个部分，可以这样安排：

  1. 用 5 分钟阅读章节入口，确认前置和目标。
  2. 用 10 分钟理解一个核心例子，并写下一句自己的解释。
  3. 用 10 分钟完成一个命令、输出观察或自测。
  4. 用 5 分钟记录证据和一个仍不确定的问题。

下一次从“不确定的问题”继续，比重新扫一遍所有文字更有效。如果命令失败，记录完整 命令、当前目录、Python 版本和第一条错误，不要只写“运行不了”。

卡住时的四步排查

  1. 确认目标：这一小步预期产生什么可观察结果？
  2. 确认位置：终端当前目录和教程要求的目录是否一致？
  3. 确认解释器：实际运行的是哪个 Python，版本是否满足要求？
  4. 缩小输入：能否先运行无网络、无依赖的最小命令？

如果最小命令也失败，回到00-03 学习准备度检查和 00-04 环境冒烟测试。如果最小命令成功而项目失败，再 检查项目自身的依赖、配置和测试，不要立刻重装操作系统或更换所有工具。

你的学习合同

现在写下三句话：

  1. 我每周准备投入多少个 30 分钟学习单元？
  2. 我优先使用离线路线，还是已经具备可控的外部服务环境？
  3. 我用什么证据判断一章完成：自己的解释、命令输出、测试结果，还是三者组合？

这不是考试，而是防止“收藏了教程就等于学会”的最小约束。

自测

  1. 为什么“读过一章”不等于“完成一章”？
  2. static-checked 和 integration-passed 有什么区别？
  3. 为什么第一条路线优先离线实现？
  4. 命令失败时，最先应该记录哪四类信息？
