05 嵌入向量

← 返回专题下载 Markdown ↓
本篇目录
  • 阅读顺序
  • 学完这一部分后
  • 始终保留的边界

前面的章节已经把原始资料变成可管理的文档和文本块。本部分继续回答下一步问题：怎样把 文本、图片等内容转换成可以比较的数值表示，以及怎样在模型选择、批量处理和版本迁移时 保持索引可解释、可重建。

嵌入向量（Embedding）不是内容的摘要，也不是事实判断器。它把输入映射到一个向量空间， 让系统可以按照某种相似度规则寻找候选。相似只表示“在当前模型和度量下接近”，不保证 两个对象含义完全相同，更不保证候选正确、最新或有权被当前用户访问。

阅读顺序

  1. 05-01 嵌入与向量空间直觉：理解输入怎样变成坐标，以及坐标能做什么、不能做什么。
  2. 05-02 相似度度量与归一化：区分余弦相似度、点积和欧氏距离，理解归一化为何必须与检索配置一致。
  3. 05-03 文本嵌入模型选择：把语言、任务、数据、成本、延迟和隐私约束变成可验证的选择过程。
  4. 05-04 图片与多模态嵌入：比较 OCR、图片向量和跨模态共享空间的责任边界。
  5. 05-05 批处理、缓存与成本：设计可重试、可观察、不会因缓存失效而悄悄混用版本的处理流程。
  6. 05-06 迁移、重建索引与常见错误：在更换模型或预处理规则时安全重建，并沿常见故障定位问题。

建议按顺序阅读。05-01 和 05-02 建立共同语言，05-03 与 05-04 讨论输入和模型选择， 最后两章处理规模化运行与变更。实际项目可以先只处理文本，但仍应提前记录表示版本， 否则第一次换模型时就可能无法判断哪些向量需要重建。

学完这一部分后

你应该能够解释嵌入向量、维度、向量空间和相似度的关系；能够用任务数据而不是单一榜单 挑选候选模型；能够区分文字识别与图片语义表示；能够设计批处理、缓存键、失败重试和 成本观察字段；还能够为模型、切分或度量变化制定重建与回滚方案。

本部分不指定唯一模型、向量数据库或云服务，也不提供尚未实现的性能结论。计划中的 嵌入生成代码、批处理程序和迁移演示仍需在后续实现批次编写并单独验证。

始终保留的边界

  • 原文、来源、权限和表示版本不能被向量替代。
  • 文档向量与查询向量只有在兼容的模型、配置和预处理约定下才可比较。
  • 相似度分数不是答案正确率，也不是通用置信度。
  • 嵌入服务可能接触原始敏感内容；向量本身也不能默认视为匿名数据。
  • 更换模型、维度、度量或关键预处理规则时，需要明确评估是否重建索引。
