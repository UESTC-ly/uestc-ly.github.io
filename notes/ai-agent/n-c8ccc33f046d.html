分章节讲解

1. 隐私与数据保护

核心定义： LLM 系统要控制敏感数据进入 Prompt、日志、向量库和第三方接口。

理解路径： - 先明确它解决的具体问题，再判断它依赖的前提条件。 - 把它放回“LLM 系统既要有能力，也要可控、合规、经济和可解释。”这条主线中理解，不要孤立记忆。 - 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

常见误区： 脱敏不彻底或日志长期保存会形成隐私风险。

2. 提示注入防护

核心定义： 提示注入通过恶意输入影响模型指令遵循，防护要结合权限隔离、内容过滤和工具调用方案。

理解路径： - 先明确它解决的具体问题，再判断它依赖的前提条件。 - 把它放回“LLM 系统既要有能力，也要可控、合规、经济和可解释。”这条主线中理解，不要孤立记忆。 - 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

常见误区： 单靠系统提示不能完全防护；工具权限和数据边界更关键。

3. 成本治理

核心定义： 成本治理关注 Token、检索、模型路由、缓存、批处理和失败重试带来的费用。

理解路径： - 先明确它解决的具体问题，再判断它依赖的前提条件。 - 把它放回“LLM 系统既要有能力，也要可控、合规、经济和可解释。”这条主线中理解，不要孤立记忆。 - 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

常见误区： 只选最强模型会浪费成本；只选便宜模型可能增加错误和重试成本。

4. 持续改进闭环

核心定义： 持续改进通过日志、反馈、评测集、错误分类和灰度实验迭代系统。

理解路径： - 先明确它解决的具体问题，再判断它依赖的前提条件。 - 把它放回“LLM 系统既要有能力，也要可控、合规、经济和可解释。”这条主线中理解，不要孤立记忆。 - 学习时至少能说出：输入是什么、输出是什么、代价是什么、失败边界是什么。

常见误区： 没有固定评测集的优化容易凭感觉回归。

3. 概念深化：逐个击破

3.1 隐私与数据保护

5. 记忆强化：三层复述法

  1. 概念层： 用一句话定义本章每个核心概念。
  2. 机制层： 不看原文画出输入到输出的流程。
  3. 边界层： 为每个概念准备一个“不能这样用”的反例。

6. 工程/做题/面试迁移

  • 工程迁移： 上线前必须回答：数据从哪来、指标如何评、失败如何回滚、日志如何追、成本如何控。
  • 做题迁移： 先把题目中的对象、关系、约束和目标函数圈出来，再映射到本章概念。
  • 面试迁移： 回答时不要只报名词，要说清“为什么需要它、它如何工作、它何时失效”。

5. 验证与复盘

  • 验证方式： 用固定评测集、轨迹日志、人工抽检、线上监控和回滚演练验证。
  • 复盘方式： 每次做题或设计后，记录“我使用了哪个前提、哪个前提最容易被破坏、如果破坏如何调整”。
  • 记忆方式： 不背孤立结论，只背“问题 → 机制 → 边界 → 验证”的链路。

本轮扩写：安全、成本与改进闭环

1. LLM 成本治理要看单次成本和失败重试成本

成本来源 典型原因 控制方式 误区
Prompt token 上下文过长 摘要、裁剪、结构化上下文 盲目塞全量文档
Completion token 输出无约束 限制格式和长度 让模型自由发挥
检索成本 召回过宽、重排过重 分层召回、缓存、TopK 控制 每次都全量重排
工具调用 Agent 循环调用 最大步数、状态缓存 只看模型费用不看工具费用
失败重试 输出不合规 schema 校验、少量重试 无限重试直到成功

2. 数据保护边界

  • 训练数据、评测数据、线上日志和用户输入要分别定义保留周期和脱敏策略。
  • Prompt 和 RAG 上下文可能携带隐私，不能默认写入可共享日志。
  • 权限要在检索前和生成前双重检查，避免“搜不到但上下文已泄露”。
  • 审计日志要记录谁在什么场景访问了什么数据，但不能记录明文敏感内容。

3. 持续改进闭环

flowchart LR
  A["线上失败样本"] --> B["归因分类"]
  B --> C["补充评测集"]
  C --> D["改 Prompt/RAG/模型"]
  D --> E["离线回归"]
  E --> F["灰度发布"]
  F --> A
  • 失败样本要按检索、事实、格式、安全、工具、权限、成本分类。
  • 每次改动都要记录版本和动机，避免“感觉变好”。
  • 评测集要保留长尾和反例，不能只保留容易通过的样本。

4. 面试追问路径

  • “如何降低 LLM 成本？”——回答模型路由、上下文压缩、缓存、批处理、工具预算和失败重试控制。
  • “如何处理用户隐私？”——回答最小化收集、脱敏、权限、审计、保留周期和删除机制。
  • “如何持续提升效果？”——回答失败归因、评测集扩充、版本化、灰度和回滚。
