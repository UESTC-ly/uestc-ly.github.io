完成本章后，你应该能够：

  • 解释为什么不同格式不能只调用同一个“转纯文本”函数；
  • 识别 Markdown、HTML、Word、Excel 和 PowerPoint 中应保留的结构；
  • 为格式适配器定义共同的输入、输出和失败契约；
  • 避免把脚本、隐藏内容或错误阅读顺序混进知识正文。

同一句话放在不同格式里，周围关系不同

在 Markdown 中，一行 ## 退款条件 明确表示二级标题；在网页中，相同文字可能位于 导航栏、正文标题或弹窗；在 Excel 中，它可能是某列的表头；在 PowerPoint 中，它可能 是当前幻灯片标题。只留下“退款条件”四个字，就丢掉了它与后续内容的关系。

摄取的目标不是保存所有排版细节，而是保留会影响检索、引用和理解的结构，并明确哪些 结构无法可靠恢复。

先定义共同适配器契约

格式适配器（format adapter）可以把特定格式映射到统一 Document 或中间节点。一个 共同契约至少说明：

  • 输入接受字节、字符还是已加载对象；
  • 支持哪些媒体类型和版本；
  • 输出哪些文本、结构节点、位置和元数据；
  • 如何报告警告、部分成功和失败；
  • 是否会读取外部资源、执行脚本或展开嵌入对象；
  • 如何限制大小、数量、深度和处理时间。

有了契约，调用方不必假装所有格式相同，同时仍能用一致方式处理状态和证据。

Markdown：简单不等于没有结构

Markdown 的标题层级、列表、引用、代码块、表格、链接和前置元数据都可能重要。解析时 常见的两个极端是：

  • 只按空行切字符串，导致代码和列表被拆散，标题关系丢失；
  • 保留所有标记符号，导致检索文本充满无意义语法噪声。

更稳妥的做法是先解析为结构节点，再为“用于检索的文本”和“用于回溯的原始片段”分别 生成表示。链接文字可以进入正文，目标地址作为元数据保存；代码围栏内的内容不能按普通 段落规则随意解释。

HTML：正文、导航与可执行内容要分开

网页包含标题、正文、导航、页脚、广告、表单、样式和脚本。直接取页面全部文字，常会 把菜单重复到每篇文档里；直接使用浏览器视觉结果，又可能引入登录状态、动态加载和时间 差异。

HTML 解析至少要考虑：

  • 页面标题、主内容和标题层级；
  • 链接目标、列表、表格和代码块；
  • script、style、隐藏元素与模板内容；
  • 规范地址、抓取时间、语言和访问权限；
  • 动态渲染后内容是否属于允许采集范围。

检索到的网页文字仍是不可信数据。删除 <script> 标签不等于解决正文中的提示注入， 授权和上下文边界仍需独立处理。

Word：段落之外还有样式与对象

Word 文档可能包含标题样式、页眉页脚、脚注、批注、修订记录、表格、文本框和嵌入对象。 视觉位置与底层存储顺序不一定相同。

项目需要先决定哪些内容属于知识正文。例如已接受的修订可以进入正文，未决批注可能只 供审阅者查看；页眉中的保密等级应进入元数据，而不是被当作每页重复段落。若解析器不能 可靠读取文本框，应记录能力缺口，而不是安静忽略。

Excel：单元格的关系比单个值更重要

把工作簿所有单元格按行拼接，会丢失工作表名称、表头、合并单元格、公式与显示值的 区别。数值 0.15 在“税率”列和“折扣”列意义不同。

处理表格时应保留：

  • 工作簿、工作表和区域身份；
  • 表头与数据行的关系；
  • 公式、缓存值和计算时间的区别；
  • 隐藏行列、筛选状态和访问范围；
  • 空白、合并单元格与错误值的处理规则。

不要自动执行来源不明的宏，也不要因为文件能打开就认为公式结果是最新或可信的。

PowerPoint：阅读顺序不能只看对象编号

演示文稿通常由标题、正文、讲者备注、图表和空间布局共同表达。对象在文件内部的顺序 可能不同于人眼阅读顺序。把每个文本框直接拼接，可能先得到结论，再得到标题和前提。

基础处理可以按幻灯片保留标题、正文、备注与对象位置，并为每页生成稳定引用。流程图、 复杂图表和动画关系无法可靠转为线性文字时，应保留原始对象引用并标记限制。

具体例子：同一份季度报告的五种附件

假设一个项目同时收到：说明用 Markdown、发布网页、正式 Word 报告、Excel 指标表和 汇报 PowerPoint。合理的管线不会把它们拼成五段无来源文本，而会：

  1. 为每个来源建立独立 Document 与权限范围；
  2. 通过对应适配器提取结构；
  3. 用业务标识关联“同一季度”，但保留各自版本和发布时间；
  4. 对重复摘要建立关联，不急于删除；
  5. 在数字冲突时保留来源与时间，让业务规则决定哪个版本有效。

格式转换不能替代业务真值判断。

验证适配器时看什么

准备很小但有代表性的 fixture：多级标题、空表、合并单元格、脚注、隐藏内容、中文文件 名、损坏文件和超限文件。断言不只检查“有输出”，还要检查标题关系、来源位置、失败状态 和未支持内容是否可见。

计划中的各格式 fixture、适配器契约测试和格式适配器图将在后续批次实现。本章没有验证 任何具体解析库的当前功能范围。
