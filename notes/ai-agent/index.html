00. Agent 学习路线与知识地图

AI Agent 不是一个“更长的 Prompt”。它是一个由 LLM、工具、状态、记忆、权限、评估、监控和工作流 组成的系统，用来把用户目标拆解为可执行步骤，并在执行中观察、调整、验证和收敛。

01. Agent 基础与架构模式

Agent 架构的核心是 决策循环 ：模型根据目标和状态选择下一步动作，工具执行动作，系统观察结果，再决定继续、修正、请求人类帮助或结束。

02. Tool Calling 与 Structured Output

Tool Calling 是让模型从“说答案”变成“请求系统执行动作”；Structured Output 是让模型输出可被程序稳定解析的数据结构。两者共同构成 Agent 行动能力的基础。

03. MCP 协议与工具生态

MCP，Model Context Protocol，是一种让 AI 应用以标准方式连接外部工具和上下文的协议。它把工具、资源、提示模板和客户端能力拆开，降低不同 Agent 应用接入外部系统的成本。

04. Context Engineering 上下文工程

Context Engineering 是对模型输入窗口的系统化管理：选择正确的信息，按正确优先级和边界组织，让模型在有限上下文内做出稳定决策。

05. Agent 记忆系统

Agent 记忆是跨轮次、跨任务保存和检索有用信息的机制；它不是把所有对话永久保存，而是有选择地保存用户偏好、任务状态、经验教训和可复用知识。

06. Workflow、状态机与 Human in the Loop

生产级 Agent 不是一次性脚本，而是一个可暂停、可恢复、可审计、可重试、可审批的工作流系统。

07. Agent 评估与 Observability

Agent 的质量不能只看最终答案，还要看是否选对工具、参数是否正确、步骤是否合理、是否遵守权限、成本是否可控、失败是否可恢复。

08. Agent 安全与权限

Agent 安全的核心原则是： 不要把权限交给模型，不要把外部文本当指令，不要让高风险动作绕过审批，不要让敏感数据进入不该进入的上下文。

09. 多 Agent 协作模式

多 Agent 的目的不是“让更多模型聊天”，而是通过角色分工、权限隔离、并行执行和互相审查，提高复杂任务的完成率和可控性。

10. LLMOps 与生产部署

LLMOps 是把 LLM 和 Agent 系统稳定、可控、可观测、可回滚地运行在生产环境中的工程体系。

04-01 固定长度、句子与段落切分

“每块应该多大”没有脱离上下文的答案。块大小至少受到四组条件影响：原文结构、用户问题的 粒度、表示模型的输入限制，以及最终回答阶段的上下文预算。

上一章把嵌入描述为向量空间中的位置。但两个点是否接近，取决于使用哪把尺子。地图上 可以比较直线距离，也可以比较行进方向；向量检索同样可以比较方向、长度或两者的组合。

05-03 文本嵌入模型选择

模型选择常从一个没有边界的问题开始：“哪个嵌入模型最好？”这个问题缺少输入语言、 文档类型、查询长度、检索目标、运行环境和预算，所以不存在脱离条件的唯一答案。

05-04 图片与多模态嵌入

一份 PDF 可能同时包含正文、截图、流程图、表格和扫描页。如果摄取过程只提取可复制文字， 图片里的错误提示、箭头关系和界面状态就会消失。后续文本嵌入再准确，也无法检索从未进入 表示的数据。

05-05 批处理、缓存与成本

想象仓库有一千个文本块。如果每个块都单独建立连接、发送请求、等待响应并写入一次， 大量时间会消耗在重复的固定步骤上。批处理（batching）把若干输入组成一批，让一次请求 或一次模型运行处理多个对象，常能降低每条记录的固定开销。

05-06 迁移、重建索引与常见错误

嵌入向量只在兼容空间中有可比较含义。若旧文档向量由模型 E1 生成，新查询向量改用 模型 E2 ，两组数值即使维度相同，也通常不能直接比较。更危险的情况是系统把新文档 向量逐条写入旧索引：查询结果会混合两个空间，却没有明显报错。

06-01 Flat 与近似最近邻索引

假设书架上只有十本书，管理员要找与“退货期限”最相关的三本。最直接的方法是把问题与 每本书的向量逐一比较，再按相似度排序。这就是 Flat 搜索的核心：不先排除候选，而是对 当前可搜索集合中的每条向量计算距离或相似度。

06-02 HNSW 的分层图直觉

分层可导航小世界图（Hierarchical Navigable Small World，HNSW）把向量记录看作图中的 节点，相近节点之间建立连接。查询不是逐一比较全部节点，而是从某个入口沿连接移动，寻找 越来越接近查询的位置。

06-03 IVF 与乘积量化

想象一张城市地图被划成多个片区，每个片区选一个代表位置。录入餐馆时，先把餐馆分到最近 的代表位置；查询时，也先判断问题更接近哪些片区，只搜索这些片区中的记录。这就是 IVF 的 核心直觉。

06-04 本地 FAISS 与元数据索引

FAISS 是常见的向量相似性搜索工具。本章只讨论它在本地教学架构中的概念位置，不声称已经 安装、运行或验证任何具体版本。具体 API、支持的索引类型和保存行为属于可变事实，后续实现 必须依据官方资料和锁定版本核查。

06-05 数据库边界与适配器抽象

“应该使用哪种数据库”不是只由数据类型决定。向量记录同时包含高维表示、结构化字段、原文 引用、权限、时间和版本。不同系统可能都能保存这些数据，但它们在近邻搜索、事务、全文搜索、 过滤、扩缩容和运维上的重点不同。

06-06 分片、复制、备份与一致性

当单机容量、吞吐或可用性不足时，系统会引入更多节点。但“有多个节点”并不自动意味着数据 安全或一致。
