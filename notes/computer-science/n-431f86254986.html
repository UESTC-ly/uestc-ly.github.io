1. TLS/SSL 协议

1.1 基本概念

TLS (Transport Layer Security) 是 SSL (Secure Sockets Layer) 的继任者，是一种加密协议，用于在网络通信中提供安全性和数据完整性。

  • SSL 1.0/2.0/3.0：早期版本，已废弃（存在安全漏洞）
  • TLS 1.0（1999）：基于 SSL 3.0
  • TLS 1.1（2006）：修复 TLS 1.0 漏洞
  • TLS 1.2（2008）：目前广泛使用
  • TLS 1.3（2018）：最新版本，更快更安全

1.2 TLS 的作用

  1. 加密（Encryption）：防止数据被窃听
  2. 认证（Authentication）：验证通信双方身份
  3. 完整性（Integrity）：防止数据被篡改

1.3 TLS 握手过程（TLS 1.2）

客户端                                      服务器
  |                                            |
  |--- 1. Client Hello ------------------->  |
  |    (支持的TLS版本、加密套件、随机数)        |
  |                                            |
  |<-- 2. Server Hello -------------------   |
  |    (选定的TLS版本、加密套件、随机数)        |
  |                                            |
  |<-- 3. Certificate --------------------   |
  |    (服务器证书)                             |
  |                                            |
  |<-- 4. Server Key Exchange -------------   |
  |    (可选，用于密钥交换)                      |
  |                                            |
  |<-- 5. Server Hello Done ---------------   |
  |                                            |
  |--- 6. Client Key Exchange ------------->  |
  |    (预主密钥，用服务器公钥加密)              |
  |                                            |
  |--- 7. Change Cipher Spec -------------->  |
  |    (通知服务器后续使用协商的密钥和算法)      |
  |                                            |
  |--- 8. Finished ----------------------->  |
  |    (加密的握手消息摘要)                     |
  |                                            |
  |<-- 9. Change Cipher Spec --------------   |
  |                                            |
  |<-- 10. Finished -----------------------   |
  |                                            |
  |=== 加密通信开始 ========================   |

关键步骤说明：

  1. Client Hello：客户端发送支持的协议版本、加密套件列表、客户端随机数
  2. Server Hello：服务器选择协议版本和加密套件，发送服务器随机数
  3. Certificate：服务器发送数字证书（包含公钥）
  4. 密钥交换：双方协商生成会话密钥（对称密钥）
  5. 完成握手：验证握手消息完整性，开始加密通信

1.4 TLS 1.3 的改进

客户端                                      服务器
  |                                            |
  |--- Client Hello + Key Share ---------->  |
  |    (猜测密钥交换算法，直接发送公钥)         |
  |                                            |
  |<-- Server Hello + Key Share -----------   |
  |    Certificate, Finished                  |
  |    (确认算法，发送公钥、证书，加密数据)     |
  |                                            |
  |--- Finished (encrypted) -------------->  |
  |                                            |
  |=== 加密通信（仅 1-RTT） ================   |

主要改进：

  • 更快：1-RTT 握手（TLS 1.2 需要 2-RTT），0-RTT 重连
  • 更安全：移除不安全的加密算法（RSA 密钥交换、SHA-1、RC4）
  • 简化：减少握手消息，加密更多握手数据

1.5 对称加密 vs 非对称加密

特性 对称加密 非对称加密
密钥 单一密钥（加密解密用同一个） 密钥对（公钥加密，私钥解密）
速度 快 慢（比对称加密慢 100-1000 倍）
用途 大量数据加密 密钥交换、数字签名
算法 AES、ChaCha20、DES RSA、ECC、DH
TLS中的使用 会话数据加密 握手阶段密钥交换

TLS 混合使用两种加密： - 用非对称加密交换对称密钥（握手阶段） - 用对称加密加密实际数据（握手完成后）

2. 数字证书

2.1 什么是数字证书

数字证书（Digital Certificate）是由可信第三方（证书颁发机构 CA）签发的电子文档，用于证明公钥所有者的身份。

2.2 证书内容（X.509 标准）

证书信息：
  - 版本号
  - 序列号（唯一标识）
  - 签名算法
  - 颁发者（CA）
  - 有效期（开始时间、结束时间）
  - 主题（证书持有者信息）
    * 国家、省份、城市
    * 组织名称
    * 通用名称（域名，如 www.example.com）
  - 公钥信息
    * 公钥算法
    * 公钥值
  - 扩展字段
    * Subject Alternative Name (SAN) - 支持多个域名
    * 密钥用途
  - CA 数字签名

2.3 证书信任链

根证书 (Root CA)
   ↓ 签发
中间证书 (Intermediate CA)
   ↓ 签发
服务器证书 (End-entity Certificate)

验证过程：

  1. 浏览器收到服务器证书
  2. 查找签发该证书的中间 CA 证书
  3. 验证中间 CA 证书的签名（使用根 CA 公钥）
  4. 验证服务器证书的签名（使用中间 CA 公钥）
  5. 检查证书有效期、域名匹配、吊销状态

信任锚点：操作系统和浏览器内置根证书列表（Root CA Store）

2.4 证书类型

类型 验证级别 颁发速度 适用场景
DV（域名验证） 仅验证域名所有权 几分钟 个人网站、博客
OV（组织验证） 验证组织身份 几天 企业网站
EV（扩展验证） 严格验证组织 几周 金融、电商（显示绿色地址栏）

2.5 自签名证书

自签名证书：证书的签发者和使用者是同一实体，没有第三方 CA 背书。

用途： - 开发测试环境 - 内网系统 - 不需要公开信任的场景

缺点：浏览器会显示不安全警告（不在受信任的根证书列表中）

2.6 证书吊销机制

CRL（证书吊销列表）： - CA 定期发布已吊销证书的列表 - 客户端下载 CRL 检查证书状态 - 缺点：列表可能很大，更新不及时

OCSP（在线证书状态协议）： - 实时查询证书状态 - 向 CA 的 OCSP 服务器发送请求 - 缺点：泄露用户访问的网站，可能被阻断

OCSP Stapling： - 服务器定期查询自己的证书状态 - 在 TLS 握手时附上 OCSP 响应 - 优点：更快、更隐私、更可靠

3. 防火墙（Firewall）

3.1 基本概念

防火墙是一种网络安全设备或软件，用于监控和控制进出网络的流量，基于预定义的安全规则允许或阻止数据包。

3.2 防火墙类型

3.2.1 包过滤防火墙（Packet Filtering）

工作层次：网络层、传输层

过滤依据： - 源 IP 地址 - 目标 IP 地址 - 源端口 - 目标端口 - 协议类型（TCP、UDP、ICMP）

示例规则：

允许：源 192.168.1.0/24 → 目标 任意，端口 80/443（HTTP/HTTPS）
拒绝：源 任意 → 目标 192.168.1.10，端口 22（SSH）

优点：速度快、资源消耗少
缺点：无法检查应用层数据，易被绕过

3.2.2 状态检测防火墙（Stateful Inspection）

工作层次：网络层到传输层

特点： - 跟踪连接状态（TCP 连接的建立、维持、终止） - 维护状态表，记录合法连接 - 只允许属于已建立连接的数据包通过

状态表示例：

源IP:端口       目标IP:端口      状态          超时
192.168.1.10:5000  8.8.8.8:80    ESTABLISHED   120s
192.168.1.15:6000  1.1.1.1:443   SYN_SENT      30s

优点：比包过滤更安全，能防御某些攻击
缺点：性能开销较大，仍无法深度检查

3.2.3 应用层防火墙（Application Firewall / Proxy Firewall）

工作层次：应用层

特点： - 理解应用层协议（HTTP、FTP、DNS 等） - 可检查应用层数据内容 - 可作为代理服务器工作

能力： - 检测 SQL 注入、XSS 攻击 - 过滤恶意 URL - 阻止特定文件类型上传 - DPI（深度包检测）

优点：安全性最高
缺点：性能开销大，配置复杂

3.2.4 下一代防火墙（NGFW - Next-Generation Firewall）

集成功能： - 传统防火墙功能 - 入侵检测/防御系统（IDS/IPS） - 应用识别与控制 - 用户身份识别 - SSL/TLS 解密检查 - 威胁情报集成

3.3 防火墙规则

规则匹配顺序：从上到下，匹配即停止（first match）

示例规则集：

1. 允许 已建立的连接（ESTABLISHED, RELATED）
2. 允许 源 内网 → 目标 任意，端口 80, 443（出站 Web 访问）
3. 允许 源 任意 → 目标 Web服务器，端口 80, 443（入站 Web 服务）
4. 拒绝 源 任意 → 目标 内网，端口 22（SSH 仅内部访问）
5. 记录并拒绝 所有其他流量（默认拒绝策略）

安全原则： - 默认拒绝（Default Deny）：除非明确允许，否则全部拒绝 - 最小权限原则：只开放必需的端口和服务

3.4 个人防火墙 vs 网络防火墙

特性 个人防火墙 网络防火墙
部署位置 终端设备（软件） 网络边界（硬件/软件）
保护对象 单台主机 整个网络
示例 Windows Defender 防火墙、iptables Cisco ASA、Palo Alto、pfSense
管理 用户自行配置 网络管理员集中管理

4. NAT（网络地址转换）

4.1 基本概念

NAT (Network Address Translation) 是一种将私有 IP 地址映射到公有 IP 地址的技术，主要用于解决 IPv4 地址短缺问题。

私有 IP 地址范围（RFC 1918）：

10.0.0.0      - 10.255.255.255    (10.0.0.0/8)
172.16.0.0    - 172.31.255.255    (172.16.0.0/12)
192.168.0.0   - 192.168.255.255   (192.168.0.0/16)

这些地址不能在公网上路由，只能在内网使用。

4.2 NAT 类型

4.2.1 静态 NAT（Static NAT）

一对一映射：一个私有 IP 固定对应一个公有 IP

私有 IP          公有 IP
192.168.1.10  ←→  203.0.113.10
192.168.1.11  ←→  203.0.113.11

用途：内网服务器需要对外提供服务（Web 服务器、邮件服务器）

4.2.2 动态 NAT（Dynamic NAT）

多对多映射：多个私有 IP 动态分配到一个公有 IP 池

私有 IP 池：192.168.1.0/24
公有 IP 池：203.0.113.10 - 203.0.113.20

192.168.1.50 → 临时分配 203.0.113.15
192.168.1.60 → 临时分配 203.0.113.18

特点：连接结束后释放公有 IP，供其他主机使用

4.2.3 PAT（端口地址转换）/ NAPT / NAT Overload

多对一映射：多个私有 IP 共享一个公有 IP，通过端口号区分

这是最常用的 NAT 类型（家庭路由器使用）

NAT 映射表：
内网 IP:端口            公网 IP:端口         目标 IP:端口
192.168.1.10:5000  →  203.0.113.5:10001  →  8.8.8.8:80
192.168.1.15:6000  →  203.0.113.5:10002  →  1.1.1.1:443
192.168.1.10:5001  →  203.0.113.5:10003  →  8.8.8.8:443

工作流程：

  1. 出站： - 内网主机 192.168.1.10:5000 → 外网 8.8.8.8:80 - NAT 设备改写：源地址改为 203.0.113.5:10001 - 记录映射关系到 NAT 表

  2. 入站： - 外网响应：8.8.8.8:80 → 203.0.113.5:10001 - NAT 设备查表，改写：目标地址改为 192.168.1.10:5000 - 转发给内网主机

4.3 NAT 的优缺点

优点： - ✅ 缓解 IPv4 地址短缺（多台设备共享一个公网 IP） - ✅ 隐藏内网拓扑，增加安全性 - ✅ 灵活更换 ISP（内网 IP 不需要变动）

缺点： - ❌ 破坏端到端连接（违背 Internet 端到端原则） - ❌ 影响某些协议（FTP、SIP、P2P 需要特殊处理） - ❌ 增加延迟（需要查表和改写数据包） - ❌ 使某些应用复杂化（需要 NAT 穿透技术）

4.4 NAT 穿透技术

由于 NAT 的存在,外网主机无法主动连接内网主机,需要特殊技术:

STUN (Session Traversal Utilities for NAT)

  • 客户端向 STUN 服务器查询自己的公网 IP 和端口
  • 用于发现 NAT 类型
  • 适用于完全锥形 NAT 和限制锥形 NAT

TURN (Traversal Using Relays around NAT)

  • 通过中继服务器转发所有流量
  • 适用于严格的 NAT（对称 NAT）
  • 缺点：消耗服务器带宽

ICE (Interactive Connectivity Establishment)

  • 综合 STUN、TURN 等技术
  • 尝试多种连接方式，选择最优路径
  • WebRTC 使用的标准方案

UPnP / NAT-PMP

  • 应用程序请求路由器开放特定端口
  • 自动配置端口映射
  • 安全风险：恶意软件可能滥用

4.5 端口转发（Port Forwarding）

手动配置路由器将特定端口的流量转发到内网特定主机

配置示例：
外部端口 80   → 转发到 → 192.168.1.100:8080  (Web 服务器)
外部端口 22   → 转发到 → 192.168.1.50:22     (SSH 服务器)
外部端口 3389 → 转发到 → 192.168.1.60:3389   (远程桌面)

用途：让外网能够访问内网服务（搭建服务器、远程桌面、游戏联机）

5. VPN（虚拟专用网络）

5.1 基本概念

VPN (Virtual Private Network) 在公共网络（如 Internet）上建立加密的专用通道，使远程用户或分支机构能安全地访问企业内网。

核心功能： - 加密：保护数据传输安全 - 身份认证：验证用户和设备 - 隧道技术：在公网上创建虚拟专用通道

5.2 VPN 类型

5.2.1 远程访问 VPN（Remote Access VPN）

场景：远程员工连接到公司网络

远程用户（家中）
     |
     | VPN 隧道（加密）
     |
   Internet
     |
     | 
  公司 VPN 网关
     |
  公司内网

特点： - 用户安装 VPN 客户端 - 拨号连接到 VPN 服务器 - 获得内网 IP，访问内网资源

5.2.2 站点到站点 VPN（Site-to-Site VPN）

场景：连接两个或多个局域网（如总部和分支机构）

总部网络 ←→ VPN 网关 ←→ Internet ←→ VPN 网关 ←→ 分支网络

特点： - 网关设备之间自动建立隧道 - 用户无需安装客户端 - 两个网络如同在同一局域网

5.3 VPN 协议

5.3.1 PPTP（点对点隧道协议）

  • 端口：TCP 1723
  • 加密：MPPE（较弱）
  • 优点：设置简单，速度快
  • 缺点：安全性差，已不推荐使用
  • 状态：几乎已废弃

5.3.2 L2TP/IPsec

L2TP (Layer 2 Tunneling Protocol)：提供隧道
IPsec：提供加密和认证

  • 端口：UDP 500（IKE）、UDP 4500（NAT-T）、ESP 协议 50
  • 加密：IPsec（强）
  • 优点：安全性高，广泛支持
  • 缺点：配置复杂，NAT 穿透问题（需要 NAT-T）

5.3.3 IPsec VPN

两种模式：

传输模式：只加密数据部分，保留原 IP 头

[ IP 头 | ESP 头 | 加密数据 | ESP 尾 | 认证 ]

隧道模式：加密整个 IP 包，添加新 IP 头（常用）

[ 新 IP 头 | ESP 头 | 加密的原始 IP 包 | ESP 尾 | 认证 ]

两种协议： - AH (Authentication Header)：提供认证和完整性，不加密 - ESP (Encapsulating Security Payload)：提供加密、认证和完整性（常用）

5.3.4 OpenVPN

  • 基于：SSL/TLS
  • 端口：UDP 1194（默认）或 TCP 443（可伪装成 HTTPS）
  • 加密：OpenSSL 库（AES、ChaCha20 等）
  • 优点：
  • 开源、跨平台
  • 安全性高
  • 易穿透防火墙（可用 TCP 443）
  • 配置灵活
  • 缺点：需要安装第三方客户端
  • 状态：企业和个人广泛使用

5.3.5 WireGuard

  • 特点：现代、极简、高性能
  • 端口：UDP（自定义，默认 51820）
  • 加密：ChaCha20、Curve25519
  • 优点：
  • 代码量少（约 4000 行，OpenVPN 超过 100000 行）
  • 性能优异
  • 易于部署
  • 已集成到 Linux 内核
  • 缺点：功能相对简单
  • 状态：快速流行，被认为是未来趋势

5.3.6 SSL VPN / TLS VPN

  • 工作层次：应用层
  • 访问方式：通过 Web 浏览器（无需客户端）
  • 端口：TCP 443
  • 优点：
  • 无需安装客户端（clientless）
  • 易穿透防火墙
  • 细粒度访问控制（可限制访问特定应用）
  • 缺点：通常只支持 Web 应用和特定协议
  • 典型产品：Cisco AnyConnect、Pulse Secure

5.5 VPN 的工作原理

5.5.1 隧道封装

原始数据包：
[ IP 头 | TCP 头 | 数据 ]

VPN 封装后：
[ 新 IP 头 | VPN 头 | 加密的（原 IP 头 | TCP 头 | 数据）| VPN 尾 ]
     ↑                            ↑
  外层头                       隧道内容
（可路由的公网地址）          （加密保护）

过程： 1. 应用程序生成数据包 2. VPN 客户端拦截数据包 3. 加密数据包 4. 添加 VPN 头（包含隧道信息） 5. 添加新的 IP 头（源：本机公网 IP，目标：VPN 服务器 IP） 6. 通过公网发送 7. VPN 服务器解密，提取原始数据包 8. 转发到目标内网地址

5.5.2 VPN 认证方式

  1. 用户名/密码：最常见
  2. 数字证书：基于 PKI，更安全
  3. 预共享密钥（PSK）：双方预先约定密钥
  4. 双因素认证（2FA）：密码 + 动态令牌
  5. 智能卡/硬件令牌：物理设备认证

5.6 VPN vs 代理

特性 VPN 代理（Proxy）
工作层次 网络层（IP 层） 应用层
加密 全流量加密 通常不加密（HTTPS 代理例外）
覆盖范围 整个系统所有流量 仅特定应用（浏览器）
配置 系统级配置 应用级配置
性能开销 较高（加密） 较低
安全性 高 低到中
典型用途 安全远程访问、连接内网 访问控制、缓存、匿名浏览

5.7 分离隧道（Split Tunneling）

完全隧道（Full Tunnel）： - 所有流量都通过 VPN - 优点：最安全 - 缺点：增加 VPN 服务器负担，访问 Internet 变慢

分离隧道（Split Tunnel）： - 只有访问内网的流量通过 VPN - 访问 Internet 的流量直接走本地网络 - 优点：节省带宽，速度快 - 缺点：部分流量未加密，存在安全风险

分离隧道：
用户 → 访问公司内网 → VPN 隧道 → 公司网络
用户 → 访问 Internet → 本地 ISP → Internet

5.8 VPN 的应用场景

  1. 远程办公：员工在家访问公司内网资源
  2. 分支机构互联：总部与各地分支机构组成统一网络
  3. 安全通信：在不可信网络（公共 Wi-Fi）上保护数据
  4. 绕过地理限制：访问特定地区的内容（合法前提下）
  5. 隐私保护：隐藏真实 IP 地址
  6. 物联网安全：保护 IoT 设备通信

6. 综合对比

6.1 安全技术栈

应用层   │ TLS/SSL（HTTPS）、SSH、应用层防火墙
传输层   │ TLS、状态检测防火墙
网络层   │ IPsec、包过滤防火墙、NAT
数据链路层│ WPA3（Wi-Fi 加密）
物理层   │ 物理隔离

6.2 企业网络安全架构示例

            Internet
               |
         [防火墙/NAT]
               |
          [IDS/IPS]
               |
       -----DMZ 区-----
       |              |
   [Web 服务器]  [邮件服务器]
                      |
              [内部防火墙]
                      |
                  [核心网络]
                   /     \
            [办公网络]  [服务器网络]
                 |           |
              [终端]      [数据库]
                           [文件服务器]

远程用户 → VPN → 防火墙 → 内网

防御层次（Defense in Depth）： 1. 边界防火墙（阻止外部攻击） 2. DMZ 隔离（公开服务与内网隔离） 3. 内部防火墙（内网分段） 4. IDS/IPS（入侵检测和防御） 5. 终端防护（杀毒软件、个人防火墙） 6. 加密通信（TLS、VPN） 7. 身份认证（多因素认证） 8. 审计日志（追踪和取证）

7. 常见面试问题

7.1 HTTPS 与 HTTP 的区别

特性 HTTP HTTPS
协议 明文传输 TLS/SSL 加密
端口 80 443
安全性 不安全，易被窃听和篡改 加密传输，认证服务器
SEO 排名靠后 搜索引擎优先
性能 略快 有握手开销（TLS 1.3 已大幅优化）
证书 不需要 需要 CA 证书

7.2 对称加密和非对称加密在 TLS 中的作用

  • 非对称加密（RSA、ECDHE）：
  • 用于握手阶段的密钥交换
  • 用于数字签名验证证书

  • 慢，但无需提前共享密钥

  • 对称加密（AES、ChaCha20）：

  • 用于加密实际传输的数据（握手完成后）
  • 快，适合大量数据

为什么不全用非对称加密？ 太慢，不适合加密大量数据

7.3 中间人攻击（MITM）与防御

攻击方式：

客户端 ←→ 攻击者 ←→ 服务器
        ↑         ↑
    假冒服务器  假冒客户端

攻击者拦截通信，分别与客户端和服务器建立连接，可以窃听和篡改数据。

防御措施： - ✅ 使用 HTTPS（TLS） - ✅ 验证服务器证书（浏览器会检查） - ✅ 证书固定（Certificate Pinning）：硬编码服务器证书或公钥 - ✅ HSTS（HTTP Strict Transport Security）：强制使用 HTTPS - ✅ 不信任公共 Wi-Fi，使用 VPN

7.4 NAT 的工作原理

见 4.2.3 PAT

关键点： - 通过修改 IP 地址和端口号实现地址转换 - 维护 NAT 映射表记录转换关系 - 出站时修改源地址,入站时修改目标地址

7.5 VPN 的实现原理

见 5.5 VPN 的工作原理

关键技术： 1. 隧道技术：在公网上封装私有数据包 2. 加密：保护隧道内的数据 3. 身份认证：验证通信双方

7.6 防火墙如何防御 DDoS 攻击

传统防火墙： - 速率限制（Rate Limiting）：限制单个 IP 的连接速率 - SYN Cookie：防御 SYN Flood 攻击 - 黑名单：阻止已知攻击源

局限性： - 分布式攻击难以防御（攻击源众多） - 带宽耗尽型攻击防火墙无能为力

更有效方案： - CDN 和 DDoS 防护服务（Cloudflare、Akamai） - 流量清洗中心 - Anycast 分散流量

7.7 TLS 1.3 相比 TLS 1.2 的改进

见 1.4 TLS 1.3 的改进

核心改进： - ⚡ 1-RTT 握手（更快） - ⚡ 0-RTT 重连（会话恢复） - 🔒 移除不安全算法（RSA 密钥交换、CBC 模式） - 🔒 加密更多握手数据 - 🔒 强制前向保密（Forward Secrecy）

7.8 CA 证书的信任链如何工作

见 2.3 证书信任链

验证步骤： 1. 客户端收到服务器证书 2. 逐级向上验证到根证书 3. 根证书必须在系统的受信任根证书列表中 4. 验证每一级的签名、有效期、吊销状态
