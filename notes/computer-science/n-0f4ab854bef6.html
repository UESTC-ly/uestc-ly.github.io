这份清单用于阶段复盘和面试自测。回答时采用四段式：定义/机制 → 工程场景 → 取舍与边界 → 如何验证。

使用与评分方法

每个勾选项按 0～3 分自评：

分数 表现
0 只听过名词，无法准确解释
1 能给定义，但不能画流程或说明错误路径
2 能实现/配置并解释常见边界
3 能在故障、容量和一致性约束下做选择，并给验证证据

核心项达到 2 分后再进入下一模块；系统设计题需要把多个 2～3 分知识点组合起来。遇到“绝对不会丢”“保证一致”“性能一定更好”等绝对表述时，主动追问故障模型和前提。

1. C++ 与 Linux

  • [ ] 能解释 RAII 如何覆盖异常和提前返回路径，以及资源释放仍可能遇到的失败。
  • [ ] 能画出 unique_ptr/shared_ptr/weak_ptr 的所有权关系，识别回调引用环和悬空捕获。
  • [ ] 能区分数据竞争和业务竞态，并给共享状态写出不变量。
  • [ ] 能解释条件变量为何要用谓词，原子变量为何不能自动保护复合状态。
  • [ ] 能设计线程池的有界队列、拒绝、取消、排空和 join 顺序。
  • [ ] 能解释 fd 复用、短读短写、EINTR/EAGAIN 和 SIGPIPE。
  • [ ] 能用 strace、ss、lsof、perf 和 Sanitizer 定位常见问题。
  • [ ] 能说明页缓存、WAL、fsync 与“写成功/提交成功”的持久性边界。

2. 网络服务

  • [ ] 能区分阻塞/非阻塞与同步/异步，不混淆 Reactor 和 Proactor。
  • [ ] 能说明 select/poll/epoll 的数据结构和复杂度差异，而不是只背数量限制。
  • [ ] 能解释 epoll LT/ET、EPOLLONESHOT、非阻塞循环读和惊群。
  • [ ] 能画出连接从 accept、读、解析、业务、写到关闭的状态机。
  • [ ] 能解释半包/粘包为何是字节流正常现象，并写出抗恶意长度的解码器。
  • [ ] 能设计空闲连接定时器，比较最小堆、时间轮和惰性删除。
  • [ ] 能说明 I/O 线程与工作线程间如何传递任务、响应和连接生命周期。
  • [ ] 能解释 HTTP keep-alive、WebSocket 升级/帧和 RPC 的超时/取消/序列化。
  • [ ] 能给出启动、readiness、停止接流量、连接排空和强制退出的顺序。
  • [ ] 能区分限流、背压、熔断和降级，并识别重试风暴。
  • [ ] 能判断内存池、对象池、连接池何时有益，何时只是隐藏瓶颈。

3. 数据库与 Redis

  • [ ] 能从查询模式和执行计划设计复合索引，说明写放大与回表代价。
  • [ ] 能解释事务隔离异常和数据库具体实现之间的关系。
  • [ ] 能计算多实例连接池对数据库总连接数的放大。
  • [ ] 能说出 Redis 五类核心数据结构的适用场景和大 key 风险。
  • [ ] 能区分 RDB/AOF 的恢复、性能和数据损失窗口。
  • [ ] 能解释过期删除与内存淘汰不是同一件事。
  • [ ] 能分别设计缓存穿透、击穿、雪崩的防护，并说明副作用。
  • [ ] 能说明 cache-aside 写库删缓存仍可能不一致，给出容忍、修复和对账方案。
  • [ ] 能解释 Redis 分布式锁的租约、续期、GC/暂停、主从切换和 fencing token 边界。
  • [ ] 能说明 Pipeline 与 Lua 各自减少/保证了什么，不夸大事务语义。
  • [ ] 能比较主从、Sentinel 与 Cluster 解决的问题。

4. 消息队列

  • [ ] 能解释 topic、partition、consumer group 和 offset 的关系。
  • [ ] 能说明生产者 ack、broker 持久化/复制、消费者提交如何共同影响可靠性。
  • [ ] 能复现“业务成功但 ack/offset 失败”导致的重复消息。
  • [ ] 能用业务键、唯一约束或状态机设计幂等消费者。
  • [ ] 能说明顺序只在什么范围成立，以及重试如何破坏处理顺序。
  • [ ] 能定位积压来自生产突增、分区不足、消费者慢、毒消息还是下游故障。
  • [ ] 能设计退避重试、重试队列、死信和人工重放流程。
  • [ ] 能解释 exactly-once 的适用范围，以及为什么外部副作用仍需幂等。
  • [ ] 能比较 Kafka、RabbitMQ、RocketMQ 的模型和适用场景。

5. 搜索与对象存储

  • [ ] 能解释倒排索引、分词、doc frequency 和 BM25 的直觉。
  • [ ] 能说明 mapping、refresh、segment、shard 和 replica 如何影响写入与查询。
  • [ ] 能读写基本 DSL、聚合，并识别深分页和高基数聚合风险。
  • [ ] 能解释向量相似度、ANN 召回、过滤、重排和质量/延迟权衡。
  • [ ] 能设计 BM25 + 向量的混合检索与离线评估，而不只主观试查询。
  • [ ] 能设计大文件 multipart、校验、断点续传、元数据和生命周期策略。
  • [ ] 能说明对象已上传、数据库已记录和消息已投递之间的失败窗口。

6. 分布式系统

  • [ ] 能准确表述 CAP 讨论的是网络分区发生时的取舍，不把系统永久贴成 CP/AP 标签。
  • [ ] 能区分线性一致性、顺序一致性、因果一致性和最终一致性。
  • [ ] 能说明超时为什么只表示“不知道结果”，而不是“操作必定没发生”。
  • [ ] 能比较客户端/服务端发现、负载均衡算法和健康检查。
  • [ ] 能设计分层超时预算，避免多层重试指数放大。
  • [ ] 能比较分布式锁、幂等、唯一约束和状态机分别解决什么。
  • [ ] 能解释 Snowflake 类 ID 的时钟回拨、节点号和趋势递增边界。
  • [ ] 能比较 2PC、TCC、Saga、Outbox 和最终一致性的代价。
  • [ ] 能说明一致性哈希的虚拟节点、倾斜和扩缩容迁移。
  • [ ] 能解释 Raft 的 term、选举、日志复制、commit 与多数派安全性直觉。
  • [ ] 能定义 RTO/RPO，设计备份恢复、跨区/跨地域和演练。
  • [ ] 能把日志、指标、追踪串成故障定位路径，并用 SLO 驱动告警。

7. 系统设计答题框架

  1. 澄清需求：功能、规模、延迟、可用性、一致性、安全与成本。
  2. 粗略估算：QPS、带宽、存储、连接、热点和增长。
  3. 定义语义：API、幂等、顺序、事务、读写一致性和错误码。
  4. 画核心路径：同步请求、异步任务、数据写入和查询路径。
  5. 找瓶颈和单点：容量、分片、复制、缓存和负载均衡。
  6. 设计失败路径：超时、重试、隔离、熔断、降级、补偿和对账。
  7. 可观测与运维：SLI/SLO、告警、灰度、回滚、RTO/RPO。
  8. 说明取舍：哪些保证是理论性质，哪些依赖工程假设，哪些风险被业务接受。

8. 最终口头练习

尝试在 10 分钟内回答以下题目，然后回看对应章节：

  1. 设计一个支持百万长连接的消息推送服务。
  2. 设计一个秒杀库存扣减系统，说明缓存、数据库、MQ 和幂等边界。
  3. 设计一个大文件上传与异步处理平台。
  4. 设计一个多租户全文 + 向量混合检索服务。
  5. 某接口 P99 突然升高但 CPU 不高，给出排查路径。
  6. Kafka 消费积压且偶有重复结果，怎样定位和修复？
  7. Redis 热 key 导致单节点过载，怎样发现、缓解并避免不一致？
  8. 服务滚动升级时出现少量 502，怎样验证连接排空和 readiness 时序？

9. 故障题回答模板

以“P99 升高但 CPU 不高”为例，避免直接猜网络或 GC：

  1. 确认影响：哪些接口/租户/实例，何时开始，错误率和吞吐是否变化。
  2. 拆分延迟：入口排队、线程池/连接池等待、业务计算、RPC/DB/Redis/MQ、序列化与网络。
  3. 看饱和信号：队列长度、池等待、fd、带宽、磁盘延迟、锁竞争、下游 P99。
  4. 与变更关联：发布、配置、流量形态、数据大小、热点 key、索引或依赖异常。
  5. 控制影响：限流、停止重试、隔离、回滚、降级或扩容；记录动作副作用。
  6. 证明根因：trace、慢查询、火焰图、系统调用或可控复现实验，而不是相关性猜测。
  7. 修复与预防：容量边界、告警、回归测试、runbook 和架构调整。

其他故障题也按“影响面 → 路径分解 → 饱和/失败证据 → 止损 → 根因 → 预防”组织。

10. 高频追问题

网络与并发

  1. ET 已经读到 EAGAIN，此时工作队列满了，应该继续读、暂停读还是断开？依据是什么？
  2. 连接关闭后 worker 返回结果，如何避免它写到被复用的 fd？
  3. shared_ptr<Connection> 能否彻底解决连接生命周期？为什么活着的对象仍可能处于逻辑关闭状态？
  4. 线程池排空时任务又提交子任务会怎样？关闭协议如何定义？

数据与中间件

  1. 更新数据库成功、删除缓存失败时，TTL、重试、消息和对账各解决哪部分风险？
  2. Redis 锁过期后旧持有者写数据库，为什么续租仍不能完全消除问题？
  3. 消费者完成数据库事务但未提交 offset，重放时唯一约束如何与业务响应配合？
  4. Kafka 分区增加后，原来的 key 顺序和 hash 映射可能发生什么变化？

搜索与分布式

  1. 为什么 BM25 与向量相似度不能简单直接相加？怎样建立融合基线？
  2. refresh 后文档可搜索与数据持久化分别由什么机制负责？
  3. RPC 超时后服务端可能已经提交，客户端如何查询或安全重试？
  4. Raft 中为什么旧 term 条目不能仅因复制到多数派就按同一规则直接提交？
  5. 多活系统中“所有地域可写”会引入哪些冲突、路由和恢复问题？
