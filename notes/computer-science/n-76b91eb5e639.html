C++ 与 Linux 基础

后端程序长时间运行、并发访问共享状态，并与大量操作系统资源交互。学习重点是让所有权、生命周期、并发关系和错误路径可解释。

学习顺序

  1. C++ 资源管理与工程基础
  2. C++ 并发与内存模型
  3. Linux 系统编程
  4. 关系数据库基础

知识依赖

  • 资源管理是后续所有章节的基础：fd、线程、事务和连接池都需要明确所有权与释放顺序。
  • 并发模型依赖生命周期模型：锁、条件变量、原子变量和线程池关闭都必须先定义共享状态的不变量。
  • Linux 系统编程把 C++ 对象落到真实内核资源：fd 表、页缓存、虚拟内存、信号和调度会直接影响网络服务行为。
  • 数据库章节连接到工程边界：事务、WAL、复制和连接池是后续 RPC deadline、重试和服务韧性的前置知识。

阶段产出

  • RAII 封装的文件描述符，禁止复制、支持移动。
  • 有界阻塞队列和固定大小线程池，能停止并回收线程。
  • 父子进程、信号、管道、文件 I/O 的小型实验。
  • 一套包含索引分析、事务并发和连接池的数据库实验。
  • 一份能解释错误路径的排查记录：包括 fd 泄漏、数据竞争、系统调用返回值和慢 SQL 执行计划。

验收标准

  • 能沿代码路径说明对象和 fd 的创建、转移和销毁。
  • 能说明互斥量保护的约束，而不只是“这里加一把锁”。
  • 能区分用户态/内核态、进程/线程、虚拟内存/物理内存、缓冲 I/O/直接 I/O。
  • 能用工具验证内存错误、数据竞争、系统调用和查询执行计划。
  • 能把“性能更好”“事务安全”“线程安全”等说法拆成具体版本、配置、边界和观测证据。

章节成果

  • 完成后应能写出一个资源安全的小型 C++ 服务骨架。
  • 能把线程、fd、事务和连接池的关闭顺序写成状态图。
  • 能针对线上现象选择 strace、perf、Sanitizer、执行计划或连接池指标。
  • 能解释每个实验的失败路径，而不只保留成功运行截图。
