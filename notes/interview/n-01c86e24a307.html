查找两个正序数组的中位数

回答：

设两个正序数组分别为 A 和 B，长度为 m、n。目标是在不真正合并数组的情况下找到第 (m+n+1)/2 小和第 (m+n+2)/2 小的元素。最优方法是在较短数组上二分切分位置。

选择切分 i 个元素来自 A，则需要 j = half - i 个元素来自 B。合法切分要求：

\[ A[i-1]\le B[j]\quad\text{且}\quad B[j-1]\le A[i]. \]

其中越界左值视为 \(-\infty\)，越界右值视为 \(+\infty\)。找到合法切分后，左半部分最大值为 \(\max(A[i-1],B[j-1])\)，右半部分最小值为 \(\min(A[i],B[j])\)。总长度为奇数时取左最大值，为偶数时取左右平均值。

from typing import List


def find_median_sorted_arrays(a: List[int], b: List[int]) -> float:
    if len(a) > len(b):
        a, b = b, a
    m, n = len(a), len(b)
    if m + n == 0:
        raise ValueError("both arrays cannot be empty")

    left, right = 0, m
    half = (m + n + 1) // 2
    neg_inf = float("-inf")
    pos_inf = float("inf")

    while left <= right:
        i = (left + right) // 2
        j = half - i
        a_left = neg_inf if i == 0 else a[i - 1]
        a_right = pos_inf if i == m else a[i]
        b_left = neg_inf if j == 0 else b[j - 1]
        b_right = pos_inf if j == n else b[j]

        if a_left > b_right:
            right = i - 1
        elif b_left > a_right:
            left = i + 1
        else:
            left_max = max(a_left, b_left)
            if (m + n) % 2 == 1:
                return float(left_max)
            right_min = min(a_right, b_right)
            return (left_max + right_min) / 2.0

    raise ValueError("input arrays are not sorted")

二分发生在较短数组上，因此时间复杂度为 \(O(\log\min(m,n))\)，额外空间复杂度为 \(O(1)\)。边界包括一个数组为空、两个数组都为空、重复元素、负数和总长度为偶数。不能只用双指针合并到中点后宣称最优，那样时间复杂度是 \(O(m+n)\)；如果面试官只要求普通实现，双指针可接受，但应说明这是线性方案。

标量、向量、矩阵、张量之间有什么联系和区别？

标量（Scalar） 是一个单独的数，可以看作 0 阶张量，例如损失值 \(L\)、学习率 \(\eta\)、温度系数 \(T\)。

向量（Vector） 是一组有序数，可以看作 1 阶张量，例如一个 token 的 embedding 向量 \(x \in \mathbb{R}^{d}\)。

矩阵（Matrix） 是二维数组，可以看作 2 阶张量，例如线性层权重 \(W \in \mathbb{R}^{d_{in} \times d_{out}}\)、注意力矩阵 \(A \in \mathbb{R}^{n \times n}\)。

张量（Tensor） 是更一般的多维数组。例如 LLM 中一批 token hidden states 常写为：

\[ X \in \mathbb{R}^{B \times S \times D} \]

其中 \(B\) 是 batch size，\(S\) 是序列长度，\(D\) 是 hidden size。多头注意力中常变形为：

\[ Q,K,V \in \mathbb{R}^{B \times H \times S \times d_h} \]

其中 \(H\) 是注意力头数，\(d_h = D/H\)。

面试回答要点：

  • 标量、向量、矩阵都是张量的特殊情况。
  • 深度学习中“维度”既可能指数学维度，也可能指张量 shape，需要结合上下文说明。
  • 工程中最容易出错的是 batch 维、sequence 维、head 维、feature 维的排列。

栈和队列有什么区别

回答：

栈遵循后进先出，常见操作是在同一端压入、弹出与查看栈顶；队列遵循先进先出，通常从队尾进入、队头移出。二者是抽象数据结构，可以用数组、链表或其他容器实现，复杂度需要结合具体实现说明。

栈适合函数调用、括号匹配、撤销和深度优先遍历；队列适合广度优先遍历、任务排队和按到达顺序处理。对于无权图，BFS 使用队列逐层扩展可以寻找最短边数路径，而 DFS 的栈顺序不保证这一点。

Python 中 list 的 append 和末尾 pop 适合实现栈，通常为摊还 O(1)；list.pop(0) 会移动后续元素，通常为 O(n)。普通双端队列可用 collections.deque，append 和 popleft 在两端高效操作。线程间生产消费应考虑 queue.Queue 等带同步与阻塞语义的抽象，不能把普通容器的单个操作特性等同于整个复合业务逻辑线程安全。

工程任务队列还需要考虑容量、背压、超时和取消。先进先出只约束取出的顺序，多个消费者并发执行时，完成顺序未必与入队顺序相同；需要严格有序时应额外设计分区串行或结果排序机制。

核心 motivation

回答：

论文的 motivation 应表述为一个可以检验的问题：已有方法在什么条件下出现什么限制，为什么值得解决。避免只复述“提升泛化、降低成本”这样的宽泛目标。

可以按“现象—已有方法缺口—关键假设—预期证据”讲述。例如示教很少、动作有多种可行方式时，单一回归可能产生不可执行的平均动作；相应工作会研究更合适的条件分布建模。这是一般性例子，具体论证要回到所讨论论文。

区分作者明确报告的事实、你对机制的理解和尚未验证的推测。motivation 强并不代表方法已解决所有问题，应核对实验是否真的覆盖了声称的难点。

准备一个反例：如果任务是确定性、短时、固定场景，论文的复杂设计是否还有必要。能说明适用边界，才表明理解了研究问题。

核心观察

当 k > 0 时，元素的具体数值只需要保留除以 k 的余数。设

\[ r_i = a_i \bmod k \]

则

\[ a_i+a_j\equiv 0\pmod{k} \quad\Longleftrightarrow\quad r_i+r_j\equiv 0\pmod{k}. \]

余数 r 的配对余数是 (k-r) % k。因此：

  • 余数为 0 的元素只能和余数为 0 的元素配对，贡献 C(cnt[0], 2)；
  • 对于 1 <= r < k-r，余数 r 与 k-r 的方案数为 cnt[r] * cnt[k-r]；
  • 如果 k 为偶数，余数 k/2 只能和自己配对，贡献 C(cnt[k/2], 2)。

“下标不同”由组合数 C(x, 2) 自然保证；“无序对”则意味着 (i,j) 和 (j,i) 只计算一次，不能在所有余数组合上直接把有序计数除以 2 后再处理特殊余数。

模型FLOPs怎么算？

同样，我们假设卷积核的尺寸是\(K\times K\)，有\(C\)个特征图作为输入，每个输出的特征图大小为\(H \times W\)，输出为\(M\)个特征图。

由于在模型中卷积一般占计算量的比重是最高的，我们依旧以卷积的计算量为例进行分析：

FLOPS（全大写）：是floating point operations per second的缩写，意指每秒浮点运算次数，理解为计算速度。是一个衡量硬件性能的指标。

FLOPs（s小写）：是floating point operations的缩写（s表示复数），意指浮点运算数，理解为计算量。可以用来衡量算法/模型的复杂度。

针对模型的计算量应该指的是FLOPs。

在上述情况下，卷积神经网络一次前向传播需要的乘法运算次数为：

\[H\times W\times M\times C\times K\times K\]

同时，所要进行的加法计算次数分为考虑偏置和不考虑偏置：

(1)考虑偏置的情况：

为了得到输出的特征图的一个未知的像素，我们需要进行 $\((C\times K\times K - 1) + (C - 1) + 1 = C \times K \times K\)$ 次加法操作，其中\(K\times K\)大小的卷积操作需要\(K\times K - 1\)次加法，由于有C个通道，所以需要将结果乘以C，每个通道间的数要相加，所以需要C - 1次加法，最后再加上偏置的1次加法。

所以总的加法计算量如下：

所以总的卷积运算计算量（乘法+加法）：

\[2 \times H\times W\times M\times C\times K\times K\]

(2)不考虑偏置的情况：

总的卷积计算量：

\[H\times W\times M\times (2\times C\times K\times K - 1)\]

模型压缩主要有哪些技术路线？各自适合什么场景？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

模型压缩常见技术路线主要有五类。

一、剪枝：删除不重要的参数或结构

剪枝的思路是：模型中不是所有参数都同等重要，可以删除贡献较小的权重、通道、卷积核、注意力头或网络层。

常见分类： - 非结构化剪枝：删除单个权重，模型变稀疏 - 结构化剪枝：删除通道、卷积核、层等完整结构

剪枝的优点是可以减少参数量和计算量；难点是剪完后可能掉精度，通常需要微调恢复效果。

二、量化：用低精度表示权重和激活

量化是把模型中的FP32、FP16等高精度数值，用INT8、INT4、FP8等低精度格式表示。

例如，把32位浮点数变成8位整数，模型大小和内存带宽需求都会降低。

量化的优点是工程落地成熟、收益明显，是推理部署中最常见的压缩方法之一。

三、知识蒸馏：用大模型指导小模型训练

知识蒸馏的思路是：先训练一个效果好的大模型作为老师模型，再训练一个更小的学生模型去模仿老师模型的输出或中间特征。

这样学生模型虽然更小，但可以学到老师模型的“软知识”，效果通常比直接训练小模型更好。

四、低秩分解：把大矩阵拆成小矩阵

低秩分解常用于全连接层、卷积层或大模型中的线性层。它把一个大的权重矩阵近似分解成两个或多个更小的矩阵，从而减少参数量和计算量。

它的优点是数学上比较清晰；缺点是压缩比例过高时精度容易下降，并且并不一定在所有硬件上都能带来实际加速。

五、轻量化结构设计：直接设计更小的模型

这类方法不是压缩已有模型，而是在模型设计阶段就使用更轻量的结构。

典型例子包括： - MobileNet使用深度可分离卷积 - ShuffleNet使用通道shuffle和分组卷积 - TinyBERT、DistilBERT等小型Transformer模型

这种方式通常部署友好，但需要重新设计或训练模型。

模型或工具持续不可用时怎么降级？

重试主要处理限流、临时网络错误等瞬时故障。模型供应商长时间不可用，或者某个工具持续报错时，继续消耗重试预算只会拉长响应时间。这时要及时熔断故障依赖，停止向它发送新请求，并根据任务风险选择备用模型、缓存结果、返回部分结果或转人工。

切换备用模型前，要用同一套评测集确认它能否承担当前任务。低风险的文本总结可以降级到能力较弱的模型；涉及退款、发消息等写操作时，模型能力下降可能同时影响工具选择和参数生成，这类任务更适合暂停执行或转人工，不能为了维持可用性静默降低安全要求。

工具降级也要看它在任务中的作用。可选工具不可用时，可以临时从工具集合中移除；缺少它仍能回答的问题，可以明确告知限制后返回部分结果；订单、权限或政策证据等必要数据拿不到时，应停止生成确定性结论。系统还要把熔断原因、降级路径和最终结果写入 Trace，方便区分“正常完成”和“降级完成”。

流量上来后还要看模型配额、工具并发、线程池、连接池和队列长度。限流与背压应尽量靠近入口，慢工具使用独立并发舱壁，避免一个第三方接口拖住全部 Agent Run。并行分支会写共享 State 时，还要提前定义合并和冲突规则。

模型提出的函数调用怎样进入执行链路？

Function Calling 的本质是让模型根据自然语言需求，选择一个结构化函数，并生成符合 Schema 的参数，由宿主程序执行函数，再把结果交回模型生成最终回答。

\text{User Request} \rightarrow \text{Model Selects Function} \rightarrow \text{Generate Arguments} \rightarrow \text{Host Executes} \rightarrow \text{Tool Result} \rightarrow \text{Model Response}

  • 模型不直接执行函数。
  • 模型只生成函数名和参数。
  • 宿主程序负责真正调用 API、数据库、文件系统或业务服务。
  • 工具返回结果后，模型再负责解释、总结或决定下一步。

模型比较维度

比较不同视频生成模型时，不宜只讨论“谁的效果更好”。面试中更稳妥的做法是拆解其任务能力、表示方式、主干架构、控制能力和部署约束，避免被演示样例的表面效果影响判断。

  1. 任务能力：支持 T2V、I2V、V2V、Subject-to-Video、Audio-to-Video、视频编辑还是统一多模态生成。
  2. 视频表示：使用图像 VAE、Video VAE、3D VAE、Causal VAE，还是更统一的 video tokenizer / spacetime patches。
  3. 主干架构：是 2D U-Net + temporal module、Video U-Net、3D U-Net、Video Transformer，还是 DiT / Video DiT。

  5. 时序与一致性：能否维持身份、场景、运动、风格和故事层面的长期稳定。
  6. 长视频能力：是否支持 causal、chunk、sliding-window、hierarchical 或 storyboard/memory 等长视频策略。
  7. 效率与部署：生成速度、采样步数、显存、吞吐、低时延交互能力和产品可用性。
  8. 开放程度与生态：是否开源权重、训练代码、数据处理管线、VAE、推理框架和社区插件。

模型离线分数提升但用户体验没有变好，应如何排查？

难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐⭐ (4/5)

这种现象通常来自五类错配：离线提升没有超过测量噪声，离线与线上生成协议不一致，评测集与线上请求分布不同，代理指标奖励了错误行为，或者视频质量的收益被延迟、失败率和交互成本抵消。排查顺序要先保证比较成立，再讨论用户偏好。

  1. 先确认提升是否真实。 检查重复运行、seed 方差、样本量和置信区间。提升小于评测波动时，暂时不能推出模型能力已经改变。
  2. 对齐生成协议。 核对 checkpoint、EMA、prompt 重写、采样器、步数、CFG、seed 策略、分辨率、后处理和安全过滤。任一项不同，都可能让问题落在推理配置而非模型权重。
  3. 重做业务分桶。 比较离线与线上在任务类型、prompt 长度、主体数、运动强度、参考条件、时长和分辨率上的分布。总分上升但高频业务桶没有改善，用户无感是合理结果。
  4. 检查指标奖励了什么。 画质提高伴随运动减弱、时序分数提高伴随输出趋于静态、文本相似度提高但关系仍错误，都说明代理指标与业务目标不一致。需要回看样本和失败标签；继续调整总分权重无法解释问题。
  5. 补齐端到端体验。 将排队、生成时长、失败与重试、可控性、编辑成功率和单位成本纳入同一版本比较。最后对争议场景做盲测或线上 A/B，区分“质量确有提升但用户不重视”与“离线评估本身失真”。

每种的底层机理了解嘛？

回答：

了解，但要加一句版本边界：Redis 的内部编码会演进，阈值也可配置，不能把旧版 ziplist 等实现当成所有版本的固定答案。可以用 OBJECT ENCODING key 观察当前对象编码。

  • String： 使用 SDS 保存二进制安全字符串，根据值和长度采用整数、嵌入式或普通字符串编码。SDS 记录长度和容量，避免每次扫描 \0，并支持预分配。

海量数据中找最大的 K 个数有哪些方案？为什么通常使用容量为 K 的小根堆，具体过程和复杂度是什么？

回答：

如果数据可全部放入内存，排序后取末尾 K 个最直接，时间复杂度 \(O(n\log n)\)。Quickselect 平均 \(O(n)\) 找到第 K 大分界，再处理 Top-K，适合离线数组但最坏 \(O(n^2)\)，且不天然适合流式数据。计数/桶方法只适用于值域有限。分布式场景可以各分片先取本地 Top-K，再归并候选。

海量或流式数据通常使用容量 K 的小根堆。堆顶是当前 Top-K 中最小的数，也就是新元素进入集合的门槛：先放入前 K 个；之后若新值不大于堆顶就丢弃，若更大则替换堆顶并下沉。遍历结束后，堆中就是最大的 K 个数。

import heapq


def top_k_largest(values, k):
    if k <= 0:
        return []
    heap = []
    for value in values:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)

时间复杂度为 \(O(n\log K)\)，额外空间 \(O(K)\)；如果只需要无序集合，不必最后排序。使用小根堆是因为能 \(O(1)\) 看到门槛、\(O(\log K)\) 替换；若找最小 K 个则对应使用大根堆。还要澄清是否保留重复值、K 大于数据量时如何处理，以及结果是否要求有序。

滑动窗口和令牌桶相比有什么缺点？

回答：

滑动窗口的优点是统计语义直观，能严格表达“最近 N 秒最多 M 次”。但和令牌桶相比，它有几个缺点。

第一，突发友好性较差。令牌桶允许在桶中积累令牌，因此可以支持短时合理突发；滑动窗口更强调窗口内总量，可能对突发流量更敏感。

第二，存储和计算成本更高。滑动日志要保存窗口内每次请求的时间戳，高 QPS 下内存压力大；滑动计数器虽然内存固定，但要维护多个桶，还要处理桶过期、求和和并发安全。令牌桶只需要 tokens 和 last_refill 两个核心状态。

第三，分布式实现更复杂。滑动窗口在 Redis 中通常要用 ZSET 或多个桶计数，需要删除过期数据、统计数量、插入当前请求；令牌桶只需原子更新令牌数和时间戳。

第四，平滑程度取决于实现。滑动计数器如果桶粒度较粗，仍会有局部边界误差；桶粒度越细，成本越高。

因此，如果需求是精确限制最近时间窗口内的请求数，滑动窗口更合适；如果需求是控制平均速率并允许突发，令牌桶更合适。

滑动窗口算法与二分答案算法

题目：假设有一个长度为 \(n\) 的非负整数的数组，我们需要找到其中和不大于 \(sum\) 的最长子数组的长度。

上述题目是最经典的滑动窗口算法和二分答案算法的应用。先讲其中的二分答案算法。

首先我们可以知道非负整数子数组的和总是越长和就越大，不会因为增加了长度反而和变小了。那么假设我们找到了一个长度为 \(L\) 的子数组，我们是否可以找到一个大小介于 \([0,L)\) 的子数组呢？显然可以，因为我们只需要不断减少这个子数组的长度即可。因此我们可以知道这个答案是具有单调性质的，可以使用二分的方法加速寻找答案。

# 使用二分答案算法

def get_longgest_subarray(nums, sum):
    n = len(nums)
    pre = [0] * (n+1)
    for i in range(1, n+1):
        pre[i] = pre[i-1] + nums[i-1]
    def check(val) -> bool:
        # 检查是否存在一个长度为val的合法子数组
        nonlocal pre
        for i in range(1, n-val+2):
            # [i, i+val-1]
            if pre[i+val-1] - pre[i-1] <= sum:
                return True
        return False

    l, r = -1, n+1 # 开区间写法
    while l+1 < r:
        mid = (l+r)//2
        if check(mid):
            l = mid            
        else:
            r = mid
    return l  # 根据循环不变量 [0,l] 是合法的

使用了二分答案之后可以很明显感受到一点：这个最长的子数组是不是可以动态维护？比如说对于以 \(nums[i]\) 结尾的子数组，我们知道了它的左边界最远为 \(left\) ，那么对于以 \(nums[i+1]\) 结尾的子数组，它的最远左边界能够是多少呢？因为刚才已经推导过了，对于长度越长的子数组，和会保持不减，所以其左边界最远就是 \(left\) ，这可以使用反证法证明，这里就不啰嗦了。因此我们可以使用两个指针维护当前的最大子数组长度，也就是经典的双指针算法。

# 双指针（滑动窗口）

def get_longgest_subarray(nums, sum):
    n = len(nums)
    l, s = 0, 0
    ans = 0
    for i in range(n):
        s += nums[i]
        while s > sum:
            s -= nums[l]
            l += 1
        if i - l + 1 > ans:
            ans = i - l + 1
    return ans

二分答案经常用来解决一种答案具有单调性质的问题，而根据计算复杂度理论，检查是否成立比求解简单。而滑动窗口算法则是一种全局的优化，本质上是动态规划的思想。二分答案在面试算法题中是一种非常重要的算法。

漏桶算法（Leaky Bucket）的原理讲一下。

回答：

漏桶算法把请求看成水，把系统处理能力看成桶底以固定速率漏水。请求进入桶中排队，桶以恒定速率处理请求；如果桶满了，新请求就被拒绝或丢弃。

它的核心特点是输出平滑。无论入口流量多么突发，漏桶都会按固定速率向下游放行，因此适合保护下游系统，避免瞬时流量冲击。例如日志写入、消息发送、第三方 API 调用、固定吞吐的后端服务。

漏桶和令牌桶的区别在于突发能力。令牌桶允许桶中积累令牌，所以短时间内可以处理超过平均速率的突发请求；漏桶强调恒定速率流出，不鼓励突发。如果业务希望用户偶尔突发访问但长期受控，令牌桶更合适；如果业务希望请求严格平滑进入下游，漏桶更合适。

实现上可以用队列加定时消费，也可以用时间戳计算理论流出进度。队列实现直观但需要存请求，内存压力更大；时间计算实现更轻量，适合只判断是否允许通过的限流器。

点云、Mesh、体素、SDF、NeRF、3D Gaussian Splatting 如何表示 3D 人体/人脸？

点云：一组 3D 点：

\[ P=\{(x_i,y_i,z_i)\}_{i=1}^{N} \]

采集容易，但缺少拓扑连接。

Mesh：顶点、边、面组成的表面，适合渲染、动画和物理绑定，是传统数字人常用表示。

体素：三维规则网格，类似 3D 像素。简单但分辨率高时内存大。

SDF：有符号距离函数：

\[ f(x,y,z)=d \]

表面为：

\[ f(x,y,z)=0 \]

适合隐式曲面和可微优化。

NeRF：学习从 3D 坐标和视角到密度、颜色的函数：

\[ F_\theta(x,d)=(\sigma,c) \]

优点是新视角合成质量高，缺点是传统 NeRF 渲染慢、动画控制难。

3D Gaussian Splatting：用大量带颜色、透明度、协方差的 3D 高斯表示场景，渲染速度快，适合实时新视角合成。数字人中可用于头部 avatar、动态场景、实时渲染。

特征值、特征向量的几何意义是什么？

若方阵 \(A\) 存在非零向量 \(v\) 和标量 \(\lambda\)，满足：

\[ Av = \lambda v \]

则 \(v\) 是 \(A\) 的特征向量，\(\lambda\) 是对应特征值。

几何意义：矩阵 \(A\) 对向量 \(v\) 做线性变换后，\(v\) 的方向不变，只被缩放了 \(\lambda\) 倍。特征值大小表示该方向被拉伸或压缩的程度。

若 \(A\) 可对角化：

\[ A = Q\Lambda Q^{-1} \]

其中 \(Q\) 的列是特征向量，\(\Lambda\) 是特征值构成的对角矩阵。

机器学习直觉：

  • 大特征值方向通常解释数据变化最大的方向。
  • PCA 就是寻找协方差矩阵最大特征值对应的方向。
  • Hessian 的特征值刻画 loss landscape 的曲率，特征值越大，对该方向参数扰动越敏感。

特征穿越是什么，你怎么防？

回答：

特征穿越是在训练或评估中使用了预测时不可能获得的信息。例如预测用户是否点击时使用点击后的停留时长，预测笔记曝光价值时使用曝光后累计收藏，或者用今天修正过的画像回填昨天的样本。结果是离线成绩很好，线上无法复现。

正确性至少要约束两个时间：事件何时发生，以及特征何时真正可用。对请求时刻 t，合法特征通常应满足：

t_{\mathrm{event}}\le t,\qquad t_{\mathrm{available}}\le t

某个行为发生在 10:00，但 10:10 才写入在线特征，不能把它用于重建 10:05 的请求。聚合窗口要相对样本时间向前截取，处理同时间事件顺序、迟到数据、时区和回填版本；标签可以使用未来观察窗口，特征不能跟着用未来信息。

训练集构建应使用 point-in-time join、带版本的历史快照或真实请求特征日志。Feast 当前文档也区分事件时间和创建时间过滤：仅按事件时间回看，未必排除后续回填修正；使用相应过滤选项前，还要确认存储支持，以及创建时间确实表示线上可用时间。工具名称不能替代数据语义审计。

目标编码、归一化统计量、词表和负采样也可能泄漏。先划分训练与验证，再在训练部分拟合统计；有监督的目标编码需要折外或严格时间处理。建立自动检查：特征时间不得晚于请求、同实体历史不可越界，并抽样重放真实线上请求验证。

独立性和条件独立性有什么区别？

若：

\[ P(X,Y)=P(X)P(Y) \]

则 \(X\) 和 \(Y\) 独立。

若给定 \(Z\) 后：

\[ P(X,Y|Z)=P(X|Z)P(Y|Z) \]

则 \(X\) 和 \(Y\) 在 \(Z\) 条件下条件独立，记作：

\[ X \perp Y | Z \]

注意：

  • 独立不一定推出条件独立。
  • 条件独立也不一定推出无条件独立。
  • 朴素贝叶斯假设“给定类别后各特征条件独立”，实际不完全成立，但常能得到可用效果。

现代 OCR 系统与传统 OCR 流程有什么变化？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

传统 OCR 主要关注“检测文字区域 + 识别文字内容”，现代 OCR 更接近文档智能系统，目标从“读出文字”扩展为“理解文档、抽取结构、支撑决策”。

现代 OCR 系统通常包括：

图像/PDF/截图输入
  -> 图像预处理与方向分类
  -> 文本检测
  -> 文本识别
  -> 版面分析
  -> 表格/公式/印章/复选框识别
  -> 关键信息抽取
  -> 结构化输出
  -> RAG/Agent/业务系统调用

变化主要体现在四点：

  • 从文字识别到文档理解：不仅识别文本，还要理解标题、段落、表格、票据字段和阅读顺序；
  • 从单模型到多模块系统：检测、识别、版面、表格、KIE、纠错、RAG 共同工作；
  • 从封闭场景到开放场景：截图、网页、合同、论文、票据、手写、公式、多语种混合都可能出现；
  • 从离线识别到 Agent 工具：OCR 成为 GUI Agent、文档 Agent、企业知识库问答的基础感知能力。

用户使用系统时，先输入什么？整体流程是什么？

回答：

用户首先进入有权限的 Workspace，上传文件或选择已有文档，明确任务类型、输入对象和版本。文档尚未处理完成时，界面应显示解析中或处理失败，而不是让用户误以为已经能够分析。

点击执行后，后端重新校验权限和版本状态，生成 run_id，并保存不可变输入快照。任务进入队列，Worker 分阶段执行；前端通过轮询或事件推送展示进度和阶段结果，完成后提供差异、证据和报告入口。任务较长时应支持离开页面后继续查看，避免把执行生命周期绑定在一次 HTTP 连接上。

用户还应看到失败原因和可采取的动作，例如文件无法解析、版本不可访问、模型服务暂时不可用。重复点击需要通过幂等请求标识控制重复创建；用户选择变化后应创建新任务，不能悄悄改变正在执行任务的输入。

用户在问到一半，切换了模型，你们怎么处理？

回答：

首先定义产品语义：切换从下一轮生效，还是中断当前执行并立即迁移。默认在清晰的轮次或步骤边界切换更容易保证一致性；不能让同一次工具动作被两个模型同时驱动。

每个 run 固定 model_id、model_version、generation_epoch。用户要求立即切换时，先标记旧 run 的取消或迁移意图，停止后续模型请求，等待或确认在途工具状态，再保存 checkpoint。已经发生的外部写入不能通过取消 HTTP 请求撤销。

将任务目标、状态、已完成步骤、工具回执和可迁移的消息转换为统一表示，再由新模型适配器生成合法输入。检查工具角色、调用 ID、Schema、上下文预算、图像能力和供应商专有内容。供应商的加密或签名推理块不能当作通用文本随意搬运。

启动新代次后，旧模型迟到的 Token 或工具建议不得继续推进任务；前端用 run 与代次标识隔离输出。动作仍使用业务幂等键，记录迁移原因与配置。历史不足或协议不兼容时，应让用户确认重启范围，而不是声称能无损继续。

用户意图识别怎么做？规则匹配、LLM 判断和混合方案怎么选？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)

先定义意图集合、槽位和拒识条件，再选识别方法。规则适合明确命令、固定格式和高精度入口；LLM 适合表达多样、隐含意图及上下文依赖；混合方案通常先匹配高精度规则，再让模型处理长尾表达，最后用代码校验结构和业务约束。

输出宜包含 intent、slots、needs_clarification、evidence，不要让模型生成任意处理器名称。多意图请求应拆解或澄清；“帮我查一下预约”与“帮我预约”必须区分。模型自报的置信度未经校准，不能直接作为放行写操作的概率。

评测除总体准确率外，还看每类召回、混淆矩阵、未知意图拒识和高风险误路由率。漏掉一次查询与误提交一次订单的代价不同，阈值要按风险配置。真正的用户身份来自认证上下文，不从用户文本中提取后直接信任。

用户输入不完整的信息，系统如何校验、补全参数并继续执行？哪些参数必须用户确认？

回答：

先做语法校验，再做语义与权限校验。JSON 合法只说明格式正确，无法证明环境、资源、时间范围或操作目标正确。

把参数分为三类：可以按业务契约填充的低风险默认值；可以从当前会话或权威目录中检索的参数；必须由用户明确决定的高风险或多义参数。补全结果需记录取值依据，不能只依赖模型的“置信度”。

提取候选参数 → schema 校验 → 权限与资源查询
    → 缺失/冲突：集中澄清 → 保存检查点 → 合并回复后重新校验
    → 参数完备：构建计划 → 按操作风险确认 → 执行并验证

生产环境选择、不可逆操作对象、金额、范围扩大、目标无法唯一确定或有冲突的业务规则，通常需要明确确认。已经授权且可唯一确定的只读参数可以直接使用；确认次数不应替代判断。

进入等待状态时保存已验证参数、仍缺字段、计划版本和期限。用户回复后只更新对应字段，重新核验资源和授权是否仍有效，再从合法节点继续，避免从头重复执行已完成副作用。

质量指标包括参数错误率、澄清轮数、错误执行数与完成率，不能单纯追求更少追问。

用户输入相关资料后，最终会输出哪些结果？

回答：

输出应和任务目标一一对应。对于完整文档对比，核心产物是结构化差异项：变化类型、基准版本位置、目标版本位置、对应文本、变化解释，以及需要人工确认的状态。在此基础上生成可阅读的摘要和完整报告。

对于定向问答，输出是问题答案、支持答案的片段与定位信息，以及证据不足时的明确提示。系统还可展示解析完成度、未匹配章节和待复核项，帮助用户判断报告是否覆盖了预期内容，而不是只给一段看似完整的自然语言结论。

必须区分用户结果与内部产物。切块记录、向量、模型原始响应和调试日志通常不直接展示；任务版本、证据引用和处理状态则有实际使用价值。不同结果采用稳定的数据结构，避免前端依赖模型随意生成的排版。

相比 STSB，MTEB 有哪些改进？其中包括哪些类别的嵌入任务？

相比 STSB，MTEB（Massive Text Embedding Benchmark）改进在于：

  1. 任务更多样：覆盖更广泛的嵌入任务类型，不仅限于语义相似度。
  2. 数据规模更大：包含更多数据集，评测更全面。
  3. 细分任务类别：支持检索、分类、聚类等多种应用场景。
  4. 统一评测框架：便于多模型、多任务的系统比较。

MTEB涵盖的嵌入任务类别主要包括：

  • 语义文本相似度（STS）
  • 文本检索（Information Retrieval）
  • 文本分类（Classification）
  • 聚类（Clustering）
  • 召回（Ranking）
  • 句子对判别（Sentence Pair Tasks）
  • 其他多模态或跨语言任务

离散 token 统一自回归路线的基本思想是什么，工程上有哪些难题？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

离散 token 统一自回归路线把语言模型的做法推广到其他模态：既然 next-token prediction 足以刻画语言，就把图像和音频也离散化为 token，用同一个目标函数统一建模。这条路线在工程上的难题集中在三方面，即统一 softmax 带来的训练不稳定、模态混合调度和量化造成的信息损失。

视觉编码器先输出连续特征 $\mathbf{z}_e\in\mathbb{R}^{d}$，再对码本 $\{e_k\}_{k=1}^{K}$ 做最近邻量化：

\[ k^*=\arg\min_k\|\mathbf{z}_e-e_k\|_2,\quad \mathbf{z}_q=e_{k^*} \]

其中 $K$ 为码本大小，$e_k$ 为第 $k$ 个码字，$k^*$ 即视觉 token。Chameleon（2024）的图像分词器把一张 $512\times 512$ 的图像编码为 1024 个编号（对应 $32\times 32$ 的特征图），码本大小 $K=8192$，这些编号并入规模为 65536 的 BPE 统一词表；7B 和 34B 两个规模的单一 Transformer 从零开始训练，理解和生成共用 $\mathcal{L}_{\mathrm{NTP}}$[7]。视觉分词器（Visual Tokenizer）通常另设重建项 $\|\mathbf{z}_e-\mathbf{z}_q\|_2^2$，码本用指数滑动平均或 straight-through 估计更新[26]，惯例是先训练好分词器，再训练 Transformer，细节见 5.2.11.2。GenEval 是文生图的组合指令评测，总分在 0 到 1 之间。

智源 Emu3 只用 next-token prediction 训练，模型共 8.49B 参数，技术报告于 2024 年发布，2026 年 1 月 28 日以论文形式发表于 Nature[27,28]。Emu3 在原始提示词下的 GenEval 为 0.54，SDXL 为 0.55，使用 GPT-4V 改写提示词后 Emu3 达到 0.66[27]。这组数字说明纯 next-token prediction 的生成质量与当时的 SDXL 相当，并未全面超过扩散模型。

词表和损失统一之后，语言模型的三类基础设施可以直接沿用：

  1. 训练配方。 数据课程、学习率退火、监督微调和强化学习对齐都不必为视觉单独设计。

  2. 推理栈。 KV cache、投机解码和量化部署都可以复用，视觉生成不需要单独维护一套扩散服务。

  3. 跨模态上下文。 理解与生成处在同一条序列中，按前一张图的风格继续生成这类依赖可以写进同一个似然。

工程上反复出现的难题有三类：

  1. 统一 softmax 下的模态竞争。 Chameleon 论文 §2.3 报告，标准 LLaMA 架构在训练中后期因范数缓慢增长而出现复杂的发散[7]。作者把原因归结为多个熵差异显著的模态共享全部权重：每个模态都会通过略微增大范数与其他模态竞争，softmax 的平移不变性（$\mathrm{softmax}(z)=\mathrm{softmax}(z+c)$）使这种增长不受约束，训练初期影响不大，一旦超出 bf16 的有效表示范围就会发散；去掉图像生成的消融实验没有发散[7]。Chameleon 的稳定化措施后来成为这条路线的常用配置。QK-Norm（Query-Key Normalization）在注意力内部对 query 和 key 做层归一化，直接控制注意力 softmax 输入的范数[7,29]，不加 QK-Norm 的 Chameleon-7B 在约 20% 个训练 epoch 后发散。QK-Norm 不能解决输出层 softmax 的 logit 漂移，Chameleon 因此沿用 PaLM 的 z-loss，对配分函数加正则[7,30]：
\[ \mathcal{L}_z=\lambda\bigl(\log\sum_i e^{z_i}\bigr)^2,\qquad \lambda=10^{-5} \]

其中 $z_i$ 为输出层第 $i$ 个词的 logit，$\sum_i e^{z_i}$ 即配分函数 $Z$，系数 $\lambda=10^{-5}$ 取自 Chameleon 论文。Chameleon-34B 还需要按 Swin Transformer 的方式调整块内归一化的位置，以限制前馈层输出范数的增长[7]。

  1. 模态混合调度。 某一模态在局部训练窗口内占比过高时，模型会学到对另一模态缺乏响应的先验，混合比例和采样课程因此需要单独设计，见 5.5.3.1。

  2. 离散化带来的信息损失。 向量量化必然损失细节，Chameleon 论文也承认其分词器难以重建含大量文字的图像，这限制了模型在 OCR 类任务上的上限[7]。LongCat-Next（2026）的结果说明，离散路线的感知上限主要取决于分词器质量：它的 dNaViT 视觉分词器能在最高约 28 倍压缩率下对任意分辨率的图像做编码和解码，文本、视觉和音频共享参数、注意力和损失，论文把这套框架称为 DiNA（Discrete Native Autoregressive，离散原生自回归）[8]。在论文的对比表中，LongCat-Next 的 OmniDocBench 英文和中文得分为 0.152 和 0.226（越低越好），优于同表的 Qwen3-Omni-A3B 和 Qwen3-VL-A3B；MMStar 为 69.3，低于 Qwen3-VL-A3B 的 72.1[8]。离散模型在文档理解上可以超过同规模的连续模型，在通用视觉问答上并没有全面超过。离散统一自回归与两处稳定化如图 5-4 所示。

端到端OCR识别中主要难点是什么？

端到端OCR识别的难点在于怎么处理不定长序列对齐的问题。OCR可建模为时序依赖的文本图像问题， 然后使用 CTC（Connectionist Temporal Classification, CTC）的损失函数来对CNN和RNN进行端到端的联合训练。

CTC是一种损失函数，它允许模型在训练期间不需要显式地对齐输入和输出序列，从而优化序列对齐问题。 这意味着模型可以自动学习如何将输入序列（如图像中的像素）与输出序列（如识别出的文本）对应起来。

简述聚类算法的核心原理、主流实现方法，同时说明K-Means算法是否存在全局最优解

回答：

聚类是无监督学习，目标是在没有标签的情况下，把相似样本划到同一组，把差异大的样本分开。它本质是在定义“相似度”和“簇结构”：相似度可以是欧氏距离、余弦距离、密度可达性、概率分布相似性；簇结构可以是球状、层次、密度连通、图社区等。

主流方法可以分几类。第一类是划分式聚类，典型是 K-Means，通过最小化样本到所属簇中心的平方距离来迭代更新。第二类是层次聚类，自底向上或自顶向下构建树状结构，适合观察多粒度分组。第三类是密度聚类，如 DBSCAN/HDBSCAN，适合发现非球状簇和离群点。第四类是概率模型，如 GMM，用混合高斯和 EM 算法估计样本属于每个簇的概率。第五类是谱聚类或图聚类，把样本关系图转成图划分问题。

K-Means 的目标函数存在全局最优解，因为有限样本、有限 K 下所有划分的目标函数有最小值。但标准 Lloyd 迭代算法通常只能保证收敛到局部最优，不能保证找到全局最优。它对初始化、K 值、尺度、离群点和簇形状非常敏感。工程上常用 K-Means++ 初始化、多次重启、特征标准化、异常值处理、轮廓系数/肘部法选 K，以及在非球状数据上换用 DBSCAN、GMM 或谱聚类。

算法工程师该如何看待硬件侧知识？

GPU乃至硬件侧的整体逻辑，是CV算法工作中必不可少的组成部分，也是算法模型所依赖的重要物理载体。

GPU的相关知识

现在AI行业有个共识，认为是数据的爆发和算力的突破开启了深度学习在计算机视觉领域的“乘风破浪”，而其中的算力，主要就是指以GPU为首的计算平台。

GPU（Graphical Processing Unit）从最初用来进行图形处理和渲染（玩游戏），到通过CUDA/OpenCL库以及相应的工程开发之后，成为深度学习模型在学术界和工业界的底层计算工具，其有以下的一些特征：

  1. 异构计算：GPU能作为CPU的协处理器与CPU协同运算。
  2. 单指令流多数据流（SIMD）架构：使得同一个指令（比如对图像数据的一些操作），可以同时在多个像素点上并行计算，从而得到比较大的吞吐量，深度学习中大量的矩阵操作，让GPU成为一个非常适合的计算平台。
  3. 多计算核心。比如Nvidia的GTX980GPU中，在和i7-5960CPU差不多的芯片面积上，有其128倍的运算速度。GTX980中有16个流处理单元，每个流处理单元中包含着128个CUDA计算核心，共有2048个GPU运算单元，与此同时i7-5960CPU只有16个类似的计算单元。
  4. CUDA模块。作为GPU架构中的最小单元，它的设计和CPU有着非常类似的结构，其中包括了一个浮点运算单元，整型运算单元以及控制单元。一个流处理单元中的CUDA模块将执行同一个指令，但是会作用在不同的数据上。多CUDA模块意味着GPU有更加高的计算性能，但更重要的是在算法侧有没有高效地调度和使用。
  5. 计算核心频率。即时钟频率，代表每一秒内能进行同步脉冲次数。就核心频率而言，CPU要高于GPU。由于GPU采用了多核逻辑，即使提高一些频率，其实对于总体性能影响不会特别大。
  6. 内存架构。GPU的多层内存架构包括全局内存，2级缓存，和芯片上的存储（包括寄存器，和1级缓存共用的共享内存，只读/纹理缓存和常量缓存）。

在使用GPU时，在命令行输入nvidia-smi命令时会打印出一张表格，其中包含了GPU当时状态的所有参数信息。

CUDA/cuDNN/OpenCL科普小知识：

  1. CUDA是NVIDIA推出的用于GPU的并行计算框架。
  2. cuDNN是NVIDIA打造的针对深度神经网络的加速库，是一个用于深层神经网络的GPU加速库。
  3. OpenCL是由苹果（Apple）公司发起，业界众多著名厂商共同制作的面向异构系统通用目的并行编程的开放式、免费标准，也是一个统一的编程环境。

深度学习的端侧设备

深度学习的端侧设备，又可以叫做边缘计算设备，深度学习特别是CV领域中，模型+端侧设备的组合能够加快业务的即时计算，决策和反馈能力，极大释放AI可能性。

深度学习的端侧设备主要由ARM架构的CPU+ GPU/TPU/NPU等协处理器 + 整体功耗 + 外围接口 + 工具链等部分组成，也是算法侧对端侧设备进行选型要考虑的维度。

在实际业务中，根据公司的不同，算法工程师涉及到的硬件侧范围也会不一样。如果公司里硬件和算法由两个部门分别负责，那么算法工程师最多接触到的硬件侧知识就是硬件性能评估，模型转换与模型硬件侧验证，一些硬件高层API接口的开发与使用；如果公司里没有这么细分的部门，那么算法工程师可能就会接触到端侧的视频编解码，模型推理加速，Opencv，FFmpeg，Tensor RT，工具链开发等角度的知识。
