3）AI 幻觉产生的原因是什么？

回答：

幻觉的本质是生成模型根据训练分布和当前上下文计算下一个 token 的条件概率，而不是直接访问一个保证真实的事实数据库。模型可以生成语言上连贯、概率上合理，但事实并不存在的内容。

主要原因有四类：

  1. 知识边界。 训练数据缺失、过时、相互矛盾，或问题属于长尾事实，模型只能基于相似模式补全。
  2. 目标错位。 语言模型优化的是 token 似然，不是事实正确率；在信息不足时，流畅回答的概率可能高于明确说“不知道”。
  3. 上下文问题。 Prompt 歧义、上下文过长、检索召回错误、证据冲突、关键信息被截断或出现 lost in the middle，都会让模型引用错误依据。
  4. 系统与工具问题。 工具选择错误、参数错误、工具返回脏数据、解析失败、重试时状态重复，以及温度较高造成的采样波动，都会把系统错误表现成模型幻觉。

因此不能把所有幻觉都归结为“模型参数不够大”。要区分知识幻觉、引用幻觉、工具幻觉和执行幻觉，再分别通过检索与引用、工具校验、结构化输出、事实核验、置信度/拒答策略和端到端评测治理。

ArcFace 身份特征如何注入 GAN 换脸网络？

ArcFace 这类人脸识别模型可以提取源人脸身份 embedding：

\[ e_{\text{id}} = E_{\text{ArcFace}}(I_{\text{source}}) \]

注入方式常见有：

  1. AdaIN/Style Modulation

将身份 embedding 映射为通道级缩放和平移，调制生成器特征。

  1. Feature Concatenation

将身份向量扩展到空间维度，与目标特征拼接。

  1. Attention Injection

让目标特征通过注意力读取身份 token。

  1. Identity Adaptive Normalization

类似条件归一化，用身份控制生成过程。

训练时常用 identity loss：

\[ \mathcal{L}_{\text{id}} = 1 - \cos(E(I_{\text{out}}), E(I_{\text{source}})) \]

但身份注入不能过强，否则会破坏目标表情、姿态和光照，出现 copy-paste 或融合不自然。好的换脸系统需要平衡：

  • 源身份相似度。
  • 目标属性保持。
  • 局部融合自然度。
  • 视频时序稳定性。

ASR 的识别效果怎么评估？遇到专有名词、同音字和错别字时怎么处理？

回答：

中文 ASR 常用字符错误率 CER：

\[ \mathrm{CER}=\frac{S+D+I}{N} \]

其中 \(S\)、\(D\)、\(I\) 分别是替换、删除和插入数，\(N\) 是参考文本字符数。英文或已分词场景常用 WER。仅看整体 CER 不够，还应按噪声、口音、设备、远近场、会议人数和业务领域分桶，并单独统计专有名词召回率、数字/日期准确率、说话人归属准确率、标点质量和实时延迟。

专有名词首先在识别前处理：维护带版本和租户隔离的热词/术语表，为人名、产品名和缩写设置发音或权重，但要控制误激活。识别后可以把 ASR 的 N-best、词级置信度和上下文交给领域纠错模块，结合拼音相似度、编辑距离、术语词典和语言模型重排。会议邀请、参会人名单和议程属于高价值上下文，但必须有权限边界。

同音字不能只靠字符串替换，应利用句法语义、局部上下文和候选置信度；低置信度片段可以保留候选或提示人工校正。大模型适合生成候选纠错，但不能无约束改写原意，必须限制修改范围、记录前后版本，并用音频时间戳回查。

评测集要来自真实业务分布并保留困难样本，训练/调参数据与测试集去重。最终同时观察离线识别指标和下游指标，例如纪要事实支持率、行动项抽取 F1 与用户修改率，避免 CER 下降却破坏关键实体。

Benchmark 的主要局限是什么？

  • 数据污染：训练数据中可能包含测试题，导致分数虚高。
  • 刷榜问题：模型或提示策略专门针对 benchmark 优化。
  • 分布不一致：公开评测和真实业务输入差异很大。
  • 开放生成难以客观打分：同一个问题可能有多个好答案。
  • Prompt 敏感：提示模板、选项顺序、解码参数会明显影响结果。
  • 语言和领域覆盖不足：中文、低资源语言、垂直行业测试不足。
  • 高分不等于体验好：榜单分数无法完整反映安全、成本、稳定性和业务价值。

Copy-Paste 现象如何评估和缓解？

Copy-Paste 指生成结果过度复刻参考图，而没有根据目标 prompt、姿态或场景产生合理变化。

旧笔记中提到 WithAnyone 的 Copy-Paste 度量思想：比较生成图 \(g\) 与目标真实图 \(t\)、参考图 \(r\) 的角距离：

\[ \mathcal{M}_{CP}(g|t,r)=\frac{\theta_{gt}-\theta_{gr}}{\max(\theta_{tr},\epsilon)} \]

若生成图更接近参考图而不是目标变化，说明复制倾向强。

缓解方法：

  • 使用同 ID 多姿态、多表情数据。
  • 使用 cross-paired 数据，避免输入输出来自同一图。
  • 对参考图做增强，削弱非身份细节。
  • 对 ID 和姿态/表情做解耦。
  • 训练中加入文本可控性和目标变化损失。

OCR领域常用的评估指标是什么？

OCR任务通常分为两个阶段，检测和识别：

  • 检测阶段：先按照检测框和标注框的IOU评估，IOU大于某个阈值判断为检测准确。这里检测框和标注框不同于一般的通用目标检测框，是采用多边形进行表示。 检测准确率：正确的检测框个数在全部检测框的占比，主要是判断检测指标。检测召回率：正确的检测框个数在全部标注框的占比，主要是判断漏检的指标。
  • 识别阶段： 字符识别准确率，即正确识别的文本行占标注的文本行数量的比例，只有整行文本识别对才算正确识别。

Q-Former 注入和 ReferenceNet 注入有什么区别？

Q-Former 注入：

引入一组可学习 query，从身份/视觉特征中读出少量 token：

\[ Z_q = \text{CrossAttn}(Q_{\text{learn}},K_{\text{id}},V_{\text{id}}) \]

优点是 token 化后易接入 Transformer/DiT，适合跨模态对齐；缺点是空间细节可能压缩丢失。

ReferenceNet 注入：

直接从参考图提取多尺度空间特征：

\[ F_{\text{ref}}^{(l)} = R^{(l)}(I_{\text{ref}}) \]

并在去噪网络对应层注入。优点是保留纹理和局部细节；缺点是更容易 copy-paste，也更占显存。

选择建议：

  • 需要灵活文本编辑和轻量接入：Q-Former/ID token 更合适。
  • 需要高保真局部细节：ReferenceNet/feature map 更合适。
  • 高质量系统常混合使用：全局 ID token + 局部 face reference feature。

一面：如何解决大模型幻觉？

回答：

大模型幻觉本质上是模型在缺少可靠依据、上下文冲突、训练分布外问题或解码不确定时，仍然生成看似合理但事实错误的内容。治理幻觉不能只靠单一手段，要分层处理。

第一层是输入和输出约束。要明确模型的回答边界，例如要求只基于给定资料回答、不知道就拒答、引用证据段落、输出置信度或不确定原因。结构化任务可以用 JSON Schema、枚举值、正则约束或函数调用限制输出空间。

第二层是知识增强。对于企业知识、实时数据、私有文档这类模型参数中没有或可能过期的信息，应通过 RAG、数据库查询、搜索 API、业务系统工具调用来获取外部证据。RAG 的关键不只是召回文档，而是保证召回内容相关、完整、可追溯，并在生成阶段要求模型基于证据回答。

第三层是工具校验。对于可验证问题，不应让模型凭概率生成结果。例如订单状态、库存、账户余额、SQL 查询、数学计算、代码测试，都应调用确定性工具或业务接口，再由模型解释结果。Agent 系统里常见做法是把生成、执行和验证拆开，用工具执行、规则校验、单元测试、权限校验兜底。

第四层是训练和对齐。微调可以让模型适应领域表达、固定输出格式、学习拒答边界和业务流程，但不适合作为事实知识的唯一来源。知识会更新，微调也可能把错误样本固化进模型。更稳妥的做法是用 SFT 训练规范回答方式，用偏好优化训练拒答和引用习惯，再配合 RAG 与工具使用。

第五层是评估与线上治理。要建立 hallucination case 集，评估事实一致性、引用命中率、拒答准确率、工具调用成功率和人工标注通过率。线上还要做日志追踪、badcase 回流、敏感场景人工审核、灰度发布和回滚机制。

总结来说，幻觉治理是“证据增强 + 工具验证 + 输出约束 + 拒答机制 + 评估闭环”。RAG 解决知识来源问题，微调解决行为习惯问题，工具调用解决可验证执行问题，三者要组合使用。

下游落地中的幻觉问题如何系统性治理？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

多模态落地中的幻觉需要先区分类型，再按输入、解码和系统三层治理，如图 6-3 所示。多模态场景中常见的幻觉有三类：

  1. 对象幻觉。 模型描述图中不存在的物体。POPE（Polling-based Object Probing Evaluation）用「图中是否有 X」这类是非题专门评测对象幻觉[4]。

  2. 细粒度抄写幻觉。 在 OCR 场景中，模型把模糊的数字、日期补全成通顺但错误的值，金融票据中这类错误会直接进入账目。

  3. 定位幻觉。 文字答案正确，但给出的边界框或页码错误，点击溯源类功能因此失效。

治理同样分为三层：

  1. 输入。 分辨率不足是抄写幻觉的首要诱因。动态分块见 5.2.4.2，token 预算要按业务中最小的字号来预留，压缩方法见 5.4.2.1。

  2. 解码。 JSON Schema 约束解码只保证结构合法。系统还应要求模型同时给出证据位置（边界框或页码），核对时只需查看一处，不必重读整页。

  3. 系统。 金额、身份证号等关键字段用专用 OCR 或规则再校验一遍，两条通道结果不一致时转人工。低置信输出可以拒答，前提是置信度本身可信。期望校准误差（Expected Calibration Error，ECE）把样本按置信度分桶，逐桶比较平均置信度与实际准确率[5]：

\[ \mathrm{ECE}=\sum_{b=1}^{B}\frac{|S_b|}{N}\,\Bigl|\,\mathrm{acc}(S_b)-\mathrm{conf}(S_b)\,\Bigr| \]

其中 $B$ 为桶数，$S_b$ 为第 $b$ 个桶的样本集合，$N$ 为样本总数。ECE 越大说明模型越过度自信，此时应先做温度缩放一类的校准[5]，再按阈值分流。医疗报告和资金结算类应用不能让模型直接输出结果而不经校验。

图 6-3 幻觉治理三层示意图

面试速答：多模态幻觉分三类：对象幻觉可用 POPE 的是非题评测，抄写幻觉会改错数字，定位幻觉会给错边界框或页码。治理上，输入侧保证分辨率，解码侧约束格式并要求给出证据位置，系统侧对关键字段二次校验。按置信度拒答之前，要先用 ECE 检查校准。

为了尽可能防止提示词注入，如何设计提示词模板？如何在系统层面检测提示词注入攻击？

  1. 提示词模板设计防护：
  • 明确角色设定：在 prompt 中指定模型身份和行为范围，如“你是一个只能回答财经问题的助手”。
  • 使用指令封闭结构：避免开放式提示，使用模板化结构如 "指令: {instruction} \n 输入: {input} \n 输出: "。
  • 控制用户插入点：将用户输入限制在变量 slot 中，避免影响系统指令。

  • 系统层面注入检测：

  • 关键词黑名单匹配：检测如“忽略之前的指令”“你现在是…”等注入特征。

  • 提示词审查机制：在提示词构造后进行语义分析，识别可能的角色切换、指令覆写。
  • 响应行为监控：监控输出是否越权，如输出系统不允许的内容，可触发告警或拒答。
  • 使用上下文分离机制：通过系统-用户分段处理，防止用户内容污染系统 prompt。

为什么不能只看流畅度？

大语言模型很擅长生成自然、顺滑、结构清楚的文本，但流畅并不等于正确。一个回答可能语言表达自然，却存在答非所问、事实错误、逻辑矛盾、遗漏关键信息、引用编造或对用户没有实际帮助等问题。

核心判断标准是：生成内容是否 自然、切题、准确、连贯、有用，并符合用户给出的约束和业务场景。

为什么大语言模型必须被系统评估？

大语言模型通常具备开放生成、多任务泛化和工具调用能力，输出空间远比传统分类模型更大，因此训练 loss、reward score 或单一 benchmark 分数都不足以说明真实可用性。判断它在目标场景中是否 有用、可靠、安全、稳定、可部署。

为什么自我一致性能提升可靠性？

单次生成可能因为采样路径、局部错误、早期假设错误而走偏。多次采样可以暴露不稳定性。如果多个独立路径收敛到同一结论，说明该结论在模型分布中更稳健。对于数学推理、逻辑推理、多跳问答和代码生成，自我一致性常能提升正确率。

注：自我一致性不是严格证明。若模型对某类问题存在系统性误解，多次采样可能一致地错。

什么是 Needle In A Haystack？

Needle In A Haystack 是一种长上下文测试方法：在很长的文本中插入一条关键信息，然后要求模型找出这条信息。它用于测试模型是否真的能利用长上下文，而不是只看开头、结尾或局部片段。评估时通常会改变：文档总长度；needle 插入位置；needle 的表述形式；干扰信息数量；问题是否需要简单检索或进一步推理。

什么是“幻觉”（Hallucination）？

大语言模型的 幻觉（Hallucination） 是指输出虽然语言流畅，却与给定资料不一致，与可验证事实冲突，或缺乏足够证据支持。Huang et al., 2023

可以从两个角度理解：

  • 上下文不忠实：回答与输入资料、对话历史或工具结果矛盾。例：资料写公司成立于 2019 年，模型却回答 2016 年。

  • 事实不准确或无依据：回答与外部事实冲突，或编造论文、条款、事件和数据。

什么是多维评估矩阵？

多维评估矩阵是指围绕模型定位，把能力、风险、成本和业务效果拆成互相独立的评估维度，避免一个分数掩盖关键短板。常见维度包括：

  • 基础能力：语言理解、文本生成、知识问答、推理、数学、代码。
  • 交互能力：指令遵循、多轮对话、结构化输出、函数调用、工具使用。
  • 长上下文能力：长文档理解、信息定位、跨段落整合、长对话一致性。
  • 事实与可靠性：事实准确性、幻觉率、引用准确性、不确定性表达。
  • 安全与合规：有害性、越狱、偏见、隐私泄露、版权和行业合规。
  • 工程性能：延迟、吞吐、显存、并发、可用性、推理成本。
  • 业务效果：任务完成率、问题解决率、转人工率、用户满意度、人工节省。

什么是拒答边界？

拒答边界是模型区分“应该回答”和“不应该回答”的能力。安全模型既要拒绝危险、违法、越权、隐私泄露等请求，也要避免对正常教育、科普、合规咨询和安全防御问题过度拒答。边界样本还要关注不确定性校准：模型应能在信息不足或政策边界不清时澄清、限界回答或安全转化，而不是自信误答。

几何一致性、物理合理性与因果连续性分别约束什么？如何评估？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐ (3/5)

三者约束的对象不同：几何一致性关注空间结构如何随视角和时间变化，物理合理性关注运动与交互是否符合任务设定下的规律，因果连续性关注事件先后和状态转移是否成立。一个视频可能只违反其中一项。

图1-9 同一初始场景下的几何、物理与因果约束及典型失败

几何一致性看空间结构。 人物转头、相机移动或物体旋转时，形状、尺度、深度顺序、透视和遮挡关系应合理。常见错误是肢体结构突变、物体忽大忽小，或相机移动后前后景关系反转。

物理合理性看动力学与交互。 需要检查接触、支撑、碰撞、重力、惯性和材质响应。例如杯子不能穿过桌面，球与墙碰撞后也不应毫无条件地悬停。若任务本身是动画或超现实设定，应按照提示中建立的世界规则评估，不能一律套用真实世界物理。

因果连续性看事件和状态依赖。 玻璃破碎应由碰撞等事件触发，门打开后人物才能穿过，后续状态要能从前序事件中解释。这里评价的是输出中的因果顺序，不能仅凭一段生成视频证明模型内部学到了可干预的因果模型。

评估时先隔离变量，再选择观测量。

几何问题可以跟踪关键点、目标尺度、深度顺序和相机轨迹；物理问题应按碰撞、流体、刚体或材质等现象分别设计初始状态，并检查轨迹、接触和结果状态；因果连续性可以先标注事件边界和状态机，再判断触发条件、先后顺序和结果是否成立。只有在参数和场景可控时，才适合与物理引擎或解析规律直接比较。

自动指标或视觉语言模型适合做大规模初筛，但可能受画面质量和提示措辞影响。关键样本仍需人评，并报告不同物理现象和失败类型的分项结果。视觉真实感高，只能说明输出更像真实视频，不能单独证明几何、物理或因果正确。

面试速答：几何一致性检查形状、尺度、深度和遮挡关系；物理合理性检查运动、接触和材质响应；因果连续性检查事件触发、先后顺序和状态转移。评估应使用可控场景和分项观测量，并区分“视频看起来真实”与“模型真正掌握世界规律”。

功能测试与实际AI效果评估有什么区别？

回答：

功能测试验证系统是否按照约定执行，例如文件上传成功、任务状态转换合法、版本选择生效、撤权后不可访问、失败可以重试。这类断言通常比较确定，主要检查接口契约和业务不变量。

AI 效果评估验证结果是否有用且正确，例如是否遗漏一条赔付条件变化、是否误读表格数值、回答是否得到证据支持。接口返回成功、JSON 格式正确、引用链接能打开，都不能单独证明答案正确。

两者应共同作为发布门槛：先通过功能和权限测试，再在固定评测集上验证任务质量、成本和延迟。还要关注交叉故障，例如程序功能正常但解析为空，或者模型回答正确却使用了无权访问的文档；前者属于效果与数据问题，后者是严重的授权问题。

汇报结果时分别提供功能通过情况和效果指标，并给出失败样本。不要用“接口成功率”替代“业务任务正确率”，也不要让单次演示成功掩盖系统的不稳定性。

多轮对话中评测如何进行，转人工率如何评测？怎么进行的A/B测试？

回答：

多轮评测必须以完整会话为单位，单轮 BLEU、相似度或 Judge 分不能代表任务完成。离线评测集应覆盖主要意图、长尾、高风险、信息缺失、目标变化和工具异常，并固定用户模拟器/回放环境版本。核心指标包括：端到端任务成功率、约束遵循率、事实与工具状态一致性、平均轮数、重复询问率、恢复率、P95 延迟、Token/工具成本、用户满意度和安全违规率。

转人工率要先定义 eligible conversation 和 transfer event：

\[ \mathrm{TransferRate}= \frac{\text{发生人工接管的有效会话数}} {\text{具备自动服务资格的有效会话数}}. \]

但这个总指标不能单独优化。应区分必要转人工和可避免转人工：高风险、用户主动要求或系统能力边界内的正确转人工是好行为；Agent 误判、循环、工具失败造成的转人工才是损失。需要同时统计应转未转率、误转率、转人工前轮数、人工处理时长、人工一次解决率和转接时上下文完整率。

A/B 测试应按用户或会话稳定随机，避免同一用户跨组污染；提前定义主指标、guardrail、最小可检测效应、样本量和观察窗口。先做日志回放、影子流量和小比例灰度，再逐步放量。比较时控制渠道、用户类型、问题难度和时间效应，必要时采用分层随机或 CUPED 降低方差。实验期间监控合规、投诉、错误操作、延迟和人工队列容量，并设置自动回滚阈值。

不能只报告转人工率下降。如果下降来自 Agent 拒绝转人工、错误自信或延长对话，业务反而更差。真正的成功应表现为任务成功率提高、可避免转人工下降，同时必要转人工召回和安全指标不退化。

如何保证大流量下消息处理的鲁棒性？

回答：

先定义可靠性的范围：允许多长延迟、可容忍多少丢失、是否允许重复、消息保留多久，以及外部副作用能否幂等。大流量系统无法靠“不断重试”保证无限可靠。

生产端使用可靠确认、合理批量和幂等机制，并为业务状态与发消息设计 outbox 或事务消息。Broker 根据可用性要求设置复制、确认与保留策略，提前估算积压容量和磁盘水位。

消费者使用有界队列、受控并发和分区背压，必要时暂停拉取；按业务键串行保证有序，独立键并行。瞬时故障使用有限退避和抖动，永久错误进入隔离或死信流程；毒消息不能无限占用分区。死信仍需监控、修复和重放，不能把转入死信等同于业务成功。

消费确认与结果持久化协调，外部写入具备幂等性；处理崩溃、重平衡、超时和网络中断时都能恢复。持续监控 lag、最老消息年龄、处理成功率、重试率、重复副作用、线程池与连接池占用。故障注入应验证下游限流、Broker 重启、消费者退出、磁盘不足和突发流量。

如何实现高保真人脸身份注入？

高保真身份注入通常需要三类信息：

  1. 身份 embedding：ArcFace/InsightFace 提取身份向量。
  2. 结构条件：landmark、face parsing、depth、3DMM、head pose。
  3. 细节参考：局部纹理、肤色、发型、配饰等图像特征。

注入方式：

  • cross attention 中注入 ID token。
  • 在 key/value 中加入 ID adapter。
  • 使用面部 mask 让 ID 条件只影响脸部区域。
  • 在多尺度 U-Net/DiT 层中注入 face feature。
  • 使用 ID loss、perceptual loss、face region loss 训练。

关键平衡：

ID 注入太弱会不像本人；太强会 copy-paste，导致姿态、表情和风格可编辑性下降。

如何控制模型的幻觉问题？

回答：

幻觉不能靠一个 Prompt 或调低温度解决，需要从“是否该回答、证据是否可靠、输出是否被验证”三层控制。

第一层是任务边界。对必须基于企业知识回答的问题，先判断是否有足够证据；检索分数低、证据冲突或超出权限时应该澄清、拒答或转人工。第二层是证据链。提升解析、切片、混合召回和 rerank 质量，去除过期/重复文档，并把最终使用的证据和来源 ID 明确提供给模型。

第三层是受约束生成和验证。要求答案中的关键事实能够映射到证据片段；对数字、实体、引用和工具执行结果使用规则或独立验证器核对；涉及写操作时采用“计划 -> 预览 -> 审批 -> 执行 -> 回读验证”，不能让模型直接宣称操作成功。

温度降低只能减少采样随机性，不能修复参数知识错误或错误证据；显式 Chain-of-Thought 也不等于事实验证，并可能产生貌似合理的错误解释。更稳的是输出简洁结论、引用和不确定性，再由验证器检查。类似“如果不知道就说不知道”的指令有帮助，但必须用评测集验证，不能脱离实验声称固定降幅。

评测至少包含有答案、无答案、证据冲突、诱导提问和越权查询。指标可看 groundedness/faithfulness、引用准确率、无答案拒答率、误拒答率和任务级事实错误率。Rocky认为，幻觉治理的本质不是让模型“更谨慎地说”，而是让系统只在证据和权限允许时行动。

如何避免评测集污染（benchmark contamination）？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

Benchmark contamination 指训练数据中包含评测题、答案、解析或高度相似内容，导致模型依靠记忆而不是泛化能力答题，从而让评测分数虚高。它在数学、代码、考试题、知识问答等任务中尤其常见，因为公开题库经常被博客、论坛、GitHub 和教程转载。

收集公开 benchmark → 建立题目/答案/解析指纹库 → 对训练数据做精确匹配、n元语法（n-gram）、最小哈希（MinHash）、相似哈希（SimHash） 或 嵌入向量检测 → 删除或降权高度相似样本 → 使用私有测试集和动态评测复核
方法 作用 适用场景
Exact Match 检测完全重复题目或答案 原题、标准答案
n-gram overlap 检测连续片段重叠 数学题、考试题、代码题
MinHash / SimHash 检测大规模近似重复 网页、文档级污染
嵌入向量相似度 检测语义改写和同义题 高价值 benchmark
时间切分 避免训练数据包含评测发布后的题解 新题、动态评测

注：第一，不能只检测题目，也要检测答案和解析；第二，不能只做精确匹配，因为很多污染来自翻译、改写和题解；第三，发布级评估不能只依赖公开 benchmark，还要保留私有测试集、动态评测集和时间后验数据。

如果评测集上的准确率很高，但线上效果很差，你会怎样排查？

回答：

先对齐测量对象：离线评测的是最终任务还是单步模型，线上“差”表现为答错、拒答、超时、越权还是成本过高。离线把工具结果直接喂给模型，线上却要求自己检索和调用工具，两者即使都叫准确率，也不具可比性。

第一步做同请求回放，固定模型、Prompt、路由、工具版本、预处理和检索快照，比较离线与线上轨迹。这样可以区分模型本身、部署差异和外部依赖。重点检查图片缩放与 EXIF 方向、token 截断、量化、解码参数、超时预算、缓存键、工具数据时效与后处理。

第二步检查数据分布：线上是否多了低分辨率、长指令、罕见类别、多轮修改、恶意输入或边界请求。评测集是否来自容易样本，是否存在模板重复、答案泄漏、人工纠正后才评测，是否忽略超时和拒绝样本。拒答比例变化时，单看“已回答样本准确率”可能误判。

第三步建立有权重的线上抽样集、固定保留集与困难回归集。按用户、文档或时间分组切分，避免同源样本泄漏。人工标签要保留分歧和标注规范；训练回流集与最终验收集分开，不能不断用测试失败样本训练，再宣称原测试集提升证明泛化。

最后做消融与灰度，分别替换检索、模型、工具和路由，定位收益来源。对于新策略，还要观察被旧策略拒绝的请求，否则选择偏差会掩盖真实质量。报告任务成功率、覆盖率、分组表现、成本和尾延迟，必要时先回滚。上线效果差首先是可观测性和评测契约问题，不能直接归结为“模型不够大”。

幻觉产生的主要原因有哪些？

幻觉通常由训练数据、生成机制、上下文和应用系统共同造成：

  • 训练数据有限：数据可能错误、过时、互相矛盾，或对长尾和专业领域覆盖不足。

  • 训练目标不直接验证事实：下一词元预测优化的是语言概率，不是逐条核验事实。

  • 参数化知识难以溯源：知识分布在模型参数中，缺少显式出处，也不便频繁更新。

  • 不确定性校准不足：模型可能无法准确判断“自己是否知道”，在证据不足时仍继续生成。

  • 上下文利用失败：关键信息可能被截断、忽略或被噪声淹没。

  • 解码与提示影响：较高随机性、含糊问题或错误前提可能增加不稳定输出，但降低采样温度（temperature）也不能保证事实正确。

  • 对齐目标冲突：模型为了显得有帮助，可能在应当拒答或表达不确定时仍给出完整答案。

幻觉如何度量？

常见指标包括：

  • Hallucination Rate：含幻觉回答占比。
  • Claim-level Error Rate：原子事实声明中错误或无证据声明的比例。
  • Unsupported Claim Rate：无法从证据中支持的断言比例。
  • Faithfulness：答案是否忠实于给定上下文。
  • Factual Consistency：回答事实是否与权威来源一致。
  • Citation Accuracy：引用是否真实存在，是否支持回答内容。
  • Calibration / Refusal Accuracy：证据不足时是否能表达不确定、澄清或拒答。

幻觉的检测手段有哪些？

  • 证据核对：将回答与文档原文、数据库、计算结果或可信来源比较。

  • 引用检查：确认引用真实存在，并且确实支持对应结论。

  • 一致性检测：多次生成或使用不同模型比较。（答案一致也不能证明事实正确，因为模型可能产生相关性错误。）

  • 语义蕴含检测：检查回答是否被给定资料支持，是否存在矛盾。

  • 不确定性估计：使用对数概率（log probability，logprob）、校准模型或分类器识别高风险回答。

  • 人工审核：在医疗、法律、金融、政务等高风险场景中，仍需要专业人员进行最终确认。

幻觉的缓解策略有哪些？

  • 检索增强生成（RAG）：先检索资料，再要求模型基于证据回答。RAG 可以减少对参数记忆的依赖，但检索错误、上下文噪声和错误引用仍可能产生幻觉。

  • 要求基于证据回答：提示模型“只根据给定资料回答”，“找不到依据就说明无法确定”，降低无依据编造。

  • 引用与证据绑定：让结论对应具体来源、原文片段或证据编号。

  • 工具调用与实时检索：对实时信息、数据库查询、计算、代码执行等任务，让模型调用搜索、数据库、计算器、代码解释器等工具。

  • 控制解码随机性：事实问答可适当降低采样温度。

  • 训练与对齐优化：使用高质量事实数据、拒答数据和偏好数据，并结合 SFT、DPO 或 RLHF，改善事实性和不确定性表达。

  • 验证器和规则检查：使用计算器、代码测试、规则、事实核查模型或大模型裁判（Large Language Model as a Judge，LLM-as-a-Judge）复核。

  • 人机协同审核：对高风险输出设置人工审核、灰度发布和追责机制，避免模型直接自动决策。

幻觉评估标签应该如何设计？

常见做法是把模型回答拆成原子事实声明，再逐条标注。

标签可以包括：

  • Unsupported Claim：答案中有断言，但给定上下文或权威来源无法支持。
  • Contradicted Claim：答案与上下文、数据库或权威来源直接矛盾。
  • Fabricated Citation：引用、链接、论文、法规或出处不存在。
  • Citation Mismatch：引用存在，但不能支持对应结论。
  • Numeric / Date Error：数值、日期、比例、版本号等关键事实错误。
  • Context Inconsistency：回答与用户提供材料或对话历史不一致。
  • Overconfident Unknown：证据不足时仍自信作答，没有澄清、限界或拒答。

每个标签还应记录严重程度、证据来源和错误位置，区分轻微表述问题、局部事实错误和高风险错误。

当模型出现幻觉问题时，一般有哪些解决思路？

回答：

幻觉的本质是模型按条件概率生成合理 Token，而不是从一个自带真实性保证的数据库读取答案。治理前应先分类：知识事实幻觉、引用不忠实、工具调用幻觉、结构化输出错误和执行状态幻觉，不能用同一个 Prompt 处理。

完整方案通常分五层：

  • 知识层： 对私域或时效知识使用 RAG、搜索或权威业务 API，保留来源、版本和时间；证据不足时允许拒答。
  • 检索层： 做查询改写、混合召回、metadata/权限过滤、Rerank、去重和冲突检测。召回错误会把模型变成“忠实地回答错误证据”。
  • 生成层： 要求区分证据、推断和未知；逐项引用；结构化任务使用 schema 或 constrained decoding，降低自由生成空间。
  • 验证层： 将答案拆成原子事实，用规则、数据库、第二次检索、NLI 或独立 Judge 核验；高风险动作由确定性规则或人工批准。
  • 系统层： 工具白名单、参数校验、状态回读、最大步数、权限和审计，防止文本幻觉转化为真实副作用。

评测至少分开看 answer correctness、faithfulness、citation correctness/completeness、拒答准确率、工具选择与参数正确率。微调可以改善领域表达、格式和行为偏好，但不能自动赋予实时事实，也不能替代外部证据。真正可靠的系统不是强迫模型每次回答，而是有证据时回答、证据不足时明确不确定、执行动作前重新验证真实状态。

怎么评估才不容易误判？

相邻帧经过运动对齐后，可以比较像素或特征残差，但要排除遮挡和新显露区域。这类局部指标适合检查 flicker，无法判断人物是否在远处再次出现时保持身份，也无法判断动作语义是否正确。实际评估需要拆开主体一致性、背景一致性、运动平滑度、动态幅度和条件遵循，并结合分段播放与人工检查。

这里还有一个常见陷阱：静态视频很容易获得较高的相邻帧相似度，却可能完全没有完成要求的动作。因此，一致性指标必须和动态程度、动作或轨迹符合度一起看。

面试速答：时序一致性要求视频中该保持的状态稳定、该变化的内容合理演化。评估时应把主体、背景、运动、局部视觉属性和条件遵循拆开，并防止静态输出用“几乎不动”换取较高的一致性分数。

数据集的质量和多样性对MLLMs的幻觉现象有何影响？

数据集的质量和多样性对MLLMs的幻觉现象有显著影响：

  • 数据质量：低质量的数据集包含噪声、不准确的标注或不完整的图像，可能导致模型在训练过程中学习到错误的信息，从而在生成文本时产生幻觉。
  • 数据多样性：缺乏多样性的数据集可能导致模型在处理未见过的场景或对象时表现不佳，容易产生幻觉。例如，训练数据中缺乏否定指令或拒绝回答的样本，可能导致模型在面对否定问题时倾向于回答“是”。

模型输出效果评测是固定自动化benchmark还是依靠人工主观判断？

回答：

两者都需要，但作用不同。固定自动化 benchmark 解决一致性、回归和规模化评估；人工主观判断解决审美、平台风格和创意质量。

自动化 benchmark 可以设计成一组固定任务集，包括不同类型的视频需求、不同素材条件、不同风格要求和异常输入。指标包括结构化输出合法率、工具调用成功率、脚本覆盖率、事实一致性、违规内容率、平均延迟、成本、自动质量分等。每次 prompt、模型或工具链改动后跑一遍，防止回归。

人工评审则要有 rubric，而不是随便看。比如从创意吸引力、内容完整性、平台风格、镜头节奏、字幕可读性、商业可用性、违和感等维度打分。最好双人标注，计算一致性，沉淀高质量 badcase。

更成熟的做法是三层评测：自动规则做底线过滤，模型评审做规模化语义判断，人工评审做高价值样本和争议样本复核。线上再看真实指标，例如完播率、点击率、发布率、用户编辑次数。AI 内容生成的评测不是一个 benchmark 能解决的，而是离线评测、人工质检和线上反馈的闭环。

模态混合比例与注入时机如何影响模型能力？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

预训练阶段影响最大的可调因素之一是数据课程，即模态组成、混合比例和注入时机。混合比例在优化中对应梯度混合，每一步的有效更新可以写成：

\[ \Delta\theta \propto \alpha\,\nabla\mathcal{L}_{\mathrm{mm}}+(1-\alpha)\,\nabla\mathcal{L}_{\mathrm{text}} \]

其中 $\alpha$ 为多模态数据所占比例，$\mathcal{L}_{\mathrm{mm}}$ 和 $\mathcal{L}_{\mathrm{text}}$ 分别为多模态数据和纯文本数据上的损失。$\alpha$ 过大时文本方向的梯度被淹没，$\alpha$ 过小时视觉梯度稀疏，对齐难以充分完成。需要区分的是，下文的「早期」指注入时机，与 5.5.1.1 的早期融合结构无关。2025 至 2026 年有两组实验可以直接引用，其结论可归为四点：

  1. 从零训练的原生模型遵循与语言模型相近的缩放律。 Apple 的扫描显示，早期融合模型的损失随计算量下降的规律为 $L\propto C^{-0.049}$，与 GPT-3 的 $C^{-0.048}$ 接近[1]。计算最优的参数量 $N^*\propto C^{0.526}$，数据量的指数约为 0.473，两者都接近计算量的平方根，与 Chinchilla 的结论一致[1,35]。数据构成会改变最优分配：交错图文数据从更大的模型中获益更多，图文对（caption）数据则从更多训练 token 中获益更多[1]。论文没有给出固定的最优混合配方，不同混合比例下的缩放趋势相近，具体配比需要按数据形态重新拟合。

  2. 注入时机比后段集中注入更重要。 Kimi K2.5 在视觉与文本 token 总预算固定的条件下做了对照：从第一步起以 10%:90% 的视觉文本比例混合，效果优于先用纯文本训练 50% 的预算、再按 20%:80% 混合，也优于先用纯文本训练 80% 的预算、再按 50%:50% 混合[12]。论文同时发现视觉比例本身对最终多模态成绩的影响很小，较早注入且比例较低的方案效果更好；作者的解释是，从一开始联合优化可以避免后段领域迁移带来的冲击，文本能力曲线也更平稳[12]。本书认为，这与表征几何在训练早期即基本定型的观察一致：纯文本梯度先塑造表征空间，再引入视觉只能在已经固化的流形上做局部修正。

  3. 配套的监督微调可以几乎不用视觉样本。 Kimi K2.5 的 Zero-Vision SFT 只用纯文本监督数据激活视觉推理和工具使用，图像操作通过 IPython 中的程序代理完成，例如用二值化和计数估计物体大小[12]。论文报告，在这一阶段加入人工设计的视觉轨迹反而损害泛化，作者认为原因是联合预训练已经建立了较强的视觉文本对齐[12]。由此看来，多模态对齐主要在预训练阶段完成，后训练更多是调用已经对齐的能力。

  4. 混合专家的路由不按模态写死。 Apple 的扫描中，路由器取 $\mathrm{softmax}(W\mathbf{h})$，不把模态编号拼入 $\mathbf{h}$，这种不看模态标签的路由（modality-agnostic routing）稳定优于按模态指定专家的路由，模型在训练中会自行学出与模态相关的专家分工[1]。LongCat-Next 同样采用不看模态标签的混合专家，并观察到部分专家逐渐偏向视觉或音频等特定模态[8]；文心 5.0 的路由也只依据统一的 token 表示[9]。把模态先验写进路由器，等于预先固定了各模态可用的专家容量。

几组公开的课程可以作为工程参照，不应视为通用最优解。三组课程如下：

  1. InternVL3.5。 论文称为原生预训练的阶段约使用 250B token，纯文本与多模态数据之比约为 1:2.5，序列长度 32K[6]。

  2. Emu3.5。 两阶段合计约 13T token，第一阶段 10T token、最大序列长度 32768，第二阶段约 3T token，提高图像分辨率并改进数据质量[36]。模型从 Qwen3 初始化，采用离散 next-token prediction，按严格口径不属于从零训练[36]。

  3. 分辨率课程。 先用低分辨率学习对齐，再用高分辨率学习细节，Emu3.5 在第二阶段提高分辨率即属此类[36]；降低成本的动机与 5.4.10.1 的渐进式缩放相同。

目前评估MLLMs幻觉现象的基准有哪些？这些基准在评估不同类型幻觉时的侧重点是什么？

线上 A/B 能否替代离线评估？

不能。线上 A/B 只能在模型已经通过离线质量、安全和业务门槛后进行。对于医疗、法律、金融、政务、企业客服等场景，直接把未充分测试的模型放到线上，会放大安全、合规和声誉风险。正确做法是先用离线集和红队测试排除明显问题，再做小流量灰度，并设置人工接管、报警和回滚机制。

缓解MLLMs幻觉现象的方法有哪些？

缓解MLLMs中幻觉现象的方法可以从数据、模型、训练和推理四个方面入手：

  • 数据：引入负样本、反事实数据和减少现有数据集中的噪声和错误。例如，LRV-Instruction通过包含正负指令样本来增强视觉指令调优的鲁棒性。
  • 模型：提升视觉编码器的分辨率和多样性，引入专用模块来控制参数知识的程度。例如，HallE-Switch通过对比学习增强视觉和文本表示的对齐。
  • 训练：使用辅助监督信号、强化学习和无监督学习等方法。例如，MOCHa框架通过多目标奖励函数引导强化学习过程，减少幻觉。
  • 推理：采用对比解码、引导解码和后处理校正等方法。例如，VCD通过对比原始和失真视觉输入的输出分布来抑制统计偏差和语言先验。
