Qwen3-VL 如何处理视频的帧采样?请说明 sample_frames 方法的实现逻辑和 VideoMetadata 的作用？

Qwen3-VL 实现了灵活的视频帧采样策略,能够根据视频特性和计算资源动态调整采样方式,同时通过 VideoMetadata 精确管理视频的时间信息。

帧采样核心方法:

在 Qwen3VLVideoProcessor.sample_frames 中:

def sample_frames(
    self,
    metadata: VideoMetadata,
    num_frames: Optional[int] = None,
    fps: Optional[Union[int, float]] = None,
    **kwargs,
):
    """
    默认采样函数,在0到总帧数之间均匀采样指定数量的帧。
    如果传入fps,则按每秒fps帧的速率均匀采样。
    num_frames和fps参数互斥。
    """
    if fps is not None and num_frames is not None:
        raise ValueError("`num_frames` and `fps` are mutually exclusive arguments!")

    total_num_frames = metadata.total_num_frames
    fps = fps if fps is not None else self.fps  # 默认fps=2

    # 根据fps计算需要采样的帧数
    if num_frames is None and fps is not None:
        if metadata.fps is None:
            metadata.fps = 24  # 默认假设24fps
            logger.warning_once(
                "Asked to sample `fps` frames per second but no video metadata was provided. "
                "Defaulting to `fps=24`. Please provide `video_metadata` for more accurate results."
            )

        # 计算公式: 采样帧数 = 总帧数 / 原始fps * 目标fps
        num_frames = int(total_num_frames / metadata.fps * fps)

        # 限制在[min_frames, max_frames]范围内
        num_frames = min(max(num_frames, self.min_frames), self.max_frames, total_num_frames)

    if num_frames is None:
        num_frames = min(max(total_num_frames, self.min_frames), self.max_frames)

    # 均匀采样
    indices = np.linspace(0, total_num_frames - 1, num_frames).round().astype(int)

    return indices

采样策略分析:

  1. 均匀采样: 使用 np.linspace 确保采样帧在时间上均匀分布
  2. FPS自适应: 根据原始视频fps和目标fps动态调整采样数量
  3. 边界保护: 通过 min_frames 和 max_frames 控制计算量

VideoMetadata 数据结构:

@dataclass
class VideoMetadata:

元数据在时间戳计算中的应用:

在 Qwen3VLProcessor._calculate_timestamps 中使用元数据:

def _calculate_timestamps(self, indices: Union[list[int], np.ndarray], video_fps: float, merge_size: int = 2):
    if not isinstance(indices, list):
        indices = indices.tolist()

    # 确保帧数对齐
    if len(indices) % merge_size != 0:
        indices.extend(indices[-1] for _ in range(merge_size - len(indices) % merge_size))

    # 根据帧索引和fps计算时间戳
    timestamps = [idx / video_fps for idx in indices]

    # 时间patch内取平均
    timestamps = [
        (timestamps[i] + timestamps[i + merge_size - 1]) / 2 
        for i in range(0, len(timestamps), merge_size)
    ]
    return timestamps

Ref-SAV数据集的特点是什么？

Ref-SAV数据集是通过自动管道从SA-V数据集中生成的，旨在提升模型在复杂视频场景中的对象分割能力。该数据集的特点包括：

  • 复杂的遮挡情况。
  • 长文本输入。

Speculative Decoding 为什么可以无损加速？接受率公式如何理解？

Speculative Decoding 使用小模型 \(q\) 快速提出多个候选 token，再由大模型 \(p\) 验证。目标是在保持大模型采样分布不变的情况下减少大模型前向次数。

对候选 token \(x\)，接受概率为：

\[ a(x)=\min\left(1,\frac{p(x)}{q(x)}\right) \]

若接受，则保留小模型生成的 token；若拒绝，则从修正分布中重新采样：

\[ p'(x)=\frac{\max(0,p(x)-q(x))}{\sum_y\max(0,p(y)-q(y))} \]

这种接受-拒绝机制保证最终 token 分布仍等于目标大模型分布 \(p\)。

Step-Video-TI2V 如何从 T2V 基座扩展到文本驱动的 I2V？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐ (3/5)

TI2V 要让 30B 视频基座在训练中学会同时使用文本和图像条件，不能只在 T2V 推理时临时加入一张图。文本规定动作、镜头和事件，图像锚定起始主体、构图和外观；两种条件在后续帧中存在天然张力。

扩展 I2V 必须打通四个环节

这类扩展必须打通四个环节：图像编码成什么表示，表示在 DiT 的哪里注入，训练样本如何构造文本—图像—视频对应关系，以及条件强度如何在推理中平衡。只增加一个图像输入接口，不能证明模型真正利用了图像条件。

两类失败来自相反的条件失衡

最常见的两类失败恰好相反：图像约束过强时，视频接近静态图或只有相机抖动；文本与运动条件过强时，首帧之后主体和背景迅速漂移。排查时分别看首帧到第二帧的连续性、主体相似度随时间的曲线、运动幅度，以及调整图像/文本 guidance 后的变化。

公开能力有明确任务边界

还要明确任务边界：Step-Video-TI2V 的公开设定是文本驱动的图像到视频，不能笼统写成支持任意参考图、首尾帧或视频编辑。不同条件作用域需要不同训练信号。

Story-level Coherence 为什么比单个 shot 质量更难？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

Story-level Coherence 难在约束对象从“一个镜头”变成了“镜头之间的关系”。单个 shot 可以独立满足画质和文本条件，但不同 shot 若分别采样，模型不会天然知道哪些实体应保持、哪些状态已经改变，以及当前镜头在事件链中处于什么位置。

一致不等于所有镜头都相似

  • 实体连续：角色、关键物体和地点在再次出现时仍可识别，多主体之间不能交换属性。
  • 状态连续：服饰、持有关系、物体状态和人物情绪要继承已经发生的变化，而不是机械恢复到最初参考。
  • 事件连续：动作顺序、因果结果和叙事目标要与脚本一致，不能漏掉必要事件或重复已经完成的动作。
  • 镜头表达一致：色彩和视觉风格可以保持统一，但景别、构图和视角本来就应随叙事变化，不能把“相似度高”直接当作故事连贯。

从生成依赖看，第 \(i\) 个镜头除了读取本镜头计划 \(P_i\)，还需要读取前序镜头沉淀的状态 \(M_{<i}\)：

p(S_{1:K} \mid C) = \prod_{i=1}^{K} p(S_i \mid P_i, M_{<i}, C)

其中，\(C\) 是全局故事条件，\(P_i\) 是当前镜头计划，\(M_{<i}\) 是此前形成的实体、场景和事件状态。这个表达不是限定具体模型，而是说明独立的逐镜头条件不足以描述跨镜头依赖。

评估要使用跨镜头切片

把单镜头质量和跨镜头一致性分开评分，并专门设置角色离场后重现、物体状态改变、多主体交互和长间隔回调等样例。身份特征相似度只能覆盖其中一部分，还需要结合脚本或状态标注检查事件顺序和状态继承。

面试速答：单个 shot 质量评价局部画质、运动和条件遵循，Story-level Coherence 评价实体、状态和事件能否跨镜头正确延续。它并不要求所有镜头视觉相似，而是要求该保持的保持、该变化的变化；评估时要把局部质量与跨镜头关系分开。

Storyboard、Keyframe 和 Shot Video 分别承担什么角色？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

Script、Storyboard、Keyframe 和 Shot Video 描述的是从叙事约束到像素视频的逐级落地过程，但它们不是统一、强制的四级标准。Storyboard 本身可以包含关键画格，有些系统也会跳过独立的关键帧生成阶段；这里的 Shot Video 只是“单个镜头的视频结果”，不是一种独立的模型类别。

各层传递什么信息

  • Script：定义角色、事件、地点和前后因果，回答“故事发生什么”。
  • Storyboard：把故事拆成 shot list，确定每个镜头的内容、景别、构图、相机意图、时长和转场关系。
  • Keyframe：把文字计划变成高带宽视觉锚点，约束主体外观、空间布局以及关键动作状态；一个 shot 可以使用首帧、尾帧或多个中间锚点。
  • Shot Video：在镜头计划和视觉锚点约束下补全运动、时序细节和镜头内变化。

Subject Control 和 Structure Control 如何跨时间持续生效？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

Subject Control 主要回答“生成谁”，Structure Control 主要回答“每个时刻在哪里、呈现什么几何或姿态”。前者通常是全局或缓慢变化的身份约束，后者往往是与时间对齐的稠密或稀疏序列。

Subject 条件需要跨帧读取，也要允许姿态变化

参考图可以被编码为全局视觉 token，也可以通过 cross-attention 或多尺度特征注入生成主干。只在首帧建立身份，再依赖局部递推，身份约束通常会随时间减弱；但持续施加强参考特征也可能复制参考图的姿态、构图或背景，使视频运动不足。长视频中更适合保留稳定的身份锚点，并按片段重新检索或注入，同时把可变服饰和事件状态单独更新。

Structure 条件必须与视频时间轴对齐

深度、姿态、掩码或布局若逐帧提供，需要与目标帧率、时间戳和相机坐标一致；只有少量关键结构时，则要明确插值、保持或重新预测的区间。当结构本应变化时，将同一张结构图复制到所有帧，常会把视频锁成近静态结果；结构序列本身抖动，模型也可能忠实地产生抖动。

排查时分别错配主体参考和结构序列：替换参考图后身份应随之改变，平移或延迟结构序列后姿态与布局应产生对应偏移。再按时间绘制身份相似度和结构误差，才能看出条件是在全程生效，还是只影响开头几帧。

面试速答：Subject Control 通过参考图或身份特征维持“是谁”，Structure Control 通过深度、姿态、布局等序列约束“每个时刻在哪里、是什么结构”。前者要在身份保持与参考复制之间取舍，后者要保证时间和坐标对齐；可以用错配条件和分段误差曲线验证它们是否持续生效。

Verifier、Reward Model、Critic、Judge Model 的目标函数有什么区别？

Verifier 通常判断答案或步骤是否正确：

\[ p_{\phi}(\text{correct}|x,y) \]

目标多为二分类交叉熵。

Reward Model 学习人类偏好或任务奖励：

\[ r_{\phi}(x,y) \]

常用 pairwise ranking loss。

Critic 在强化学习中估计价值函数：

\[ V^{\pi}(s)=\mathbb{E}_{\pi}\left[\sum_{t}\gamma^tr_t|s_0=s\right] \]

或动作价值：

\[ Q^{\pi}(s,a) \]

Judge Model 更偏评审器，可输出打分、排序或自然语言评价。它可能用分类、回归、偏好学习或 instruction tuning 训练。

一句话区分：

Verifier 关心对错，Reward Model 关心偏好分数，Critic 关心未来回报，Judge Model 关心评审任务的综合判断。

与其他方法相比，VScan 在高缩减率下优势显著，例如在 LLaVA-1.5-7B 的 88.9% 缩减率下，平均性能比第二好的 VisionZip 高 4.0%；在Qwen-2.5-VL 的 75% 缩减率下，指称定位任务性能达原始模型的 80.7%，远超 FastV 和 PyramidDrop 的约 50% 性能。此外，VScan 与 FlashAttention 兼容，可进一步减少推理时间，如 LLaVA-NeXT-7B 在 11% 保留率下，结合 FlashAttention 后推理时间从 488 秒减至 473 秒。

Wan-S2V 如何从单图和音频生成电影级人物视频？

Wan-S2V 属于大视频模型驱动的 speech-to-video 路线。它的目标不是只修嘴，而是从一张参考图和一段音频生成更完整的人物视频，覆盖口型、表情、身体动作和镜头表现。

核心思路：

  1. 基于 Wan 系列视频底模

使用大规模视频生成底座承载人物动态、场景和镜头语言，而不是从零训练一个小型 talking head 网络。

  1. 音频条件注入

用 Wav2Vec/HuBERT 类编码器提取音频特征，将音素、节奏和情绪信息注入视频生成过程。

  1. 文本与音频互补

音频负责时序和口型，文本 prompt 可控制动作、表演风格、镜头和场景。

  1. 支持半身和全身

生成目标从头像扩展到半身/全身，因此需要手势、肩颈、身体节奏和构图稳定。

  1. 长视频工程

常结合分段生成、上下文继承、运动压缩、缓存和多 GPU 推理，避免长视频漂移。

面试回答时要强调：Wan-S2V 的价值在于把“音频驱动数字人”纳入大视频模型能力范围，生成结果更像视频内容生产，而不只是传统嘴部同步。

Wav2Vec、Whisper、HuBERT 等音频编码器在数字人里如何使用？

音频编码器负责把波形转成与语音内容、节奏、音素、情绪相关的特征。

Wav2Vec 2.0：常用于提取连续语音表征，适合音频驱动唇形、表情和头动。

Whisper：强在语音识别和多语种鲁棒性，部分方法用其 encoder feature 表达语音语义和节奏。

一个 AI 视频创作系统为什么不能只依赖一次性 T2V 生成？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

一次性 T2V 适合生成候选短片：输入一段描述，经过一次采样得到视频。如果任务只有一个短镜头，也不要求后续修改和素材复用，这种方式已经足够。完整创作的问题在于，约束来自不同层级，而且会在制作过程中变化。

  • 项目级约束贯穿全片，包括叙事目标、角色设定、视觉风格和交付规格。
  • 镜头级约束只作用于某个 shot，例如景别、运镜、人物动作和镜头时长。
  • 局部约束可能只影响一个对象或几帧画面，例如换装、去除穿帮或修正口型。

把这些约束都压进一个长 prompt，会丢失作用范围和依赖关系。结果出错后，系统也不知道应该调整脚本、重做镜头，还是只修改局部区域。更现实的做法是把 T2V、I2V 和视频编辑视为工作流中的执行能力：上游给出镜头计划和资产引用，下游检查结果并决定接受、修改或重生成。

工作流的另一项作用是保护已经确认的内容。某个局部动作有问题时，若只能整段重采样，修复会同时改变角色外观、构图和节奏；具备镜头版本和编辑作用域后，系统才有机会控制修改带来的连带影响。

面试速答：一次性 T2V 适合生成单个候选短片，但完整创作同时包含项目、镜头和局部三个尺度的约束。工作流要把这些约束映射到具体资产和时间范围，并在生成后支持检查、局部修改和版本回退。因此，T2V 更适合作为工作流中的执行模块，而不是完整创作系统本身。

一个典型 AI 视频生成系统的端到端流程是什么？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

如果题目没有特别说明，先按推理链路回答：处理条件，初始化视频 latent，反复调用生成主干和采样更新，最后由 Video VAE 解码成像素视频。完整数据流如图2-7所示。

图2-7 潜空间视频生成系统的端到端推理数据流

一次生成请求通常经过四步

  1. 准备条件。 文本经分词和文本编码，图像、视频或结构信号经各自路径得到序列特征、全局向量或空间对齐 latent。这里还会处理帧率、分辨率、时长和 mask 等元数据。
  2. 初始化视频 latent。 T2V 通常从随机噪声开始；I2V 和 V2V 还可能先编码输入图像或视频，再通过加噪、反演、拼接或 mask 构造初始状态。具体形式取决于训练时采用的条件接口。
  3. 迭代生成。 主干在当前 latent、时间变量和条件表示下预测噪声、velocity、去噪 latent 或流场；采样器或数值求解器据此更新状态，重复若干次得到目标 latent。
  4. 解码与输出。 Video VAE Decoder 将 latent 还原为像素帧，系统再完成色彩、帧率、编码格式等后处理。

训练链路与此不同：目标视频需要经过 VAE Encoder，模型随机采样时间并构造带噪或插值状态，通常不会执行完整的多步采样循环。另一个容易说错的点是，纯 T2V 推理通常只需要 VAE Decoder；只有存在图像或视频输入时，VAE Encoder 才可能进入请求链路。

面试速答：推理时先把条件转成主干可用的表示，再根据任务初始化视频 latent，由主干预测、采样器更新，最后经 Video VAE 解码。T2V、I2V 和 V2V 不只条件不同，latent 初始化、输入编码和已知区域约束也可能不同；训练时则要编码目标视频并直接构造训练状态。

三个概念各自回答什么？

  • Spatial：画面里有什么、在哪里。 包括对象、纹理、形状、布局和局部结构。
  • Temporal：前后如何衔接。 包括帧序、持续时间、状态依赖和事件展开过程。
  • Motion：内容怎样变化。 包括目标位移、姿态与表情变化、形变、遮挡关系变化和相机运动。

三者为什么需要联合建模？

Spatial 决定单帧是否清晰、结构是否正确；Temporal 与 Motion 决定这些空间内容能否沿时间稳定演化。只重视空间质量，容易得到“每帧都好看、连起来却不对”的视频；只做时序平滑，又可能压低细节和运动幅度。

面试速答：Spatial 管单帧内容与布局，Temporal 管时间顺序与依赖，Motion 管内容随时间的具体变化。Motion 属于时序建模的重要部分，但时序关系还包括状态保持、事件顺序和持续时间，范围更广。

不同模态条件分别解决什么控制问题？条件越多越好吗？

为什么 BLIP 要在 CLIP 式双编码器之外引入生成式解码器？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)

CLIP 式纯双编码器只能做判别，给定图文算相似度，没法生成文本。BLIP 引入生成式解码器，是想让一个模型同时覆盖理解和生成，补上 CLIP 留下的两块空白：

  1. CLIP 不能生成。 图像描述（captioning）、视觉问答（VQA）要求模型输出自然语言，双塔最后只输出一个相似度，没有逐词解码的通路。BLIP 的图像引导文本解码器用因果自注意力加 cross-attention，可以看着图自回归地写出句子，captioning、VQA 由此进入能力范围。

  2. CLIP 缺少细粒度跨模态交互。 CLIP 的图文只在最后一层点积，属性绑定、空间关系这些细节处理不好。BLIP 的图像引导文本编码器在每层插入 cross-attention，文本 token 可以逐层关注图像的不同区域，ITM 学到的对齐比 ITC 精细得多。

BLIP 论文还认为，编码和解码共享大部分参数后，可以从多任务训练中获益，这是它用一套 MED 权重同时做两类任务的依据[4]。

另一个动机在数据上。有了生成式解码器，BLIP 才能用模型自己生成 caption 来清洗训练数据（CapFilt 里的 Captioner），用生成能力反过来提升数据质量。

面试速答：CLIP 双塔只输出相似度，做不了 captioning、VQA 这些生成任务，也缺少细粒度交互。BLIP 用图像引导的文本解码器补上生成能力，用逐层 cross-attention 的编码器学细粒度匹配，两者共享大部分参数。有了解码器，BLIP 还能用自己生成的 caption 清洗训练数据。

为什么 rowspan/colspan 这类复杂表格在多模态 LLM 场景下仍然容易被“拆碎”或“错位”？

(1)视觉-语言对齐粒度不足 当前主流多模态 LLM（如 Qwen-VL、Monkey、InternVL）在预训练阶段以「整图-整段文字」对齐为主，缺乏单元格级别的显式坐标监督。模型只能隐式猜测网格边界，跨行列合并时误差放大。

(2)位置编码机制限制 基于 RoPE 或 2-D 绝对位置编码的 Transformer，在子图裁剪或高分辨率切片后，全局坐标系被重置，导致跨行列合并的相对位置关系丢失。

(3)训练数据缺陷 公开表格数据集（PubTabNet、FinTabNet）以「单页-单表」为主，极少出现跨页、跨栏、重复表头的极端情况；模型在微调阶段未见过这类长尾分布，自然在推理阶段表现退化。

(4)工程对策 在训练阶段引入「单元格级框+HTML 树结构」双重监督；采用「先检测网格后语言建模」的级联框架（例如 OCRFlux 的做法），把视觉网格检测与语言生成解耦，降低 LLM 直接回归坐标的难度。

为什么 Wan 是开放视频模型家族？其底层技术路线是什么？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

Wan 是一套共享技术底座、按规模和任务拆分 checkpoint 的开放模型家族。1.3B 与 14B 对应不同质量和部署成本，T2V、I2V、首尾帧生成与 VACE 编辑又有不同条件接口。这里的“家族”不等于一个模型通过切换参数完成所有任务。

共享技术底座包含四部分

  • Wan-VAE：3D causal VAE 负责时空压缩，并通过缓存支持长视频分块编解码。先验收 VAE 重建，才能判断后续模糊、闪烁是否来自 DiT。
  • Flow Matching DiT：T5 编码多语言文本，各 Transformer block 通过 cross-attention 注入条件，主干学习从噪声到视频 latent 的速度场。
  • 可扩展数据与训练：大规模图像、视频经过清洗、去重和质量分层；不同任务需要相应的条件构造，不能只靠同一个预训练目标自然涌现。
  • 分层评测与部署：不同参数规模必须在同一提示集上同时比较质量、稳定性、延迟和显存。小模型能在低成本设备运行，不代表它在高分辨率和复杂运动上与 14B 等价。

同一家族的 checkpoint 也不能随意混用

实际选型先按任务和资源排除 checkpoint，再比较质量。把 14B 的 LoRA 直接用于 1.3B，或者在 T2V 与 I2V checkpoint 间混用权重，通常会因形状或特征分布不匹配而失败；同属 Wan 家族不代表参数可以自由组合。

面试速答：Wan 是按参数规模和任务拆分的开放 checkpoint 家族，共享 Wan-VAE、Flow Matching DiT、数据与评测方法。它统一的是技术底座和生态，不是单一权重；选型必须同时看任务、显存、分辨率和质量上限。

为什么StableDiffusion使用CLIP而不使用BLIP?

CLIP是通过对比学习的方式训练图像和文本的编码器，使得图像和文本之间的语义空间能够对齐。CLIP的架构和训练方式可能更适合Stable Diffusion模型的目标，即生成与文本描述相匹配的高质量图像。

BLIP由于其图像特征受到了图文匹配（ITM)和图像条件语言建模(LM)的影响，可以理解为其图像特征和文本特征在语义空间不算对齐的。

最大区别：损失函数，CLIP和BLIP针对任务不同，不同任务不同损失函数。

为什么上下文爆炸会成为长视频生成的核心瓶颈？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

上下文瓶颈首先来自时空 token 的乘法增长。设视频经过时空压缩和 patchify 后，时间、空间尺寸分别为 \(T'\)、\(H'\) 和 \(W'\)，则 token 数近似为：

N = T'H'W'

如果主干在全部视频 token 上执行稠密 self-attention，单层注意力计算量近似为：

\mathcal{O}(N^2 d)

其中 \(d\) 是注意力特征维度。未采用显存优化实现时，注意力矩阵的存储也随 \(N^2\) 增长。空间分辨率与视频时长相乘，使长视频训练很快受到计算量和激活显存限制；扩散或流模型还要在多个采样步中重复执行主干网络。

成本需要按架构分别判断

  • 稠密全时空注意力主要受二次复杂度约束；分解注意力、局部窗口或稀疏注意力会改变实际增长曲线。
  • KV cache 是 causal 或自回归实现中的典型成本，不应泛化到所有视频扩散模型。它能减少历史 token 的重复计算，但缓存本身仍会随有效历史增长。
  • chunk 方法把单次计算限制在固定窗口内，却把压力转移到跨片段状态传递和边界一致性上。

计算预算解决后，仍有信息利用问题。长视频包含大量相邻帧冗余，远距离历史中真正相关的信息只占一部分；上下文过长时，模型还可能检索不到关键状态，或者反复利用已经出错的历史。实践中通常为近邻上下文保留细粒度信息，将远距离历史压缩为记忆或按需检索，再用高层规划维护事件结构。4.4.2 和 4.4.3 将继续展开这些方案。

面试速答：视频 token 数近似为 \(N = T'H'W'\)，稠密全时空注意力的主要计算量随 \(N^2\) 增长，因此时长和分辨率会共同推高训练与采样成本。KV cache 主要属于 causal 或自回归实现；更常见的取舍是用局部窗口保留短时细节，再用压缩记忆或检索传递远距离状态。

为什么多模态模型必须引入投影器？它解决了什么问题？

难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐ (4/5)

编码器的输出不能直接送进 LLM。投影器（Projector，也称对齐模块、连接器或适配器）接在两者之间，负责把编码器输出变成 LLM 能用的输入。它要解决两个问题：

  1. 维度不匹配。 视觉编码器 CLIP-ViT-L 输出 1024 维，LLaMA-7B 的隐藏维度是 4096[2,7]，维度不同就拼不成统一序列。投影器最基本的工作是做维度变换，把编码器输出投到 LLM 的隐藏维度。

  2. 语义空间不对齐。 CLIP 的视觉编码器在图文对比任务上训练，输出落在视觉特征空间；LLM 的 token 嵌入落在它自己的语言空间。同样表示“猫”，CLIP 输出的视觉向量和 LLaMA 里“cat”这个 token 的嵌入并不会自然落在一起。投影器要在训练中学到一个变换，让 LLM 能把视觉 token 当作有意义的输入来处理。

面试速答：因为编码器输出和 LLM 输入之间有两道坎。一是维度不匹配，CLIP-ViT-L 输出 1024 维，LLaMA-7B 要 4096 维；二是语义空间不对齐，视觉向量和词嵌入不在同一区域。投影器负责维度变换，并在训练中学到一个变换，让 LLM 能把视觉 token 当作有意义的输入。

为什么统一视频系统的关键往往在条件接口，而不只在 backbone？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

条件接口不是简单接收多种输入的连接层，而是一组明确的数据约定：每个条件表达什么，采用哪套空间和时间坐标，作用在哪些帧与区域，强度如何控制，缺失或冲突时怎样处理。只有这些约定稳定，不同任务才能复用同一套模型组件和工程链路。

条件表示要保留有用结构。 文本通常提供全局语义，首帧和源视频带有像素或 latent 坐标，姿态、深度和轨迹具有空间结构，音频则是高采样率的时间信号。统一接口不要求它们变成完全相同的特征，但要把各自的语义、空间位置和时间戳映射到生成视频的坐标系中。

注入位置必须匹配作用范围。 全局语义可以影响整段视频，mask 只应控制指定区域，首尾帧具有明确时间位置，轨迹和音频事件还要对齐到对应帧。条件进入哪一层、覆盖哪些 token、是否跨帧传播，比“是否接入了这种模态”更能决定控制效果。

训练数据要覆盖真实使用方式。 模型需要见过条件与目标视频之间的有效配对，也要覆盖条件单独出现、组合出现和部分缺失的情况。随机丢弃条件可以提高缺失条件下的鲁棒性或支持无分类器引导（classifier-free guidance），但不能代替冲突样本和组合任务的训练。

面试速答：统一条件接口要解决五件事：条件表示、时空对齐、作用范围、注入路径和训练监督。不同模态不必压成同一种特征，但必须与目标视频的空间区域和时间位置对齐。判断接口是否有效，要固定其他输入，只改变一个条件，检查输出是否在预期作用域内响应。

为什么视频生成不能依赖单一指标判断模型好坏？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

单一指标只能观察视频质量的一个投影。画面、运动、条件遵循、长程一致性和多样性可能朝不同方向变化；把它们压成一个总分，会掩盖严重退化发生在哪个维度。

FVD 应该怎么用。 FVD 是集合级统计量，不适合解释单条视频。原始工作报告了它与人类判断的相关性，后续研究也指出其对特征空间、时间扰动和样本规模存在敏感性。这两类结论并不矛盾：FVD 可以作为固定协议下的趋势信号，但不能独立承担模型发布决策。

工程比较需要固定评测协议。 prompt 集、生成数量、seed、帧率、时长、分辨率、采样配置、预处理和指标实现版本都要保持一致。协议不同，即使指标名称相同，数值也未必可直接横向比较。最终应保留分维得分和失败样本，严重安全或一致性问题使用硬门槛处理，不让加权总分把它抵消。

面试速答：单一指标只覆盖视频质量的一部分。FVD 看生成集与参考集的分布差异，文本相似度看整体语义，帧级指标看空间质量，运动指标看局部时间变化；它们都不能单独判断一条视频是否完成了任务。可靠结论需要固定评测协议，同时查看分维指标、场景分桶和失败样本，关键问题再用人评校准。

为什么视频生成正在从二维像素连续走向3D/4D场景一致性？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

二维视频只记录世界投影到图像平面后的结果。同一组像素变化可能由物体运动、相机移动、遮挡变化或形变引起；模型即使生成了连续帧，也未必建立了稳定的场景几何。相机大幅移动、对象离开视野后重新出现或需要跨视角生成时，这种歧义尤其明显。

这里的 3D/4D 指世界坐标中的场景表示及其随时间的变化，不是网络结构中的 3D 卷积。希望维护的信息通常包括：

  • 相机位姿、深度和场景几何；
  • 对象在三维空间中的身份、位置和遮挡关系；
  • 对象形变、运动轨迹以及场景随时间的状态变化。

实现上并不存在唯一答案。显式路线可以预测深度、点图、点云、三维高斯或对象轨迹，几何关系容易读取和控制，但需要额外监督，重建误差也可能限制画质。隐式路线把世界状态保存在模型 latent 中，适合沿用大规模视频预训练，却较难确认模型究竟维护了什么。混合方案则用显式几何或相机信号约束视频生成主干，在可控性和数据规模之间取平衡。

3D/4D 一致性的收益主要体现在大幅运镜、跨视角生成、对象持续存在和空间交互上。评估时应固定场景并改变相机轨迹，检查不同视角能否对应同一几何；还可以让对象短暂离开视野再返回，观察身份、位置和场景状态是否保持。单帧质量和普通时间平滑指标无法替代这些测试。

这条趋势也有明确边界：显式几何不能自动保证物理规律正确，静态场景重建能力也不等于能够表示复杂形变和多主体交互。因此，更稳妥的判断是视频生成正在加强几何和持久状态约束，而不是所有模型都会统一采用某一种 4D 表示。

面试速答：二维视频只提供投影结果，无法唯一确定相机、几何和对象运动。3D/4D 感知的目标是维护世界坐标中的场景结构、对象状态及其时间变化，从而提高大幅运镜、跨视角和遮挡恢复的一致性。实现可以是显式几何、隐式 latent 或混合方案；评价要看跨视角几何和状态持续，不能只看帧间平滑。

为什么视频生成通常选择 latent space？它把哪些问题留给了 VAE？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

视频通常选择 latent space，是因为像素视频包含大量局部冗余。先用 VAE 压缩空间、可选地压缩时间，再让生成主干处理更短的时空网格，可以明显降低训练显存和推理成本。Latent Diffusion 已验证这种“感知压缩 + 生成建模”的分工能够在计算量与细节保真之间取得实用平衡；视频只是把这个问题扩展到了时间维度。

代价是 VAE 设定了信息上限

这是一种工程折中，不是生成模型的必要条件。像素空间模型、离散 tokenizer 和多级级联都能生成视频。Latent 路线的优势是把高成本迭代放在紧凑表示上，代价是主干只能建模 VAE 保留下来的信息：小字、人脸细节、高频纹理或短促运动一旦在编解码阶段丢失，后续扩散模型很难可靠恢复。

面试速答：latent space 用有损压缩换取更低的时空建模成本，让生成主干集中处理语义、结构和运动。它不是唯一方案；代价是 VAE 会设置信息上限。工程上应先检查 VAE 重建，再判断生成主干是否有问题。

为什么长视频不能只沿用短视频评估指标？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

短视频指标仍然必要，但它们的观察窗口通常不足以覆盖长视频中的远距离依赖。单帧质量、局部闪烁、短时运动和句级文本对齐都很好，仍可能在更晚的位置出现主体重置、事件顺序错误或控制条件失效。

面试速答：短视频指标没有失效，但主要覆盖单帧和局部时间窗口。长视频还要评估远距离状态、事件顺序、跨镜头关系和条件持续遵循，并统一时长、帧率与采样次数；只报逐帧平均分，容易漏掉少量但严重的长程错误。

为什么长视频不能简单保存所有历史帧？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

完整保存并反复读取所有历史帧，通常既昂贵，也不保证长期一致性。历史管理需要同时解决容量、相关性和状态更新，这与 4.4.3.1 的“记住哪些内容”是两个不同问题。

全部保留会遇到四个问题

  • 成本持续增长：原始帧或高分辨率 latent 会扩大注意力计算、缓存和数据搬运开销。
  • 大量内容重复：相邻帧通常共享外观和背景，逐帧保存会把预算花在低价值冗余上。
  • 相关信息被淹没：当前片段只需要少量历史状态，过多上下文不代表模型一定能检索到正确内容。
  • 旧状态和错误会继续影响生成：物体状态已经改变时，早期参考可能过时；生成错误若写入长期记忆，也会在后续被反复调用。

更合理的策略是让近期与远期历史采用不同精度，并显式控制检索和更新：

r_i = \mathrm{Retrieve}(q_i, \mathcal{M}_i), \qquad
\mathcal{M}_{i+1} = \mathrm{Update}(\mathcal{M}_i, e_i)

其中，近期窗口保存细粒度运动，长期记忆 \(\mathcal{M}_i\) 保存压缩后的身份、场景和事件状态； \(q_i\) 表示当前片段的查询条件， \(e_i\) 是由新片段产生、并经写入门控筛选的状态变化。Update 需要支持覆盖过时状态，也要避免把低置信度生成错误直接写入长期记忆。

验证时至少比较近期窗口、完整历史、压缩记忆和按需检索四种设置，并加入“主体离场后重现”“物体状态被改变”和“记忆中混入错误帧”等切片。若完整历史不比检索式记忆稳定，瓶颈通常在信息选择或记忆更新，不在容量本身。

面试速答：保存全部历史会带来不断增长的计算与缓存开销，还会保留冗余、过时状态和生成错误。更实用的做法是近期窗口保留运动细节，长期记忆压缩身份、场景和事件状态，再按当前片段检索并更新；评估时要检查记忆是否选对、是否及时覆盖旧状态。

为什么长视频生成不能简单理解为“短视频生成跑更久”？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

把短视频模型直接延长推理时间，通常只能增加输出长度，不能自动获得长期状态保持能力。时间范围扩大以后，模型需要持续维护主体、场景、物体状态和事件进度，还要承担更高的计算与显存成本。

时间拉长后，问题会发生三种变化

  • 依赖范围变长：短片段主要依赖邻近帧；长视频中的当前内容还可能受更早的角色状态、空间关系和事件结果约束。
  • 生成分布发生变化：采用 causal 或 chunk 递推时，模型会逐步接触自己的历史输出。训练时若主要看到短片段或更干净的上下文，推理越长，训练与推理的差异越容易暴露。
  • 时空 token 持续增长：更长的时间轴会扩大注意力、激活存储和采样开销，完整保留历史通常不可行。

还要先区分任务设定。单镜头长视频强调连续时间中的运动和状态延续；多镜头长视频允许视角、景别和时间跳跃，但需要额外维护角色、场景与事件逻辑。后者将在 4.4.4 中展开。

上述变化之间的关系如图4-1所示。

工程上，“能连续出帧”只能证明模型具备长度扩展能力。还要检查远距离重现主体时身份是否稳定、事件状态是否被重置、片段边界是否连续，以及后段是否重复或静态化。这些现象共同改善，才支持模型有效利用了长期上下文；要定位具体由哪种记忆机制起作用，还需要相应的条件消融。

面试速答：延长短视频模型的推理时间，只解决“能生成更长”，没有自动解决长期状态保持。长视频还要处理远距离依赖、递推误差、时空 token 成本和训练与推理长度错位；单镜头侧重连续状态，多镜头还要维护镜头间的事件逻辑。

为什么需要过滤低亮度或低美学的视频？这对生成结果有何影响？

原因： - 低亮度：可能导致模型学习到错误的纹理或面部特征（如阴影遮挡关键区域）。 - 低美学：包含不自然表情、姿势或背景的视频会引入噪声，降低生成视频的视觉质量。

影响： - 过滤后数据能提升模型对高质量面部运动和自然场景的学习能力，减少生成视频中的伪影（如扭曲表情或模糊背景）。 - 实验表明，未经过滤的数据会导致FID（Fréchet Inception Distance）显著升高

为什么音视频联合生成不应只理解为“视频后配音”？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

关键不在于最后是否同时输出音频和视频，而在于两种模态是否在生成过程中相互影响。

传统后配音通常先确定画面，再以视频和文本为条件生成语音、音效或音乐。它的优势是模块成熟、训练和调试相对简单，也方便单独替换音频模型。但画面一旦固定，声音就无法反过来改变人物动作、镜头切换或节奏。例如关门动作与撞击声错开时，音频模型只能尽量追随已有画面，不能修正动作本身。

原生音视频生成更强调以下两点：

  1. 共享事件与时间结构。 人物开口、物体碰撞和镜头切换等事件，不应由两个模型各自猜测，而应建立在一致的事件状态和时间轴上。
  2. 输出固定前存在跨模态交互。 音频特征能够影响画面，视觉特征也能约束声音。这种交互既可以发生在统一 Transformer 中，也可以通过两个生成分支之间的跨模态注意力完成，并不要求音频和视频共用同一个解码器。

因此，“原生”更适合作为一种系统能力描述，而不是由某个概率公式定义。联合建模也不会自动带来同步，最终仍取决于配对数据质量、交互机制和训练目标。

面试速答：后配音是画面先固定、声音随后适配；原生音视频生成则要求音频和视频在输出固定前共享事件与时间结构，并发生跨模态交互。判断关键不是是否一次输出两种模态，而是声音能否影响画面、画面能否约束声音。

为何选择FVD而非传统的PSNR/SSIM评估视频质量？

PSNR/SSIM局限性： - 仅衡量像素级相似性，忽略时序动态和语义一致性（如表情自然度）。

主流输入投影器的分类维度与代表方案有哪些？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐ (4/5)

按结构，主流投影器可以分成四类：

  1. 线性投影（Linear Projection）。 最简单的形态，一层全连接完成维度变换。代表是 LLaVA-1.0，CLIP-ViT 输出的视觉 token 经一层 Linear 直接接到 Vicuna 的词嵌入空间[8]。

  2. MLP 投影器。 在线性投影的基础上加非线性激活，通常是两层。LLaVA-1.5、LLaVA-1.6 用两层 GELU-MLP[9,39]，InternVL 系列也用 MLP 投影器[30]，这是目前最常用的轻量投影器。

  3. 交叉注意力投影器（也叫 Resampler、Q-Former）。 用一组可学习的 query token，通过交叉注意力从视觉特征里提取信息。代表有 BLIP-2 的 Q-Former 和 Flamingo 的 Perceiver Resampler[10,40]，MiniGPT-4 直接沿用了 BLIP-2 训练好的 Q-Former，只多训一层线性投影[15]。它们的主要特点是会压缩 token 数量。

  4. 卷积投影器（Conv Mapper）。 用卷积或 Pixel Shuffle 做空间下采样和维度变换。代表有 MobileVLM 的 LDP（Lightweight Downsample Projector）[41]和 InternVL-1.5 的 Pixel Shuffle 加 MLP[30]。

另外还有一些混合方案。Honeybee 的 C-Abstractor 先用几个 ResNet 块提取局部特征，再用自适应平均池化压到指定的 token 数，之后再接 ResNet 块[42]；Qwen-VL 用单层交叉注意力模块，把视觉特征压成 256 个 query token[43]。它们都可以看作上面几类的工程变体。

面试速答：按结构分四类。线性投影只有一层全连接，代表是 LLaVA-1.0；MLP 投影器加了非线性，LLaVA-1.5 和 InternVL 都用；交叉注意力投影器用 query 压缩 token，代表是 Q-Former；卷积投影器做空间下采样，代表是 MobileVLM 的 LDP。
