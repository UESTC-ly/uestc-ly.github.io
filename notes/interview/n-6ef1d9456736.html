Docker容器使用

Docker客户端

Docker客户端非常简单，我们可以直接输入docker命令来查看到Docker客户端的所有命令选项。也可以通过命令docker command --help更深入的了解指定的Docker命令使用方法。

docker

容器使用

获取本地没有的镜像。如果我们本地没有我们想要的镜像，我们可以使用 docker pull 命令来载入镜像：

docker pull 镜像

启动容器。以下命令使用ubuntu镜像启动一个容器，参数为以命令行模式进入该容器：

docker run -it 镜像 /bin/bash

参数解释：

  • -i：允许你对容器内的标准输入 (STDIN) 进行交互。
  • -t：在新容器内指定一个伪终端或终端。
  • /bin/bash：放在镜像名后的是命令，这里我们希望有个交互式Shell。

我们可以通过 <仓库名>:<标签> 的格式来指定具体是这个软件哪个版本的镜像。如果不给出标签，将以latest作为默认标签。

要退出终端，直接输入exit或者CTRL+D。

启动已经停止运行的容器。查看所有的容器的命令如下：

docker ps -a

我们也可以用docker ps命令查看正在运行的容器。

docker ps

我们可以使用 docker start 启动一个已停止的容器：

docker start 容器

想要后台运行容器，我们可以过 -d 指定容器的运行模式：

docker run -itd --name 指定创建的容器名 容器 /bin/bash

加了 -d 参数默认不会进入容器，想要进入容器需要使用下面的指令进入容器：

  • docker attach
  • docker exec：推荐大家使用 docker exec 命令，因为使用此命令退出容器终端，不会导致容器的停止。
docker attach 容器  //如果从这个容器退出，会导致容器的停止。

docker exec -it 容器 /bin/bash   //如果从这个容器退出，不会导致容器的停止。

想要停止容器，其命令如下：

docker stop 容器ID

停止的容器重启命令：

docker restart 容器ID

删除容器：

docker rm -f 容器ID

Docker简介

Docker是一个开源的应用容器引擎，基于Go语言并遵从Apache2.0协议开源。

Docker可以打包代码以及相关的依赖到一个轻量级、可移植的容器中，然后发布到任何流行的Linux机器上，也可以实现虚拟化。

容器完全使用沙箱机制，相互之间不会有任何接口（类似iPhone的app），更重要的是容器性能开销极低。

Docker的应用场景： 1. Web应用的自动化打包和发布。 2. 自动化测试和持续集成、发布。 3. 在服务器环境中部署/调整数据库或其它的后台应用。

Docker镜像的修改和自定义

docker镜像的更新

在启动docker镜像后，写入一些文件、代码、更新软件等等操作后，退出docker镜像，之后在终端输入如下命令：

docker commit -m="..." -a= "..." 容器ID 指定要创建的目标镜像名称

  • -m：提交的描述信息

docker tag IMAGEID(镜像id) REPOSITORY:TAG（仓库：标签）

EG3D 的 tri-plane 表示为什么重要？

EG3D 的核心是 tri-plane representation。它不用完整 3D 体素网格，而是使用三个正交的二维特征平面：

  • \(F_{xy}\)
  • \(F_{xz}\)
  • \(F_{yz}\)

对于三维点 \(x=(x,y,z)\)，分别投影到三个平面上采样特征，再聚合得到该点的特征：

\[ f(x) = F_{xy}(x,y) + F_{xz}(x,z) + F_{yz}(y,z) \]

再通过轻量 decoder 得到颜色和密度，用体渲染生成低分辨率图像，最后通过超分网络得到高分辨率结果。

tri-plane 的优势：

  • 比 3D voxel 更省内存。
  • 比纯 MLP NeRF 查询更快。
  • 与 StyleGAN2 生成器兼容，能继承高质量图像先验。
  • 能保持一定 3D 一致性。

它的重要性在于：为高质量 3D-aware 人脸生成提供了效率和质量之间的平衡点。

Embodied Reasoning 模型主要解决什么问题？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

Embodied Reasoning（ER，具身推理）模型主要解决的是：机器人在真实世界中执行任务前，如何进行空间、物理、任务进度和安全相关的推理。

它不一定直接输出动作，而是更偏“高层理解和决策支持”：

  1. 空间推理：物体在哪里、相互关系如何、目标点是否可达。
  2. 点选/定位推理：指向目标、可抓取点、危险区域或操作位置。
  3. 进度判断：任务是否完成，是否需要重试。
  4. 多视角理解：结合腕部相机、俯视相机、移动视角判断状态。
  5. 安全判断：哪些物体不能碰、哪些动作会违反约束。

Google DeepMind 的 Gemini Robotics 系列就是典型例子：它把 VLA 和 ER 分工，VLA 负责视觉-语言到动作，ER 负责更强的具身推理、任务规划和安全判断。2026 年的 Gemini Robotics-ER 1.6 进一步强调空间推理、多视角理解、成功检测和仪表读取等真实世界任务。

Few-shot 示例应该如何选择？

高质量示例应满足：

FFN模块内部结构是怎样的，有哪些可替代的设计

回答：

标准 Transformer FFN 是对每个 token 独立应用、各位置共享参数的两层非线性网络。它通常先扩大通道维度，再投影回模型维度：

\mathrm{FFN}(x)=\phi(xW_1+b_1)W_2+b_2,
\quad W_1\in\mathbb{R}^{d\times d_{\mathrm{ff}}},
\quad W_2\in\mathbb{R}^{d_{\mathrm{ff}}\times d}.

传统结构可以使用 ReLU 或 GELU，很多现代大模型会省略部分偏置。FFN 的作用是对注意力聚合后的特征进行非线性变换；没有非线性时，两层线性投影可以合成一层，表达优势会大幅减少。

一种常见替代是门控 FFN，如 SwiGLU：

\mathrm{SwiGLU}(x)=
\bigl(\mathrm{SiLU}(xW_g)\odot(xW_u)\bigr)W_d.

它通过两个上投影分支进行逐元素门控，再下投影，因此主要权重规模约为 3d·d_mid，而标准两层 FFN 约为 2d·d_ff。比较参数预算时要相应调整中间维度，不能固定宽度后声称门控没有成本。若传统 d_ff=4d，忽略偏置且保持相近权重规模，门控中间维度约取 8d/3，实际通常按硬件要求对齐。

MoE 可以用多个 FFN 专家替代单个稠密 FFN，每个 token 只激活部分专家，以更少的活跃计算承载更大总参数容量，但增加路由、通信和负载管理。其他方案包括低秩分解、参数共享、稀疏化或卷积混合等，是否有效取决于任务、训练和内核支持。MoE 专家内部仍然可以使用 SwiGLU，所以它们不是互斥选项。

面试中应补充 FFN 经常占模型很大一部分参数与 FLOPs。替换结构要在相同参数量、活跃计算或延迟预算下比较，并检查质量、训练稳定性和部署成本。

Flan-T5、ChatGLM、LLaMA这些语言模型有什么区别?

Flan-T5、ChatGLM和LLaMA均是基于Transformer架构的语言模型，但它们在设计理念、训练策略和应用领域上各有侧重，展现出不同的技术特色和应用价值。

Flan-T5 Flan-T5（Fine-tuning Approximation of T5）是一个多任务学习框架，其核心在于通过共享的编码器和解码器架构来高效处理多种自然语言处理（NLP）任务。该模型的设计目标是为了实现任务间的知识共享和迁移学习，从而提高模型在不同任务上的泛化能力。Flan-T5通过在大量多样化的任务上进行预训练，使得模型能够更好地适应新的任务需求，减少了针对特定任务进行微调所需的资源和时间。其应用场景广泛，涵盖文本分类、问答、摘要、翻译等多种NLP任务。

ChatGLM ChatGLM是一款专注于对话生成的语言模型，他的设计目标在于提升对话的连贯性、相关性和质量，使其能够更自然地与用户进行交互。为了实现这一目标，ChatGLM在训练过程中引入了大量的对话数据和特定的优化策略，旨在更好地捕捉对话上下文和用户意图。其应用场景主要集中于智能客服、虚拟助手、聊天机器人等领域，旨在提供更加流畅和人性化的对话体验。

GAN Inversion 在数字人里有什么作用？

GAN Inversion 是把一张真实图像映射回 GAN 潜空间的过程：

\[ w^* = \arg\min_w \mathcal{L}(G(w), I) \]

常见方法：

  1. 优化式反演

直接优化 latent code，重建质量较高但速度慢。

  1. 编码器式反演

训练 encoder 一次前向得到 latent，速度快但细节可能差。

  1. 混合式反演

先用 encoder 初始化，再进行少量优化。

  1. PTI/Pivotal Tuning

在给定人物上微调生成器，提升重建保真度。

数字人用途：

  • 真实人脸编辑。
  • 虚拟人身份创建。
  • 人脸修复和超分。
  • 文本/属性控制的人脸重绘。
  • 将真实人物转换到可控生成空间。

面试要点：GAN Inversion 的核心矛盾是“重建保真度”和“可编辑性”。重建越强，可能越依赖 \(W+\) 或生成器微调；但越偏离原始 GAN 分布，后续编辑越容易产生伪影。

GAN 在数字人发展中解决过什么核心问题？

GAN，全称 Generative Adversarial Network，是数字人生成早期最重要的生成模型之一。它通过生成器和判别器的对抗训练，让生成器学习产生接近真实图像或视频的结果。

GAN 在数字人中主要解决过四类问题：

  1. 高保真人脸生成

StyleGAN 系列显著提升了人脸图像的真实感、分辨率和可编辑性，使“虚拟人脸生成、身份编辑、年龄/表情/姿态编辑”成为可用能力。

  1. 人脸换脸与身份迁移

DeepFakes、FaceShifter、SimSwap、HiFiFace 等方法通过 identity embedding、attribute encoder、融合网络实现高效换脸。

  1. 肖像动画与表情驱动

FOMM、face reenactment、GAN talking head 等方法用关键点、光流、3DMM 或音频特征驱动静态头像动起来。

  1. 3D-aware 人脸生成

HoloGAN、pi-GAN、StyleNeRF、EG3D 等方法将 GAN 与 3D 表示、体渲染或 tri-plane 结合，提升视角一致性。

从技术演进看，GAN 数字人是连接传统图像编辑、神经渲染和当前扩散/DiT 数字人的重要阶段。

GAN 如何用于 3D 数字人的纹理、材质和细节增强？

GAN 不一定只生成整张脸，也可以作为 3D 数字人的细节增强模块。

常见用法：

  1. UV 纹理生成

在 UV 空间生成或补全人脸/人体纹理，保证贴图可绑定到 Mesh。

  1. 法线/位移细节

GAN 换脸如何处理姿态、表情、遮挡和边界融合？

常见策略：

  1. 姿态与表情保持

目标图像通过 attribute encoder 提供姿态、表情、光照和背景特征，源图只提供身份。

  1. 3DMM 辅助对齐

使用 3DMM 估计头姿和脸部几何，做姿态归一化、mask 生成、UV 对齐或形状约束。

  1. 遮挡处理

对头发、眼镜、手、麦克风等遮挡区域预测 occlusion mask，避免生成脸覆盖不可替换区域。

  1. 边界融合

使用 segmentation mask、Poisson blending、颜色匹配、alpha matte 或专门的 blending network。

  1. 局部判别器

对眼睛、嘴巴、脸部边界等区域使用局部 adversarial loss，提升细节。

  1. 多尺度生成

先生成低分辨率结构，再补高分辨率细节，减少边界伪影。

面试中要强调：换脸不是简单替换五官，而是身份与属性解耦。源身份应该进入脸型和五官身份特征，目标属性应该保留姿态、表情、光照和上下文。

GLM-4.6V在“设计到代码”任务中如何实现像素级复现与交互式编辑？

“设计到代码”任务要求模型将设计稿精准转换为前端代码，并支持用户圈选修改。GLM-4.6V在此方面的突破基于两项创新：

回答：

工程上应减少不必要分配、复用缓冲区但避免错误池化、关注逃逸分析、监控 heap/alloc/pause 和 p99 延迟。GC 不能替代关闭文件、连接和 goroutine；泄漏通常来自仍可达的引用、缓存或阻塞 goroutine。

HunyuanVideo模型有哪些特点？

单-双流TransFormer架构

HunyuanVideo模型采用了Transformer架构，设计了一个“双流到单流”的混合模型用于视频生成。在双流阶段，视频特征和文本token通过并行的Transformer Block独立处理，使得每个模态可以学习适合自己的调制机制而不会相互干扰。在单流阶段，再将视频特征和文本token连接起来并将它们输入到后续的Transformer Block中进行有效的多模态信息融合。这种设计和FLUX.1这个AI绘画大模型有异曲同工之妙，捕捉了视觉和语义信息之间的复杂交互，增强了整体模型性能。

使用MLLM文本编码器

之前的AI视频大模型通常使用预训练的CLIP和T5-XXL作为文本编码器。而HunyuanVideo则是使用了一个预训练的Multimodal Large Language Model (MLLM)作为文本编码器，其具有以下优势：

  1. 与T5-XXL相比，MLLM模型基于图文数据指令微调后在特征空间中具有更好的图像-文本对齐能力，这就减轻了扩散模型中的图文特征对齐的难度。
  2. 与CLIP相比，MLLM模型在图像的细节描述和复杂推理方面表现出更强的能力。
  3. MLLM模型可以通过遵循系统指令实现零样本生成，从而帮助文本特征更多地关注关键信息。
  4. 由于MLL模型是基于Causal Attention机制的，而T5-XXL使用了Bidirectional Attention机制为扩散模型提供更好的文本引导。因此，HunyuanVideo引入了一个额外的token优化器来增强文本特征的引导。

回答：

Imitation Learning 从示教或专家反馈学习行为；Reinforcement Learning 根据奖励和环境转移优化长期回报。区别主要在学习信号与目标，不在是否使用 Transformer 或是否运行在机器人上。

J(\pi)=\mathbb E_{\tau\sim\pi}\left[\sum_{t=0}^{T-1}\gamma^t r_t\right]
维度 IL RL
主要信号 专家动作、偏好或行为约束等 奖励与转移信息

InfoNCE假负样本带来的负面影响，对应的缓解手段

回答：

InfoNCE 通常把同一 batch 中其他 Item 当作负样本：

\[ \mathcal{L}_i=-\log\frac{\exp(s(q_i,i_i^+)/\tau)}{\sum_j\exp(s(q_i,i_j)/\tau)} \]

但同一个 Item 可能同时满足多个 Query，或 batch 中存在语义相近、业务上也相关的 Item。把它们强行当负样本就是假负样本，会错误地把真实相关内容推远，破坏 embedding 空间，尤其伤害多兴趣、长尾、同主题、多正样本和 Recall@K。

我会先按样本 ID、内容实体、Query 意图和时间窗口做去重，再使用曝光、点击、收藏、人工相关性或教师模型构造负样本 mask。一个 Query 有多个正例时用 multi-positive InfoNCE，让多个正例进入分子或正例集合，而不是只保留一个对角线正例。对高度相似但标签不确定的样本可以降权、忽略或单独作为软负例。

此外可以做分层负采样：随机负例提供覆盖，模型高分但明确不相关的 hard negative 提供区分能力，潜在正例则屏蔽；用 cross-encoder、规则和人工抽检识别假负样本。更复杂的场景可使用 debiased contrastive learning 或教师分布蒸馏，但核心仍是降低错误监督。

不能为了消除假负样本而删除所有 hard negative，否则模型会失去边界学习。应通过消融比较负样本策略对 Recall@K、nDCG、长尾分桶、训练稳定性和线上负反馈的影响。

KL 散度非负性如何证明？

KL 散度：

\[ D_{KL}(P\|Q)=\sum_xP(x)\log\frac{P(x)}{Q(x)} \]

使用 Jensen 不等式。因为 \(-\log x\) 是凸函数：

\[ D_{KL}(P\|Q) =\sum_xP(x)\left[-\log\frac{Q(x)}{P(x)}\right] \]

由 Jensen 不等式：

\[ \sum_xP(x)\left[-\log\frac{Q(x)}{P(x)}\right] \ge -\log\sum_xP(x)\frac{Q(x)}{P(x)} \]

右边化简：

\[ -\log\sum_xQ(x)=-\log 1=0 \]

因此：

\[ D_{KL}(P\|Q)\ge 0 \]

当且仅当 \(P=Q\) 时取等号。

面试易错点：

  • KL 非负，但不是距离，因为它不对称，也不满足三角不等式。
  • 若存在 \(P(x)>0\) 但 \(Q(x)=0\)，KL 会发散到无穷大。

langchain、langgraph 这些框架为什么选择？底层流程了解吗？

回答：

LangGraph的核心关键点是什么？

回答：

LangGraph 的核心是把 Agent 从“线性 chain”提升为“有状态图”。它用 graph 来表达任务流，用 state 来承载中间状态，用 node 表示执行步骤，用 edge 表示流转条件，适合多步骤、可分支、可循环、可恢复的 Agent 任务。

关键点有四个。第一是 State。LangGraph 不是每步只传一段文本，而是维护结构化状态，例如用户需求、当前计划、工具结果、错误信息、候选素材、评测结果。

第二是 Node。每个 node 是一个可执行单元，可以是 LLM 调用、工具调用、检索、校验、人工确认或媒体处理。

第三是 Edge 和 Conditional Edge。它可以根据状态决定下一步走哪里，例如工具成功进入下一节点，失败进入 retry 或 fallback，质量不达标回到修复节点。

第四是循环和 checkpoint。Agent 常常需要 plan-act-observe-replan，LangGraph 能表达这种循环，并通过 checkpoint 保存状态，支持中断恢复、调试和人工介入。

它适合复杂 Agent，不适合所有任务。简单问答用普通 chain 就够了；多步骤、有状态、需要重试和分支的任务，LangGraph 更清晰。

LLM调用失败怎么排查？

面试官： 调用大模型API失败，你的排查流程是什么？

回答：

排查 LLM 调用失败应先回答三个问题：请求是否到达服务端，服务端是否开始生成，失败是否可以安全重试。推荐按调用链分层，而不是一上来只看 CPU 和内存。

  1. 确定影响范围。 是单请求、单模型、单地域、单租户还是全量失败；记录开始时间、错误率、P95/P99 延迟和最近变更。
  2. 建立关联。 用 trace_id/request_id 串起网关、应用、模型服务和工具日志。记录模型、版本、区域、流式与否、输入/输出 Token、参数摘要和 HTTP 状态，但不得记录密钥或未脱敏的敏感 Prompt。
  3. 定位网络阶段。 分别检查 DNS、TCP、TLS、代理、连接池、连接超时、首字节/首 Token 超时、流式空闲超时和总 Deadline。能够建连不代表流式响应没有中途断开。
  4. 按状态码分类。 400 多为参数、Schema 或上下文问题；401/403 是认证、权限或项目配置；404 可能是模型名或 Endpoint；409 常见于状态冲突；429 是速率或配额限制；5xx 表示服务端、上游依赖或容量异常。仍应以具体供应商错误码为准。
  5. 检查请求内容。 计算真实 Token，验证模型上下文限制、Tool Schema、JSON 格式、图片大小、停止条件和内容安全策略。不要只按字符数猜 Token。
  6. 最小化复现。 使用相同模型和认证发送最小请求，再逐项恢复参数、工具和上下文，找出触发差异。对比最近成功样本与失败样本，但先做脱敏。
  7. 检查服务端资源。 若是自部署模型，再看队列长度、Batch、GPU OOM、KV Cache、显存碎片、推理引擎日志、模型权重、NCCL 和节点健康。

重试必须服从错误语义。连接重置、部分 429/5xx 可采用指数退避、随机抖动和 Retry-After；参数错误与权限错误不应重试。对有副作用的工具链要带幂等键，避免模型请求重试导致动作重复。流式调用中断后，不能默认把半截输出当成完整答案，应标记不完整并决定续写、重放或降级。

生产系统还需要熔断、备用模型、区域切换、队列削峰、请求限流和质量降级，并监控成功率、首 Token 延迟、生成吞吐、Token 使用、取消率和降级率。排障的关键是按层定位并保留请求关联，而不是把所有失败都归因于“网络波动”。

load average 和 CPU 使用率有什么区别？

load average 反映一段时间内系统中可运行任务和不可中断睡眠任务的数量，Linux 下主要对应 R 状态和 D 状态；CPU 使用率描述 CPU 时间具体花在用户态、内核态、I/O wait、中断、空闲或虚拟化 steal 等位置。

load 高既可能是可运行任务在争抢 CPU，也可能是大量任务在等待块设备、网络存储、文件系统或 Swap，后一种情况下 CPU 仍可能有空闲。判断 load 还要结合逻辑 CPU 数：同样是 load 8，对 1 个逻辑 CPU 和 64 个逻辑 CPU 的压力完全不同。

LRU 缓存的实现原理讲一下。

回答：

LRU 表示 Least Recently Used，淘汰最近最少使用的数据。它基于一个假设：最近被访问的数据未来更可能再次被访问。

经典实现是 HashMap + 双向链表。HashMap 负责 O(1) 查找 key 对应的节点；双向链表维护访问顺序，链表头表示最近访问，链表尾表示最久未访问。

get 操作时，如果 key 不存在，返回空；如果存在，通过 HashMap 找到节点，把节点移动到链表头，然后返回 value。put 操作时，如果 key 已存在，更新 value 并移动到链表头；如果 key 不存在，创建新节点插入链表头，并写入 HashMap。如果容量超过限制，就删除链表尾节点，并从 HashMap 中移除。

双向链表的作用是支持 O(1) 删除任意节点和 O(1) 插入头部；HashMap 的作用是 O(1) 定位节点。两者结合才能让 get 和 put 都是 O(1)。

工程上要注意并发安全、容量为 0、更新已有 key、淘汰回调、过期时间、内存估算等问题。Redis 的近似 LRU 不是严格 HashMap + 双链表，而是采样淘汰；本地缓存如 Java LinkedHashMap 或 Go list+map 可以实现严格 LRU。

MAE 为什么对应 Laplace 噪声假设？

假设误差服从 Laplace 分布：

\[ y=f_{\theta}(x)+\epsilon,\quad \epsilon\sim\text{Laplace}(0,b) \]

Laplace 密度：

\[ p(y|x;\theta)=\frac{1}{2b}\exp\left(-\frac{|y-f_{\theta}(x)|}{b}\right) \]

负对数似然：

\[ -\log p(D|\theta) =\sum_i\left[\log(2b)+\frac{|y_i-f_{\theta}(x_i)|}{b}\right] \]

若 \(b\) 固定，忽略常数和比例系数：

\[ \theta^*=\arg\min_{\theta}\sum_i |y_i-f_{\theta}(x_i)| \]

这就是 MAE。

结论：

MAE 等价于假设观测误差服从 Laplace 分布时的最大似然估计。

MSE 与 MAE 对比：

  • MSE 对大误差更敏感，优化更平滑。
  • MAE 对异常值更鲁棒，但在 0 点不可导，实践中可用 Smooth L1/Huber Loss 折中。

Huber Loss：

\[ L_{\delta}(r)= \begin{cases} \frac{1}{2}r^2, & |r|\le\delta \\ \delta(|r|-\frac{1}{2}\delta), & |r|>\delta \end{cases} \]

Mask-based 和 Mask-free 虚拟换衣路线有什么差异？

Mask-based 方法把换衣区域视作 inpainting 区域：

\[ I_{\text{out}} = G(I_{\text{person}}\odot(1-M), I_{\text{cloth}}, M, c) \]

优点是目标区域明确；缺点是依赖人体解析和 mask 质量，mask 过大容易丢失人体/头发/手臂信息，mask 过小则衣服替换不完整。

Mask-free 方法不显式依赖二值换衣 mask，而是通过服装编码、人体姿态和注意力对齐来生成穿着效果。优点是保留原图信息更好，缺点是对齐更难，训练数据要求更高。

实践中常用混合方案：

粗 mask 提供区域先验，服装 encoder 提供纹理，pose/densepose 提供几何，扩散模型负责细节生成和融合。

MLLM 端到端方案与传统 OCR 管线如何对比与融合？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

传统 OCR 管线分段优化检测、识别和版面分析，速度快且错误可以定位；MLLM 端到端方案一次读完整页，复杂版面上更稳，但会把看不清的数字补错。实际系统多采用两者融合的形态，如图 6-7 所示。三条路线的特点分别是：

  1. 传统管线。 文本检测、行识别、版面与阅读顺序分别优化，检测有 DBNet 一类方法，识别从 CRNN 发展到 SVTR。它的优点是速度快，错误可以定位到具体环节再修复；缺点是级联误差会累积，多栏混排、表格嵌图、印章覆盖文字等复杂版面的结构还原一直是难点。

  2. 端到端。 端到端模型一次前向读完整页，输入整页图像，直接输出 Markdown、LaTeX 或 HTML 表格。GOT-OCR2.0 是约 580M 参数的专用模型[12]，Qwen3-VL 是通用 MLLM 的代表[13]。这类模型对复杂版面更稳，语义先验能纠正模糊字符，还可以直接接着做文档问答；但同样的先验会把看不清的数字补成通顺的错误值，即 5.6.1.3 中的抄写幻觉，字符级精度也缺少传统管线那种按框可查的保证。单页成本高于传统管线，具体差距取决于批量和硬件。

  3. 融合。 公开的融合形态至少有三种，另有一种工程上的双通道做法。MinerU 初版是由版面检测、公式检测与识别、表格识别和专用 OCR 组成的流水线[29]。MinerU2.5 采用由粗到细的两阶段解析，先在降采样的整页上分析版面，再按版面结果从原图裁取原分辨率区域做内容识别[30]。olmOCR 走端到端路线，用微调后的 Qwen2-VL-7B 把页面图像直接转写为线性化的纯文本[31]。工程上的双通道做法是在端到端输出之外，用专用 OCR 复核金额、证件号等关键字段，两条通道结果不一致时转人工。选型上，自由格式的文档问答用端到端方案，高精度的结构化录入用融合方案或双通道复核，海量的简单版面仍由传统管线处理。

图 6-7 文档解析路线对照示意图

面试速答：传统 OCR 分段完成检测、识别和版面分析，速度快、错误易定位，但复杂版面会累积误差。端到端模型一次读整页，GOT-OCR2.0 和 Qwen3-VL 是两种规格，抗复杂版面，但可能把数字识别错。融合形态中，MinerU 初版是专用模型流水线，MinerU2.5 先看版面再裁原图，olmOCR 直接转写全文。

MLLM的模态接口有哪些主要类型？它们各自的工作原理是什么？

MLLM的模态接口主要有两种类型：投影式连接器和查询式连接器。

  • 投影式连接器：这种连接器的核心思想是将编码器输出的特征转换为标记（tokens），然后将这些标记与文本标记一起发送到LLM中。具体实现上， 通常会使用一组可学习的查询标记来提取信息，这种方式最初在BLIP-2中实现，并随后被多种工作继承和改进。 例如，Q-Former风格的连接器通过压缩视觉标记来减少表示向量的数量。
  • 查询式连接器：这种连接器通过一个线性MLP将视觉标记投影到与词嵌入对齐的特征空间中。例如，LLaVA系列使用一个或两个线性MLP来实现这一点。

此外，还有一种融合式连接器，它允许在LLM内部进行特征级融合。例如，Flamingo在LLM的冻结Transformer层之间插入额外的交叉注意力层， 从而增强语言特征与外部视觉线索的结合。

MSE 为什么对应高斯噪声假设？

假设回归标签由真实函数加高斯噪声得到：

\[ y=f_{\theta}(x)+\epsilon,\quad \epsilon\sim\mathcal{N}(0,\sigma^2) \]

则条件概率为：

\[ p(y|x;\theta)=\frac{1}{\sqrt{2\pi\sigma^2}}\exp\left(-\frac{(y-f_{\theta}(x))^2}{2\sigma^2}\right) \]

对数据集取负对数似然：

\[ -\log p(D|\theta) =-\sum_i \log p(y_i|x_i;\theta) \]

代入高斯密度：

\[ -\log p(D|\theta) =\sum_i \left[\frac{(y_i-f_{\theta}(x_i))^2}{2\sigma^2}+\frac{1}{2}\log(2\pi\sigma^2)\right] \]

若 \(\sigma\) 固定，与 \(\theta\) 无关的常数项可忽略：

\[ \theta^*=\arg\min_{\theta}\sum_i (y_i-f_{\theta}(x_i))^2 \]

这就是 MSE。

结论：

MSE 等价于假设观测误差服从同方差高斯分布时的最大似然估计。

NeRF 的核心思想是什么？

NeRF，全称 Neural Radiance Fields，是一种用神经网络表示三维场景辐射场的方法。它学习一个函数：

\[ F_\theta(x, d) = (\sigma, c) \]

其中：

  • \(x\) 是三维空间位置。
  • \(d\) 是观察方向。
  • \(\sigma\) 是体密度。
  • \(c\) 是该位置在该方向下的颜色。

对一条相机射线 \(r(t)\)，像素颜色通过体渲染积分得到：

\[ C(r)=\int_{t_n}^{t_f} T(t)\sigma(r(t))c(r(t),d)dt \]
\[ T(t)=\exp\left(-\int_{t_n}^{t}\sigma(r(s))ds\right) \]

NeRF 的核心价值是：用多视角图像监督一个连续三维函数，从而实现高质量新视角合成。

数字人场景中的 NeRF 常见变体：

  • 静态头部 NeRF：适合高保真人头新视角。
  • 动态 NeRF：增加时间或形变场，表示表情和动作。
  • 条件 NeRF：用音频、表情参数、骨骼或 SMPL 条件控制。
  • Avatar NeRF：将人物绑定到 canonical space，再通过形变场映射到观察空间。

NVTX 标记如何嵌入应用代码并与 Nsight Systems 联动分析？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐ (3/5)

一、NVTX 的作用

NVTX（NVIDIA Tools Extension）是 NVIDIA 提供的轻量级标记库，可以在代码中插入自定义标签，这些标签会显示在 Nsight Systems 的 Timeline 上：

没有 NVTX 的 Timeline：
  [一串无差别的 Kernel 序列……]

有 NVTX 标记的 Timeline：
  [预处理]|[推理-Encoder]|[推理-Decoder]|[后处理]
   ↑ 清晰的语义分段

二、NVTX 的使用方式

Python（torch.cuda.nvtx）：

import torch

# 方式 1：上下文管理器
with torch.cuda.nvtx.range("preprocessing"):
    input_tensor = preprocess(image)

# 方式 2：显式 push/pop
torch.cuda.nvtx.range_push("inference")
output = model(input_tensor)
torch.cuda.nvtx.range_pop()

# 方式 3：带分类标记
torch.cuda.nvtx.range_push("inference:decoder")

C++（原生 NVTX API）：

#include <nvtx3/nvToolsExt.h>
nvtxRangePushA("inference");
// ... 推理代码 ...
nvtxRangePop();

三、与 Nsight Systems 联动

使用 NVTX 标记后，用 Nsight Systems 采集时需添加 --nvtx 参数：

nsys profile -t cuda,nvtx,osrt --nvtx-include "inference*" python app.py

在 Nsight Systems GUI 中，NVTX 标记会以彩色横条出现在 Timeline 上，与 CUDA Kernel、Memcpy 等事件对齐，直观展示应用逻辑分段。

四、实战中的 NVTX 标记策略

# 推荐：按推理阶段标记
with torch.cuda.nvtx.range("pipeline:preprocess"):
    ...
with torch.cuda.nvtx.range("pipeline:inference"):
    with torch.cuda.nvtx.range("encoder"):
        ...
    with torch.cuda.nvtx.range("decoder"):
        ...
with torch.cuda.nvtx.range("pipeline:postprocess"):
    ...

这样在 Nsight Systems 中就能精确看到每个阶段的起止时间、GPU 活动情况和各阶段之间的时间关系。

可以总结为：NVTX 是连接应用逻辑和底层工具的关键桥梁。通过给关键代码段打标记，Nsight Systems 的 Timeline 从"无差别的 Kernel 序列"变成了"有语义的推理阶段"，极大提升了分析效率。面试中展示 NVTX 的使用经验说明有实际工程调优能力。

observation / action 如何建模

回答：

observation 要让策略获得完成任务所需的信息，同时避免把训练时可见、部署时拿不到的信息泄漏进去。常见输入包括外部/腕部相机、深度、关节位置与速度、末端位姿、夹爪状态，以及任务语言；触觉和力信息按硬件与任务选择。

观测的时间同步、相机标定和历史窗口很重要。单帧图像可能无法区分速度和运动方向，部分可观测任务可利用历史、递归状态或显式估计，但会增加计算和数据要求。

动作表示 优点 需要明确的契约
关节目标或增量 接近机器人接口 关节顺序、单位、极限和控制模式
末端位姿/增量 便于描述操作几何 世界/基座/末端坐标系、IK 与可达性
速度或力矩 更直接影响动态过程 控制频率、稳定性和约束更严格
夹爪命令 描述开合或连续位置 正负约定、范围、迟滞和执行延迟

旋转可用四元数、轴角或其他连续表示，不同表示有归一化、符号等价或奇异性问题，不能按普通欧氏量随意混用。动作标准化与反标准化的统计和轴顺序必须一致。

跨机器人迁移还需处理形态、工作空间与控制器差异。“动作维度相同”只说明数组形状一致，不能说明物理语义一致。

坐标系是最值得现场举例的工程细节。 令 $T^B_E$ 表示把末端坐标表达转换到基座坐标表达的位姿矩阵。若增量被定义为基座系中的左乘刚体变换，组合为：

T^{B\prime}_E=\Delta T_B T^B_E.

若增量被定义为末端局部系中的右乘刚体变换，则组合为：

T^{B\prime}_E=T^B_E\Delta T_E.

两个式子对应不同动作契约，旋转和平移一般不满足交换律。实际接口也可能规定“基座系平移直接相加、姿态单独更新”，这时必须按该接口实现，不能照搬完整左乘变换。面试中应把矩阵约定和控制器要求一起说清楚。

夹爪也不宜被当成普通连续维度随意平均：有些数据用开/闭二值，有些用宽度、位置或力目标。旋转四元数存在正负号等价，先统一符号或采用适当的旋转距离，再讨论损失与插值，否则几何上相近的姿态可能出现很大的数值误差。

OCR如何处理复杂表格

回答：

复杂表格 OCR 至少包含文字识别、表格结构恢复和语义映射三项任务。先定位表格区域，检测文字与单元格，再推断行列、跨行跨列、表头和阅读顺序，最后把文字填入结构化单元格。
