声明、定义、链接与ODR

常见问法：声明和定义有什么区别；头文件里能否定义变量和函数。

声明把名称和类型等信息引入程序，定义则提供对象、函数或类等实体所需的完整内容。一个程序通常由多个翻译单元分别编译再链接，链接属性影响同名声明是否指向同一实体；单一定义规则约束这些实体如何在程序中出现。

头文件会被每个包含它的翻译单元处理，因此普通外部变量或非 inline 函数的重复定义可能产生冲突。模板、inline 函数和 C++17 的 inline 变量具有特定的多定义规则，不能用“头文件绝对不能定义任何内容”概括。声明可以让调用通过编译，链接阶段仍可能因缺少定义或签名不匹配而失败。

参考资料：规范或原始文档校核。

const、constexpr与常量表达式

常见问法：const和constexpr有什么区别；const修饰指针和成员函数有什么作用。

const 约束通过该类型接口进行修改，constexpr 还用于表达可参与常量求值的对象或函数。const 对象的初始化值可以到运行期才确定，因此 const 不自动意味着编译期常量；constexpr 函数也不表示每次调用都必须在编译期执行，是否常量求值取决于调用语境和参数。

const T 约束经指针修改目标，T const 约束指针本身重新指向；顶层 const 的值参数不构成不同函数签名。const 成员函数约束通过 this 修改通常的成员，但 mutable 等机制有明确例外。去掉类型上的 const 不代表修改原本就是 const 的对象合法，后者可能触发未定义行为。

参考资料：forthespada/InterviewGuide：const关键字的作用有哪些?。

static的不同语境

常见问法：static变量与普通变量有什么区别；局部static初始化是否线程安全。

static 的含义依附于声明位置：局部静态对象具有静态存储期；命名空间作用域的 static 名称通常具有内部链接；静态数据成员属于类而不属于某一个实例；静态成员函数没有普通的 this 对象参数，因此不能直接访问某个实例的非静态成员。

C++11 起，函数局部静态对象的首次初始化有并发进入时的语言保证，但这只保护初始化过程，不自动保护之后对对象的可变访问。静态对象还需要考虑销毁次序与跨翻译单元初始化依赖，不能仅凭“全局可用”忽略生命周期。

参考资料：规范或原始文档校核。

指针、引用与悬空访问

常见问法：指针和引用有什么区别；引用一定比指针安全吗。

指针是可以保存地址等值的对象，可以重新赋值；引用在正常绑定后作为已有对象的别名使用，不能通过赋值重新绑定。语法上的简便不能消除生命周期要求：返回局部对象的引用、引用已经销毁的对象、保存 vector 扩容前的元素地址，都可能导致悬空访问。

合法引用应绑定到满足使用条件的对象，但引用并不自动拥有对象，也不自动延长任意对象的生命周期。需要表达“可能没有对象”时可使用可空指针等明确类型；需要表达独占所有权时应用所有权类型，而不是仅在指针和引用之间换写法。

参考资料：forthespada/InterviewGuide：指针和引用的区别；规范或原始文档校核。

显式类型转换与运行时检查

常见问法：四种C++类型转换如何选择；dynamic_cast什么时候失败。

static_cast 表达一类受语言规则约束的显式转换，但不提供一般运行时类型检查；dynamic_cast 用于受支持的多态类型关系，向下或交叉转换可以检查运行时对象类型。指针形式失败返回空指针，引用形式失败会抛出 std::bad_cast。

const_cast 调整限定符，但不能据此合法修改原本为 const 的对象；reinterpret_cast 表达更底层的重解释，之后的访问仍必须满足对象类型、对齐和生命周期规则。C 风格转换把多类意图混合在一个语法里，难以审查；选择命名转换能明确意图，却不意味着转换后的每一次使用都会自动安全。

参考资料：规范或原始文档校核。

对象生命周期与存储期

常见问法：对象存在和内存已分配有什么区别；栈对象和堆对象怎样销毁。

存储说明一片内存何时可用，生命周期说明某个类型的对象何时在其中有效存在。分配了足够空间，并不总等于已经构造出可正常使用的类对象；反过来，对象析构后，相关存储也可能尚未释放或稍后被其他对象复用。

自动、静态、线程和动态存储期决定不同的存储管理路径。日常所说的“栈、堆、全局区”是常见实现视角，不是 C++ 对所有平台统一规定的内存地图。判断访问是否合法时，要同时看目标对象是否仍在生命周期内、类型与权限是否合适，而不仅看地址是否还映射在进程里。

参考资料：规范或原始文档校核。

new/delete与malloc/free

常见问法：new和malloc有什么区别；delete和delete数组有什么区别。

malloc/free 管理原始存储，不自动运行普通 C++ 类的构造与析构；new 表达式通常先取得存储再初始化对象，delete 表达式在相应条件下先析构再释放。operator new 是可定制的分配函数，与完整的 new 表达式不应混为一谈。

通常的抛出式 new 在分配失败时抛出 std::bad_alloc，nothrow 形式另有约定。资源必须按匹配方式释放，不能混用 malloc 与 delete，也不能把 new[] 获得的数组交给普通 delete。构造函数抛异常时，已经成功构造的子对象会按规则清理，尚未构造完成的整体对象不会正常执行其析构函数。

参考资料：forthespada/InterviewGuide：new / delete 与 malloc / free的异同。

RAII与异常安全

常见问法：RAII如何管理资源；异常发生时怎样避免资源泄漏。

RAII 把资源所有权绑定到对象生命周期：对象成功构造后，析构负责释放，作用域退出和异常栈展开便沿同一条清理路径运行。资源不只包括内存，也可以是锁、文件、连接和句柄；std::unique_ptr 与 std::lock_guard 是典型工具。

异常安全要先明确保证等级：基本保证维持不变量且不泄漏，强保证在失败时不产生可见状态改变，no-throw 保证不抛异常。RAII 解决释放责任，但业务状态更新仍可能需要先准备后提交等结构。析构函数通常不应向外抛出异常，尤其不能在异常传播期间再次逃逸异常。

参考资料：forthespada/InterviewGuide：使用智能指针管理内存资源，RAII是怎么回事？。

拷贝控制与零规则

常见问法：浅拷贝为什么会重复释放；拷贝构造和拷贝赋值有什么区别。

拷贝构造初始化一个新对象，拷贝赋值修改已经存在的对象，两者面对的资源状态不同。若类直接拥有一个原始资源句柄，默认逐成员复制可能让两个对象都认为自己负责释放，进而重复释放或悬空；正确策略取决于是否允许复制以及复制应共享还是独立拥有资源。

优先用标准容器和所有权类型封装资源，让编译器生成成员函数，即零规则。必须自管资源时再统一考虑析构、拷贝与移动操作，避免只补一个析构函数却留下错误的复制语义。深拷贝不是所有类的统一答案，shared_ptr 有意共享，unique_ptr 则禁止普通复制。

参考资料：forthespada/InterviewGuide：浅拷贝和深拷贝的区别。

移动语义、右值引用与stdmove

常见问法：stdmove真的移动对象了吗；为什么右值引用变量仍可能是左值。

移动语义允许把可转移资源从一个对象交给另一个对象，减少不必要的深复制。std::move 本质上是一次值类别转换，使表达式可以参与右值相关重载选择；是否真的移动，由所选构造或赋值函数决定，没有合适移动操作时也可能调用复制。

一个有名字的右值引用变量作为表达式仍是左值，继续转移它往往需要显式表达意图。移动后的标准库对象通常仍然有效，但状态可能未指定；不能统一断言“必为空”或“不能再用”。对 const 对象做 move 通常也不能匹配要求可修改源对象的常见移动构造。

参考资料：forthespada/InterviewGuide：说说移动构造函数。

转发引用与完美转发

常见问法：T双引用为什么不一定是普通右值引用；stdforward和stdmove有什么区别。

模板类型推导中的特定 T&& 形参可以成为转发引用，接收左值时推导与引用折叠会保留左值性质，接收右值时则保留右值性质。它与一个固定类型的右值引用不同，不能只看两个 & 就断言只能绑定右值。

std::forward(x) 根据推导出的 T 恢复调用者传入的值类别，适用于把参数继续交给下一层；std::move 则统一表达可以从该对象取走资源的意图。完美转发保持的是相关类型与值类别信息，不会自动延长悬空对象寿命，也不能任意反复转发一个已经被消费的参数。

参考资料：规范或原始文档校核。

智能指针与所有权

常见问法：unique_ptr和shared_ptr如何选择；weak_ptr怎样解决循环引用。

unique_ptr 表达独占所有权，不能普通复制但可以移动；shared_ptr 用控制块记录共享所有权，最后一个强引用消失时销毁所管理对象。weak_ptr 观察共享对象但不增加强引用计数，使用前通过 lock 获取有效的共享所有权，适合打破不应拥有彼此的关系。

控制块上的并发引用计数管理，不意味着被指向对象的数据访问线程安全，也不意味着任意并发读写同一个 shared_ptr 变量都自动安全。不能为同一个裸指针各自创建独立控制块，否则可能重复释放。选择共享所有权应有真实的生命周期需求，而不是把 shared_ptr 当成默认万能指针。

类型 所有权 常见使用
unique_ptr 独占，可移动 单一释放责任、工厂返回资源
shared_ptr 共享强引用 多个主体确实共同决定寿命
weak_ptr 非拥有观察 打破拥有环、异步执行前检查对象

参考资料：forthespada/InterviewGuide：智能指针出现循环引用怎么解决？。

虚函数、动态绑定与对象切片

常见问法：C++多态如何实现；虚函数表是不是语言标准要求。

通过合适的基类指针或引用调用虚函数时，可以根据对象的动态类型选择最终覆盖函数，这让调用方依赖接口而非具体派生类型。常见实现用虚表和虚表指针支持分派，但标准规定的是行为，并不要求所有实现使用同一内存布局。

把派生对象按值拷贝成基类对象会发生切片，派生部分不再属于这个新对象，不能期待它继续表现为原派生类型。重载依赖参数与编译期选择，覆盖要求满足虚函数覆盖规则，二者不能混淆。可用 override 让编译器检查覆盖意图，减少签名不匹配。

参考资料：forthespada/InterviewGuide：C++的多态如何实现。

构造析构顺序与虚析构

常见问法：构造函数里调用虚函数会怎样；基类析构函数何时需要virtual。

对象先构造基类与成员，再进入自身构造函数体；成员按声明顺序初始化，而非初始化列表的书写顺序。析构按相反层次展开。构造或析构期间的虚调用，不能按“已经完整存在的最派生对象”来推断，分派受当前构造析构阶段限制。

若允许通过基类指针删除派生对象，通常需要虚析构函数，使销毁行为覆盖完整对象。对不满足相应规则的对象直接经非虚基类析构路径 delete，在常见讨论条件下是未定义行为，不能仅描述成“一定只析构基类，所以只是漏一点内存”。并非所有类都必须有虚析构，关键在接口是否支持这种多态销毁。

参考资料：forthespada/InterviewGuide：为什么析构函数一般写成虚函数；规范或原始文档校核。

继承、组合与菱形结构

常见问法：public继承表达什么关系；虚继承解决什么问题。

公有继承通常用于表达可替换的接口关系，派生对象应满足基类操作的约定；组合把另一对象作为成员，适用于实现复用但不承诺可替换性的场景。访问权限影响成员可见性，不能只用“继承可以复用代码”解释设计选择。

多继承中两条路径可能各自包含一份相同基类子对象；虚继承可以让相应路径共享虚基类子对象，解决特定的重复状态与歧义问题，同时增加初始化与布局复杂度。虚继承与虚函数是不同机制，前者处理基类子对象关系，后者处理动态分派。

参考资料：forthespada/InterviewGuide：什么是虚拟继承。

模板、实例化与特化

常见问法：模板代码什么时候生成；模板为什么常放在头文件。

模板描述一族类型或函数，编译器在需要具体实例时用模板参数进行替换、检查和生成相关实体。模板既支持类型参数，也支持受规则约束的非类型参数等形式；重载、特化与约束影响最终选择，并非把文本像宏一样无条件替换。

实例化需要看到足够的定义，因此常把模板定义放在头文件，或者明确组织显式实例化。模板编译错误可能来自依赖名称、推导、重载或实例化时语义，不应全部归咎于语法难读。泛型设计应把合法操作与不变量表达清楚，避免让错误直到很深的实例化链才暴露。

参考资料：forthespada/InterviewGuide：模板会写吗？写一个比较大小的模板函数。

vector的容量、扩容与摊还复杂度

常见问法：vector扩容为什么会使指针失效；reserve和resize有什么区别。

vector 提供连续元素存储，size 是已构造元素数，capacity 是无需重新分配便可容纳的元素数。reserve 预留容量而不直接增加元素数，resize 改变元素数，并按要求构造或销毁元素。扩容时通常需要取得新存储并转移已有元素，旧地址因而失效。

连续存储支持高效随机访问与较好的局部性；中间插入删除通常需要移动后续元素。尾部追加可具有摊还常数复杂度，但一次触发扩容的操作仍可能很昂贵。增长倍率是实现策略，不是所有标准库统一固定的 1.5 或 2；预估容量有助于减少重分配，但过度预留也会增加内存占用。

参考资料：forthespada/InterviewGuide：STL中vector的实现。

list、deque与容器选择

常见问法：链表一定比数组更适合插入删除吗；deque和vector怎样选择。

list 以节点方式组织元素，已知合法位置的插入删除可以不移动其他元素，但定位第 n 个元素通常需要遍历，节点还有指针和分配开销。deque 支持高效两端操作与随机访问，常见实现使用分段存储，不能假定整个序列物理连续。

选择要同时计算定位、修改和遍历成本。若先遍历寻找删除位置，链表的常数修改优势可能抵不过缓存不友好和分配成本；顺序读取与随机访问往往适合 vector。容器的引用稳定性和迭代器稳定性还可能不同，需要按具体操作查规则，而不是只用“是否连续”推断。

参考资料：规范或原始文档校核。

有序关联容器与哈希容器

常见问法：map和unordered_map有什么区别；哈希表一定比平衡树快吗。

有序关联容器维护键的排序关系，支持按序遍历与范围操作，查找等通常有对数复杂度保证；标准不强制 map 必须采用某一种特定树实现。unordered_map 按哈希组织，平均查找可为常数，但受哈希质量、冲突、负载因子和重哈希影响，最坏情况不同。

哈希容器需要哈希与相等关系配合：认为相等的键必须产生一致的哈希结果。键参与排序、哈希或相等比较的部分不能被随意修改，否则破坏容器结构的前提。需要有序范围、最坏复杂度或稳定行为时，不能仅按平均大 O 选择哈希表。

参考资料：forthespada/InterviewGuide：STL中unordered_map和map的区别和应用场景。

迭代器、引用和失效规则

常见问法：STL迭代器什么时候失效；erase循环怎样避免使用失效位置。

迭代器失效来自容器结构或元素生命周期改变。vector 重新分配时，指向原元素的迭代器、指针和引用失效；不重新分配的中间插入会使插入点及其之后的相关位置失效。删除元素时，删除位置及后续位置同样需要按规则处理。

节点式容器删除一个节点通常不使其他节点的迭代器失效，哈希容器重哈希又有单独的迭代器规则。不要把 list、deque、vector 与 unordered_map 归为同一种失效行为。循环删除时，使用 erase 返回的后继位置或遵循该容器的安全遍历方式；“指针数值还没变”并不能证明对象仍可访问。

参考资料：forthespada/InterviewGuide：STL中迭代器失效的情况有哪些？。

string、字符串视图与借用寿命

常见问法：string与char指针有什么区别；string_view为什么可能悬空。

std::string 是拥有字符存储的字符串对象，负责容量与生命周期；char* 只是一种指针类型，本身不表达内存归谁所有、长度是多少或是否允许修改。字符串字面量不应被当作可写缓冲区，C 风格接口还需要明确终止符与边界。

string_view 是带长度的非拥有视图，不自动复制或延长所引用字符的寿命。返回指向局部 string 的视图、保存临时字符串生成的视图，都会产生悬空风险；源 string 的某些修改也可能使视图所指存储失效。减少复制的前提是借用关系和失效边界清楚。

参考资料：forthespada/InterviewGuide：C++中新增了string，它与C语言中的 char *有什么区别吗？它是如何实现的？。

对齐、填充与对象布局

常见问法：sizeof结构体为什么大于成员大小之和；alignas和alignof有什么作用。

对象地址必须满足类型的对齐要求，编译器可能在成员之间和对象末尾添加填充，以满足成员放置与数组中相邻对象的要求。因此 sizeof 不一定等于成员大小相加；最大成员的大小也不总能直接当成整个类型的对齐值。

alignof 查询对齐要求，alignas 可以在合法范围内指定对齐，但不能把类型要求强行弱化成不合规布局。具体大小还受 ABI、成员类型、继承与编译选项影响。压缩结构体用于外部二进制协议时要格外谨慎：布局、字节序和未对齐访问都应明确，不能直接把任意内存对象等同于可移植线格式。

参考资料：forthespada/InterviewGuide：结构体内存对齐问题？；规范或原始文档校核。

数据竞争、原子与happens-before

常见问法：原子操作为什么还需要内存序；volatile能实现线程同步吗。

多个执行线程访问同一内存位置，至少一个修改，并且在相应条件下缺少必要同步，会形成数据竞争；C++ 程序不能依靠“测试时没出错”来接受这种行为。原子类型提供单个操作的原子访问，复合业务不变量则可能仍需锁或专门协议。

happens-before 描述必须被程序观察到的先后关系。release 发布与读到该发布的 acquire 获取可以建立同步，relaxed 原子主要保证相关原子访问而不自动发布其他普通内存。volatile 用于特定可观察访问语义，不提供一般线程互斥或内存发布保证。除非能清楚证明更弱顺序正确，优先采用易于推理的锁或默认原子顺序。

参考资料：规范或原始文档校核。

lambda捕获与异步生命周期

常见问法：lambda按值和按引用捕获有什么区别；捕获this为什么可能悬空。

lambda 的闭包对象保存所需捕获状态。按值捕获通常保存相关值，按引用捕获借用已有对象；捕获指针的值只复制地址，不会把指向对象也自动复制或拥有。把 lambda 交给异步任务时，调用可能晚于原作用域结束，借用对象就可能已经不存在。

捕获 this 通常借用了当前对象的地址，不能据此保证成员访问时对象仍存活。需要异步延续寿命时应明确所有权，或使用弱引用在执行时检查，避免无意共享所有权形成环。捕获方式要按对象寿命和并发访问规则选择，不要只为了省复制就普遍使用引用捕获。

参考资料：规范或原始文档校核。

未定义行为与调试证据

常见问法：未定义行为为什么可能看似正常；越界和释放后使用怎样定位。

未定义行为表示标准不再对该次程序行为施加相应要求，例如某些越界、悬空访问、错误别名或数据竞争。它可能崩溃、悄悄损坏数据，也可能暂时表现正常；优化器可以依据合法程序的前提推理，因此切换优化等级后结果变化并不奇怪。

调试应缩小触发条件并观察对象生命周期、边界和线程交错。编译器警告、地址或未定义行为检测器、线程检测器等能发现不同类别的问题，但一次运行没有报告不证明程序必然正确。资源泄漏与悬空访问也不是一回事：前者通常是所有权丢失，后者是在寿命结束后继续访问。

编译、静态链接与动态链接

常见问法：源码到可执行文件经过什么；静态库和动态库怎样选择。

常见构建过程包含预处理、编译、汇编和链接，各阶段分别处理头文件与宏、语言语义、目标代码以及符号与重定位。静态库通常是目标文件集合，链接器按规则把需要部分纳入最终程序；动态库则让程序在装载或运行时通过动态链接机制使用共享目标。

静态与动态链接在部署依赖、更新方式、加载和共享成本上取舍，并非“静态必快、动态必省”。二进制兼容还依赖 ABI、编译选项、运行库和导出接口。extern "C" 调整适用声明的语言链接规则，常用于连接 C 接口，但不会把 C++ 类对象布局自动变成跨语言通用格式。
