简单介绍 SFT 的训练流程，并比较 PPO、DPO 和 GRPO 的区别。

回答：

SFT 使用高质量的指令-回答或多轮轨迹做教师强制训练。流程包括定义能力目标、采集与清洗数据、统一消息模板与 tokenizer、控制长度与样本权重、训练并监控 loss/梯度，再用去重后的能力集、安全集和业务集评测。其目标通常是对答案 Token 做交叉熵：

\[ \mathcal{L}_{\mathrm{SFT}}=-\sum_t \log \pi_\theta(y_t\mid x,y_{<t}) \]

PPO 属于在线策略优化。模型采样回答，经奖励模型或可验证奖励打分，critic 估计价值/优势，使用 clipped objective 限制策略更新，并通过 KL 约束避免偏离参考模型。优点是可直接优化序列级奖励，缺点是需要采样、reward/reference/critic 等组件，训练复杂且容易受奖励漏洞影响。

DPO 用同一 Prompt 的 chosen/rejected 偏好对直接优化策略相对参考模型的偏好，不显式训练 reward model 和 critic。它实现简单、稳定、适合离线偏好数据，但受数据覆盖和偏好质量限制，也不能天然解决分布外探索。

GRPO 对同一 Prompt 采样一组回答，用组内奖励的相对位置或标准化值估计优势，通常不依赖单独 critic，从而降低大模型 RL 的价值模型成本。它适合有可验证奖励、能产生多样候选的推理任务，但增加组采样成本，并依赖奖励区分度、组大小和方差控制。

四者不是简单替代：SFT 建立基本行为，DPO 适合离线偏好对齐，PPO/GRPO 适合需要在线采样与序列级优化的阶段。选择要看奖励可得性、算力、探索需求和稳定性。

简述预训练基础模型的四种主要学习机制，并分析它们各自的优缺点

预训练基础模型的四种主要学习机制包括：

有监督学习：使用标注数据进行训练，模型需要学习输入和输出之间的映射关系。

半监督学习：使用少量标注数据和大量未标注数据进行训练，模型需要学习输入和输出之间的潜在关系。

弱监督学习：使用少量标注数据和大量未标注数据进行训练，但标注数据仅提供部分信息，例如图像中的某些区域或文本中的某些单词。

自监督学习：使用未标注数据进行训练，模型需要学习数据中的内在结构，例如图像中的纹理或文本中的语法规则。

算子优化常见两类瓶颈是什么

回答：

经典分类是 compute-bound 与 memory-bound。前者主要受计算单元吞吐或指令执行能力限制，后者主要受某一级存储的数据搬运限制；带宽不足与内存访问延迟无法被隐藏也要进一步区分。

判断需要看算术强度、实测吞吐、流量、缓存命中、并行度和 stall，而非只凭算子名字。相同 GEMM 在大 batch 与极小 batch 下可能处于不同区域；同一 attention 的 prefill 与 decode 也不必有相同瓶颈。

计算受限时关注 Tensor Core/向量化、形状适配、减少冗余指令；内存受限时关注合并访问、缓存复用、融合和数据量。融合也可能增加寄存器压力，所以需要评估新的资源平衡。

这两类并不穷尽服务问题。kernel launch、同步、通信、CPU 排队、串行依赖及并行度不足可能让计算和带宽都不饱和，此时强行二选一会误导优化。

算法题：lc70 爬楼梯（送分，3分钟写出滚动数组优化）

回答：

若一次可爬 1 或 2 阶，到达第 $n$ 阶的最后一步来自第 $n-1$ 或 $n-2$ 阶，两种情况不相交，所以 $f(n)=f(n-1)+f(n-2)$。取 $f(0)=1,f(1)=1$，其中零阶的一种方式表示不行动。

def climb_stairs(n):
    if not isinstance(n, int) or isinstance(n, bool) or n < 0:
        raise ValueError("n must be a nonnegative integer")
    prev, curr = 1, 1
    for _ in range(2, n + 1):
        prev, curr = curr, prev + curr
    return curr

n=1,2,3,5 分别返回 1,2,3,8。每轮只依赖两个旧状态，因此无需长度为 n 的数组。常规固定成本整数模型下时间 $O(n)$、额外状态 $O(1)$；如果 n 极大，精确整数位数和加法成本随 n 增长，需要另算位复杂度，也可按需求使用快速倍增或矩阵方法。

联合训练如何做到纯文本能力不退化？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

「加入视觉必然削弱文本能力」曾是常见判断，5.1.1.2 中 LLaVA-1.5 的 MT-Bench 下降就是缝合路线的例子。2026 年的证据表明退化并非必然，数据课程的形状比是否加入视觉更关键。

从机制上看，退化主要来自训练分布的突变。纯文本阶段收敛到 $p_{\mathrm{text}}$ 之后，如果把混合比 $\alpha$ 由 0 突然提高到 0.5，小批量内的 token 分布会发生跳变，优化轨迹偏离已经形成的文本区域，这与灾难性遗忘的典型过程一致。Kimi K2.5 的学习曲线也显示，从一开始混合的方案文本能力曲线更平稳，后段注入的方案则出现领域迁移带来的冲击[12]。全程保持较小且恒定的 $\alpha$，相当于在 $p_{\mathrm{text}}$ 附近持续施加少量多模态扰动，三种课程的对照见 5.5.3.1。

Kimi K2.5 的文本侧证据需要对应到正确的训练阶段。约 15T 混合 token 的继续预训练建立的是视觉与文本的对齐；纯文本基准的提升出现在其后的视觉强化学习阶段，MMLU-Pro 从 84.7% 提高到 86.4%，GPQA-Diamond 从 84.3% 提高到 86.4%，LongBench v2 从 56.7% 提高到 58.9%[12]。SWE-bench Verified 的 76.8% 是最终模型的成绩，并非继续预训练前后的差值[12]。

工程上有三项做法反复出现：

  1. 纯文本数据流全程保留。 预训练全程保留纯文本数据，避免多模态数据独占某个训练阶段；Kimi K2.5 的早期混合方案中，纯文本始终占混合数据的 90%[12]。

  2. 视觉从早期以低比例进入。 采用 Kimi K2.5 的课程，可以避免后段大剂量多模态数据冲击已经收敛的语言分布。本书认为，分布突变比「视觉占用了模型容量」更能解释这类遗忘。

  3. 稳定 logit。 z-loss 和 QK-Norm 抑制多模态共享权重引起的范数增长，在离散路线上几乎是必要组件，见 5.5.2.1；连续路线的视觉位置不参与 softmax，压力较小，但同样可以沿用。

评估一家厂商的训练配方时，首先要看它是否公布多模态化前后的纯文本基准。Kimi K2.5 公布了视觉强化学习前后的 MMLU-Pro 和 GPQA-Diamond，两项都上升[12]；只报告多模态榜单、不报告纯文本对照的模型，外部无法判断其语言能力是否受损。

面试速答：纯文本能力下降常常是因为视觉数据在训练后段突然占据很大比例，分布跳离了已经收敛的语言区域。Kimi K2.5 从第一步起按约 10% 的视觉比例混合并全程保留文本数据，其后的视觉强化学习还使 MMLU-Pro 从 84.7% 升到 86.4%，GPQA-Diamond 从 84.3% 升到 86.4%。

自回归语言模型的最大似然训练目标是什么？

给定序列 \(x=(x_1,...,x_T)\)，自回归分解：

\[ p_{\theta}(x)=\prod_{t=1}^{T}p_{\theta}(x_t|x_{<t}) \]

最大似然训练等价于最小化负对数似然：

\[ L(\theta)=-\sum_{t=1}^{T}\log p_{\theta}(x_t|x_{<t}) \]

对 batch 求平均后就是常见 Cross Entropy Loss。

Causal mask 的作用：

训练时每个位置只能看见当前位置之前的 token，避免信息泄露：

\[ \text{mask}_{ij}= \begin{cases} 0, & j \le i \\ -\infty, & j > i \end{cases} \]

将 mask 加到 attention logits 后，未来 token 的注意力概率变为 0。

自重构和交叉重构分别训练什么能力？

自重构（Self-Reconstruction）：

从同一个视频中取参考帧和目标帧：

\[ (I_{\text{ref}}^A, P_{\text{target}}^A) \rightarrow I_{\text{target}}^A \]

它训练模型保持同一身份和同一场景下的动作迁移能力。

交叉重构（Cross-Reconstruction）：

从不同视频/不同身份中组合参考外观和目标姿态：

\[ (I_{\text{ref}}^A, P_{\text{target}}^B) \rightarrow \tilde{I} \]

它训练模型把任意外观和任意姿态组合，提升泛化能力。

两者配合：

自重构稳定训练，交叉重构避免死记硬背。比例上通常需要从自重构为主逐渐加入交叉任务。

视频切片、去重和镜头切分为什么会直接影响训练效果？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

切片定义了模型看到的基本时间单元，去重则改变了每类内容在训练中的实际权重。二者处理不当，即使原始视频规模很大，有效数据分布也可能已经失真。

第一，clip 边界要符合目标任务。 对单镜头连续生成，clip 通常应落在同一 shot 内，并尽量保留完整动作。若没有切镜条件，却把无关镜头拼进同一 clip，模型看到的只是一次无法解释的时空跳变。多镜头生成或视频编辑可以使用跨镜头样本，但切换位置和语义应被显式建模，不能与连续运动样本混在一起处理。

第二，采样策略要控制时间分布。 帧率、真实时长、动作是否完整以及运动强弱都会改变监督信号。大量静止 clip 会让数据分布偏向低运动，但静止样本并非都该删除：若目标产品包含静态镜头，就应保留合理比例。关键是统计并控制分布，而不是套用统一阈值。

第三，去重要看“有效重复”，不只是文件是否相同。 同一素材可能经过裁剪、转码、加字幕或变速后再次出现。只做文件哈希只能发现完全重复，还需结合感知特征或 clip 表征识别近重复，并按来源或模板做聚类。近重复不只是增加过拟合风险，还会悄悄放大某些主体、风格和动作的采样权重；训练集与验证集之间也要单独检查重复，避免评测偏高。

工程上应同时检查切分准确率与处理后的分布：抽样复核镜头边界的误切和漏切，统计重复簇大小、时长、帧率和运动强度，并在固定验证集上比较清洗前后的结果。这样才能判断过滤规则是在去噪，还是误删了业务需要的长尾样本。

面试速答：切片决定模型学习什么样的时间变化，去重决定不同内容在训练中的实际权重。单镜头任务通常要求 clip 不跨无关切镜并尽量覆盖完整动作；采样还要控制时长、帧率和运动分布。去重则要从完全重复扩展到转码、裁剪和模板化近重复，同时防止训练集与验证集交叉污染。

判断视频训练是否稳定，不能只看一条平均 loss。先按表5-3把现象分层，才能选择有效的最小实验。

表5-3 视频生成训练异常的分层定位

现象层 典型信号 优先检查 最小验证
数值异常 loss 或梯度出现 NaN/Inf，动态 loss scale 连续下降 异常 batch、学习率、混合精度、归一化与梯度裁剪 保存首个异常 step 的输入，用更高精度和单卡短跑复现

  1. 先让问题可复现。 固定 checkpoint、EMA 或原始权重、prompt、seed、采样器和 CFG，避免把评估配置变化误判为训练退化。
  2. 找到第一个异常点。 对齐当时的 batch、bucket、学习率、loss scale、梯度范数和配置变更。只看异常后的长期曲线，常常已经错过触发原因。
  3. 缩小到单一变量。 用单 bucket、固定小数据集或短时间高精度运行验证假设。若连小数据都无法拟合，优先查实现和数值；若小数据正常而全量训练异常，再回到数据分布、采样和分布式一致性。
  4. 修复后做回归。 除整体 loss 外，还要复查单帧质量、运动幅度、时序一致性、文本遵循及不同规格的失败率。

面试速答：视频训练异常应先分成数值发散、优化失衡、数据或 latent 异常、生成评估回退和系统异常。排查时固定生成配置，定位第一个异常 step，再用单 bucket、固定小数据或高精度短跑验证单一假设。总 loss 正常不能排除运动、时序或文本遵循已经回退，step time 和 OOM 则应单独进入系统链路排查。

视频扩散模型训练时究竟学什么？为什么不能理解为逐帧去噪？

难度评分：⭐⭐⭐ (3/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

视频扩散模型学习的是：在给定噪声级别和条件后，如何从受扰动的时空 latent 估计去噪方向。典型训练并不会对每个样本完整执行一遍反向链，而是随机采样时间 \(t\) 和噪声 \(\epsilon\)，直接构造 \(z_t\)，用一次网络前向计算监督信号：

\begin{aligned}
z_t &= \alpha_t z_0 + \sigma_t \epsilon, \qquad \epsilon \sim \mathcal{N}(0,I), \\
\mathcal{L} &= \mathbb{E}\left[\left\lVert y(z_0,\epsilon,t)-f_\theta(z_t,t,c)\right\rVert_2^2\right].
\end{aligned}

预测目标可以采用不同参数化

\(y\) 取决于参数化方式，可以是噪声 \(\epsilon\)、干净 latent \(z_0\)，也可以是常见约定下的 velocity \(v_t=\alpha_t\epsilon-\sigma_tz_0\)。三种写法描述的是相关的预测量，但损失权重、数值尺度和训练动态并不完全相同；更换 prediction type 时，采样器中的转换公式也必须同步。

视频一致性来自时空联合建模

“不是逐帧去噪”的原因不在损失函数名称，而在模型处理的数据与网络结构。视频 latent 通常形如 \(T'\times H'\times W'\times C\)，主干通过 3D 卷积、时间注意力或时空注意力联合处理多帧。若网络仍按帧独立预测，即使使用同一扩散损失，也不会自动获得可靠的运动连续性。时序一致性来自时空表示、主干结构和视频数据的共同约束，不能全部归功于 Diffusion。

训练误差要按噪声区间观察

工程上应按噪声区间统计训练误差，并分别检查静态镜头、快速运动和镜头切换样本。高噪声区语义结构学不好、低噪声区细节恢复差，是两类不同问题；只看一个全局平均 loss 很容易掩盖它们。

面试速答：训练时通常随机采样一个噪声级别，模型用一次前向预测 \(\epsilon\)、\(z_0\) 或 \(v\)，完整的多步求解主要发生在推理阶段。视频不是逐帧独立去噪，因为主干应在时空 latent 上联合预测；Diffusion 目标本身并不保证跨帧一致性。

视频模型训练中如何做显存优化，而不是简单减 batch？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

先定位显存峰值。 前向阶段达到峰值，通常先查输入规格、padding、激活和 attention 临时量；反向峰值更可能与保存的激活、梯度和重算策略有关；优化器更新或保存 checkpoint 时溢出，则要检查优化器状态、参数聚合和 state dict 的生成方式。只有分清峰值来源，优化手段才不会错位。

再判断显存花在了哪里。 参数、梯度和优化器状态属于模型状态；随 micro-batch、token 数和层数变化的部分主要是激活；attention workspace、通信 buffer、内存碎片等属于临时开销。表5-4 给出了常见方案实际作用的位置。

表5-4 视频模型训练中的主要显存优化手段

方法 主要减少的显存 主要代价或边界
BF16/FP16，必要时 FP8 参数计算副本、激活和部分通信量 FP8 依赖硬件与算子支持，还要验证量化尺度和数值稳定性
memory-efficient attention attention 中间量及 HBM 读写 不改变稠密 attention 的理论计算量；具体收益受形状和 kernel 支持影响
activation checkpointing 反向所需的保存激活 反向阶段增加重算，checkpoint 粒度过细还会增加调度开销
FSDP/ZeRO 参数、梯度和优化器状态的冗余副本 引入参数聚合与梯度切分通信，也会产生短时的未切分参数峰值
context/sequence parallel 长序列相关的激活；具体范围取决于实现 需要额外通信，且 sequence parallel 在不同框架中的语义并不相同
CPU/NVMe offload GPU 上的模型状态或激活 把压力转移到主存、PCIe 或存储带宽，通常会牺牲吞吐

优化顺序取决于占用来源。 实际调整时可以按下面的顺序推进：

  1. 消除无效占用。 先处理过度 padding、异常大的 bucket 和不必要的在线 VAE。VAE latent 预计算只会移除在线编码的计算和工作区；如果 VAE 原本已冻结并在 no_grad 下运行，就不能把它描述为节省生成主干的激活显存。
  2. 降低激活开销。 常见组合是低精度、memory-efficient attention 和分层 activation checkpointing，并根据吞吐损失选择重算粒度。
  3. 切分模型状态。 若参数、梯度和优化器状态仍占主导，再引入 FSDP 或 ZeRO，并检查参数聚合造成的临时峰值和通信开销。
  4. 处理超长单样本。 长视频的单样本激活仍然放不下时，再使用 context parallel 等序列维度切分。

单独看 micro-batch 的作用。 减小 micro-batch 确实能降低激活显存，但不会减少参数和优化器状态。可以用梯度累积维持全局 batch，代价是单次参数更新需要更多前后向；如果连全局 batch 也一起改变，还要重新核对学习率、优化器统计和收敛表现。

面试速答：先按 OOM 出现位置判断峰值来自模型状态、激活还是临时 buffer。激活侧优先检查 padding、低精度、memory-efficient attention 和 checkpointing；状态侧使用 FSDP/ZeRO；超长序列再考虑 context parallel。减 micro-batch 只解决激活峰值，不能替代显存归因。

视频训练吞吐低，应该从哪些环节排查？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

吞吐指标先统一。 samples/s 会把短视频和长视频视为同一个样本，原始 tokens/s 又可能把 padding 算作有效工作。视频训练更适合同时记录有效视频 tokens/s、step time 的 p50/p95、各 rank 到达同步点的时间差以及 padding 比例，再用 samples/s 说明业务尺度。

定位时沿关键路径收缩范围。 可以按下面四步进行：

  1. 先确认 GPU 是否在等数据。 对比 dataloader wait、Host-to-Device 拷贝时间和 GPU timeline；再用合成 latent 或内存缓存数据短跑。如果吞吐明显上升，继续检查存储、解码、在线 VAE 和 bucket。完整的数据链路定位见 4.5.1.1，本节不再重复。
  2. 再拆分单步计算。 分开统计前向、反向、激活重算和优化器更新时间，查看 attention、矩阵乘和大量小算子各占多少。GPU 利用率高也可能只是反复重算或运行低效率 kernel，因此还要比较关闭 checkpointing、替换 attention kernel 等单变量实验。
  3. 判断通信是否暴露在关键路径上。 在保持单卡 token 规模不变的情况下，依次比较单卡、单机多卡和多机吞吐。单机扩展正常、多机明显下降，通常要继续检查 all-reduce、all-gather、reduce-scatter 的耗时，通信与计算是否重叠，以及网络拓扑与并行组是否匹配。
  4. 检查负载不均与周期性停顿。 比较各 rank 的 token 数、计算时间和同步等待时间。某个 bucket 过长、坏节点、保存 checkpoint 或数据分片倾斜，都会让其余 rank 等待最慢者；只看平均 step time 容易漏掉这类长尾。

优化效果看端到端。 某项优化即使缩短了一个 kernel，只要引入更多 padding、通信或重算，整体训练速度仍可能下降。

面试速答：先用有效视频 tokens/s 和 step time 分位数确认问题，再做分层替换：合成 latent 隔离数据供给，单卡到多机的扩展实验隔离通信，逐 rank timeline 定位负载不均。GPU 利用率只能辅助判断，高利用率也可能来自无效 padding、重算或低效率 kernel。

训练与推理阶段如何缓解模态鸿沟问题？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

模态鸿沟（modality gap）采用 Liang 等人（2022）的定义，指对比学习模型中两种模态的嵌入各自聚成一团，在共享空间里相互分离[99]。生成器的输出还受到另外两类误差的影响，即向量量化造成的细节损失，以及手指畸形、文字乱码等局部错误。这两类属于生成误差，不是模态鸿沟，下文分开表述。

模态鸿沟与两类生成误差

  1. 模态鸿沟：即使经过 CLIP 对齐，图像嵌入和文本嵌入仍各自聚在共享空间中的一个区域，彼此分离。Liang 等人在 NeurIPS 2022 发表的《Mind the Gap》系统分析了 CLIP 等模型里的这种现象[99]。

  2. 表示粒度造成的细节损失（生成误差）：文本是离散 token，图像和语音是连续信号。用码本把它们离散化会丢失细节，这是早期自回归图像生成质量不如扩散的重要原因。

  3. 局部细节错误（生成误差）：模型学到了整体分布，局部细节却生成不准，早期 Stable Diffusion 常见的手指畸形和文字乱码属于这一类。

训练阶段的缓解策略

  1. 大规模配对预训练：CLIP 的 4 亿图文对[2]、LAION-5B 的 58 亿图文对[100]、DataComp-1B 等[101]，用对比学习把不同模态拉进同一个空间，这是跨模态生成的基础。

  2. 统一 token 空间联合训练：Chameleon、Emu3 把图像和文本放进同一个 Transformer 一起训练[58,70]，让模型在表示层就学到统一空间。

  3. 共享表示空间：ImageBind（Meta，2023）以图像为中心把 6 种模态绑定到同一空间，只用图像与其他各模态的配对数据训练，文本和音频之间也自动对齐了[102]。

  4. 合成描述增强：用视觉语言模型给海量图片生成详细描述，弥补网页 alt-text 过于简略的问题。DALL·E 3（2023）用重新生成的详细描述训练[103]；SD3 用 CogVLM 生成合成描述，和原始描述各占一半，消融实验里 GenEval 总分从 43.27 提到 49.78[59]。

推理阶段的工程手段

  1. 即插即用的适配器：IP-Adapter（参考图条件）、T2I-Adapter（结构条件）、LoRA（风格）[54,104,105]，不重训基座就能加入新条件。

  2. 详细 prompt 和负向提示词：正向写“highly detailed, professional photography”强化质量，负向写“deformed hands, extra fingers, low quality”抑制常见缺陷，这是 SD 社区的常用做法。

  3. 后处理修复：人脸用 GFPGAN 或 CodeFormer 修复，手部用 HandRefiner 局部重绘[106-108]，文字用 OCR 校对。很多商用 SD 工作流的最后一步都是后处理。

  4. 多轮编辑修正：FLUX.2、Qwen-Image-2.1（2026）这类把生成和编辑放进同一个模型的方案[49,109]，可以对同一张图连续做多轮修改，一次没生成好的地方分几次修好。

面试速答：模态鸿沟指对比学习模型中两种模态的嵌入各自成团、在共享空间里相互分离；离散化丢细节和局部细节错误属于生成误差。训练时靠大规模配对预训练、统一 token 空间联合训练、共享表示空间和合成详细描述缓解，推理时靠适配器、提示词、后处理修复和多轮编辑补救。

训练中如何设计帧数、分辨率、帧率和长宽比的 bucketing？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

bucketing 要同时解决两个问题：让形状相近的样本高效组成 batch，并让训练规格覆盖目标生成分布。只按尺寸分桶会忽略真实时间跨度，只追求低 padding 又可能改变数据采样权重。

帧数、帧率、分辨率和长宽比分别控制不同变量，不能混成一个“视频大小”。表5-1 给出了设计 bucket 时应保留的边界。

表5-1 视频训练多规格变量的作用与常见误区

变量 实际控制的内容 常见误区
帧数 \(T\) 输入包含多少个离散时间点，直接影响序列长度 把相同帧数当成相同时长
帧率或采样间隔 相邻帧对应的真实时间跨度，影响动作位移和播放速度 改变抽帧密度后，模型没有获得相应的时间尺度信息
分辨率 \(H \times W\) 空间细节、构图以及空间 token 数 统一拉伸到固定尺寸，破坏主体比例
长宽比 横竖构图与裁剪范围；它可由 \(H,W\) 推出，不是额外独立尺寸 bucket 过细，产生大量低频规格
latent/patch token 数 生成主干看到的实际序列规模 只按像素面积估算成本，忽略 VAE 与 patchify

一套可落地的设计通常按下面的顺序推进：

  1. 从目标分布确定主规格。 先统计训练数据与产品请求中的时长、帧率、分辨率和长宽比，再选择需要重点覆盖的 bucket。数据里存在某种规格，不代表必须等比例训练。
  2. 把样本映射到可计算形状。 bucket 尺寸要满足 VAE 和 patchify 的整除或填充规则。分配样本时限制裁剪、缩放和 padding 的幅度，超出阈值的样本应进入其他 bucket 或被单独处理。
  3. 逐 bucket 标定 batch size。 token 数可以给出初始估计，最终仍要实测峰值显存和 step time。长序列 bucket 往往需要更小的 batch、更多梯度累积，必要时再配合序列并行。
  4. 显式控制采样权重。 按样本数、按 step 或按 token 采样会得到不同训练分布。低频 bucket 过度采样容易重复，高频 bucket 完全按原始占比又可能挤压业务关键规格，需要记录每类 bucket 的实际曝光量。

bucketing 也不是唯一方案。对不同时长的样本，可以通过 packing 提高利用率；但必须正确处理 attention mask、位置编码和样本边界，避免不同视频之间互相注意。无论采用分桶还是 packing，都应监控 padding 比例、各 bucket 的 samples/s 与 tokens/s、step time 尾延迟、OOM 率和分规格验证质量。

面试速答：bucketing 先按目标生成分布选择帧数、帧率、分辨率和长宽比规格，再把样本映射到满足 VAE 与 patchify 约束的形状。不同 bucket 的 batch size 由 token 估算起步，再按实测显存和 step time 标定；同时要显式控制各 bucket 的采样权重。帧数不等于时长，固定总 token 也不保证固定计算量。

训练加速

  1. 使用 BF16、FlashAttention、fused optimizer 和通信计算 overlap；TF32 主要影响 FP32 矩阵乘法路径，不能把它当作 BF16 的替代品。

  3. 做 sequence packing 或长度分桶，减少 padding；多模态 batch 还需按图片 token 数、文本长度和生成长度分桶，否则一个超长样本会拖慢整批。
  4. 控制全局 batch、mini-batch、group size、生成长度和 reward 计算频率，避免为了增大 batch 造成显存溢出或通信饱和。GRPO 的有效样本量不能只看 prompt 数，还要看每个 prompt 的 response 数和有效 token 数。
  5. 用 NCCL 拓扑、梯度桶大小、通信 overlap、持久化 worker 和预分配显存降低同步开销；保存 checkpoint 时异步写盘，避免训练线程长时间阻塞。

回答：

训练部分先固定数据契约和损失，再说明哪些参数更新、采样方式、优化器、学习率、batch、精度和随机种子。若使用冻结骨干、LoRA 或全量微调，应说明选择依据与对照结果。

训练大语言模型的核心资源要素有哪些？为什么说它是资本密集型工程？

难度评分：⭐⭐ (2/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

  • 核心资源要素包括：（1）算力资源，如 GPU/TPU 集群、高速互联网络、分布式训练系统；（2）数据资源，如高质量通用文本、代码数据、数学数据、领域专用数据和偏好数据；（3）基础设施资源，如数据中心、存储系统、网络系统、任务调度系统；（4）人力资源，如算法工程师、系统工程师、数据工程师、平台工程师和安全合规团队；（5）软件工具资源，如训练框架、并行训练框架、数据治理平台、监控系统和评估系统。

训练视频生成模型时，数据管线最容易拖垮哪些环节？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

真正容易拖垮训练的，不是某一个固定模块，而是下面四段链路中的最慢环节：

  1. 读取与解码。 远端存储带宽不足、随机 seek、编码格式混杂、损坏文件重试，都会让 CPU 侧供给出现长尾。此时最典型的现象不是报错，而是训练进程间歇性等数据。
  2. 样本构造。 镜头切分、clip 采样、过滤和 caption 决定“喂给模型的是什么”。这一段吞吐可能正常，但错误切镜、无效样本或条件错配会让有效训练信号下降。
  3. 预处理与 latent 编码。 resize、裁剪和 VAE 编码若在线执行，会占用 CPU/GPU 时间；预先缓存 latent 能减轻训练时计算，却会增加存储成本，并要求 VAE 版本、归一化和数据增强策略保持一致。
  4. 组 batch。 不同帧数、分辨率和长宽比造成的 worker 负载不均与尾部等待，也会打断稳定供给。这里先关注“能否持续形成 batch”，token 利用率和 bucket 设计放到 4.5.2 再讨论。

如图 5-1 所示，排查时应给每个阶段单独记录处理耗时、队列深度、失败率和输出速率，而不是只看 GPU 利用率。

图5-1 视频训练数据供给链路与吞吐瓶颈定位

定位瓶颈时，可以做一组由简到全的替换实验：

  • 用随机张量替代真实数据，先确认训练计算和通信本身的上限；
  • 换成预计算 latent，判断问题是否集中在读取、解码或 VAE；
  • 再依次恢复在线 VAE、视频解码和完整过滤链路，观察 samples/s、有效 tokens/s、data wait time 与 GPU 空闲时间在哪一步明显恶化。

这里有一个常见误区：GPU 利用率低不等于数据管线一定慢，小算子、同步通信同样可能造成空闲。只有结合阶段计时和替换实验，才能把“GPU 在等什么”定位清楚。

面试速答：视频数据管线主要会卡在读取解码、样本构造、预处理或 VAE 编码、组 batch 四个环节。排查不能只看 GPU 利用率，应记录各阶段耗时和队列，再用“随机张量 → 缓存 latent → 在线 VAE → 完整视频链路”的替换实验逐层恢复，定位吞吐下降从哪一步开始。

训练路径、推理时间步、数值求解器与 CFG 分别控制什么？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

这四个概念处在不同层级：

  1. 训练路径规定 \(\alpha_t\)、\(\sigma_t\) 或中间概率路径，决定训练时模型看到哪些信噪比和目标速度。
  2. 推理时间步选择从噪声端到数据端实际访问哪些 \(t\) 或 \(\sigma\)。步数越少，网络调用越少，但离散误差通常更大。
  3. 数值求解器根据模型在当前状态的预测计算下一状态，例如 Euler、Heun 或 DPM-Solver 类方法。高阶方法可能减少误差，也可能增加单步网络调用。
  4. CFG在每次模型预测时组合有条件与空条件结果，改变条件引导强度。用一般预测量 \(f\) 表示：
f_{\mathrm{cfg}}
=f_\theta(z_t,t,\varnothing)
+s\left(f_\theta(z_t,t,c)-f_\theta(z_t,t,\varnothing)\right).

其中 \(s\) 是 guidance scale。增大 \(s\) 往往能强化文本遵循，却可能压缩多样性，并带来颜色过饱和、结构伪影；在视频中也可能改变运动幅度或放大时序抖动。这是经验风险，不代表所有模型都会出现同一种退化。

讲一下什么场景下用 SFT，什么场景下用 RL

回答：

SFT 适合有可信示范答案或轨迹的任务：格式遵循、领域表达、工具参数生成和基本交互行为。它直接学习示范分布，成本与稳定性通常更容易控制，但上限受示范质量和覆盖限制。

RL 适合能够对模型采样结果提供有效反馈的任务，例如程序是否通过测试、数学答案是否正确、工具任务是否实际完成。模型可以探索不同输出并优化奖励，不要求每个输入都有唯一示范；代价是采样、奖励计算与策略训练复杂，可能出现奖励投机。

二者常组合：先 SFT 建立可用行为，再用 RL 优化可验证目标。主观偏好有高质量离线比较对时，也可考虑 DPO 等方法。动态知识缺失优先改善检索和数据，不能认为 RL 会自动补足知识库。

详细说明多模态大模型中LoRA的推理过程？

LoRA（Low-Rank Adaptation）是一种用于大型多模态模型的微调技术，它通过低秩分解来减少需要更新的参数数量，从而在保持模型性能的同时降低计算成本和存储需求。以下是LoRA在多模态大模型中的推理过程：

LoRA的推理过程

  1. 冻结预训练模型参数： - 在微调过程中，LoRA首先冻结预训练模型的所有参数，这些参数在微调过程中保持不变。这样做可以确保模型的基本结构和特征不受影响，同时减少需要更新的参数数量。

  2. 引入低秩分解矩阵： - 在Transformer架构的每一层中，LoRA注入两个可训练的低秩分解矩阵A和B。矩阵A使用随机高斯分布进行初始化，维度为r×k，负责将输入数据维度降至r维；矩阵B使用0进行初始化，维度为d×r，负责将数据维度升至d维。

  3. 低秩矩阵的初始化和更新： - 在微调过程中，仅训练低秩分解矩阵A和B。具体来说，待更新的参数矩阵ΔW表示为低秩分解BABA的形式，其中BB和AA是随机初始化并在微调过程中更新的。

  4. 合并训练参数： - 最后，将LoRA训练得到的参数与原始模型参数合并，并保存到新的模型中。这样，模型在保持原有性能的同时，获得了针对特定任务的微调效果。

LoRA的优势

  • 减少计算资源和存储需求：通过仅更新低秩矩阵，LoRA显著减少了微调所需的计算资源和存储空间。
  • 保持模型性能：LoRA通过低秩分解技术，能够在保持模型原始性能的基础上，实现有效的微调。
  • 推理效率高：LoRA在推理阶段不引入额外的计算量，保持了高效的推理性能。

LoRA通过其独特的低秩分解技术，为多模态大模型的微调提供了一种高效且有效的方法。它不仅减少了计算资源和存储需求，还能在保持模型性能的同时，实现快速的微调和推理。

请简要描述图优化、算子库、内存管理与运行时调度分别解决什么问题？

难度评分：⭐⭐⭐⭐⭐ (5/5) | 考察频率：⭐⭐⭐ (3/5)

一、图优化模块：解决计算冗余与计算图低效的问题

训练框架（PyTorch/TensorFlow）导出的模型或中间表示通常优先服务于训练和模型表达，重点是灵活性、可调试性和通用性，不一定适合直接高效推理。原始图中可能存在： - 多个可以合并的小算子，例如 Conv + BN + ReLU - 可以在编译期提前计算的常量表达式 - 不再影响输出的无效节点或分支 - 不合理的数据布局和算子执行顺序

图优化通过一系列保持计算语义等价的图变换，对计算图进行重构，典型手段包括常量折叠、死代码消除、公共子表达式消除、算子融合、布局转换等。它的核心目标是少算、少搬数据、减少调度开销，并让后续算子库和硬件后端更容易发挥性能。

二、算子库模块：解决单个算子执行效率低的问题

图优化决定"应该怎么组织计算"，算子库决定"每个计算单元如何在硬件上高效执行"。如果算子实现效率低，即使计算图已经优化，仍然无法充分发挥硬件性能。通用实现往往难以充分利用： - CPU 的 SIMD 指令、多线程和缓存层次 - GPU 的 CUDA Core、Tensor Core、shared memory 和访存合并 - NPU / TPU 等专用加速器的算子格式和编译后端

算子库会针对不同硬件的指令集、内存层次和并行计算单元提供高度优化的 GEMM、Conv、Attention、LayerNorm、Elementwise 等算子实现。常见优化包括向量化、多线程、tile/block划分、共享内存复用、访存合并、低精度计算和kernel融合，目标是让硬件计算单元尽量保持高利用率。

三、内存管理模块：解决内存开销、分配开销和显存碎片的问题

深度学习推理需要存储模型权重、输入输出张量、中间激活、临时 workspace，以及大模型生成过程中的 KV Cache。内存管理模块通常负责： - 内存池 / 显存池：减少频繁 malloc/free 或 cudaMalloc/cudaFree 带来的开销 - 张量复用：根据张量生命周期复用不再使用的内存块 - 静态内存规划：在 shape 相对固定时提前规划峰值内存 - 显存碎片控制：降低碎片和预留浪费 - KV Cache 管理：通过 PagedAttention、Block Table、Prefix Cache、KV Cache量化等方式支撑长上下文和高并发

它的核心目标是降低峰值显存、减少分配释放开销、提高显存可承载的 batch 和并发规模。

四、运行时调度模块：解决执行顺序、资源利用率和请求调度的问题

运行时调度负责把优化后的计算图和算子放到真实硬件与线上请求流量中执行。常见问题包括： - 算子执行顺序不合理，导致依赖等待 - 计算与数据传输串行执行，硬件空闲时间长 - 小 kernel 过多，kernel launch 和同步开销明显 - 在线请求动态到达，固定 batch 难以兼顾延迟和吞吐 - 多模型、多任务或多租户之间存在资源竞争

运行时调度主要分为两个层面： - 算子级调度：管理算子执行顺序、依赖关系、任务分发、异步拷贝、stream并发、计算通信重叠，目标是减少等待并提高硬件利用率。 - 请求级调度：管理请求队列、动态batching、连续批处理、优先级、抢占和资源分配，目标是在延迟约束下提升吞吐量。

可以总结为：图优化负责让计算图更适合推理，算子库负责让单个算子跑得快，内存管理负责让显存用得省且稳定，运行时调度负责让硬件和请求流持续高效运转。

请详细分析多模态预训练模型的推理优化方法，包括模型压缩、量化和加速等技术

多模态预训练模型的推理优化是实际部署中的关键挑战，需要在保持模型性能的同时提升推理效率。模型压缩是最基础的优化方向，包括知识蒸馏和模型剪枝等技术。知识蒸馏通过将大模型的知识转移到小模型中，既能保持较好的性能，又能显著减少模型大小。而模型剪枝则通过识别和移除冗余参数，实现模型的稀疏化，但需要仔细平衡压缩率和性能损失。

量化技术是另一个重要的优化手段。通过将模型参数从浮点数转换为低位整数表示，可以显著减少模型大小和计算开销。动态量化和静态量化各有优势，前者能够保持更好的精度但推理开销较大，后者则能提供更快的推理速度但可能带来更多的精度损失。混合精度量化是一个折中方案，通过对不同层使用不同的量化策略来平衡性能和效率。

推理加速还需要考虑计算架构的优化。注意力机制的优化是一个重要方向，如通过稀疏注意力或线性注意力来减少计算复杂度。此外，模型并行和流水线并行等分布式计算策略也能显著提升推理效率。在实际部署中，还需要考虑硬件特性和推理框架的选择，通过算子融合、内存优化等技术手段进一步提升性能。最新的研究还探索了神经架构搜索和自动化优化方法，试图找到更优的模型结构和推理策略。

选择LoRA微调而非全量微调的原因

回答：

LoRA 的核心是冻结基座权重，只训练一个低秩增量。对线性层，可以写成：

y=W_0x+\frac{\alpha}{r}BAx,\qquad
A\in\mathbb{R}^{r\times d_{\mathrm{in}}},\quad
B\in\mathbb{R}^{d_{\mathrm{out}}\times r}

可训练参数由单矩阵的 \(d_{\mathrm{out}}d_{\mathrm{in}}\) 变为 \(r(d_{\mathrm{in}}+d_{\mathrm{out}})\)。常见初始化是 A 随机、B 为零，初始增量为零，起点保持基座输出；两者同时初始化为零会导致这两个矩阵的梯度都为零。这里的低秩是假设任务更新能在较小子空间内表达，并不意味着基座矩阵本身低秩。

比较项 LoRA 全量微调
训练自由度 受 rank、目标模块和层选择约束 可更新全部参数
状态显存 显著减少可训练梯度与优化器状态 通常更高，常需分片
数据与任务 适合低成本验证、多任务适配和多版本管理 适合充分数据下更广泛的能力调整
上线形态 可保留适配器，也可条件允许时合并 通常部署独立完整权重

决策上，先明确业务差异、数据规模、遗忘风险和预算，建立同数据、可比较算力预算的实验。LoRA 若在关键长尾桶已满足要求，不必为了参数更多而全量训练；若扩大 rank 和目标层仍欠拟合，再评估部分解冻或全量微调。全量微调也不保证效果更好，数据噪声和过拟合可能让它更差。

QLoRA 进一步量化冻结基座，降低权重存储成本，同时训练低秩适配器；它不是所有前反向都用 4 bit。PEFT 还提供 rsLoRA、DoRA 等配置：rsLoRA 调整 rank 缩放，DoRA 区分幅值与方向，它们都需要实测，不能凭方法更新就断言收益。

尤其要明确：LoRA 主要减少可训练状态，不会自动消除基座权重、激活和长序列注意力的成本。 合并适配器可消除独立低秩分支，但量化权重的反量化、重合并与再量化可能改变数值精度，导出后应重跑评测。

长上下文训练中，GLM-4.5V如何通过128K令牌的序列长度处理复杂文档？

处理长文档的难点在于保持跨页信息的连贯性与计算效率。GLM-4.5V的解决方案包含三方面：
1. 序列打包与梯度累积：将多个变长样本拼接至接近32K令牌的序列，通过梯度累积模拟大批训练，同时使用负载均衡算法分配DP秩间的序列长度，避免单卡过载；
2. 位置编码自适应：对ViT的绝对位置嵌入进行双三次插值，使其适应动态分辨率的输入图像，支持从极宽图表到长文档的多样化布局；
3. 时空注意力优化：对视频输入插入时间索引令牌，显式编码帧间时间距离，提升长视频的时序推理能力。

在金融报告分析案例中，模型需同时处理四家公司年报（约150页）。实验显示，模型能准确提取跨文档的毛利率、研发支出等关键指标，并生成对比表格。其性能依赖长上下文持续训练阶段注入的交互式图文数据（超8K令牌），此类数据包含学术论文、技术手册等复杂排版内容，迫使模型学习页码关联、参考文献跳转等长程依赖。

长文本训练各类优化Trick

答：长文本训练可以从数据、位置编码、attention、显存和课程学习几个角度回答。

数据层面，首先要做 sequence packing，把多条短样本拼成接近最大长度的训练序列，减少 padding 浪费。其次要构造真正需要长上下文的样本，例如长文问答、跨章节推理、代码仓库理解、长视频字幕理解、needle-in-a-haystack 检索任务。只把短样本拼长，并不等于模型学会了长程依赖。

位置编码层面，可以使用 position interpolation、NTK scaling、YaRN 等 RoPE 外推方法。常见做法是先在短上下文上训练稳定能力，再用少量长上下文数据继续训练，让模型适配更大的位置范围。

attention 层面，可以使用 FlashAttention、Ring Attention、sequence parallel、sliding window attention、block sparse attention、global-local attention。训练超长上下文时，显存瓶颈通常来自 attention activation 和 KV，因此需要结合 activation checkpointing、ZeRO、张量并行、序列并行。

loss 层面，可以做 chunked loss 或只对关键回答区域计算 loss，避免无效长上下文 token 主导训练。对于“长上下文检索式问答”，可让问题依赖远处证据，强制模型学习跨距离定位。

课程学习层面，可以从 4K、8K、32K、128K 逐步扩展到更长，而不是一开始就训练极长序列。这样更稳定，也能控制成本。

工程层面，常见 trick 包括 BF16 混合精度、梯度累积、梯度裁剪、optimizer state offload、激活重计算、异步数据加载、样本按长度 bucket、动态 batch token 数控制。长文本训练更适合按 token budget 组 batch，而不是按样本数固定 batch。

评估层面不能只看困惑度，需要看长距离检索、跨段综合、引用定位、多文档问答、长代码依赖、长视频时间定位等任务。因为模型可能在 PPL 上正常，但一到超长上下文就出现“只看开头和结尾”的退化。

问题2中说到了模型的微调，面试官问对模型微调那些算法了解吗？

回答：

大模型微调可以按目标分成三类：监督微调、参数高效微调和偏好对齐或强化学习。

监督微调 SFT 是最常见的方式，用高质量 instruction-response 数据继续训练模型，让模型学习特定领域的回答风格、任务格式和业务流程。SFT 适合让模型按要求做事，例如客服话术、结构化抽取、代码解释、领域问答格式。但它不适合频繁注入实时知识，因为参数更新成本高，也容易遗忘或过拟合。

全参数微调会更新模型全部参数，效果上限高，但显存和数据要求高，训练风险也更大，容易破坏原模型通用能力。企业落地更常用 PEFT 参数高效微调，例如 LoRA、QLoRA、Adapter、Prefix Tuning、P-Tuning。LoRA 的核心是冻结原模型权重，只在部分线性层旁加入低秩矩阵学习增量参数；QLoRA 在量化基础上训练 LoRA，显存更省，适合资源有限场景。

偏好优化用于让模型更符合人类偏好或业务标准。RLHF 通常包括奖励模型训练和 PPO 等强化学习优化；DPO 不显式训练奖励模型，而是直接用偏好对数据优化模型，使 chosen response 概率高于 rejected response。还有 IPO、KTO、ORPO、GRPO 等变体，目标是改善回答质量、拒答、安全性、推理风格或任务完成度。

在 Agent 或大模型应用场景中，微调还可以服务于工具调用和工作流。例如用 SFT 让模型学习什么时候调用工具、如何生成合法参数、如何在工具失败后重试；用偏好数据让模型更倾向于引用证据、避免编造、遵守业务边界。但工具调用是否正确不能只靠微调，还要有 schema 校验、权限控制、执行反馈和 trace 评估。

选型时可以这样回答：如果是领域表达和格式问题，优先 SFT 或 LoRA；如果是知识更新问题，优先 RAG，不优先微调；如果是回答偏好、安全边界、拒答问题，用 DPO/RLHF 类方法；如果资源受限，用 QLoRA；如果担心通用能力损伤，就控制学习率、训练轮数，并做回归评测。

问题6：Dropout的原理、在训练和测试时的区别？

Dropout是一种常用的正则化方法， 其原理是在每次迭代中随机将一部分神经元的输出置为0，从而减少神经元之间的共适应性，防止过拟合。 在训练时，Dropout会随机将一定比例的神经元的输出置为0，而在测试时，为了保持网络的稳定性，Dropout通常被关闭。

问题7：Dropout 是怎么做的？有什么作用？推理和训练时 Dropout 的区别？如果推理也用 dropout 会怎么样？

Dropout是一种正则化技术，通过在训练过程中随机丢弃（即设置为零）一部分神经元来防止过拟合。具体步骤为：

  1. 在每一层的输出中，以一定的概率 \(\( p \)\) 随机丢弃一些神经元。
  2. 对保留的神经元进行放大 \(( \frac{1}{1-p} \)\) ，以保持总的激活值不变。

作用：通过随机丢弃神经元，减少节点之间的相互依赖，从而提高模型的泛化能力。

推理和训练时 Dropout 的区别 - 训练时：应用Dropout，即随机丢弃神经元，并对保留的神经元进行放大。 - 推理时：不应用Dropout，使用完整的网络。

如果推理时也用Dropout，模型的输出将变得不稳定，因为每次推理时网络结构都不同，导致结果不可预测且精度下降。

问题7：SGD、Adam、动量优化的SGD？

问题8：讲讲 BN？BN 训练和推理什么区别？有什么用？

Batch Normalization（BN）是一种加速深层神经网络训练并提高其稳定性的方法。BN通过对每一层的输入进行标准化，使得输入具有零均值和单位方差， 同时允许网络学习最优的均值和方差。

训练和推理的区别

  • 训练时：使用mini-batch的均值和方差，并更新全局均值和方差的移动平均值。
  • 推理时：使用训练过程中计算的全局均值和方差。

作用

  • 减少内部协变量偏移（Internal Covariate Shift）。
  • 加快训练速度。
  • 提高模型的泛化能力。

预训练、微调和提示词工程有什么区别？

预训练与微调在通用性、成本、能力保持上有何关键权衡？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

预训练与微调的权衡体现在通用性、成本和能力保持三个方面：

  1. 通用性与专用性。 预训练出来的模型通用能力强，LLaVA-1.5、Qwen-VL、InternVL 等基座在 MMBench、MME、ScienceQA 这些通用榜单上表现比较均衡，但直接用于医疗影像、工业质检这类垂直领域，往往达不到上线部署的要求。微调后的模型在目标任务上会明显变好，通用能力则可能下降。

  2. 成本。 预训练需要千卡级 GPU 集群训练数周到数月，微调通常在单机上训练数小时到数天（均为经验量级）；作为参照，LLaVA-1.5-13B 的完整训练在单台 8 卡 A100 上约一天完成[6]。成本差异决定了产业分工，基座模型由少数具备大规模算力的团队训练，下游应用团队以微调为主。

  3. 能力保持。 微调阶段需要重点防范灾难性遗忘（catastrophic forgetting），即模型在专用任务上训练之后，通用任务的表现明显下降。例如在医疗影像上做全参数微调之后，模型描述自然图像的能力可能随之退化。

缓解灾难性遗忘的常见做法

  1. 混入通用数据：在微调数据里掺入一定比例的通用指令数据（如 LLaVA-Instruct[2]），保持模型的基础能力，比例按任务和遗忘程度经验调节。

  2. 用 LoRA 保留基座权重：LoRA 只训练低秩增量，基座的原始权重保持不变[46]。语言模型上的对比实验显示，LoRA 对目标领域以外能力的保持优于全参数微调，代价是目标领域上的提升较小[50]。

  3. 选择性冻结：冻结视觉编码器，语言模型只微调投影器和最后若干层，其余层保持预训练权重，尽量多保留预训练学到的知识。

高质量 video caption 应该如何服务于 T2V 训练？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐⭐ (5/5)

video caption 是 T2V 的条件监督。它的目标不是把文字写得尽可能长，而是用模型能够利用的表达，准确覆盖视频里确实存在的主体、动作和时间关系。

一条有效 caption 通常包含四类信息：

  1. 主体与场景：谁在什么环境中，关键属性和主体关系是什么；
  2. 动作与变化：谁做了什么，运动方向、速度或状态如何变化；
  3. 时间关系：动作是同时发生还是先后发生，事件是否分阶段推进；
  4. 镜头信息：景别、视角和相机运动，但只描述画面中能够判断的内容。

真正难的是动态信息。只根据少量关键帧生成 caption，往往能看见“有什么”，却看不准“怎么动”和“先后发生了什么”。因此工程上常把帧级视觉证据、整段视频表征、镜头边界和已有元数据合并，再生成或重写训练 caption。不同粒度的描述可以并存，但都要落回视频证据，不能为了丰富而补写不存在的动作或镜头语言。

caption 质量主要看三点：

  • 事实一致：主体、数量、属性、动作与视频相符，不能把模型猜测当成事实；
  • 时间可辨：描述能区分方向、动作阶段和先后关系，而不只是静态名词堆叠；
  • 训练可用：重要信息位于文本编码器可见范围内，表达粒度与推理时的用户 prompt 不至于严重错位。

评估时不能只用 caption 长度或单一图文相似度。更可靠的做法是构造方向、顺序、主体—动作绑定和相机运动等对照样本，检查模型能否区分近义但时序关系不同的 prompt；同时抽样做人审，尤其关注 caption 模型容易产生的动作补写和主体错配。若自动评估器与 caption 生成器同源，还要警惕二者共享错误偏好。

面试速答：高质量 video caption 要基于整段视频证据，准确描述主体、动作、时间顺序和可判断的镜头变化。重点不是越长越好，而是事实正确、动态关系清楚、训练时可被文本编码器有效利用；评估时应专门测试方向、先后顺序和主体—动作绑定，不能只看图文相似度。

高质量微调和偏好后训练主要解决什么问题？

难度评分：⭐⭐⭐⭐ (4/5) | 考察频率：⭐⭐⭐⭐ (4/5)

高质量微调和偏好后训练都发生在基础训练之后，但监督信号不同。高质量微调仍用目标视频和条件做生成训练，主要把模型移向更干净、更贴近业务的样本分布；偏好后训练利用候选结果之间的比较或奖励信号，调整模型对“哪种输出更好”的排序。

两者的职责边界见表5-2。

表5-2 高质量微调与偏好后训练的监督信号和风险

训练阶段 主要监督 更适合改善 主要风险
高质量微调 精选视频、准确条件及原有 Diffusion/Flow Matching 目标 目标领域覆盖、文本遵循、视觉质量和特定失败样本 小数据过拟合、能力遗忘、运动或内容多样性收缩
偏好后训练 同一条件下的候选排序、人工偏好或经过校准的奖励信号 难以用单个目标视频表达的审美、可用性和多目标取舍 奖励偏置、过度优化可测指标、输出趋同

“高质量”不能只等同于高分辨率。数据还要检查动作完整性、时序稳定、caption 准确度、来源分布和业务覆盖。微调集如果大量偏静态，即使单帧画质上升，运动能力也可能回退；如果只保留审美风格相近的样本，生成多样性也会缩小。

偏好数据同样需要按维度设计。画质、文本遵循、运动自然度、主体一致性和安全性可能互相冲突，把它们压成一个未经校准的总分，模型容易沿评估器的偏好取巧。DPO、reward-weighted training 或带奖励的优化只是实现方式，核心仍是偏好数据是否覆盖真实产品取舍，以及训练是否受参考模型或其他约束限制。

更稳妥的验证方式是保留基础能力回归集，并同时观察偏好胜率、运动幅度、内容多样性、文本遵循和严重失败率。偏好分数提高但视频越来越静、构图越来越相似，通常说明模型在迎合评估信号，不能视为整体质量提升。

面试速答：高质量微调用精选视频继续原有生成目标，主要调整模型的数据分布；偏好后训练用候选比较或奖励信号调整输出排序。前者要防止小数据过拟合和能力遗忘，后者要防止奖励偏置、输出趋同和运动静态化。两者都应保留基础能力回归集，偏好分数提高不能单独证明模型整体变好。
